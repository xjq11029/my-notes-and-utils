# 第 8 章 长期记忆：跨工程跨会话的经验沉淀

## 一、概念

**长期记忆**是 Coding Agent 内置的一套机制：

> 在你跟它沟通的对话过程中，它会把一些**关键信息**记录下来。

它不是会话上下文（第 2 章），而是**跨会话、跨工程**持久存在的另一层记忆。

讲师在讲这一章之前说了一句题外话，值得记录：

> 聊这些东西吧，它还不一定是为了我们将来去使用它，只是其中一个方面，**主要是消除同学们内心的恐惧**——不然的话，Coding Agent 始终是一个黑匣子，同学们不知道里面发生了什么，就容易把它神化。

学到这里应该已经清楚：**它里面没有什么非常恐怖、特别的东西。**

## 二、原理推导

### 8.1 存储位置

长期记忆的落盘形式**各家不同**：

- 有可能是**本地的一个 SQLite 数据库**
- 也有可能是**记录到一个文件里**

**Codex 的位置**：用户主目录下的 `memory` 文件夹。

### 8.2 记录内容

长期记忆记录的是：

- **用户的习惯**
- **用户的偏好**
- 在跟用户打交道的过程中产生的**经验和教训**

**生效范围**：**可以跨越工程、跨越会话**——这是它与会话上下文的本质区别。

### 8.3 黑盒属性

讲师反复强调它**不透明**：

| 不确定项 | 说明 |
|---|---|
| 记录到哪里 | SQLite 还是文件，各家不同 |
| 记录什么 | 不同 Agent 记录的东西不一样 |
| 什么时候记录 | 时机也不一样 |

> 那是个黑盒子，我不知道它里面啥写的。

**各工具情况**：

- **Claude Code**：肯定有
- **Codex**：不确定有没有，**不要太过于指望它**

### 8.4 实践建议

这是本章最有价值的部分：

> 我们在使用过程中，如果说开发某一个项目，有什么东西需要让它知道、有些问题以后不要再犯了，**正确的方法应该是放到提示词里边**。

也就是说：**需要长期生效的约定，写进提示词才可靠**，不要指望记忆系统自己记住。

**最佳实践⑥**（课件原文）：

> **奖罚分明，有利于形成长期记忆。**

对做对的事给予正反馈，有助于它把经验沉淀下来。

## 三、演示步骤（按讲解顺序还原）

1. **找记忆文件**：查看 Codex 的目录结构，定位到用户主目录下的 `memory` 文件夹
2. **说明现状**：如果这边还没有产生，说明记忆尚未落盘
3. **说明机制**：记忆可以跨越工程、跨越会话，记录习惯、偏好与经验教训
4. **给出建议**：需要长期生效的约定，**写进提示词**才是可靠做法

## 四、关键结论

1. **Coding Agent 通常内置长期记忆系统**，会记录沟通中沉淀的经验和教训。
2. **落盘形式不一**：本地 SQLite 数据库或文件。
3. **Codex 位置**：用户主目录下的 `memory` 文件夹。
4. **记录内容**：用户习惯、偏好、经验教训。
5. **跨工程、跨会话生效**——这是它区别于会话上下文的关键。
6. **它是黑盒**：记录什么、何时记录，各家实现都不一样。
7. **Claude Code 肯定有；Codex 不确定，不要太指望**。
8. **实践建议：需要长期生效的约定要写进提示词**，不要依赖记忆系统。
9. **最佳实践⑥：奖罚分明，有利于形成长期记忆**。

## 本节要点回顾

- **长期记忆 = 跨工程、跨会话**的经验沉淀（区别于会话上下文）。
- 落盘：**SQLite 或文件**；Codex 在用户主目录 `memory/`。
- 记录：**习惯 / 偏好 / 经验教训**。
- **黑盒**：记录什么、何时记录都不透明。
- **Claude Code 有；Codex 不确定**——别太指望。
- **可靠做法：需要长期生效的约定，写进提示词**。
- **最佳实践⑥：奖罚分明，有利于形成长期记忆**。
- 学完这一章，Coding Agent 不再神秘——**没有黑魔法，都是前面几章的机制在组合**。
