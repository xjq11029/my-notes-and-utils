## 课程主线（一句话版）

**所有 Coding Agent 机制本质相同——「告诉模型有哪些能力可用 → 模型决定调用 → Agent 执行 → 结果回灌模型」；差别只在于「什么时候告诉模型、告诉多少」。串起全部机制的暗线，是上下文管理。**

## 术语表（英文缩写 + 中文注释）

> 按「首见章节」排序；术语在各章正文首次出现处均有上下文解释。

### 基础概念（第 1 章）

| 术语 | 中文注释 | 首见 |
|---|---|---|
| Agent | 代理 / 智能体——代理用户与模型通信的程序；**不是严格技术名词**（类比「H5」） | ch1 |
| Coding Agent | 编程代理——Claude Code、Codex、OpenCode 等，工具调用的真正执行者 | ch1 |
| Tools / Function Calling | 工具 / 函数调用——模型可调用的能力，本质就是函数 | ch1 |
| 六步流程 | 加提示词 → 传模型 → 返回 JSON → Agent 执行 → 结果回灌 → 循环至最终答案 | ch1 |
| `command` / `read` / `write` / `delete` | 内置四类常用工具（多数功能也基于 `command` 实现） | ch1 |
| vibe coding | 氛围编程——凭感觉描述需求，让 AI 自由发挥 | ch1 |
| spec coding | 规范驱动开发（SDD）——先写规格文档，再让 AI 按规格实现 | ch1 |

### 会话与提示词（第 2–3 章）

| 术语 | 中文注释 | 首见 |
|---|---|---|
| Conversation / Session / Thread | 会话的三个叫法——同一会话内，每次发消息都要带上**全部历史** | ch2 |
| Token | 词元——上下文越长消耗越大，且越易产生幻觉 | ch2 |
| 全局提示词 | 存于用户主目录，所有工程生效（Claude Code：`~/.claude/CLAUDE.md`；Codex：`~/.codex/AGENTS.md`） | ch3 |
| 工程提示词 | 存于工程根目录，仅当前工程生效（`CLAUDE.md` / `AGENTS.md`） | ch3 |
| 无头苍蝇效应 | 缺少工程提示词时，模型不知从哪下手，反复用 tools 探索工程 → 上下文暴涨 | ch3 |

### 深度思考（第 4 章）

| 术语 | 中文注释 | 首见 |
|---|---|---|
| 深度思考 / 推理 / 思维链 | 同一件事的三个叫法——模型先输出思考过程，再据此产出最终回复 | ch4 |
| 思考过程 | 相当于**模型给自己生成的更完善的提示词** | ch4 |

### 工具协议（第 5–6 章）

| 术语 | 中文注释 | 首见 |
|---|---|---|
| MCP | Model Context Protocol——可简单理解为「**一个 Tool 的集合**」，第三方编写的独立进程 | ch5 |
| MCP Server | MCP 服务进程——本地启动或远程 HTTP 访问 | ch5 |
| 发现工具 | Agent 向 MCP 询问「你提供哪些工具」，MCP 返回标准化工具列表 | ch5 |
| MCP 调用循环 | 模型 → Agent → MCP 工具 → 结果 → 模型，反复直至信息足够 | ch5 |
| `npx` / `uvx` | 启动 MCP 的命令：Node 写的用 `npx`，Python 写的用 `uvx` | ch5 |
| Skill | 技能——本质是提示词（`SKILL.md`），**渐进式**加载 | ch6 |
| `SKILL.md` | 技能文件；`name` 必须与文件夹同名，`description` 决定何时被触发 | ch6 |
| Progressive Disclosure | 渐进式披露——先给指引，需要时再取详细内容 | ch6 |
| 技能商店 | <https://skills.sh/>；`find-skill` 找技能、`create-skill` 造技能 | ch6 |
| CLI | Claude Code 提出的**渐进式工具**概念——只告知一句话，按需运行命令查询子命令 | ch6 |

### 隔离与记忆（第 7–8 章）

| 术语 | 中文注释 | 首见 |
|---|---|---|
| Sub Agent / 子代理 | 拥有独立系统提示词与独立会话上下文的代理 | ch7 |
| 内置子代理 | 系统内置、用户无法干预（黑盒）；如写代码、分析需求、制定计划、长期记忆 | ch7 |
| 用户子代理 | 用户通过提示词启动，用于并行、独立的开发任务 | ch7 |
| 长期记忆 | 跨工程、跨会话的记忆系统；Codex 存于用户主目录 `memory/` 文件夹 | ch8 |

## 全课程核心结论速查

1. **Agent 是个程序**——模型只输出「想调用什么」（JSON），真正执行工具的是 Agent。
2. **六步流程**是全部机制的骨架：提示词 → 模型 → JSON → Agent 执行 → 结果回灌 → 循环。
3. **会话 = 每次携带全部历史**；Token 随轮次近似指数增长，且越长越易幻觉——**「装得下，但记不住」**。
4. **写提示词的目的是减少上下文**：不写 → 模型无头苍蝇 → 反复探索 → 上下文暴涨。
5. **深度思考 = 模型给自己写更完善的提示词**；档位动态调节，调到顶仍不行就靠工具链。
6. **MCP = 一个 Tool 的集合**，独立进程 + 标准化协议；缺点是**非渐进式**，工具列表全量下发 → 上下文爆炸。
7. **Skill 用渐进式解决提示词过大**：会话开始只给 `description` 一行，需要时才加载正文。
8. **Skill 目前优于 MCP**（工具调用非高频），但**不能完全替代**——执行工具时 MCP 更干脆。
9. **CLI 是渐进式工具的下一步**；渐进式处理上下文是未来主流。
10. **Sub Agent 的价值在隔离**：独立上下文、可并行、能力专注；多数情况需用户显式指定开启。
11. **长期记忆不可全指望**——需要长期生效的约定，写进提示词才可靠。
12. **一条暗线贯穿全课**：Skills、CLI、Sub Agents 无一例外，都是为了**精简 / 隔离上下文**。
