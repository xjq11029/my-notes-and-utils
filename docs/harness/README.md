# Agent Harness 深度讲解

一份关于 **Agent Harness（智能体脚手架 / 运行时控制层）** 的深度技术讲解，以及配套的可运行最小 Harness 演示代码。

内容从底层思想出发，经第一性原理推导、结构解剖、可运行实现，最终落到 Codex 的源码级实现与横向案例对比。

### `code/minimal_harness.py`

用一个脚本化的 Mock LLM（**无需 API Key，可完全离线运行**）演示一件事：**模型一个字都没改，只替换外面的 harness，任务成功率就完全不同。**

六个版本递进，每版都带"对照 A（缺该机制）/ 对照 B（有该机制）"：

| 版本 | 新增机制 | 它解决的问题 | 对照结果 |
|---|---|---|---|
| v0 | （无） | 模型碰不到世界 | 声称已修复，但文件一行没动 → 0 passed |
| v1 | ReAct 循环 + 工具 | 模型无法行动 | 能真正改文件了，但会过早收工 → 1 passed |
| v2 | 权限与沙箱 | 提示注入导致灾难 | 无策略：`src` 被删除；有策略：`rm` 被拦截 |
| v3 | 状态持久化 | 跨会话失忆 | 无状态：会话 2 误判完成；有状态：2 passed ✅ |
| v4 | 上下文压缩 | 上下文膨胀 | 坏摘要：文件回退；好摘要：进度保住 |
| v5 | 验证门 | 未验证就宣布完成 | 拒绝一次「完成」后 → 2 passed ✅ |

## 如何使用

### 阅读讲解

直接双击 `agent-harness-deep-dive.html`，或用任意浏览器打开。无需联网、无需启动服务。

### 运行演示代码

只依赖 Python 标准库，不需要安装任何第三方包：

```bash
cd code
python minimal_harness.py            # 运行六个对照实验，结束时自动清理临时工作区
python minimal_harness.py --keep     # 保留临时工作区，便于逐个检查中间状态
```

预期输出：六个版本的对照实验，最后打印汇总表。全程离线（无网络请求、无随机数），**结果确定可复现**——临时目录路径每次不同，但所有判定结果一致。

### 核心结论

- **Agent = Model + Harness**。模型负责判断"下一步该做什么"，harness 负责决定"这一步如何落到真实世界，以及是否放行"。
- 长周期任务必然带来五个问题：**上下文腐化、错误累积、跨会话失忆、权限越界、无法自验**。harness 的每个组件都是为对冲其中之一而存在。
- **Codex 采用了这套思想，并把它作为核心工程方法论**（OpenAI 于 2026 年 2 月连发两篇官方文章）。
- 但 harness 不是越厚越好，也不是某一家的最好：模型与脚手架是共同演化的，正确的比较单位永远是 **Model + Harness**，而不是单独的模型 ID。

## 维护约定

### `agent-harness-deep-dive.html`

- 保持**单文件自包含**，不要引入外部 CDN 依赖（需支持离线打开）
- 深色主题，所有 SVG 必须使用**显式 `fill`**，不要依赖颜色类
- 代码块内的 `<` `>` `&` 必须转义为 `&lt;` `&gt;` `&amp;`
- 新增章节需同步更新左侧 `nav.toc` 的锚点链接
- 事实性数据必须标注来源与时间；单一来源无法交叉验证的需标注"据公开资料"

### `code/minimal_harness.py`

- 修改后必须**实际运行验证**，确保六版对照结果符合预期（见上方表格）
- 文件列表统一使用 POSIX 风格路径（`as_posix()`），避免 Windows 反斜杠导致"模型"匹配失败
- 工具输出截断只应用于命令类输出（`bash` / `run_tests`），不要应用到文件读取，否则会把代码截成语法错误
- **注意"崩溃参数"不要跨会话复用**：模拟进程中断的 `crash_after_writes` 只能给"会话 1"用，会话 2 必须用不带该参数的配置，否则输出会出现误导性的"进程被中断"标记
- 新增 demo 时记得用 `make_workspace()` 创建沙箱，它会自动登记到退出清理列表

## 已知限制

- HTML 中的源码级细节（函数名、常量值、语法格式）来自公开仓库的第三方源码分析，如与最新版本有出入，以仓库实际代码为准。
- 厂商官方数据（如 OpenAI 的 1500 个 PR、Anthropic 的 200+ features）来自官方文章，未做独立验证。
- 演示代码里的"模型"是脚本化的 Mock LLM，用于隔离 harness 变量。它刻意做得很"笨"（不会规划、不会反思），这样 harness 的价值才清晰可测——如果模型很聪明，就分不清功劳是谁的。
