### 核心结论

- **Agent = Model + Harness**。模型负责判断"下一步该做什么"，harness 负责决定"这一步如何落到真实世界，以及是否放行"。
- 长周期任务必然带来五个问题：**上下文腐化、错误累积、跨会话失忆、权限越界、无法自验**。harness 的每个组件都是为对冲其中之一而存在。
- **Codex 采用了这套思想，并把它作为核心工程方法论**（OpenAI 于 2026 年 2 月连发两篇官方文章）。
- **"Harness" 有三种用法**：软件测试的 test harness、本档采用的主流用法（模型之外的控制层），以及一支把它等同于 "Best-of-N + LLM as Judge 择优" 的旁支用法——旁支描述的是主流用法内部的一个子系统，不是并列概念。
- 但 harness 不是越厚越好，也不是某一家的最好：模型与脚手架是共同演化的，正确的比较单位永远是 **Model + Harness**，而不是单独的模型 ID。

## `code/minimal_harness.py`（演示代码）

用一个脚本化的 Mock LLM（**无需 API Key，可完全离线运行**）演示一件事：**模型一个字都没改，只替换外面的 harness，任务成功率就完全不同。**

六个版本递进，每版都带"对照 A（缺该机制）/ 对照 B（有该机制）"：

| 版本 | 新增机制 | 它解决的问题 | 对照结果 |
|---|---|---|---|
| v0 | （无） | 模型碰不到世界 | 声称已修复，但文件一行没动 → 0 passed |
| v1 | ReAct 循环 + 工具 | 模型无法行动 | 能真正改文件了，但会过早收工 → 1 passed |
| v2 | 权限与沙箱 | 提示注入导致灾难 | 无策略：`src` 被删除；有策略：`rm` 被拦截 |
| v3 | 状态持久化 | 跨会话失忆 | 无状态：会话 2 误判完成；有状态：2 passed ✅ |
| v4 | 上下文压缩 | 上下文膨胀 | 坏摘要：文件回退；好摘要：进度保住 |
| v5 | 验证门 | 未验证就宣布完成 | 拒绝一次「完成」后 → 2 passed ✅ |

## 如何使用

### 阅读讲解

- **精读版**：直接双击 `agent-harness-deep-dive.html`，或用任意浏览器打开。无需联网、无需启动服务。
- **纯文本版**：用任意 Markdown 编辑器打开 `harness-from-principle-to-codex.md`；图片为相对路径引用，保持在仓库内即可正常显示。

### 运行演示代码

只依赖 Python 标准库，不需要安装任何第三方包：

```bash
cd code
python minimal_harness.py            # 运行六个对照实验，结束时自动清理临时工作区
python minimal_harness.py --keep     # 保留临时工作区，便于逐个检查中间状态
```

预期输出：六个版本的对照实验，最后打印汇总表。全程离线（无网络请求、无随机数），**结果确定可复现**——临时目录路径每次不同，但所有判定结果一致。

| **HTML 居中不可靠** | 本地预览器把 `<div align="center">` 转义成纯文本（用户截图实证）；知乎同样剥离。而发布稿要在多个环境里都能看 | 按 Xjq 的选择，**把图号烧进图片**：给抽取脚本加 `--label`，在每张图底部注入一行居中的「图 N」（viewBox 高度 +34）。⚠️ 底栏放在**原 viewBox 之外**——各图底部留白从 6px 到 38px 不等，塞进留白会让留白小的图（如图 5，仅 6px）压到内容。MD 里那 13 行 HTML 全部删除，说明段保留 |
| **顺手修掉一个静默陷阱** | 自查时发现：按 `articles/README.md` 记录的再生成命令**重跑抽取，13 张里只有图 6 与现有文件不一致**——图 6 图内「与 3.1 的组件表一致」这条修正**只落在抽出的 SVG 上、没进 HTML 源**（`3.1` 在长文里是对的，只有发布稿重编号后才失效）。也就是说**重跑抽取会复活死引用** | 给脚本加 `--replace OLD=NEW`（可重复；规则是**全局**的，一条规则可能只命中其中一张图，**全程 0 命中才报错**），把这条修正写进再生成命令。**手改产物、不改源 = 隐式差异**，现在源与产物之间不再有 |
| **结构校验** | — | SVG：13/13 viewBox +34、底矩形同步长高且仍是首个子元素、图号文本与文件名序号一致；PNG：13/13 为 2720 宽 + 深色底（合计 2.46MB）；MD：**0 条 HTML 标签行**、13 张图后均紧跟「空行 + 说明段」、行数 650 → 624、行尾纯 LF（CR=0） |
| **同步落点** | — | `articles/README.md`（再生成命令 / 新增「图号：做进图片里，不靠 HTML」一节 / 差异表 / 「已修正的图内文字」补记陷阱）、`scripts/README.md`（`--label`、`--replace` 参数与用法）、[`docs/README.md`](../README.md)、skill `html-longform-to-publish-post`（图注规则改为「烧进图片」） |

## 已知限制

- HTML 中的源码级细节（函数名、常量值、语法格式）来自公开仓库的第三方源码分析，如与最新版本有出入，以仓库实际代码为准。
- 厂商官方数据（如 OpenAI 的 1500 个 PR、Anthropic 的 200+ features）来自官方文章，未做独立验证。
- 演示代码里的"模型"是脚本化的 Mock LLM，用于隔离 harness 变量。它刻意做得很"笨"（不会规划、不会反思），这样 harness 的价值才清晰可测——如果模型很聪明，就分不清功劳是谁的。
