# 教程写法规范（框架线 · 内部元文件）

> 本文件是 `ch01`–`ch19` 的改写依据，不面向学习者。2026-10-19 第八轮（叙事优先改写）起生效。

## 1. 起因

用户反馈：框架线的写法与 `docs/harness/`（Agent Harness 深度讲解）、`docs/大模型与神经网络原理笔记/` 两篇范本不连贯、不易理解。核查确认：框架线的事实与实测纪律强于范本，但**叙述层是「参考手册式」**——节内以「表 + 坑 + 结论」堆叠，缺少问题导入与推导链；范本是「叙事式」——每个概念先被一个问题逼出来，再展开。第八轮的目标：**把框架线的叙述层改为叙事优先，事实层一字不动**。

## 2. 范本特征（两篇共通的五条）

| # | 特征 | 范本实例 |
|---|---|---|
| 1 | **问题驱动开场**：从具体症状 / 困惑 / 场景进入，不从定义进入 | harness 开篇「模型是无状态函数 f(text)→text，四件事做不到」；大模型「用户传入一段自然语言 → 得到一段回复」 |
| 2 | **一句话主线先行**：开篇即告知本篇要去哪儿 | 大模型 README「基础模型 → 模型服务 → AI 应用 → …」主线一句话版 |
| 3 | **推导链**：每个新概念出现前，先讲它被什么问题逼出来 | harness 刻意避开组件清单式讲法，「读者记不住不知道每个组件是被什么问题逼出来的」 |
| 4 | **类比台阶**：用日常类比降低新概念门槛，类比只做台阶、不做论证 | 冯·诺依曼计算机（CPU/RAM/磁盘）、梯度下降「黑夜下山」、洋葱模型「快递包装」 |
| 5 | **从机制答为什么**：不只说是什么，更说为什么这样设计 | 大模型「输出为什么贵 = 自回归每生成一个 token 就要把整段输入再走一次前向」 |

## 3. 框架线既定纪律（不可动）

1. **章节骨架**：`## 一、这一章要解决的问题` → `## 二、机制与原理` → `## 三、代码：Python 与 TypeScript` → `## 四、常见坑与边界条件` → `## 五、关键结论` → `## 本章要点回顾`（ch01 第三节为「安装与环境」，无代码节，属既定例外）。
2. **结论与回顾分工**：`五、关键结论` 只放可迁移判断（3–5 条）；`本章要点回顾` 只做可勾选清单；**同一事实只出现一次**。
3. **四级口径**：示例实测 / 本机核对 / 源码核对 / 未实测。每条结论必须带口径；口径标签可以**移位或精简措辞**（如从句中移到句末括号、节末集中），但**不可删除、不可升级**（未实测不得写成实测）。
4. **双语言一一对应**：代码块只允许改注释与排版，不允许改逻辑；两段代码必须保持同一件事。
5. **图号**：全局连续且按出现顺序递增；图注、README 配图索引、`_写作大纲与来源登记.md` 三处联动——改写不新增 / 不删除图，图号即不动。
6. **引用**：跨章引用（「第 N 章」）、节号引用（「2.2 节」「第四节坑 2」）、文件路径引用必须保持有效；**节号与节标题不改**（它们是全书的引用锚点）。
7. **术语表**：README 术语表的「首见」章节不得因改写而漂移。

## 4. 改写规则

### 4.1 可做（叙述层）

1. **章首强化**：`一、这一章要解决的问题` 用症状 / 场景导入（改前允许），并补一句**一句话主线**（「本章回答：……」）。
2. **节首接缝**：每节（x.y）开头补一句「讲什么、为什么现在讲」——推广 ch02 第五轮接缝修复的范式到全部章节。
3. **节内重排叙述顺序**：先问题 / 场景 → 再机制 → 后数据；表格、代码是论据，论据之前必须有「要回答什么」的框定（保留既有的「下表回答的问题是：…」引导语范式）。
4. **重参考块后置**：大块参考材料（长列表、口径总表、版本表）可移到所在节末尾或章末「参考块」，**内容一字不删**，只在正文留一句指向。
5. **补类比台阶**：为新概念配日常类比，注明「类比」身份；不得用类比替代机制解释。
6. **过渡句**：节与节之间、表与表之间、代码与解释之间，补承上启下的句子。
7. **口径标签后置**：把句中插队的口径标签改为句末括号或节末集中标注，减少叙事打断；标签与结论的对应关系不得丢失。

### 4.2 不可做（事实层）

1. 改任何事实、数字、API 名、参数名、默认值、版本号、日期。
2. 删除或弱化任何口径标签；把「未实测」写成既成事实。
3. 改节号、节标题、图号、图注、代码块逻辑、跨章引用、文件路径。
4. 新增无出处的事实或性能数字（查不到出处的数字不采用）。
5. 改变 `五、关键结论` 与 `本章要点回顾` 的内容分工（可改写法，不可改分工与去重规则）。

## 5. 每章自检清单

- [ ] 章首有症状导入 + 一句话主线
- [ ] 每节开头有「讲什么、为什么现在讲」
- [ ] 通读 diff：事实、数字、口径标签与改前完全一致（只有位移与措辞精简）
- [ ] 图号 / 代码块 / 引用零改动
- [ ] 结论与回顾仍满足分工去重
- [ ] 盖住目录能口述本章主线；随便截一段问「这段在回答什么问题」能有确定答案
