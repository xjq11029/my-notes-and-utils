# 教程写法规范（框架线 · 内部元文件）

> 本文件是 `ch01`–`ch19` 的改写与一致性修复依据，不面向学习者。2026-10-19 第八轮（叙事优先改写）起生效；2026-10-21 第十轮补入图文码一致性与最小例子规则。

## 0. 适用范围与两条轨道

- **适用范围**：框架线 `ch01`–`ch19`。手写线 `handwritten/` 不强制适用；若要借用，另开一轮并单独核查。
- **轨道 A｜叙述改写**：只改叙述层，事实层冻结（第八轮的做法）。
- **轨道 B｜一致性修复**：代码 / 参数 / 图 / 正文互相矛盾时，允许改事实、表头、图注、图内容和代码输出字符串；必须按 §4.3 登记证据并重跑构建。
- **裁决顺序**：事实准确（有实跑 / 源码依据）> 口径 > 叙事 > 形式。冲突时先保事实，再保口径，最后才谈叙述。

## 1. 起因（用户反馈与核查诊断分开）

**用户反馈（2026-10-21 回溯）**：

1. 教程写法没有参考 `docs/harness/` 与 `docs/大模型与神经网络原理笔记/`，不连贯、不易理解；
2. `ch02` 的代码参数与下文是否一致（附截图）；
3. 图片与下文引起的语义问题；
4. 缺少简单易懂的例子。

**核查诊断（不是用户原话）**：叙述层偏「参考手册式」；此外存在代码 / 参数 / 图 / 正文不一致，以及缺少最小例子。第八轮只处理了第 1 条的叙述层；第十轮补第 2–4 条。

## 2. 范本特征（两篇共通的七条）

| # | 特征 | 范本实例 |
|---|---|---|
| 1 | **问题驱动开场**：从具体症状 / 困惑 / 场景进入，不从定义进入 | harness §2.1「模型是一个无状态函数」+「四件事」；大模型「用户传入一段自然语言 → 得到一段回复」 |
| 2 | **一句话主线先行**：开篇即告知本篇要去哪儿 | 大模型 README「基础模型 → 模型服务 → AI 应用 → …」主线一句话版 |

## 3. 框架线既定纪律

1. **章节骨架**：`## 一、这一章要解决的问题` → `## 二、机制与原理` → `## 三、代码：Python 与 TypeScript` → `## 四、常见坑与边界条件` → `## 五、关键结论` → `## 本章要点回顾`。例外：`ch01` 第三节为「安装与环境」；`ch19` 末尾另有 `## 全书回顾`。
2. **结论与回顾分工**：`五、关键结论` 只放可迁移判断（新改写 3–5 条；存量例外见 §3 第 8 条）；`本章要点回顾` 只做可勾选清单；**去重范围限定为「结论与回顾之间」**——正文中的必要复述、主线句、接缝句不计入重复。纯事实不得在结论里罗列。
3. **口径**：四级口径为**示例实测 / 本机核对 / 源码核对 / 未实测**，允许子标注：
   - 示例实测（假模型 / 真实模型 / 构造层）
   - 本机核对（签名 / 字段 / 构造层）
   - 源码核对（docstring / 推断）
   - 未实测（需 Key / 需账号 / 需额外安装）

   别名映射：`本机实测` → 本机核对；`字段核对` / `构造层实测` / `假模型实测` → 对应的父级 + 子标注；`推断` → 源码核对（推断）或标「判断」。每条**实证**结论必须可追溯到口径（邻近标注，或节末集中并给出对应关系）；规范性判断标「判断」或省略。口径标签**不可删除、不可升级**。
4. **双语言一一对应**：代码块只允许改注释、排版与输出字符串，不允许改逻辑；两段代码必须保持同一件事；输出字符串必须与实跑输出一致。
5. **图号**：**严格按正文出现顺序全局连续**（2026-10 增补轮起取消全部编号例外）；新增图插入后其后图号顺延；图注、README 配图索引、`_写作大纲与来源登记.md` 三处联动；改图后必须重渲染 PNG 并重跑 HTML。
6. **引用**：跨章引用、节号引用、文件路径引用必须保持有效。**叙述改写轮次不得改节号 / 节标题**；事实修正若必须改，须同步全量引用并登记（见 §4.3）。
7. **术语表**：README 术语表的「首见」指**首次正式定义 / 展开的章节**，前向引用不计；不得因改写而漂移。
8. **存量例外与整改**：
   - `ch01` 第三节、`ch19` 全书回顾；
   - 关键结论超过 5 条的存量章节：**当前无**（批次 1–4 已全部收敛到 3–5 条）；新改写必须满足 3–5 条；
   - 结论未逐条标注口径的存量章节，按「实证结论可追溯」逐步补；不得把未标注的写成已实测。

## 4. 改写规则

### 4.1 可做（叙述层）

1. **章首强化**：`一、这一章要解决的问题` 用症状 / 场景导入，并补一句**可独立摘出的一句话主线**（「本章回答：……」或「一句话主线：……」均可）。
2. **节首接缝**：每节（x.y）开头点出上一节留下的问题 / 为什么现在讲。
3. **节内重排**：先问题 / 场景 → 再机制 → 后数据；表格、代码前必须有「要回答什么」的框定（保留「下表回答的问题是：…」范式）。
4. **重参考块后置**：大块参考材料（> 20 行或 > 3 张表）可移到节末或章末「参考块」，内容不删，正文留一句指向。
5. **补类比台阶**：为新概念配日常类比，标注「类比」身份；类比只做台阶，不得替代机制解释；**类比不是最小例子**。
6. **补最小例子**：每个新概念先给 3–10 行、或 3 步「输入 → 输出」的具体例子，再给完整示例；最小例子要能独立读懂，最好可运行；完整示例标注「完整版」。
7. **过渡句**：节与节、表与表、代码与解释之间补承上启下。
8. **口径标签后置**：可移到句末括号或节末集中标注；集中时必须给出「哪几条对应哪档」的对应关系；不得丢失、不得升级。
9. **图文互证**：新增 / 改写的图必须在正文有对应解释；图只画子集时图注写明「只画了……」；图注不得引入正文没有的结论。

### 4.2 不可做（叙述改写轮次的事实层）

1. 不得改任何事实、数字、API 名、参数名、默认值、版本号、日期。
2. 不得删除或弱化任何口径标签；不得把「未实测」写成既成事实。
3. 不得改节号、节标题、图号、图注、代码块逻辑、跨章引用、文件路径。
4. 不得新增无出处的事实或性能数字（查不到出处的数字不采用）。
5. 不得改变 `五、关键结论` 与 `本章要点回顾` 的内容分工与去重规则。

### 4.3 一致性修复（轨道 B，允许改事实）

触发：代码 / 参数 / 表 / 图 / 正文互相矛盾，或用户明确指出不一致。

1. **真源顺序**：实跑输出 > 可运行代码 > 正文 / 图注；官方文档只在无本地证据时使用，并标口径。
2. **四者互证**：代码签名、参数表、正文、实跑输出逐项对齐；表头必须与列内容同义；每个参数名 / 数字 / 默认值可追溯。
3. **图-文-码互证**：图里每个元素、数量词、分类在下文有解释；图只画子集时注明；图注不超出正文；代码注释 / 输出字符串与实跑输出一致。
4. **允许改**：正文事实、表头 / 表格、图注 / 图内容、代码注释与输出字符串；不改代码逻辑，除非代码本身是错误源且有实跑证据。
5. **必须做**：重跑受影响示例 → 更新 `_实测输出核验/` → 重渲染 SVG / PNG（2×）→ 重跑 `_build_html.py` 两次 md5 一致 → 更新 README / 大纲 / 术语表。
6. **登记**：每条修正记录位置、旧值、新值、依据（输出文件 / 源码 / 官方 URL）与日期。

## 5. 每章自检清单

- [ ] 章首有症状导入 + 可独立摘出的主线句。
- [ ] 每节开头有「讲什么、为什么现在讲」。
- [ ] 新概念有最小例子（3–10 行 / 3 步），完整示例已标注。
- [ ] 关键结论 3–5 条（或属 §3 第 8 条存量例外）；纯事实不在结论里。
- [ ] 结论与回顾之间无重复事实；正文必要复述与导航句不计。
- [ ] 每条实证结论可追溯到口径；规范性判断标「判断」；无「未实测」升级。
- [ ] 代码签名 / 参数表 / 正文 / 实跑输出一致；表头与列内容同义。
- [ ] 图 / 文 / 码一致：图中元素、数量词、分类都有解释；图注不超出正文。
- [ ] Python / TS 代码逻辑一一对应；输出字符串与实跑输出一致。
- [ ] 图号 / 图注 / README 配图索引 / 大纲同步；图号 1–38 严格连续、无缺号重号。
- [ ] 术语表首见未漂移（按正式定义口径）。
- [ ] 重跑示例；SVG → PNG；`_build_html.py` 连跑两次 md5 一致。
- [ ] 通读 diff：叙述改写轮次中事实 / 数字 / 口径 / 图号 / 引用零改动；一致性修复轮次中每条改动有登记。
- [ ] 盖住目录能口述本章主线；随便截一段能回答「这段在回答什么问题」。
