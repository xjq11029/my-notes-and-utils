## 三、官方文档 vs 本机实测：差异清单

> 写正文时以本表为准。**凡本表列出「实测」结论的地方，正文用实测结论，并标注版本号。**

| # | 主题 | 官方文档的说法 | 本机实测（1.4.2 / 1.2.12 / 0.7.18） | 正文口径 |
|---|---|---|---|---|
| 1 | Deep Agents 默认工具集 | 概览页把 `write_todos` 列为「可选能力，v0.7 起需主动开启」，未给出默认工具清单 | **要区分两个口径**：<br>· 工具节点里注册了 **9 个**：`ls`、`read_file`、`write_file`、`edit_file`、`delete`、`glob`、`grep`、`execute`、`task`<br>· **绑定给模型的只有 8 个**（不含 `execute`）——因为默认后端 `StateBackend` 不提供执行能力，`execute` 不向模型暴露<br>· `write_todos` 两者都没有，必须显式加 `TodoListMiddleware()` | 以实测为准：正文写「注册 9 / 模型可见 8」，并点明「注册了 ≠ 模型看得见」 |
| 2 | `SkillsMiddleware` 的导入位置 | 文档在 Agents 页把它与 `FilesystemMiddleware` 等并列为「来自 `deepagents` 包」 | `deepagents` **顶层不导出** `SkillsMiddleware`；须从 `deepagents.middleware` 导入 | 正文明确写导入路径 |
| 3 | `FilesystemMiddleware` / `SubAgentMiddleware` 的归属 | 文档在 LangChain Middleware 页把它们列入「预置 middleware 清单」 | `langchain.agents.middleware`（1.4.2）**没有**这两个类；它们在 `deepagents` 里 | 正文按包归属分开讲 |
| 4 | MCP 接入 API | 文档用 `MCPAdapter`（`langchain.mcp`，需 `langchain[mcp]`，beta） | 需额外装 `langchain[mcp]`；未装时 `import` 直接 `ModuleNotFoundError: fastmcp` | 正文标注「需额外安装 `langchain[mcp]`」 |
| 5 | `SqliteSaver` | 文档在排障章节直接引用 `langgraph.checkpoint.sqlite` | 默认安装**不含** `langgraph.checkpoint.sqlite`，须另装 `langgraph-checkpoint-sqlite` | 正文标注需单独安装 |
| 6 | 中间件钩子触发顺序 | 文档只给出「模型调用前后」的示意，未给可执行顺序 | 一次含工具调用的完整轮次，实测顺序为：`before_agent` → `before_model` → `wrap_model_call` → `after_model` → `wrap_tool_call` → `before_model` → `wrap_model_call` → `after_model` → `after_agent` | 用实测顺序画图 10、写 ch06 |
| 7 | `create_agent` 的完整参数 | 文档正文只列了部分参数 | 实测签名含 `interrupt_before` / `interrupt_after` / `cache` / `transformers` 等文档正文未列出的参数 | 正文参数表按实测签名给全 |
| 8 | `stream_mode` 取值 | 文档列 7 种：values / updates / messages / custom / checkpoints / tasks / debug | 与文档一致 | 按文档 |
| 9 | 无 reducer 的字段在新一轮 `invoke` 时的行为 | 文档只讲 reducer 语义，未讲「同一线程再次 invoke 时输入如何进入状态」 | 实测：**无 reducer 的字段被输入直接覆盖**（`n=1` 的线程再传 `n=100` → 100 → 节点后 101）；**有 `add_messages` 的字段则是追加** | ch11 用实测结论讲清「同一线程再次 invoke」的语义 |
| 10 | `deepagents` 的图节点名 | 文档未给 | 实测节点：`__start__` / `model` / `tools` / `<各中间件>.before_agent` / `__end__`；开启 memory / skills / interrupt 后新增 `MemoryMiddleware.before_agent`、`SkillsMiddleware.before_agent`、`HumanInTheLoopMiddleware.after_model` | 图 26 按实测节点名画 |
| 11 | `HarnessProfile` 的字段 | 文档只提到 `excluded_tools` / `excluded_middleware` | 实测签名：`base_system_prompt`、`system_prompt_suffix`、`tool_description_overrides`、`excluded_tools`、`excluded_middleware`、`extra_middleware`、`general_purpose_subagent` | 正文按实测给全 |
| 12 | `SubAgent` 的字段 | 文档只列 `name` / `description` / `system_prompt` / `tools`（可选 `model` / `middleware`） | 实测还有 `interrupt_on`、`skills`、`permissions`、`response_format`、`mode`（`isolated` \| `fork`） | 正文按实测给全 |
| 13 | `ToolException` / `handle_tool_error` | 文档未提 | v1 的 agent 路线**不再推荐**（但 **API 未删除**：`langchain.tools` 仍导出 `ToolException`，`StructuredTool` 仍有 `handle_tool_error`，`langchain/mcp/tools.py` 仍在用）；错误处理改走 `@wrap_tool_call` 中间件或 `ToolErrorMiddleware` | ch07 明确写「不再推荐，但未删除」——**不要写成「已废弃」** |
| 14 | `InjectedState` / `InjectedStore` / `get_runtime()` | 文档列为「旧注入模式」 | 实测确认新写法统一走 `runtime: ToolRuntime` 参数 | ch07 给新旧对照表 |
| 15 | **工具抛异常的默认行为** | 文档讲错误处理时只说「用 middleware」 | **两语言不同**：Python 异常**原样抛出**（`ZeroDivisionError` 终止整个调用）；JS 被 `ToolNode` **吞成 error `ToolMessage`**（内容形如 `Error: …\n Please fix your mistakes.`），流程继续 | ch07 §2.7 用对照表写清；已在 `code/README.md` 差异清单第 15 条登记 |
| 16 | **JS 有两个同名 `InMemoryStore`** | 文档未提 | `langchain` 也导出 `InMemoryStore`，但**没有** `put` / `get` / `batch`；传进 `createAgent({store})` 后在 `runtime.store.put` 报 `this.store.batch is not a function`。**必须**从 `@langchain/langgraph` 导入 | ch07「常见坑」；已在 `code/README.md` 差异清单第 16 条登记 |

2. **不臆造数字**：厂商宣传数字标注来源与时间；查不到出处的性能数字不采用。
3. **英文逐字引用必附中译**。
4. **改示例代码必须重跑**，输出同步到正文与 `code/README.md`。
5. **双语言示例一一对应**：同一编号的 `.py` 与 `.ts` 演示同一件事，输出语义一致（措辞可因语言习惯不同）。
