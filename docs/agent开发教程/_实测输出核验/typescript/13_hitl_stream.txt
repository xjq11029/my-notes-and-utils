==============================================================================
① interrupt / resume 的完整往返
==============================================================================
  第一次 invoke（会停在 interrupt）：
    __interrupt__ = {"question":"确认扣款 199 元？","amount":199}
    此时状态：{"amount":199,"status":"待审批"}
    待执行节点 next = ["approval"]

  第二次 invoke（用 Command resume 恢复）：
    最终状态：{"amount":199,"status":"已扣款"}

  副作用日志（看清「节点从头重跑」这件事）：
    1. 节点开始，读到 amount=199
    2. 节点开始，读到 amount=199

  ⚠️ 看到没——「节点开始，读到 amount=199」出现了**两次**：
     恢复不是从中断那一行继续，而是把整个节点**从头再执行一遍**。
     所以 interrupt() 之前的代码必须是幂等的；
     真正的副作用（扣款）要放到 interrupt() **之后**的节点里。

==============================================================================
② streamMode：同一张图，多种投影
==============================================================================
  streamMode="values"    → [{"n":0,"note":""},{"n":1,"note":"第 1 步完成"}]
  streamMode="updates"   → [{"step":{"n":1,"note":"第 1 步完成"}}]
  streamMode="custom"    → ["进度：正在处理第 1 步"]

  各档给你的东西：
    values  每步之后的**完整状态**（体积最大，但最省心）
    updates 每步节点返回的**增量**（带节点名，适合做进度条）
    custom  节点里用 getWriter() 主动推的事件（适合推「第 3/10 步」）
    debug   checkpoints + tasks 的合并，信息最多
  另有：messages（LLM 逐 token，最常用于打字机效果）、checkpoints / tasks

==============================================================================
③ 坑：agent 放进父图当子图后，内部消息默认不透传
==============================================================================
  A. 直接 stream 子 agent —— 3 个分块，内部消息一览无余：
       ns=() node=model_request [AIMessageChunk] ""
       ns=() node=tools [ToolMessage] "x 的结果"
       ns=() node=model_request [AIMessageChunk] "查完了。"

  B. 父图 stream，**不加** subgraphs —— 1 个分块：
       ns=() node=model_request [AIMessageChunk] "查完了。"
       ↑ 只剩跨边界的少数几条，模型内部的 token 全没了
         （具体条数取决于版本与实现，Python 侧实测是 2 条、JS 侧是 1 条——
          重点是「子图内部的消息被吞掉了」这件事，不是数字）

  C. 父图 stream，**加** subgraphs —— 1 个分块：
       ns=agent node=model_request [AIMessageChunk] "查完了。"
       ↑ 分块带上了 namespace，能区分「这是哪个子图吐出来的」

  ⚠️ 因为 createAgent 返回的是**已编译的图**，把它当节点加进父图，它就变成了子图。
     子图的内部输出默认不透传——这就是「图能跑、结果也对，
     但打字机效果莫名其妙没了」的原因。要透传就显式加 subgraphs: true。

==============================================================================
④ 七档 streamMode：每种投影给你什么形状
==============================================================================
  values       2 个分块，首块类型 object
  updates      1 个分块，首块类型 object
  custom       1 个分块，首块类型 string
  checkpoints  3 个分块，首块类型 object
  tasks        2 个分块，首块类型 object
  debug        5 个分块，首块类型 object
  messages     1 个分块
  → values/updates/custom/checkpoints/tasks/debug 不需要模型；messages 需要图里有模型节点。

==============================================================================
⑤ list-mode + subgraphs：分块形状怎么解
==============================================================================
  streamMode=['updates','custom'] → [["custom","进度：正在处理第 1 步"],["updates",{"step":{"n":1,"note":"第 1 步完成"}}]]
  → JS 每块是 [mode, payload] 数组；Python 每块是 (mode, payload) 二元组。
  ns=child mode=custom payload="进度：正在处理第 1 步"
  ns=child mode=updates payload={"step":{"n":1,"note":"第 1 步完成"}}
  ns=() mode=updates payload={"child":{"n":1,"note":"第 1 步完成"}}
  → 加 subgraphs: true 后是 [namespace, mode, payload] 数组；Python 侧是三元组。

⑥ astreamEvents：模型级事件流
==============================================================================
  model.streamEvents → ["on_chat_model_start","on_chat_model_stream","on_chat_model_end"]
  ⚠️ agent.streamEvents 在 1.4.17 只给 start/end；
     逐 token 用 agent.stream({streamMode:'messages'})，模型自身的 streamEvents 才会给 stream 事件。
