① write_todos：规划能力长什么样
==============================================================================
  状态里的 todos：
    [x] 读需求文档  (completed)
    [~] 设计数据模型  (in_progress)
    [ ] 写接口  (pending)

  write_todos 是**全量覆盖**语义：模型每次都要把整张表重新写一遍，
  而不是「追加一条」。所以状态里的 todos 永远是最新的一张完整表。
  ⚠️ 这也意味着：模型忘掉一条，那条就真的没了——规划列表不是 append-only。

==============================================================================
④ mode 'isolated' 与 'fork'：子代理能看见什么
==============================================================================
  isolated（默认）  子代理拿到**干净的上下文**：只有你派给它的那段任务描述。
                    适合：任务自包含、只需要一句话就能说清。

  fork              子代理**继承主代理当前的对话历史**，再叠加任务描述。
                    适合：任务需要主代理已经积累的上下文才能做对。

  取舍：
    isolated 上下文干净、省 token，但你要把背景写全；
    fork     不用重复背景，但子代理的上下文一开始就很长，
             隔离带来的收益被削掉一部分。

  ⚠️ 子代理的价值是**上下文隔离**，不是「多几个模型并行跑」。
     如果任务之间需要频繁来回对齐，拆子代理反而更慢——
     路由开销 + 交接时的上下文损失，这两项经常被低估。
