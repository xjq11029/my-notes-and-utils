========================================================================
六个钩子的真实触发顺序
========================================================================
   1. before_agent
   2. before_model
   3. wrap_model_call
   4. after_model
   5. wrap_tool_call
   6.         └─ 工具函数体真正执行
   7. before_model
   8. wrap_model_call
   9. after_model
  10. after_agent

  读法：
  · before_agent / after_agent 包住**整个** agent 调用，各只触发一次；
  · before_model → wrap_model_call → after_model 是**每一次**模型调用都走一遍；
  · 轮次里出现了两次 before_model，因为这一轮调了两次模型
    （第一次决定调工具，第二次拿到工具结果后给最终答案）；
  · wrap_tool_call 只在工具执行时出现一次，且夹在两次模型调用之间。

========================================================================
wrap_* 钩子能改写请求：动态切换模型
========================================================================
  第一次调用：消息数 1 ≤ 2 → 用便宜模型
  最终回复："便宜模型的回答"
  第二次调用：消息数 3 > 2 → 换用强模型
  最终回复："强模型的回答"
  → JS 侧改写请求的约定是 `handler({ ...request, model })`；
    Python 侧则是 `handler(request.override(model=...))`。
    两边都保留链上其它中间件的语义，不要直接改 request 对象本身。

========================================================================
③ humanInTheLoopMiddleware：工具调用前停下来等人
========================================================================
  待审批工具 = refund
  允许决策   = ["approve","edit","reject"]
  审批前退款次数 = 0
  approve 后退款次数 = 1，最终回复 = "已处理。"
  reject 后退款次数 = 1（未增加），最终回复 = "已处理。"
  → JS 的载荷字段是 camelCase（actionRequests / reviewConfigs），且只支持 approve/edit/reject；
    Python 多一个 respond 决策。底层同样是 interrupt + checkpointer。

========================================================================
④ piiMiddleware：模型侧只看到脱敏文本
========================================================================
  模型实际收到：["联系 [REDACTED_EMAIL]，卡号 ****-****-****-1111"]
  → 选项名是 camelCase：applyToInput / applyToOutput / applyToToolResults；默认值与 Python 一致。

========================================================================
⑤ 限额：模型调用与工具调用的上限
========================================================================
  modelCallLimit(runLimit=1) → 最后一条："Model call limits exceeded: run level call limit reached with 1 model calls"
  ToolMessage: "上海: 22°C，晴"
  ToolMessage: "Tool call limit exceeded. Do not call 'get_weather' again."

========================================================================
⑥ 重试与回退：toolRetry / modelRetry / modelFallback
========================================================================
  toolRetry(maxRetries=2) → 工具实际调用 3 次，最后回复 = "查到了。"
  modelRetry → "重试成功"（fails 余量 0）
  modelFallback → "备用模型的回答"
  → 重试解决「偶发失败」，回退解决「主模型整体不可用」；两者可以叠加，但顺序决定语义。
