==============================================================================
两种手段的机制差异（这是本示例的核心结论）
==============================================================================

  SummarizationMiddleware
    实现方式：before_model 钩子，返回一条摘要消息，**写回图状态**
    后果    ：状态与模型输入一起变小；原文从当前状态消失
              ⚠️「永久丢失」要加前提：**不配 checkpointer** 才是；
                 配了 checkpointer 时，摘要前那个检查点仍保有原文（第 7 章）
    适用    ：对话很长、旧轮次的细节确实不再需要

  ContextEditingMiddleware
    实现方式：wrap_model_call 钩子，deepcopy 一份消息、改完只传给模型，
              **不回写状态**（源码里是 request.override(messages=edited)）
    后果    ：状态里的历史一条不少（便于审计 / 时间旅行），
              但模型看不到那些被清掉的工具输出
    适用    ：工具输出又大又只用一次（日志、网页正文、检索片段）

  ⚠️ 两者都会造成**静默失败**：清理和压缩本身不报错，
     只是关键信息悄悄没了，后面的回答开始变差——不报错的失败最难查。

  第四种手段「外部存储」不在本章演示：把长内容写进虚拟文件系统或 Store，
  上下文里只留一句「已保存到 /xxx」——见第 11 章与第 13 章。
