# 平台线：腾讯云 ADP（智能体开发平台）

平台线回答的问题是：**不写代码，只靠一个企业级平台，能把智能体做到什么程度？**

框架线（`ch01`–`ch19`）讲的是"用 LangChain / LangGraph 自己搭"，手写线（`handwritten/`）讲的是"框架底下是什么"。本线是第三条：**换到厂商平台视角**，看产品化的智能体开发平台把哪些工程问题做成了配置项，又把哪些判断留给了人。

> **四条线的分工**
> - `docs/harness/`：为什么需要 harness（原理篇）
> - 框架线 `ch01`–`ch19`：用现成框架怎么搭（工程篇）
> - 手写线 `handwritten/`：框架底下是什么（实现篇）
> - **本线**：平台把工程做成了什么形态（产品篇）

## 取材说明（重要）

本线的素材来源与另两条线**不同**：不是官方文档、不是源码，而是**课程页面的长截图**。

| 项 | 值 |
|---|---|
| 原始素材 | `adp/2.1.png`、`2.2上.png`、`2.2中.png`、`2.2下和2.3.png`（浏览器整页截图，宽 1232–1324，高 10 218–13 785） |
| 提取方式 | 裁掉右侧空白（保留 x 40–890）→ 按 1450 px 纵向切片、片间重叠 130 px → 逐片读图转录 |
| 为什么不用录像 | `docs/ADP产品能力.mp4` 曾尝试过：2 fps 抽帧 862 张 → RapidOCR → 拼接。结论是**快速滚动导致帧间内容缺口，且界面截图区域 OCR 全为噪声**，只能还原正文骨架，无法还原表格行序与操作细节。长截图无运动模糊、无缺口，是正确素材形态 |

**素材与产出的边界**（写作时必须守住）：

| 素材里有什么 | 能写成什么 |
|---|---|
| 正文段落 | 可逐字引用（标「本机核对·长截图」） |
| 表格 | 可完整还原（合并单元格需人工判断） |
| 示意图 | 关键机制图**直接裁课程原图嵌入**（仅限本仓库内部笔记，不用于 `articles/` 对外发布稿）；课程没画的补充机制用自绘 SVG |
| 界面截图 | 只提取"页面上有什么"，**不写具体点击路径**（路径需实机验证） |
| 课程数字 | 一律标「课程口径」，视为厂商自述 |

## 章节骨架

沿用框架线六段式，第三节按章节性质落地：

```
## 一、这一章要解决的问题
## 二、机制与原理
## 三、落地：案例与操作        ← 替代框架线的「代码：Python 与 TypeScript」
## 四、常见坑与边界条件
## 五、关键结论
## 本章要点回顾
```

第三节的写法：

- **概念章**（2.x）：以案例为主，按「业务现象 → 三步看图法 → 落到组合 → 失败模式」四段走
- **实操章**（3.x）：以控制台操作路径为主，配界面说明；**没有实机验证的部分必须标「未实测」**

课程原文里的「本节学习目标」「QUIZ」「进入下一节」等平台化组件不搬进正文；QUIZ 若题目有诊断价值，可改写为章首的"常见误解"。
