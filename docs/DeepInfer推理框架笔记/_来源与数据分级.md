## 三、明确「未核实」的内容

以下内容在正文中只作描述，**不当作已验证结论**：

1. **本机运行结果**：本机不满足最低硬件要求（Linux + SM100 / 昇腾 950），无法执行任何示例；正文不写「实测 xx tokens/s」。
2. **V4.1-Flash 的完整模型结构**：仓库只含推理代码与配置读取逻辑，模型权重、训练细节、论文未随仓库提供；第 5、6 章对结构的描述均来自推理代码的字段与注释，可能存在推断成分。
3. **生产 KV 存储 / 负载均衡 / P/D 编排**：官方明确未开源（S2），第 11 章只复述官方描述。
4. **`deepseek-recipe` 的行为**：独立仓库，本笔记未阅读其源码。
5. **vendor 子模块内部实现**：DeepEP / DeepGEMM / DeepSelect / FlashMLA 只按接口与调用方式描述，不展开其 kernel 实现。
6. **性能数字的归因**：官方给出端到端结果与部分配置，但未给出可完全复现的实验环境；正文避免把收益归因到单一特性。

## 四、维护规则

1. 新增或修改正文数字时，先查本表；表中没有的，补一行再改正文。
2. 官方 README / Q&A 更新后，优先以新版本为准，并在本表「快照」列记日期与 commit。
3. 若某结论只来自代码注释、且注释与实现不一致，正文以**实现**为准，并在「常见坑」里注明分歧。
4. 不把三方报道混入「官方」；若引用三方，正文必须写明「来源：三方」。
