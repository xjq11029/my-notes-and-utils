## 一句话版

**大语言模型被造出来是给「人」读的，Jev 被造出来是给「程序」调用的** —— 你给它一段状态和一组预先定义好的问题，它不写文章，只返回一个类型化、已校准的判断：一个 `choice`、一个 `score`，或一个是 / 否概率。

## 核心结论速查

1. **Jev 只做判断**：输入自然语言状态 + 预定义问题，输出类型化结果（`choice` / `score` / `noul`）与 `confidence`，不生成自由文本（来源：官方）。
2. **type-safe 不等于正确**：输出空间由请求锁定，所以它造不出你没列过的选项；但**仍可能在合法选项里选错**，也可能对错误答案给出高置信度（来源：官方）。
3. **RLCD 优化的是校准，不是流利**：说 80% 把握，就应当在大约 80% 的情况下是对的。校准 ≠ 保证正确，它保证的是「那个数字可以被你当作阈值使用」（来源：官方）。
4. **「零幻觉」与「校准」是两件独立的事**：前者来自类型化契约，后者来自训练方法 —— 两者互不替代（来源：官方）。
5. **最精准的定位是一个能理解自然语言的「模糊 if 语句」**：确定性规则继续交给代码，语义判断交给 Jev，真正需要生成文字时再调 LLM（来源：三方）。
6. **它最先替代的是 Agent 里的小调用**：该用哪个工具、结果能否通过、任务是否结束 —— 这些问题过去每一个都消耗一次 LLM 调用（来源：三方）。
7. **官方倍数与第三方实测差 1–2 个量级**：官方称快 193.6×、便宜 444.6×；第三方实测速度约 2–3.6×，成本对小模型约 4.7–7.5×、对前沿模型约 40–49×。倍数取决于拿谁当分母（来源：三方）。
8. **「是不是就是个分类器」尚未有定论**：官方未公开架构，训练方法 RLCD 的细节也无法从外部验证（来源：三方）。
9. **它可能比 LLM 更黑盒**：LLM 至少还能被要求解释判断，Jev 最终交给开发者的可能只有一个数字，无法追问这个数字从何而来（来源：三方）。

## 术语表

> 按「首见章节」排序；术语在各章正文首次出现处均有上下文解释。

| 术语 | 中文注释 | 首见 |
|---|---|---|
| System One / System Two | 借自思维心理学：System Two 是缓慢、审慎、语言化的推理（LLM 模仿的对象），System One 是瞬间发生的直觉式判断。Jev 自我定位为前者（来源：官方） | ch1 |
| 决策式模型（Decision Model） | 输出「判断」而非「文本」的模型；输出空间由调用方预先定义 | ch1 |
| 生成式模型（Generative Model） | 逐 token 生成自由文本的模型，即通常说的 LLM / 聊天模型 | ch1 |
| TypeSafe AI | Jev 的出品公司，旧金山初创，2026-09 结束两年隐身状态（来源：三方） | ch1 |
| Diogo Almeida | TypeSafe AI 创始人；前 Google Brain / OpenAI 研究员。官方称 RLHF 由他共同发明；InstructGPT 论文（arXiv:2203.02155）第 4 作者、GPT-4 技术报告（arXiv:2303.08774）贡献者（来源：官方、一手） | ch1 |
| 杰文斯悖论（Jevons Paradox） | 效率提高、单位成本下降，反而导致总消耗量上升 —— Jev 命名的由来（来源：三方） | ch1 |
| 原语（Primitive） | Jev 可回答的三类问题：`choice` / `score` / `noul`（来源：官方） | ch2 |
| `noul` | 是 / 否问题，返回 0 到 1 的概率（来源：官方） | ch2 |
| `choice` | 从调用方定义的选项集中选一个，返回所选选项 + 全量概率分布（最多 255 个选项）（来源：官方） | ch2 |
| `score` | 沿调用方定义的有序量表打分，返回概率加权值（2 到 10 级）（来源：官方） | ch2 |
| `state` | 请求体里「要判断的内容」，可为字符串、JSON 对象或文本数组（来源：官方） | ch2 |
| `confidence` | 由概率分布导出的确定性度量，0 到 1；`choice` 与 `score` 才有（来源：官方） | ch2 |
| type-safe | 输出被锁死在你定义的形状内，不会返回未列出的选项或畸形结构（来源：官方） | ch2 |
| RLCD | Reinforcement Learning for Calibrated Decisions，Jev 的训练方法（来源：官方） | ch3 |
| 校准（Calibration） | 模型声称的概率与真实正确率对齐：说 80% 就在约 80% 的情况下对（来源：官方） | ch3 |
| 可靠度图（Reliability Diagram） | 横轴为模型声称的置信度、纵轴为实际正确率的散点图；完美校准落在对角线上，过度自信落在下方 | ch3 |
| RLHF | Reinforcement Learning from Human Feedback，基于人类反馈的强化学习；优化的是「人更偏好什么」（来源：三方） | ch3 |
| 合成数据（Synthetic Data） | 训练 Jev 的数据来源，据媒体报道完全基于合成数据（官方未确认）（来源：三方） | ch3 |
| 置信度分流 | 按 `confidence` 阈值把决策分为自动执行 / 复核 / 升级三路（来源：官方） | ch5 |
| 扇出（Fan-out） | 一次请求携带多个问题、并行求值，摊薄 `state` 的重复输入成本（来源：官方） | ch5 |
| 复合评分（Composite Scoring） | 把复合判断拆成多个原子问题、在代码里组合结果（来源：官方） | ch5 |
| 模型锯齿（Jaggedness） | `state` 变长时准确率的漂移，官方专门用一页文档说明 `jev-1.13` 的这一现象（来源：官方） | ch5 |
