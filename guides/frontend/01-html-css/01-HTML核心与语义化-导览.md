## 一、核心概念

### 1.1 DOCTYPE 声明

| 维度 | 内容 |
|------|------|
| 是什么 | 声明文档类型为 HTML5 的指令，告诉浏览器使用标准模式渲染页面。 |
| 能做什么 | 确保浏览器以标准模式解析 HTML，避免怪异模式（Quirks Mode）导致的盒模型计算不一致和 CSS 渲染差异。 |
| 怎么用 | `<!DOCTYPE html>`（HTML5 唯一写法，放在文档第一行） |
| 原理和工作流程 | 浏览器解析 HTML 前先读取 DOCTYPE 声明，若存在且为 HTML5 则进入标准模式；若缺失或声明为旧版 DTD 则进入怪异模式。怪异模式下盒模型计算方式不同（width 包含 padding 和 border），CSS 渲染规则也存在差异，导致跨浏览器兼容问题。 |
| 缺点 | 无严重缺点。唯一的注意事项是必须放在文档第一行，之前不能有任何字符（包括 BOM 头），否则 IE 可能触发怪异模式。 |

### 1.2 HTML5 新特性

| 维度 | 内容 |
|------|------|
| 是什么 | HTML5 标准引入的一组新标签、API 和能力，覆盖语义化、表单、多媒体、存储、通信等多个领域。 |
| 能做什么 | 语义化标签提升 SEO 和可访问性；表单增强支持原生验证；音视频替代 Flash；Canvas/SVG 支持 2D/3D 绘图；Web Storage 提供客户端持久化；WebSocket 实现全双工通信。 |
| 怎么用 | `<article>`、`<input type="email">`、`<video src="...">`、`<canvas>`、`localStorage.setItem()`、`new WebSocket()` |
| 原理和工作流程 | HTML5 规范由 W3C 和 WHATWG 共同制定，浏览器厂商按规范实现新的解析规则和 API。语义化标签被解析为具有特定含义的 DOM 节点；Web Storage 在浏览器沙箱中分配存储空间；WebSocket 通过 HTTP 升级协议建立持久连接。 |
| 缺点 | 旧版浏览器（如 IE8 及以下）不支持 HTML5 新特性，需要 polyfill 或优雅降级。（历史兼容场景，2026 年新项目按现代浏览器基线） |

### 1.3 语义化标签详解

| 维度 | 内容 |
|------|------|
| 是什么 | 使用具有明确语义含义的 HTML 标签（如 `<header>`、`<nav>`、`<main>`、`<article>`）替代无语义的 `<div>`，使页面结构具有可读性。 |
| 能做什么 | 提升 SEO 排名（搜索引擎爬虫能理解页面结构）；增强可访问性（屏幕阅读器能识别内容区域）；提高代码可维护性（开发者快速理解页面布局）；移动端浏览器可能对语义化标签有特殊优化。 |
| 怎么用 | `<header>` 包裹页头、`<nav>` 包裹导航、`<main>` 包裹核心内容（唯一）、`<article>` 包裹独立内容、`<section>` 包裹有标题的分组、`<aside>` 包裹侧边栏、`<footer>` 包裹页脚 |
| 原理和工作流程 | 搜索引擎爬虫和屏幕阅读器根据标签语义构建页面大纲（Document Outline）。`<main>` 标记页面唯一核心区域，`<article>` 标记可独立分发的内容块，`<nav>` 标记导航链接集。合理的语义结构相当于给页面建立了一套"标准目录"，机器可准确解析。 |
| 缺点 | 需要开发者对每个标签的语义有准确理解，滥用或误用反而降低可读性；大量使用语义化标签会增加 DOM 层级深度。 |

### 1.4 块级元素 vs 行内元素 vs 行内块元素

| 维度 | 内容 |
|------|------|
| 是什么 | 按 CSS 显示模式对 HTML 元素分类：**块级**独占一行、**行内**同行排列、**行内块**兼具同行排列和宽高设置能力。 |
| 能做什么 | 块级元素用于构建页面结构骨架（div、p、h1~h6）；行内元素用于文本内部标记（span、a、strong）；行内块元素用于需要同行排列且可设置宽高的场景（img、input、button）。 |
| 怎么用 | 块级：`display: block`；行内：`display: inline`；行内块：`display: inline-block` |
| 原理和工作流程 | 块级元素在渲染时生成块级框（Block Box），前后自动换行，默认宽度为父元素 100%；行内元素生成行内框（Inline Box），不换行，宽高由内容决定，margin/padding 仅水平方向生效；行内块元素生成行内块级框，不换行但宽高和四方向 margin/padding 均有效。 |
| 缺点 | 行内元素无法设置宽高和垂直 margin/padding，限制了布局灵活性；行内块元素之间默认存在空白间隙（由 HTML 源码中的换行产生），需要额外处理。 |

## 二、底层原理

### 2.1 浏览器解析 HTML 流程

| 维度 | 内容 |
|------|------|
| 是什么 | 浏览器将 HTML 字节流逐步转换为 DOM 树的完整流水线过程。 |
| 能做什么 | 理解解析流程有助于优化首屏渲染性能（减少 DOM 层级、合理安排资源加载顺序），以及排查渲染异常问题。 |
| 怎么用 | 流程：`HTML 字节流 → 字符流 → Token → DOM 节点 → DOM 树` |
| 原理和工作流程 | 1. 字节流解码：按 HTTP 响应头或 `<meta charset>` 指定的编码将字节流解码为字符流；2. 词法分析：Tokenizer 将字符流切分为 Token（开始标签、结束标签、文本、属性）；3. DOM 树构建：根据 Token 创建 DOM 节点并构建树结构；4. CSSOM 树构建：并行解析 CSS 构建 CSSOM 树；5. 渲染树合成：DOM + CSSOM 合并为 Render Tree 后进入布局和绘制阶段。 |
| 缺点 | 解析过程是同步的，遇到 `<script>` 标签（无 async/defer）会阻塞 DOM 构建，延长白屏时间。 |

### 2.2 script 标签的 async 和 defer

| 维度 | 内容 |
|------|------|
| 是什么 | `<script>` 标签的两个布尔属性，控制外部脚本的下载和执行时机，解决脚本阻塞 HTML 解析的问题。 |
| 能做什么 | `async` 适合独立脚本（如统计代码），异步下载后立即执行，不保证顺序；`defer` 适合依赖 DOM 的脚本，异步下载后在 DOMContentLoaded 前按顺序执行。两者均不阻塞 HTML 解析。 |
| 怎么用 | `<script async src="analytics.js"></script>`、`<script defer src="app.js"></script>` |
| 原理和工作流程 | 无属性时：浏览器解析到 script 标签立即暂停 DOM 构建，下载并执行脚本后继续解析。`async`：异步并行下载脚本，下载完成后立即执行（此时 HTML 解析可能未完成），执行顺序不保证。`defer`：异步并行下载脚本，但延迟到整个 HTML 解析完成后、DOMContentLoaded 事件触发前按文档顺序执行。 |
| 缺点 | `async` 无法保证脚本执行顺序，依赖关系复杂的脚本不能使用；`defer` 在个别旧浏览器中存在兼容性问题。 |

### 2.3 meta 标签的作用

| 维度 | 内容 |
|------|------|
| 是什么 | 位于 `<head>` 中的元数据标签，提供页面字符编码、视口、SEO 描述、搜索引擎爬取控制等配置信息。 |
| 能做什么 | 声明字符编码防止乱码（`charset`）；适配移动端视口（`viewport`）；提供 SEO 页面描述（`description`）；控制搜索引擎爬取行为（`robots`）；指定 IE 渲染模式（`X-UA-Compatible`）。 |
| 怎么用 | `<meta charset="UTF-8">`、`<meta name="viewport" content="width=device-width, initial-scale=1.0">`、`<meta name="description" content="...">`、`<meta name="robots" content="noindex,nofollow">` |
| 原理和工作流程 | 浏览器在解析 `<head>` 时读取 meta 标签。`charset` 影响解码方式，必须放在 head 最前面（前 1024 字节内）；`viewport` 控制移动端布局视口宽度和缩放比例；`description` 被搜索引擎用作搜索结果摘要；`robots` 告知爬虫是否索引页面和跟踪链接。 |
| 缺点 | `keywords` 标签已被主流搜索引擎忽略，设置无实际效果；`viewport` 配置不当会导致移动端缩放异常。 |

## 三、实战应用

### 3.1 SEO 优化最佳实践

| 维度 | 内容 |
|------|------|
| 是什么 | 通过 HTML 结构和 meta 标签优化，使搜索引擎更好地理解和收录页面内容，提升搜索排名。 |
| 能做什么 | 合理使用语义化标签、title、description、canonical URL 等提升搜索引擎对页面内容的理解质量，增加自然搜索流量。 |
| 怎么用 | `<html lang="zh-CN">`、`<title>页面标题</title>`、`<meta name="description" content="...">`、`<link rel="canonical" href="...">`、`<h1>` 唯一主标题、语义化标签结构 |
| 原理和工作流程 | 搜索引擎爬虫按 URL 抓取页面 HTML，解析 title、description、h1~h6、语义化标签等构建页面理解模型。`canonical` 标签用于解决重复内容问题，告知搜索引擎哪个 URL 是权威版本。语义化标签帮助爬虫区分主要内容、导航、侧边栏等区域，更准确提取正文。 |
| 缺点 | HTML 层面的 SEO 优化只是基础，还需要配合内容质量、外链策略、页面加载速度等多方面因素。 |

### 3.2 可访问性（ARIA）

| 维度 | 内容 |
|------|------|
| 是什么 | WAI-ARIA（Web Accessibility Initiative - Accessible Rich Internet Applications）规范，通过 HTML 属性为辅助技术（屏幕阅读器等）提供语义信息。 |
| 能做什么 | 让视障用户通过屏幕阅读器准确理解页面元素的功能和状态；为自定义交互组件（如用 div 实现的按钮）提供语义标注。 |
| 怎么用 | `<button aria-label="提交表单">`、`<img alt="收入增长趋势图">`、`aria-disabled="false"` |
| 原理和工作流程 | 屏幕阅读器通过操作系统无障碍 API 读取 DOM 树和 ARIA 属性，将元素语义（角色、名称、状态）转换为语音或盲文输出。原生 HTML 元素（如 `<button>`）自带隐式语义，自定义组件需要通过 ARIA 显式标注角色和状态。 |
| 缺点 | ARIA 属性不能替代原生语义化 HTML，优先使用原生语义标签；滥用 ARIA 可能导致屏幕阅读器输出混乱；需要实际测试确保兼容性。 |

## 四、常见面试题

### 1. HTML5 新增了哪些标签？语义化的好处是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 HTML5 新增语义化标签（header/nav/main/article/section/aside/footer）和语义化概念的理解。 |
| 能做什么 | 检验候选人对 HTML5 标准的熟悉程度，以及是否理解语义化对 SEO、可访问性的实际价值。 |
| 怎么用 | 新增标签：`<header>`、`<nav>`、`<main>`、`<article>`、`<section>`、`<aside>`、`<footer>`；表单增强：`<input type="email">`、`<input type="date">`；多媒体：`<audio>`、`<video>` |
| 原理和工作流程 | 语义化好处由四个层面支撑：SEO 层面（爬虫准确理解结构）、可访问性层面（屏幕阅读器识别区域）、维护层面（开发者快速理解布局）、移动端层面（浏览器可能特殊优化）。 |
| 缺点 | 回答时需注意区分"标签"和"API"（如 Web Storage 是 API 而非标签），避免混淆。 |

### 2. script 标签的 async 和 defer 有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 `<script>` 标签 async 和 defer 属性的下载时机、执行时机和执行顺序三个维度的差异。 |
| 能做什么 | 检验候选人是否理解浏览器资源加载策略，能否在实际项目中正确选择脚本加载方式。 |
| 怎么用 | `async`：异步下载，下载完立即执行，不保证顺序，适合独立脚本。`defer`：异步下载，DOM 解析完成后按顺序执行，适合依赖 DOM 的脚本。 |
| 原理和工作流程 | 无属性时脚本阻塞 HTML 解析。`async` 下载和执行都不阻塞解析，但执行时会暂停解析；`defer` 下载不阻塞，但执行推迟到解析完成后。两者都只在有 src 属性的外部脚本时生效。 |
| 缺点 | 回答时注意区分"不阻塞 HTML 解析"和"不阻塞渲染"是两个概念。 |

### 3. HTML5 存储方式有哪些？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查浏览器端数据持久化方案：localStorage、sessionStorage、IndexedDB、Cookie 四者的区别和适用场景。 |
| 能做什么 | 检验候选人对客户端存储方案的全面了解，以及在项目中选择合适存储方案的能力。 |
| 怎么用 | `localStorage.setItem('key', 'value')`、`sessionStorage.setItem('key', 'value')`、`document.cookie`、IndexedDB 通过 `indexedDB.open()` |
| 原理和工作流程 | localStorage 持久化存储（5MB），同源共享，手动清除或代码删除；sessionStorage 会话级存储，关闭标签页后清除；IndexedDB 支持索引和事务的结构化存储，容量大；Cookie 4KB，每次 HTTP 请求自动携带，可设置过期时间。 |
| 缺点 | 回答时注意区分 Cookie 的自动携带特性（可能影响性能）和 Storage 的纯客户端特性。 |

### 4. 什么是 Web Worker？

| 维度 | 内容 |
|------|------|
| 是什么 | 浏览器提供的在后台线程中运行 JavaScript 的机制，不阻塞主线程（UI 线程）。 |
| 能做什么 | 处理 CPU 密集型任务（大数据计算、图像处理、加密解密）而不影响页面响应；Worker 线程与主线程通过 `postMessage` 通信传递数据。 |
| 怎么用 | `const worker = new Worker('worker.js'); worker.postMessage(data); worker.onmessage = (e) => { console.log(e.data); }` |
| 原理和工作流程 | 浏览器为每个 Worker 实例创建独立的线程和独立的 JavaScript 执行环境（无 window 对象、无 DOM 访问权限）。主线程和 Worker 线程通过结构化克隆（Structured Clone）传递数据，数据被复制而非共享。 |
| 缺点 | 不能操作 DOM；不能使用 window 对象的某些方法和属性；数据通过复制传递，大对象开销较大（可使用 Transferable 对象转移所有权优化）。 |

## 五、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 汇总 HTML 核心开发中四个高频错误及其解决方案，涵盖 viewport、h1、语义化标签、script 加载四个方面。 |
| 能做什么 | 帮助开发者避免移动端缩放异常、SEO 扣分、代码可读性差、页面白屏时间长等常见问题。 |
| 怎么用 | 添加 `<meta name="viewport">`；每个页面只用一个 h1；按内容选择语义化标签；使用 defer 或将 script 放在 body 底部。 |
| 原理和工作流程 | 忘记 viewport 导致移动端使用默认 980px 视口渲染，页面缩小；多个 h1 破坏页面大纲，影响 SEO 评分；div 滥用使爬虫和屏幕阅读器无法区分内容区域；head 中 script 阻塞 DOM 构建导致白屏。 |
| 缺点 | 这些避坑方案是基础规范，实际项目中还需要结合具体场景调整。 |
