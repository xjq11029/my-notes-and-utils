# 前端工程化 - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 开发环境 CSS 正常，生产环境样式丢失 | 生产环境使用 style-loader 将 CSS 注入 DOM，而非提取为独立文件 | 生产环境使用 MiniCssExtractPlugin 替代 style-loader 提取 CSS 为独立文件 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| Loader 配置后构建报错或样式不生效 | Loader 从右向左执行，use 数组顺序错误导致转换链断裂 | 确保 use 数组顺序正确，如 `['style-loader', 'css-loader', 'sass-loader']`（sass-loader 在最右） | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 开发环境正常，生产环境构建后浏览器报错 | 生产构建时 babel 配置或 polyfill 缺失，目标浏览器兼容性未覆盖 | 检查 babel 配置和 browserslist，确保兼容目标浏览器范围 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| Vite 项目中 import 图片路径报错 | Vite 的静态资源处理方式与 Webpack 不同，直接拼接路径无效 | 使用 `new URL('./img.png', import.meta.url).href` 或直接 import 图片 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| Webpack 打包后单文件过大（超过 1MB） | 未启用代码分割和 Tree Shaking，所有代码打包到单一 bundle | 配置 splitChunks 拆包，使用动态 import 路由懒加载，启用 BundleAnalyzerPlugin 分析 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| Vite 项目在老浏览器中无法运行 | Vite 默认不处理 ES6+ 语法降级和 API polyfill | 使用 @vitejs/plugin-legacy 插件，自动注入 polyfill 和语法降级 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| Vite 开发环境代理配置后接口 404 或跨域 | proxy 配置的路径或目标地址不匹配，或未处理路径重写 | 检查 proxy 配置的 path 和 target，确认路径重写规则正确 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| dist 目录被提交到 Git 仓库 | 未在 .gitignore 中忽略构建产物 | 在 .gitignore 中添加 `/dist` 或 `/build` | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 保存文件后 ESLint 和 Prettier 来回切换格式 | 两个工具的规则重叠，互相覆盖 | 安装 eslint-config-prettier，在 extends 末尾添加 `'prettier'` 关闭冲突规则 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| lint-staged 提交时检查了所有文件而非暂存文件 | lint-staged 配置中命令格式不正确，未使用文件参数 | 确保配置中命令格式为 `"eslint --fix"` 而非 `"eslint --fix ."`，lint-staged 自动传入暂存文件路径 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| commitlint 不生效，提交信息未被检查 | Husky 钩子未正确安装或 Git 未识别钩子文件 | 运行 `pnpm exec husky install`，确保 `.husky/commit-msg` 文件存在且可执行 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| Monorepo 中包之间循环依赖导致构建失败 | 包 A 依赖包 B，包 B 又依赖包 A，形成循环 | 使用 Turborepo 或 Nx 进行依赖分析，重构代码消除循环依赖 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| Nginx 部署 SPA 后刷新页面显示 404 | Nginx 缺少 SPA 路由 fallback 配置，非文件请求未返回 index.html | 添加 `try_files $uri $uri/ /index.html` 配置 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| Docker 构建产物镜像体积超过 1GB | 多阶段构建时未清理中间文件，或基础镜像过大 | 使用多阶段构建，生产阶段只复制必要文件，使用 alpine 基础镜像 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| Monorepo 中共享依赖出现多个版本冲突 | 不同包依赖了不同版本的同一个库 | 在根 package.json 中统一管理公共依赖版本，使用 pnpm 的 overrides 字段 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| CI/CD 中生产环境构建结果与本地不一致 | pnpm install 未锁定版本，可能安装不同的小版本 | 使用 `pnpm install --frozen-lockfile`，确保 lockfile 已提交到仓库 | [工程规范与流程导览](./02-工程规范与流程-导览.md) |
| 老浏览器报 `Promise is not defined` | 把语法降级当成了 API polyfill，esbuild 只降级语法不做 core-js 注入 | 开启 SWC 的 `env` 模式，或保留 Babel 的 `useBuiltIns` | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 类型错误被带到生产环境 | 以为 SWC / esbuild 会做类型检查，它们只擦除类型标注 | 保留 `tsc --noEmit` 或 `fork-ts-checker-webpack-plugin` 独立检查 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| Next.js 项目编译变慢，部分优化失效 | 残留了 `babel.config.js`，存在 Babel 配置时 Next.js 会退回 Babel | 确认无 Babel 插件需求后删除该文件 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 构建报错或注入了错误的 core-js 路径 | `useBuiltIns: 'usage'` 与 `corejs` 版本不匹配 | 统一 `corejs: '3.x'` 与安装的 `core-js@3` 主版本一致 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 兼容范围与预期不符 | 以为 esbuild 会读 browserslist，它只认显式的 `target` | 手动设置 `target`，并与 browserslist 声明保持同步 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 把 Babel 插件直接搬到 SWC，配置报错且插件不生效 | `@swc/core` 不识别 `@babel/plugin-*` | 寻找对应的 SWC 实现，或改用 WASM 插件 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 用 `thread-loader` 包 `babel-loader` 后 loader 间变量丢失 | 多进程模式下 loader 上下文被隔离，无法共享状态 | 改用 SWC / esbuild 获得原生并行，而非叠加进程方案 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| `import.meta.env[key]` 读到 `undefined` | 构建时只做静态字面量替换，不支持动态 key | 用固定写法读取，或集中收口到一个 config 模块 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 密钥出现在前端产物中 | 误以为 `VITE_` 前缀是保护机制，它只是"暴露给客户端"的开关 | 密钥只留在服务端，前端统一走 BFF 代理 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 用 `DefinePlugin` 注入字符串后产物语法错误或变量未定义 | 值被当作代码片段解析，未做序列化 | 字符串一律用 `JSON.stringify(value)` 包裹 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 真实 `.env` 被提交到 Git，密钥泄露 | 未加入 `.gitignore` | 只提交 `.env.example`，忽略 `.env.local` 与真实 `.env` | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 改了运行时配置文件但不生效 | `config.js` / `config.json` 被 CDN 强缓存 | 对该文件设置 `Cache-Control: no-cache`，或加时间戳参数 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| staging 环境被当成 production | 用 `NODE_ENV` 区分环境，而它只有 development / production 两种语义 | 用 `mode`（Vite）或 `--env`（Webpack）显式声明环境名 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 改了 `.env` 不重新构建却期望生效 | 环境变量是构建时静态替换，产物里已是字面量 | 需要运行时可变就改用 `window.__CONFIG__` 或远程配置 | [构建工具原理导览](./01-构建工具原理-导览.md) |
| 生产环境接口地址为空，线上直接报错 | 构建时未做校验，空值被静默打进产物 | 构建前置校验脚本，缺必填配置直接 `exit 1` | [构建工具原理导览](./01-构建工具原理-导览.md) |
| `git commit` 后 Husky 脚本没有执行，检查被跳过 | `.husky/` 目录权限不正确，或 `core.hooksPath` 配置错误 | 执行 `pnpm exec husky init` 重新初始化；检查 `git config core.hooksPath`；确保 `.husky/pre-commit` 有执行权限 | [测试集成与质量门禁导览](./04-测试集成与质量门禁-导览.md) |
| 每次开发新功能都因覆盖率不足导致 CI 失败 | 覆盖率阈值设置不合理，未区分核心逻辑与 UI 组件 | 按目录设置不同阈值：核心逻辑 85-95%，UI 组件 70-80%；或用 watermarks 给警告而非直接失败 | [测试集成与质量门禁导览](./04-测试集成与质量门禁-导览.md) |
| 多个 CI job 同时写缓存导致不确定性的构建失败 | `actions/cache` 的 restore-keys 命中旧缓存，不同 job 依赖版本不一致 | 用 `hashFiles('pnpm-lock.yaml')` 作为缓存 key；不同 job 用独立 key；构建前 `pnpm install --frozen-lockfile` 验证 | [测试集成与质量门禁导览](./04-测试集成与质量门禁-导览.md) |
