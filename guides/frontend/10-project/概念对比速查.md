### accessToken vs refreshToken

| 对比维度 | accessToken | refreshToken |
|---------|-------------|-------------|
| 核心定位 | 用于访问受保护资源的短期凭证 | 用于获取新 accessToken 的长期凭证 |
| 有效期 | 短期（通常 15-30 分钟） | 长期（通常 7-30 天） |
| 传输频率 | 每次请求都携带 | 仅在 accessToken 过期时使用 |
| 暴露风险 | 高（频繁传输，易被拦截） | 低（传输次数少） |
| 存储位置 | 内存或 localStorage | localStorage 或 HttpOnly Cookie |
| 失效影响 | 短期失效，用户几乎无感知 | 长期失效，用户需重新登录 |
| 安全设计 | 短期有效降低被窃取后的影响窗口 | 可配合黑名单实现主动失效 |
| 并发刷新 | 需要处理多个请求同时过期的情况 | 用 isRefreshing 标记防止重复刷新 |
| 选择建议 | 始终使用短期 accessToken 保护 API | 配合 accessToken 实现无感刷新 |

### 静态路由 vs 动态路由

| 对比维度 | 静态路由 | 动态路由 |
|---------|---------|---------|
| 核心定位 | 所有用户共享的路由配置，无需权限 | 根据用户权限动态注册的路由 |
| 注册时机 | 应用初始化时一次性注册 | 登录后根据权限列表动态 addRoute |
| 典型页面 | 登录页、404 页、无权限提示页 | 业务页面（用户管理、订单管理、报表等） |
| 权限控制 | 无需权限校验 | 每个路由 meta 携带 permission 字段 |
| 菜单渲染 | 全部可见 | 仅渲染有权限的路由 |
| 安全性 | 公开页面，无安全风险 | 无权限用户无法通过 URL 直接访问 |
| 实现复杂度 | 低，直接定义 RouteRecordRaw[] | 中，需要过滤 + addRoute + 防重复 |
| 侧边栏联动 | 固定菜单 | 根据过滤后的路由动态生成菜单 |
| 选择建议 | 登录页、错误页等公开页面 | 所有需要权限控制的业务页面 |

### RBAC vs ABAC 权限模型

| 对比维度 | RBAC | ABAC |
|---------|------|------|
| 核心定位 | 基于角色的访问控制，用户通过角色间接关联权限 | 基于属性的访问控制，通过用户属性、资源属性、环境属性综合判断 |
| 权限模型 | 用户 -> 角色 -> 权限（N:M 关系） | 主体属性 + 资源属性 + 环境属性 + 操作 -> 策略评估 |
| 粒度 | 角色级别，粗粒度 | 属性级别，细粒度 |
| 灵活性 | 低，权限变更需要修改角色配置 | 高，可通过调整属性组合动态控制 |
| 实现复杂度 | 低，三张表（用户、角色、权限）即可 | 高，需要策略引擎和属性管理 |
| 管理成本 | 低，角色变更即可 | 高，需要维护属性元数据和策略规则 |
| 典型场景 | 企业后台管理系统、CMS | 多租户 SaaS、金融风控、医疗系统 |
| 扩展性 | 角色爆炸问题（角色过多难以管理） | 策略复杂度随属性增长 |
| 前端实现 | 动态路由 + 按钮权限指令 | 需要额外的策略评估 API |
| 选择建议 | 中小型企业后台，权限结构简单 | 多租户平台、跨组织权限管理 |

### Pinia vs Vuex

| 对比维度 | Pinia | Vuex 4 |
|---------|-------|--------|
| 核心定位 | Vue 3 官方推荐的状态管理库 | Vue 生态传统状态管理库 |
| API 风格 | Composition API 风格，定义 store 如写 setup | Options API 风格，state/mutations/actions/getters 分离 |
| mutations | 不需要，直接修改 state | 必须通过 mutations 修改 state（强制同步） |
| TypeScript | 原生支持，类型推导完整 | 需要额外类型声明，推导较弱 |
| 模块化 | 天然模块化，每个 store 独立 | 通过 modules 嵌套，命名空间需手动处理 |
| 体积 | 约 1KB（gzip） | 约 4KB（gzip） |
| DevTools | 支持，且追踪更清晰 | 支持 |
| 插件系统 | 简单，支持 pinia-plugin-persistedstate | 较复杂，需要理解插件机制 |
| 废弃 mutations | 是，直接修改 state | 否，必须通过 mutations |
| 选择建议 | Vue 3 新项目默认使用 Pinia | 维护 Vue 2 / Vuex 旧项目 |
