## 核心概念

| 维度 | 内容 |
|------|------|
| 是什么 | AI 编程工具的定义与定位：Cursor 是 AI-first IDE（图形界面优先），Claude Code 是 CLI 原生编程助手（终端优先），GitHub Copilot 是 IDE 内嵌 AI 助手（生态集成优先）。三者定位不同，互补使用可最大化效率。 |
| 能做什么 | 从行内补全（Tab 补全）到单文件编辑（Cmd+K）到多文件重构（Composer/Agent）到全项目级自主任务，AI 编程工具已实现多层级能力覆盖。同时支持代码审查、PR 自动描述、测试生成等辅助功能。 |
| 怎么用 | 理解各工具定位：日常编码用 Cursor（Tab 补全流畅），复杂重构用 Claude Code（项目级理解强），团队协作选 Copilot（GitHub 生态深度集成）。推荐组合：Cursor（日常编码）+ Claude Code（复杂任务），两者互补。 |
| 原理和工作流程 | AI 编程工具通过读取项目上下文（文件结构、规则配置、代码风格）构建 Prompt，发送给后端大语言模型，模型基于训练数据和上下文推理生成代码建议，流式返回给编辑器/终端实时展示。上下文质量直接决定输出质量。 |
| 缺点 | 与传统开发的核心区别：AI 生成代码不保证运行时正确（必须验证）；AI 可能胡编不存在的 API（需要约束和审查）；过度依赖 AI 可能导致独立编码能力退化；AI 无法替代架构决策、安全把关等需要深度思考的工作。 |

## Cursor

| 维度 | 内容 |
|------|------|
| 是什么 | 基于 VS Code 深度定制的 AI-first IDE，内置多模型 AI 能力，支持 Tab 补全、Cmd+K 编辑、Composer 多文件生成、Agent 自主模式。 |
| 能做什么 | Tab 多行智能补全；Cmd+K 选中代码用自然语言修改；Composer Agent 从零创建完整功能模块；@ 引用文件/文件夹/网页作为上下文。 |
| 怎么用 | 安装 Cursor → 导入项目 → 配置 `.cursorrules` 项目规则 → Tab 补全日常编码 → Cmd+K 精准修改 → Cmd+I Composer 生成新功能。 |
| 原理和工作流程 | 利用 IDE 上下文（当前文件、项目结构、规则配置）构建 Prompt → 发送给后端 AI 模型 → 流式返回代码建议 → 在编辑器中实时展示。 |
| 缺点 | 免费额度有限；Agent 模式在超复杂任务中可能出错需要人工干预；过度依赖可能降低独立编码能力。 |

## Claude Code

| 维度 | 内容 |
|------|------|
| 是什么 | Anthropic 推出的 CLI 原生 AI 编程助手，在终端中直接运行，擅长项目级上下文理解和复杂多文件重构。 |
| 能做什么 | 自动读取项目全貌进行理解；一次对话修改多个文件；执行终端命令并查看结果；通过 CLAUDE.md 定义项目级行为规范。 |
| 怎么用 | 终端中运行 `claude` → 用自然语言描述任务 → AI 读取项目文件 → 生成代码并直接修改文件 → 终端中运行验证命令。 |
| 原理和工作流程 | 读取项目文件结构 → 构建项目级上下文 → 根据用户指令和 CLAUDE.md 规范 → 生成多文件修改 → 执行终端命令验证。 |
| 缺点 | 无实时 Tab 补全（纯对话式）；CLI 交互对非终端用户不友好；学习曲线比 IDE 工具高。 |

## GitHub Copilot

| 维度 | 内容 |
|------|------|
| 是什么 | GitHub 推出的 AI 编程助手，深度集成在 VS Code、JetBrains 等主流 IDE 中，与 GitHub 生态无缝衔接。 |
| 能做什么 | 行内幽灵文本补全；Copilot Chat 对话式编码；自动识别和修复终端错误；PR 自动代码审查；Workspace 代理跨文件修改。 |
| 怎么用 | 安装 VS Code 插件 → GitHub 登录 → 编码时自动触发补全 → Cmd+I 打开 Chat → 选择代码后右键 Copilot 菜单。 |
| 原理和工作流程 | 基于当前文件上下文和 GitHub 公开代码库训练 → 实时生成补全建议 → 以灰色幽灵文本展示 → Tab 接受。 |
| 缺点 | 代码隐私争议（企业版可解决）；补全质量不如 Cursor（上下文范围较小）；对非英语 Prompt 支持较弱。 |

## AI 编程工作流最佳实践

| 维度 | 内容 |
|------|------|
| 是什么 | 从需求分析到 PR 合并的完整 AI 辅助开发链路：需求分析（Chat 讨论技术方案）→ 架构设计（Chat 拆解子任务）→ 任务拆解 → Prompt 编写 → AI 生成（Composer/Agent 生成代码）→ 代码审查（AI 辅助 + 人工）→ 合并部署。每个阶段都有对应的 AI 工具和最佳实践。 |
| 能做什么 | 需求分析阶段：AI 分析需求文档、提出技术问题、生成技术方案文档；编码阶段：AI 搭建项目结构、生成核心逻辑、编写单元测试和样式；代码审查阶段：AI 检查代码质量、安全漏洞、竞态条件；提交阶段：AI 自动生成 PR 描述。 |
| 怎么用 | 遵循分阶段策略：先配置 `.cursorrules`/`CLAUDE.md` 项目规则文件统一风格；需求阶段用 Chat 讨论方案不写代码；编码阶段用 Composer Agent 生成功能模块，用 Cmd+K 精准修改细节；审查阶段用 AI 扫描常见问题后人工复核；提交前运行 TypeScript 类型检查 + ESLint + 单元测试三重质量关卡。 |
| 原理和工作流程 | 上下文管理是工作流的核心：项目级规则文件定义全局规范 → 精确引用（@file/@folder）指定上下文范围 → 渐进式上下文（先概要后细节）→ 上下文清理（对话过长时开新对话避免污染）。上下文越精确，AI 输出质量越高。 |
| 缺点 | 分步执行耗时较长，不如一次性生成快速；需要人工判断每步结果的正确性，不能全自动流转；不同 AI 工具在各阶段的优势不同，需要切换工具（增加切换成本）；长对话可能超出上下文窗口导致 AI 遗忘早期约束。 |

## 常见问题与避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | AI 编程中常见的五类陷阱：上下文溢出（对话历史超出窗口导致 AI 遗忘早期约束）、AI 幻觉代码（编造不存在的 API 或过时语法）、过度依赖 AI（不再自己思考逻辑导致技能退化）、生成代码质量不稳定（风格不一致、缺少错误处理）、代码看起来对但实际运行错误（AI 不保证运行时正确性）。 |
| 能做什么 | 识别并规避 AI 编程的常见问题：上下文溢出 → 定期开启新对话并用规则文件替代重复说明；AI 幻觉 → 在 Prompt 中约束 API 使用范围，要求使用已知库；过度依赖 → 保持"理解后再使用"原则；质量不稳定 → 配置 `.cursorrules`/`CLAUDE.md` 统一规范；运行错误 → 必须运行测试验证后再合并。 |
| 怎么用 | 建立 AI 代码质量保障机制（六道关卡）：TypeScript 类型检查 → ESLint 静态分析 → 单元测试功能验证 → AI 安全扫描 → 人工性能审查 → 人工可维护性审查。每道关卡针对不同维度的问题，组合使用可拦截大部分 AI 代码缺陷。 |
| 原理和工作流程 | AI 代码问题的根因：上下文窗口有限（长对话导致信息丢失）→ 训练数据包含过时/错误信息（AI 无法区分真伪）→ AI 默认生成"快乐路径"代码（缺少错误处理）→ 缺乏项目规范约束（风格不一致）。解决思路是"约束 + 验证"：约束 AI 的生成范围，验证 AI 的输出结果。 |
| 缺点 | 质量保障机制增加了开发流程的步骤和耗时；部分问题（如运行时错误）只能在运行时发现，静态检查无法完全覆盖；过度约束可能限制 AI 的创造力，导致生成代码过于保守；人工审查仍然不可替代，AI 只能加速但不能取代。 |
