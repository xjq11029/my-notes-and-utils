## 一、异步编程

### 1.1 回调函数（Callback）

| 维度 | 内容 |
|------|------|
| 是什么 | 异步编程的基础模式，将后续操作作为函数参数传递给异步操作，异步操作完成后调用该函数。 |
| 能做什么 | 处理简单的异步操作如 setTimeout、事件监听、Node.js 早期 API。 |
| 怎么用 | `setTimeout(() => { console.log('done'); }, 1000);`、`fs.readFile('file.txt', (err, data) => { ... })` |
| 原理和工作流程 | 回调函数被注册到异步操作的完成回调列表中，异步操作完成后由事件循环调度执行回调函数。回调函数内的错误需要通过回调参数传递，无法像同步代码那样 try/catch 捕获。 |
| 缺点 | 多层嵌套产生"回调地狱"（Callback Hell），代码缩进层叠、难以阅读和维护；错误处理分散在每个回调中；流程控制困难（并行、串行、竞态）。 |

### 1.2 Promise

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 引入的异步编程方案，表示一个异步操作的最终结果，有三种状态：pending（进行中）、fulfilled（成功）、rejected（失败），状态一旦改变不可逆转。 |
| 能做什么 | 解决回调地狱问题，通过链式调用 then() 实现顺序执行；通过 Promise.all()/race()/allSettled()/any() 实现并发控制；通过 catch() 统一错误处理。 |
| 怎么用 | `fetch('/api').then(res => res.json()).then(data => console.log(data)).catch(err => console.error(err));` |
| 原理和工作流程 | Promise 构造函数执行器中的 resolve/reject 改变状态。then() 返回一个新 Promise，实现链式调用。Promise 回调属于微任务，在宏任务间隙执行。catch() 是 then(null, rejection) 的语法糖，可捕获链上任意位置的错误。 |
| 缺点 | 链式调用过长时仍有可读性问题；未处理的 Promise 拒绝（unhandled rejection）可能导致静默失败；中途取消 Promise 需借助 AbortController。 |

### 1.3 async/await

| 维度 | 内容 |
|------|------|
| 是什么 | ES2017 引入的异步语法糖，基于 Promise 和 Generator 实现，让异步代码以同步方式书写。 |
| 能做什么 | 消除 Promise 链式调用的嵌套，异步代码像同步代码一样直观；await 暂停 async 函数执行直到 Promise 完成，错误处理用 try/catch；支持 for 循环中 await 实现顺序异步操作。 |
| 怎么用 | `async function fetchData() { try { const res = await fetch('/api'); const data = await res.json(); return data; } catch(err) { console.error(err); } }` |
| 原理和工作流程 | async 函数始终返回 Promise（非 Promise 值自动包装）。await 将后续代码转为 then 回调，相当于 Generator 的 yield + co 自动执行器的组合。执行到 await 时函数暂停，Promise 完成后继续执行，不阻塞事件循环。 |
| 缺点 | await 是顺序执行，多个无依赖的异步操作使用 await 会降低性能，应使用 Promise.all 并行；顶层 await 需要模块支持（ESM）；滥用 try/catch 包裹整个函数降低可读性。 |

### 1.4 异步方案对比

| 维度 | 内容 |
|------|------|
| 是什么 | 回调函数、Promise、async/await 三种异步方案的对比：写法、错误处理、并发控制。 |
| 能做什么 | 根据场景选择合适方案：简单操作可用回调；需要链式调用用 Promise；复杂异步流程用 async/await。 |
| 怎么用 | 回调：简单但易产生回调地狱；Promise：链式调用统一错误处理，支持并发 API；async/await：同步写法，try/catch 错误处理，推荐首选。 |
| 原理和工作流程 | 三种方案层层递进，回调是基础，Promise 标准化异步状态，async/await 基于 Promise 和生成器提供语法糖。实际项目中 async/await 是首选，Promise 用于并发场景，回调仅用于简单 API 调用。 |
| 缺点 | 没有任何一种方案是万能解药，需要根据场景混合使用。 |

## 二、ES6+ 核心特性

### 2.1 解构赋值

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 提供的从数组或对象中按模式提取值并赋给变量的简洁语法。 |
| 能做什么 | 简化变量提取（从对象/数组中获取值）；函数参数解构提供默认值；交换变量值无需临时变量；提取嵌套对象深层属性。 |
| 怎么用 | `const { name, age } = user;`、`const [first, second] = arr;`、`const { data: { list } } = response;`、`[a, b] = [b, a];` |
| 原理和工作流程 | 解构是模式匹配：按照数组/对象的结构模式从左侧的变量声明中提取右侧对应位置的值。数组解构基于索引位置，对象解构基于属性名匹配。支持默认值、剩余运算符（...rest）和别名（: 重命名）。 |
| 缺点 | 深层嵌套解构可读性差；对象解构中 `{a: b}` 的冒号表示重命名，容易与属性赋值语法混淆。 |

### 2.2 展开运算符与剩余参数

| 维度 | 内容 |
|------|------|
| 是什么 | 展开运算符 `...` 在函数调用/数组字面量中展开数组元素，在对象字面量中展开对象属性；剩余参数 `...` 在函数参数中收集剩余参数为数组。 |
| 能做什么 | 展开用于数组拼接、对象合并、函数参数传递、浅拷贝；剩余参数替代 arguments 对象，收集不确定数量的参数。 |
| 怎么用 | 数组：`[...arr1, ...arr2]`、`Math.max(...numbers)`；对象：`{...obj1, ...obj2}`；函数参数：`function fn(a, ...rest) {}` |
| 原理和工作流程 | 展开运算符在数组上下文中调用可迭代对象的迭代器逐项展开；在对象字面量中通过 Object.assign 语义展开属性。剩余参数必须是函数参数的最后一个，收集剩余实参为真数组。 |
| 缺点 | 展开运算符做的是浅拷贝，嵌套对象引用仍然共享；剩余参数不支持 arguments 的 callee 属性。 |

### 2.3 模板字符串

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 使用反引号包裹的字符串，支持变量插值（`${}`）、多行字符串、标签模板函数。 |
| 能做什么 | 简化字符串拼接（不再需要 + 连接）；多行字符串无需 \n 转义；标签模板函数实现自定义字符串处理（如 styled-components 的 CSS-in-JS）。 |
| 怎么用 | `` `Hello, ${name}! You have ${count} messages.` ``、`` `多行\n字符串` ``、`` styled.div`color: ${color};` `` |
| 原理和工作流程 | 模板字符串在解析时识别 `${}` 表达式并计算插入值，转换为字符串拼接。标签模板函数接收字符串数组和所有插值表达式，可自定义处理逻辑，常用于 SQL 注入防护、国际化翻译等场景。 |
| 缺点 | 复杂模板字符串可读性不如 JSX 或单独的函数调用；字符串插值中不宜放复杂逻辑。 |

### 2.4 箭头函数

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 引入的简洁函数语法，使用 `=>` 定义，没有自己的 this、arguments、super、new.target，this 继承外层作用域。 |
| 能做什么 | 简化函数书写（尤其是回调函数）；解决 this 绑定问题（React 类组件中的方法绑定）；配合数组方法如 map/filter/reduce 实现简洁的函数式编程。 |
| 怎么用 | `const add = (a, b) => a + b;`、`arr.map(item => item * 2);`、`setTimeout(() => { this.doSomething(); }, 1000);` |
| 原理和工作流程 | 箭头函数没有自身的 this 绑定，其 this 值在函数定义时从外层作用域继承，不会因调用方式改变。因此不能作为构造函数（无 prototype），不能使用 call/apply/bind 修改 this，没有 arguments 对象。 |
| 缺点 | 不能作为构造函数，不能使用 new 调用；不能作为 Generator 函数；不适用于需要动态 this 的场景（如事件处理中需要访问触发元素）。 |

### 2.5 Class 语法

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 引入的面向对象语法糖，本质是原型链继承的封装，提供 class、constructor、extends、super、static 等关键字。 |
| 能做什么 | 定义类、构造函数和实例方法；通过 extends 继承父类；通过 super 调用父类构造函数和方法；static 定义静态方法。 |
| 怎么用 | `class Person { constructor(name) { this.name = name; } sayHi() { console.log(this.name); } }`；`class Student extends Person { constructor(name, grade) { super(name); this.grade = grade; } }` |
| 原理和工作流程 | class 底层仍是原型链：实例方法定义在 `Person.prototype` 上，静态方法定义在类函数自身上。extends 设置 `Child.prototype.__proto__ = Parent.prototype`，super 调用父类构造函数。class 声明的类不存在变量提升。 |
| 缺点 | 语法糖可能让开发者忽视底层原型链机制；class 不支持私有属性（ES2020 引入 # 私有字段前需用 WeakMap 模拟）。 |

### 2.6 Map 与 Set

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 新增的两种数据结构：Map 是键值对集合，键可以是任意类型；Set 是值集合，值唯一不重复。 |
| 能做什么 | Map 替代普通对象作为字典（键不限于字符串）；Set 用于去重、集合运算（交集、并集、差集）；WeakMap 用于私有数据存储和 DOM 节点关联，不阻止 GC。 |
| 怎么用 | `new Map([['key', 'value']])`、`map.set(key, val).get(key)`；`new Set([1, 2, 3])`、`set.add(4).has(2)`；`[...new Set(arr)]` 数组去重 |
| 原理和工作流程 | Map 内部使用哈希表，键的比较基于 SameValueZero 算法（类似 === 但 NaN 等于自身）。Set 内部也是哈希表，保证值唯一性。WeakMap 和 WeakSet 的键必须是对象，且是弱引用，不阻止垃圾回收。 |
| 缺点 | Map 和 Set 不能直接使用 JSON.stringify 序列化；WeakMap 不可迭代，无法获取所有键。 |

### 2.7 模块化（ESM）

| 维度 | 内容 |
|------|------|
| 是什么 | ES6 官方模块系统，使用 import 和 export 关键字实现模块化，支持静态分析和 Tree Shaking。 |
| 能做什么 | 按需导入导出；默认导出和命名导出支持两种导入方式；静态结构允许打包工具进行 Tree Shaking 和死代码消除；浏览器原生支持（type="module"）。 |
| 怎么用 | `export const add = (a, b) => a + b;`；`export default function() {}`；`import { add } from './math.js';`；`import * as math from './math.js';`；`<script type="module" src="app.js"></script>` |
| 原理和工作流程 | ESM 是静态结构，编译阶段确定依赖关系，支持 Tree Shaking。浏览器中使用 ESM 脚本默认 deferred。import 提升到模块顶部，所有导入在模块代码执行前完成。循环依赖情况下，导出的是绑定引用而非值副本。 |
| 缺点 | Node.js 中 ESM 和 CJS 混用有兼容问题；旧版浏览器不支持；浏览器中跨域请求需要 CORS 配置。 |

## 2.8 ES2023 不可变数组方法与查找增强

| 维度 | 内容 |
|------|------|
| 是什么 | ES2023 引入的 4 个不可变数组方法（`toSorted()`、`toReversed()`、`toSpliced()`、`with()`）和 2 个逆向查找方法（`findLast()`、`findLastIndex()`），所有方法都不修改原数组，返回新数组。 |
| 能做什么 | 替代 `sort()`、`reverse()`、`splice()` 等会原地修改数组的方法，避免副作用引发的 Bug；在 React/Vue 等框架中直接用于状态更新，无需手动展开拷贝；`findLast()` 和 `findLastIndex()` 从数组末尾开始查找，适合查找最后一个匹配项的场景。 |
| 怎么用 | `arr.toSorted()` 返回排序后的新数组；`arr.toReversed()` 返回反转后的新数组；`arr.toSpliced(start, deleteCount, ...items)` 返回删除/替换后的新数组；`arr.with(index, value)` 返回替换指定索引后的新数组（支持负索引）；`arr.findLast(callback)` 从后往前查找元素；`arr.findLastIndex(callback)` 从后往前查找索引。 |
| 原理和工作流程 | 不可变方法借鉴函数式编程理念，在内部先创建数组的浅拷贝，再对拷贝执行操作并返回；`sort()` 原地排序时间复杂度 O(n log n)，`toSorted()` 额外 O(n) 空间开销；`with()` 可以理解为 `arr.slice()` + 索引赋值 的语法糖；`findLast()` 等价于 `[...arr].reverse().find()`。 |
| 缺点 | 不可变方法每次调用都会创建新数组，频繁操作大数组时有额外内存开销；`with()` 只能替换单个索引，批量替换不如 `toSpliced()`；部分旧浏览器（如 Safari 15.x）尚未支持，需要 polyfill。 |

### 2.9 ES2024 数据分组与 Promise 增强

| 维度 | 内容 |
|------|------|
| 是什么 | ES2024 引入的三个核心特性：`Object.groupBy()` 和 `Map.groupBy()` 用于声明式数据分组；`Promise.withResolvers()` 用于手动控制 Promise 的 resolve/reject；`String.prototype.isWellFormed()` 和 `toWellFormed()` 用于处理 Unicode 代理对。 |
| 能做什么 | `Object.groupBy()` 替代手写 `reduce` 分组逻辑，代码更简洁语义化；`Map.groupBy()` 支持非字符串键分组；`Promise.withResolvers()` 简化事件驱动场景的 Promise 创建；`toWellFormed()` 安全处理含孤立代理的字符串，避免序列化错误。 |
| 怎么用 | `Object.groupBy(array, callback)` 返回分组对象；`Map.groupBy(array, callback)` 返回分组 Map；`const { promise, resolve, reject } = Promise.withResolvers()` 一步获取 Promise 和 resolve/reject 函数；`str.isWellFormed()` 检查是否含孤立代理；`str.toWellFormed()` 将孤立代理替换为 U+FFFD。 |
| 原理和工作流程 | `groupBy` 内部遍历数组，对每个元素调用回调函数获取分组键，将元素追加到对应分组的数组中；`Promise.withResolvers()` 内部创建 Promise，将 resolve 和 reject 与 promise 打包返回，避免变量声明提升的问题；`isWellFormed` 检查字符串中是否存在不成对的 UTF-16 代理，`toWellFormed` 将不成对的代理替换为 U+FFFD。 |
| 缺点 | `Object.groupBy()` 返回的是普通对象（无 prototype），不能直接调用 `hasOwnProperty` 等方法；`Promise.withResolvers()` 如果滥用可能导致 Promise 链外的错误传播失控；`toWellFormed()` 会修改原始数据内容，可能导致静默数据丢失。 |

### 2.10 ES2025 Temporal API

| 维度 | 内容 |
|------|------|
| 是什么 | ES2025 正式定稿（Stage 4），已于 2025 年 6 月 25 日批准为 ECMAScript 标准。全新的日期时间 API，旨在全面替代 `Date` 对象，提供不可变、多时区、纳秒精度的日期时间处理能力。核心类型包括 `Temporal.Instant`、`Temporal.PlainDate`、`Temporal.PlainTime`、`Temporal.PlainDateTime`、`Temporal.ZonedDateTime` 和 `Temporal.Duration`。 |
| 能做什么 | 解决 `Date` 对象的可变性 Bug（`setMonth` 修改原对象）；完整支持 IANA 时区数据库（`Asia/Shanghai`、`Asia/Tokyo` 等）；自动处理月份天数计算（`2025-01-31` + 1 月 = `2025-02-28`）；纳秒精度时间戳；专用比较方法而非依赖时间戳对比。 |
| 怎么用 | `Temporal.PlainDate.from('2025-07-17')` 创建纯日期；`date.add({ months: 1 })` 返回新日期（不修改原对象）；`Temporal.ZonedDateTime.from({ timeZone: 'Asia/Shanghai', ... })` 创建带时区的日期时间；`zoned.withTimeZone('Asia/Tokyo')` 转换时区；`Temporal.Duration.from({ hours: 3, minutes: 45 })` 创建时间间隔。 |
| 原理和工作流程 | Temporal 的设计遵循不可变原则，所有修改操作返回新对象；内部使用 IANA 时区数据库进行精确的时区计算；日历算术基于 ISO 8601 日历系统，自动处理闰年、月末等边界情况；所有类型可以通过 `toString()` 序列化，通过 `from()` 反序列化。 |
| 缺点 | ES2025 正式定稿，但部分旧浏览器尚未原生支持（需通过 `@js-temporal/polyfill` 使用）；API 表面积较大，学习曲线比 `Date` 高；与现有的 `Date` 生态（如 `moment.js`、`date-fns`）不兼容，需要逐步迁移。 |

## 三、常见面试题

### 1. Promise 的三种状态和基本用法

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Promise 的三种状态（pending/fulfilled/rejected）和 then/catch/finally 基本用法。 |
| 能做什么 | 检验对 Promise 核心概念的掌握，是异步编程的基础考点。 |
| 怎么用 | 状态：pending → fulfilled 或 pending → rejected，不可逆；Promise.resolve() 和 Promise.reject() 创建已确定状态的 Promise；then/catch/finally 处理状态变化。 |
| 原理和工作流程 | Promise 构造函数执行器立即执行，resolve/reject 异步改变状态。then 返回新 Promise 支持链式调用，内部根据回调返回值决定新 Promise 状态。 |
| 缺点 | 容易忽略 then 返回新 Promise 的机制，以及返回值对下一个 then 的影响。 |

### 2. async/await 的使用和注意事项

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 async/await 的基本用法、与 Promise 的关系、错误处理、并发处理。 |
| 能做什么 | 检验对 async/await 的全面理解，能否在实际项目中正确使用。 |
| 怎么用 | async 函数返回 Promise；await 暂停函数等待 Promise 完成；try/catch 处理错误；并发用 Promise.all() 而非多个 await。 |
| 原理和工作流程 | async/await 基于 Promise 和 Generator，async 函数返回 Promise，await 相当于 then 回调的语法糖。多个 await 顺序执行可能降低性能，无依赖的异步操作应使用 Promise.all 并行。 |
| 缺点 | 容易写出"多个 await 顺序执行"的低效代码；忘记 try/catch 导致未处理拒绝。 |

### 3. 箭头函数和普通函数的区别

| 维度 | 内容 |
|------|------|
| 是什么 | 考查箭头函数与普通函数在 this 绑定、arguments、构造函数、prototype 四个方面的差异。 |
| 能做什么 | 检验对箭头函数适用场景和限制的理解。 |
| 怎么用 | this：箭头函数继承外层，普通函数动态绑定；arguments：箭头函数无，普通函数有；new：箭头函数不能作为构造函数，无 prototype；generator：箭头函数不能作为 Generator。 |
| 原理和工作流程 | 箭头函数没有自己的 this 和 arguments，在定义时从外层作用域继承。普通函数的 this 在调用时确定，遵循 new > 显式绑定 > 隐式绑定 > 默认绑定。 |
| 缺点 | 只记住"this 不一样"是不够的，需要说出四个具体差异。 |

### 4. ES6 模块化与 CommonJS 的区别

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 ESM 和 CJS 在语法、加载时机、输出方式、循环依赖处理四个方面的差异。 |
| 能做什么 | 检验对模块化方案的深入理解，Node.js 和浏览器环境的选择。 |
| 怎么用 | ESM：import/export，编译时加载，静态结构；CJS：require/module.exports，运行时加载，动态。ESM 输出引用绑定，CJS 输出值副本。 |
| 原理和工作流程 | ESM 在编译阶段确定依赖关系，静态分析支持 Tree Shaking，输出的是动态绑定引用；CJS 在运行时加载模块，输出的是值的浅拷贝。循环依赖时，ESM 能正确处理（因为输出引用），CJS 可能得到未完成的对象。 |
| 缺点 | 混淆"编译时"和"运行时"加载的区别；不知道循环依赖的处理差异。 |

## 四、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 汇总异步编程和 ES6+ 特性中 6 个高频错误：Promise 未处理拒绝、多个 await 顺序执行、箭头函数做构造函数、解构默认值、展开运算符浅拷贝、Map 键使用对象引用。 |
| 能做什么 | 帮助开发者避免常见异步编程陷阱和 ES6 特性误用。 |
| 怎么用 | 始终 catch 或 try/catch 处理 Promise 错误；无依赖异步用 Promise.all()；箭头函数不用于构造函数；解构注意默认值触发条件；深拷贝用 structuredClone；Map 键用字符串而非对象。 |
| 原理和工作流程 | 每个错误对应一个特性误解：Promise 拒绝未被捕获会导致 unhandledRejection；多个 await 顺序执行慢是因为后续 await 等待前面的完成；展开运算符是浅拷贝只复制第一层。 |
| 缺点 | 部分避坑方案需要理解底层实现，盲目套用可能引入新问题。 |
