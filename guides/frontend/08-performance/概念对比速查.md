### 强缓存 vs 协商缓存

| 对比维度 | 强缓存 | 协商缓存 |
|---------|--------|----------|
| 核心定位 | 浏览器在有效期内不发送请求，直接使用本地缓存 | 浏览器发送请求到服务器，服务器验证资源是否变化 |
| 是否发送请求 | 否，直接使用缓存 | 是，发送请求验证 |
| HTTP 状态码 | 200（from disk cache / from memory cache） | 304 Not Modified（未变化）或 200（新内容） |
| 控制头部 | Cache-Control: max-age、Expires | ETag / If-None-Match、Last-Modified / If-Modified-Since |
| 优先级 | 高（浏览器先判断强缓存） | 低（强缓存过期后才判断协商缓存） |
| 适用资源 | 带哈希的 JS/CSS、图片、字体（内容长期不变） | HTML 入口文件（需要及时更新） |
| 缓存位置 | 磁盘缓存（disk cache）或内存缓存（memory cache） | 不缓存，每次验证 |
| 选择建议 | 内容不变或通过文件名哈希控制版本时使用 | 内容可能变化且需要及时生效时使用 |

### preload vs prefetch vs preconnect

| 对比维度 | preload | prefetch | preconnect |
|---------|---------|----------|------------|
| 核心定位 | 声明式提前加载当前页面必需的关键资源 | 浏览器空闲时加载未来页面可能需要的资源 | 提前与第三方域名建立完整连接 |
| 优先级 | 高，浏览器立即加载 | 低，浏览器空闲时加载 | 中，提前建立连接但不加载资源 |
| 使用场景 | 首屏关键 CSS、字体文件、LCP 图片 | 下一页的 JS/CSS、可能访问的页面资源 | 确定会使用的第三方 API、CDN 域名 |
| 加载时机 | 页面加载时立即开始 | 浏览器空闲时（当前页面加载完成后） | 页面加载早期 |
| 建立内容 | 资源内容（文件） | 资源内容（文件） | DNS + TCP + TLS 连接（不含资源内容） |
| 未使用后果 | 3 秒内未使用触发浏览器控制台警告 | 无影响，资源可能被缓存供后续使用 | 无影响，连接建立后若未使用会超时关闭 |
| 选择建议 | 仅用于确定会立即使用的关键资源，避免滥用 | 用于高概率访问的下一页资源 | 用于确定会使用的第三方域名，减少后续请求延迟 |

### 防抖 vs 节流

| 对比维度 | 防抖（Debounce） | 节流（Throttle） |
|---------|-----------------|-----------------|
| 核心定位 | 连续触发只执行最后一次，每次触发重置计时器 | 固定时间间隔内只执行一次，记录上次执行时间 |
| 执行时机 | 停止触发后延迟 N 毫秒执行 | 每 N 毫秒最多执行一次 |
| 触发频率 | 最终执行一次 | 均匀分布，定期执行 |
| 实现核心 | 每次触发 clearTimeout 重置定时器 | 记录上次执行时间，间隔不足则跳过 |
| 典型场景 | 搜索框输入联想、窗口 resize、按钮防重复提交 | 滚动事件监听、鼠标移动、无限滚动加载 |
| 用户感知 | 持续触发期间完全无反馈 | 持续触发期间有定时反馈 |
| 选择建议 | 关注"最终结果"时使用（如搜索请求只关心最终输入） | 关注"持续反馈"时使用（如滚动进度需要实时更新） |

### SSR vs SSG vs ISR vs CSR

| 对比维度 | SSR（服务端渲染） | SSG（静态生成） | ISR（增量静态再生） | CSR（客户端渲染） |
|---------|------------------|----------------|---------------------|-------------------|
| 核心定位 | 每次请求在服务端渲染完整 HTML | 构建时预渲染为静态 HTML 文件 | 首次请求时生成静态页面，之后按 revalidate 间隔复用 | 浏览器下载空 HTML 壳，由 JS 渲染内容 |
| 渲染时机 | 每次请求时 | 构建时 | 首次请求时生成，后续按间隔更新 | 浏览器端运行时 |
| 数据新鲜度 | 实时 | 构建时（部署时） | 可配置（revalidate 秒级间隔） | 实时 |
| 首屏速度 | 快 | 最快 | 快（首次较慢，后续快） | 慢（需等待 JS 下载执行） |
| 服务器压力 | 高（每次请求都渲染） | 低（纯静态文件） | 中（首次请求或 revalidate 时渲染） | 最低（仅提供静态文件） |
| SEO 友好 | 是 | 是 | 是 | 否（搜索引擎爬取效果差） |
| 适用场景 | 个性化内容、实时数据页面 | 文档、博客、营销页、产品介绍页 | 商品详情页、新闻列表、内容更新不频繁的页面 | 后台管理系统、需登录的应用 |
| 框架支持 | Next.js、Nuxt.js | Next.js、Nuxt.js、Gatsby | Next.js（ISR 特性） | React、Vue SPA |
| 选择建议 | 内容个性化强、SEO 要求高 | 内容不常变化、追求极致性能 | 内容更新不频繁但需 SEO | 无需 SEO 的内部应用 |

### 重排 vs 重绘

| 对比维度 | 重排（Reflow） | 重绘（Repaint） |
|---------|---------------|----------------|
| 核心定位 | 元素几何属性变化导致浏览器重新计算布局 | 元素外观属性变化但不影响布局，仅重新绘制 |
| 触发条件 | 修改宽高、边距、定位、添加/删除 DOM、读取 offsetTop/scrollTop 等布局属性 | 修改 color、background-color、box-shadow、visibility 等外观属性 |
| 开销 | 大，需重新计算几何属性、构建布局树、绘制 | 较小，跳过布局计算，直接绘制 |
| 触发关系 | 重排一定触发重绘 | 重绘不一定触发重排 |
| 优化策略 | 批量修改 DOM、使用 className 一次性应用、DocumentFragment、离线 DOM、transform 动画、读写分离、requestAnimationFrame | 使用 will-change 提前告知浏览器、使用 CSS 动画而非 JS 动画 |
| 渲染管线阶段 | 涉及 Layout 阶段 | 跳过 Layout 阶段，仅 Paint 和 Composite |
| 选择建议 | 优先使用 transform 和 opacity 替代 top/left/width/height 等触发布局的属性 | 无法避免时，通过批量操作减少重绘次数 |

### LCP vs INP（FID） vs CLS

| 对比维度 | LCP（最大内容绘制） | INP（交互到下次绘制） | CLS（累积布局偏移） |
|---------|-------------------|----------------------|---------------------|
| 核心定位 | 衡量页面加载性能，视口内最大可见元素完成渲染的时间 | 衡量页面交互响应性，所有交互延迟的第 98 百分位值 | 衡量页面视觉稳定性，意外布局偏移的累积分数 |
| 良好标准 | < 2.5s | < 200ms | < 0.1 |
| 需改进标准 | 2.5s ~ 4.0s | 200ms ~ 500ms | 0.1 ~ 0.25 |
| 差标准 | >= 4.0s | >= 500ms | >= 0.25 |
| 测量方式 | PerformanceObserver 监听 largest-contentful-paint | PerformanceObserver 监听 event timing（需要真实用户交互） | PerformanceObserver 监听 layout-shift |
| 优化方向 | 预加载关键资源、CDN、压缩图片、优化关键渲染路径 | 减少长任务、代码分割、Web Worker、避免同步耗时操作 | 设置图片/视频宽高、预留动态内容空间、font-display: swap |
| 与 FID 的关系 | 无关 | INP 于 2024 年 3 月替代 FID，FID 仅测量首次交互延迟，INP 测量所有交互延迟 | 无关 |
| 选择建议 | 关注加载速度，优先保障首屏体验 | 关注交互流畅度，避免长任务阻塞 | 关注视觉稳定，预留内容空间 |

> 三者共同构成 Google Core Web Vitals，是搜索排名影响因素，缺一不可。
