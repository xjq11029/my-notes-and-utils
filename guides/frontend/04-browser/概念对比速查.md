### 重排 vs 重绘

| 对比维度 | 重排（Reflow） | 重绘（Repaint） |
|---------|---------------|----------------|
| 触发条件 | 修改影响元素几何属性（宽高、位置、显示隐藏） | 修改不影响几何属性的样式（颜色、背景、阴影） |
| 触发阶段 | 触发Layout阶段，重新计算布局 | 跳过Layout阶段，直接进入Paint阶段 |
| 性能成本 | 高，可能引发级联重排 | 相对较低 |
| 触发操作 | 修改width/height、增删DOM、改变字体、获取offsetWidth | 修改color、background、box-shadow、visibility |
| 优化方案 | 使用transform替代top/left，使用flex/grid替代float | 使用will-change提示浏览器，使用合成层 |
| 选择建议 | 最小化重排次数，使用动画时优先使用transform | 控制重绘范围，避免频繁的颜色变化 |

### 宏任务 vs 微任务

| 对比维度 | 宏任务（MacroTask） | 微任务（MicroTask） |
|---------|--------------------|--------------------|
| 常见来源 | setTimeout、setInterval、I/O、postMessage | Promise.then、MutationObserver、queueMicrotask |
| 执行时机 | 每个事件循环从宏任务队列取一个执行 | 每个宏任务执行完后，清空微任务队列 |
| 优先级 | 低于微任务，宏任务之间可能插入UI渲染 | 高于宏任务，在下次渲染前执行 |
| 队列数量 | 一个任务队列 | 一个微任务队列 |
| 执行策略 | 每次取一个执行 | 一次性清空所有微任务 |
| 典型场景 | 延迟执行、定时任务、用户交互回调 | 状态更新后的DOM操作、链式Promise |
| 选择建议 | 需要延迟执行或与UI渲染相关时使用 | 需要尽快执行且不阻塞渲染时使用 |

---

### 同源 vs 跨域

| 对比维度 | 同源 | 跨域 |
|---------|------|------|
| 核心定位 | 协议+域名+端口完全相同 | 协议、域名、端口任一不同 |
| 资源访问 | 可以自由访问DOM、Cookie、Storage | 受限，浏览器默认阻止 |
| 通信方式 | 直接调用 | 需要CORS、JSONP、postMessage、代理等方式 |
| 安全性 | 相对安全，同源策略保护 | 需要安全配置，防范CSRF等攻击 |
| XHR/Fetch | 直接发送请求 | 需要服务端CORS头支持 |
| Cookie | 可以设置和读取 | 默认不携带，需要withCredentials配置 |
| 选择建议 | 同源策略是浏览器安全基石 | 跨域方案选择：CORS（推荐）> 代理 > JSONP（不推荐） |

---

### XSS vs CSRF

| 对比维度 | XSS（跨站脚本攻击） | CSRF（跨站请求伪造） |
|---------|--------------------|---------------------|
| 攻击目标 | 在用户浏览器中执行恶意脚本 | 在用户不知情下发起伪造请求 |
| 攻击方式 | 注入恶意脚本到页面中 | 利用用户已登录状态发起请求 |
| 防护手段 | 输入转义、输出编码、CSP、HttpOnly Cookie | CSRF Token、SameSite Cookie、Referer校验 |
| 危害 | 窃取Cookie、篡改页面、钓鱼攻击 | 修改用户数据、发起转账、更改密码 |
| 攻击位置 | 用户浏览器端 | 用户浏览器端（利用服务端信任） |
| 检测难度 | 较难检测，需要全面防御 | 相对容易检测，可通过Token机制防御 |
| 选择建议 | 多层防御：输入校验+输出编码+CSP+HttpOnly | 优先使用SameSite Cookie + CSRF Token双层防护 |
