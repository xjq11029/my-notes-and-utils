# 浏览器原理 - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 频繁修改DOM样式导致布局抖动 | 每次修改样式都可能触发重排，读值后立即写值造成强制同步回流 | 使用className批量修改样式，使用requestAnimationFrame批量更新DOM | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 使用for循环批量插入DOM导致卡顿 | 每次appendChild都触发一次回流 | 使用DocumentFragment批量插入，或使用innerHTML一次性设置 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 在JS中直接操作DOM导致动画性能差 | 直接在JS中修改样式触发重排 | 使用transform和opacity操作动画，利用合成线程避免重排 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 使用width/height/getComputedStyle触发重排 | 在修改样式后立即读取布局属性触发强制回流 | 先批量读取所有尺寸，再统一修改，避免读写交替 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 使用eval或with导致V8无法优化 | 动态作用域阻止V8的内联缓存优化 | 避免使用eval和with，使用对象属性访问代替 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 大量使用delete删除对象属性导致V8降级 | 删除属性破坏隐藏类结构 | 将不需要的属性设置为null或undefined，避免使用delete | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 宏任务与微任务混用导致执行顺序错误 | 不理解事件循环中宏任务和微任务的执行顺序 | 每个宏任务执行完立即清空微任务队列，再执行下一个宏任务 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 使用定时器做动画出现掉帧和抖动 | setTimeout/setInterval精度不足，无法与屏幕刷新率同步 | 使用requestAnimationFrame实现动画，与浏览器刷新率同步 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 用户输入未经转义直接渲染到HTML中 | 对XSS攻击的防御意识不足 | 使用textContent设置文本内容，使用DOMPurify清洗HTML，设置CSP策略 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| CORS请求失败但不知原因 | 不了解跨域资源共享的策略和header设置 | 在服务端设置Access-Control-Allow-Origin头，配置正确的CORS策略 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 未设置SameSite属性导致CSRF漏洞 | 不了解Cookie的SameSite属性对CSRF的防护作用 | 设置SameSite=Strict或Lax，配合CSRF Token双重防护 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 忽略Service Worker缓存导致页面更新不及时 | Service Worker拦截请求但不更新缓存 | 使用SW版本号管理缓存，实现合理的缓存更新策略 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| JSONP请求未验证来源导致数据泄露 | JSONP不受同源策略限制，容易被恶意站点利用 | 避免使用JSONP，改用CORS方案，如果必须使用则验证Referer | [浏览器笔面试题集导览](./03-浏览器笔面试题集-导览.md) |
| 使用localStorage存储敏感数据导致泄露 | localStorage可以被JS直接读取，无法设置过期时间 | 敏感数据使用httpOnly Cookie存储，设置合理的过期时间 | [浏览器笔面试题集导览](./03-浏览器笔面试题集-导览.md) |
| 组件卸载后定时器仍在运行，内存持续增长 | 定时器回调引用了组件与 DOM，无法被回收 | 组件卸载时务必 `clearInterval`/`clearTimeout` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 元素已删除但事件监听仍留在内存中，事件多次触发 | `addEventListener` 与 `removeEventListener` 未配对 | 绑定与解绑成对出现，卸载时移除全部监听 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 对象属性访问性能差 | 大量动态添加属性导致 V8 隐藏类频繁变化 | 在构造函数中一次性声明所有属性，避免动态增删 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 全局内存泄漏，变量一直不回收 | 忘记声明变量，变量被挂到 `window` 上 | 使用严格模式 `'use strict'`，用 TS 从源头规避 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 缓存导致内存持续增长 | 缓存越来越大，旧数据从不清理 | 设置缓存最大容量，采用 LRU 淘汰策略 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 全局写 `will-change: transform`，GPU 内存暴涨、合成更慢 | `will-change` 会长期占用图层与纹理内存 | 只在即将动画的元素上临时添加，动画结束改回 `auto` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 无脑用 `translateZ(0)` 提升图层，文本渲染变差 | 旧 hack，无条件创建图层导致图层数量失控 | 用 `transform`/`opacity` 做动画，按需配合 `will-change` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 以为提升图层后任何改动都不重绘 | 提升只让合成属性的变化跳过布局与绘制 | 动画属性限定为 `transform` / `opacity`，改背景色仍会重绘 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 滚动时卡顿、迟滞 | 未用 passive 监听 touch/wheel，浏览器要等主线程决定是否 `preventDefault` | 添加 `{ passive: true }` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 元素被提升为合成层后 `position: fixed` 失效 | 提升创建了新的包含块 | 把 `fixed` 元素移出被提升的元素，或重新规划层级 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 图层提升后子元素 `z-index` 不生效 | 提升创建了新的层叠上下文 | 按层叠上下文树重新规划层级，必要时用 `isolation` 明确边界 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| `will-change: all` 或堆一堆属性，资源被按最坏情况分配 | 等于告诉浏览器"什么都可能变" | 只声明真正会变化的属性 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 页面同时预渲染多个链接，带宽和 CPU 被吃满 | 同时预渲染多个页面会消耗大量资源 | 控制预渲染数量（Chrome 限制 2 个），用 `eagerness` 控制触发时机 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| View Transitions 过渡期间 fixed 定位元素闪烁 | 过渡期间页面被渲染到伪元素树中，fixed 定位上下文变化 | 为 fixed 元素设置单独的 `view-transition-name` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 调用 `navigation.navigate()` 后页面完整刷新而非无刷新导航 | 未在 `navigate` 事件中调用 `event.intercept()` | 必须在 `navigate` 事件中调用 `event.intercept()` 才能实现同文档导航 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 预渲染页面导致埋点数据重复计数 | 预渲染页面也会执行 JS，分析代码被提前触发 | 监听 `document.onprerenderingchange`，延迟加载分析代码 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 以为 Shadow DOM 能隔离布局，shadow 内部尺寸变化照样引起外部重排 | 它只做 DOM/样式封装，渲染共享同一布局上下文 | 需要真正隔离布局时使用 `iframe` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 用文档选择器改 shadow 内部元素，样式完全不生效 | 文档选择器无法匹配 shadow tree 内部 | 用 `::part()`、CSS 自定义属性或 `:host` 暴露样式接口 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| `::slotted()` 匹配不到深层节点 | `::slotted()` 只匹配直接分配的顶层节点 | 用 CSS 变量传值，或在组件内部再包一层并暴露 `part` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 自定义元素内部块级布局异常 | 宿主默认是 inline，shadow 内容按 inline 参与布局 | 在 `:host` 上设置 `display: block` / `inline-block` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 外部监听拿到的 `event.target` 是宿主而非真实节点 | 事件跨边界被重定向到宿主 | 在 shadow 内部监听，或用 `composedPath()[0]` | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 每个组件各写一份 `<style>`，内存与样式开销累积 | 每个 shadow root 维护独立样式作用域 | 用 `adoptedStyleSheets` 共享 `CSSStyleSheet` 实例 | [浏览器渲染与V8原理导览](./01-浏览器渲染与V8原理-导览.md) |
| 用 `innerHTML` 渲染用户输入，页面被注入恶意脚本 | `innerHTML` 会执行 HTML 中的脚本 | 使用 `textContent`，或先用 DOMPurify 清洗 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| Promise 输出顺序与预期不符 | 不知道 `new Promise` 的构造函数是同步执行的 | 只把异步操作放在 Promise 构造函数中，理解其同步性 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 页面卡死、完全无法响应 | 微任务中不断产生新微任务，队列永远清空不完 | 微任务中不要递归产生微任务，改用 `setTimeout` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 跨域请求带 Cookie 失败 | 带 Cookie 时 `Access-Control-Allow-Origin` 不能为 `*` | 服务端必须返回具体域名，并设置 `Access-Control-Allow-Credentials` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| CSRF Token 放在 Cookie 中导致防护失效 | Cookie 会被浏览器自动携带，攻击者同样能利用 | Token 放在请求头或表单字段中，不要放 Cookie | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 使用 `document.domain` 跨域，部分浏览器不支持 | 该 API 已被 Chrome 115+ 和 Firefox 默认禁用 | 改用 `postMessage` 或 CORS 替代 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 期望 `persist()` 一定返回 true，逻辑假设数据安全 | 授权由浏览器启发式规则决定，可能被拒绝 | 无论结果如何都要有降级方案 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 在 Safari 无痕模式依赖 localStorage，`setItem` 直接抛 `QuotaExceededError` | 无痕模式下配额为 0 | 用内存兜底或直接降级提示 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 用户数据莫名消失 | 本地存储是 best-effort，会被 LRU 淘汰，Safari 还有 7 天无交互清理 | 关键数据同步到服务端，必要时申请 `persist()` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 只给 localStorage 加 try/catch，IndexedDB 写入失败无人处理 | IDB 超限表现为事务 abort，不会抛同步异常 | 监听 `transaction.onabort` 与 `request.onerror` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 在 IndexedDB 事务中 `await` 非 IDB Promise，报 `TransactionInactiveError` | 事务在当前任务与微任务结束后自动提交 | 先取出所需数据，再开新事务写入，或拆成两个事务 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| IndexedDB 游标只拿到第一条数据 | 游标需要手动推进 | 处理完当前项后调用 `cursor.continue()` / `advance()` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 用 `add` 更新已有数据报 `ConstraintError` | `add` 在键冲突时报错 | 新增用 `add`，更新用 `put` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 新页面卡在 `onblocked`，数据库版本升级失败 | 其它标签页仍占用旧连接 | 在 `db.onversionchange` 中调用 `db.close()` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 用 `open()` 打开低于当前版本的库报 `VersionError` | 版本号只能升不能降 | 统一维护版本常量；需要降级时先 `deleteDatabase` | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 存入函数或 DOM 节点报 `DataCloneError` | IndexedDB 只能存结构化克隆支持的类型 | 只存可序列化数据（含 `Map`/`Set`/`Blob`/`ArrayBuffer`） | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 以为写入成功其实被回滚 | 请求成功 ≠ 事务提交成功 | 以 `transaction.oncomplete` 作为成功标志 | [事件循环与Web安全导览](./02-事件循环与Web安全-导览.md) |
| 用 `encodeURI` 编码 URL 参数值，服务器解析错误 | `encodeURI` 保留了 `&`、`=` 等结构字符 | 参数值使用 `encodeURIComponent` 编码 | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 文件上传失败或服务端无法解析 | 手动设置了 `Content-Type: multipart/form-data`，缺少 `boundary` | 使用 `FormData` 时不要手动设置 `Content-Type` | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 非简单请求被浏览器拦截，CORS 报错 | 未处理 OPTIONS 预检请求 | 后端配置 `Access-Control-Allow-*` 头部，并正确处理 OPTIONS 方法 | [网络协议基础导览](./04-网络协议基础-导览.md) |
| HTTPS 页面加载 HTTP 资源失败 | 浏览器安全策略禁止混合内容 | 所有资源使用 HTTPS，或使用 `//` 协议相对 URL | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 请求一直挂起，页面无响应 | `fetch` 默认没有超时时间 | 用 `AbortController` + `setTimeout` 实现超时控制 | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 分页期间数据变化导致列表出现重复项 | offset 分页在数据新增后页边界漂移 | 改用 cursor-based 分页，或使用 snapshot 机制 | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 发布新版本后用户仍看到旧页面 | 静态资源设置了过长的 `max-age` | 文件名使用内容 hash，HTML 文件不缓存（协商缓存） | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 大文件上传没有进度提示 | `fetch` 不支持上传进度监听 | 使用 `XMLHttpRequest.upload.onprogress` 实现进度回调 | [网络协议基础导览](./04-网络协议基础-导览.md) |
| 触发限流后立即重试，被持续封禁 | 未按服务器建议的等待时间重试 | 429 响应时读取 `Retry-After` 头，等待后再重试 | [网络协议基础导览](./04-网络协议基础-导览.md) |
| CSP 配置了 `script-src 'unsafe-inline'`，XSS 防护失效 | `'unsafe-inline'` 允许所有内联脚本，完全绕过 CSP 的脚本控制 | 使用 nonce 或 hash 替代，配合 `'strict-dynamic'` 允许已授权脚本动态加载 | [前端安全深度导览](./05-前端安全深度-导览.md) |
| CSP Report-Only 模式长期不切换为强制执行，防护形同虚设 | 团队担心拦截导致功能异常，迟迟不敢切换 | 分阶段收紧：先分析报告修复违规点 → 按页面逐步强制执行 → 保留 report-uri 持续监控 | [前端安全深度导览](./05-前端安全深度-导览.md) |
| `pnpm audit` 报出的漏洞长期未修复 | 修复建议可能涉及 breaking change 或依赖版本冲突 | 建立漏洞修复 SLA（Critical 24h / High 7d），用 Renovate 自动提 PR，无法修复的做风险评估 | [前端安全深度导览](./05-前端安全深度-导览.md) |
