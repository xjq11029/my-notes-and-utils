# React - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 在条件语句中使用 Hooks，状态错乱或报错"渲染的 Hook 比预期少" | Hooks 依赖调用顺序，条件调用导致链表索引错位 | 始终在函数组件顶层调用 Hooks，条件逻辑放在 Hooks 调用之后 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useEffect 闭包捕获过期值，数据不更新 | 依赖数组不完整，effect 不会重新执行，一直使用初始值 | 使用 ESLint 规则 `react-hooks/exhaustive-deps` 检查，诚实填写依赖数组 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useEffect 中直接使用 async 函数，控制台警告或清理函数失效 | useEffect 回调不能是 async（返回 Promise 而非清理函数） | 在 useEffect 内部定义 async 函数并调用，保持回调返回清理函数或 undefined | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useCallback 依赖空数组但内部使用了 state，回调始终使用初始 state | 闭包捕获了初始值，依赖为空不会重新创建函数 | 将状态加入依赖数组，或使用函数式更新 `setCount(c => c + 1)` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 滥用 useMemo 缓存简单计算，代码复杂且性能反而下降 | useMemo 本身有开销（比较依赖、存储缓存），简单计算不值得缓存 | 仅对昂贵的计算（如大数组过滤、复杂数学运算）使用 useMemo | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 在 render 中创建新对象/函数，导致 React.memo 子组件仍然重渲染 | 每次渲染都创建新引用，浅比较判定为"变化" | 使用 useMemo 包裹对象和数组，useCallback 包裹函数 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useLayoutEffect 中执行耗时操作，页面渲染阻塞、长时间白屏 | useLayoutEffect 同步执行，阻塞浏览器渲染 | 耗时操作移到 useEffect 中异步执行，useLayoutEffect 仅用于同步读取 DOM 尺寸 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| Context 值变化导致所有消费者重渲染，性能差 | Context 值变化通知所有消费者，任一字段变化都触发全局渲染 | 拆分 Context 为多个独立 Context，或使用 useMemo 包裹 value | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 使用 index 作为 key，列表重排时大量 DOM 更新，输入框内容错乱 | index 不稳定，顺序变化导致 key 对应关系错乱 | 使用数据唯一 ID 作为 key，无 ID 时用 nanoid 生成 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 使用随机数作为 key，每次渲染全部节点重建，性能极差 | key 每次变化，React 无法复用节点 | 使用稳定的唯一标识，绝对禁止 `Math.random()` | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 滥用 useMemo/useCallback，代码可读性下降，内存开销增加 | 每个 memo 都需要存储缓存和比较依赖 | 仅在确实需要优化时使用，优先通过组件拆分和状态提升解决问题 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| Context 未拆分，全局状态中任一字段变化，所有消费者重渲染 | 所有消费者订阅同一个 Context | 按业务领域拆分多个 Context | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| useEffect 依赖数组不完整，闭包引用过期值导致逻辑错误 | 内部使用的变量未声明为依赖 | 开启 ESLint 规则，诚实填写依赖 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 将整个组件树用 React.memo 包裹，比较开销超过渲染开销 | 浅比较本身也有开销 | 仅对渲染开销大的子组件使用 React.memo | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 未使用生产模式构建，性能表现差 | 开发模式有额外的警告和严格模式检查 | 生产环境使用 `NODE_ENV=production` 构建 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| BrowserRouter 刷新后非首页路径 404 | 服务器未配置 fallback，找不到对应 HTML 文件 | Nginx 配置 `try_files $uri /index.html`，或使用 HashRouter | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Redux state 直接修改，state 被修改但 UI 不更新 | 直接修改破坏了不可变性，React 无法检测变化 | 始终返回新对象，或使用 RTK 的 immer 集成直接修改 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| useSelector 返回整个 state，任何字段变化都触发重渲染 | useSelector 默认使用严格相等比较 | 精确选择需要的字段，或使用 shallowEqual 比较器 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 路由守卫未处理异步状态，未登录时短暂显示受保护页面 | 异步检查登录状态，初始状态为 null | 添加 loading 状态判断，在认证状态确定前显示加载中 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Zustand selector 返回新引用，组件频繁重渲染 | selector 每次返回新对象，浅比较判定为变化 | 选择基本类型值，或使用 shallow 比较器 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 嵌套路由忘记 Outlet，子路由不显示 | 缺少 Outlet 作为子路由渲染出口 | 在父组件中放置 `<Outlet />` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| createAsyncThunk 未处理错误，异常未被捕获、应用崩溃 | thunk 内部抛出异常未处理 | 使用 extraReducers 处理 rejected 状态，显示错误信息 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 错误边界在 `getDerivedStateFromError` 中做日志上报，日志重复 | render 阶段有副作用，可能重复执行 | 日志上报放在 `componentDidCatch` 中，而不是 `getDerivedStateFromError` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 只包一个根级错误边界，局部错误放大为全站白屏 | 错误边界粒度太粗 | 在关键模块层级分别包裹错误边界，缩小爆炸半径 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 错误边界的 fallback 里没有 reset 机制，用户只能刷新页面 | 未提供恢复入口 | 在 fallback 中提供"重试"按钮，重置错误边界状态 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 以为错误边界能兜住接口请求失败 | 网络错误不会被错误边界捕获 | 网络错误在数据层处理（TanStack Query / SWR 的错误状态） | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 以为 Portal 会阻断事件冒泡，浮层内的点击触发了父组件逻辑 | React 事件沿组件树冒泡，而不是沿真实 DOM 树冒泡 | 浮层内需要 `stopPropagation`，或判断 `e.target` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| SSR 下直接调用 `createPortal` 报错 | 服务端没有 `document` | 用 `useEffect` 包裹，或用 `typeof document !== 'undefined'` 守卫 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| Portal 内容渲染后样式异常（字号、颜色、`box-sizing` 丢失） | 只改了 DOM 位置，忘了 CSS 继承链已变化 | 在 Portal 容器上补齐继承相关样式 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| Portal 浮层仍被其他层遮挡 | `z-index` 未配合 `position: fixed` 或层级值不够 | 给 Portal 容器设置合适的 `position` 与 `z-index` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 使用 Portal 后弹窗无法用键盘关闭、焦点逃逸 | 无障碍焦点管理需要自行处理 | 实现焦点陷阱、`aria-modal`、Esc 关闭 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| React 18 下 `useImperativeHandle` 的 `ref` 为 `null` 并报警告 | 忘记用 `forwardRef` 包裹组件 | 用 `forwardRef` 包裹（React 19 起 ref 可作为普通 prop 传递） | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| `useImperativeHandle` 的 `createHandle` 捕获了过期 props | 依赖数组为空，却使用了会变化的 props / state | 把用到的 props / state 加入依赖数组 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 通过 `useImperativeHandle` 暴露 `setState` 之类的写方法，破坏单向数据流 | 命令式 API 暴露了内部状态写入能力 | 只暴露读操作或受控命令（如 `focus()`、`scrollTo()`） | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 在 render 期间调用 `ref.current` 上的方法，报 ref 未赋值 | 此时 layout 阶段尚未执行 | 把命令式调用放到事件处理函数或 effect 中 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| `useSyncExternalStore` 报 "The result of getSnapshot should be cached" | `getSnapshot` 每次返回新对象或新数组 | 让 `getSnapshot` 返回缓存过的稳定引用 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| `useSyncExternalStore` 反复订阅与取消订阅 | `subscribe` 每次渲染都是新函数 | 用 `useCallback` 固定 `subscribe` 引用 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| SSR 下报 `Missing getServerSnapshot` | 忘记传第三个参数 | 提供 `getServerSnapshot` 返回服务端可用的初始快照 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 在 `subscribe` 内同步调用 `callback`，造成渲染循环 | 订阅时立即通知变更，触发重新渲染 | 只在数据真正变化时异步调用 `callback` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 只写 `value` 不写 `onChange`，输入框变只读并报警告 | 受控组件必须同时提供 `value` 与 `onChange` | 补齐 `onChange`，或改用非受控组件 + `defaultValue` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 受控/非受控切换警告 | 传 `value={undefined}` 时 React 视为非受控，切换会告警 | 始终传具体值，用 `''` 而不是 `undefined` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 修改 `defaultValue` 后 DOM 不同步 | `defaultValue` 只在首次挂载生效 | 需要重置时改变组件的 `key`，强制重新挂载 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 给 `<input type="file" />` 传 `value` 直接报错 | 文件输入框的值不可由 React 控制 | 只使用 `ref` 读取 `files`，不要传 `value` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 快速输入时字符丢失 | 在 `onChange` 中用 state 拼接新值（`setValue(value + char)`） | 直接使用 `e.target.value`，或使用函数式更新 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 用 `<BrowserRouter>` 却写 `loader`，loader 完全不执行 | `loader` / `action` 只属于数据路由 | 迁移到 `createBrowserRouter` + `<RouterProvider>`，或把取数逻辑放回组件 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 在 `errorElement` 中读 `error.message` 得到 `undefined` | `throw new Response(...)` 抛出的是 `Response` 而非 `Error` | 先用 `isRouteErrorResponse(error)` 判断，再读 `status` / `statusText` / `data` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 快速切换路由后旧请求仍返回并写回状态 | `loader` 中未传 `request.signal`，导航取消不会中止 `fetch` | 写成 `fetch(url, { signal: request.signal })` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| `loader` 中访问 `localStorage` / `document` 在 SSR 下报错 | `loader` 可能在服务端执行，没有浏览器 API | 浏览器相关逻辑移到组件或 `action`，或用 `typeof window !== 'undefined'` 守卫 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| `loader` 中 `setState` 或操作 DOM 报错 | `loader` 是纯数据函数，执行时组件尚未挂载 | 只返回数据，把副作用留在组件里 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| `loader` 抛错导致整个应用崩溃 | 没有就近的错误边界 | 在路由层级配置 `errorElement` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| `<Await>` 抛错或 fallback 不生效 | `<Await>` 依赖 React Suspense 机制 | 用 `<Suspense fallback={...}>` 包裹 `<Await>` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 使用 `defer` 后流式加载失效，退化为阻塞导航 | `defer` 的对象里对 Promise 做了 `await` | 只 `await` 关键数据，非关键 Promise 直接透传给 `defer` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 表单提交成功后 URL 不变，刷新回到旧数据 | `action` 只负责写，导航需要显式返回 | 写操作成功后 `return redirect(path)` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 用旧式 `lazy: () => import('./X')` 时 loader 仍在主包 | 旧式 `lazy` 只懒加载组件，不懒加载 loader | 改用返回 `{ Component, loader, action }` 的函数式 `lazy` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| `queryKey` 遗漏参数或混入无关 UI 状态，切换主题也触发重新请求 | 缓存键未完整表达请求依赖，或混入了无关值 | 把影响请求的所有参数都放进 `queryKey`，无关值剔除，用 `queryOptions` 统一管理 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 数据刚过期就被回收，缓存几乎不起作用 | `gcTime` 小于 `staleTime`，配置矛盾 | 保证 `gcTime` ≥ `staleTime`，一般为 3~10 倍 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| SSR 下用户 A 看到用户 B 的数据 | 模块级单例 `QueryClient` 在请求之间共享缓存 | 每个请求创建新的 `QueryClient` 实例 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 水合后立刻再请求一次接口 | 默认 `staleTime: 0`，灌入的数据立即变 stale | 服务端与客户端统一设置合理的 `staleTime` | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 乐观更新的数据被在途请求覆盖，UI 闪烁 | 在途请求与乐观写入竞争同一缓存 | `onMutate` 中先 `await queryClient.cancelQueries({ queryKey })` | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 乐观数据与服务端真实数据长期不一致 | 回滚只处理失败路径，成功路径缺少最终同步 | 在 `onSettled` 中 `invalidateQueries`，让服务端数据最终生效 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 无限滚动长时间使用后内存持续增长 | 所有页数据都保留在缓存中 | 设置 `maxPages` 限制保留页数 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 接口返回 404 / 500 被当作成功 | `fetch` 只在网络错误时 reject，HTTP 错误码不会抛错 | 在 `queryFn` 中手动 `if (!res.ok) throw new Error(...)` | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 取消请求被当作业务错误弹出提示 | 未区分 `AbortError` | 在 catch 中判断 `err.name !== 'AbortError'` 再处理 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
| 同一份数据出现两个真相，UI 不一致 | 手动 `fetch` 与 Query 混用，绕过了缓存 | 统一通过 `useQuery` / `setQueryData` 读写，保持单一数据源 | [数据请求与缓存层导览](./05-数据请求与缓存层-导览.md) |
