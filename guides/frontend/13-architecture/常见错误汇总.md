# 常见错误汇总

---

## 微前端常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 子应用样式影响主应用或其他子应用，全局样式错乱 | 未启用 CSS 隔离，或全局样式选择器未带前缀 | qiankun 启用 `experimentalStyleIsolation`；子应用使用 CSS Modules 或 BEM 命名；wujie 天然隔离 | [01-微前端架构-导览 - 2.1](./01-微前端架构-导览.md) |
| React hooks 报错 "Invalid hook call"，多个 React 实例冲突 | 主应用和子应用各自加载了独立的 React 副本，MF shared 未设置 singleton | 所有 shared 依赖必须设置 `singleton: true`，尤其是 react、react-dom、vue 等框架库 | [01-微前端架构-导览 - 2.2](./01-微前端架构-导览.md) |
| 子应用切换后内存泄漏，页面卡顿，定时器仍在运行 | 子应用 unmount 未清理全局事件监听、定时器、WebSocket 连接 | 在 unmount 生命周期中彻底清理：`clearInterval`、`removeEventListener`、`ws.close()` | [01-微前端架构-导览 - 3.1](./01-微前端架构-导览.md) |
| 子应用内部路由跳转后刷新页面出现 404 | 子应用路由与主应用路由冲突，或子应用未配置 historyApiFallback | 主应用配置通配路由捕获子应用路径；子应用 devServer 配置 `historyApiFallback: true` | [01-微前端架构-导览 - 3.3](./01-微前端架构-导览.md) |
| 子应用运行时出现奇怪的 undefined 错误 | 主应用和子应用使用了不同版本的共享依赖 | 统一 `package.json` 中的依赖版本；使用 Module Federation 的 `shared` + `singleton` 机制 | [01-微前端架构-导览 - 2.2](./01-微前端架构-导览.md) |
| 子应用 JS/CSS 加载失败 | 子应用 publicPath 配置不正确，或跨域头未设置 | 动态设置 `__webpack_public_path__`；配置 CORS 头 `Access-Control-Allow-Origin: *` | [01-微前端架构-导览 - 3.1](./01-微前端架构-导览.md) |

## 设计系统与组件库常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 业务代码中无意覆盖了组件库样式，导致组件显示异常 | 组件库样式优先级不够高，或使用了相同的选择器 | 使用 CSS @layer 将组件库样式放在低优先级层；使用 CSS Modules 或 CSS-in-JS 生成唯一类名 | [02-设计系统与组件库架构-导览 - 2.2](./02-设计系统与组件库架构-导览.md) |
| 页面加载时先显示默认主题，然后闪烁切换到用户保存的主题 | JavaScript 在客户端执行主题切换，晚于 CSS 渲染 | 在 `<head>` 中内联执行主题初始化脚本，阻止页面渲染直到主题设置完成 | [02-设计系统与组件库架构-导览 - 3.3](./02-设计系统与组件库架构-导览.md) |
| 项目打包后体积显著增加，首屏加载慢 | 全量引入组件库（如 `import { Button } from 'antd'` 可能引入整个 antd） | 使用支持 Tree Shaking 的组件库；按需引入；使用 ESM 格式；考虑使用 Headless UI + 自定义样式 | [02-设计系统与组件库架构-导览 - 1.3](./02-设计系统与组件库架构-导览.md) |

## 前端分层架构与技术管理常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 一个简单的 CRUD 页面需要经过 5 层调用，开发效率极低 | 教条式地套用分层架构，不考虑项目实际规模 | 小项目可以简化分层（如只分 View + Hook）；分层架构适用于中大型项目 | [03-前端分层架构与技术管理-导览 - 1.1](./03-前端分层架构与技术管理-导览.md) |
| 组件中直接调用 API、处理业务校验、格式化数据 | 开发者为了快速完成功能，将所有逻辑写在组件中 | 严格遵守分层规范；Code Review 时重点检查视图层是否包含业务逻辑 | [03-前端分层架构与技术管理-导览 - 3.1](./03-前端分层架构与技术管理-导览.md) |
| 引入不成熟的新技术，导致项目不稳定、团队成员学习成本高 | 技术选型时过于关注技术本身，忽略了团队能力和项目风险 | 使用五维度评估矩阵；优先选择团队熟悉的成熟技术；新技术先在小型项目中试点 | [03-前端分层架构与技术管理-导览 - 3.4](./03-前端分层架构与技术管理-导览.md) |
| 用岛屿架构构建高度交互的 SaaS 应用，页面交互响应慢、组件间通信困难 | 岛屿之间共享状态需要额外机制，而 SaaS 大部分组件都需要交互 | SaaS 应用使用 SSR/CSR 混合（如 Next.js App Router）；岛屿架构适合内容型网站 | [03-前端分层架构与技术管理-导览 - 6.4](./03-前端分层架构与技术管理-导览.md) |
| 在 Astro 中导入含副作用的第三方库导致构建失败或运行时错误 | 岛屿组件在服务端和客户端执行环境不同 | 使用 `client:only` 指令跳过 SSR，或用 `import.meta.env.SSR` 条件判断 | [03-前端分层架构与技术管理-导览 - 6.4](./03-前端分层架构与技术管理-导览.md) |
| Qwik 中闭包序列化错误或 JS 体积膨胀 | 忘记用 `$()` 包装函数，未标记的函数无法被正确拆分 | 所有事件处理函数、异步任务必须用 `$()` 包装 | [03-前端分层架构与技术管理-导览 - 6.4](./03-前端分层架构与技术管理-导览.md) |
| 页面切换时岛屿状态丢失 | 混淆 Islands 与传统 SPA 路由；Astro 默认是 MPA 模式，每次导航会重新加载页面 | 使用 Astro 的 View Transitions 或 SPA 模式（`transition:persist`）保持岛屿状态 | [03-前端分层架构与技术管理-导览 - 6.4](./03-前端分层架构与技术管理-导览.md) |
| 首屏 JS 体积过大，加载变慢 | 过度使用 `client:load`，所有岛屿都立即水合，失去了岛屿架构的优势 | 按交互优先级选择水合策略：`idle`、`visible` 或 `media` | [03-前端分层架构与技术管理-导览 - 6.4](./03-前端分层架构与技术管理-导览.md) |

## BFF 与权限架构常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| BFF 演变成新的巨石，改一处要全量回归 | 团队把业务逻辑写进 BFF，而非只做聚合编排 | BFF 只做聚合、裁剪、协议转换；业务逻辑归下游领域服务 | [05-BFF与权限架构-导览 - 1.1](./05-BFF与权限架构-导览.md) |
| 同一段校验逻辑在前端、BFF、后端各写一遍，三处不一致导致脏数据 | 没有明确"校验归属" | 格式校验在前端（体验），业务校验在领域服务（唯一可信），BFF 只透传 | [05-BFF与权限架构-导览 - 1.2](./05-BFF与权限架构-导览.md) |
| 客户端能调到下游内部管理接口 | 只做转发未做接口白名单 | 用显式路由表（白名单）；禁止 `app.use('*', proxy)` 式通配转发 | [05-BFF与权限架构-导览 - 2.1](./05-BFF与权限架构-导览.md) |
| CDN 把 A 用户的数据返回给 B 用户 | 带用户身份的接口未设 `Cache-Control: private`，且 CDN 忽略 Cookie 缓存 | 用户私有接口强制 `private`；CDN 对 `/api/` 默认不缓存；上线前做缓存穿透测试 | [05-BFF与权限架构-导览 - 2.2](./05-BFF与权限架构-导览.md) |
| 优惠券服务抖动导致整个首页白屏 | 聚合接口用 `Promise.all`，未区分关键与非关键数据 | 关键数据用 `Promise.all`，非关键数据用 `Promise.allSettled` + 兜底值，并返回 `degraded` 标记 | [05-BFF与权限架构-导览 - 2.2](./05-BFF与权限架构-导览.md) |
| BFF 事件循环被慢下游占满，全部接口变慢 | 下游调用未设置请求超时 | 所有下游调用必须设超时（`AbortSignal.timeout`），并配合熔断器 | [05-BFF与权限架构-导览 - 2.2](./05-BFF与权限架构-导览.md) |
| 用户看到他人数据（跨用户缓存泄露） | DataLoader 做成了全局单例，请求级缓存跨请求存活 | DataLoader 必须按请求创建，随请求上下文回收 | [05-BFF与权限架构-导览 - 2.1](./05-BFF与权限架构-导览.md) |
| 动态路由注册后页面空白或 404 | `router.addRoute` 后未重新导航，当前导航已按旧路由表解析完成 | 守卫中返回 `{ ...to, replace: true }` 触发重新匹配 | [05-BFF与权限架构-导览 - 3.1](./05-BFF与权限架构-导览.md) |
| 切换账号后低权限用户仍能通过地址访问旧权限页面 | 登出时未移除动态路由，`addRoute` 注册的路由仍在内存中 | 保存 `addRoute` 返回的移除函数，登出时逐个调用 | [05-BFF与权限架构-导览 - 3.1](./05-BFF与权限架构-导览.md) |
| 动态路由永远匹配不到，全部跳 404 | 404 通配路由 `/:pathMatch(.*)*` 在动态路由之前注册 | 通配路由必须最后注册，或用 `hasRoute` 显式判断 | [05-BFF与权限架构-导览 - 3.1](./05-BFF与权限架构-导览.md) |
| Token 超过 8KB 被网关拒绝；权限变更需等 Token 过期 | 把权限码放进了 JWT Payload，而权限码数量多且 Token 体积敏感 | Token 只放 `userId` + `tenantId` + `permVersion`；权限清单由独立接口返回 | [05-BFF与权限架构-导览 - 3.2](./05-BFF与权限架构-导览.md) |
| 攻击者遍历 ID 枚举出有效资源区间 | 无权返回 403、不存在返回 404，状态码可区分 | 统一返回 404；日志中记录真实原因供排查 | [05-BFF与权限架构-导览 - 3.3](./05-BFF与权限架构-导览.md) |
| 打开 Network 面板即可看到完整手机号 | 只在前端做了 `138****8888` 展示脱敏，响应体仍含原始值 | 敏感字段在后端删除或脱敏后再返回，前端拿不到原始值 | [05-BFF与权限架构-导览 - 3.3](./05-BFF与权限架构-导览.md) |
| 跨租户串数据，A 公司看到 B 公司数据 | 多租户缓存 Key 未含租户 ID | 统一格式 `tenant:{tid}:...`；用工具函数生成 Key 避免手写 | [05-BFF与权限架构-导览 - 3.4](./05-BFF与权限架构-导览.md) |
| 同一用户在不同请求间命中不同灰度版本，数据错乱 | 按随机数分流而非按稳定标识哈希 | 按用户 ID / 设备 ID 哈希取模，保证同一用户稳定命中 | [05-BFF与权限架构-导览 - 2.3](./05-BFF与权限架构-导览.md) |

## 国际化与多端同构常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 改一次文案后全项目 key 失效，所有翻译丢失 | 直接用源语言文案当 i18n key | key 用语义化命名空间（`order.action.submit`）；key 一旦发布不改名，重构时保留旧 key 作别名 | [06-国际化与多端同构-导览 - 2.1](./06-国际化与多端同构-导览.md) |
| 俄语、阿拉伯语等语言复数形式错误 | 只写了 `one` / `other` 两个分支，假设所有语言只有两种复数类别 | 按 CLDR 规则补全分支；用 `Intl.PluralRules` 验证 | [06-国际化与多端同构-导览 - 2.2](./06-国际化与多端同构-导览.md) |
| 其他语言语序错乱 | 用字符串拼接代替消息模板，如 `'你有 ' + count + ' 条消息'` | 整句作为 ICU 消息模板，变量交给 MessageFormat 处理 | [06-国际化与多端同构-导览 - 2.2](./06-国际化与多端同构-导览.md) |
| `€1.234,56` 被写成 `€1234.56` | 手写货币符号与千分位 | 用 `Intl.NumberFormat` 的 `style: 'currency'` | [06-国际化与多端同构-导览 - 2.3](./06-国际化与多端同构-导览.md) |
| 金额出现 `0.30000000000000004`，对账差异 | 用浮点数（`Number`）表示元并参与运算 | 以最小货币单位（分）的整数传输；后端返回 `{ amount, currency }` | [06-国际化与多端同构-导览 - 2.3](./06-国际化与多端同构-导览.md) |
| 跨时区用户看到的时间相差数小时 | 接口返回无时区的字符串，如 `2026-09-17 10:00:00` | 统一返回 ISO 8601（带 `Z` 或偏移）；前端用 `Intl` 的 `timeZone` 显式格式化 | [06-国际化与多端同构-导览 - 2.3](./06-国际化与多端同构-导览.md) |
| 服务端（UTC）与客户端（+08:00）判断"今天"结果不一致 | 用 `new Date().getDate()` 判断日期，未显式指定时区 | 用 `Intl.DateTimeFormat` 指定业务时区后比较日期字符串 | [06-国际化与多端同构-导览 - 2.3](./06-国际化与多端同构-导览.md) |
| SSR 页面出现注水不匹配警告，内容短暂闪烁 | 服务端按 `Accept-Language` 定语言，客户端自行 `detectLocale()`，两侧 locale 不一致 | 服务端把 locale 序列化传给客户端，客户端初始化时直接使用 | [06-国际化与多端同构-导览 - 3.1](./06-国际化与多端同构-导览.md) |
| 数据含 `</script>` 时被提前闭合，造成 XSS | 把 `JSON.stringify` 的结果直接内联到 `<script>` | 用 `serialize-javascript` 的 `isJSON: true`，或 `replace(/</g, '\\u003c')` | [06-国际化与多端同构-导览 - 3.1](./06-国际化与多端同构-导览.md) |
| 界面出现中英混杂 | 语言包缺失 key，依赖 `fallbackLocale` 兜底 | CI 中校验 key 一致性、占位符一致性、空值；不依赖 fallback 兜底 | [06-国际化与多端同构-导览 - 2.4](./06-国际化与多端同构-导览.md) |
| 切换语言后部分文案不更新 | 缓存了 `t()` 的返回值，如 `const TITLE = t('...')` 在模块加载时执行一次 | 在渲染时调用 `t()`，或用 `computed(() => t('...'))` | [06-国际化与多端同构-导览 - 2.4](./06-国际化与多端同构-导览.md) |
| RTL 语言下布局错乱，间距出现在错误一侧 | 只用了 `margin-left` 等物理属性 | 改用逻辑属性：`margin-inline-start`、`inset-inline-start`、`text-align: start` | [06-国际化与多端同构-导览 - 2.5](./06-国际化与多端同构-导览.md) |
| 整体 `scaleX(-1)` 翻转后文字镜像不可读、数字反向 | 未区分方向性图标与不可翻转元素 | 只翻转方向性图标；图表逐项配置 `inverse` / `position` | [06-国际化与多端同构-导览 - 2.5](./06-国际化与多端同构-导览.md) |
| 弹窗、下拉、分页器方向仍为 LTR | 只设置了 `dir="rtl"`，未引入组件库的 RTL 样式 | Ant Design 用 `direction="rtl"`；Element Plus 引入 RTL 样式文件 | [06-国际化与多端同构-导览 - 2.5](./06-国际化与多端同构-导览.md) |
| 搜索引擎只抓到默认语言，多语言页面不被索引 | 用 `navigator.language` 或 Cookie 在客户端做语言跳转 | 语言体现在 URL 中，服务端按 URL 前缀渲染；`Accept-Language` 只用于 302 | [06-国际化与多端同构-导览 - 4.1](./06-国际化与多端同构-导览.md) |
