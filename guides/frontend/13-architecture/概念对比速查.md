## 一、微前端方案对比

| 维度 | qiankun | Module Federation | wujie |
|---|---|---|---|
| 出品方 | 阿里 | Webpack 5 官方 | 腾讯 |
| 隔离方式 | JS Proxy 沙箱 + CSS 前缀/Shadow DOM | 无内置沙箱，依赖 shared 配置 | iframe + WebComponent 双保险 |
| 改造成本 | 高（主应用 + 子应用均需改造） | 中（仅需修改构建配置） | 低（子应用几乎零改造） |
| 运行时性能 | 中（Proxy 遍历开销） | 高（共享依赖，减少重复加载） | 中（iframe 开销，保活模式可优化） |
| 样式隔离 | 实验性（前缀）/ 严格（Shadow DOM） | 无（依赖团队规范） | 天然隔离（iframe） |
| JS 隔离 | 强（Proxy 沙箱） | 无（依赖团队规范） | 强（iframe 独立 window） |
| 技术栈限制 | 无 | 同技术栈（React/React 或 Vue/Vue） | 无 |
| 跨域支持 | 需配置 CORS | 需配置 CORS | 原生支持 |
| 子应用嵌套 | 不支持 | 支持 | 支持 |
| 社区生态 | 成熟（中文文档完善） | 成熟（Webpack 官方） | 发展中 |
| 适用场景 | 存量系统改造、多技术栈共存 | 全新项目、同技术栈、追求性能 | 快速接入、强隔离、跨域子应用 |

**选择建议**：
- 存量 Vue 2 项目迁移到 Vue 3 → **qiankun**
- 全新 React 项目，多团队并行 → **Module Federation**
- 需要接入第三方不可信子应用 → **wujie**
- 子应用部署在独立域名 → **wujie**

## 二、组件库模式对比

| 维度 | Headless UI（Radix UI） | Copy-in（shadcn/ui） | 传统 npm 包（Ant Design） |
|---|---|---|---|
| 样式控制 | 完全自定义 | 可自由修改源码 | 受限于主题配置 |
| 开发效率 | 低（需自己写样式） | 中（复制后修改） | 高（开箱即用） |
| 体积 | 小（仅逻辑） | 中（按需复制） | 大（全量安装） |
| 可访问性 | 优秀（内置 WAI-ARIA） | 好（继承 Radix UI） | 一般（部分支持） |
| 更新方式 | pnpm update | 手动重新复制 | pnpm update |
| 设计一致性 | 依赖团队设计系统 | 依赖团队设计系统 | 内置设计语言 |
| 学习曲线 | 中（需学库 API + 样式方案） | 低（标准 React 组件） | 低（文档完善） |
| 适用场景 | 有成熟设计系统的团队 | 快速启动，需要高度定制 | 后台管理系统、快速原型 |

**选择建议**：
- 有自己的设计团队和设计系统 → **Headless UI**
- 快速启动项目，后续需要深度定制 → **Copy-in（shadcn/ui）**
- 后台管理系统，对样式没有特殊要求 → **传统 npm 包**

## 三、CSS 方案对比

| 维度 | Tailwind CSS v4 | Panda CSS | StyleX | CSS Modules |
|---|---|---|---|---|
| 类型 | 原子 CSS | 原子 CSS + 样式函数 | 原子 CSS（Meta） | 作用域 CSS |
| 语法 | 工具类（HTML 中） | `css({})` 对象语法 | `stylex.create()` | `.module.css` 文件 |
| 运行时 | 0 | 0 | 0 | 0 |
| 类型安全 | 中（VSCode 插件） | 强（TS 类型推断） | 强（Flow/TS） | 弱 |
| 学习曲线 | 低 | 中 | 高 | 低 |
| 构建工具 | 独立 CLI / PostCSS | 独立 CLI | Webpack/Rollup 插件 | 各构建工具原生支持 |
| 设计令牌集成 | 通过 `theme.extend` | 原生支持 | 通过 `defineVars` | 通过 CSS 变量 |
| 动态样式 | 受限（需完整类名） | 支持（`css({ color: props.color })`） | 支持 | 受限 |
| 适用场景 | 快速开发、团队协作 | 类型安全要求高的项目 | 大型 Meta 风格项目 | 传统项目、简单项目 |

**选择建议**：
- 追求开发效率，团队熟悉工具类 → **Tailwind CSS v4**
- 需要强类型安全 + 设计令牌集成 → **Panda CSS**
- 简单项目，不想引入额外依赖 → **CSS Modules**

## 四、部署架构对比

| 维度 | 巨石应用 | 微前端（qiankun） | 模块联邦（Module Federation） |
|---|---|---|---|
| 仓库结构 | 单一仓库 | 多仓库（主应用 + N 个子应用） | 多仓库（Host + N 个 Remote） |
| 构建方式 | 一次构建 | 各子应用独立构建 | 各 Remote 独立构建 |
| 部署方式 | 一次部署 | 各子应用独立部署 | 各 Remote 独立部署 |
| 发布风险 | 高（一处改动全量发布） | 低（独立发布，互不影响） | 低（独立发布，互不影响） |
| 技术栈 | 统一 | 可混合（Vue 2/3 + React） | 统一（同框架） |
| 首屏性能 | 好 | 中（需加载主应用框架 + 子应用） | 好（共享依赖，减少重复） |
| 调试难度 | 低 | 高（跨应用调试） | 中（共享依赖，调试相对简单） |
| 团队协作 | 差（Git 冲突频繁） | 好（独立仓库，各自开发） | 好（独立仓库，各自开发） |
| 运维成本 | 低 | 高（多服务、多域名） | 高（多服务、多域名） |
| 适用规模 | 小型项目（< 10 人） | 中大型项目（> 20 人，多团队） | 中大型项目（> 20 人，同技术栈） |

**选择建议**：
- 小型项目、团队 < 10 人 → **巨石应用**
- 中大型项目、多团队、多技术栈 → **微前端（qiankun）**
- 中大型项目、多团队、同技术栈 → **模块联邦（Module Federation）**

## 五、状态管理方案对比

| 维度 | Redux Toolkit | Zustand | Pinia | Jotai |
|---|---|---|---|---|
| 框架 | React | React | Vue | React |
| 范式 | 单向数据流（Flux） | 单向数据流（简化 Flux） | 响应式 | 原子化（Recoil 风格） |
| 模板代码 | 多 | 少 | 少 | 少 |
| 体积 | ~11KB gzipped | ~1KB gzipped | ~5KB gzipped | ~3KB gzipped |
| TypeScript | 优秀 | 优秀 | 优秀 | 良好 |
| DevTools | 强大（时间旅行） | 基础 | 强大（Vue DevTools） | 基础 |
| 中间件生态 | 丰富 | 一般 | 一般 | 一般 |
| 学习曲线 | 中高 | 低 | 低 | 低 |
| 适用场景 | 复杂状态管理、大型团队 | 中小型应用、快速开发 | Vue 3 项目 | 细粒度状态、原子化思维 |

**选择建议**：
- React 项目，需要中间件和 DevTools → **Redux Toolkit**
- React 项目，追求简洁和性能 → **Zustand**
- Vue 3 项目 → **Pinia**
- 需要细粒度响应式状态 → **Jotai**
