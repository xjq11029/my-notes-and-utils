# 02-设计系统与组件库架构

---

## 一、核心概念

### 1.1 什么是设计系统

**设计系统（Design System）** 是由 **Design Tokens（设计令牌）**、**组件库（Component Library）**、**文档规范（Documentation）** 三者构成的三角体系，是前端工程化在视觉一致性层面的核心实践。

```
         Design Tokens
        (设计令牌 - 视觉原子)
           /        \
          /          \
   Component        Documentation
   Library          (文档规范)
  (组件库)
```

**三角关系**：
- **Design Tokens**：定义颜色、间距、字体、圆角等最基础的视觉变量，是整个设计系统的"原子"
- **组件库**：基于 Design Tokens 构建可复用的 UI 组件，是设计系统的"分子"和"有机体"
- **文档规范**：描述组件用法、设计原则、无障碍标准，是设计系统的"使用说明书"

**为什么要建设计系统**：
- 保证多产品、多平台之间的视觉一致性
- 提升设计到开发的协作效率（设计师和开发者使用同一套语言）
- 降低维护成本（改一处 Design Token，全局生效）
- 加速新功能开发（直接复用已有组件，无需从零设计）

### 1.2 W3C DTCG 三层令牌体系

W3C 设计令牌社区组（Design Tokens Community Group, DTCG）提出了三层令牌体系：

```
原始令牌（Raw Tokens）      →  语义令牌（Semantic Tokens）  →  组件令牌（Component Tokens）
─────────────────────────────────────────────────────────────────────────────────
调色板中的具体颜色值          品牌色、功能色等语义化命名        按钮背景色、输入框边框色等
blue-500: #3B82F6            color-brand-primary: blue-500    button-bg-primary: color-brand-primary
```

**用调色板类比**：

| 层级 | 类比 | 示例 | 职责 |
|---|---|---|---|
| 原始令牌 | 调色板上的颜料管 | `blue-500: #3B82F6` | 定义所有可用的原始值 |
| 语义令牌 | 给颜色起名："品牌主色" | `color-brand-primary: {value: '{blue.500}'}` | 将原始值与业务语义绑定 |
| 组件令牌 | 决定按钮用什么颜色 | `button-bg-primary: {value: '{color.brand.primary}'}` | 将语义令牌应用到具体组件 |

**代码示例**：

```json
// design-tokens/tokens.json - W3C DTCG 格式
{
  "blue": {
    "500": {
      "$type": "color",
      "$value": "#3B82F6"
    }
  },
  "color": {
    "brand": {
      "primary": {
        "$type": "color",
        "$value": "{blue.500}",
        "$description": "品牌主色，用于主要按钮、链接等"
      }
    }
  },
  "component": {
    "button": {
      "primary": {
        "background": {
          "$type": "color",
          "$value": "{color.brand.primary}"
        }
      }
    }
  }
}
```

```css

  --blue-500: #3B82F6;
  --color-brand-primary: var(--blue-500);
```

## 二、底层原理

### 2.1 CSS 变量的级联与主题切换原理

CSS 自定义属性（变量）具有级联特性，子元素继承父元素的变量值。利用这一特性，通过切换根元素的 `data-theme` 属性，即可实现全局主题切换。

```css
/* 主题变量定义 */
:root,
[data-theme='light'] {
  --color-bg: #ffffff;
  --color-text: #1a1a1a;
  --color-primary: #3B82F6;
  --color-border: #e5e7eb;
  --shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.05);
}

[data-theme='dark'] {
  --color-bg: #1a1a1a;
  --color-text: #f5f5f5;
  --color-primary: #60A5FA;
  --color-border: #374151;
  --shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.3);
}

/* 组件中使用变量 */
.card {
  background-color: var(--color-bg);
  color: var(--color-text);
  border: 1px solid var(--color-border);
  box-shadow: var(--shadow-sm);
}
```

```typescript
// 主题切换逻辑
function toggleTheme() {
  const html = document.documentElement;
  const currentTheme = html.getAttribute('data-theme');
  const nextTheme = currentTheme === 'dark' ? 'light' : 'dark';
  html.setAttribute('data-theme', nextTheme);
  localStorage.setItem('theme', nextTheme);
}

// 初始化时读取 localStorage 或系统偏好
function initTheme() {
  const savedTheme = localStorage.getItem('theme');
  const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
  const theme = savedTheme || (prefersDark ? 'dark' : 'light');
  document.documentElement.setAttribute('data-theme', theme);
}
```

**主题切换的底层原理**：
1. CSS 变量定义在 `:root`（或 `[data-theme]` 选择器）上
2. 所有使用 `var(--xxx)` 的组件自动继承当前作用域下的变量值
3. 切换 `data-theme` 属性时，浏览器重新计算所有依赖该变量的样式
4. 整个过程无需 JavaScript 操作 DOM 样式，性能极高

### 2.2 @layer 优先级管理

CSS `@layer` 规则允许开发者显式控制样式优先级，解决组件库样式与业务样式冲突的问题。

```css
/* 定义层级顺序（越后面优先级越高） */
@layer reset, base, components, utilities;

/* reset 层：最低优先级 */
@layer reset {
  *,
  *::before,
  *::after {
    box-sizing: border-box;
    margin: 0;
    padding: 0;
  }
}

/* components 层：组件库样式 */
@layer components {
  .btn {
    padding: 8px 16px;
    border-radius: 6px;
    font-size: 14px;
    background-color: var(--color-primary);
    color: white;
  }
}

/* 业务代码不写 @layer 时，优先级最高，能覆盖组件库样式 */
.btn {
  background-color: red; /* 业务覆盖生效 */
}
```

**@layer 的三条核心规则**：
1. 声明顺序决定优先级：`@layer A, B, C;` 中 C 的优先级最高
2. 未分层（unlayered）的样式优先级高于所有分层样式
3. `!important` 反转层级优先级（分层中的 `!important` 高于未分层）

```javascript
// Figma Tokens 插件导出的 JSON → 转换为 Tailwind 配置
// scripts/figma-tokens-to-tailwind.js
const tokens = require('./figma-tokens.json');

function convertToTailwind(tokens) {
  const config = { theme: { extend: {} } };

  // 转换颜色
  if (tokens.color) {
    config.theme.extend.colors = {};
    Object.entries(tokens.color).forEach(([key, value]) => {
      config.theme.extend.colors[key] = value.$value;
    });
  }

  // 转换间距
  if (tokens.spacing) {
    config.theme.extend.spacing = {};
    Object.entries(tokens.spacing).forEach(([key, value]) => {
      config.theme.extend.spacing[key] = value.$value;
    });
  }

  return config;
}
```

### 3.3 暗色模式完整实现

```typescript
// hooks/useTheme.ts
import { useState, useEffect, useCallback } from 'react';

type Theme = 'light' | 'dark' | 'system';

export function useTheme() {
  const [theme, setThemeState] = useState<Theme>(() => {
    if (typeof window === 'undefined') return 'system';
    return (localStorage.getItem('theme') as Theme) || 'system';
  });

  // 解析实际生效的主题
  const [resolvedTheme, setResolvedTheme] = useState<'light' | 'dark'>('light');

  const applyTheme = useCallback((theme: Theme) => {
    const root = document.documentElement;
    root.classList.remove('light', 'dark');

    if (theme === 'system') {
      const systemTheme = window.matchMedia('(prefers-color-scheme: dark)').matches
        ? 'dark'
        : 'light';
      root.classList.add(systemTheme);
      setResolvedTheme(systemTheme);
    } else {
      root.classList.add(theme);
      setResolvedTheme(theme);
    }
  }, []);

  const setTheme = useCallback(
    (newTheme: Theme) => {
      setThemeState(newTheme);
      localStorage.setItem('theme', newTheme);
      applyTheme(newTheme);
    },
    [applyTheme]
  );

  // 初始化
  useEffect(() => {
    applyTheme(theme);
  }, []);

  // 监听系统主题变化
  useEffect(() => {
    const mediaQuery = window.matchMedia('(prefers-color-scheme: dark)');
    const handleChange = () => {
      if (theme === 'system') {
        applyTheme('system');
      }
    };
    mediaQuery.addEventListener('change', handleChange);
    return () => mediaQuery.removeEventListener('change', handleChange);
  }, [theme, applyTheme]);

  return { theme, resolvedTheme, setTheme, toggleTheme: () =>
    setTheme(resolvedTheme === 'dark' ? 'light' : 'dark')
  };
}
```

```css
  --color-primary-foreground: hsl(var(--primary-foreground));
}
```

### 3.4 组件 API 设计原则

```typescript
// 原则 1：一致性 - 同类组件保持一致的 API 命名
// ✅ 好的设计
<Input size="sm" />
<Select size="sm" />
<Button size="sm" />

// ❌ 差的设计
<Input small />
<Select size="small" />
<Button size="sm" />

// 原则 2：可组合性 - 组件可以灵活组合
// ✅ 好的设计
<Card>
  <Card.Header>
    <Card.Title>标题</Card.Title>
    <Card.Description>描述</Card.Description>
  </Card.Header>
  <Card.Content>内容</Card.Content>
  <Card.Footer>
    <Button>操作</Button>
  </Card.Footer>
</Card>

// 原则 3：受控与非受控双模式
// ✅ 支持两种模式
<Dialog open={isOpen} onOpenChange={setIsOpen} /> {/* 受控 */}
<Dialog defaultOpen /> {/* 非受控 */}

// 原则 4：asChild 模式 - 支持渲染为其他元素
// ✅ 好的设计
<Button asChild>
  <a href="/dashboard">跳转到仪表盘</a>
</Button>

// 原则 5：正向布尔属性命名
// ✅ 好的命名
<Button disabled />
<Input readonly />
<Dialog modal={false} />

// ❌ 差的命名
<Button enable={false} />
<Input editable={false} />
```

## 四、常见面试题

**Q1：请解释 Design Tokens 的三层架构及其作用。**

**答案要点**：
- 原始令牌（Raw Tokens）：定义最基础的视觉值（如 `blue-500: #3B82F6`），是设计系统的原子
- 语义令牌（Semantic Tokens）：将原始值与业务语义绑定（如 `color-brand-primary: blue-500`），实现值与用途的解耦
- 组件令牌（Component Tokens）：将语义令牌应用到具体组件（如 `button-bg-primary: color-brand-primary`）
- 三层架构的好处：修改一处原始值，所有引用该值的组件自动更新，且语义层保持稳定

**Q2：Headless UI 与传统组件库的区别是什么？各适用于什么场景？**

**答案要点**：
- Headless UI 只提供逻辑（状态管理、键盘交互、无障碍），不提供任何样式
- 传统组件库（如 Ant Design）提供完整的样式和行为，开箱即用
- Headless UI 适合有自己设计系统的团队，需要完全控制样式
- 传统组件库适合快速开发、后台管理系统、对样式定制要求不高的场景
- Copy-in 模式（如 shadcn/ui）是折中方案：组件代码属于项目，可自由修改

**Q3：CSS 变量的主题切换原理是什么？相比 CSS-in-JS 方案有什么优势？**

**答案要点**：
- CSS 变量通过 `data-theme` 属性切换根元素的变量值，所有使用 `var()` 的元素自动更新
- 运行时零开销：浏览器原生支持，无需 JavaScript 计算样式
- 与 CSS-in-JS 方案对比：CSS-in-JS 需要在 JS 运行时中计算样式，有性能开销
- CSS 变量支持级联和继承，可以局部覆盖（如某个组件单独使用暗色主题）
- 配合 `prefers-color-scheme` 媒体查询，可以无缝支持系统主题

**Q4：CSS @layer 解决了什么问题？如何使用？**

**答案要点**：
- 解决了样式优先级不可控的问题，特别是组件库样式与业务样式冲突
- 通过 `@layer reset, base, components, utilities;` 声明层级顺序
- 未分层的样式优先级始终高于分层样式，业务代码可以覆盖组件库样式
- 组件库可以将样式放在 `@layer components` 中，确保业务代码可以覆盖
- `!important` 会反转层级优先级

**Q5：设计一个组件库时，组件 API 设计需要遵循哪些原则？**

**答案要点**：
- 一致性：同类组件保持一致的 API 命名（如 size 统一用 sm/md/lg）
- 可组合性：组件可以灵活组合（如 Card.Header + Card.Content）
- 受控/非受控双模式：支持 `value` + `onChange`（受控）和 `defaultValue`（非受控）
- asChild 模式：支持渲染为其他元素（如 `<Button asChild><a></a></Button>`）
- 正向布尔属性：使用 `disabled` 而非 `enabled={false}`
- 类型安全：充分利用 TypeScript 泛型和类型推导

## 五、避坑指南

| 坑点 | 现象 | 原因 | 解决方案 |
|---|---|---|---|
| 组件库样式被业务覆盖 | 业务代码中无意覆盖了组件库样式，导致组件显示异常 | 组件库样式优先级不够高，或使用了相同的选择器 | 使用 CSS @layer 将组件库样式放在低优先级层；使用 CSS Modules 或 CSS-in-JS 生成唯一类名 |
| 主题切换闪烁 | 页面加载时先显示默认主题，然后闪烁切换到用户保存的主题 | JavaScript 在客户端执行主题切换，晚于 CSS 渲染 | 在 `<head>` 中内联执行主题初始化脚本，阻止页面渲染直到主题设置完成 |
| 组件库体积过大 | 项目打包后体积显著增加，首屏加载慢 | 全量引入组件库（如 `import { Button } from 'antd'` 可能引入整个 antd） | 使用支持 Tree Shaking 的组件库；按需引入；使用 ESM 格式；考虑使用 Headless UI + 自定义样式 |
