## 二、底层原理

### setup 函数和 `<script setup>`

| 维度 | 内容 |
|------|------|
| 是什么 | setup 函数是 Composition API 的入口点，在 `beforeCreate` 之前执行，接收 `props` 和 `context`（attrs、slots、emit），返回的对象可在模板中使用；`<script setup>` 是其语法糖，顶层变量自动暴露给模板。 |
| 能做什么 | 按逻辑关注点组织代码，解决 Options API 中同一逻辑代码分散在 data、methods、computed 中的问题；import 导入的组件直接可用，不需要注册。 |
| 怎么用 | `const props = defineProps({ title: String }); const emit = defineEmits(['update']); const count = ref(0);` 在 `<script setup>` 中直接声明。 |
| 原理和工作流程 | setup 函数在组件初始化时最先执行，早于 `beforeCreate`；`<script setup>` 编译时将顶层变量自动暴露给模板，`defineProps` 和 `defineEmits` 是编译宏，不需要导入；组件内部的响应式数据通过 `ref` 和 `reactive` 创建。 |
| 缺点 | setup 函数中无法访问 `this`，与 Options API 的 `this.xxx` 访问方式不同，需要适应。 |

### 响应式 API：ref vs reactive

| 维度 | 内容 |
|------|------|
| 是什么 | ref 用于创建响应式的基本类型值和对象，通过 `.value` 访问，内部对对象自动调用 reactive；reactive 用于创建响应式对象，直接访问属性，不支持基本类型。 |
| 能做什么 | ref 支持基本类型和对象，替换整个对象方便（直接替换 .value）；reactive 直接访问属性无需 .value，更适合复杂对象。 |
| 怎么用 | `const count = ref(0); count.value++`；`const user = reactive({ name: '张三', age: 18 }); user.age++`；解构时用 `toRefs(user)` 保持响应性。 |
| 原理和工作流程 | ref 返回一个带有 `getter/setter` 的包装对象，通过 `.value` 触发依赖收集和派发更新；reactive 使用 Proxy 代理整个对象，直接访问属性触发 getter 进行依赖收集；两者解构后都会丢失响应性，需要用 `toRef`/`toRefs` 保持。 |
| 缺点 | ref 需要 `.value` 访问，在模板中自动解包但 JS 中需要手动 `.value`；reactive 不支持基本类型，直接替换整个对象会丢失响应性。 |

### 计算属性 vs 方法

| 维度 | 内容 |
|------|------|
| 是什么 | computed 计算属性基于依赖缓存，只有依赖变化时才重新计算；methods 方法每次组件重新渲染都会重新执行，没有缓存。 |
| 能做什么 | computed 适合需要复杂计算且依赖不变的场景，避免不必要的重复计算；methods 适合事件处理或每次渲染都需要重新计算的场景。 |
| 怎么用 | `const undoneCount = computed(() => todos.value.filter(t => !t.done).length)`；可写计算属性：`computed({ get() { return count.value * 2 }, set(v) { count.value = v / 2 } })`。 |
| 原理和工作流程 | computed 内部维护一个 dirty 标记，依赖变化时标记为 dirty，下次访问时重新计算并缓存；methods 每次调用都重新执行，不缓存结果。 |
| 缺点 | computed 不适合产生副作用（如异步请求），应保持为纯计算函数；可写计算属性增加复杂度，需谨慎使用。 |

### 侦听器：watch vs watchEffect

| 维度 | 内容 |
|------|------|
| 是什么 | watch 需要显式指定监听源，默认惰性执行，可获取新旧值；watchEffect 自动追踪回调中的响应式依赖，立即执行，不需要手动指定监听源。 |
| 能做什么 | watch 适合需要回调执行时机控制或新旧值对比的场景；watchEffect 适合简单的副作用，依赖自动追踪。 |
| 怎么用 | `watch(count, (newVal, oldVal) => { ... })`；`watch([count, user], ([nC, nU], [oC, oU]) => { ... })`；`watchEffect(() => { console.log(count.value, user.value.name) })`。 |
| 原理和工作流程 | watch 通过指定监听源建立依赖关系，变化时触发回调，`immediate: true` 立即执行，`deep: true` 深度监听；watchEffect 在首次执行时自动收集所有被访问的响应式依赖，任一依赖变化时重新执行；flush 选项控制执行时机：`pre`（DOM 更新前）、`post`（DOM 更新后）、`sync`（同步）。 |
| 缺点 | watchEffect 不能获取新旧值；watch 需要手动指定监听源，依赖较多时写法繁琐。 |

### 生命周期钩子变化

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 3 生命周期钩子全部改为 Composition API 形式，命名以 `on` 开头，`beforeCreate` 和 `created` 被 setup 函数替代，`beforeDestroy`/`destroyed` 改为 `onBeforeUnmount`/`onUnmounted`。 |
| 能做什么 | 在 setup 中直接使用 `onMounted`、`onUnmounted` 等钩子注册生命周期回调，支持多个同类型钩子按注册顺序执行。 |
| 怎么用 | `onMounted(() => { console.log('挂载完成'); window.addEventListener('resize', handler); }); onUnmounted(() => { window.removeEventListener('resize', handler); })`。 |
| 原理和工作流程 | 每个钩子可以注册多个回调函数，按注册顺序依次执行；setup 替代了 beforeCreate 和 created，在 setup 中直接编写的代码等价于 created 中执行；新增 `onRenderTracked` 和 `onRenderTriggered` 用于调试响应式依赖追踪。 |
| 缺点 | 从 Options API 迁移时需要适应新的生命周期命名方式。 |

### 组件通信方式

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 3 中六种组件通信方式：props/emits（父子通信）、defineExpose（父访问子）、provide/inject（跨层级通信）、v-model（双向绑定）、mitt（事件总线）、Pinia（全局状态管理）。 |
| 能做什么 | 根据通信层级选择合适方式：父子用 props/emits，跨层级用 provide/inject，全局用 Pinia，子组件暴露方法用 defineExpose。 |
| 怎么用 | `const props = defineProps({ title: String }); const emit = defineEmits(['update']);` props/emits；`provide('theme', theme); const theme = inject('theme', 'light')`；`defineExpose({ count, increment })`；`<Child v-model:title="title" />`。 |
| 原理和工作流程 | props 是单向数据流，父组件传递数据给子组件，子组件不能修改 props 只能通过 emit 通知父组件更新；provide/inject 建立依赖注入关系，祖先组件 provide 的数据在后代组件中 inject 获取；v-model 无参数时是 `:modelValue` + `@update:modelValue`；带参数时（如 `v-model:title`）是 `:title` + `@update:title` 的语法糖。 |
| 缺点 | 组件通信方式过多，选择不当可能增加代码复杂度；事件总线（mitt）难以追踪事件流向，大规模使用难以维护。 |

## 三、实战应用

### 组合式函数复用逻辑

| 维度 | 内容 |
|------|------|
| 是什么 | 将可复用的状态逻辑提取到独立的组合式函数（composables）中，如 `useMouse()` 封装鼠标位置跟踪，在组件中按需引入。 |
| 能做什么 | 解决 Options API 中 mixins 的命名冲突和来源不清晰问题；实现逻辑的高内聚和可复用。 |
| 怎么用 | `export function useMouse() { const x = ref(0); const y = ref(0); onMounted(() => window.addEventListener('mousemove', update)); onUnmounted(() => window.removeEventListener('mousemove', update)); return { x, y }; }`。 |
| 原理和工作流程 | 组合式函数内部使用 Vue 响应式 API 创建状态，通过生命周期钩子管理副作用；每个组件调用组合式函数时创建独立的状态实例，不共享状态。 |
| 缺点 | 组合式函数之间可能产生依赖关系，需要规范命名和文档；过度提取可能导致代码碎片化。 |

### 响应式解构

| 维度 | 内容 |
|------|------|
| 是什么 | 使用 `toRefs` 解构 reactive 对象以保持响应性，直接解构（`const { name } = user`）会丢失响应式连接。 |
| 能做什么 | 在需要解构响应式对象时保持每个属性的响应性，修改解构后的值会同步更新原对象。 |
| 怎么用 | `const { name, age } = toRefs(user); name.value = '李四';` 修改 name 同时更新原对象；嵌套对象解构：`const { city } = toRefs(user.address)`。 |
| 原理和工作流程 | `toRefs` 将 reactive 对象的每个属性转换为独立的 ref，这些 ref 与原始对象保持同步；`toRef` 为单个属性创建 ref；直接解构会得到普通值，丢失 Proxy 代理。 |
| 缺点 | 解构后的属性需要通过 `.value` 访问，在模板中会自动解包但 JS 中需要手动操作。 |

### 合理使用计算属性

| 维度 | 内容 |
|------|------|
| 是什么 | 避免在模板中直接编写复杂表达式，将复杂计算提取到 computed 属性中，利用缓存机制优化性能。 |
| 能做什么 | 减少模板复杂度，提高代码可读性；利用缓存避免每次渲染都重新计算。 |
| 怎么用 | `const undoneCount = computed(() => todos.value.filter(t => !t.done).length)`；模板中 `<div>{{ undoneCount }}</div>` 代替 `<div>{{ todos.filter(t => !t.done).length }}</div>`。 |
| 原理和工作流程 | computed 内部维护缓存，依赖不变时直接返回缓存值，不重新执行计算函数；模板中每次渲染都会执行表达式，无缓存。 |
| 缺点 | 过度使用 computed 会增加组件代码量；简单的取值操作不需要 computed。 |

### 正确使用 watch 和 watchEffect

| 维度 | 内容 |
|------|------|
| 是什么 | 需要获取新旧值时使用 watch；需要立即执行且依赖自动追踪时使用 watchEffect。 |
| 能做什么 | watch 适合需要精确控制监听时机和获取变化前后值的场景；watchEffect 适合简单的副作用，如根据 userId 自动请求数据。 |
| 怎么用 | `watch(count, (n, o) => console.log(n, o))`；`watchEffect(async () => { const data = await fetchUser(userId.value); user.value = data })`。 |
| 原理和工作流程 | watch 通过指定监听源和回调函数，依赖变化时触发回调；watchEffect 首次执行时收集依赖，后续自动追踪。 |
| 缺点 | watchEffect 中使用异步操作需要处理竞态问题（多次触发导致请求顺序不确定）。 |

### `defineModel` 宏（Vue 3.4+）

| 维度 | 内容 |
|------|------|
| 是什么 | `defineModel` 是 Vue 3.4 引入的编译宏，用于简化 v-model 双向绑定的声明，自动创建 `modelValue` prop 和 `update:modelValue` emit，返回一个可读写的 ref。 |
| 能做什么 | 替代手动声明 `defineProps` + `defineEmits`，一行代码完成 v-model 的双向绑定；支持带名称的 v-model（`defineModel<string>('title')`）和校验（`{ required: true, validator: ... }`）。 |
| 怎么用 | `const model = defineModel<number>()` 绑定默认 v-model；`const title = defineModel<string>('title')` 命名 v-model；`model.value = newValue` 自动触发 emit。 |
| 原理和工作流程 | `defineModel` 是编译宏，编译时展开为 `defineProps` + `defineEmits` 组合，返回一个 computed ref，`get` 读取 props，`set` 触发 emit。 |
| 缺点 | 仅 Vue 3.4+ 可用；编译宏语法，在非 `<script setup>` 中不可用。 |

### `useTemplateRef()`（Vue 3.5+）

| 维度 | 内容 |
|------|------|
| 是什么 | `useTemplateRef()` 是 Vue 3.5 引入的新 API，用于获取模板中 DOM 元素或组件实例的引用，通过字符串参数关联模板 ref 属性名，是传统 ref 模板引用的类型安全替代方案。 |
| 能做什么 | 解决传统 ref 模板引用中变量名必须与模板 ref 属性名一致的限制；变量名自由，解构友好；支持动态 ref 名称。 |
| 怎么用 | `const inputRef = useTemplateRef<HTMLInputElement>('input')`；模板中 `<input ref="input" />`；访问 `inputRef.value?.focus()`。 |
| 原理和工作流程 | `useTemplateRef` 通过字符串参数匹配模板中的 `ref` 属性值，在组件挂载后自动填充 DOM 元素或组件实例引用；支持动态 ref 名称（如 `v-for` 中的 `:ref`）。 |
| 缺点 | 仅 Vue 3.5+ 可用；字符串参数与模板 ref 属性名需手动保持一致。 |

### `onWatcherCleanup()`（Vue 3.5+）

| 维度 | 内容 |
|------|------|
| 是什么 | `onWatcherCleanup()` 是 Vue 3.5 引入的新 API，用于在 `watch` 或 `watchEffect` 回调中注册清理函数，当 watcher 重新执行或停止时自动调用，替代传统的 `onInvalidate` 回调参数。 |
| 能做什么 | 取消上一次的异步操作（如 AbortController 取消请求、清除定时器）；处理竞态问题；在嵌套函数中更方便地注册清理逻辑。 |
| 怎么用 | `import { watchEffect, onWatcherCleanup } from 'vue'`；`watchEffect(() => { const timer = setTimeout(...); onWatcherCleanup(() => clearTimeout(timer)); })`。 |
| 原理和工作流程 | `onWatcherCleanup` 从 `vue` 直接导入，无需回调参数传递；在任何嵌套层级都可调用；`watch` 和 `watchEffect` 均支持，替代了仅 `watchEffect` 可用的 `onInvalidate`。 |
| 缺点 | 仅 Vue 3.5+ 可用；需要显式调用注册清理函数，可能遗漏。 |

## 四、常见面试题

### 1. Vue 3 中 ref 和 reactive 有什么区别

| 维度 | 内容 |
|------|------|
| 是什么 | ref 可以声明基本类型和对象，通过 `.value` 访问，内部对对象自动调用 reactive；reactive 只能声明对象，直接访问属性。 |
| 能做什么 | ref 更通用，解构替换整个对象方便；reactive 访问更简洁，适合复杂对象。 |
| 怎么用 | `const count = ref(0); count.value++`；`const user = reactive({ name: '张三' }); user.name = '李四'`。 |
| 原理和工作流程 | ref 返回包装对象，通过 getter/setter 实现响应式；reactive 通过 Proxy 代理整个对象；两者解构都需要 toRef/toRefs。 |
| 缺点 | ref 需要 `.value` 访问；reactive 不支持基本类型，替换整个对象丢失响应性。 |

### 2. computed 和 watch 有什么区别

| 维度 | 内容 |
|------|------|
| 是什么 | computed 是计算衍生值，有缓存，依赖不变不重新计算；watch 是监听变化执行副作用，没有缓存，变化就执行回调。 |
| 能做什么 | computed 适合派生数据计算；watch 适合响应数据变化执行异步操作或 DOM 操作。 |
| 怎么用 | `const doubled = computed(() => count.value * 2)`；`watch(count, (n) => fetchData(n))`。 |
| 原理和工作流程 | computed 基于依赖缓存，内部有 dirty 标记控制重新计算；watch 每次依赖变化都执行回调，可获取新旧值。 |
| 缺点 | computed 不应产生副作用；watch 没有缓存，多次访问需重复计算。 |

### 3. v-if 和 v-show 有什么区别

| 维度 | 内容 |
|------|------|
| 是什么 | v-if 是条件渲染，条件为 false 时不渲染到 DOM 中，切换开销大；v-show 始终渲染到 DOM，通过 CSS `display` 属性切换，初始渲染开销大但切换开销小。 |
| 能做什么 | v-if 适合不频繁切换的场景（如权限控制）；v-show 适合频繁切换的场景（如 Tab 切换）。 |
| 怎么用 | `<div v-if="isVisible">内容</div>`；`<div v-show="isVisible">内容</div>`。 |
| 原理和工作流程 | v-if 在条件为 false 时 DOM 元素完全不存在，惰性渲染（第一次为 true 才渲染）；v-show 元素始终存在，只是 `display: none` 隐藏。 |
| 缺点 | v-if 频繁切换会导致频繁的 DOM 创建和销毁；v-show 初始渲染时所有元素都会被创建。 |

### 4. v-for 中为什么需要 key

| 维度 | 内容 |
|------|------|
| 是什么 | key 是 Vue Diff 算法中用于识别 VNode 身份的唯一标识，帮助 Vue 跟踪每个节点，进行最小化 DOM 操作。 |
| 能做什么 | 使 Vue 能在数据顺序变化时正确复用已有节点，避免不必要的 DOM 重建和组件状态错乱。 |
| 怎么用 | `<div v-for="item in items" :key="item.id">{{ item.name }}</div>`；推荐使用唯一 id，不推荐使用数组索引。 |
| 原理和工作流程 | Vue 的 Diff 算法通过 key 对比新旧 VNode 列表，判断节点是可复用、需要移动还是需要删除/创建；使用索引作为 key 时，数据顺序变化会导致 key 对应关系错乱。 |
| 缺点 | 使用索引作为 key 在数据增删时会导致组件状态错误和性能下降。 |

### 5. Composition API 相比 Options API 有什么优势

| 维度 | 内容 |
|------|------|
| 是什么 | Composition API 按逻辑关注点聚合代码，Options API 将同一逻辑的代码分散在 data、methods、computed 等选项中。 |
| 能做什么 | 更好的代码组织：大型组件中相关代码集中在一起；更好的逻辑复用：组合式函数比 mixins 更清晰，无命名冲突；更好的 TypeScript 支持；更好的 Tree Shaking。 |
| 怎么用 | `export function useFeature() { const state = ref(null); function doSomething() { ... } return { state, doSomething }; }` 提取复用逻辑。 |
| 原理和工作流程 | Composition API 基于 setup 函数，所有逻辑在同一个函数中组织，按功能分组而非按选项类型分组；组合式函数是普通的 JavaScript 函数，可以嵌套使用。 |
| 缺点 | 学习曲线较陡，需要理解响应式 API 和生命周期钩子的新用法。 |

## 五、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 聚合了 Vue 3 核心语法开发中八个常见错误：直接解构 reactive、忘记给 ref 添加 .value、watch 中修改监听值导致无限循环、直接给 reactive 赋值整个对象、v-for 使用数组索引作为 key、模板中大量使用复杂表达式、watchEffect 中使用异步未正确清理、生命周期中忘记移除事件监听。 |
| 能做什么 | 快速对照排查：使用 toRef/toRefs 解构 reactive；记住 ref 需要 .value；避免在 watch 回调中修改监听值；使用 `Object.assign(state, newState)` 替代直接赋值；使用唯一 id 作为 key；提取复杂计算到 computed；watchEffect 中使用可取消的请求；在 onUnmounted 中移除事件监听。 |
| 怎么用 | `const { name } = toRefs(user)`；`count.value++`；`watchEffect(onInvalidate => { ... })`；`Object.assign(state, newState)`；`<div v-for="item in items" :key="item.id">`。 |
| 原理和工作流程 | 直接解构 reactive 得到的是普通值，丢失 Proxy 连接；ref 的 `.value` 是响应式入口，忘记则拿到的是 RefImpl 对象而非实际值；watch 中修改监听值会触发新变化形成无限循环；reactive 是原对象的代理，替换整个对象意味着新对象不是代理对象。 |
| 缺点 | 需要开发者持续注意这些编码规范；部分错误（如无限循环）在特定场景下才触发，不易排查。 |

## Teleport 详解

| 维度 | 内容 |
|------|------|
| 是什么 | Teleport 是 Vue 3 内置组件，用于将组件模板中的 DOM 内容"传送"到 DOM 树中的任意位置（通过 `to` 属性指定 CSS 选择器），同时保持组件逻辑层级不变。 |
| 能做什么 | 解决模态框、弹窗、通知等需要脱离父组件 CSS 上下文（如 `overflow: hidden`、`z-index` 限制）的场景；支持 `disabled` 属性动态控制传送是否生效；多个 Teleport 可传送到同一目标。 |
| 怎么用 | `<Teleport to="body"><div class="modal">内容</div></Teleport>`；`<Teleport to="body" :disabled="isMobile">...</Teleport>`。 |
| 原理和工作流程 | 组件逻辑（props、事件、状态）仍在父组件中管理，渲染时 VNode 被挂载到 `to` 指定的目标 DOM 节点下，实现 DOM 层级分离；事件冒泡仍然遵循虚拟 DOM 树结构，而非 DOM 层级。 |
| 缺点 | `to` 指定的目标元素必须在 Teleport 挂载前已存在于 DOM 中；传送后的 DOM 脱离了父组件 CSS 作用域，scoped 样式可能不生效。 |

## Suspense 详解

| 维度 | 内容 |
|------|------|
| 是什么 | Suspense 是 Vue 3 内置组件，用于协调组件树中异步依赖的加载状态，提供 `default`（异步内容）和 `fallback`（加载占位）两个插槽，支持 `@pending`、`@resolve`、`@fallback` 事件钩子。 |
| 能做什么 | 等待异步组件或异步数据加载时显示骨架屏/加载动画；支持多个异步组件并发加载，全部就绪后统一显示；支持嵌套 Suspense 实现精细加载控制。 |
| 怎么用 | `<Suspense><template #default><AsyncComp /></template><template #fallback><Loading /></template></Suspense>`；配合 `defineAsyncComponent` 实现代码分割懒加载。 |
| 原理和工作流程 | 初次进入 Suspense 时同时渲染 default 和 fallback 的 VNode，先显示 fallback；所有异步依赖 resolve 后切换到 default 显示；异步依赖变化时重新进入 pending 状态。 |
| 缺点 | 目前仍是实验性功能（Vue 3 中），API 可能变化；其中一个异步组件加载失败会导致整个 Suspense 进入错误状态，需配合错误处理。 |

## 自定义指令原理

### 指令钩子与 binding 对象

| 维度 | 内容 |
|------|------|
| 是什么 | 自定义指令是 Vue 中第三种代码复用方式，定位为复用涉及普通元素底层 DOM 访问的逻辑；指令定义对象提供 7 个可选钩子：`created`、`beforeMount`、`mounted`、`beforeUpdate`、`updated`、`beforeUnmount`、`unmounted`。`binding` 是描述绑定信息的只读对象，包含 `value`、`oldValue`、`arg`、`modifiers`、`instance`、`dir`。 |
| 能做什么 | 复用对单个元素的 DOM 操作逻辑（聚焦、事件绑定、权限移除、懒加载）；通过 `arg` 传事件名、通过 `modifiers` 传开关与参数、通过 `value` 传业务数据，实现一份指令多场景复用。 |
| 怎么用 | `const vFocus = { mounted(el, binding) { if (binding.value === false) return; el.focus() } }`；模板 `<input v-focus:foo.bar="value" />` 对应 `binding` 为 `{ arg: 'foo', modifiers: { bar: true }, value }`。 |
| 原理和工作流程 | 编译期 `v-focus` 被转换为 `withDirectives(vnode, [[resolveDirective('focus'), value, arg, modifiers]])`，VNode 被打上 `NEED_PATCH` 标记并把指令信息挂到 `vnode.dirs`；运行期渲染器在 `mountElement` / `patchElement` / `unmount` 的关键节点调用 `invokeDirectiveHook` 依次派发 7 个钩子。`oldValue` 仅在 `beforeUpdate` 和 `updated` 中可用；`prevVnode` 是钩子参数而非 `binding` 字段。 |
| 缺点 | 钩子按元素生命周期触发而非组件生命周期，容易与组件钩子的执行顺序混淆（组件内指令的 `updated` 早于组件自身的 `onUpdated`）；`binding` 只读，跨钩子共享信息需借助 `dataset` 或 WeakMap。 |

### 注册方式与 SSR 注意事项

| 维度 | 内容 |
|------|------|
| 是什么 | 全局注册使用 `app.directive('focus', {...})`，局部注册使用 Options API 的 `directives` 选项，或在 `<script setup>` 中以 `v` 开头的驼峰变量自动注册；SSR 下大多数指令被忽略，需要产出属性的指令要实现 `getSSRProps(binding)`。 |
| 能做什么 | 全局注册让指令在整个应用可用；局部注册可被 Tree Shaking；`getSSRProps` 让指令在服务端也输出正确属性，避免水合不匹配；`data-allow-mismatch`（Vue 3.5+）可有选择地消除无法避免的警告。 |
| 怎么用 | 全局：`app.directive('focus', { mounted: (el) => el.focus() })`；局部：`<script setup>` 中 `const vFocus = { mounted: (el) => el.focus() }`；SSR：`getSSRProps(binding) { return { id: binding.value } }`。 |
| 原理和工作流程 | `resolveDirective('focus')` 的查找顺序是当前组件实例的 `directives` 选项 → 应用级注册表。SSR 期间只有 `created`（以及组件的 `beforeCreate` / `created` / setup 根作用域）会被调用，`mounted` / `updated` / `unmounted` 只在客户端执行，因此 `v-focus` 在首屏无效；`getSSRProps` 只接收一个 `binding` 参数，返回需要渲染到元素上的属性对象。 |
| 缺点 | 全局注册的指令无法 Tree Shaking；`created` 在服务端会被调用，在其中访问 `window` / `document` 会直接报错；在组件上使用自定义指令时多根组件会被忽略并告警，且无法通过 `v-bind="$attrs"` 转发。 |

### 实战案例（v-focus / v-debounce / v-permission）

| 维度 | 内容 |
|------|------|
| 是什么 | 三个高频实战指令：`v-focus` 在 `mounted` 中调用 `el.focus()`，比原生 `autofocus` 在动态插入元素时也有效；`v-debounce` 通过 `binding.arg` 指定事件名、数字修饰符指定延迟、`.immediate` 控制首次立即执行，并用 WeakMap 在 `mounted` / `unmounted` 间共享包装函数；`v-permission` 读取 `binding.value` 声明的角色列表做按钮级权限拦截。 |
| 能做什么 | 弹窗打开后自动聚焦输入框；把任意事件的防抖逻辑从业务代码中抽离成声明式指令；按角色隐藏或移除无权限的按钮。 |
| 怎么用 | `<input v-focus.select v-if="visible" />`；`<input v-debounce:input.500.immediate="handleInput" />`；`<button v-permission="['admin', 'editor']">删除</button>`。 |
| 原理和工作流程 | `v-focus` 必须放在 `mounted` 而非 `beforeMount`，因为元素此时才真正位于文档中；`v-debounce` 在 `mounted` 中 `addEventListener` 并缓存句柄，在 `unmounted` 中 `removeEventListener` 防止内存泄漏；`v-permission` 在 `mounted` 中比对角色后 `el.parentNode.removeChild(el)` 或设置 `display: none`。 |
| 缺点 | `removeChild` 不可恢复，权限动态变化时应改用 `v-if`；前端权限指令只是 UI 层拦截，后端必须二次校验；SSR 下在指令中直接 `useUserStore()` 可能造成跨请求状态污染，应通过 `app.provide()` 注入的鉴权对象读取权限。 |
