# Vue3 - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| ref对象解构后丢失响应式 | 解构赋值会断开与ref的引用关系 | 使用toRefs或toRef保持响应式，或直接使用.value访问 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| reactive对象进行整体替换后丢失响应式 | 直接将新对象赋值给reactive变量会断开响应式引用 | 使用Object.assign更新属性，或使用ref包裹对象 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 在setup中忘记computed的依赖会触发多次计算 | 不了解computed的缓存机制 | 确保computed依赖的响应式数据正确，computed只在依赖变化时重新计算 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| v-if和v-for同时使用导致性能问题 | v-for优先级高于v-if，v-if在每次循环中执行 | 使用computed过滤数据后v-for遍历，或使用template包裹v-if然后v-for | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 组合式函数中直接修改props | props是单向数据流，子组件不应修改父组件传入的值 | 使用emit通知父组件修改，使用computed或者本地ref作为副本 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 使用ref获取DOM时机错误 | 在组件挂载前访问ref（如setup顶层） | 在onMounted生命周期中访问ref，或使用watchEffect监听ref值变化 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 响应式数据使用普通for...in循环导致性能问题 | 不了解Proxy的get陷阱每次读取属性都会触发依赖收集 | 使用Object.keys获取属性列表，或者使用shallowRef避免深层响应式 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 大列表未使用v-memo或虚拟列表导致卡顿 | 大量DOM节点同时渲染造成性能瓶颈 | 使用v-memo缓存不变的行，或使用虚拟列表库只渲染可视区域 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 多组件间共享状态使用不当导致数据流混乱 | 不了解provide/inject与响应式API的配合 | 使用provide传递ref对象，inject接收后读取.value，或使用Pinia管理状态 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 使用watchEffect未注意副作用导致无限循环 | watchEffect中修改了依赖的响应式数据 | 检查watchEffect内部的副作用，确保不会无限触发依赖更新 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 路由跳转后页面状态丢失 | 组件销毁时状态未保存 | 使用keep-alive包裹router-view缓存组件，使用pinia将状态提升到全局 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 路由守卫中访问store但store未初始化 | 路由守卫执行时机早于pinia安装 | 在路由守卫中动态导入store，或使用pinia的独立store实例 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Pinia store中直接修改state导致持久化未更新 | 直接修改state未通过action触发持久化钩子 | 使用action统一修改state，在action中调用持久化插件的方法 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 动态路由参数变化时组件未重新渲染 | 未监听路由参数变化或未使用key绑定 | 使用watch监听route.params变化，或给router-view添加key绑定 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 使用Vue3的Composition API但未正确导入生命周期 | 从vue包导入生命周期函数名称错误 | 使用onMounted、onUnmounted等正确名称，注意on前缀 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Teleport组件内容样式未正确生效 | Teleport将内容渲染到目标位置，CSS作用域可能失效 | 在目标元素上定义样式，或使用:deep()穿透作用域 | [Vue3笔面试题集导览](./04-Vue3笔面试题集-导览.md) |
| Suspense组件使用不当导致白屏 | 未正确处理异步组件的加载状态 | 使用Suspense包裹异步组件，提供fallback插槽显示加载状态 | [Vue3笔面试题集导览](./04-Vue3笔面试题集-导览.md) |
| 在 setup 中解构 `reactive` 对象，修改后视图不更新 | 解构后得到的是普通变量，丢失了响应式连接 | 用 `toRef` / `toRefs` 包装后再解构（Vue 3.5+ 可直接解构 `defineProps`） | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 拿到的是 ref 对象而不是实际值 | `ref` 返回包装对象，必须通过 `.value` 访问 | 记住 ref 需要 `.value`，`reactive` 不需要 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 在 `watch` 回调中修改被监听的值，造成无限循环 | 值变化触发回调，回调又改值，再次触发变化 | 避免在回调中修改监听的值；使用 `immediate` 时注意加判断 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 用数组索引作为 `v-for` 的 key，数据增删后组件状态错乱 | 索引不能唯一标识节点，顺序变化时 Diff 无法复用 | 使用数据的唯一 id 作为 key | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 模板中堆大量复杂表达式，每次渲染都重新计算 | 把所有计算写在模板里，无法利用缓存 | 把复杂计算提取到计算属性中，利用 computed 的缓存 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| `watchEffect` 中发起异步请求，多次触发导致请求竞争 | 异步返回顺序不确定，后返回的旧数据覆盖新数据 | 使用可取消的请求（AbortController），或 watch 配合防抖 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 组件卸载后事件监听仍在，回调重复触发 | 未在 `onUnmounted` 中移除监听与定时器 | 在 `onUnmounted` 中移除所有事件监听、定时器、Observer | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 自定义指令在 `beforeMount` 中调用 `el.focus()` 无效 | 元素此时尚未插入文档 | 把聚焦等依赖文档的操作放到 `mounted` 中执行 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 在 `beforeUpdate` 中读 `binding.value` 当作旧值，拿到的是新值 | `binding.value` 始终是当前值，旧值在 `oldValue` 中 | 用 `binding.oldValue` 做前后对比 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 自定义指令只写 `mounted` 忘记 `unmounted` 清理 | 组件卸载后监听器仍持有元素与闭包引用 | 成对编写 `mounted` / `unmounted`，或用 WeakMap 记录句柄 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 在 `created` 中访问 `window` / `document`，SSR 时报错 | `created` 在服务端也会执行，Node.js 没有浏览器全局对象 | 平台相关逻辑放到 `mounted`，服务端属性走 `getSSRProps` | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| `<script setup>` 中定义的指令在模板里用不了 | `<script setup>` 仅把 `v` 开头的驼峰变量识别为指令 | 命名为 `vFocus`、`vPermission` 这种以 `v` 开头的形式 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 在多根节点组件上使用自定义指令被忽略并告警 | 指令只能作用于单一根节点，且无法通过 `$attrs` 转发 | 改为在具体元素上使用指令 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 权限变化后按钮无法恢复显示 | 用自定义指令替代 `v-if` 做权限控制，而 `removeChild` 不可逆 | 权限动态变化时使用 `v-if` + 权限判断函数 | [Vue3核心语法导览](./01-Vue3核心语法-导览.md) |
| 将响应式对象赋给普通变量后修改，视图不更新 | 普通变量没有响应式连接 | 保持使用 `ref` / `reactive`，不要中转成普通变量 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 在 Vue 3 中调用 `Vue.set` / `Vue.delete` 报错或无效 | Vue 3 已移除这些 API，Proxy 能直接处理增删 | 直接赋值和删除即可，不需要额外 API | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 内存占用大、性能差 | 过度使用响应式，不需要响应式的大数据也用了 ref/reactive | 不需要响应式的数据用普通变量，大数据用 `shallowRef` | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 在模板中直接修改 computed 报警告 | computed 默认是只读的 | 使用可写计算属性（提供 setter），或直接修改源数据 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 直接修改 props 的值，警告或视图不更新 | props 是单向数据流，子组件不能修改 | 通过 emit 通知父组件修改，或使用 `v-model` | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| `watch` 监听深层对象但回调不触发 | 对象引用没变，默认浅比较认为没变化 | 使用 `{ deep: true }` 做深度监听 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 在 computed 中发请求，数据不可预测 | computed 应该是纯计算函数，不应有副作用 | 副作用放在 `watch` 或 `watchEffect` 中 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| `v-memo` 依赖数组漏写变量，数据变了视图不更新 | 依赖不变时整棵子树被跳过更新 | 依赖数组必须覆盖子树中所有会变化的绑定；不确定时不要用 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| `v-memo` 指令不生效 | `v-memo` 必须和 `v-for` 绑定在同一个元素上 | 把 `v-memo` 移到带 `v-for` 的那个元素上 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 用 `v-memo` 优化只有几十条的列表，性能反而下降 | 依赖比较本身有成本，收益覆盖不了开销 | 只在超过 1000 条的海量列表或单行极重的场景使用 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| `shallowRef` 中 `push` 后视图不更新 | 内部值未被代理，深层变更不触发更新 | 整体替换 `.value`，或显式调用 `triggerRef` | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 对已经是响应式的对象调用 `markRaw` 无效 | 代理已经存在，`markRaw` 无法撤销 | 在对象被响应式化之前就 `markRaw`，或新建普通对象 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 界面永远停留在首屏数据 | 把 `v-once` 用在了会变化的内容上 | 只在确定永不变化的内容上使用；"减少更新"用 `v-memo` | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 虚拟列表滚动时内容错乱、复用错误 | 可视区切片后下标会变化，用 `index` 作 key 不再稳定 | 使用业务唯一 id 作 `key` | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 虚拟列表滚动卡顿、掉帧 | 滚动时逐项设置 `top`，修改 `top` 触发重排 | 用 `transform: translateY` 做整体位移，只触发合成 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 组件卸载后 `ResizeObserver` 仍在触发回调 | 观察器持有 DOM 与闭包引用 | 在 `onBeforeUnmount` / `onUnmounted` 中调用 `disconnect()` | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| 页面卡死、控制台刷屏 | `ResizeObserver` 回调中无条件写回高度，再次触发观察形成死循环 | 只在高度真实变化时写回，避免同步修改被观察元素尺寸 | [响应式与编译优化导览](./02-响应式与编译优化-导览.md) |
| history 模式刷新页面 404 | 服务器找不到对应路径的真实 HTML 文件 | 配置服务器 fallback，Nginx 用 `try_files $uri $uri/ /index.html` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 从 `/user/1` 跳到 `/user/2` 页面数据不变 | 组件被复用，不会重新创建 | 用 `watch` 监听 `route.params`，或用 `onBeforeRouteUpdate` 守卫 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 在 Pinia 中直接替换整个 state，响应式丢失 | 直接替换 state 对象引用，丢失了 Proxy 代理 | 使用 `$patch` 更新，或使用 `$reset` 重置 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 路由卡住无法导航 | 守卫中缺少 `next()` 调用 | 检查每个守卫分支都调用了 `next()` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Pinia action 的异步错误静默失败 | 异步操作可能抛出异常但未被处理 | 调用 action 时使用 `try/catch` 或 `.catch()` 处理错误 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 页面切换卡顿 | 守卫中同步执行大量异步操作，阻塞导航 | 非必要的异步操作放到 `afterEach`，或改为懒加载 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 多个 store 之间循环引用报错 | store A 依赖 store B，store B 又依赖 store A | 在 action 或 getter 内部按需引入，避免顶层 import 造成循环依赖 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 在 `onMounted` 中获取首屏数据，服务端 HTML 里没有内容 | `onMounted` 在 SSR 期间不执行，SEO 失效 | 改用 `useAsyncData` / `useFetch`，纯 Vue SSR 用 `onServerPrefetch` | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 服务端定时器永不清理，内存持续增长 | 在 setup 根作用域写 `setInterval`，清理钩子在 SSR 期间不执行 | 副作用放到 `onMounted`，并在 `onUnmounted` 中清理 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| SSR 渲染时报 `window is not defined` | 服务端没有浏览器全局对象 | 用 `import.meta.client` 判断；放到 `onMounted`；用 `<ClientOnly>` 或 `*.client.vue` 隔离 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 引入第三方库时立即报 `window is not defined` | 该库在模块顶层访问了 `window`，未做通用化处理 | 改为动态 `import()`，或仅在客户端加载 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| SSR 下不同用户串数据 | 模块级 `ref` / `reactive` 作为共享状态，服务端模块只初始化一次，单例被所有请求复用 | 用 `useState`，或每请求创建实例并 `app.provide()` | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| Pinia 在 SSR 下跨请求状态污染 | `state` 写成对象而非函数，对象形式在模块加载时创建，成为单例 | 使用 `state: () => ({ ... })` 函数形式 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 首屏显示未登录，水合后才变成登录态 | 服务端 `$fetch` 没有浏览器的 cookie 自动附带 | 用 `useRequestHeaders(['cookie'])` 取出后传入 `headers` | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 敏感数据出现在浏览器 payload 中 | state 会随 HTML 序列化下发到客户端 | 敏感数据只留在服务端，不进 `useState` / Pinia | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 两个组件显示同一份数据，刷新逻辑互相干扰 | `useAsyncData` 的 key 冲突导致 payload 复用错位 | key 用业务语义命名并保证全局唯一 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 模板中直接用 `data.xxx` 报"读取 null 的属性" | `useAsyncData` / `useFetch` 的 `data` 默认是 `null` | 提供 `default` 兜底，或用 `v-if="data"` 保护 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 出现水合不匹配（Hydration Mismatch）警告 | 用 `typeof window !== 'undefined'` 渲染了不同内容，服务端与客户端分支不一致 | 用 `<ClientOnly>`，或 `data-allow-mismatch`（Vue 3.5+），或延后到 `onMounted` | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 模板 `<p><div>hi</div></p>` 导致水合不匹配 | 浏览器会纠正非法嵌套，DOM 与 VNode 结构不一致 | 使用合法的 HTML 嵌套结构 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
| 使用 `Math.random()` / 本地时间格式化导致水合不匹配、首屏闪烁 | 服务端与客户端两次执行结果不同（随机值、时区差异） | 用 `v-if` + `onMounted` 延后到客户端，或统一随机种子 / 时区 | [SSR与Nuxt实战导览](./05-SSR与Nuxt实战-导览.md) |
