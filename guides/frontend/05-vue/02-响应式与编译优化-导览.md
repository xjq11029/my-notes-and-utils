## 二、底层原理

### Vue 2 响应式原理

> Vue 2 已于 2023-12-31 停止维护（EOL），新项目请使用 Vue 3

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 2 使用 `Object.defineProperty` 劫持对象属性的 getter 和 setter，在 getter 中收集依赖，在 setter 中派发更新，递归遍历所有属性实现响应式。 |
| 能做什么 | 实现数据变化时自动更新视图，避免手动操作 DOM。 |
| 怎么用 | `function defineReactive(obj, key, val) { Object.defineProperty(obj, key, { get() { dep.depend(); return val; }, set(newVal) { val = newVal; dep.notify(); } }) }`。 |
| 原理和工作流程 | 初始化时递归遍历对象所有属性，为每个属性设置 getter/setter；getter 中通过 Dep 收集依赖（当前渲染的 Watcher）；setter 中通过 Dep 通知所有依赖的 Watcher 重新渲染；数组的七个变异方法（push、pop、shift、unshift、splice、sort、reverse）被重写以触发更新。 |
| 缺点 | 无法检测新增属性和删除属性，需要 `Vue.set`/`Vue.delete`；无法检测数组索引修改和 length 修改；初始化时递归遍历所有属性，深层嵌套对象性能开销大。 |

### Vue 3 响应式原理

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 3 使用 ES6 Proxy 代理整个对象，配合 Reflect API 实现响应式，支持新增/删除属性检测、数组索引修改和惰性响应式。 |
| 能做什么 | 解决 Vue 2 中 Object.defineProperty 的所有局限性：检测新增属性、检测删除属性、检测数组索引和 length 修改，无需重写数组方法。 |
| 怎么用 | `const state = reactive({ count: 0 }); state.count++`；`const state = reactive({}); state.newProp = 'value'` 自动响应式。 |
| 原理和工作流程 | Proxy 的 `get` 陷阱中执行 `track(target, key)` 收集依赖，`set` 陷阱中执行 `trigger(target, key)` 派发更新，`deleteProperty` 陷阱中也能触发更新；惰性响应式：初始化只代理第一层，访问嵌套对象时才递归代理；使用 `targetMap`（WeakMap）存储所有响应式对象的依赖关系；ref 本质是带有 getter/setter 的包装对象，内部调用 track 和 trigger。 |
| 缺点 | Proxy 无法被 polyfill，不支持 IE11 等老旧浏览器；Proxy 代理整个对象，内存开销略高于 Object.defineProperty。（历史兼容场景，2026 年新项目按现代浏览器基线） |

### 虚拟 DOM（Virtual DOM）原理

| 维度 | 内容 |
|------|------|
| 是什么 | 虚拟 DOM 是用 JavaScript 对象描述真实 DOM 结构的轻量级表示，每个 VNode 包含标签名、属性、子节点等信息。 |
| 能做什么 | 减少真实 DOM 操作，通过 Diff 算法找出最小变更批量更新；实现跨平台渲染（Web、Native、小程序）；支持声明式编程。 |
| 怎么用 | `const vnode = { tag: 'div', props: { id: 'app' }, children: [{ tag: 'span', children: ['Hello'] }] }`；开发者不需要直接操作 VNode。 |
| 原理和工作流程 | 状态变化时生成新的 VNode 树；通过 patch 算法对比新旧 VNode 树，同层比较，标签名不同直接替换，标签名相同复用节点并更新属性和子节点；子节点通过 Diff 算法对比列表。 |
| 缺点 | 首次渲染需要生成完整 VNode 树，速度不如直接操作 DOM；需要额外的 Diff 计算开销；需要维护 VNode 树的内存。 |

### Vue 3 Diff 算法优化

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 3 在编译器层面实现了四项 Diff 优化：静态标记（PatchFlag）、静态提升（HoistStatic）、Block Tree 和事件缓存（cacheHandlers），大幅减少运行时 Diff 的工作量。 |
| 能做什么 | 跳过静态节点对比，只检查动态属性；避免重复创建静态节点；将动态节点集中管理，Diff 时只对比动态节点；缓存事件函数避免子组件不必要的更新。 |
| 怎么用 | 开发者无需手动配置，Vue 3 编译器自动在编译阶段进行优化。 |
| 原理和工作流程 | PatchFlag 为动态节点标记类型（TEXT=1、CLASS=2、STYLE=4 等），运行时只检查标记的属性；HoistStatic 将静态节点提升到 render 函数外部，多次渲染复用同一个 VNode；Block Tree 将动态节点收集到 `dynamicChildren` 数组中，Diff 时跳过静态节点直接对比动态节点；cacheHandlers 将事件函数缓存到 `_cache` 数组中，避免每次渲染创建新函数。 |
| 缺点 | 对于几乎全是动态内容的模板，优化效果有限。 |

### 编译器优化

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 3 模板编译分为三个阶段：parse（解析模板为 AST）、transform（对 AST 进行优化转换，标记静态节点和动态绑定）、generate（生成 render 函数代码）。 |
| 能做什么 | 在编译阶段完成静态标记、PatchFlag 生成、静态提升、Block Tree 构建等优化，减轻运行时负担。 |
| 怎么用 | 开发者无需手动操作编译器，Vue 3 在构建时自动编译 `.vue` 文件。 |
| 原理和工作流程 | parse 将模板字符串解析为 AST 树结构；transform 阶段标记静态节点、生成 PatchFlag、执行静态提升、构建 Block Tree；generate 将优化后的 AST 转换为 render 函数代码，包含 `_createBlock`、`_createVNode` 等运行时辅助函数。 |
| 缺点 | 编译过程增加了构建时间；模板语法限制意味着某些动态场景无法充分利用编译优化。 |

### nextTick 原理

| 维度 | 内容 |
|------|------|
| 是什么 | nextTick 将回调推迟到下次 DOM 更新循环之后执行，Vue 3 仅使用 `Promise.resolve().then()`（微任务）实现，无降级策略（Vue 2 曾使用 Promise.then → MutationObserver → setImmediate → setTimeout 降级链）。 |
| 能做什么 | 在数据变化后获取更新后的 DOM（如获取元素尺寸、滚动位置）；确保子组件渲染完成后再执行操作。 |
| 怎么用 | `count.value++; await nextTick(); console.log(document.querySelector('#count').textContent)`；或 `nextTick(() => { ... })`。 |
| 原理和工作流程 | 多个 nextTick 回调被收集到 `callbacks` 数组中，通过 `pending` 标志控制只触发一次异步执行；优先使用微任务（Promise.then）确保在当前宏任务内执行，比宏任务更快；`flushCallbacks` 执行所有回调并重置队列。 |
| 缺点 | 过度使用 nextTick 嵌套会导致代码逻辑混乱。 |

### Vapor Mode（无虚拟 DOM 编译策略）

| 维度 | 内容 |
|------|------|
| 是什么 | Vapor Mode 是 Vue 团队正在开发的全新编译策略，旨在跳过虚拟 DOM 层，直接将模板编译为高性能的 DOM 操作代码，借鉴了 Solid.js 和 Svelte 的无虚拟 DOM 思路但保留 Vue 的响应式系统和模板语法。 |
| 能做什么 | 移除虚拟 DOM 运行时，减少约 40% 运行时代码体积；首次渲染更快（无需构建 VNode 树）；细粒度 DOM 更新（每个动态绑定独立追踪，无需组件级 Diff）；降低内存占用。 |
| 怎么用 | 目前仍在开发中（Vue 3.6+ 实验性功能），需配合 Vapor Mode 专用编译器和运行时；仅支持模板语法，不支持 render 函数和 JSX。 |
| 原理和工作流程 | 编译时分析模板的静态结构和动态绑定，直接生成 `effect(() => setText(el, ctx.text))` 式的 DOM 操作代码；传统 Vue 3 流程为"模板 → 编译 → VNode → Diff → DOM"，Vapor Mode 简化为"模板 → 编译 → DOM 操作"。 |
| 缺点 | 目前仍是实验性功能，API 可能变化；仅支持模板语法，部分动态特性（如 `<component :is>`）可能受限；对模板静态分析要求更高。 |

## 三、实战应用

### 理解 shallowRef 和 shallowReactive

| 维度 | 内容 |
|------|------|
| 是什么 | shallowRef 只有 `.value` 本身的替换是响应式的，内部属性变化不触发更新；shallowReactive 只有第一层属性是响应式的，深层属性变化不触发更新。 |
| 能做什么 | 当数据量很大且只有顶层引用需要响应式时，使用浅层响应式可大幅提升性能，减少不必要的 Proxy 代理。 |
| 怎么用 | `const data = shallowRef({ list: [] }); data.value = { list: [1,2,3] }` 触发更新；`data.value.list.push(4)` 不触发更新；`const state = shallowReactive({ list: [] }); state.list = [1,2,3]` 触发更新。 |
| 原理和工作流程 | shallowRef 不对内部值进行深层响应式处理；shallowReactive 只对对象第一层属性创建 Proxy 代理，嵌套对象保持原样。 |
| 缺点 | 使用不当会导致视图不更新，需要明确理解哪些操作会触发响应式。 |

### 避免不必要的响应式

| 维度 | 内容 |
|------|------|
| 是什么 | 不需要响应式的数据（如静态配置对象）直接使用普通 JavaScript 变量，避免创建不必要的 Proxy 代理，减少内存和性能开销。 |
| 能做什么 | 减少响应式系统的负担，提升大数据量场景下的性能。 |
| 怎么用 | `const config = { title: '系统设置', version: '1.0.0' }` 普通变量；`const user = ref({ name: '张三' })` 需要响应式时使用 ref。 |
| 原理和工作流程 | 每个 ref/reactive 都会创建 Proxy 代理或 getter/setter 包装，有内存和计算开销；普通变量无此开销。 |
| 缺点 | 需要开发者判断哪些数据需要响应式，容易误判。 |

### 合理使用 nextTick

| 维度 | 内容 |
|------|------|
| 是什么 | 两种典型场景：数据变化后获取更新后的 DOM 位置（如滚动到底部）；确保子组件渲染完成后再执行校验或操作。 |
| 能做什么 | 在滚动场景中，先添加消息再通过 nextTick 获取更新后的滚动高度；在表单验证中，触发验证后通过 nextTick 等待错误信息渲染。 |
| 怎么用 | `messages.value.push(newMsg); await nextTick(); container.value.scrollTop = container.value.scrollHeight`；`formRef.value.validate(); await nextTick()`。 |
| 原理和工作流程 | Vue 的 DOM 更新是异步的，数据变化后组件不会立即重新渲染，而是在 nextTick 中批量更新；在 nextTick 回调中可以获取到最新的 DOM 状态。 |
| 缺点 | 过度使用 nextTick 会增加代码的异步复杂度；在不需要等待 DOM 更新时使用 nextTick 是多余的。 |

## 四、常见面试题

### 1. Vue 2 和 Vue 3 响应式原理的区别

| 维度 | 内容 |
|------|------|
| 是什么 | Vue 2 使用 Object.defineProperty 劫持属性，Vue 3 使用 Proxy 代理整个对象；Vue 2 无法检测新增/删除属性和数组索引修改，Vue 3 可以。 |
| 能做什么 | Vue 3 的 Proxy 方案解决了 Vue 2 中需要 `Vue.set`/`Vue.delete` 的痛点，数组操作更自然。 |
| 怎么用 | Vue 3：`const state = reactive({}); state.newProp = 'value'` 自动响应式；Vue 2：`Vue.set(obj, 'newProp', 'value')`。 |
| 原理和工作流程 | Vue 2 初始化时递归遍历所有属性设置 getter/setter；Vue 3 使用 Proxy 拦截所有操作，惰性代理（访问时才代理嵌套对象）；Vue 3 使用 Reflect 保证 this 指向正确。 |
| 缺点 | Vue 3 Proxy 不支持 IE11；Vue 2 的 Object.defineProperty 有诸多局限性。（历史兼容场景，2026 年新项目按现代浏览器基线） |

### 2. 虚拟 DOM 的原理和优缺点

| 维度 | 内容 |
|------|------|
| 是什么 | 虚拟 DOM 是用 JavaScript 对象描述真实 DOM 结构的轻量级表示，通过 Diff 算法对比新旧 VNode 找出最小变更批量更新。 |
| 能做什么 | 减少 DOM 操作次数，提升性能；跨平台渲染（Web、Native）；支持声明式编程。 |
| 怎么用 | 开发者无需直接操作 VNode，框架自动处理。 |
| 原理和工作流程 | 状态变化生成新 VNode 树，通过 patch 算法同层比较，标签名不同替换，标签名相同更新属性，子节点通过 Diff 算法对比。 |
| 缺点 | 首次渲染需要生成完整 VNode 树；需要额外的 Diff 计算开销；内存占用增加。 |

### 3. Vue 3 Diff 算法做了哪些优化

| 维度 | 内容 |
|------|------|
| 是什么 | 四项优化：静态标记（PatchFlag）标记动态内容类型；静态提升（HoistStatic）将静态节点提升到 render 函数外；Block Tree 动态节点收集到 dynamicChildren 中；事件缓存（cacheHandlers）缓存事件函数。 |
| 能做什么 | 运行时 Diff 只检查标记的属性，跳过静态节点，避免重复创建静态节点，减少不必要的子组件更新。 |
| 怎么用 | 编译期自动优化，开发者无需手动配置。 |
| 原理和工作流程 | PatchFlag 是位掩码标记，运行时按位与判断需要检查哪些属性；HoistStatic 将静态 VNode 创建移到 render 函数外部，多次渲染复用；Block Tree 在 createBlock 时收集 dynamicChildren，Diff 时仅对比这些节点；cacheHandlers 用 `_cache[0] || (_cache[0] = handler)` 缓存。 |
| 缺点 | 对于几乎全是动态内容的模板，优化效果有限。 |

### 4. nextTick 的原理和使用场景

| 维度 | 内容 |
|------|------|
| 是什么 | nextTick 将回调推迟到下次 DOM 更新循环之后执行，Vue 3 仅使用 `Promise.resolve().then()`（微任务）实现，无降级策略（Vue 2 曾使用降级链）。 |
| 能做什么 | 数据变化后获取更新后的 DOM；确保子组件渲染完成后再执行操作；在 created 或 setup 中等待 DOM 渲染完成。 |
| 怎么用 | `await nextTick(); console.log(element.textContent)`。 |
| 原理和工作流程 | 多个 nextTick 回调收集到队列中，通过 pending 标志控制只触发一次异步执行；优先使用微任务确保在当前宏任务内尽快执行。 |
| 缺点 | 过度使用导致代码逻辑复杂。 |

## 五、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 聚合了响应式与编译优化开发中八个常见错误：将响应式对象直接赋值给普通变量、在 Vue 3 中使用 Vue.set/Vue.delete、认为所有数据都需要响应式、在模板中直接修改 computed、直接修改 props、watch 中监听深层对象但使用浅拷贝比较、在 computed 中产生副作用、在 nextTick 中嵌套使用 nextTick。 |
| 能做什么 | 快速对照排查：保持使用 ref/reactive 不赋值为普通变量；Vue 3 直接赋值和删除即可；不需要响应式的数据用普通变量；使用可写计算属性或修改源数据；通过 emit 通知父组件修改；使用 `{ deep: true }` 深度监听；副作用放在 watch 中；只在必需时使用 nextTick。 |
| 怎么用 | `const state = reactive({ ... })` 保持引用；`state.newProp = 'value'` 直接赋值；`const config = { ... }` 普通变量；`computed({ get, set })` 可写计算属性；`emit('update', value)` 通知父组件。 |
| 原理和工作流程 | 响应式对象赋值给普通变量后，普通变量无 Proxy 代理，修改不触发更新；Proxy 直接支持新增/删除属性，不需要额外 API；computed 应保持为纯函数，副作用导致数据不可预测。 |
| 缺点 | 需要开发者理解响应式原理才能正确使用；部分错误在特定场景下才表现出问题。 |

## 性能调优专题

### v-memo

| 维度 | 内容 |
|------|------|
| 是什么 | `v-memo`（Vue 3.2+）是内置指令，接收一个固定长度的依赖值数组，数组中的每个值与上次渲染都相同时，整棵子树的更新被跳过；元素和组件上都可以使用。 |
| 能做什么 | 跳过整棵子树的 VNode 创建与 Diff，甚至直接复用缓存的子树副本；在长度超过 1000 的海量 `v-for` 列表中收益最明显。 |
| 怎么用 | `<div v-memo="[valueA, valueB]">...</div>`；与 `v-for` 搭配：`<div v-for="item in list" :key="item.id" v-memo="[item.id === selected]">`；`v-memo="[]"` 等同于 `v-once`。 |
| 原理和工作流程 | 渲染时比较依赖数组，全部相等则跳过该子树的更新与 VNode 创建。与 `v-for` 搭配时依赖数组不需要包含 `:key` 字段，因为 Vue 已通过 `:key` 判断。**`v-memo` 必须和 `v-for` 绑定在同一个元素上，不能写在 `v-for` 内部的子元素上。** |
| 缺点 | 把依赖声明的责任交给开发者，漏写会导致「数据变了视图不动」且难以排查；依赖比较本身有成本，短列表反而更慢。 |

### shallowRef / shallowReactive / markRaw

| 维度 | 内容 |
|------|------|
| 是什么 | 三个降低响应式开销的 API：`shallowRef` 只在 `.value` 被替换时触发更新，内部值不做深层响应式转换；`shallowReactive` 只有根级属性是响应式的；`markRaw` 标记对象使其永远不会被转换为响应式代理。 |
| 能做什么 | 跳过 Proxy 代理与依赖表的创建与维护，降低大数据量场景的内存占用与初始化耗时；适合持有第三方类实例、不可变数据源、大列表原始数据。 |
| 怎么用 | `const config = shallowRef({ list: [] }); config.value = { list: [] }` 触发更新，`config.value.list.push(1)` 不触发；需要手动触发时用 `triggerRef(config)`；`const state = shallowReactive({ list: [] }); state.list = [1]` 触发；`const chart = markRaw(new ECharts(el))`。 |
| 原理和工作流程 | `shallowRef` 只对 `.value` 的 getter/setter 做 `track` / `trigger`，不调用 `toReactive` 做深层转换；`shallowReactive` 只代理第一层属性；`markRaw` 在对象上打永久标记，`reactive()` 检测到该标记后直接返回原对象。 |
| 缺点 | `shallowRef` 内部深层变更不触发更新；`shallowReactive` 的嵌套对象完全不是响应式的；`markRaw` 标记**永久且不可撤销**，对已经是响应式代理的对象调用无效，无法「取消」已有响应式。 |

### v-once

| 维度 | 内容 |
|------|------|
| 是什么 | `v-once` 只渲染元素或组件一次，之后的重新渲染中该元素/组件及其所有子节点被视为静态内容并跳过。 |
| 能做什么 | 消除「首次渲染后永不变化」内容的更新开销，可用于单个元素、带子元素的容器、组件以及 `v-for` 中的每一项。 |
| 怎么用 | `<span v-once>永不变化：{{ msg }}</span>`；`<div v-once>...</div>`；`<MyComponent v-once :comment="msg" />`；`<li v-for="i in list" v-once>{{ i }}</li>`。 |
| 原理和工作流程 | 首次渲染后缓存该子树的 VNode 并标记为静态，后续更新直接跳过，与编译器的静态提升（HoistStatic）思路一致但作用在运行时。 |
| 缺点 | 之后该子树完全不再响应任何数据变化，误用在会变化的内容上会导致「界面停留首屏」且难以排查；定位是「确定永不变化」，减少更新应使用 `v-memo`。 |

### 虚拟列表实现

| 维度 | 内容 |
|------|------|
| 是什么 | 虚拟列表（虚拟滚动）只渲染可视区内的列表项，用占位元素撑开总高度，滚动时动态替换渲染内容，使真实 DOM 数量保持在可视区量级。分固定高度与动态高度两种方案。 |
| 能做什么 | 把渲染复杂度从 O(数据总量) 降到 O(可视区项数)，支撑万级甚至百万级数据滚动；固定高度实现简单、性能最好；动态高度可支撑聊天记录、富文本卡片等高度不定的场景。 |
| 怎么用 | 固定高度：`startIndex = Math.floor(scrollTop / itemHeight) - overscan`，`endIndex = Math.ceil((scrollTop + viewportHeight) / itemHeight) + overscan`，用 `transform: translateY(startIndex * itemHeight)` 整体位移，配 `@scroll.passive`；动态高度：`ResizeObserver` 测量每项真实高度 → 维护 `offsets` 前缀和 → 二分查找定位起始索引 → 绝对定位 + `top`。 |
| 原理和工作流程 | 占位层设置总高度 `items.length * itemHeight` 撑开滚动条；渲染层用 `transform`（固定高度）或 `top`（动态高度）位移到正确位置；`overscan` 缓冲区避免快速滚动白屏；动态高度需处理首屏估算（`estimatedHeight`）、`ResizeObserver` 死循环（仅在高度真实变化时写回）与高度修正导致的滚动位置偏移（锚点补偿）。 |
| 缺点 | 固定高度用 `index` 作 `key` 会导致切片后 `key` 不稳定、内容错乱；动态高度实现复杂，涉及锚点补偿、测量缓存等细节，建议使用 `vue-virtual-scroller` 的 `DynamicScroller` 或 `@tanstack/vue-virtual`；忘记在 `unmounted` 中断开 `ResizeObserver` 会造成内存泄漏。 |

### 大列表渲染优化的完整决策路径

| 维度 | 内容 |
|------|------|
| 是什么 | 面对「列表渲染卡顿」的六层逐级排查路径：数据是否需要响应式 → 是否需要一次性渲染全部 → 可视区外是否必须存在 DOM → 一次更新中多少项会变 → 渲染结果是否会变 → 列表项 props 与计算是否稳定。 |
| 能做什么 | 按收益从大到小定位优化点：数据层（分页/触底加载）> 渲染数量层（虚拟列表）> 更新范围层（`v-memo`）> 静态化层（`v-once`）> 计算与引用层（`computed`、稳定 `key`），避免盲目加 `v-memo` 或 `shallowRef`。 |
| 怎么用 | 不需要响应式 → `markRaw` / `shallowRef` / `Object.freeze`；能分页 → 分页或触底加载；需要滚动且数据量大 → 虚拟列表；只有少数项变化 → `v-memo="[依赖]"`；永不变化 → `v-once`；计算昂贵 → 提取到 `computed`；`:key` 用 index → 换成业务唯一 id。 |
| 原理和工作流程 | 越靠前的层级减少的是「需要参与响应式与渲染的数据量」，收益呈数量级；越靠后的层级减少的是「单次渲染的常数开销」。因此先做数据层与渲染数量层的优化，再做 `v-memo` 这类边际优化。 |
| 缺点 | 需要先确认性能瓶颈的真实位置（用 Vue DevTools 的 Performance 面板或浏览器 Performance 录制），否则容易优化错方向；虚拟列表会牺牲部分无障碍与「Ctrl+F 查找」体验。 |
