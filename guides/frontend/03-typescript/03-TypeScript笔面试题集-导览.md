### 3. 以下哪个不是泛型约束的写法？

| 能做什么 | 检验对泛型约束语法的记忆。 |

### 4. 关于枚举描述错误的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查枚举特性：const enum 编译时内联，不生成反向映射对象。 |
| 能做什么 | 检验对枚举类型和编译产物的理解。 |
| 怎么用 | 数字枚举从 0 递增，编译后生成反向映射对象；字符串枚举每个值必须初始化；const enum 编译后内联值，无额外代码。 |
| 原理和工作流程 | 普通枚举编译后生成包含正向和反向映射的对象；const enum 编译时替换为具体值，减少运行时代码。 |
| 缺点 | 不知道 const enum 和普通 enum 编译产物的区别。 |

### 7. 以下哪个关于 any 和 unknown 的描述是正确的？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 any 和 unknown 的区别：unknown 是安全版本，使用前必须类型守卫。 |
| 能做什么 | 检验对类型安全层次的理解。 |
| 怎么用 | any 可以赋值给任何类型，也可以访问任何属性，跳过类型检查；unknown 只能赋值给 any 和 unknown，使用前必须类型收窄。 |
| 原理和工作流程 | unknown 是 top type，所有类型可以赋值给 unknown，但 unknown 不能赋值给其他类型（除 any 和 unknown），必须类型守卫后才能使用。 |
| 缺点 | 认为 unknown 和 any 一样可以随意使用是常见错误。 |

### 8. 关于 never 类型描述错误的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 never 类型特性：never 是 bottom type，可以赋值给任何类型（但没有任何类型可以赋值给 never）。 |
| 能做什么 | 检验对 never 特殊类型的理解。 |
| 怎么用 | never 表示永远不会到达的值，用于函数抛异常或无限循环的返回类型；用于穷举检查确保 switch 覆盖所有情况。 |
| 原理和工作流程 | never 是类型系统的 bottom type，任何类型不能赋值给 never（但 never 可以赋值给任何类型）。用于确保 switch 穷举时，如果某分支没有被处理，其类型会落到 never 上触发编译错误。 |
| 缺点 | 搞反 never 的方向（说任何类型可以赋值给 never 实际是反的）。 |

## 三、场景设计题（5 题，每题附思路和核心代码）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查实际场景下 TypeScript 类型设计能力，要求写出类型定义。 |
| 能做什么 | 检验将类型系统知识应用到实际场景的能力，不仅懂概念还要能设计类型。 |
| 怎么用 | 看完题目先自己思考类型设计，再对照参考思路和代码检查差异。 |
| 原理和工作流程 | 5 道场景题覆盖 API 响应类型、函数重载、泛型约束、工具类型组合、条件类型，都是高频类型设计题。 |
| 缺点 | 题目只给思路和核心代码，完整类型设计可能需要更多边界情况处理。 |

### 1. 题目：设计一个 API 响应类型，支持成功和失败两种状态

| 维度 | 内容 |
|------|------|
| 是什么 | 考查使用联合类型设计 API 响应，通过 status 字段区分成功和失败，配合类型守卫实现类型收窄。 |
| 能做什么 | 检验对联合类型和类型守卫的实际运用能力。 |
| 怎么用 | `type ApiResponse<T> = { status: 'success'; data: T; } | { status: 'error'; message: string; code: number; };`，通过 `if (res.status === 'success')` 类型收窄。 |
| 原理和工作流程 | 可辨识联合类型通过共同字段（status）区分不同状态，类型守卫后每个分支获得精确类型，避免访问不存在的属性。 |
| 缺点 | 忘记使用泛型参数 T 让 data 类型可配置是常见错误。 |

### 2. 题目：实现函数重载，支持不同参数类型返回不同结果

| 维度 | 内容 |
|------|------|
| 是什么 | 考查函数重载语法，根据参数类型返回不同结果。 |
| 能做什么 | 检验对函数重载的理解和运用。 |
| 怎么用 | 写多个函数签名，每个签名对应不同参数类型和返回值类型，最后写实现签名，通过类型守卫区分参数类型。 |
| 原理和工作流程 | 编译器从上到下匹配函数签名，找到第一个匹配的确定返回值类型。实现签名需要完整覆盖所有场景。 |
| 缺点 | 实现签名中忘记类型守卫导致类型错误。 |

### 3. 题目：实现一个泛型函数，限制参数必须有 length 属性

| 维度 | 内容 |
|------|------|
| 是什么 | 考查泛型约束：使用 extends 限制泛型参数必须包含 length 属性。 |
| 能做什么 | 检验对泛型约束的理解和运用。 |
| 怎么用 | `function getLength<T extends { length: number }>(arg: T): number { return arg.length; }`，支持 string、array、有 length 的对象。 |
| 原理和工作流程 | extends 约束确保 T 类型至少包含 length 属性，函数内部可以安全访问 arg.length，编译器不会报错。 |
| 缺点 | 不使用泛型约束直接写 arg.length 会编译报错。 |

### 4. 题目：实现一个工具类型 DeepReadonly，递归将所有属性变为只读

| 维度 | 内容 |
|------|------|
| 是什么 | 考查映射类型和条件类型的组合使用，实现递归只读类型。 |
| 能做什么 | 检验对高级类型和递归类型设计的理解。 |
| 怎么用 | `type DeepReadonly<T> = { readonly [P in keyof T]: T[P] extends object ? DeepReadonly<T[P]> : T[P]; };` |
| 原理和工作流程 | 映射类型遍历所有属性，条件类型判断属性值是否为对象，如果是对象递归应用 DeepReadonly，否则直接设为 readonly。 |
| 缺点 | 忘记递归处理嵌套对象属性，只做了一层 readonly。 |

### 5. 题目：实现一个条件类型 IsString<T>，判断 T 是否为 string

| 维度 | 内容 |
|------|------|
| 是什么 | 考查条件类型基本语法：`T extends U ? X : Y` 实现类型级别条件判断。 |
| 能做什么 | 检验对条件类型的理解。 |
| 怎么用 | `type IsString<T> = T extends string ? true : false;`，`IsString<string>` 返回 true，`IsString<number>` 返回 false。 |
| 原理和工作流程 | 条件类型在编译时根据类型关系求值，联合类型自动分发，每个类型独立判断后重新联合。 |
| 缺点 | 不熟悉条件类型语法，不会写 `extends` 和 `? ... :` 的正确顺序。 |
