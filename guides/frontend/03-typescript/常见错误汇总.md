# TypeScript - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 使用any类型导致类型检查失效 | 类型标注过于宽松，滥用any逃避类型检查 | 使用具体类型或unknown替代any，启用strict模式 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 混淆JS运行时的typeof与TS类型中的typeof | TS中的typeof是类型查询，JS中的typeof是运行时运算符 | 区分类型空间和值空间，理解类型上下文中的typeof含义 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 联合类型函数参数未进行类型收窄 | 联合类型直接使用成员方法会报错 | 使用typeof instanceof或in进行类型守卫，收窄后再使用 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 使用as断言绕过类型检查而非正确处理类型 | 图方便使用类型断言逃避编译器报错 | 编写正确的类型定义，使用类型守卫，只在确信比编译器更了解类型时使用断言 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 枚举反向映射导致意外行为 | 数字枚举默认生成反向映射，可能造成类型安全问题 | 使用const enum或字符串枚举，避免反向映射 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 泛型约束过度导致类型不灵活 | 泛型约束过于严格限制了传入类型 | 使用extends定义最小必要约束，结合条件类型实现更灵活的泛型 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| tsconfig.json配置strict未开启 | 项目初始化时未启用严格模式 | 在tsconfig.json中启用strict: true，逐步修复类型错误 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 类型声明文件与实现文件不匹配 | 手动维护类型声明容易遗漏或错误 | 优先使用tsc自动生成声明文件，或使用JSDoc注释生成 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| mapped type与keyof组合使用不当 | 对映射类型的语法理解不充分 | 注意keyof操作符和索引访问类型的结合使用，使用as关键字过滤键 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 条件类型中使用never导致分发问题 | 不熟悉条件类型的分布式特性 | 使用元组包裹类型参数避免分发，或使用[]包裹 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 泛型类型推断失败导致使用any | 泛型参数未正确传递或约束导致推断失败 | 明确指定泛型参数，或使用extends约束提供默认推断 | [TypeScript笔面试题集导览](./03-TypeScript笔面试题集-导览.md) |
| 类型守卫编写不完整导致窄化失败 | 类型守卫返回值类型标注不正确 | 使用`arg is Type`语法标注返回值，确保守卫逻辑覆盖所有分支 | [TypeScript笔面试题集导览](./03-TypeScript笔面试题集-导览.md) |
| 工具类型实现与预期不符 | 对工具类型的内置实现理解不准确 | 理解Partial/Required/Readonly/Pick/Omit等工具类型的实现原理 | [TypeScript笔面试题集导览](./03-TypeScript笔面试题集-导览.md) |
| 类型守卫编译通过，但运行时访问属性报错 | TS 不校验守卫函数体的逻辑，实现与谓词声明不一致 | 守卫函数内必须做真实校验；复杂结构改用 zod 等运行时校验库 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 写 `typeof x === 'object'` 后直接取属性，报"对象可能为 null" | `typeof null === 'object'`，收窄结果是 `object \| null` | 追加 `x !== null` 判断后再访问属性 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 报错"A type predicate's type must be assignable to its parameter's type" | 谓词类型比参数类型更宽，谓词只能收窄、不能凭空造类型 | 把参数类型放宽为 `unknown` 或公共基类 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 断言函数报错要求显式类型标注 | 断言函数依赖显式标注，箭头函数简写无法满足 | 写成 `const assertX: (v: unknown) => asserts v is T = ...` | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| switch 无法按判别属性分流，类型不收敛 | 判别属性用了 `string` / `number` 等宽类型，不是单元类型 | 改用字面量联合类型（必要时配合 `as const`） | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| switch 漏写 default 后穷尽性检查形同虚设 | 没有触发 `never` 赋值，新增分支不会被编译器发现 | 必须补 `default` 分支并把值赋给 `never` 类型变量 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 在异步回调里依赖外部的类型收窄，回调内类型报错 | 收窄不跨越函数边界，尤其对 `let` 变量；赋值与 `await` 后也会重置收窄 | 先把值复制到 `const` 局部变量，再进回调；必要时重新判断 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 报错"This overload signature is not compatible with its implementation signature" | 实现签名参数写窄，无法接受所有重载的参数 | 实现签名参数放宽为联合类型或更宽的父类型 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 重载函数返回类型与预期不符 | 重载从上到下取第一个匹配，顺序颠倒导致宽泛签名抢先命中 | 具体签名写在前面，宽泛签名写在后面 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 敏感字段仍能被 `(obj as any).x` 读到 | 把 `private` 当成了安全边界，它只是编译期约束 | 真正需要运行时封装时使用 `#field` 私有字段 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 派生类构造函数中访问 this 报错 | 必须先调用 `super()` 才能访问 `this` | 把 `super(...)` 放在构造函数最前面 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 访问类字段得到 undefined，getter/setter 失效 | 字段声明覆盖了原型上的 getter/setter（`useDefineForClassFields` / `target: ES2022+` 使用 defineProperty 语义） | 用 `declare` 声明纯类型字段，或显式在构造函数中赋值 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 基类方法改名后子类覆写静默失效 | 未开启 `noImplicitOverride`，漏写 `override` 不报错 | 开启 `noImplicitOverride`，覆写一律写 `override` 关键字 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 对象字面量多写一个属性就报错 | 多余属性检查是刻意设计的严格规则 | 检查是否拼错；确有多余属性就先赋给变量再传入 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 把子类型数组当父类型数组写入，运行时出现"缺方法"的对象 | 数组协变不安全，TS 不阻止这种写入 | 用 `readonly T[]`，或避免把子类型数组当父类型数组写 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 同样的参数类型，方法语法报错而函数属性语法不报错 | `strictFunctionTypes` 只对函数属性语法生效，方法语法保持双变 | 需要严格逆变检查就用函数属性语法声明 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 用 `any` 当"兼容性补丁"，错误在项目里扩散 | `any` 双向可赋值且会污染推导结果 | 改用 `unknown` + 收窄，或写出精确类型 | [TypeScript基础与类型系统导览](./01-TypeScript基础与类型系统-导览.md) |
| 条件类型返回联合类型而非元组，与预期不符 | 裸联合类型在条件类型中会自动分发 | 需要整体判断时用 `[T] extends [U]` 包裹类型参数 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| `infer` 报语法错误或无法推导 | `infer` 只能在条件类型的 `extends` 子句中使用 | 把 `infer` 放到 `extends` 那一侧，写在待推导的位置 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 映射类型遍历得不到正确的键 | 混淆了 `T` 和 `keyof T` | 映射遍历的是 `keyof T`，再配合 `as` 关键字过滤键 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 编辑器里 `@/utils` 不报错，`vite build` 却失败 | 只配了 tsconfig 的 `paths`，它不影响运行时解析 | 同步配置 `resolve.alias` / `moduleNameMapper`；单元测试也要配别名 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| `.vue` 文件里的类型错误不影响构建 | Vite 用 esbuild 转译，只擦除类型不做检查 | CI 增加 `vue-tsc --noEmit`（或 `vue-tsc -b`）独立门禁 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 在 `.d.ts` 里写实现代码，报"环境上下文中不能有实现" | `.d.ts` 只描述类型，不能包含实现 | 把实现留在 `.ts` 里，声明文件只写签名 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 全局声明文件里写了 `import`，其他文件找不到全局类型 | 有顶层 `import` 后文件变成模块，声明不再注入全局 | 用 `declare global { }` 包住全局声明，并在首行加 `export {}` | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 手写 `*.vue` shim 后组件 props 类型全变 `any` | 与 vue-tsc / Volar 的原生 `.vue` 支持冲突 | 用 vue-tsc 的项目应删除该 shim 文件 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| `@types` 版本与库版本不匹配，报类型错误或 API 不存在 | 类型定义滞后于库本身 | 对齐版本，或用 `overrides` 固定 `@types` 版本 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 发布库后使用方没有类型提示 | 没开 `declaration`，或 `package.json` 的 `types` 字段没指向入口声明 | 开启 `declaration` 并配置 `types` 字段；注意别名残留需用 `tsc-alias` 改写 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 用 `const enum` 跨文件时打包器行为与 tsc 不一致 | 单文件转译无法跨文件内联常量枚举 | 改用 `as const` 对象 + `typeof` 取值的写法替代 | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| Vue 组件数组/对象默认值在所有实例间共享 | 默认值字面量只求值一次，被多个实例复用 | 用工厂函数返回新值，如 `tags: () => []` | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| React 19 中继续使用 `forwardRef` 造成代码冗余 | React 19 起 `ref` 已是普通 prop | 直接接收 `ref` prop；仅在需要兼容旧版本时保留 `forwardRef` | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 用 `ComponentProps<'button'>` 后自己的 `ref` 类型冲突 | `ComponentProps` 包含原生 ref 类型 | 改用 `ComponentPropsWithoutRef<'button'>` | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
| 用 `ReactNode` 顶替需要 `ReactElement` 的位置，类型不兼容 | `ReactNode` 包含 `string` / `number` / `null` 等 | 按目标 API 的要求选择 `ReactElement` 或 `ReactNode` | [高级类型与工程配置导览](./02-高级类型与工程配置-导览.md) |
