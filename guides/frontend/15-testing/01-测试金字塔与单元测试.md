## 一、核心概念

### 1.1 测试金字塔

测试金字塔是 Mike Cohn 在《Succeeding with Agile》中提出的测试策略模型，它用金字塔的层级结构描述了不同测试类型的理想比例。

**建筑类比**：测试金字塔就像建造一栋大楼的验收流程：

| 金字塔层级 | 测试类型 | 理想占比 | 建筑类比 |
|---|---|---|---|
| 顶层 | E2E 测试 | 5-10% | 整栋楼验收：走一遍完整的消防通道、检查所有水电 |
| 第三层 | 集成测试 | 10-15% | 房间验收：检查厨房水电是否连通、卫生间防水 |
| 第二层 | 组件测试 | 20-30% | 墙体验收：检查每面墙是否平整、承重是否达标 |
| 底层 | 单元测试 | 50-60% | 地基验收：检查每一块砖、每一根钢筋是否合格 |

**核心原则**：越底层的测试，运行速度越快、维护成本越低、定位问题越精确。因此底层测试应该占据最大比例。

```typescript
// 测试金字塔的直观体现：不同层级的测试数量对比
// 单元测试（大量、快速、精确）
describe('calculateDiscount', () => {
  it('满100减20', () => { /* ... */ });
  it('满200减50', () => { /* ... */ });
  it('不满100不减', () => { /* ... */ });
  it('负数金额抛异常', () => { /* ... */ });
  // 一个函数可能有 10+ 个单元测试
});

// 组件测试（适中、验证用户交互）
describe('ShoppingCart', () => {
  it('添加商品后列表更新', () => { /* ... */ });
  it('删除商品后列表更新', () => { /* ... */ });
  // 一个组件通常有 5-10 个组件测试
});

// 集成测试（较少、验证模块协作）
describe('下单流程', () => {
  it('选商品→加购物车→下单→支付', () => { /* ... */ });
  // 一个流程通常有 1-3 个集成测试
});

// E2E 测试（最少、验证关键路径）
test('用户注册到下单完整流程', () => { /* ... */ });
// 一个关键用户路径只有 1 个 E2E 测试
```

### 1.2 测试 ROI 分析

**为什么底层测试投入产出比最高？**

| 维度 | 单元测试 | 组件测试 | 集成测试 | E2E 测试 |
|---|---|---|---|---|
| 编写速度 | 快（分钟级） | 中（十分钟级） | 慢（小时级） | 很慢（天级） |
| 运行速度 | 极快（毫秒级） | 快（秒级） | 中（十秒级） | 慢（分钟级） |
| 维护成本 | 低 | 中 | 较高 | 高 |
| 问题定位精度 | 精确到行 | 精确到组件 | 精确到模块 | 模糊（需进一步排查） |
| 稳定性 | 极高 | 高 | 中 | 低（易受环境干扰） |
| 投入产出比 | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★★☆☆☆ |

**测试反模式：冰淇淋甜筒（Ice Cream Cone）**

一些团队的反模式是测试形状像倒置的甜筒——大量手工 E2E 测试，少量单元测试。这导致：
- CI 运行时间极长（30 分钟+）
- 测试不稳定（flaky tests）频繁打断开发
- 问题定位困难（E2E 失败只知道"哪里出错了"，不知道"为什么出错"）

```typescript
// 反模式示例：用 E2E 测试覆盖所有边界条件
// 错误：为每个折扣计算用 E2E 测试
test('满100减20的E2E验证', async () => {
  await page.goto('/cart');
  await page.fill('#amount', '100');
  await page.click('#apply-discount');
  await expect(page.locator('#final-price')).toHaveText('80');
  // 运行一次需要 30 秒，维护成本高
});

// 正确做法：将逻辑移到单元测试
describe('calculateDiscount', () => {
  it.each([
    [100, 0.2, 80],
    [200, 0.25, 150],
    [50, 0, 50],
    [0, 0, 0],
  ])('金额 %i 折扣后应为 %i', (price, rate, expected) => {
    expect(calculateDiscount(price, rate)).toBe(expected);
  });
  // 运行 100 个用例只需 0.1 秒
});
```

## 二、底层原理

### 2.1 Vitest 的测试运行机制

Vitest 的测试运行机制基于三个核心 API：`describe`、`it`/`test`、`expect`。

**describe/it/expect 的内部实现原理**：

```typescript
// ========================
// describe/it/expect 的简化实现原理
// ========================

// 全局测试套件注册表
const globalSuiteRegistry: Map<string, Suite> = new Map();

// Suite 类：表示一个 describe 块
class Suite {
  name: string;
  parent: Suite | null;
  tests: TestCase[] = [];
  suites: Suite[] = [];
  beforeAllHooks: Function[] = [];
  afterAllHooks: Function[] = [];
  beforeEachHooks: Function[] = [];
  afterEachHooks: Function[] = [];

  constructor(name: string, parent: Suite | null = null) {
    this.name = name;
    this.parent = parent;
  }
}

// TestCase 类：表示一个 it/test 块
class TestCase {
  name: string;
  fn: Function;
  suite: Suite;

  constructor(name: string, fn: Function, suite: Suite) {
    this.name = name;
    this.fn = fn;
    this.suite = suite;
  }
}

// 当前活跃的 describe 块（栈结构支持嵌套）
let currentSuiteStack: Suite[] = [];

// 全局 describe 函数
function describe(name: string, fn: () => void): void {
  const parent = currentSuiteStack.length > 0
    ? currentSuiteStack[currentSuiteStack.length - 1]
    : null;
  const suite = new Suite(name, parent);

  if (parent) {
    parent.suites.push(suite);
  } else {
    globalSuiteRegistry.set(name, suite);
  }

  currentSuiteStack.push(suite);
  fn(); // 执行 describe 回调，收集其中的 it 和嵌套 describe
  currentSuiteStack.pop();
}

// 全局 it/test 函数
function it(name: string, fn: Function): void {
  const currentSuite = currentSuiteStack[currentSuiteStack.length - 1];
  if (!currentSuite) {
    throw new Error('it() 必须在 describe() 内部调用');
  }
  currentSuite.tests.push(new TestCase(name, fn, currentSuite));
}

// 全局 beforeAll / beforeEach / afterAll / afterEach
function beforeEach(fn: Function): void {
  const currentSuite = currentSuiteStack[currentSuiteStack.length - 1];
  currentSuite.beforeEachHooks.push(fn);
}

// ========================
// expect 的简化实现
// ========================
class Expectation<T> {
  private actual: T;
  private isNot: boolean = false;

  constructor(actual: T) {
    this.actual = actual;
  }

  get not(): Expectation<T> {
    this.isNot = !this.isNot;
    return this;
  }

  toBe(expected: T): void {
    const pass = Object.is(this.actual, expected);
    this.assert(pass, `期望 ${expected}，实际得到 ${this.actual}`);
  }

  toEqual(expected: T): void {
    const pass = deepEqual(this.actual, expected);
    this.assert(pass, `期望深度相等，但实际不相等`);
  }

  toThrow(expectedMessage?: string): void {
    let pass = false;
    try {
      (this.actual as Function)();
    } catch (error: any) {
      if (expectedMessage) {
        pass = error.message.includes(expectedMessage);
      } else {
        pass = true;
      }
    }
    this.assert(pass, `期望抛出异常`);
  }

  private assert(pass: boolean, message: string): void {
    if (this.isNot ? pass : !pass) {
      throw new AssertionError(message);
    }
  }
}

// 全局 expect 函数
function expect<T>(actual: T): Expectation<T> {
  return new Expectation(actual);
}

// 深度比较工具函数（简化实现，不处理 Date、RegExp、Map、Set 等特殊类型）
// 边界情况说明：
//   - NaN === NaN 为 false，但 deepEqual(NaN, NaN) 会因 typeof NaN === 'number' 且 NaN !== NaN 而返回 false（需 Number.isNaN 特殊处理）
//   - +0 和 -0 在三等号下相等，但 Object.is(+0, -0) 为 false（本实现不区分）
//   - 循环引用会导致无限递归，需额外引入 WeakSet 检测
//   - 原型链上的属性不会被 Object.keys 枚举，因此只比较自有属性
function deepEqual(a: any, b: any): boolean {
  if (a === b) return true;
  if (typeof a !== 'object' || typeof b !== 'object') return false;
  if (a === null || b === null) return false;

  const keysA = Object.keys(a);
  const keysB = Object.keys(b);
  if (keysA.length !== keysB.length) return false;

  return keysA.every(key => deepEqual(a[key], b[key]));
}

// ========================
// 测试运行器
// ========================
async function runSuite(suite: Suite): Promise<TestResult[]> {
  const results: TestResult[] = [];

  // 收集所有祖先的 hooks
  const allBeforeEach = collectHooks(suite, 'beforeEachHooks');
  const allAfterEach = collectHooks(suite, 'afterEachHooks');

  // 执行 beforeAll hooks
  for (const hook of suite.beforeAllHooks) {
    await hook();
  }

  // 执行当前 suite 的测试用例
  for (const testCase of suite.tests) {
    // 执行 beforeEach hooks
    for (const hook of allBeforeEach) {
      await hook();
    }

    try {
      await testCase.fn();
      results.push({ name: testCase.name, status: 'passed' });
    } catch (error) {
      results.push({ name: testCase.name, status: 'failed', error });
    }

    // 执行 afterEach hooks
    for (const hook of allAfterEach) {
      await hook();
    }
  }

  // 递归执行嵌套的 suite
  for (const childSuite of suite.suites) {
    results.push(...await runSuite(childSuite));
  }

  // 执行 afterAll hooks
  for (const hook of suite.afterAllHooks) {
    await hook();
  }

  return results;
}

function collectHooks(suite: Suite, hookType: string): Function[] {
  const hooks: Function[] = [];
  let current: Suite | null = suite;
  while (current) {
    hooks.unshift(...(current as any)[hookType]);
    current = current.parent;
  }
  return hooks;
}

// 使用示例
describe('calculateDiscount', () => {
  let originalPrice: number;

  beforeEach(() => {
    originalPrice = 100;
  });

  it('满100减20', () => {
    expect(calculateDiscount(originalPrice)).toBe(80);
  });

  it('不满100不减', () => {
    expect(calculateDiscount(50)).toBe(50);
  });
});
```

### 2.2 Mock 策略

Vitest 提供三种核心 Mock 策略，分别适用于不同场景。

**2.2.1 vi.mock —— 模块级 Mock**

```typescript
// ========================
// vi.mock：替换整个模块
// ========================

// src/api/user.ts（被 mock 的模块）
export async function fetchUser(id: string) {
  const response = await fetch(`/api/users/${id}`);
  return response.json();
}

export async function updateUser(id: string, data: any) {
  const response = await fetch(`/api/users/${id}`, {
    method: 'PUT',
    body: JSON.stringify(data),
  });
  return response.json();
}

// src/api/__tests__/user.test.ts
import { vi, describe, it, expect } from 'vitest';

// vi.mock 会被提升到文件顶部（hoisting），确保模块在导入前就被替换
vi.mock('../user', () => ({
  fetchUser: vi.fn(),
  updateUser: vi.fn(),
}));

import { fetchUser, updateUser } from '../user';

describe('user API（mock 版本）', () => {
  it('fetchUser 被 mock 替换后不发送真实请求', async () => {
    // 设置 mock 返回值
    vi.mocked(fetchUser).mockResolvedValue({ id: '1', name: '张三' });

    const result = await fetchUser('1');

    expect(result).toEqual({ id: '1', name: '张三' });
    expect(fetchUser).toHaveBeenCalledWith('1');
    expect(fetchUser).toHaveBeenCalledTimes(1);
  });

  it('updateUser 返回 mock 数据', async () => {
    vi.mocked(updateUser).mockResolvedValue({ id: '1', name: '李四' });

    const result = await updateUser('1', { name: '李四' });

    expect(result.name).toBe('李四');
    expect(updateUser).toHaveBeenCalledTimes(1);
  });
});
```

**2.2.2 vi.fn —— 函数级 Mock**

```typescript
// ========================
// vi.fn：创建独立的 mock 函数
// ========================

describe('vi.fn 使用示例', () => {
  it('创建 mock 函数并验证调用', () => {
    const callback = vi.fn();

    // 调用 mock 函数
    callback('hello', 42);
    callback('world', 100);

    // 验证调用次数
    expect(callback).toHaveBeenCalledTimes(2);

    // 验证调用参数
    expect(callback).toHaveBeenCalledWith('hello', 42);
    expect(callback).toHaveBeenCalledWith('world', 100);

    // 获取所有调用信息
    expect(callback.mock.calls).toEqual([
      ['hello', 42],
      ['world', 100],
    ]);
  });

  it('mock 函数返回自定义值', () => {
    const mockFn = vi.fn();

    // 设置返回值
    mockFn.mockReturnValue('default');
    // 设置单次返回值
    mockFn.mockReturnValueOnce('first').mockReturnValueOnce('second');

    expect(mockFn()).toBe('first');   // 第一次调用
    expect(mockFn()).toBe('second');  // 第二次调用
    expect(mockFn()).toBe('default'); // 后续调用
  });

  it('mock 异步函数', async () => {
    const mockAsync = vi.fn();

    mockAsync.mockResolvedValue({ data: 'success' });
    // 或者 mock 失败场景
    // mockAsync.mockRejectedValue(new Error('network error'));

    const result = await mockAsync();
    expect(result).toEqual({ data: 'success' });
  });

  it('mock 函数实现自定义逻辑', () => {
    const mockFn = vi.fn((a: number, b: number) => a + b);

    expect(mockFn(1, 2)).toBe(3);
    expect(mockFn(10, 20)).toBe(30);
  });
});
```

**2.2.3 vi.spyOn —— 监听已有函数**

```typescript
// ========================
// vi.spyOn：监听模块中已有函数的调用，同时保留原始实现
// ========================

// src/utils/math.ts
export const mathUtils = {
  add(a: number, b: number): number {
    return a + b;
  },
  multiply(a: number, b: number): number {
    return a * b;
  },
};

// src/utils/__tests__/math.test.ts
import { mathUtils } from '../math';

describe('vi.spyOn 使用示例', () => {
  it('监听对象方法的调用（保留原始实现）', () => {
    const spy = vi.spyOn(mathUtils, 'add');

    const result = mathUtils.add(1, 2);

    expect(result).toBe(3);           // 原始实现仍然执行
    expect(spy).toHaveBeenCalledWith(1, 2);
    expect(spy).toHaveBeenCalledTimes(1);

    spy.mockRestore(); // 恢复原始实现
  });

  it('替换对象方法的实现', () => {
    const spy = vi.spyOn(mathUtils, 'multiply').mockImplementation(
      (a: number, b: number) => 100 // 始终返回 100
    );

    const result = mathUtils.multiply(5, 5);

    expect(result).toBe(100);
    expect(spy).toHaveBeenCalledWith(5, 5);

    spy.mockRestore();
  });

  it('模拟方法抛出异常', () => {
    const spy = vi.spyOn(mathUtils, 'add').mockImplementation(() => {
      throw new Error('计算失败');
    });

    expect(() => mathUtils.add(1, 2)).toThrow('计算失败');

    spy.mockRestore();
  });
});

// vi.spyOn vs vi.fn vs vi.mock 选择指南
// vi.mock：替换整个模块，适用于 API 层、第三方库
// vi.fn：创建独立 mock 函数，适用于回调函数、依赖注入
// vi.spyOn：监听已有方法，适用于需要部分保留原始行为的场景
```

### 2.3 测试覆盖率原理

测试覆盖率是衡量测试质量的重要指标，Vitest 支持两种覆盖率引擎：Istanbul 和 V8。

**Istanbul 代码插桩原理**：

```typescript
// ========================
// Istanbul 代码插桩原理示意
// ========================

// 原始代码
function calculateDiscount(price: number, isVip: boolean): number {
  if (isVip) {
    return price * 0.8;  // 行A
  } else if (price > 100) {
    return price - 20;   // 行B
  } else {
    return price;        // 行C
  }
}

// Istanbul 插桩后的代码（简化示意）
const coverageData = {
  // 记录每个语句是否被执行
  statementMap: { /* ... */ },
  // 记录每个分支是否被执行
  branchMap: { /* ... */ },
  // 记录每个函数是否被执行
  fnMap: { /* ... */ },
};

function calculateDiscount(price: number, isVip: boolean): number {
  // 插桩计数器
  coverageData.f[0]++; // 函数调用计数 +1

  if (isVip) {
    coverageData.b[0]++; // 分支 0（vip 分支）计数 +1
    coverageData.s[0]++; // 语句 0（行A）计数 +1
    return price * 0.8;
  } else if (price > 100) {
    coverageData.b[1]++; // 分支 1（满减分支）计数 +1
    coverageData.s[1]++; // 语句 1（行B）计数 +1
    return price - 20;
  } else {
    coverageData.b[2]++; // 分支 2（原价分支）计数 +1
    coverageData.s[2]++; // 语句 2（行C）计数 +1
    return price;
  }
}
```

**四种覆盖率类型**：

| 覆盖率类型 | 含义 | 计算方式 |
|---|---|---|
| 行覆盖率（Lines） | 每一行代码是否被执行过 | 被执行的行数 / 总有效行数 |
| 分支覆盖率（Branches） | 每个条件分支（if/else、switch）是否都被执行过 | 被执行的分支数 / 总分支数 |
| 函数覆盖率（Functions） | 每个函数是否被调用过 | 被调用的函数数 / 总函数数 |
| 语句覆盖率（Statements） | 每个语句是否被执行过 | 被执行的语句数 / 总语句数 |

```typescript
/**
 * 格式化日期为 YYYY-MM-DD
 */
export function formatDate(date: Date | string): string {
  const d = typeof date === 'string' ? new Date(date) : date;
  const year = d.getFullYear();
  const month = String(d.getMonth() + 1).padStart(2, '0');
  const day = String(d.getDate()).padStart(2, '0');
  return `${year}-${month}-${day}`;
}

/**
 * 格式化金额为货币字符串
 */
export function formatCurrency(amount: number, currency = 'CNY'): string {
  const localeMap: Record<string, string> = {
    CNY: 'zh-CN',
    USD: 'en-US',
    EUR: 'de-DE',
  };
  const locale = localeMap[currency] || 'zh-CN';

  return new Intl.NumberFormat(locale, {
    style: 'currency',
    currency,
    minimumFractionDigits: 2,
  }).format(amount);
}

/**
 * 计算商品折扣价
 */
export function calculateDiscount(
  price: number,
  discountRate: number
): number {
  if (price < 0) throw new Error('价格不能为负数');
  if (discountRate < 0 || discountRate > 1) throw new Error('折扣率必须在 0-1 之间');
  return Math.round(price * (1 - discountRate) * 100) / 100;
}

/**
 * 数据转换：将 API 返回的扁平数据转为树形结构
 */
export function buildTree<T extends { id: string; parentId: string | null }>(
  items: T[]
): (T & { children: T[] })[] {
  const map = new Map<string, T & { children: T[] }>();
  const roots: (T & { children: T[] })[] = [];

  // 初始化所有节点
  items.forEach(item => {
    map.set(item.id, { ...item, children: [] });
  });

  // 构建树
  items.forEach(item => {
    const node = map.get(item.id)!;
    if (item.parentId && map.has(item.parentId)) {
      map.get(item.parentId)!.children.push(node);
    } else {
      roots.push(node);
    }
  });

  return roots;
}
```

```typescript
import { create } from 'zustand';

interface CartItem {
  id: string;
  name: string;
  price: number;
  quantity: number;
}

interface CartStore {
  items: CartItem[];
  totalPrice: number;
  totalCount: number;

  // Actions
  addItem: (item: Omit<CartItem, 'quantity'>) => void;
  removeItem: (id: string) => void;
  updateQuantity: (id: string, quantity: number) => void;
  clearCart: () => void;
}

export const useCartStore = create<CartStore>((set, get) => ({
  items: [],
  totalPrice: 0,
  totalCount: 0,

  addItem: (item) => {
    const { items } = get();
    const existingIndex = items.findIndex(i => i.id === item.id);

    let newItems: CartItem[];
    if (existingIndex >= 0) {
      // 已存在，增加数量
      newItems = items.map((i, index) =>
        index === existingIndex
          ? { ...i, quantity: i.quantity + 1 }
          : i
      );
    } else {
      // 新商品，添加到列表
      newItems = [...items, { ...item, quantity: 1 }];
    }

    set({
      items: newItems,
      totalPrice: newItems.reduce((sum, i) => sum + i.price * i.quantity, 0),
      totalCount: newItems.reduce((sum, i) => sum + i.quantity, 0),
    });
  },

  removeItem: (id) => {
    const newItems = get().items.filter(i => i.id !== id);
    set({
      items: newItems,
      totalPrice: newItems.reduce((sum, i) => sum + i.price * i.quantity, 0),
      totalCount: newItems.reduce((sum, i) => sum + i.quantity, 0),
    });
  },

  updateQuantity: (id, quantity) => {
    if (quantity <= 0) {
      get().removeItem(id);
      return;
    }
    const newItems = get().items.map(i =>
      i.id === id ? { ...i, quantity } : i
    );
    set({
      items: newItems,
      totalPrice: newItems.reduce((sum, i) => sum + i.price * i.quantity, 0),
      totalCount: newItems.reduce((sum, i) => sum + i.quantity, 0),
    });
  },

  clearCart: () => {
    set({ items: [], totalPrice: 0, totalCount: 0 });
  },
}));
```

```typescript
}

  return response.json();

    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(data),
  });
  if (!response.ok) {
    throw new Error(`创建用户失败: ${response.status}`);

  return response.json();
```

```typescript
        'src/**/*.{ts,tsx}',
      ],

      // 排除的文件
      exclude: [
        'src/**/*.test.{ts,tsx}',
        'src/**/*.spec.{ts,tsx}',
        'src/**/__tests__/**',
        'src/**/__mocks__/**',
        'src/types/**',
        'src/vite-env.d.ts',
      ],

      // 覆盖率阈值（不满足时 CI 失败）
      thresholds: {
        // 全局阈值
        lines: 80,
        branches: 80,
        functions: 80,
        statements: 80,

        // 针对特定文件的阈值
        // 格式：'src/**/*.ts' 匹配所有 ts 文件
        'src/utils/**': {
          lines: 90,
          branches: 90,
          functions: 100,
          statements: 90,
        },
        'src/stores/**': {
          lines: 85,
          branches: 85,
          functions: 100,
          statements: 85,
        },
      },

      // 当覆盖率低于阈值时是否允许通过
      // CI 环境中应设为 false
      // thresholds: { ... },
      // 在 vitest 中，低于阈值会直接导致测试失败

      // 水印（watermarks）：在 HTML 报告中用颜色区分覆盖率等级
      watermarks: {
        statements: [50, 80],
        functions: [50, 80],
        branches: [50, 80],
        lines: [50, 80],
      },
    },
  },
});
```

## 四、常见面试题

**Q1：解释测试金字塔模型，为什么底层测试应该占比最大？**

答案要点：测试金字塔是 Mike Cohn 提出的测试策略模型，底层（单元测试）占 50-60%，中层（组件测试）占 20-30%，上层（集成测试）占 10-15%，顶层（E2E）占 5-10%。底层测试占比最大是因为：执行速度快（毫秒级）、维护成本低、问题定位精确到行、反馈周期短。越上层的测试，执行越慢、维护成本越高、越不稳定，因此数量应该递减。反模式"冰淇淋甜筒"会导致 CI 时间过长、测试不稳定、开发效率下降。

**Q2：Vitest 相比 Jest 有哪些优势？**

答案要点：与 Vite 共享配置（无需维护两套构建配置）、原生 ESM 支持（无需额外配置）、HMR 测试运行（watch 模式下只重跑受影响的测试）、开箱即用的 TypeScript 支持（无需 ts-jest）、浏览器模式（可运行在真实浏览器中）、速度更快（基于 ESBuild 转译）。但 Jest 的生态更成熟、社区资源更丰富、部分老旧项目迁移成本高。

**Q3：vi.mock、vi.fn、vi.spyOn 的区别和使用场景？**

答案要点：vi.mock 用于替换整个模块（如 API 层、第三方库），适合彻底隔离外部依赖；vi.fn 用于创建独立的 mock 函数，适合回调函数、依赖注入场景；vi.spyOn 用于监听已有对象的方法调用，可以选择保留或替换原始实现，适合需要部分保留原始行为的场景。vi.mock 会被 hoisting 提升到文件顶部，确保模块在导入前被替换。

**Q4：测试覆盖率 100% 是否意味着代码质量高？为什么？**

答案要点：不是。100% 覆盖率只能保证代码被执行过，不能保证测试用例的质量（如断言是否正确、边界条件是否覆盖）。追求 100% 覆盖率会导致：为 getter/setter 等简单代码编写无意义测试、忽视真正重要的业务逻辑测试、测试代码维护成本急剧上升。建议设定合理的阈值（如 80%），将精力集中在核心业务逻辑的测试质量上，而非数量。

**Q5：快照测试的适用场景和注意事项是什么？**

答案要点：适用场景包括 UI 组件渲染结果验证、配置文件输出验证、错误信息格式验证。注意事项：快照应该小而聚焦（避免整个页面的巨型快照）、使用内联快照提高可读性、使用属性匹配器忽略动态值（如时间戳、ID）、快照文件应提交到版本控制、review 快照变更时需仔细确认每个差异是否为预期变更、不要用快照测试替代行为测试（快照不能验证交互逻辑）。

## 五、避坑指南

| 错误现象 | 产生原因 | 正确做法 |
|---|---|---|
| 重构代码后大量单元测试失败，但重构逻辑是正确的 | 测试过度依赖实现细节（如内部方法名、中间变量值），而非公共接口和行为 | 测试应验证公共 API 的输入输出行为，而非内部实现；使用行为驱动测试（BDD）风格，关注"做什么"而非"怎么做" |
| Mock 过度使用导致测试失去意义，代码有 bug 但测试全绿 | 将所有依赖都 mock 掉，测试只验证了 mock 行为，而非真实集成行为 | 遵循"mock 你不拥有的，测试你拥有的"原则；只 mock 外部边界（网络请求、文件系统），内部模块尽量用真实实例；如果 mock 太多说明代码耦合度过高，应先重构 |
| 追求测试覆盖率 100% 导致大量时间浪费在 getter/setter 和简单代码上 | 将覆盖率指标当作目标而非手段，盲目追求数字 | 设定合理的覆盖率阈值（如 80%），将精力放在核心业务逻辑上；覆盖率是质量指标之一，不是唯一指标；关注分支覆盖率比行覆盖率更重要 |
