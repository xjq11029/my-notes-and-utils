# Git - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| `git reset --hard` 丢了代码，工作区修改找不到 | `--hard` 会覆盖工作区，未提交的修改直接丢掉 | 任何 reset --hard 之前先把修改 commit 或 stash 保存；错了立刻看 git reflog | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 把不该提交的大文件或敏感信息提交了（node_modules、密码、密钥） | 没写 `.gitignore`，或者一开始没注意 | 提前写好 `.gitignore`；已经提交了用 `git filter-branch` 或 `bfg` 从历史移除 | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 直接在 `master` 分支开发并直接推送，影响他人 | 没有分支开发意识 | 功能开发新建 feature 分支，测试完再合并到 master | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 提交信息写得乱七八糟，git log 看不懂每次改了什么 | 不重视提交信息 | 提交信息第一行一句话说明做了什么，改动大的话空一行写详情；用祈使语气，现在时态 | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| pull 不用 rebase，历史一堆合并提交，log 历史很乱 | 默认 pull 是 merge，每次拉都产生合并提交 | 配置 `git config --global pull.rebase true`，默认 pull --rebase 保持线性 | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 推远程失败提示快进失败（error: failed to push some refs） | 远程有本地没有的提交，需要先 pull | 先 `git pull --rebase` 把远程更新拉下来，解决冲突再推 | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 解决完 rebase 冲突不知道下一步，卡住了 | rebase 流程是一步步来的 | 解决完冲突后 `git add`，然后 `git rebase --continue`，要放弃就 `git rebase --abort` | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 本地分支推远程写错了远程分支名，远程多出来一个错的分支 | 不小心推错了 | 删除远程分支：`git push origin --delete wrong-branch` | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| 误删了分支，分支上的代码也找不到了 | 以为删了就没了 | Git 不会立刻删除提交，只要没 gc，用 `git reflog` 找最后一次提交恢复 | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
| tag 打错了想改，已经把错误 tag 推远程了 | 打错了版本号 | 本地删：`git tag -d v1.0.0`，远程删：`git push origin --delete v1.0.0`，然后重新打正确的再推 | [Git核心概念与常用命令导览](./01-Git核心概念与常用命令-导览.md) |
