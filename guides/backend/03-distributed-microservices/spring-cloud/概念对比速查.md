# Spring Cloud - 概念对比速查

---

### Nacos vs Eureka

| 对比维度 | Nacos | Eureka |
|---------|-------|-------|
| 核心定位 | 注册中心+配置中心一体化平台 | 仅注册中心 |
| 适用场景 | 微服务注册发现+配置管理+服务治理 | 仅服务注册发现 |
| CAP模型 | AP/CP可切换（Distro/Raft协议） | 仅AP（无Leader设计） |
| 健康检查 | 客户端心跳+服务端主动探测 | 仅客户端心跳 |
| 配置中心 | 内置，支持动态刷新、三层隔离 | 无 |
| 服务下线感知 | 主动通知+自动剔除，响应快 | 多级缓存，更新慢 |
| 维护状态 | 持续维护 | 已停更 |
| 选择建议 | 新项目首选，功能全面 | 历史项目遗留，不推荐新项目使用 |

### Gateway vs Zuul

| 对比维度 | Spring Cloud Gateway | Zuul 1.x |
|---------|---------------------|----------|
| 核心定位 | 基于WebFlux的非阻塞API网关 | 基于Servlet的阻塞API网关 |
| 适用场景 | 高并发微服务网关，支持万级并发 | 低并发场景或历史项目 |
| I/O模型 | 非阻塞I/O（Netty+Reactor） | 阻塞I/O（Servlet） |
| 线程模型 | 少量Event Loop线程处理大量请求 | 一个请求一个线程 |
| 长连接支持 | 天然支持 | 不支持 |
| 维护状态 | 持续维护 | 已停止维护 |
| 选择建议 | 新项目唯一选择 | 已淘汰，不推荐使用 |

### Seata AT vs TCC

| 对比维度 | AT模式 | TCC模式 |
|---------|--------|---------|
| 核心定位 | 无侵入自动回滚，基于undo_log | 有侵入手动回滚，需实现Try/Confirm/Cancel |
| 适用场景 | 大多数通用场景 | 高性能要求、需要自定义资源 |
| 侵入性 | 无侵入（自动生成回滚日志） | 有侵入（需实现三个方法） |
| 实现难度 | 简单，只需引入依赖 | 复杂，需要自定义资源预留和回滚逻辑 |
| 性能特点 | 有全局锁，性能一般 | 无锁，性能好 |
| 回滚方式 | 自动（undo_log执行反向SQL） | 手动（Cancel方法） |
| 数据一致性 | 最终一致 | 最终一致 |
| 数据库要求 | 仅支持关系型数据库（依赖ACID） | 无限制 |
| 选择建议 | 优先选择，开发效率高 | 性能瓶颈时选用，或非关系型数据库场景 |

### OpenFeign vs RestTemplate

| 对比维度 | OpenFeign | RestTemplate |
|---------|-----------|-------------|
| 核心定位 | 声明式HTTP客户端，接口即契约 | 编程式HTTP客户端，手动构造请求 |
| 适用场景 | 微服务间调用，接口定义清晰 | 自由度高、非标准API调用 |
| 调用方式 | 定义Java接口+注解，自动生成HTTP调用 | 手动拼接URL、构造请求 |
| 代码可读性 | 接口即契约，集中管理 | URL分散在代码各处 |
| 负载均衡 | 自动集成（Spring Cloud LoadBalancer） | 需配合@LoadBalanced |
| 熔断降级 | fallback/fallbackFactory原生支持 | 需手动处理 |
| 维护成本 | URL变更改注解即可 | URL变更需改多处理代码 |
| 选择建议 | 微服务间调用首选 | 调用外部API或需高度自定义时使用 |
