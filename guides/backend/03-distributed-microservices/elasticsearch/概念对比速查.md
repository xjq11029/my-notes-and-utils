# Elasticsearch - 概念对比速查

---

### Elasticsearch vs MySQL

| 对比维度 | Elasticsearch | MySQL |
|---------|-------------|-------|
| 核心定位 | 分布式搜索和分析引擎 | 关系型数据库管理系统 |
| 数据模型 | 文档型（JSON），基于 Index/Document/Field | 关系型，基于 Database/Table/Row/Column |
| 存储引擎 | 基于 Apache Lucene 的倒排索引 | InnoDB（B+Tree）、MyISAM 等 |
| 查询语言 | DSL（JSON 格式），支持全文检索 | SQL，支持精确查询和 JOIN |
| 事务支持 | 不支持 ACID 事务 | 完整支持 ACID 事务 |
| CAP 定位 | AP 系统，牺牲强一致性 | CP 系统（默认），保证强一致性 |
| 水平扩展 | 原生支持分片和副本，水平扩展 | 需借助分库分表中间件 |
| 全文检索 | 核心能力，基于倒排索引和分词器 | 有限支持（LIKE、FULLTEXT），性能差 |
| 聚合分析 | 强大的聚合分析能力（Bucket/Metric/Pipeline） | GROUP BY + 聚合函数，大数据量下性能差 |
| 写入吞吐 | 批量写入高吞吐 | 单行写入，受事务和索引约束 |
| 适用场景 | 全文搜索、日志分析、实时监控 | 业务数据存储、事务操作、强一致性需求 |
| 选择建议 | 搜索和分析场景选 ES；事务型主存储选 MySQL；两者配合使用 | |

### Lucene vs Elasticsearch

| 对比维度 | Lucene | Elasticsearch |
|---------|-------|-------------|
| 核心定位 | Java 全文检索库，搜索引擎底层组件 | 基于 Lucene 构建的分布式搜索和分析引擎 |
| 使用方式 | 需要编写 Java 代码调用 API | 提供 RESTful API，语言无关 |
| 分布式能力 | 无，需自行实现 | 原生支持分片、副本、集群管理 |
| 运维管理 | 需自行管理索引、合并、优化 | 自动化分片分配、段合并、集群健康监控 |
| 高级功能 | 仅提供基础检索能力 | 聚合分析、高亮显示、索引别名、数据管道 |
| 学习成本 | 高，需理解底层 API | 中，RESTful API 易上手 |
| 适用场景 | 嵌入式搜索、对性能有极致要求的场景 | 分布式搜索、日志分析、业务搜索服务 |
| 选择建议 | 需要内嵌搜索能力或深度定制时选用；大多数场景直接使用 ES | |

### 倒排索引 vs B+树

| 对比维度 | 倒排索引 | B+树 |
|---------|---------|------|
| 核心定位 | 词项到文档 ID 列表的映射，用于全文检索 | 排序的平衡多路搜索树，用于精确查询和范围查询 |
| 数据结构 | Term Dictionary + Term Index（FST） + Posting List | 多层节点，叶子节点形成有序链表 |
| 检索方式 | 通过词项直接定位文档列表，O(1) 复杂度 | 从根节点逐层二分查找，O(log N) 复杂度 |
| 适用查询类型 | 全文检索、模糊匹配、相关性评分 | 精确等值查询、范围查询、排序 |
| 索引大小 | 较小，稀疏索引，每 8192 行一个 Mark | 较大，稠密索引，每行一个索引项 |
| 更新成本 | 高，需重建 Segment | 低，支持原地更新 |
| 存储引擎 | Elasticsearch 底层使用 | MySQL InnoDB 底层使用 |
| 选择建议 | 全文检索场景选倒排索引；OLTP 精确查询选 B+树 | |
