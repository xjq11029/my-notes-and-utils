# Nginx - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 反向代理配置 proxy_pass 末尾漏写斜杠导致路径异常 | proxy_pass 末尾有无斜杠的 URI 拼接规则不同，漏写/多写导致路径错误 | 不带路径时末尾不加斜杠；带路径替换时末尾加斜杠 | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| upstream 中 server 地址写错导致 502 Bad Gateway | 后端服务地址配置错误或服务未启动 | 配置前确认后端服务地址和端口正确；使用 `nginx -t` 检查配置语法 | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 未配置 proxy_read_timeout 导致长请求被中断 | 默认 60 秒超时，长耗时请求被提前断开 | 根据业务特点设置合理的 proxy_read_timeout 值 | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 负载均衡未配置健康检查导致请求打到故障节点 | upstream 默认无主动健康检查，宕机节点仍可能被路由 | 配置 max_fails 和 fail_timeout 被动健康检查；或安装 nginx_upstream_check_module 主动检查 | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 多个 location 匹配规则冲突导致请求路由到错误 location | 对 location 优先级（精确匹配 > 前缀匹配 > 正则匹配）理解有误 | 掌握 location 匹配优先级，使用 `=` 精确匹配高优先级路径 | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 修改配置后直接 reload 但配置文件有语法错误导致服务中断 | 未执行 `nginx -t` 语法检查直接 reload，配置错误导致服务不可用 | 每次修改配置后先执行 `nginx -t` 检查语法，通过后再 reload | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 静态资源未配置缓存策略导致重复请求 | 未设置 Cache-Control 和 Expires，浏览器每次请求都重新下载 | 配置 `expires 30d` 并设置合理的 Cache-Control 头 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 未限制客户端请求体大小导致被大文件上传攻击 | 默认 client_max_body_size 为 1MB，但未按需调整或缺省值被覆盖 | 按业务需求精确设置 client_max_body_size，防止恶意大包攻击 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 未配置 gzip 压缩导致传输带宽浪费 | 文本类响应未压缩，网络传输效率低 | 开启 gzip 并配置 gzip_types 指定压缩类型，最小压缩长度 gzip_min_length | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| worker_processes 设置不当导致 CPU 资源浪费或不足 | 未根据 CPU 核心数配置 worker_processes | 设置为 auto 自动匹配 CPU 核心数 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| HTTPS 配置后 SSL 协议版本过低存在安全漏洞 | 仍支持 TLS 1.0/1.1 等已被淘汰的协议 | 配置 `ssl_protocols TLSv1.2 TLSv1.3;` 仅支持安全协议 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 反向代理和正向代理概念混淆导致配置错误 | 对两种代理的请求流向和客户端感知差异理解不清 | 正向代理代理客户端（如 VPN 科学上网）；反向代理代理服务端（如 Nginx 负载均衡） | [03-导览](./03-Nginx笔面试题集-导览.md) |
| 负载均衡算法选错导致 Session 丢失 | 使用轮询算法时，用户 Session 未持久化到共享存储，请求分发到不同服务器 | 需要 Session 粘性时使用 ip_hash 或 sticky cookie；或将 Session 存到 Redis 共享存储 | [03-导览](./03-Nginx笔面试题集-导览.md) |
| 静态资源 URL 配置错误导致 404 | root 和 alias 路径拼接规则混淆 | root 拼接完整路径（location + URI）；alias 替换 location 为指定路径 | [03-导览](./03-Nginx笔面试题集-导览.md) |
| gzip 开启后 CPU 使用率持续偏高 | 对大文件、已经压缩过的格式（JPG/PNG）也开启了压缩，压缩级别过高 | 调整 `gzip_min_length` 只压缩超过阈值的响应，图片等已压缩格式排除在外，`gzip_comp_level` 不超过 6 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 大量连接处于等待状态，吞吐上不去 | `worker_connections` 设置过小，并发连接数超过限制 | 根据实际并发调大（一般 10240 足够）；总连接数 ≈ `worker_processes × worker_connections`，两者要一起评估 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 报错 `open() ... failed (24: Too many open files)` | `worker_rlimit_nofile` 设置过小，或只调大了 Nginx 配置却没同步调整系统 `ulimit` | 设置 `worker_rlimit_nofile 65535;`，同时调整系统 `ulimit -n`，保证配置与系统限制匹配 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| HTTPS 首次访问握手慢、延迟高 | 未开启会话缓存，且仍在使用被淘汰的旧协议 | 开启 `ssl_session_cache`，只保留 `TLSv1.2 TLSv1.3`，并启用 HTTP/2 复用连接 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 客户端请求头较大时直接返回 400 错误 | `large_client_header_buffers` 太小，请求头缓冲区装不下 | 调大为 `4 8k` 或更大，注意同时评估 `client_header_buffer_size` | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 配置了 `expires` 但静态资源仍被反复请求 | `expires` 配置位置不对，没有落在真正命中静态资源的 `location` 块里 | 在静态资源对应的 `location` 块中配置 `expires`，配置后用 `curl -I` 检查响应头是否真的带上了 `Cache-Control` / `Expires` | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| 部分客户端（移动端、老浏览器）提示证书不受信任，PC 浏览器却正常 | `ssl_certificate` 只配了服务器证书，没有包含中间证书，证书链不完整 | 使用全链证书文件（服务器证书 + 中间证书按顺序拼接）配置 `ssl_certificate`，用 `openssl s_client -connect` 验证链完整 | [02-导览](./02-Nginx性能优化与安全配置-导览.md) |
| WebSocket 连接频繁断开或握手失败 | 未设置协议升级头，或沿用了默认的 60s 读取超时 | 配置 `proxy_http_version 1.1;`、`proxy_set_header Upgrade $http_upgrade;`、`proxy_set_header Connection "upgrade";`，并把 `proxy_read_timeout` 调大（如 3600s） | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 后端日志里客户端 IP 全是 Nginx 的 IP，无法做限流和审计 | 反向代理默认不会透传客户端真实信息，漏配 `proxy_set_header` | 至少配置 `Host $host`、`X-Real-IP $remote_addr`、`X-Forwarded-For $proxy_add_x_forwarded_for`，HTTPS 场景再加 `X-Forwarded-Proto $scheme` | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 后端生成的回调 URL、重定向地址指向错误的主机名 | 漏配 `proxy_set_header Host $host`，后端拿到的是 upstream 内部地址 | 显式传递 `Host $host`，让后端感知原始请求的域名 | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| `rewrite` 重写后没有进入新的 `location`，或 URI 被重复改写 | `last` 与 `break` 选错：`last` 会用新 URI 重新匹配 location，`break` 留在当前 location 继续执行 | 重写后需要交给另一个 location 处理用 `last`；只想在当前 location 内改写 URI 用 `break` | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 临时跳转被浏览器长期缓存，改回配置后用户仍访问旧地址 | 临时跳转误用了 `permanent`（301 永久重定向，浏览器会缓存） | 临时 URL 跳转用 `redirect`（302）；只有域名迁移、URL 永久变更才用 `permanent` | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 使用 `fair` 算法后 Nginx 启动失败或行为异常 | `fair` 属于第三方模块 `nginx-upstream-fair`，已多年未维护，与 Nginx 1.15+ 存在兼容性问题 | 生产环境不要用 `fair`；需要按响应时间调度时用 Nginx Plus 的 `least_time` | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
| 各后端配置相近，但请求处理时间差异大时仍出现负载不均 | 使用默认轮询，不考虑后端当前连接数，慢请求把某台机器压满 | 请求处理时间差异大的场景改用 `least_conn`（按当前连接数动态分配） | [01-导览](./01-Nginx反向代理与负载均衡-导览.md) |
