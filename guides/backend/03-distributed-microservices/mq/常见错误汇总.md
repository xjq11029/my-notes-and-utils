# 消息队列 - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件的避坑指南章节与题集解析中提取。

---

## Kafka

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 设置过大的 batch.size 导致消息延迟增加 | 消息在缓冲区等待凑批时间过长 | 建议 16KB-32KB，配合 linger.ms（5-10ms）控制最大等待时间 | [Kafka核心原理导览](./kafka/01-Kafka核心原理-导览.md) |
| Consumer 长时间阻塞被踢出消费组，触发 Rebalance | 处理消息超过 max.poll.interval.ms（默认 5 分钟） | 将慢处理消息转发到专用 Topic；使用线程池异步处理，主线程快速返回 | [Kafka核心原理导览](./kafka/01-Kafka核心原理-导览.md) |
| Partition 数量规划不当导致元数据开销大、故障恢复慢 | Partition 过多会增加元数据开销和恢复时间 | 每个 Broker 上 Partition 总数不超过 2000-4000；预留 20-30% 扩容余量 | [Kafka核心原理导览](./kafka/01-Kafka核心原理-导览.md) |
| 依赖全局消息顺序导致业务逻辑异常 | Kafka 只在单个 Partition 内保证消息顺序 | 设计为幂等处理，不依赖全局顺序；必要时使用单一 Partition（牺牲并行度） | [Kafka核心原理导览](./kafka/01-Kafka核心原理-导览.md) |
| 不监控消费 Lag 导致消费积压严重 | 消费能力不足时 Lag 持续增长，未及时发现 | 生产环境必须监控 Lag，设置告警阈值，及时扩容或优化 | [Kafka核心原理导览](./kafka/01-Kafka核心原理-导览.md) |
| Rebalance 频繁抖动导致消费反复暂停 | 消费者频繁上下线或网络抖动触发心跳超时（session.timeout.ms 默认 45s） | 调大 session.timeout.ms（30s）与 heartbeat.interval.ms（3s）；使用 Cooperative Sticky 分配策略与静态成员 group.instance.id | [Kafka笔面试题集导览](./kafka/Kafka笔面试题集-导览.md) |
| 自动提交位移导致消息被跳过或重复消费 | enable.auto.commit=true 按时间间隔提交，提交时机与业务处理完成无关 | 关闭自动提交（enable.auto.commit=false），处理成功后 commitSync；消费端实现业务幂等 | [Kafka笔面试题集导览](./kafka/Kafka笔面试题集-导览.md) |
| 试图减少 Topic 分区数导致操作失败 | Kafka 只支持增加分区，减少会改变消息归属、破坏分区内顺序与位移连续性 | 分区数只增不减，规划时预留 2-3 倍余量；确需减少只能新建 Topic 迁移数据 | [Kafka笔面试题集导览](./kafka/Kafka笔面试题集-导览.md) |
| 开启幂等生产者但未设置 acks=all 导致配置冲突 | enable.idempotence=true 要求 acks=all 且 retries>0，配置不匹配会报错 | 开启幂等的同时设置 acks=all、retries=Integer.MAX_VALUE、max.in.flight≤5 | [Kafka笔面试题集导览](./kafka/Kafka笔面试题集-导览.md) |
| 消费者实例数超过分区数导致部分消费者完全空闲 | 并行度上限等于分区数，多余消费者分配不到任何分区 | 消费者数不超过分区数；需要更高并行度时先扩容分区再扩容消费者 | [Kafka笔面试题集导览](./kafka/Kafka笔面试题集-导览.md) |
| 消息顺序错乱：依赖全局顺序或未开幂等且 max.in.flight>1 | Kafka 只保证单 Partition 内有序；重试在途请求可能导致分区内乱序 | 按业务 Key 哈希到同一分区；开启幂等且 max.in.flight.requests.per.connection≤5；设计为幂等消费不依赖全局顺序 | [Kafka笔面试题集导览](./kafka/Kafka笔面试题集-导览.md) |

## RabbitMQ

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 生产环境使用匿名队列导致消费者断开后消息丢失 | 匿名队列（autoDelete=true）在消费者断开后自动删除 | 使用命名持久化队列（durable=true） | [RabbitMQ核心原理导览](./rabbitmq/02-RabbitMQ核心原理-导览.md) |
| 消费端未实现幂等导致消息重复消费、业务数据出错 | RabbitMQ 的"至少一次"投递语义可能导致重复 | 使用唯一业务 ID 去重；数据库唯一约束；Redis 记录已处理消息 ID | [RabbitMQ核心原理导览](./rabbitmq/02-RabbitMQ核心原理-导览.md) |
| 设置过大的 Prefetch 导致消息在消费者端堆积 | 消费者一次拉取过多消息，未确认的消息需重新投递 | 设置较小的 prefetch（10-50），配合手动确认 | [RabbitMQ核心原理导览](./rabbitmq/02-RabbitMQ核心原理-导览.md) |
| 队列无限增长导致内存和磁盘耗尽 | 未设置队列长度限制或消息 TTL | 设置 x-max-length 限制队列最大长度；设置消息 TTL | [RabbitMQ核心原理导览](./rabbitmq/02-RabbitMQ核心原理-导览.md) |
| 过于复杂的路由拓扑导致运维困难 | 过多的 Exchange、Queue、Binding 增加复杂度 | 保持路由拓扑简洁，每个 Exchange 绑定不超过 10 个 Queue | [RabbitMQ核心原理导览](./rabbitmq/02-RabbitMQ核心原理-导览.md) |
| 未开启 Publisher Confirm 导致消息丢失无感知 | 默认不确认，Broker 未收到消息或消息无法路由时生产者完全无感知 | 开启 publisher-confirm-type=correlated 与 publisher-returns=true（配合 mandatory），未确认消息落库重发 | [RabbitMQ笔面试题集导览](./rabbitmq/RabbitMQ笔面试题集-导览.md) |
| 消费端使用 auto ack 导致处理失败时消息丢失 | 自动确认在消息投递后立即 ack，业务处理异常时消息已被删除 | 使用 acknowledge-mode=manual，处理成功后 basicAck，失败 basicNack 并按重试次数决定是否 requeue | [RabbitMQ笔面试题集导览](./rabbitmq/RabbitMQ笔面试题集-导览.md) |
| 消息级 TTL 造成延迟队列队头阻塞 | RabbitMQ 只检查队头消息是否过期，长 TTL 消息会阻塞后续短 TTL 消息 | 不同延迟档位使用独立队列（队列级 TTL 统一）；或改用 rabbitmq-delayed-message-exchange 插件 | [RabbitMQ笔面试题集导览](./rabbitmq/RabbitMQ笔面试题集-导览.md) |
| 死信队列无消费者导致死信无限堆积直至磁盘写满 | 只配置了死信交换机与死信队列，未部署死信消费者也未做堆积监控 | 死信队列必须有消费者并监控深度；解析 x-death 定位死信原因；死信处理失败也要 ack 避免死循环 | [RabbitMQ笔面试题集导览](./rabbitmq/RabbitMQ笔面试题集-导览.md) |
| 依赖镜像队列做高可用导致切换时丢消息 | 镜像队列无一致性协议保证，网络分区时可能出现脑裂并丢失数据 | 关键队列改用 Quorum Queue（Raft 多数派确认），集群节点数至少 3 且为奇数 | [RabbitMQ笔面试题集导览](./rabbitmq/RabbitMQ笔面试题集-导览.md) |
| basicNack requeue=true 导致失败消息死循环 | 消息处理必然失败却反复重新入队，消费者反复重试挤占有效吞吐 | 记录重试次数，达上限后 requeue=false 进入死信队列；同时设置重试间隔 | [RabbitMQ笔面试题集导览](./rabbitmq/RabbitMQ笔面试题集-导览.md) |

## RocketMQ

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| Consumer 消费失败后直接吞异常导致消息静默丢失 | 消费失败未返回 RECONSUME_LATER 或抛出异常，消息被标记为成功消费 | 消费失败时抛出异常或返回 RECONSUME_LATER 触发重试；异常需记录日志 | [RocketMQ核心原理导览](./rocketmq/01-RocketMQ核心原理-导览.md) |
| 同步发送 + 同步刷盘 + 同步复制全部开启导致吞吐量极低 | 三个同步操作串行叠加，每次发送需等待刷盘 + 复制完成 | 根据业务场景选择：金融场景用同步刷盘 + 同步复制；普通业务用异步刷盘 + 同步复制 | [RocketMQ核心原理导览](./rocketmq/01-RocketMQ核心原理-导览.md) |
| readQueueNums 设置过小导致消费积压、消费者扩容无效 | 消费者并行度上限等于 readQueueNums，消费者数量超过 readQueueNums 则多余消费者空闲 | 预估流量，readQueueNums 设置为消费者数量的 2-4 倍；预留扩容空间 | [RocketMQ核心原理导览](./rocketmq/01-RocketMQ核心原理-导览.md) |
| 生产环境使用默认消费重试 16 次导致故障消息阻塞消费队列 | 每次重试延迟递增，16 次需要约 2-3 小时才能进入死信队列 | 根据业务设置合理的重试次数（如 3-5 次），失败后快速进入死信队列人工处理 | [RocketMQ核心原理导览](./rocketmq/01-RocketMQ核心原理-导览.md) |
| NameServer 全部部署在同一台机器导致集群不可用 | NameServer 单点故障，Producer/Consumer 无法获取路由信息 | 至少部署 2 台 NameServer（推荐 3 台），分布在不同的物理机上 | [RocketMQ核心原理导览](./rocketmq/01-RocketMQ核心原理-导览.md) |
| 未设置消息 Key 或 Tag 导致消息无法按 Key 查询 | 生产消息时未设置 Key，无法通过 IndexFile 按 Key 检索消息 | 每条消息设置唯一的业务 Key（如订单号），设置合理的 Tag 进行分类 | [RocketMQ核心原理导览](./rocketmq/01-RocketMQ核心原理-导览.md) |
| 广播模式下未实现幂等导致消费者重启后重复消费 | 广播模式消费进度存储在 Consumer 本地，重启后从上次本地进度消费 | 消费者实现幂等逻辑（唯一业务 ID 去重）；消费前检查消息是否已处理 | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| 顺序消费时处理耗时过长导致消息积压、吞吐量极低 | ConsumeMode.ORDERLY 单线程消费，前一条消息处理慢会阻塞后续所有消息 | 将耗时操作异步化（如发送到线程池处理）；非关键逻辑拆分为普通消息消费 | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| 事务消息回查逻辑不完善导致半消息长时间未确认 | checkLocalTransaction 实现有 Bug，未能正确返回本地事务状态 | 回查逻辑必须幂等；根据数据库实际状态判断；添加日志记录每次回查结果 | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| 延迟消息等级选择不当导致消息延迟时间不符合预期 | 未理解延迟等级与延迟时间的对应关系 | 参考延迟等级表选择；如需自定义延迟时间，修改 Broker 的 messageDelayLevel 配置 | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| SQL 过滤条件和 Tag 同时使用导致消息未按预期过滤 | Tag 和 SQL 过滤是 AND 关系，同时设置时只有两者都满足的消息才会被消费 | 避免同时使用 Tag 和 SQL 过滤；优先使用 Tag 过滤（性能更好）；SQL 过滤用于复杂条件 | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| Dledger 节点数配置为偶数导致选举失败、集群不可用 | Raft 协议要求超过半数节点投票才能选出 Leader，偶数节点可能出现平票 | Dledger 节点数配置为奇数（推荐 3 个或 5 个） | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| 消息重复消费未做幂等导致业务数据重复 | RocketMQ 提供至少一次语义，消费重试与位点重置都会造成重复投递 | 以业务唯一 ID 去重（Redis 记录或数据库唯一索引），消费逻辑设计为幂等 | [RocketMQ笔面试题集导览](./rocketmq/RocketMQ笔面试题集-导览.md) |
| Broker 磁盘使用率超过阈值导致消息写入被拒 | 磁盘保护机制触发，使用率超过 diskMaxUsedSpaceRatio 时 Broker 拒绝写入 | 配置磁盘水位告警；及时清理过期 CommitLog 或扩容磁盘；合理设置文件保留时长 | [RocketMQ高级特性导览](./rocketmq/02-RocketMQ高级特性-导览.md) |
| 消费位点被重置导致大量消息重复消费 | 控制台误操作重置位点或按时间回溯，历史消息被重新投递 | 重置位点前评估影响并暂停生产；消费端保持幂等；对位点变更操作留审计记录 | [RocketMQ笔面试题集导览](./rocketmq/RocketMQ笔面试题集-导览.md) |
