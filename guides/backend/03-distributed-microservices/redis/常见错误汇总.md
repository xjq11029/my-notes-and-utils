# Redis - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 使用 KEYS * 查询导致 Redis 卡顿 | KEYS 是 O(N) 操作，遍历所有 key 进行模式匹配，阻塞主线程 | 使用 SCAN 渐进式遍历：`SCAN 0 MATCH user:* COUNT 100` | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 存储大 Key 导致网络阻塞、DEL 阻塞、主从复制延迟 | 单个 key 的 value 过大（String > 10KB，集合元素 > 10000） | 单个 key 的 value 控制在 10KB 以内；拆分大 Key；使用 UNLINK 异步删除 | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| RedisTemplate 默认 JDK 序列化导致 Redis 中查看乱码 | 默认使用 JdkSerializationRedisSerializer，不可读且体积大 | 配置 Jackson2JsonRedisSerializer 或 StringRedisSerializer | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| HGETALL/SMEMBERS/LRANGE 0 -1 等全量操作导致主线程阻塞 | 大集合全量返回，内存和网络开销大 | 使用 HSCAN/SSCAN/ZSCAN 渐进式遍历；List 分页获取 | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 热 Key 导致单节点 CPU 过载 | 频繁访问的 key 导致单节点成为瓶颈 | 本地缓存（Caffeine）+ 多副本分摊 | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 大量 key 同时过期导致瞬时卡顿 | Redis 惰性删除 + 定期删除，大量 key 同时过期集中处理 | 设置过期时间时加随机偏移量 | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 内存淘汰策略未配置导致 Redis OOM | 未设置 maxmemory 和淘汰策略 | 设置 maxmemory 并使用 allkeys-lru 或 volatile-lru | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 连接池耗尽导致高并发时获取连接失败 | Lettuce 连接池默认最大 8 个连接，高并发不足 | 高并发场景调大 max-active 和 max-idle | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 多条命令非原子执行导致并发下数据不一致 | 单条命令是原子的，多条命令组合不是 | 使用 Lua 脚本或 MULTI/EXEC 事务保证原子性 | [01-导览](./01-Redis核心数据结构与底层原理-导览.md) |
| 用 Redis 做消息队列导致消费者宕机后消息丢失 | Redis List/Pub/Sub 缺少 ACK 机制 | 简单场景使用 Redis Stream（5.0+）；复杂场景使用 Kafka/RabbitMQ | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 生产环境使用 KEYS/FLUSHALL/FLUSHDB 导致服务不可用 | KEYS 遍历所有 key 阻塞主线程；FLUSHALL 后果不可逆 | 使用 SCAN 渐进式遍历；通过 rename-command 禁用危险命令 | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 所有从节点挂到一个主节点导致复制风暴 | 单个主节点挂载过多从节点，主节点输出缓冲区压力大 | 使用树状复制结构分散压力 | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 集群模式下跨槽批量操作报错 CROSSSLOT | MGET/MSET/DEL 等要求所有 key 在同一槽 | 使用 Hash Tag：`order:{1001}:status` 确保同一槽 | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 误以为 Redis 事务支持回滚 | 运行时错误不触发回滚，其他命令继续执行 | 在开发阶段充分测试，避免运行时错误 | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 大 Key 和热 Key 未处理 | 大 Key 导致网络阻塞、主从复制延迟；热 Key 导致单节点 CPU 过载 | 拆分大 Key、UNLINK 异步删除；本地缓存 + 多副本分散热 Key | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 未配置 maxmemory 和淘汰策略导致 Redis 耗尽服务器内存 | 未设置内存上限和淘汰策略，触发 OOM Killer | 设置 `maxmemory 4gb` 和 `maxmemory-policy allkeys-lru` | [02-导览](./02-Redis高级特性与实战-导览.md) |
| 分布式锁直接用 DEL 解锁导致误删他人的锁 | 锁已过期被其他线程获取，直接 DEL 误删 | 使用 Lua 脚本先 GET 判断 value 再 DEL，保证原子性 | [03-导览](./03-Redis笔面试题集-导览.md) |
| 缓存穿透、击穿、雪崩概念混淆导致选错方案 | 对三种缓存失效问题的定义和解决方案理解不清 | 穿透用布隆过滤器+缓存空值；击穿用互斥锁+逻辑过期；雪崩用随机过期+集群高可用+限流降级 | [03-导览](./03-Redis笔面试题集-导览.md) |
