# Redis - 概念对比速查

---

### Redis vs Memcached

| 对比维度 | Redis | Memcached |
|---------|-------|-----------|
| 核心定位 | 多功能内存数据库，支持丰富数据结构与持久化 | 纯内存缓存，仅支持二进制 String |
| 数据结构 | String、Hash、List、Set、ZSet、Bitmap、HyperLogLog、GEO、Stream | 仅二进制 String |
| 持久化 | 支持 RDB 快照 + AOF 日志，数据可恢复 | 不支持持久化，进程重启数据丢失 |
| 集群 | 原生支持 Redis Cluster（16384 个槽位） | 需要客户端一致性哈希或第三方代理 |
| 线程模型 | 6.0 前单线程，6.0+ 引入多线程 I/O（命令执行仍单线程） | 多线程 |
| 内存管理 | 多种内存淘汰策略（LRU/LFU/TTL 等） | 仅 LRU 淘汰 |
| 适用场景 | 缓存、分布式锁、排行榜、消息队列、计数器、Session 共享 | 纯缓存场景 |
| 选择建议 | 现代项目首选，功能全面，生态丰富 | 仅适合极简纯缓存且无需持久化的场景 |

### RDB vs AOF

| 对比维度 | RDB | AOF |
|---------|-----|-----|
| 核心定位 | 定时全量快照持久化，生成二进制文件 | 追加写命令日志持久化，以文本记录 |
| 文件大小 | 小（二进制压缩） | 大（文本命令，可重写精简） |
| 恢复速度 | 快（直接加载到内存） | 慢（需逐条回放命令） |
| 数据安全性 | 较低（可能丢失最后一次快照后数据） | 较高（everysec 最多丢 1 秒） |
| 性能影响 | fork() 时可能阻塞，COW 触发内存翻倍 | 取决于写入策略，always 影响最大 |
| 可读性 | 二进制，不可读 | 文本格式，可读可编辑 |
| 触发方式 | 手动 SAVE/BGSAVE；自动按 save 规则触发 | 实时追加写入 |
| 选择建议 | 适合冷备份和灾难恢复；对数据丢失容忍度较高时选用 | 适合数据安全性要求高的场景；生产环境推荐 RDB + AOF 混合持久化 |

### 缓存穿透 vs 缓存击穿 vs 缓存雪崩

| 对比维度 | 缓存穿透 | 缓存击穿 | 缓存雪崩 |
|---------|---------|---------|---------|
| 核心定位 | 查询不存在的数据，缓存和数据库都查不到 | 热点 key 过期瞬间，大量并发请求打到数据库 | 大量 key 同时过期或 Redis 集群宕机 |
| 触发条件 | 恶意构造大量不存在的 key / 查询不存在的数据 | 某个热点 key 过期且大量并发请求该 key | 大量 key 设置了相同过期时间 / Redis 集群故障 |
| 影响范围 | 每次请求都穿透缓存直达数据库 | 热点 key 对应的全部并发请求打到数据库 | 大量请求全部打到数据库，可能压垮数据库 |
| 核心方案 | 布隆过滤器前置拦截 + 缓存空值（短过期时间） | 互斥锁（SETNX）串行重建缓存 + 逻辑过期返回旧值 | 过期时间加随机值打散 + 集群高可用 + 限流降级 |
| 辅助方案 | 参数校验过滤非法请求 | 双重检查、异步更新 | 主从+哨兵自动故障转移 |
| 方案复杂度 | 中等（需引入布隆过滤器） | 中等（需实现互斥锁逻辑） | 较低（配置调整为主） |
