# LangChain与RAG - 概念对比速查

---

### LangChain vs LlamaIndex

| 对比维度 | LangChain | LlamaIndex |
|---------|-----------|------------|
| 核心定位 | 通用LLM应用开发框架，覆盖Chain、Agent、Tool、Memory全链路 | 专注于数据索引与检索的LLM框架，以RAG为核心 |
| 适用场景 | 复杂Agent、多步推理、工具调用、多模态应用、对话系统 | 文档问答、知识库搜索、数据摘要、结构化数据查询 |
| 性能特点 | 组件丰富但抽象层多，学习曲线陡峭，适合需要灵活编排的场景 | 索引结构优化好（支持多种索引类型），RAG场景上手快 |
| 生态集成 | 支持多种LLM、向量数据库、工具；LangSmith追踪；LangGraph状态图 | 内置多种数据连接器（PDF、SQL、API）；支持LangChain集成 |
| 选择建议 | 需要构建复杂Agent或多工具编排的应用 | 主要做文档问答或知识库检索，追求快速搭建RAG |

### RAG vs 微调

| 对比维度 | RAG（检索增强生成） | 微调（Fine-tuning） |
|---------|-------------------|---------------------|
| 核心定位 | 不修改模型参数，通过外部知识库检索增强生成 | 在预训练模型基础上用领域数据修改模型参数 |
| 适用场景 | 知识频繁更新、需要可溯源、多领域知识问答 | 学习特定风格/格式、注入领域知识、纠正模型行为 |
| 性能特点 | 知识更新即时（改库即可），可解释性强（可溯源），但检索延迟额外开销 | 推理时无额外延迟，但知识更新需重新训练 |
| 数据需求 | 需要构建和维护知识库文档，文档质量决定效果 | 需要高质量标注数据，数据量通常需数千条以上 |
| 选择建议 | 知识库内容频繁变化、需要引用来源、快速上线 | 需要改变模型行为风格、领域知识固定、追求推理速度 |

### Chroma vs Pinecone vs Milvus

| 对比维度 | Chroma | Pinecone | Milvus |
|---------|--------|----------|--------|
| 核心定位 | 轻量级开源向量数据库，适合原型开发和本地部署 | 全托管云原生向量数据库，零运维 | 高性能开源向量数据库，适合大规模生产环境 |
| 适用场景 | 原型验证、小规模项目、本地开发、嵌入应用 | 中小规模生产、快速上线、不想管理基础设施 | 大规模生产（亿级向量）、高性能检索、需自建或私有部署 |
| 性能特点 | 本地部署延迟低，但扩展性有限，不支持分布式 | 自动扩展，高可用，但成本随规模增长 | 支持多种索引（IVF/HNSW/DiskANN），GPU加速，分布式架构 |
| 部署方式 | pip安装，嵌入式运行，Python/JS双SDK | SaaS托管，无需运维 | Docker/K8s自建，支持云原生部署 |
| 选择建议 | 开发阶段快速验证RAG方案 | 快速上线无需运维，中小规模生产 | 大规模生产环境，需要高性能和私有化部署 |
