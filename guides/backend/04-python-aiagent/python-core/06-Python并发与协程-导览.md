## 一、并发、并行与异步：先把概念摆正

### 1.1 三个概念的分界
| 维度 | 内容 |
|------|------|
| 是什么 | 并发、并行、异步三个常被混用的概念及其边界。 |
| 能做什么 | 判断任务结构、是否需要多核、等待如何管理；避免选型靠感觉。 |
| 怎么用 | 并发用线程/协程；并行用多进程；异步用 asyncio、回调或事件驱动。 |
| 原理和工作流程 | 并发是重叠时间段内推进，并行是同一时刻执行，异步是等待时让出执行者；单核可并发不可并行，单线程可异步。 |
| 缺点 | 概念混用会导致“用了线程就以为并行”；异步也不等于多线程。 |
### 1.2 任务画像与 Python 工具箱
| 维度 | 内容 |
|------|------|
| 是什么 | CPU 密集、IO 密集、混合型任务与 threading、multiprocessing、asyncio 三套工具。 |
| 能做什么 | 先判断瓶颈再选工具；按边界组合多种模型。 |
| 怎么用 | CPU 密集选进程或 C 扩展；阻塞 IO 选线程；海量网络 IO 选 asyncio。 |
| 原理和工作流程 | 线程共享内存但受 GIL；进程独立内存与 GIL；协程单线程协作调度，切换成本低。 |
| 缺点 | 混合型任务需要拆分；没有一种工具能同时最优解决计算与等待。 |

## 二、GIL：CPython 的全局解释器锁

### 2.1 GIL 锁住了什么
| 维度 | 内容 |
|------|------|
| 是什么 | CPython 中保证同一时刻只有一个线程执行 Python 字节码的全局互斥锁。 |
| 能做什么 | 解释多线程为何不能并行计算；判断何时会释放 GIL。 |
| 怎么用 | `sys.getswitchinterval()` 查看切换间隔；阻塞 IO 与部分 C 扩展会自动释放。 |
| 原理和工作流程 | 为引用计数内存管理与 C 扩展简单性而设；线程是真实 OS 线程，由系统抢占调度，GIL 只互斥字节码。 |
| 缺点 | CPU 密集多线程无法利用多核；GIL 不保证复合操作原子；是 CPython 实现细节。 |
### 2.2 GIL 下的 CPU 与 IO 任务
| 维度 | 内容 |
|------|------|
| 是什么 | CPU 密集与 IO 密集任务在 GIL 下的不同表现。 |
| 能做什么 | 判断该用线程还是进程；识别 C 扩展释放 GIL 的收益。 |
| 怎么用 | 用顺序/多线程对比脚手架实测；CPU 任务换多进程，IO 任务用线程或协程。 |
| 原理和工作流程 | CPU 任务持续占用字节码执行权；IO 阻塞时释放 GIL，其他线程可继续；线程切换有成本。 |
| 缺点 | 具体收益受实现与负载影响；不能把“IO 会释放 GIL”套到所有扩展上。 |
### 2.3 绕过 GIL 的路径
| 维度 | 内容 |
|------|------|
| 是什么 | 多进程、C/C++ 扩展、向量化库、free-threaded 构建等绕过 GIL 的方式。 |
| 能做什么 | 实现 CPU 真并行；按成本与兼容性选择路径。 |
| 怎么用 | `multiprocessing`；NumPy 等释放 GIL 的库；free-threaded 构建（3.13 起提供，初期实验性）。 |
| 原理和工作流程 | 每进程独立解释器与 GIL；原生代码可主动释放 GIL；无 GIL 构建移除全局锁但需生态适配。 |
| 缺点 | 多进程有启动与序列化开销；C 扩展开发成本高；无 GIL 构建仍是可选项。 |

## 三、threading：线程、锁与队列

### 3.1 创建、等待与守护线程
| 维度 | 内容 |
|------|------|
| 是什么 | `threading.Thread` 的创建、`start`、`join` 与守护线程机制。 |
| 能做什么 | 并发执行阻塞任务；等待线程结束；设置后台线程。 |
| 怎么用 | `Thread(target=worker, args=("A", 0.05))`；`start()`；`join(timeout)`；`daemon=True`。 |
| 原理和工作流程 | `start()` 创建 OS 线程并调度；`join()` 阻塞等待；守护线程随主线程退出被强制结束；线程异常不自动传播。 |
| 缺点 | 守护线程不保证清理；线程异常易丢失；线程创建与栈内存开销高于协程。 |
### 3.2 竞态、Lock 与死锁
| 维度 | 内容 |
|------|------|
| 是什么 | 共享可变状态下的竞态条件、互斥锁与死锁问题。 |
| 能做什么 | 保护读改写；识别并避免死锁；选择 `Lock` 或 `RLock`。 |
| 怎么用 | `with lock:` 包住临界区；递归加锁用 `RLock`；统一锁顺序；`acquire(timeout=1.0)`。 |
| 原理和工作流程 | `counter += 1` 由多条字节码组成，切换可能丢更新；死锁需同时满足互斥、持有并等待、不可抢占、循环等待。 |
| 缺点 | 锁粒度过大降低并发；嵌套锁易死锁；`RLock` 释放次数不匹配会长期占用。 |
### 3.3 Condition、Event 与 Semaphore
| 维度 | 内容 |
|------|------|
| 是什么 | 线程间等待/通知、事件标志、计数信号量与屏障等同步原语。 |
| 能做什么 | 有界缓冲区等待；优雅停机；限制并发访问；分阶段同步。 |
| 怎么用 | `Condition.wait/notify`；`Event.set/wait`；`Semaphore.acquire/release`；`Barrier.wait`。 |
| 原理和工作流程 | 条件变量在等待时释放锁、唤醒后重新获取；Event 维护布尔标志；Semaphore 维护许可计数。 |
| 缺点 | 虚假唤醒需用 `wait_for`；忘记 `notify` 会永久等待；信号量许可泄漏会耗尽并发额度。 |
### 3.4 queue.Queue 与线程池
| 维度 | 内容 |
|------|------|
| 是什么 | 线程安全队列与 `ThreadPoolExecutor` 线程池。 |
| 能做什么 | 生产者-消费者解耦；有界缓冲；批量提交任务并收集结果。 |
| 怎么用 | `Queue(maxsize)`、`put/get`、`task_done/join`；`submit`、`as_completed`。 |
| 原理和工作流程 | 队列内置锁与条件变量，满时阻塞生产者；线程池复用固定数量线程，Future 承载结果。 |
| 缺点 | 无界队列会 OOM；哨兵遗漏导致消费者不退出；线程池不能绕过 GIL。 |

## 四、multiprocessing：绕开 GIL 的真并行

### 4.1 进程模型与启动方式
| 维度 | 内容 |
|------|------|
| 是什么 | 独立内存与独立 GIL 的多进程模型，以及 spawn、fork、forkserver 三种启动方式。 |
| 能做什么 | CPU 密集真并行；故障隔离；跨平台进程管理。 |
| 怎么用 | `get_context("spawn")` 显式指定；`Process`、`Pool`、`Queue`。 |
| 原理和工作流程 | 每个进程独立解释器；spawn 启动新解释器并导入主模块，fork 复制父进程，forkserver 从服务器进程派生。 |
| 缺点 | 启动慢、内存翻倍、序列化开销；fork 在多线程下不安全；跨平台默认值不同。 |
### 4.2 Windows spawn 的三条硬规则
| 维度 | 内容 |
|------|------|
| 是什么 | Windows 只能 spawn 带来的入口保护、可 pickle、无共享全局三条约束。 |
| 能做什么 | 避免递归创建进程；避免序列化错误；写出跨平台可用的多进程代码。 |
| 怎么用 | 入口放 `if __name__ == "__main__":`；传顶层函数与可 pickle 参数；不依赖模块级状态。 |
| 原理和工作流程 | 子进程重新导入主模块，模块顶层代码会再次执行；lambda、局部函数、不可 pickle 对象无法传输。 |
| 缺点 | 启动比 fork 慢；交互式环境与 Notebook 中调试困难；全局状态需显式传递。 |
### 4.3 进程间通信与共享状态
| 维度 | 内容 |
|------|------|
| 是什么 | Queue、Pipe、Manager、Value/Array、shared_memory 等进程间数据通道。 |
| 能做什么 | 传递任务与结果；共享配置；大数组零拷贝；简单计数。 |
| 怎么用 | `Queue.put/get`；`Pipe` 两端收发；`Manager().dict()`；`shared_memory.SharedMemory`。 |
| 原理和工作流程 | 数据 pickle 后经管道传输；Manager 通过代理进程访问；共享内存映射同一块物理内存。 |
| 缺点 | 序列化有开销；Manager 代理慢；共享内存需手动同步与清理。 |
### 4.4 进程池的边界
| 维度 | 内容 |
|------|------|
| 是什么 | `Pool` 与 `ProcessPoolExecutor` 的任务分发、结果收集与资源边界。 |
| 能做什么 | 批量并行；惰性 `imap`；异步结果；统一执行器接口。 |
| 怎么用 | `pool.map`、`imap`、`apply_async`；上下文管理器；`ProcessPoolExecutor.submit`。 |
| 原理和工作流程 | 主进程维护任务队列，工作进程取任务、执行、回传结果；异常与返回值都要可 pickle。 |
| 缺点 | 守护进程不能开子进程；池嵌套易死锁；小任务不划算；Ctrl-C 清理麻烦。 |

## 五、concurrent.futures：统一的执行器抽象

### 5.1 Executor 与 Future
| 维度 | 内容 |
|------|------|
| 是什么 | 线程池与进程池共享的 Executor 接口，以及 Future 结果占位对象。 |
| 能做什么 | 提交任务；等待结果；获取异常；注册完成回调。 |
| 怎么用 | `submit(fn, *args)`；`result()`、`exception()`、`done()`、`cancel()`、`add_done_callback`。 |
| 原理和工作流程 | Future 维护 pending/running/finished 状态；任务在线程或进程中执行，完成后设置结果或异常。 |
| 缺点 | 不读 `result()` 会丢异常；`cancel()` 只能取消未开始任务；不能与 asyncio.Future 混用。 |
### 5.2 map、as_completed 与取消
| 维度 | 内容 |
|------|------|
| 是什么 | 批量提交、按完成顺序消费、条件等待与取消的接口。 |
| 能做什么 | 保持结果顺序；按进度处理；控制超时与退出；取消排队任务。 |
| 怎么用 | `map`；`as_completed`；`wait(fs, return_when=FIRST_COMPLETED)`；`cancel()`；`shutdown(cancel_futures=True)`。 |
| 原理和工作流程 | `map` 立即提交全部任务并按输入顺序产出；`as_completed` 完成一个产出一个；`wait` 返回 done/not_done 集合。 |
| 缺点 | `map` 的异常延迟到迭代时；运行中任务不可取消；进程硬终止会丢清理逻辑。 |

## 六、asyncio：事件循环与协程

### 6.1 事件循环与协程
| 维度 | 内容 |
|------|------|
| 是什么 | 单线程事件循环调度协程的异步模型。 |
| 能做什么 | 高并发 IO；等待时切换任务；流式处理。 |
| 怎么用 | `async def` 定义协程；`await` 驱动；`asyncio.run(main())` 启动。 |
| 原理和工作流程 | 循环维护就绪回调、定时器和 IO 事件；协程在 `await` 处让出，循环调度其他就绪任务；协作式、无抢占。 |
| 缺点 | 任何阻塞调用都会卡死整个循环；协程调用只创建对象，不会自动执行。 |
### 6.2 Task、gather 与结构化并发
| 维度 | 内容 |
|------|------|
| 是什么 | Task 调度包装、gather/wait/as_completed 聚合，以及 3.11+ TaskGroup。 |
| 能做什么 | 并发运行协程；按顺序或完成顺序收集结果；失败时取消兄弟任务。 |
| 怎么用 | `create_task`；`gather(*aws, return_exceptions=True)`；`TaskGroup` + `create_task`。 |
| 原理和工作流程 | Task 把协程注册到循环；gather 按输入顺序返回结果；TaskGroup 在任一任务失败时取消同组任务并抛 ExceptionGroup。 |
| 缺点 | `create_task` 只有弱引用；gather 默认不取消其余任务；TaskGroup 需要 3.11+。 |
### 6.3 超时、取消与清理
| 维度 | 内容 |
|------|------|
| 是什么 | `wait_for`、`asyncio.timeout`、`Task.cancel` 与取消清理机制。 |
| 能做什么 | 限制等待时间；主动取消；释放连接与锁；防止任务泄漏。 |
| 怎么用 | `await wait_for(coro, timeout)`；`async with asyncio.timeout(5)`；`task.cancel()`；`finally` 清理后重抛。 |
| 原理和工作流程 | 取消在下一次 `await` 注入 `CancelledError`；`wait_for` 超时会取消内部任务并等待；`timeout` 把取消转换为 `TimeoutError`。 |
| 缺点 | 吞掉取消会破坏上层等待；阻塞清理会卡循环；`asyncio.timeout` 需 3.11+。 |
### 6.4 同步与异步的边界
| 维度 | 内容 |
|------|------|
| 是什么 | 在异步代码中调用同步函数、在同步代码中调用异步函数的桥接方式。 |
| 能做什么 | 复用阻塞 SDK；保护事件循环；在脚本入口运行协程。 |
| 怎么用 | `asyncio.to_thread`；`loop.run_in_executor`；`asyncio.run`；`run_coroutine_threadsafe`。 |
| 原理和工作流程 | 阻塞函数被提交到线程池或进程池执行；`to_thread` 会传播 contextvars；事件循环线程只负责调度。 |
| 缺点 | 线程池有上限；进程池要求可 pickle；嵌套 `asyncio.run` 会报错。 |

## 七、异步限流、队列与背压

### 7.1 Semaphore 与 Queue
| 维度 | 内容 |
|------|------|
| 是什么 | asyncio 的信号量与异步队列。 |
| 能做什么 | 限制在途请求数；生产者-消费者解耦；有界缓冲。 |
| 怎么用 | `async with sem:`；`asyncio.Queue(maxsize=8)`；`await put/get`；`task_done/join`。 |
| 原理和工作流程 | 信号量维护许可计数，超出则等待；队列满时 `put` 等待，空时 `get` 等待；队列本身提供背压。 |
| 缺点 | asyncio 原语不是线程安全的；无界队列会 OOM；多消费者需各自哨兵。 |
### 7.2 背压与生产者-消费者
| 维度 | 内容 |
|------|------|
| 是什么 | 让生产速度受消费速度约束的机制。 |
| 能做什么 | 防止内存暴涨；保护下游；平滑流量峰值。 |
| 怎么用 | 有界队列、信号量、拉式异步生成器。 |
| 原理和工作流程 | 队列满时生产者阻塞；许可耗尽时新任务等待；生成器只在消费者请求时生产。 |
| 缺点 | 背压会降低吞吐；取消时可能留下队列残留；设计不当会互相等待。 |

## 八、异步 LLM 调用与流式输出

### 8.1 并发调用与限流
| 维度 | 内容 |
|------|------|
| 是什么 | 用 asyncio 并发调用 LLM，并用信号量、超时、重试控制风险。 |
| 能做什么 | 并行请求多个模型或工具；限制在途数；失败重试；成本与延迟观测。 |
| 怎么用 | `FakeLLM.complete` + `Semaphore` + `gather`；指数退避加抖动；只重试幂等请求。 |
| 原理和工作流程 | 网络等待时协程让出，循环调度其他请求；信号量限制在途；超时取消慢请求。 |
| 缺点 | 限流不当会触发上游 429；重试风暴会放大故障；超时设置需区分单次与整体。 |
### 8.2 流式输出与工具调用
| 维度 | 内容 |
|------|------|
| 是什么 | 异步生成器消费 token 流，并处理工具调用参数分片。 |
| 能做什么 | 实时展示；累积完整回答；解析工具调用；客户端断开时清理。 |
| 怎么用 | `async for token in stream`；边 yield 边 append；拼接 `arguments` 后统一 `json.loads`。 |
| 原理和工作流程 | 异步生成器按需产出，天然拉式背压；SSE 逐行到达；工具参数 JSON 分片到达，流结束才完整。 |
| 缺点 | 分片解析会失败；有依赖的工具必须串行；断开不清理会泄漏连接。 |

## 九、FastAPI 边界：别让阻塞调用卡死事件循环

### 9.1 async def 与 def 的执行位置
| 维度 | 内容 |
|------|------|
| 是什么 | FastAPI 中异步路由与同步路由的不同执行位置。 |
| 能做什么 | 判断阻塞风险；决定写 `async def` 还是 `def`。 |
| 怎么用 | `async def` + 异步客户端；`def` 交给线程池；依赖项同样遵循规则。 |
| 原理和工作流程 | `async def` 在事件循环线程执行；`def` 被 Starlette 放到线程池；事件循环单线程，阻塞会停住所有请求。 |
| 缺点 | `async def` 里阻塞会拖垮整个 worker；`def` 受线程池大小限制。 |
### 9.2 阻塞调用的正确下沉
| 维度 | 内容 |
|------|------|
| 是什么 | 把同步阻塞调用转移到线程池或进程池，保护事件循环。 |
| 能做什么 | 复用同步 SDK；处理文件 IO；执行 CPU 密集计算。 |
| 怎么用 | `await asyncio.to_thread(fn, arg)`；`loop.run_in_executor(pool, fn, arg)`；优先改异步库。 |
| 原理和工作流程 | 阻塞函数在另一个线程或进程运行，事件循环继续调度；进程池要求函数与参数可 pickle。 |
| 缺点 | 线程池有上限；进程池启动与序列化开销大；Windows 需 `__main__` 保护。 |
### 9.3 流式响应与生命周期
| 维度 | 内容 |
|------|------|
| 是什么 | `StreamingResponse` + 异步生成器、`lifespan` 与 `BackgroundTasks` 的边界。 |
| 能做什么 | SSE 流式输出；客户端断开清理；复用连接池；响应后小任务。 |
| 怎么用 | `StreamingResponse(event_stream(), media_type="text/event-stream")`；`lifespan` 初始化客户端；`BackgroundTasks` 只做短任务。 |
| 原理和工作流程 | Starlette 在断开时取消流式任务；`lifespan` 管理应用级资源；后台任务在响应后执行；多 worker 是多个进程。 |
| 缺点 | 长任务不适合 BackgroundTasks；断开清理需自己写；多 worker 限流是各自独立的。 |

## 十、选型表：到底该用哪一种

### 10.1 按任务与约束选型
| 维度 | 内容 |
|------|------|
| 是什么 | 按 IO/CPU、共享状态、隔离性、平台约束选择并发模型的决策表。 |
| 能做什么 | 快速选型；识别备选方案；按下游容量规划并发度。 |
| 怎么用 | 大量 HTTP/LLM 选 asyncio；阻塞 SDK 选线程池；CPU 密集选多进程；简单批量用 futures。 |
| 原理和工作流程 | 工具特性与瓶颈匹配：协程省切换、线程扛阻塞、进程绕 GIL；共享状态与隔离性决定边界。 |
| 缺点 | 表格简化了现实；混合系统需要拆分；最终要压测验证。 |
### 10.2 混合架构与反模式
| 维度 | 内容 |
|------|------|
| 是什么 | async 外层 + 线程/进程内层的混合架构，以及常见反模式。 |
| 能做什么 | 设计分层并发；识别线程每请求、进程每小任务、无界队列等坏味道。 |
| 怎么用 | FastAPI + 异步客户端 + `to_thread` + 进程池；所有队列有界、所有调用有超时。 |
| 原理和工作流程 | 外层用事件循环接高并发 IO，内层用线程池承接阻塞库、进程池承接 CPU 计算，边界清晰。 |
| 缺点 | 架构复杂度上升；跨层取消与超时难统一；资源池可能互相争抢。 |

## 十一、常见坑

### 11.1 死锁与竞态
| 维度 | 内容 |
|------|------|
| 是什么 | 锁顺序不一致导致的死锁，以及 check-then-act、非原子累加导致的竞态。 |
| 能做什么 | 识别永久等待与丢更新；设计无死锁的加锁策略。 |
| 怎么用 | 统一锁顺序；`acquire(timeout=...)`；用锁包住判断与写入；必要时用原子结构。 |
| 原理和工作流程 | 死锁需四个条件同时成立；竞态源于读改写之间被切换；GIL 不保证复合操作原子。 |
| 缺点 | 死锁难复现；锁粒度过大降低吞吐；超时重试可能引入活锁。 |
### 11.2 事件循环阻塞与任务丢失
| 维度 | 内容 |
|------|------|
| 是什么 | 阻塞调用卡住事件循环，以及 `create_task` 弱引用导致任务被回收。 |
| 能做什么 | 诊断“所有请求一起变慢”；保证后台任务存活与异常可见。 |
| 怎么用 | 用 `to_thread` 下沉阻塞；保存 Task 强引用；`add_done_callback` 记录异常；用 TaskGroup 管理。 |
| 原理和工作流程 | 事件循环单线程，阻塞调用不让出；循环只弱引用 Task；未取回的异常可能静默丢失。 |
| 缺点 | 症状隐蔽、日志少；强引用集合需清理，否则内存泄漏。 |
### 11.3 取消、进程与线程池陷阱
| 维度 | 内容 |
|------|------|
| 是什么 | 取消信号被吞、Windows 多进程缺 guard、池嵌套、Future 异常丢失等工程陷阱。 |
| 能做什么 | 保证取消可传播；避免递归进程与池死锁；让异常可观测。 |
| 怎么用 | 清理后重抛 `CancelledError`；入口加 guard；扁平化任务；读取 `result()` 或加回调。 |
| 原理和工作流程 | 取消通过异常传播；spawn 重新导入主模块；池是有限资源；Future 异常需主动取回。 |
| 缺点 | 容易漏写；不同 Python 版本行为有差异；线程无法安全强杀。 |
