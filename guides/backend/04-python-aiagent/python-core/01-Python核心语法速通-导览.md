## 一、与Java对比概览

### 1.1 解释型 vs 编译型

| 维度 | 内容 |
|------|------|
| 是什么 | 对比Python解释执行与Java编译执行两种语言运行模式的差异。 |
| 能做什么 | 衡量启动速度与运行性能差异；区分开发流程；指导选型与性能优化方向。 |
| 怎么用 | `python script.py` 直接运行；Java需 `javac` 编译后 `java` 运行。 |
| 原理和工作流程 | Java源码编译为字节码由JVM运行，启动快、性能高；Python解释器逐行解析执行字节码，启动较慢、运行性能适中，生产环境可用Cython、PyPy等编译手段优化。 |
| 缺点 | Python解释执行致启动慢、运行性能不及JVM；CPU密集计算还受GIL进一步制约。 |

---

### 1.2 动态 vs 静态类型

| 维度 | 内容 |
|------|------|
| 是什么 | 对比Python运行时推断类型与Java编译期声明类型的类型系统差异。 |
| 能做什么 | 决定是否需显式声明类型；影响代码简洁度与重构安全性；指导是否引入类型注解。 |
| 怎么用 | `name = "张三"` 自动推断；`name: str = "张三"` 类型注解。 |
| 原理和工作流程 | Java在编译期确定变量类型，类型不匹配编译报错，IDE重构可靠；Python解释器运行时绑定类型，变量可随时指向不同类型对象，大型项目需mypy等工具做静态检查。 |
| 缺点 | 动态类型削弱IDE补全与重构安全性，运行时类型错误难以提前发现，大型项目必须依赖类型注解与静态检查工具。 |

---

### 1.3 缩进 vs 花括号

| 维度 | 内容 |
|------|------|
| 是什么 | 对比Python以缩进表示代码块与Java以花括号界定代码块的语法差异。 |
| 能做什么 | 统一代码格式；减少语法噪音；强制规范缩进风格。 |
| 怎么用 | `if x > 0:\n    print(x)` 缩进4空格表示块。 |
| 原理和工作流程 | Python词法分析器将相同缩进层次的语句归为同一块，缩进不一致触发IndentationError；Java用花括号显式界定作用域，缩进仅为可读性约定。 |
| 缺点 | 缩进错误即语法错误，混用空格与Tab易出错；复制粘贴代码常破坏缩进导致运行失败。 |

---

### 1.4 pip vs Maven/Gradle

| 维度 | 内容 |
|------|------|
| 是什么 | 对比Python的pip包管理器与Java的Maven/Gradle构建工具。 |
| 能做什么 | 安装依赖；管理依赖文件；查询已装包；构建发布产物。 |
| 怎么用 | `pip install pkg`；依赖写入 `requirements.txt`。 |
| 原理和工作流程 | pip从PyPI下载包到site-packages，无生命周期管理；Maven/Gradle基于pom.xml/build.gradle解析依赖树、执行编译打包测试等生命周期阶段，本地仓库缓存于~/.m2。 |
| 缺点 | pip依赖解析较弱易产生版本冲突；缺乏标准化的构建生命周期与锁文件机制，需pip-tools、poetry补充。 |

## 二、基础语法

### 2.1 变量定义

| 维度 | 内容 |
|------|------|
| 是什么 | Python无需声明类型、直接赋值即创建变量的绑定方式。 |
| 能做什么 | 单变量赋值；多重赋值；元组解包赋值；运行时改变绑定类型。 |
| 怎么用 | `a = b = c = 10`；`x, y, z = 1, 2, 3`。 |
| 原理和工作流程 | 赋值时解释器创建对象并在命名空间建立名字到对象的引用，变量本质是引用而非内存盒子；多重赋值先在右侧构建元组再逐个绑定到左侧名字。 |
| 缺点 | 无类型声明降低可读性与安全性；可变对象作为默认值或共享引用时易产生意外副作用。 |

---

### 2.2 基本数据类型

| 维度 | 内容 |
|------|------|
| 是什么 | Python内置的int、float、bool、str、None等基础类型集合。 |
| 能做什么 | 表示整数、浮点、布尔、字符串、空值；支持任意精度整数运算。 |
| 怎么用 | `age = 25`；`is_ok = True`；`name = None`。 |
| 原理和工作流程 | int为任意精度对象无溢出；bool首字母大写且是int子类（True==1）；None为单例空值对象；str为不可变Unicode序列。对应Java的int/long、boolean、String、null。 |
| 缺点 | 任意精度int运算慢于原生整型；bool继承int易引发隐式数值比较bug；None与空容器判断需显式区分。 |

---

### 2.3 List（列表）

| 维度 | 内容 |
|------|------|
| 是什么 | Python内置有序可变序列，对应Java的ArrayList。 |
| 能做什么 | 随机访问；增删元素；切片；存放异构类型；成员判断。 |
| 怎么用 | `nums = [1,2,3]`；`nums.append(6)`；`nums[1:3]`。 |
| 原理和工作流程 | 底层为指向PyObject指针的动态数组，超容量按策略扩容复制；支持负索引与切片生成新列表；in操作为线性扫描。 |
| 缺点 | 头部插入删除O(n)性能差；存放异构类型失去类型安全；大量数据内存占用高于原生数组。 |

---

### 2.4 Tuple（元组）

| 维度 | 内容 |
|------|------|
| 是什么 | Python内置有序不可变序列，相当于不可变List。 |
| 能做什么 | 存储固定序列；解包赋值；作为字典key与集合元素；函数返回多值。 |
| 怎么用 | `coord = (10, 20)`；`x, y = coord`。 |
| 原理和工作流程 | 底层为不可变指针数组，创建后长度与元素引用不可变；因不可变可哈希，故可作为dict的key；括号可省略，解包按位置绑定。 |
| 缺点 | 不可变无法修改元素；单元素需写 `(x,)` 易遗漏逗号；方法丰富度不及list。 |

---

### 2.5 Dict（字典）

| 维度 | 内容 |
|------|------|
| 是什么 | Python内置键值对映射，对应Java的HashMap。 |
| 能做什么 | 按key存取；增删改；遍历键值；默认值获取；成员判断。 |
| 怎么用 | `p = {"name":"Alice"}`；`p.get("age", 0)`。 |
| 原理和工作流程 | 3.7+为插入有序，底层开放寻址哈希表，冲突时按探测序列查找，负载因子超阈值扩容rehash；key必须可哈希。 |
| 缺点 | key必须可哈希，list/dict不能作key；内存开销大于列表；旧版本无序行为不一致。 |

---

### 2.6 Set（集合）

| 维度 | 内容 |
|------|------|
| 是什么 | Python内置无序不重复元素集合，对应Java的HashSet。 |
| 能做什么 | 去重；交并差集运算；成员判断；增删元素。 |
| 怎么用 | `s = {1,2,3}`；`a & b` 交集；`a | b` 并集。 |
| 原理和工作流程 | 底层哈希表仅存key无value，借助哈希实现O(1)平均查找与去重；元素必须可哈希；空集合必须用set()而非{}。 |
| 缺点 | 元素必须可哈希且不可变；无序无法按索引访问；内存开销高于列表。 |

---

### 2.7 列表推导式 Python特色

| 维度 | 内容 |
|------|------|
| 是什么 | 用单行表达式从可迭代对象生成列表的语法构造。 |
| 能做什么 | 映射变换；条件过滤；嵌套循环；生成字典与集合推导式。 |
| 怎么用 | `[n*n for n in nums if n%2==0]`。 |
| 原理和工作流程 | 解释器将推导式编译为等价循环并在独立作用域执行，结果一次性构建为新列表；比显式for循环加append减少字节码指令与函数调用开销。 |
| 缺点 | 复杂嵌套可读性差；生成全量列表占内存，大数据应改用生成器表达式。 |

## 三、函数与模块

### 3.1 函数定义 - def

| 维度 | 内容 |
|------|------|
| 是什么 | Python用def关键字定义函数并支持默认参数的机制。 |
| 能做什么 | 封装逻辑；接收参数返回值；设置默认参数；f-string格式化返回。 |
| 怎么用 | `def add(a, b): return a + b`；`def greet(name, greeting="Hello"):`。 |
| 原理和工作流程 | def在执行时创建函数对象并绑定到名字，默认参数在函数定义时求值并存储于__defaults__，调用时未传参则复用默认值。 |
| 缺点 | 默认参数在定义时求值，可变默认值会跨调用共享导致累积bug；无重载需用默认参数或dispatch模拟。 |

---

### 3.2 *args 和 **kwargs - 可变参数

| 维度 | 内容 |
|------|------|
| 是什么 | Python用*args收集位置参数为tuple、**kwargs收集关键字参数为dict的可变参数机制。 |
| 能做什么 | 接收任意数量位置参数；接收任意数量关键字参数；解包调用传参；函数转发。 |
| 怎么用 | `def f(*args, **kwargs):`；`f(*lst, **dict)`。 |
| 原理和工作流程 | 调用时解释器将多余位置参数打包为tuple绑定到args，多余关键字参数打包为dict绑定到kwargs；解包调用时*与**将序列与字典展开为独立参数传入。 |
| 缺点 | 参数含义不直观，IDE无法提示参数名；滥用削弱类型安全与可读性；关键字参数顺序约束易出错。 |

---

### 3.3 lambda - 匿名函数

| 维度 | 内容 |
|------|------|
| 是什么 | Python用lambda定义单表达式匿名函数，对应Java的Lambda表达式。 |
| 能做什么 | 内联定义简单函数；作为排序等高阶函数的key；临时回调。 |
| 怎么用 | `add = lambda a, b: a + b`；`sorted(lst, key=lambda x: x[1])`。 |
| 原理和工作流程 | lambda在运行时创建函数对象，只能包含单个表达式并返回其值，不能含语句；与def创建的函数同为callable对象，仅语法形式不同。 |
| 缺点 | 仅支持单表达式无法写复杂逻辑；无函数名降低可读性与可调试性；过度使用使代码难维护。 |

---

### 3.4 import - 导入模块

| 维度 | 内容 |
|------|------|
| 是什么 | Python导入模块与成员的多种写法，对应Java的import。 |
| 能做什么 | 导入整个模块；导入特定成员；重命名导入；相对导入；通配导入。 |
| 怎么用 | `import math`；`from math import pi`；`import numpy as np`。 |
| 原理和工作流程 | import触发模块加载并执行顶层代码，将模块对象绑定到命名空间；from...import将成员绑定到当前命名空间；相对导入依包结构用.与..定位。 |
| 缺点 | `from m import *` 污染命名空间且难以追踪来源；循环导入易引发部分初始化错误；相对导入在脚本直接运行时易失效。 |

## 三点五、流程控制与文件操作

### 流程控制

| 维度 | 内容 |
|------|------|
| 是什么 | Python条件分支、循环及循环else子句组成的控制流语法。 |
| 能做什么 | if-elif-else分支；for遍历；while循环；break/continue；match-case模式匹配。 |
| 怎么用 | `for i in range(5):`；`match grade: case "A": ...`。 |
| 原理和工作流程 | if依条件跳转字节码；for基于迭代器协议调用__next__取值；循环else仅在正常结束未break时执行；3.10+ match-case按模式匹配跳转。 |
| 缺点 | 3.10前无switch语句；循环else语义反直觉易误用；match-case版本兼容性受限。 |

---

### 文件操作

| 维度 | 内容 |
|------|------|
| 是什么 | Python文件读写与上下文管理机制，对应Java的try-with-resources。 |
| 能做什么 | 文本/二进制读写；逐行读取；JSON/CSV处理；资源自动关闭。 |
| 怎么用 | `with open("f.txt","r",encoding="utf-8") as f: f.read()`。 |
| 原理和工作流程 | with语句触发对象的__enter__与__exit__，块结束自动调用close释放文件描述符；mode参数控制读写追加与二进制模式；忘记close会泄漏fd。 |
| 缺点 | 不用with易遗忘关闭导致资源泄漏；encoding处理不当引发UnicodeDecodeError；大文件read()一次性载入内存。 |

## 四、面向对象

### 4.1 类定义 - class

| 维度 | 内容 |
|------|------|
| 是什么 | Python用class关键字定义类、__init__构造、self引用实例的面向对象机制。 |
| 能做什么 | 定义类与实例变量；定义实例方法；创建对象；封装数据与行为。 |
| 怎么用 | `class Person:\n    def __init__(self,name): self.name=name`。 |
| 原理和工作流程 | 类即type实例，创建对象调用__new__分配内存再调__init__初始化；实例方法首参self显式接收实例引用，访问成员需self.前缀；实例属性存于__dict__。 |
| 缺点 | self必须显式书写增加样板代码；实例属性动态添加削弱封装；无原生访问控制符，靠约定下划线区分私有。 |

---

### 4.2 self vs this

| 维度 | 内容 |
|------|------|
| 是什么 | 对比Python显式self参数与Java隐式this引用的差异。 |
| 能做什么 | 引用当前实例；访问实例变量与方法；区分局部变量与成员变量。 |
| 怎么用 | `def m(self): self.x = 1`。 |
| 原理和工作流程 | Python方法本质是类属性中的函数，实例调用时绑定机制将实例作为首参传入self；Java编译器隐式传入this，仅在变量遮蔽时需显式书写。 |
| 缺点 | self显式书写繁琐易遗漏导致参数错位；命名约定虽统一但增加代码量。 |

---

### 4.3 继承

| 维度 | 内容 |
|------|------|
| 是什么 | Python子类继承父类并通过super调用父类方法的机制。 |
| 能做什么 | 复用父类逻辑；重写方法；调用父类构造与方法；扩展功能。 |
| 怎么用 | `class Student(Person):\n    def __init__(self,...): super().__init__(...)`。 |
| 原理和工作流程 | 子类在括号声明父类，实例属性与方法沿MRO查找；super()返回按MRO顺序的代理对象调用父类方法，避免硬编码父类名与多继承重复调用。 |
| 缺点 | 多继承下super调用顺序依赖MRO不易直观判断；菱形继承需super协调否则重复初始化。 |

---

### 4.4 多继承与MRO

| 维度 | 内容 |
|------|------|
| 是什么 | Python支持子类同时继承多个父类，并用C3算法确定方法解析顺序。 |
| 能做什么 | 同时复用多个父类；实现Mixin模式；按MRO统一解析方法来源。 |
| 怎么用 | `class C(A, B): pass`；`C.__mro__` 查看顺序。 |
| 原理和工作流程 | C3线性化算法保证子类优先、父类声明顺序、单调性，生成__mro__元组；方法查找按该顺序遍历，遇首个匹配返回，遵循广度优先。 |
| 缺点 | 多继承复杂易致菱形继承与状态冲突；MRO无法计算时抛TypeError；过度使用Mixin造成类层次混乱。 |

---

### 4.5 魔术方法（Magic Methods）

| 维度 | 内容 |
|------|------|
| 是什么 | Python以双下划线包裹命名的特殊方法，对应Java的toString等方法重写。 |
| 能做什么 | 初始化对象；转字符串；支持len/下标/调用运算；自定义对象行为。 |
| 怎么用 | `def __str__(self): return ...`；`def __call__(self): ...`。 |
| 原理和工作流程 | 解释器在特定语法或内建函数触发时查找对应魔术方法，如print调__str__、len()调__len__、obj()调__call__，构成数据模型协议。 |
| 缺点 | 方法名繁多难记忆；误重写魔术方法破坏对象协议；调试时隐式调用链不直观。 |

---

### 4.6 @property - 优雅的getter/setter

| 维度 | 内容 |
|------|------|
| 是什么 | Python用@property装饰器将方法包装为属性访问的机制，替代Java冗长getter/setter。 |
| 能做什么 | 以属性语法读写；在setter加校验逻辑；只读属性控制；延迟计算。 |
| 怎么用 | `@property\ndef age(self): return self._age`；`@age.setter\ndef age(self,v): ...`。 |
| 原理和工作流程 | @property将方法转为描述符对象，访问obj.age触发其__get__，赋值触发@age.setter的__set__，从而以属性语法执行自定义读写逻辑。 |
| 缺点 | 仅靠下划线约定无法真正阻止直接访问_;继承时覆盖setter需重新声明property；性能低于直接属性访问。 |

## 五、常用标准库

### 5.1 os - 操作系统接口

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库os提供操作系统接口，对应Java的java.io.File等。 |
| 能做什么 | 目录操作；路径拼接与判断；获取工作目录；文件大小与存在性检查。 |
| 怎么用 | `os.getcwd()`；`os.path.join('dir','f.txt')`；`os.path.exists(p)`。 |
| 原理和工作流程 | os模块封装POSIX/Windows系统调用，path子模块按当前平台处理分隔符，join自动选择斜杠方向，避免硬编码路径分隔符。 |
| 缺点 | 部分函数跨平台行为不一致；新代码建议改用pathlib更面向对象；权限错误需显式捕获。 |

---

### 5.2 sys - Python解释器相关

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库sys提供解释器运行时相关变量与函数。 |
| 能做什么 | 读取命令行参数；控制退出码；查看版本与模块搜索路径。 |
| 怎么用 | `sys.argv`；`sys.exit(0)`；`sys.path`。 |
| 原理和工作流程 | argv保存脚本名及参数列表；exit抛出SystemExit异常终止解释器并返回状态码；path为模块查找路径列表，运行时可动态修改。 |
| 缺点 | argv需自行解析，复杂参数应改用argparse；exit抛异常可能被try捕获导致未退出；path修改影响全局。 |

### 5.3 json - JSON处理

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库json处理JSON序列化与反序列化，比Java的Jackson/Gson简洁。 |
| 能做什么 | 对象转JSON字符串；字符串转对象；直接读写文件；格式化输出。 |
| 怎么用 | `json.dumps(obj, ensure_ascii=False)`；`json.loads(s)`。 |
| 原理和工作流程 | dumps遍历对象按类型映射到JSON语法，ensure_ascii=False保留中文；loads词法解析构建Python对象；dump/load直接对接文件对象。 |
| 缺点 | 仅支持基本类型，自定义对象需自定义编码器；日期等类型需default回调处理；loads不可信字符串有注入风险。 |

### 5.4 re - 正则表达式

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库re提供正则匹配、查找、替换、分割功能，对应Java的java.util.regex。 |
| 能做什么 | 搜索匹配；查找全部；替换；按模式分割；原生字符串避免转义。 |
| 怎么用 | `re.findall(r'\d+', text)`；`re.sub(r'\d+','X',text)`。 |
| 原理和工作流程 | re将模式编译为正则状态机，search返回首个Match对象，findall返回所有匹配列表，sub按匹配替换；r''原生字符串使反斜杠不被转义。 |
| 缺点 | 正则易写难读维护性差；贪婪与回溯可能引发性能问题；Unicode匹配需注意re.UNICODE标志。 |

### 5.5 datetime - 日期时间

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库datetime处理日期时间，对应Java的java.time。 |
| 能做什么 | 获取当前时间；格式化与解析；时间运算；时区处理。 |
| 怎么用 | `datetime.now().strftime('%Y-%m-%d')`；`now + timedelta(days=7)`。 |
| 原理和工作流程 | datetime封装年月日时分秒，strftime按格式符输出字符串，strptime按格式解析，timedelta表示时间差支持加减运算得到新datetime。 |
| 缺点 | naive datetime不带时区易出错，需pytz/zoneinfo处理时区；格式符与Java不一致需记忆；运算返回新对象需注意。 |

### 5.6 collections - 高级数据结构

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库collections提供Counter、defaultdict、deque等高级数据结构。 |
| 能做什么 | 计数；默认值字典；双端队列；有序字典；命名元组。 |
| 怎么用 | `Counter(words).most_common(2)`；`defaultdict(list)`；`deque()`。 |
| 原理和工作流程 | Counter继承dict自动计数；defaultdict在缺失key时调工厂函数创建默认值；deque为双向链表式结构支持O(1)头尾操作。 |
| 缺点 | defaultdict掩盖key缺失易引入隐性bug；deque随机访问O(n)；Counter负数计数场景需注意。 |

### 5.7 itertools - 迭代器工具

| 维度 | 内容 |
|------|------|
| 是什么 | Python标准库itertools提供排列组合、笛卡尔积、无限迭代等迭代器工具。 |
| 能做什么 | 排列组合；笛卡尔积；无限计数；链式与分组迭代。 |
| 怎么用 | `itertools.permutations(nums,2)`；`itertools.product(a,b)`。 |
| 原理和工作流程 | 全部函数返回惰性迭代器，按需生成元素不预占内存；permutations按位置取排列，combinations不考虑顺序，count生成等差无限序列。 |
| 缺点 | 惰性迭代器只能消费一次，重复使用需重新构造；无限迭代器无break会死循环；结果为元组需list转换查看。 |
