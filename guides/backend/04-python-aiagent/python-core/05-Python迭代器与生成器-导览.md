## 一、可迭代对象与迭代器

### 1.1 一个 for 循环的完整旅程

| 维度 | 内容 |
|------|------|
| 是什么 | `for` 把可迭代对象转成迭代器并逐个取值的执行过程。 |
| 能做什么 | 解释任意对象为何能被遍历；手动控制迭代；理解循环何时结束。 |
| 怎么用 | `it = iter(obj)`，循环调用 `next(it)`，捕获 `StopIteration` 后结束。 |
| 原理和工作流程 | `iter()` 取得迭代器，`next()` 逐个产出元素，耗尽时抛 `StopIteration`；`for` 还负责 `break`、`continue` 与循环 `else`。 |
| 缺点 | 手写驱动代码冗长；忘记捕获 `StopIteration` 会把正常结束当成错误。 |

---

### 1.2 可迭代对象与迭代器的分界

| 维度 | 内容 |
|------|------|
| 是什么 | 只实现 `__iter__` 的容器与同时实现 `__iter__`、`__next__` 的迭代器之间的区别。 |
| 能做什么 | 判断对象能否重复遍历；区分容器与游标；正确实现自定义可迭代类型。 |
| 怎么用 | `isinstance(obj, Iterable)` 判断可迭代；`iter(obj) is obj` 判断是否为迭代器。 |
| 原理和工作流程 | 容器每次 `iter()` 返回新迭代器，支持嵌套循环；迭代器的 `__iter__` 返回自身，耗尽后不复位；文件对象是同时具备两种身份的例外。 |
| 缺点 | 两个概念名称相近，容易混用；把容器当迭代器会导致嵌套遍历互相干扰。 |

---

### 1.3 手写迭代器与可重复迭代

| 维度 | 内容 |
|------|------|
| 是什么 | 用类实现 `__iter__`、`__next__`，或把 `__iter__` 写成生成器函数。 |
| 能做什么 | 自定义遍历逻辑；实现一次性迭代器；实现可反复遍历的对象。 |
| 怎么用 | 一次性迭代器让 `__iter__` 返回 `self`；可重复对象让 `__iter__` 返回新生成器。 |
| 原理和工作流程 | `__next__` 维护游标并在耗尽时抛 `StopIteration`；`__iter__` 含 `yield` 时每次调用创建独立生成器，天然支持重复遍历。 |
| 缺点 | 返回 `self` 的迭代器只能消费一次；手写状态机容易漏掉边界条件。 |

## 二、迭代器协议：iter、next 与 StopIteration

### 2.1 iter() 的两种形态

| 维度 | 内容 |
|------|------|
| 是什么 | `iter(obj)` 与 `iter(callable, sentinel)` 两种构造迭代器的方式。 |
| 能做什么 | 从容器取迭代器；把“反复读取直到哨兵”的接口包装成迭代器。 |
| 怎么用 | `iter([1, 2])`；`iter(lambda: stream.read(3), b"")`。 |
| 原理和工作流程 | 第一种调用 `__iter__`；第二种反复调用无参 callable，直到返回值 `==` 哨兵，哨兵本身不产出。 |
| 缺点 | callable 必须无参；哨兵比较依赖 `==` 语义；哨兵选择不当可能提前结束。 |

---

### 2.2 StopIteration 的边界

| 维度 | 内容 |
|------|------|
| 是什么 | 迭代正常结束时抛出的信号异常，以及 `next()` 的默认值机制。 |
| 能做什么 | 判断迭代结束；安全取值；避免把结束信号误当错误。 |
| 怎么用 | `next(it, default)`；需要区分时捕获 `StopIteration`；生成器内用 `return` 结束。 |
| 原理和工作流程 | 消费者捕获 `StopIteration` 停止；PEP 479 把生成器体内冒出的 `StopIteration` 转成 `RuntimeError`，避免与正常结束混淆。 |
| 缺点 | 在生成器里主动 `raise StopIteration` 会触发 `RuntimeError`；内部 `next()` 漏出的异常也会被转换。 |

## 三、生成器函数与 yield

### 3.1 调用生成器函数时发生了什么

| 维度 | 内容 |
|------|------|
| 是什么 | 含 `yield` 的函数调用后返回生成器对象，而不是立即执行函数体。 |
| 能做什么 | 惰性生产数据；暂停与恢复执行；保存局部状态。 |
| 怎么用 | `g = gen()` 创建；`next(g)` 驱动到下一个 `yield`；耗尽时捕获 `StopIteration`。 |
| 原理和工作流程 | 首次 `next()` 开始执行到第一个 `yield`，保存栈帧与指令位置；后续 `next()` 从暂停点恢复；结束或 `return` 时抛 `StopIteration`。 |
| 缺点 | 调用不等于执行，容易误以为函数体已运行；生成器只能单向推进，不能回退。 |

---

### 3.2 生成器的四种状态

| 维度 | 内容 |
|------|------|
| 是什么 | `GEN_CREATED`、`GEN_RUNNING`、`GEN_SUSPENDED`、`GEN_CLOSED` 四个生命周期状态。 |
| 能做什么 | 调试生成器为何不执行；判断是否已耗尽；定位重入错误。 |
| 怎么用 | `inspect.getgeneratorstate(g)` 查看状态；`next()`、`send()`、`close()` 驱动迁移。 |
| 原理和工作流程 | 创建后为 CREATED，执行中为 RUNNING，遇到 `yield` 转 SUSPENDED，结束、异常或 `close()` 后转 CLOSED。 |
| 缺点 | 状态是 CPython 的调试视图，不应作为业务逻辑依赖；RUNNING 时重入会抛 `ValueError`。 |

---

### 3.3 生命周期与资源释放

| 维度 | 内容 |
|------|------|
| 是什么 | 生成器作为资源管理边界，通过 `finally`、`with`、`close()` 保证清理。 |
| 能做什么 | 关闭文件、连接、锁；在提前退出时释放资源；避免句柄泄漏。 |
| 怎么用 | 生成器内用 `with`；调用方用 `close()` 或 `contextlib.closing`。 |
| 原理和工作流程 | `close()` 在暂停点抛 `GeneratorExit`，触发 `finally` 与 `with.__exit__`；CPython 引用计数归零时也可能触发清理，但时机不应依赖。 |
| 缺点 | 处理 `GeneratorExit` 时再 `yield` 会抛 `RuntimeError`；不关闭生成器可能导致资源长期占用。 |

## 四、生成器表达式

### 4.1 语法与求值时机

| 维度 | 内容 |
|------|------|
| 是什么 | 用圆括号构造的惰性推导式，返回生成器对象。 |
| 能做什么 | 按需计算序列；作为聚合函数的输入；避免中间列表。 |
| 怎么用 | `(expr for x in it if cond)`；作为唯一实参时可省略外层括号。 |
| 原理和工作流程 | 创建时只确定最外层可迭代对象，元素表达式与过滤条件在每次 `next()` 时求值；自由变量按运行时的名字查找。 |
| 缺点 | 只能消费一次；不支持 `len()`、索引；调试时看不到元素，只能看到生成器对象。 |

---

### 4.2 与列表推导式的取舍

| 维度 | 内容 |
|------|------|
| 是什么 | 立即物化的列表推导式与惰性生成器表达式在内存、访问方式上的对比。 |
| 能做什么 | 根据数据量和访问模式选择合适构造；避免不必要的内存占用。 |
| 怎么用 | 需重复遍历或随机访问用列表；只需顺序消费一次用生成器表达式。 |
| 原理和工作流程 | 列表推导式创建时计算全部元素，内存 O(n)；生成器表达式逐元素计算，额外内存 O(1)，异常延迟到迭代时。 |
| 缺点 | 生成器表达式不一定更快；小数据反复使用时列表更直接；物化操作会抵消惰性优势。 |

## 五、yield from：委托与双向通道

### 5.1 委托迭代与递归展平

| 维度 | 内容 |
|------|------|
| 是什么 | 把一个可迭代对象的产出委托给当前生成器的语法。 |
| 能做什么 | 拼接多个迭代器；递归展平嵌套结构；把子生成器作为流水线一段。 |
| 怎么用 | `yield from sub`；递归函数中用 `yield from flatten(item)`。 |
| 原理和工作流程 | 当前生成器把 `next()` 请求转发给子迭代器，逐个产出其元素；子迭代器耗尽后继续执行 `yield from` 之后的代码。 |
| 缺点 | 递归过深会触发递归深度限制；对普通 `for + yield` 的优势只在需要双向通信或返回值时体现。 |

---

### 5.2 双向通道与返回值

| 维度 | 内容 |
|------|------|
| 是什么 | `yield from` 在产出之外，还转发 `send()`、`throw()`、`close()` 并接收子生成器返回值。 |
| 能做什么 | 组合生成器协程；把调用方的值送进子生成器；获取子生成器的 `return` 值。 |
| 怎么用 | `result = yield from inner()`；`g.send(v)` 会转发到子生成器。 |
| 原理和工作流程 | 子生成器产出的值原样上传，调用方送入的值原样下传；子生成器结束时 `StopIteration.value` 成为表达式结果。 |
| 缺点 | 语义比普通迭代复杂，调试链路长；子生成器未捕获的异常会向外传播并关闭外层。 |

## 六、send、throw 与 close

### 6.1 send：向暂停点送入数据

| 维度 | 内容 |
|------|------|
| 是什么 | 把值送进生成器暂停点，作为 `yield` 表达式结果的驱动方式。 |
| 能做什么 | 实现生成器协程；维护跨次调用的状态；驱动累加器、状态机。 |
| 怎么用 | 先 `next(g)` 或 `g.send(None)` 启动，再 `g.send(value)`。 |
| 原理和工作流程 | `send(v)` 恢复生成器，把 `v` 赋给当前 `yield` 表达式，运行到下一个 `yield` 并返回其产出。 |
| 缺点 | 首次传入非 None 会抛 `TypeError`；返回值是下一个 `yield` 的值，容易与送入值混淆。 |

---

### 6.2 throw 与 close：异常注入和清理

| 维度 | 内容 |
|------|------|
| 是什么 | 在生成器暂停点注入异常（`throw`）或请求结束（`close`）的方法。 |
| 能做什么 | 通知生成器处理错误；触发 `finally` 清理；主动结束无限生成器。 |
| 怎么用 | `g.throw(ValueError("boom"))`；`g.close()`。 |
| 原理和工作流程 | `throw` 在暂停点抛出异常，生成器可捕获；`close` 抛 `GeneratorExit`，生成器应清理后退出，不能再次 `yield`。 |
| 缺点 | 未捕获的异常会关闭生成器；`GeneratorExit` 不是 `Exception` 子类；三参数 `throw` 形式在 3.12 起弃用。 |

## 七、itertools 常用工具

### 7.1 无限、有限与组合三类工具

| 维度 | 内容 |
|------|------|
| 是什么 | 标准库 `itertools` 提供的惰性迭代器工具集合。 |
| 能做什么 | 生成无限序列；切片、串联、分组、累积；排列组合与笛卡尔积。 |
| 怎么用 | `islice(count(), n)`；`chain(a, b)`；`groupby(sorted_rows, key)`。 |
| 原理和工作流程 | 所有函数返回惰性迭代器；无限工具需外部边界；`groupby` 只合并相邻 key；组合工具按数学公式生成元组。 |
| 缺点 | 无限工具直接 `list()` 会耗尽内存；`groupby` 未排序会重复分组；`tee` 会缓冲未消费元素。 |

---

### 7.2 工程常用的四个模式

| 维度 | 内容 |
|------|------|
| 是什么 | 分批、滑动窗口、展平、轮询四类基于 `itertools` 的工程写法。 |
| 能做什么 | 控制批大小；计算相邻窗口；展平嵌套；轮转候选资源。 |
| 怎么用 | `chunks` 用 `islice`；窗口用 `deque(maxlen=size)`；展平用 `chain.from_iterable`；轮询用 `cycle`。 |
| 原理和工作流程 | `chunks` 反复切片直到空批次；窗口保持固定长度并逐项滑动；`chain` 串联迭代器；`cycle` 缓存原序列并循环产出。 |
| 缺点 | `chunks` 的末批可能不足；窗口需处理不足长度；`cycle` 缓存大序列占内存；自定义实现需自行测试边界。 |

## 九、常见坑

### 9.1 生成器耗尽与重复消费

| 维度 | 内容 |
|------|------|
| 是什么 | 生成器一次性消费，耗尽后再次遍历得到空结果。 |
| 能做什么 | 识别“第二次为空”的根因；选择重建、物化或 `tee` 等修复方式。 |
| 怎么用 | 重新调用生成器函数；`list(gen)` 缓存；`itertools.tee` 复制；改造成可重复对象。 |
| 原理和工作流程 | 生成器内部游标只前进；短路消费者（`any`、`next`）会留下未消费元素；`tee` 用缓冲支持多分支。 |
| 缺点 | 物化占 O(n) 内存；`tee` 缓冲可能持续增长；重建会重复计算。 |

---

### 9.2 闭包延迟绑定

| 维度 | 内容 |
|------|------|
| 是什么 | 闭包捕获变量本身，而不是变量在函数创建时的值。 |
| 能做什么 | 解释循环中创建的回调为何都使用最后一个值；正确注册工具处理器。 |
| 怎么用 | `lambda query, name=name: f"{name}:{query}"`；`functools.partial(handle, tool_name=name)`；工厂函数。 |
| 原理和工作流程 | 函数体执行时才按名字查找自由变量；循环结束后变量停在最终值，所有闭包看到同一结果。 |
| 缺点 | 默认参数会固定值但也改变签名；`partial` 增加一层调用；工厂函数代码更多。 |

---

### 9.3 生成器中的异常与 return

| 维度 | 内容 |
|------|------|
| 是什么 | 生成器暂停点的异常传播、`finally` 清理，以及 `return` 值进入 `StopIteration.value` 的语义。 |
| 能做什么 | 正确传播流式处理错误；保证清理执行；读取生成器返回值。 |
| 怎么用 | 用 `try/finally` 清理；异常记录后重新抛出；手动 `next()` 或 `yield from` 获取返回值。 |
| 原理和工作流程 | 异常在恢复执行时从 `yield` 处抛出，`finally` 先执行再传播；`return` 结束生成器并设置 `StopIteration.value`，普通 `for` 丢弃该值。 |
| 缺点 | 吞异常会让下游收到残缺数据；PEP 479 把生成器内的 `StopIteration` 转成 `RuntimeError`；`for` 看不到返回值。 |

---

### 9.4 其他高频陷阱

| 维度 | 内容 |
|------|------|
| 是什么 | 生成器表达式误用、遍历时修改容器、无限流、首次 `send`、异步生成器等常见错误。 |
| 能做什么 | 快速定位运行时报错或结果异常；在评审中识别高风险写法。 |
| 怎么用 | 需要长度或索引时先物化；过滤时生成新列表；无限流加 `islice`；首次 `send(None)`；异步委托用 `async for`。 |
| 原理和工作流程 | 生成器不支持序列协议；容器迭代器按索引推进；无限工具没有终点；生成器启动前没有暂停点；异步生成器不支持 `yield from`。 |
| 缺点 | 这些错误有的直接抛异常，有的静默丢数据，排查成本高；需要靠约定和测试兜底。 |
