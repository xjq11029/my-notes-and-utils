## 一、为什么 Agent 代码大量使用装饰器

| 维度 | 内容 |
|------|------|
| 是什么 | 用装饰器把工具注册、生命周期钩子、调用包装、缓存重试等横切逻辑从业务函数中剥离的工程模式。 |
| 能做什么 | 把普通函数注册成工具；在模型或工具调用前后插入钩子；统一实现日志、重试、限流、权限。 |
| 怎么用 | 用 `@tool` 注册工具，用 `@before_model` / `@after_model` 挂生命周期钩子，用 `@wrap_model_call` / `@wrap_tool_call` 包住 handler。 |
| 原理和工作流程 | 装饰器在函数定义时接收原函数并返回增强后的可调用对象，框架在启动时收集这些对象，运行时按注册顺序或包装顺序执行。 |
| 缺点 | 装饰器隐藏了调用链，滥用会让控制流难以追踪；不同框架的装饰器语义和版本行为可能不同。 |

**速记**：Agent 框架用装饰器做三件事——注册能力、挂载钩子、包装调用。

## 二、函数是一等对象与装饰器语法糖

| 维度 | 内容 |
|------|------|
| 是什么 | Python 函数是运行时创建的对象，可以赋值、传参、返回、挂属性；`@decorator` 是 `f = decorator(f)` 的语法糖。 |
| 能做什么 | 把函数存入注册表；按配置选择实现；给函数附加 schema；用装饰器替换函数名绑定。 |
| 怎么用 | `handler = greet`；`@trace` 写在 `def` 上方；等价的显式写法是 `add = trace(add)`。 |
| 原理和工作流程 | 执行到 `def` 时先创建函数对象，再求值装饰器表达式，然后从下往上应用装饰器，把名字重新绑定到返回值；调用时执行 wrapper。 |
| 缺点 | 装饰器在定义时执行，容易把 I/O 或副作用带到导入阶段；叠加顺序不直观，排错需要展开调用链。 |

**速记**：`@a` 在 `@b` 上方等价于 `a(b(f))`，下面的装饰器先包裹。
**易错点**：装饰器表达式在定义时求值，不要在装饰器工厂里做昂贵的网络请求。

## 三、闭包与 LEGB

| 维度 | 内容 |
|------|------|
| 是什么 | 闭包是内层函数加上它引用的外层变量；LEGB 是 Local、Enclosing、Global、Built-in 的名字查找顺序。 |
| 能做什么 | 让函数记住配置或状态；实现计数器；让装饰器持有原函数和参数；用 `nonlocal` 修改外层状态。 |
| 怎么用 | 外层函数定义变量并返回内层函数；内层用 `nonlocal` 声明要修改的外层变量；用 `__closure__` 和 `co_freevars` 观察捕获。 |
| 原理和工作流程 | 编译期确定名字的作用域，运行时把自由变量放进 cell；外层函数返回后 cell 仍被内层函数引用，变量生命周期被延长。 |
| 缺点 | 闭包会延长对象生命周期，可能造成内存滞留；捕获的是变量而非值，容易引发 late binding。 |

**速记**：闭包记住的是变量单元格，不是创建那一刻的值。
**易错点**：函数内给名字赋值就会创建局部变量，想改外层必须声明 `nonlocal`。

## 四、late binding 与循环变量陷阱

| 维度 | 内容 |
|------|------|
| 是什么 | 闭包在调用时才从 cell 读取变量当前值，导致循环中创建的函数全部使用最后一个循环变量。 |
| 能做什么 | 解释 `[lambda: i for i in range(3)]` 全返回 2；识别批量注册回调、工具时的错误；用三种方式修复。 |
| 怎么用 | 用 `lambda i=i: i` 固定默认值；用工厂函数 `make_handler(name)` 创建独立作用域；用 `partial(handle, name)` 绑定参数。 |
| 原理和工作流程 | 循环只创建多个函数对象，它们共享同一个变量 cell；循环结束后 cell 保留最后值，调用时统一读取该值。 |
| 缺点 | 默认参数修复法在可变默认值上有额外风险；工厂函数增加一层代码；`partial` 只适合已有函数。 |

**速记**：要固定值就用默认参数或工厂，要共享状态就保留 late binding。

## 五、带参数的装饰器

| 维度 | 内容 |
|------|------|
| 是什么 | 先接收配置、再返回装饰器的三层结构；`@retry(times=3)` 等价于 `retry(times=3)(func)`。 |
| 能做什么 | 给重试配置次数和延迟；给工具配置名称和描述；给日志配置级别；在定义时校验配置。 |
| 怎么用 | 外层 `retry(times, delay)` 收配置，中层 `decorator(func)` 收函数，内层 `wrapper(*args, **kwargs)` 执行逻辑；需要兼容两种写法时用 `func=None` 分支。 |
| 原理和工作流程 | 定义时先执行外层得到装饰器，再用装饰器包裹原函数；外层只执行一次，wrapper 每次调用执行。 |
| 缺点 | 多一层嵌套降低可读性；`@decorator` 与 `@decorator()` 混用容易出错；配置在定义时固定，后续修改外部变量不会生效。 |

**速记**：带参装饰器是"配置层、装饰层、调用层"三层，配置在导入时冻结。
**易错点**：`@retry` 和 `@retry()` 的参数含义不同，混用会让函数被错误替换。

## 六、类装饰器与可调用对象

| 维度 | 内容 |
|------|------|
| 是什么 | 用实现 `__call__` 的类实例包裹函数，或用装饰器作用于类；前者保存状态，后者注册或改写类。 |
| 能做什么 | 统计调用次数；保存连接或缓存；把类登记到注册表；用 `@dataclass` 生成方法。 |
| 怎么用 | 类实现 `__init__` 保存 `func`、`__call__` 执行调用；装饰实例方法时实现 `__get__` 返回 `MethodType(self, obj)`；装饰类时修改并返回原类。 |
| 原理和工作流程 | `@Class` 让名字变成类实例；调用触发 `__call__`；属性访问触发 `__get__`，从而把实例绑定为方法。 |
| 缺点 | 类实例默认不是描述符，装饰方法时容易丢失 `self`；类属性上的装饰器实例会被所有对象共享状态；代码量大于闭包。 |

**速记**：类装饰器能存状态，但装饰方法必须补 `__get__`。
**易错点**：类属性上的装饰器实例会被所有实例共享，计数前先确认隔离粒度。

## 七、functools.wraps 与签名保留

| 维度 | 内容 |
|------|------|
| 是什么 | `functools.wraps` 把原函数的元数据复制到 wrapper，并写入 `__wrapped__`，让反射工具看到原签名。 |
| 能做什么 | 保留 `__name__`、`__doc__`、`__module__`、`__annotations__`；让 FastAPI、LangChain、pytest 正确解析参数；便于日志归类。 |
| 怎么用 | 在每个 wrapper 上加 `@wraps(fn)`；需要自定义时用 `update_wrapper` 的 `assigned` 和 `updated` 参数。 |
| 原理和工作流程 | `wraps` 调用 `update_wrapper` 复制指定属性并更新 `__dict__`，最后设置 `__wrapped__`；`inspect.signature` 默认沿 `__wrapped__` 查找原签名。 |
| 缺点 | 只改元数据，不改变 wrapper 仍接收 `*args, **kwargs` 的事实；包装可调用对象时可能缺少 `__name__`；不能替代真正的参数校验。 |

**速记**：包装函数默认加 `@wraps`，否则框架看到的签名是 `(*args, **kwargs)`。
**易错点**：`wraps` 只修元数据，不会替 wrapper 做参数校验或类型转换。

## 八、functools.lru_cache 与缓存边界

| 维度 | 内容 |
|------|------|
| 是什么 | 按参数构建缓存键、缓存满时淘汰最近最少使用条目的标准库装饰器；`@cache` 等价于无上限版本。 |
| 能做什么 | 加速递归和重复计算；缓存纯函数结果；通过 `cache_info` 观测命中率；通过 `cache_clear` 手动失效。 |
| 怎么用 | `@lru_cache(maxsize=128)`；不可哈希参数先转元组；异步函数缓存最终数据而不是协程。 |
| 原理和工作流程 | 调用时用参数生成键，命中直接返回，未命中执行函数并写入；缓存满时按访问顺序淘汰；异常结果不写入缓存。 |
| 缺点 | 参数必须可哈希；关键字参数顺序影响键；实例方法缓存强引用 `self`；没有 TTL 和跨进程共享；不能直接用于 async 函数。 |

**速记**：`lru_cache` 只适合可哈希、无副作用、同步的纯函数。

## 九、functools.partial 与 singledispatch

| 维度 | 内容 |
|------|------|
| 是什么 | `partial` 预绑定部分参数生成新可调用对象；`singledispatch` 按第一个参数的类型选择实现。 |
| 能做什么 | 为工具注入默认配置；把通用函数适配成回调；按字符串、字典、列表等类型渲染工具结果。 |
| 怎么用 | `partial(call_tool, "search", timeout=2.0)`；`@singledispatch` 定义兜底，再用 `@render.register` 按注解注册。 |
| 原理和工作流程 | `partial` 保存原函数、位置参数和关键字参数，调用时合并；`singledispatch` 在注册表里按类型 MRO 查找实现，最终回退到 `object`。 |
| 缺点 | `partial` 默认没有 `__name__`，日志不友好；`singledispatch` 只看第一个参数，联合类型注册在 3.10 需拆开。 |

**速记**：`partial` 绑参数，`singledispatch` 按首参类型分派。

## 十、描述符与 property 的关系

| 维度 | 内容 |
|------|------|
| 是什么 | 描述符是接管属性读写的协议；`property` 是标准库提供的数据描述符，也是装饰器。 |
| 能做什么 | 在赋值时校验；把方法伪装成属性；实现只读属性；用 `cached_property` 缓存派生值。 |
| 怎么用 | `@property` 定义 getter，`@x.setter` 定义 setter；自定义描述符实现 `__get__`、`__set__`、`__set_name__`。 |
| 原理和工作流程 | 数据描述符优先于实例 `__dict__`，访问属性触发 `__get__`，赋值触发 `__set__`；`@x.setter` 返回带 `fset` 的新 property 对象。 |
| 缺点 | 描述符协议概念绕；property 增加访问开销；`cached_property` 可被实例属性覆盖且没有 setter。 |

**速记**：`property` 是数据描述符；方法绑定靠函数的非数据描述符 `__get__`。
**易错点**：`@x.setter` 必须复用同一个属性名，否则会得到两个互不相关的 property。

## 十一、用装饰器写回调与注册表

| 维度 | 内容 |
|------|------|
| 是什么 | 函数定义时把自己登记到事件表或工具表，运行时按名字查找并调用。 |
| 能做什么 | 注册 Agent 生命周期回调；注册工具及其 schema；检测重复注册；把元数据附着到函数对象。 |
| 怎么用 | 写 `on(event)` 返回注册函数；用 `inspect.signature` 读取参数并写入 `fn.tool_schema`；注册成功返回原函数。 |
| 原理和工作流程 | 装饰器在模块导入时执行，把函数引用写入字典；运行时执行器按事件名取出函数并调用；只有需要改变调用行为时才返回 wrapper。 |
| 缺点 | 副作用发生在导入阶段，模块未导入就不会注册；重复注册容易静默覆盖；注册表是全局状态，测试之间可能污染。 |

**速记**：注册型装饰器返回原函数；元数据在定义时读取，运行时只查表。

## 十二、用装饰器写中间件

| 维度 | 内容 |
|------|------|
| 是什么 | 用 wrapper 包住 handler，在调用前后插入逻辑，多个装饰器形成洋葱式调用链。 |
| 能做什么 | 记录请求响应；重试超时；做权限校验；改写模型请求；实现限流和审计。 |
| 怎么用 | `with_logging(with_retry(call_model))`；或用 `@with_logging` 放在 `@with_retry` 上方；hook 型则给函数打阶段标记。 |
| 原理和工作流程 | 最外层装饰器先接收请求，逐层调用内层，最内层执行原函数；响应按相反方向返回；hook 型由运行时在固定阶段统一调用。 |
| 缺点 | 顺序决定语义，放错位置会重复认证或重复计费；wrap 型嵌套过深难调试；hook 型不能直接短路。 |

**速记**：wrap 型包住 handler 能短路；hook 型只登记，由运行时按阶段调用。
**易错点**：把重试放在认证外层，会让认证失败也被重复执行。

## 十三、异步装饰器与上下文传递

| 维度 | 内容 |
|------|------|
| 是什么 | 用 `async def` wrapper 包装异步函数，并用 `ContextVar` 在异步调用链中传递请求上下文。 |
| 能做什么 | 统计异步模型调用耗时；统一记录异常；传递 request id；实现异步超时和取消清理。 |
| 怎么用 | `async def wrapper` 中 `await fn(...)`；用 `inspect.iscoroutinefunction` 分支兼容同步函数；用 `ContextVar.set/reset` 配合 `finally`。 |
| 原理和工作流程 | 异步 wrapper 返回协程，事件循环调度时执行 `await`；`ContextVar` 为每个任务保存上下文副本，`reset` 恢复旧值；超时通过取消任务实现。 |
| 缺点 | 同步与异步 wrapper 混用会改变调用契约；`ContextVar` 忘记 reset 会泄漏；取消是 `BaseException`，清理逻辑必须可靠。 |

**速记**：异步装饰器必须 `async def` + `await`；上下文用 `ContextVar`，reset 放 `finally`。
**易错点**：`lru_cache` 缓存的是协程对象，第二次 `await` 会直接报错。

## 十四、常见坑与根因分析

| 维度 | 内容 |
|------|------|
| 是什么 | 汇总 late binding、可变默认参数、wraps 丢失、装饰器顺序、类装饰器绑定、同步异步混用六类高频问题。 |
| 能做什么 | 根据报错或异常现象快速定位根因；区分"默认值只算一次"和"闭包延迟取值"。 |
| 怎么用 | 对照"现象、根因、修复"表格排查；可变默认参数用 `None` 哨兵；方法绑定补 `__get__`；异步函数用类型分支。 |
| 原理和工作流程 | 六类问题分别来自闭包 cell、默认值存储、元数据复制、装饰器应用顺序、描述符协议和协程调用约定。 |
| 缺点 | 表格只覆盖高频模式，复杂框架问题仍需看源码和调用栈；修复方式可能互相影响。 |

**速记**：先判断问题属于"值捕获、元数据、顺序、绑定、协程"中的哪一类。

## 十六、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 六个工程向陷阱：忘写括号、丢 wraps、循环闭包、缓存误用、顺序随缘、类装饰器丢 self。 |

**速记**：括号、wraps、工厂、缓存边界、顺序、`__get__`，六项检查完再提交。
