## 一、大模型发展脉络

### 1.1 从传统NLP到大语言模型

| 维度 | 内容 |
|------|------|
| 是什么 | 梳理NLP技术从统计方法到词向量、预训练模型、大语言模型四个阶段的演进脉络。 |
| 能做什么 | 定位当前技术所处阶段；理解各时代代表模型与核心特点；识别2017年Transformer和2018年BERT/GPT两个关键转折点。 |
| 怎么用 | 对照四阶段时间线：统计NLP（2000-2012）、词向量（2013-2017）、预训练PLM（2018-2019）、大语言模型（2020至今）。 |
| 原理和工作流程 | 统计NLP依赖n-gram和HMM做特征工程；Word2Vec将词映射为静态分布式向量；BERT和GPT开创预训练加微调范式，在无标注语料上学习通用表示后用少量标注数据适配下游任务；GPT-3后进入规模扩展阶段，通过增大参数和数据涌现出复杂能力。2017年《Attention Is All You Need》用自注意力取代RNN/LSTM，成为整个技术栈切换的基石。 |
| 缺点 | 阶段划分较粗略，实际技术演进存在交叉并行；词向量时代的静态表示无法解决一词多义问题。 |

### 1.2 GPT-1：生成式预训练的起点

| 维度 | 内容 |
|------|------|
| 是什么 | OpenAI于2018年发布的首个生成式预训练语言模型，确立无监督预训练加有监督微调的两阶段范式。 |
| 能做什么 | 在无标注文本上学习语言规律；用少量标注数据适配分类、蕴含、相似度等下游任务；在12个NLP任务的9个上取得当时最佳结果。 |
| 怎么用 | 阶段一：在BooksCorpus上做语言模型预训练；阶段二：在标注数据上微调，最终目标L = L2 + λ×L1。 |
| 原理和工作流程 | 架构为12层Transformer Decoder，768维隐藏层，12个注意力头，参数量117M。预训练目标是给定前k个词预测下一个词的概率；微调阶段在输入序列后预测分类标签，并加入语言模型辅助目标防止遗忘。残差层权重按1/√N缩放以稳定深层训练。 |
| 缺点 | 模型规模小（117M），能力有限；仅在BooksCorpus（5GB）上训练，数据覆盖面窄；Zero-Shot能力尚未显现。 |

### 1.3 GPT-2：Zero-Shot与规模扩展

| 维度 | 内容 |
|------|------|
| 是什么 | 2019年发布的生成式预训练模型，主张语言模型本身可作为多任务学习器，无需显式微调即可完成各类任务。 |
| 能做什么 | 展现Zero-Shot推理能力；随模型规模增大持续提升任务性能；引入Pre-Norm结构改善训练稳定性。 |
| 怎么用 | 输入"translate English to French: Hello"，模型直接输出"Bonjour"，无需任何翻译示例或微调。 |
| 原理和工作流程 | 最大版本1.5B参数，48层，1600维隐藏层，在WebText数据集（40GB，经Reddit高赞过滤）上训练。将LayerNorm移到Attention和FFN之前（Pre-Norm），残差层权重按1/√N缩放。词汇表从40K扩展到50,257。核心发现是Zero-Shot性能随规模持续提升，直接启发了后续Scaling Law研究。 |
| 缺点 | Zero-Shot能力在复杂任务上仍然有限；真正的突破需要等待GPT-3的规模跃升；数据过滤策略可能引入偏差。 |

### 1.4 GPT-3：In-Context Learning与涌现能力

| 维度 | 内容 |
|------|------|
| 是什么 | 2020年发布的1750亿参数大语言模型，展示In-Context Learning（上下文学习）和涌现能力，实现从微调适应任务到提示词引导任务的范式转变。 |
| 能做什么 | 通过Few-Shot示例理解任务并生成正确回答；展现算术推理、多语言翻译、代码生成、文章摘要、常识推理等涌现能力。 |
| 怎么用 | Zero-Shot：无示例直接推理；One-Shot：提供1个示例；Few-Shot：提供多个示例，均不更新参数。 |
| 原理和工作流程 | 96层Transformer Decoder，12288维隐藏层，96个注意力头，上下文窗口2048 tokens，训练数据约300B tokens。In-Context Learning的核心机制是在Prompt中放入几个示例，模型通过注意力机制从上下文中学习任务模式，不做任何参数更新即可推理。参数量较GPT-2提升100倍，达到涌现阈值。 |
| 缺点 | 训练数据仅300B tokens，按Chinchilla定律严重训练不足；上下文窗口仅2048 tokens；生成内容可能有害、有偏见、不准确，需要后续对齐训练。 |

### 1.5 GPT-4：多模态与安全对齐

| 维度 | 内容 |
|------|------|
| 是什么 | 2023年发布的多模态大语言模型，实现从纯文本到文本加图像输入的跨越，推理能力和安全对齐大幅增强。 |
| 能做什么 | 理解图像、图表、截图、手写内容；在数学、逻辑、编程等复杂推理任务上大幅提升；通过System Prompt精确控制模型行为和风格；律师资格考试前10%。 |
| 怎么用 | 输入文本加图像，通过System Prompt定义角色和行为约束，模型按指令生成回答。 |
| 原理和工作流程 | 上下文窗口扩展到8K/32K tokens。推测采用MoE（混合专家模型）架构，约1.76万亿参数，每次推理只激活部分专家。采用可预测扩展技术用小模型预测大模型性能。多阶段训练：预训练、SFT、RLHF、安全训练。GPT-4o（2024年）进一步实现原生多模态，文本图像音频统一处理，响应速度320ms接近人类对话。 |
| 缺点 | 架构和参数量未公开，技术细节依赖推测；推理成本高；多模态对齐仍存在幻觉问题。 |

### 1.6 Scaling Law：规模定律

| 维度 | 内容 |
|------|------|
| 是什么 | 描述模型性能与参数量、数据量、计算量之间幂律关系的经验规律，由OpenAI在2020年系统研究提出。 |
| 能做什么 | 预测给定计算预算下的最优模型配置；指导模型规模和数据量的配比决策；量化参数量和数据量对损失的影响。 |
| 怎么用 | 核心公式L(N,D) = (Nc/N)^αN + (Dc/D)^αD + L∞，其中αN≈0.076，αD≈0.095。 |
| 原理和工作流程 | 三大核心发现：参数量每增加10倍损失呈幂律下降；数据量需随模型规模同步增长；给定计算预算存在最优的模型大小和数据量配比。Chinchilla定律（DeepMind 2022）修正指出最优配置为每1个参数配约20个训练token，GPT-3的175B参数仅用300B tokens属严重训练不足，而Chinchilla的70B参数用1.4T tokens在同等计算预算下性能更优。 |
| 缺点 | 幂律在极大规模下可能偏离；最优配比针对训练阶段计算量，未考虑推理成本；数据质量无法被Scaling Law量化。 |

### 1.7 涌现能力：量变引起质变

| 维度 | 内容 |
|------|------|
| 是什么 | 模型规模达到某个阈值后突然展现的能力，这些能力在小模型上完全不存在，表现为阶梯式性能跃升。 |
| 能做什么 | 解释大模型为何在特定规模后才具备算术推理、多语言翻译、代码生成、Chain-of-Thought等能力。 |
| 怎么用 | 对照涌现阈值表：算术推理约10B参数，Chain-of-Thought约50B参数，指令遵循约50B参数。 |
| 原理和工作流程 | 小模型能力接近随机水平，参数量达到临界阈值后能力突然跃升。可能原因：复杂任务可分解为多个子任务，大模型能同时学习所有子任务；模型容量足够大时可记忆更多模式并建立丰富关联；平滑的损失下降对应阶梯式任务性能提升。 |
| 缺点 | 涌现阈值难以精确预测；无法保证增大规模一定涌现特定能力；涌现能力的度量依赖评估基准，可能存在基准偏差。 |

## 二、Transformer架构

### 2.1 为什么需要Transformer

| 维度 | 内容 |
|------|------|
| 是什么 | 2017年Google提出的序列建模架构，抛弃循环结构，完全依赖自注意力机制建模序列中任意两个位置的关系。 |
| 能做什么 | 实现完全并行计算；直接连接任意位置建模长距离依赖；O(1)时间步完成序列处理。 |
| 怎么用 | 输入序列经Positional Encoding加位置信息，依次通过Multi-Head Attention、Add&Norm、Feed-Forward Network、Add&Norm，输出融合全文上下文的表示向量。 |
| 原理和工作流程 | RNN/LSTM存在三个根本问题：必须串行计算无法并行、梯度消失导致长距离依赖衰减、O(n)时间步训练慢。Transformer用自注意力取代循环结构，每个位置直接与所有位置计算注意力权重，复杂度为O(n²×d)。整体由Encoder和Decoder组成，每层包含多头注意力子层和前馈网络子层，均配合残差连接和LayerNorm。 |
| 缺点 | 自注意力复杂度O(n²×d)，长序列时显存和计算开销急剧增长；位置编码是外部附加而非原生感知。 |

### 2.2 Self-Attention：自注意力机制

| 维度 | 内容 |
|------|------|
| 是什么 | 让序列中每个词关注所有词（包括自己），学习词与词之间依赖关系的注意力计算机制。 |
| 能做什么 | 捕获句子中的指代关系（如"it"指代"animal"）；建模任意两个位置的语义关联；为每个词生成融合全局上下文的表示。 |
| 怎么用 | Q = X×W_Q，K = X×W_K，V = X×W_V；Score = Q×K^T/√d_k；Attention_Weights = Softmax(Score)；Output = Attention_Weights×V。 |
| 原理和工作流程 | 输入序列X通过三个独立线性变换得到Query、Key、Value矩阵。计算Q与K的点积衡量词间相似度，除以√d_k缩放防止梯度消失，经Softmax归一化得到注意力权重，最后对V加权求和输出。每个词的输出是所有词Value向量的加权和，权重由Query-Key相似度决定。 |
| 缺点 | 置换不变，无法感知词序，必须依赖外部位置编码；计算和显存复杂度为O(n²)，长序列开销大。 |

### 2.3 Q/K/V矩阵详解

| 维度 | 内容 |
|------|------|
| 是什么 | Self-Attention的三个核心矩阵，均来自同一输入X通过不同线性变换得到，类比数据库检索中的查询、键、值。 |
| 能做什么 | Q表示当前位置的搜索意图；K表示所有位置的特征标签；V表示所有位置的实际内容；通过Q与K匹配决定从V提取多少信息。 |
| 怎么用 | 假设d_model=512，h=8，每个头d_k=64；W_Q形状(512,64)，Q = X×W_Q形状(n,64)。 |
| 原理和工作流程 | 输入X分别乘以W_Q、W_K、W_V得到三个矩阵。点积Q·K^T衡量Query与Key的相似度，当d_k较大时点积值很大，经Softmax后进入梯度饱和区导致梯度消失，因此除以√d_k使方差保持为1。缩放后Softmax输出更平滑，梯度更稳定。 |
| 缺点 | 三个矩阵增加了参数量和计算量；线性变换的维度选择需要平衡表达能力和计算效率。 |

### 2.4 Multi-Head Attention：多头注意力

| 维度 | 内容 |
|------|------|
| 是什么 | 将输入线性投影到多个低维子空间，每个头独立计算注意力后拼接输出的机制，使模型从多个角度同时关注序列。 |
| 能做什么 | 不同头捕获不同关系模式：语法关系、位置关系、语义关系、指代关系等；提升模型对复杂语义的理解能力。 |
| 怎么用 | MultiHead = Concat(head_1,...,head_h)×W_O，其中head_i = Attention(Q×W_Qi, K×W_Ki, V×W_Vi)。 |
| 原理和工作流程 | 以Transformer-Base为例，d_model=512，h=8，每个头维度64。输入(n,512)被投影为8个(n,64)的子空间，8个头并行计算Scaled Dot-Product Attention，输出拼接为(n,512)后经W_O线性变换恢复原维度。多个头相当于多个独立的注意力函数，各自学习不同的关注模式。 |
| 缺点 | 头数过多时每个头维度过小，表达能力下降；增加参数量和计算量；不同头之间可能学习到冗余模式。 |

### 2.5 Position Encoding：位置编码

| 维度 | 内容 |
|------|------|
| 是什么 | 为输入序列中每个位置添加位置信息的编码方案，弥补Self-Attention置换不变导致的位置感知缺失。 |
| 能做什么 | 使模型感知词的顺序；支持相对位置关系的表达；允许外推到比训练时更长的序列。 |
| 怎么用 | PE(pos,2i) = sin(pos/10000^(2i/d_model))，PE(pos,2i+1) = cos(pos/10000^(2i/d_model))。 |
| 原理和工作流程 | 正弦位置编码使用不同频率的正弦和余弦函数生成，值域[-1,1]不会过大。相对位置关系可通过线性变换表达：PE(pos+k)可由PE(pos)线性表示。GPT系列使用可学习位置嵌入，将位置编码作为可训练参数。LLaMA等现代模型使用RoPE旋转位置编码，对Q和K分别乘旋转矩阵，使点积自然包含相对位置信息。 |
| 缺点 | 正弦编码的外推能力有限；可学习编码无法外推到训练时未见的长度；RoPE在极长序列上仍需配合长度外推技术。 |

### 2.6 LayerNorm与残差连接

| 维度 | 内容 |
|------|------|
| 是什么 | Transformer中用于解决深层网络梯度消失的两项技术：残差连接让信息绕过子层直接传递，LayerNorm在特征维度上做归一化。 |
| 能做什么 | 缓解梯度消失；允许训练更深网络（12层到24层以上）；稳定训练过程；不依赖batch size。 |
| 怎么用 | Post-Norm：LayerNorm(x + Sublayer(x))；Pre-Norm：x + Sublayer(LayerNorm(x))。 |
| 原理和工作流程 | 残差连接将子层输入直接加到输出上，使梯度可绕过子层反向传播。LayerNorm在最后一个维度上计算均值和方差，通过γ和β做缩放和偏移：LN(x) = γ×(x-μ)/√(σ²+ε)+β。Post-Norm将LN放在残差加法之后，需要warmup但效果可能更好；Pre-Norm将LN放在子层之前，梯度更平滑，GPT-2及之后普遍采用。 |
| 缺点 | LayerNorm引入额外计算开销；Post-Norm训练不稳定需要warmup；Pre-Norm在极深网络中性能可能略低于Post-Norm。 |

### 2.7 Feed-Forward Network

| 维度 | 内容 |
|------|------|
| 是什么 | 每个Transformer层在注意力之后的位置独立前馈网络，由两层全连接和激活函数组成，负责存储事实性知识。 |
| 能做什么 | 对注意力聚合后的表示做非线性变换；扩展中间维度（通常4倍）增加表达能力；存储大量事实性知识。 |
| 怎么用 | 标准FFN(x) = ReLU(x×W1)×W2；SwiGLU(x) = (Swish(x×W1)⊙(x×W2))×W3。 |
| 原理和工作流程 | 输入维度512经第一层扩展到2048（4倍），经激活函数非线性变换后第二层压缩回512。研究表明FFN层存储了大量事实性知识，而Attention层负责检索和聚合信息。现代架构（GPT系列、LLaMA）多使用GELU或SwiGLU激活函数，SwiGLU引入门控机制让模型自适应选择信息。 |
| 缺点 | 中间层扩展4倍导致参数量和计算量较大，通常是计算瓶颈；位置独立处理无法建模词间关系。 |

### 2.8 Transformer完整计算流程

| 维度 | 内容 |
|------|------|
| 是什么 | 以Encoder为例，单个Token从输入到输出的完整前向传播流程，涵盖Embedding、多层注意力、残差、FFN等全部操作。 |
| 能做什么 | 描述Token在Transformer中的完整变换路径；量化各操作的计算复杂度；定位计算瓶颈。 |
| 怎么用 | Token→Embedding+Position Encoding→[LayerNorm→MHA→Residual→LayerNorm→FFN→Residual]×N→输出。 |
| 原理和工作流程 | Token经Embedding映射为512维向量并加位置编码，进入Encoder Layer：先LayerNorm归一化，再Multi-Head Attention计算注意力输出，残差相加；再LayerNorm归一化，FFN两层全连接，残差相加。多层重复后输出融合全文上下文的表示向量。Self-Attention复杂度O(n²×d)，FFN复杂度O(n×d²)，长序列时Self-Attention主导。 |
| 缺点 | 长序列时Self-Attention的O(n²)复杂度成为瓶颈；FFN的O(d²)参数量大；整体计算流程无法完全并行化Decoder部分。 |

## 三、Encoder-Decoder架构对比

### 3.1 三种架构总览

| 维度 | 内容 |
|------|------|
| 是什么 | Transformer根据使用的子模块不同分为Encoder-Only（BERT类）、Decoder-Only（GPT类）、Encoder-Decoder（T5类）三种主流变体。 |
| 能做什么 | 提供三种架构的注意力方式对比；指导不同任务场景的架构选择；解释当前LLM主流架构的选择依据。 |
| 怎么用 | 对照三架构表：Encoder-Only双向注意力适合理解任务，Decoder-Only单向注意力适合生成任务，Encoder-Decoder适合seq2seq任务。 |
| 原理和工作流程 | Encoder-Only使用双向注意力，每个词可看到左右所有词；Decoder-Only使用单向因果注意力，每个词只能看到左边；Encoder-Decoder结合两者，Encoder双向编码输入，Decoder单向生成输出并通过Cross-Attention关注Encoder输出。三者分别对应MLM、自回归语言模型、Span Corruption预训练任务。 |
| 缺点 | 三分法较为简化，实际模型可能混合多种技术；架构选择缺乏统一理论指导，依赖经验。 |

### 3.2 BERT类：Encoder-Only

| 维度 | 内容 |
|------|------|
| 是什么 | Google于2018年发布的仅使用Transformer Encoder部分的模型，采用双向注意力和MLM预训练任务，专注自然语言理解。 |
| 能做什么 | 文本分类、命名实体识别、问答、语义相似度等理解任务；每个词可同时看到左右所有词；深层理解文本语义。 |
| 怎么用 | MLM预训练：将句子中部分词替换为[MASK]，模型预测原始词；注意力矩阵全为可见。 |
| 原理和工作流程 | BERT使用双向注意力，注意力矩阵中所有位置互相可见。预训练任务为MLM（Masked Language Model）加NSP（Next Sentence Prediction）。MLM随机遮挡15%的token让模型预测，迫使模型利用双向上下文。代表模型包括BERT、RoBERTa、ALBERT、DeBERTa、ELECTRA。 |
| 缺点 | 不能直接用于文本生成，需要额外解码器；MLM预训练与下游微调存在预训练-微调不一致问题（微调时不遮挡）。 |

### 3.3 GPT类：Decoder-Only

| 维度 | 内容 |
|------|------|
| 是什么 | 仅使用Transformer Decoder部分的模型，采用单向因果注意力和自回归语言模型预训练，是目前最主流的LLM架构。 |
| 能做什么 | 文本生成、对话、代码生成、翻译、推理等通用任务；一次前向传播并行预测所有位置的下一个词；随规模增大展现更好涌现能力。 |
| 怎么用 | 因果注意力掩码：上三角矩阵置为不可见，每个词只能看到左边和当前位置；预训练目标为Next Token Prediction。 |
| 原理和工作流程 | 因果注意力通过上三角掩码实现，位置i只能关注位置0到i。预训练目标为自回归语言模型，给定前文预测下一个token。成为主流的原因：自回归生成天然适合语言建模和文本生成；GPT-3证明强大的上下文学习能力；一次前向传播可并行预测所有位置；随规模增大展现更好涌现能力。代表模型包括GPT-1/2/3/4、LLaMA、Claude、Qwen。 |
| 缺点 | 单向注意力无法利用右侧上下文，理解任务上不如双向模型；自回归生成速度慢，需逐token生成。 |

### 3.4 T5类：Encoder-Decoder

| 维度 | 内容 |
|------|------|
| 是什么 | Google于2019年发布的完整Encoder-Decoder架构模型，将所有NLP任务统一为文本到文本格式，采用Span Corruption预训练。 |
| 能做什么 | 翻译、摘要、问答等seq2seq任务；Encoder双向理解输入后Decoder单向生成输出；通过统一格式处理多种任务。 |
| 怎么用 | 翻译："translate English to German: Hello → Hallo"；摘要："summarize: [长文本] → [摘要]"。 |
| 原理和工作流程 | Encoder使用双向注意力编码输入，Decoder使用单向注意力生成输出，并通过Cross-Attention关注Encoder输出。Cross-Attention中Q来自Decoder，K和V来自Encoder最终输出。预训练任务为Span Corruption，随机遮挡文本片段让模型恢复。T5将所有任务统一为"前缀指令加输入→输出"的文本到文本格式。代表模型包括T5、BART、mT5、Flan-T5。 |
| 缺点 | 参数效率低于Decoder-Only（同等参数量下生成能力较弱）；架构较复杂，扩展性不如Decoder-Only；在大规模预训练上的优势不明显。 |

### 3.5 架构选择指南

| 维度 | 内容 |
|------|------|
| 是什么 | 根据任务类型推荐合适Transformer架构的决策指南，涵盖文本分类、文本生成、翻译摘要、通用LLM等场景。 |
| 能做什么 | 为文本分类/NER推荐Encoder-Only；为文本生成/对话推荐Decoder-Only；为翻译/摘要推荐Encoder-Decoder；为通用LLM推荐Decoder-Only。 |
| 怎么用 | 对照任务类型表选择架构：理解任务用BERT，生成任务用GPT，seq2seq用T5，通用LLM用Decoder-Only。 |
| 原理和工作流程 | 选择依据是架构的注意力特性与任务需求的匹配度。双向注意力适合需要完整上下文的理解任务；单向因果注意力适合自回归生成任务；Cross-Attention适合输入输出分离的seq2seq任务。当前趋势是Decoder-Only成为主流，GPT-4、Claude、LLaMA、Gemini均采用此架构，因其通用性强、扩展性好。 |
| 缺点 | 指南基于经验而非严格理论；特定领域专用模型可能优于通用指南推荐；Encoder-Only和Encoder-Decoder在通用LLM竞争中逐渐边缘化。 |

## 四、GPT系列详解

### 4.1 GPT-1：预训练+微调范式

| 维度 | 内容 |
|------|------|
| 是什么 | 2018年6月OpenAI发布的生成式预训练模型，117M参数，确立无监督预训练加有监督微调的两阶段训练范式。 |
| 能做什么 | 在BooksCorpus上学习语言规律；用标注数据适配12类NLP任务；在9个任务上取得当时最佳结果；加入语言模型辅助目标防止微调遗忘。 |
| 怎么用 | 预训练目标L1 = Σlog P(ui|ui-k,...,ui-1)；微调目标L2 = Σlog P(y|x1,...,xm)；最终L = L2 + λ×L1。 |
| 原理和工作流程 | 架构为12层Transformer Decoder，768维隐藏层，12头注意力，FFN中间层3072维。使用Post-Norm结构。预训练用Adam优化器，学习率最大2.5e-4，warmup 2000步。微调阶段在任务数据上训练分类头，同时加入语言模型辅助目标L1（权重λ）帮助保持通用能力。 |
| 缺点 | 模型规模小，能力有限；Post-Norm训练需warmup；仅在5GB数据上训练，泛化能力受限。 |

### 4.2 GPT-2：Zero-Shot能力

| 维度 | 内容 |
|------|------|
| 是什么 | 2019年2月发布的生成式预训练模型，最大1.5B参数，主张足够强大的语言模型可不经微调完成多任务。 |
| 能做什么 | 展现Zero-Shot推理能力；随规模增大持续提升性能；引入Pre-Norm改善训练稳定性；扩大词汇表到50,257。 |
| 怎么用 | 输入"translate English to French: Hello"，模型直接输出"Bonjour"，无需任何示例或微调。 |
| 原理和工作流程 | 关键改进四项：更大的模型和数据（1.5B参数，WebText 40GB）；Pre-Norm结构（LayerNorm移到子层前）；残差层权重按1/√N缩放；词汇表从40K扩展到50,257。核心主张是所有任务都可表示为"基于上下文预测下一个词"，因此足够强大的语言模型无需微调即可完成多任务。 |
| 缺点 | Zero-Shot在复杂任务上能力有限；真正的突破需等待GPT-3的规模跃升；WebText数据经Reddit过滤可能引入偏差。 |

### 4.3 GPT-3：In-Context Learning

| 维度 | 内容 |
|------|------|
| 是什么 | 2020年6月发布的1750亿参数大语言模型，展示In-Context Learning能力，实现从微调到提示词引导的范式转变。 |
| 能做什么 | 通过Few-Shot示例理解任务并生成回答；展现算术推理、翻译、代码生成等涌现能力；无需任何参数更新完成多任务。 |
| 怎么用 | Few-Shot：在Prompt中放多个"输入→输出"示例，模型据此推理新输入的输出。 |
| 原理和工作流程 | 96层Decoder，12288维隐藏层，96个注意力头（每头128维），上下文窗口2048 tokens，训练数据约300B tokens。In-Context Learning的核心是在Prompt中提供几个示例，模型通过注意力机制从上下文中学习任务模式。三种推理模式：Zero-Shot（0示例）、One-Shot（1示例）、Few-Shot（2-64示例），均不更新参数，区别于Fine-Tuning（全量数据更新参数）。 |
| 缺点 | 训练数据300B tokens按Chinchilla定律训练不足；上下文窗口仅2048 tokens；生成内容存在有害和偏见问题。 |

### 4.4 InstructGPT：RLHF对齐

| 维度 | 内容 |
|------|------|
| 是什么 | 2022年1月OpenAI发布的对齐模型，通过RLHF三阶段流程将人类偏好注入模型训练，证明对齐训练比单纯扩大模型更有效。 |
| 能做什么 | 让模型学会遵循指令；显著减少幻觉和有害输出；1.3B参数的InstructGPT在用户偏好上优于175B的GPT-3。 |
| 怎么用 | 三阶段：SFT（监督微调）→RM（奖励模型训练）→PPO（强化学习优化）。 |
| 原理和工作流程 | 阶段一SFT：人类标注者编写高质量Prompt和理想回答，在GPT-3上微调产出SFT模型。阶段二RM：SFT模型对每个Prompt生成K个回答，人类排序后用Bradley-Terry模型训练奖励模型。阶段三PPO：以RM为奖励信号用PPO算法优化SFT策略，加入KL散度惩罚防止偏离SFT太远。效果：指令遵循从弱到强，幻觉显著减少，有害性大幅降低。 |
| 缺点 | 依赖大量人工标注，成本高；PPO训练不稳定，超参数敏感；需同时维护4个模型，显存开销大。 |

### 4.5 GPT-4：多模态突破

| 维度 | 内容 |
|------|------|
| 是什么 | 2023年3月发布的多模态大语言模型，支持文本加图像输入，推理能力显著增强，采用多层安全对齐机制。 |
| 能做什么 | 理解图表、照片、截图、手写内容；数学逻辑编程推理大幅提升；多语言能力增强；律师资格考试前10%。 |
| 怎么用 | 输入文本加图像，通过System Prompt控制模型行为，模型按指令生成多模态回答。 |
| 原理和工作流程 | 上下文窗口8K/32K tokens。推测采用MoE架构约1.76万亿参数，每次推理只激活部分专家。关键技术包括可预测扩展（小模型预测大模型性能）、多阶段训练（预训练→SFT→RLHF→安全训练）、System Prompt精确控制行为。GPT-4o（2024年5月）实现原生多模态，文本图像音频统一处理，端到端训练无需独立语音识别模块，响应速度320ms。 |
| 缺点 | 架构和参数量未公开；推理成本高；多模态对齐仍存在幻觉；闭源无法本地部署。 |

### 4.6 GPT系列技术演进总结

| 维度 | 内容 |
|------|------|
| 是什么 | 梳理GPT-1到GPT-4o的技术演进脉络，总结每个版本的核心创新和关键突破。 |
| 能做什么 | 展示从117M到万亿参数的规模演进；归纳预训练微调、Zero-Shot、In-Context Learning、RLHF、多模态五大技术里程碑。 |
| 怎么用 | 对照演进表：GPT-1（预训练+微调，117M）→GPT-2（Zero-Shot，1.5B）→GPT-3（ICL，175B）→InstructGPT（RLHF，1.3B~175B）→GPT-4（多模态+推理）。 |
| 原理和工作流程 | GPT-1证明生成式预训练有效性；GPT-2验证规模越大能力越强；GPT-3展示涌现能力和In-Context Learning；InstructGPT证明对齐训练比扩大模型更有效（1.3B优于175B）；GPT-4实现多模态和复杂推理突破；GPT-4o实现原生多模态实时交互。每次演进都在规模、训练方法或模态上有质的飞跃。 |
| 缺点 | 演进总结偏向事后归纳，实际研发路径更复杂；GPT-4之后的技术细节不透明；演进规律不一定适用于其他模型系列。 |

## 五、LLaMA系列模型

### 5.1 LLaMA-1：开源首发与Chinchilla定律

| 维度 | 内容 |
|------|------|
| 是什么 | Meta于2023年2月开源的大语言模型系列，以更小参数规模达到与闭源模型相当性能，核心理念是用更多数据训练较小模型。 |
| 能做什么 | 7B到65B全尺寸覆盖；严格遵循Chinchilla定律（65B用1.4T tokens训练）；LLaMA-13B在多数基准上超过GPT-3（175B）。 |
| 怎么用 | 架构改进：Pre-Norm+RMSNorm+RoPE+SwiGLU+AdamW+Cosine调度。 |
| 原理和工作流程 | RMSNorm去掉LayerNorm的均值中心化，仅用均方根归一化，计算量减少7%~64%。SwiGLU引入门控机制：SwiGLU(x) = Swish(x×W1)⊙(x×W2)×W3，自适应选择信息。训练数据多样：CommonCrawl(67%)、C4(15%)、GitHub(4.5%)、Wikipedia(4.5%)等。LLaMA-65B用1.4T tokens训练，接近Chinchilla最优配比（65B×20=1.3T），证明数据质量比扩大参数更关键。 |
| 缺点 | 仅研究使用许可，不支持商用；上下文窗口仅2048 tokens；词表32K对中文支持差。 |

### 5.2 LLaMA-2：GQA与商用许可

| 维度 | 内容 |
|------|------|
| 是什么 | Meta于2023年7月发布的第二代开源大模型，引入GQA注意力、商用许可和完整RLHF对齐流程。 |
| 能做什么 | 70B版本采用GQA降低KV Cache显存；支持商用许可（月活超7亿需单独申请）；提供LLaMA-2 Chat对话版本；上下文扩展到4096 tokens。 |
| 怎么用 | 训练流程：预训练（2T tokens）→SFT（27,540条对话）→拒绝采样微调（多轮迭代）→PPO强化学习。 |
| 原理和工作流程 | 三大核心创新：GQA分组查询注意力（70B版本）大幅降低KV Cache显存占用；RLHF对齐训练含Safety RM和Helpfulness RM双模型，加入Ghost Attention支持多轮对话指令遵循；商用许可催生庞大开源微调生态。安全策略包括训练数据过滤、安全专用RM、350人红队测试、输入输出双重安全过滤。 |
| 缺点 | 7B/13B版本仍用MHA非GQA；词表仍为32K；商用许可条款对大型企业有限制。 |

### 5.3 LLaMA-3：规模与上下文突破

| 维度 | 内容 |
|------|------|
| 是什么 | Meta于2024年4月发布的第三代开源大模型，训练数据增至15T tokens，采用128K词表TikToken分词器，支持128K上下文。 |
| 能做什么 | 8B/70B/405B全尺寸覆盖；128K超长上下文（3.1版本）；多轮后训练流程（SFT+拒绝采样+DPO）；Needle In A Haystack检索准确率超95%。 |
| 怎么用 | 后训练流程：第一轮SFT+拒绝采样+DPO，第二轮在新数据上重复并加入能力特定数据。 |
| 原理和工作流程 | 训练数据从2T增长到15T tokens（提升7.5倍）。放弃SentencePiece改用TikToken BPE，词表从32K扩展到128K，中文压缩率提升约2倍，同样文本比LLaMA-2少用约30% tokens。上下文扩展采用RoPE基础旋转加位置插值，渐进式从8K扩展到128K。多轮后训练在多轮数据上重复SFT+DPO，并加入代码、数学、推理能力特定数据。 |
| 缺点 | 405B版本部署成本极高；128K上下文的推理显存压力大；过度训练策略增加了一次性训练成本。 |

### 5.4 GQA原理详解：MHA vs MQA vs GQA

| 维度 | 内容 |
|------|------|
| 是什么 | 三种注意力机制对比：MHA每个头独立K/V，MQA所有头共享1组K/V，GQA将Q头分组每组共享1组K/V，在显存和性能间取平衡。 |
| 能做什么 | MHA质量最好但显存最高；MQA显存最低但质量下降明显；GQA显存大幅降低且质量接近MHA。 |
| 怎么用 | 以LLaMA-2 70B为例：MHA KV Cache=80GB，GQA(n_kv_heads=8) KV Cache=10GB，节省87.5%。 |
| 原理和工作流程 | KV Cache显存公式：Memory = 2×n_layers×n_kv_heads×d_head×seq_len×2bytes。MHA的KV头数等于Q头数，显存最高；MQA所有头共享1组K/V，显存降至1/n但表达能力受损；GQA将Q头分组，每组共享1组K/V，KV头数m在1到n之间。GQA-8（8个KV头）性能接近MHA-64（64个KV头），但KV Cache显存仅为1/8。LLaMA-2/3、Mistral均采用GQA。 |
| 缺点 | GQA的KV头数选择需在显存和性能间权衡；MQA质量下降明显不推荐；GQA实现比MHA略复杂。 |

### 5.5 训练数据策略：数据量、数据质量与Scaling Law

| 维度 | 内容 |
|------|------|
| 是什么 | LLaMA系列验证"数据为王"理念的训练数据策略，涵盖数据量增长、过度训练、数据质量清洗和Scaling Law修正。 |
| 能做什么 | 指导训练数据量与模型规模的配比；通过过度训练小模型换取推理效率；设计数据清洗和质量过滤流程。 |
| 怎么用 | 数据量趋势：GPT-3(175B/300B tokens)→LLaMA-1(65B/1.4T)→LLaMA-2(70B/2T)→LLaMA-3(70B/15T)。 |
| 原理和工作流程 | 过度训练的理论依据：Chinchilla定律给的是训练阶段计算最优配置，但推理是持续成本。训练8B模型用15T tokens（成本略高于70B最优配置），推理成本仅为70B的1/9，性能达70B的80-90%。数据清洗流程：原始收集→质量过滤（启发式规则+模型打分+安全过滤）→去重（精确MD5+模糊MinHash+LSH）→数据混合（按领域比例）→课程学习（后期增加高质量数据比例）。修正后的实践：数据质量>数据数量>模型规模。 |
| 缺点 | 过度训练增加一次性训练成本；数据清洗流程复杂且耗时；数据混合比例的最优值依赖经验调试。 |

| 怎么用 | 对照开源vs闭源对比表，根据场景选择：私有部署/垂直领域/成本敏感选开源，追求极致性能选闭源。 |
| 原理和工作流程 | 开源生态四个层面影响：微调生态（Alpaca用Self-Instruct数据，Vicuna用ShareGPT对话数据）；架构衍生（Mistral加滑动窗口注意力，CodeLlama加代码数据继续训练）；工具链成熟（vLLM高效推理，llama.cpp边缘部署，Ollama一键部署）；商业影响（降低门槛、数据隐私、成本控制）。开源与闭源差距正在缩小，LLaMA-3.1 405B多项基准接近GPT-4。 |
| 缺点 | 开源模型性能仍略低于闭源SOTA；迭代速度依赖社区和原团队；开源许可条款可能变化。 |

## 六、Qwen系列模型

### 6.1 Qwen架构特点

| 维度 | 内容 |
|------|------|
| 是什么 | 阿里巴巴开源的大语言模型系列，基于LLaMA架构针对中文和多语言场景深度优化，采用152K大词表和YaRN长度外推。 |
| 能做什么 | 中文编码效率显著提升（7 tokens vs LLaMA-2的15 tokens）；支持32K到128K上下文外推；原生集成CLIP视觉编码器支持多模态。 |
| 怎么用 | 架构：Decoder-Only+Pre-Norm+RMSNorm+RoPE+SwiGLU+GQA，大词表151,936 tokens，YaRN长度外推。 |
| 原理和工作流程 | 大词表设计（152K）是中文能力出色的关键：LLaMA-2的32K词表将中文拆成字节级碎片（"人工智能"约15 tokens），Qwen的152K词表完整保留中文常用词（约7 tokens），效率提升2倍以上。YaRN通过调整RoPE旋转基频实现长度外推：低频维度用插值平滑过渡，高频维度保持原始RoPE，中频维度线性混合，从4K训练长度外推到32K+性能损失极小。Qwen-VL集成CLIP ViT-Large视觉编码器加Cross-Attention适配器。 |
| 缺点 | 大词表导致Embedding层参数增多（152K×4096≈6.2亿，占8B模型7.8%）；YaRN外推在极长序列上仍有性能衰减。 |

### 6.2 Qwen-1.5与Qwen-2演进

| 维度 | 内容 |
|------|------|
| 是什么 | Qwen系列的两次重大升级：Qwen-1.5覆盖0.5B到110B全尺寸，Qwen-2在多语言和长上下文方向突破。 |
| 能做什么 | Qwen-1.5提供端侧到高性能全尺寸覆盖含MoE版本；Qwen-2覆盖29种语言，支持128K上下文，HumanEval pass@1达72%（7B版本）。 |
| 怎么用 | 对照性能表：Qwen-2 72B在MMLU(82.1)、HumanEval(86.0)、GSM8K(85.8)、C-Eval(86.1)上均优于LLaMA-3 70B。 |
| 原理和工作流程 | Qwen-1.5覆盖0.5B到110B全尺寸，7B以上采用GQA，含MoE版本（总参数14B激活2.7B）。Qwen-2核心改进：多语言能力覆盖29种语言（非中英文比例大幅提升）；上下文窗口最大128K（YaRN+Dual Chunk Attention）；代码能力加入大量高质量代码数据；数学能力加入数学推理数据；GQA全面采用（7B以上全部）。Qwen-2 7B在C-Eval上78.4远超LLaMA-3 8B的60.1。 |
| 缺点 | 全尺寸覆盖增加维护成本；128K上下文的实际有效利用依赖任务类型；小模型版本性能受限。 |

### 6.3 Chat/Code/Math/Coder变体

| 维度 | 内容 |
|------|------|
| 是什么 | Qwen系列提供的任务专用变体矩阵，包括Chat、Coder、Math、VL、Audio、MoE等，满足不同场景需求。 |
| 能做什么 | Coder支持92种编程语言和64K代码上下文；Math的GSM8K准确率85.4%（7B）；VL支持图像理解和OCR；Audio支持语音识别；MoE总参数14B激活2.7B。 |
| 怎么用 | 变体训练：代码数据继续预训练→代码指令微调→代码偏好对齐（用代码执行结果作奖励信号）。 |
| 原理和工作流程 | 各变体基于基座模型分阶段训练：Qwen-Coder先在92种编程语言500B tokens上继续预训练，再做代码指令微调（补全、修复、解释、生成），最后用代码执行通过率作为奖励信号做偏好对齐。Qwen-Math在大量数学竞赛题和推理过程上训练。Qwen-VL集成CLIP ViT加Adapter，支持2D位置编码。Qwen-Audio集成Whisper Encoder。Qwen-MoE总参数14B激活2.7B，推理速度接近2.7B模型。 |
| 缺点 | 变体增多增加选择复杂度；专用变体在通用任务上可能不如通用版本；多模态变体的视觉/音频能力仍弱于专用模型。 |

### 6.4 Qwen与LLaMA对比

| 维度 | 内容 |
|------|------|
| 是什么 | 当前最重要的两个开源大模型系列的全方位对比，涵盖架构、能力、设计哲学和选型建议。 |
| 能做什么 | 对比架构差异（词表、位置编码、多模态）；量化各维度性能差异；提供场景化选型建议。 |
| 怎么用 | 选型表：中文场景选Qwen-2，英文场景选LLaMA-3，多模态选Qwen-VL，端侧选Qwen-2 0.5B/1.5B。 |
| 原理和工作流程 | 架构共性：均基于Decoder-Only+Pre-Norm+RMSNorm+RoPE+SwiGLU+GQA。差异：Qwen词表152K（LLaMA-3为128K），Qwen用YaRN外推，Qwen原生支持多模态，小模型用tie_word_embeddings共享权重。能力对比：中文C-Eval Qwen-2 72B(86.1)远超LLaMA-3 70B(72.3)；多语言Qwen-2(78.8)远超LLaMA-3(62.4)；英文MMLU两者接近。设计哲学：LLaMA追求简洁高效和Scaling Law，Qwen追求中文多语言优先和大词表换编码效率。 |
| 缺点 | 对比基于公开基准，实际业务表现可能不同；两系列迭代速度快，对比结果时效性有限；选型建议较粗略，需结合具体业务验证。 |

## 七、Tokenization分词技术

### 7.1 为什么需要分词

| 维度 | 内容 |
|------|------|
| 是什么 | 将文本切分为Token并映射为数字ID的过程，是大语言模型处理原始文本的前置步骤。 |
| 能做什么 | 在词汇表大小和序列长度间取得平衡；处理未登录词（OOV）问题；影响模型编码效率和上下文有效长度。 |
| 怎么用 | 现代LLM统一使用子词级分词：字符级序列太长丢失语义，词级词汇表巨大有OOV问题，子词级平衡两者。 |
| 原理和工作流程 | 三种分词粒度对比：字符级词汇表极小但序列太长丢失语义；词级语义完整但词汇表巨大且有OOV问题；子词级（如"un"+"fortun"+"ately"）在粒度和词汇表间平衡，高频词保持完整，低频词被拆分。子词级成为现代LLM统一选择。 |
| 缺点 | 子词切分方式依赖分词器训练，不同分词器对相同文本产生不同Token序列，影响模型间可比性。 |

### 7.2 BPE（Byte Pair Encoding）

| 维度 | 内容 |
|------|------|
| 是什么 | 最广泛使用的子词分词算法，基于频率统计迭代合并最高频字符对，被GPT系列和LLaMA等模型采用。 |
| 能做什么 | 高频词保持完整，低频词被拆分；有效处理OOV问题；训练简单不需要语言模型。 |
| 怎么用 | 初始词汇表=所有字符→统计相邻字符对频率→合并最高频对→重复直到达到目标词汇表大小。 |
| 原理和工作流程 | 训练过程：从所有字符开始，统计所有相邻字符对频率，合并频率最高的字符对（如"l"+"o"→"lo"），更新词汇表，重复统计和合并直到达到预定词汇表大小（如50,000）。编码时用贪婪最长匹配将文本切分为词汇表中的子词。BPE基于频率统计，高频组合优先合并，低频词被拆分为多个子词。 |
| 缺点 | 纯频率驱动可能合并语义不相关的字符对；对多语言支持一般，非英语语言编码效率低；需要预分词处理空格。 |

### 7.3 WordPiece

| 维度 | 内容 |
|------|------|
| 是什么 | Google在BERT中提出的子词分词算法，与BPE类似但合并策略基于似然度最大化而非频率。 |
| 能做什么 | 选择能使训练数据似然度最大化的字符对合并；用"##"标记词内延续；BERT词汇表约30,000个token。 |
| 怎么用 | Score(A,B) = count(A,B)/(count(A)×count(B))，选择Score最大的字符对合并。 |
| 原理和工作流程 | BPE选择频率最高的字符对，WordPiece选择似然度增益最大的字符对。评分公式Score(A,B)=count(A,B)/(count(A)×count(B))，分子是共现频率，分母是各自独立频率的乘积，偏向选择共现频率高但各自频率适中的对。BERT的WordPiece处理："The transformer is powerful"→["The","trans","##former","is","power","##ful"]，"##"表示该token是前一个词的延续。 |
| 缺点 | 似然度计算比BPE复杂；仍需预分词处理空格；词汇表较小（30K），多语言支持一般。 |

### 7.4 SentencePiece

| 维度 | 内容 |
|------|------|
| 是什么 | Google开发的分词工具，核心特点是直接处理原始文本不依赖预分词，被T5、LLaMA、Mistral等模型采用。 |
| 能做什么 | 直接将文本当字符流处理无需预分词；用特殊字符"▁"替代空格；支持BPE和Unigram两种算法；内置NFKC Unicode规范化。 |
| 怎么用 | SentencePiece BPE模式（LLaMA用）：文本→字符流→BPE合并；Unigram模式（T5用）：从大词汇表逐步删除低概率token。 |
| 原理和工作流程 | 传统方法先按空格分词再对每个词应用BPE/WordPiece，SentencePiece直接将文本当作字符流处理。BPE模式与标准BPE相同但不预分词。Unigram模式：初始化大词汇表（所有字符+常见子串），对语料计算所有可能分词路径的概率，选择最可能分词，删除概率最低的x% token，重复直到词汇表缩小到目标大小。字节回退机制遇到未知字符时回退到字节级编码。 |
| 缺点 | "▁"特殊字符在下游处理时需额外注意；Unigram模式训练比BPE复杂；对数字处理可能拆分过细。 |

### 7.5 三种分词方法对比

| 维度 | 内容 |
|------|------|
| 是什么 | BPE、WordPiece、SentencePiece三种主流子词分词算法在合并策略、预分词依赖、空格处理等维度的系统对比。 |
| 能做什么 | 指导分词器选择；明确各算法的合并策略差异；关联分词器与代表模型的对应关系。 |
| 怎么用 | 对照对比表：BPE频率最高（GPT系列），WordPiece似然度最大（BERT），SentencePiece不需预分词（T5/LLaMA）。 |
| 原理和工作流程 | BPE选择频率最高的字符对合并，需预分词，依赖预分词处理空格，词汇表50K-100K。WordPiece选择似然度最大的字符对合并，需预分词，词汇表30K。SentencePiece支持BPE或Unigram两种算法，不需要预分词，内置空格处理（用"▁"替代），词汇表32K-100K，多语言支持优秀。 |
| 缺点 | 三种方法各有局限，没有 universally 最优方案；实际选择更多依赖模型传统和工程惯性而非严格对比。 |

### 7.6 分词对模型性能的影响

| 维度 | 内容 |
|------|------|
| 是什么 | 分词质量直接影响模型编码效率、多语言支持、数字代码处理和上下文有效利用的分析。 |
| 能做什么 | 量化分词器对编码效率的影响（更少token=更长有效上下文）；指导多语言分词器设计；平衡词汇表大小和编码效率。 |
| 怎么用 | 对照模型分词器表：GPT-2 BPE(50K)，BERT WordPiece(30K)，LLaMA SentencePiece(32K)，Qwen(152K)。 |
| 原理和工作流程 | 编码效率：好的分词器用更少token表示相同语义，意味着更长的有效上下文。英文"The cat sat on the mat"用BPE约7 tokens，字符级22 tokens。中文"人工智能正在改变世界"用GPT-2 BPE约12 tokens，专用分词器约6 tokens。多语言支持取决于分词器对非英语语言的覆盖。词汇表平衡：太大增加Embedding层参数，太小降低编码效率。主流模型趋势是增大词表（GPT-4o约200K）以提升多语言效率。 |
| 缺点 | 增大词表以提升编码效率的代价是Embedding层参数增多；不同分词器产生的Token序列不可直接比较；分词器一旦训练完成难以修改。 |
