## 第一段：RLHF 总览与三阶段框架

### 1.1 为什么需要 RLHF

| 维度 | 内容 |
|------|------|
| 是什么 | 预训练模型通过最大化似然学到的分布P(x)与人类期望分布P(y\|x)存在偏差，RLHF用人类反馈将二者对齐的技术。 |
| 能做什么 | 解决预训练模型的有害输出、幻觉、不遵循指令等问题；让1.3B的InstructGPT在用户偏好上优于175B的GPT-3。 |
| 怎么用 | 将人类偏好数据转化为奖励信号，通过强化学习优化策略模型使其生成符合人类期望的回答。 |
| 原理和工作流程 | 预训练目标是最大化P(x)（语料中下一个词概率），但人类期望的是P(y\|x)（给定指令后的优质回答概率），两者存在偏差。RLHF通过三阶段将人类偏好注入模型：SFT学习指令遵循、RM学习偏好排序、PPO用RM信号优化策略。核心机制是用偏好排序代替绝对评分，因为让标注员比较两个回答的优劣比给每个回答打分更容易且更一致。 |
| 缺点 | 依赖大量人工标注成本高；PPO训练不稳定超参数敏感；需同时维护多个模型显存开销大；标注者偏好可能不一致引入噪声。 |

### 1.2 RLHF 的起源与演进

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF从2017年TAMER框架到2022年InstructGPT再到2023年ChatGPT的发展脉络，以及DPO等新兴方法的演进。 |
| 能做什么 | 梳理RLHF技术从概念到成熟的时间线；定位InstructGPT三阶段框架为当前主流方案；介绍DPO等简化替代方案。 |
| 怎么用 | 对照时间线：2017 TAMER(概念)→2019 contextual bandits→2022 InstructGPT(三阶段框架)→2023 ChatGPT(产品化)→2023 DPO(简化)。 |
| 原理和工作流程 | TAMER（2017）提出从人类反馈学习奖励函数的概念但未用于LLM。2019-2021年OpenAI在上下文赌博机和小模型上验证RLHF可行性。InstructGPT（2022）提出SFT+RM+PPO三阶段框架，证明1.3B参数模型在用户偏好上优于175B的GPT-3，奠定RLHF技术范式。ChatGPT（2023）将InstructGPT规模化成为现象级产品。2023年后DPO绕过RM直接用偏好数据训练，RLAIF用AI替代人工反馈，进一步降低成本。 |
| 缺点 | 演进脉络简化实际路径更复杂；早期方法与现代LLM差距大可比性低；技术选型需结合具体场景不能仅按时间线。 |

### 1.3 RLHF 三阶段全景

| 维度 | 内容 |
|------|------|
| 是什么 | InstructGPT定义的RLHF三阶段框架：SFT（监督微调）、RM（奖励模型训练）、PPO（强化学习优化），每阶段有不同的输入输出和目标。 |
| 能做什么 | SFT将预训练模型转化为指令遵循模型；RM从偏好数据学习人类偏好打分函数；PPO用RM信号优化策略模型生成更好回答。 |
| 怎么用 | 阶段一SFT：用instruction-output对微调预训练模型产出SFT模型；阶段二RM：用prompt-choosen-rejected偏好对训练奖励模型；阶段三PPO：用PPO算法以RM奖励优化SFT策略。 |
| 原理和工作流程 | 阶段一SFT的输入是instruction-output对，输出是SFT模型π_SFT，目标是最小化负对数似然L=-Σlog π_SFT(y\|x)。阶段二RM的输入是prompt和模型生成的K个回答的人工排序，输出是奖励模型r_φ(x,y)，目标是最大化偏好对的似然L=-log σ(r(x,y_w)-r(x,y_l))。阶段三PPO的输入是SFT模型和RM，输出是对齐后的策略模型π_RL，目标函数含RM奖励项和KL惩罚项。 |
| 缺点 | 三阶段流程长，每阶段都可能引入误差且误差累积；阶段间需人工干预；RM质量直接决定PPO效果，RM偏差会被放大。 |

### 1.4 三阶段的数据流与信息流

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF三阶段之间数据如何传递、信息如何流动的完整描述，涵盖各阶段的输入数据、输出产物和参数继承关系。 |
| 能做什么 | 追踪SFT模型如何作为RM训练的生成器和PPO的初始策略；RM如何作为PPO的奖励信号；SFT如何作为PPO的KL参考。 |
| 怎么用 | 数据流：SFT模型→生成K个回答→人工排序→训练RM；SFT模型→PPO初始策略+KL参考模型→RM奖励信号→优化策略。 |
| 原理和工作流程 | SFT阶段输入instruction-output数据集，微调预训练模型得到π_SFT。RM阶段用π_SFT对每个prompt生成K个回答，标注者排序后构成偏好数据集D={(x,y_w,y_l)}，训练RM得到r_φ。PPO阶段用π_SFT作为初始策略π_θ和KL参考模型π_ref，对每个prompt由π_θ采样回答，RM计算奖励r_φ(x,y)，PPO目标最大化奖励同时最小化与π_ref的KL散度。整个流程的参数继承：π_SFT→RM的Backbone(移除LM头加标量头)→PPO的π_θ和π_ref。 |
| 缺点 | 数据流长导致训练管线复杂；SFT质量差会传递到RM和PPO；RM的偏差通过奖励信号传播到最终策略。 |

## 第二段：RL 基础理论

### 2.1 马尔可夫决策过程（MDP）

| 维度 | 内容 |
|------|------|
| 是什么 | 强化学习的数学形式化框架，用五元组(S,A,P,R,γ)描述智能体与环境交互的决策过程。 |
| 能做什么 | 形式化定义状态、动作、转移概率、奖励和折扣因子；为策略评估和优化提供数学基础；连接RLHF中的序列生成问题。 |
| 怎么用 | 五元组：S状态集合、A动作集合、P(s'\|s,a)转移概率、R(s,a)奖励函数、γ∈[0,1]折扣因子。 |
| 原理和工作流程 | 智能体在状态s_t下选择动作a_t，环境根据转移概率P(s_{t+1}\|s_t,a_t)转移到新状态s_{t+1}，并给出奖励r_t=R(s_t,a_t)。智能体的目标是找到一个策略π(a\|s)最大化期望累计折扣回报E[Σγ^t r_t]。在LLM场景中：状态是已生成的token序列，动作是下一个token，转移是确定的（给定token序列和下一个token，新状态确定），奖励是RM给出的回答质量分数。 |
| 缺点 | MDP假设马尔可夫性（未来只依赖当前状态），实际LLM生成中历史信息可能重要；状态空间随序列长度指数增长；连续状态空间难以精确建模。 |

### 2.2 价值函数

| 维度 | 内容 |
|------|------|
| 是什么 | 衡量在某个状态或状态-动作对下，遵循给定策略能获得的期望累计回报的函数，分状态价值V(s)和动作价值Q(s,a)。 |
| 能做什么 | V(s)评估状态s的好坏指导策略选择；Q(s,a)评估在状态s采取动作a的好坏；两者关系Q(s,a)=R(s,a)+γV(s')。 |
| 怎么用 | V^π(s)=E[Σγ^t r_t\|s_0=s, π]；Q^π(s,a)=E[Σγ^t r_t\|s_0=s, a_0=a, π]；A^π(s,a)=Q(s,a)-V(s)为优势函数。 |
| 原理和工作流程 | 状态价值函数V^π(s)表示从状态s出发遵循策略π能获得的期望累计折扣回报。动作价值函数Q^π(s,a)表示在状态s采取动作a后遵循策略π能获得的期望回报。优势函数A^π(s,a)=Q^π(s,a)-V^π(s)衡量动作a相对于策略平均水平的好坏，A>0表示动作优于平均水平应鼓励，A<0表示劣于平均水平应抑制。在Actor-Critic架构中Critic估计V(s)或Q(s,a)，Actor根据优势函数更新策略。 |
| 缺点 | 价值函数估计需要大量采样才准确；高方差导致估计不稳定；在连续或大状态空间中需用神经网络近似，训练困难。 |

### 2.3 贝尔曼方程

| 维度 | 内容 |
|------|------|
| 是什么 | 连接当前状态价值与下一状态价值的递归方程，是值迭代和Q-Learning等算法的理论基础。 |
| 能做什么 | 将无限horizon的期望回报分解为即时奖励加下一状态折扣价值；为动态规划求解价值函数提供递推关系。 |
| 怎么用 | V(s)=Σ_a π(a\|s)[R(s,a)+γΣ_{s'}P(s'\|s,a)V(s')]；Q(s,a)=R(s,a)+γΣ_{s'}P(s'\|s,a)V(s')。 |
| 原理和工作流程 | 贝尔曼方程将价值函数递归分解：当前状态的价值等于即时奖励加上下一状态价值的折扣期望。V^π(s)=E[R(s,a)+γV^π(s')]，即当前状态价值=一步奖励+γ×下一状态价值。Q^π(s,a)=E[R(s,a)+γE_{a'~π}[Q^π(s',a')]]。最优价值函数满足贝尔曼最优方程V*(s)=max_a[R(s,a)+γΣP(s'\|s,a)V*(s')]。值迭代算法通过反复应用贝尔曼最优方程更新价值函数直到收敛。 |
| 缺点 | 贝尔曼方程需要已知转移概率P和奖励R（model-based），实际中常未知需通过采样估计；在连续空间中无法枚举所有状态。 |

### 2.4 时序差分学习（TD Learning）

| 维度 | 内容 |
|------|------|
| 是什么 | 结合蒙特卡洛和动态规划优点的无模型学习方法，用当前估计的下一状态价值作为bootstrap目标更新当前价值。 |
| 能做什么 | 无需知道环境模型（转移概率和奖励函数）；在线学习每步更新无需等待episode结束；方差低于蒙特卡洛。 |
| 怎么用 | TD(0)更新：V(s)←V(s)+α[r+γV(s')-V(s)]，其中δ=r+γV(s')-V(s)为TD误差。 |
| 原理和工作流程 | TD学习的核心是用已估计的下一状态价值V(s')作为目标的一部分来更新当前状态价值V(s)，这种自举(bootstrap)方式使其无需等待episode结束。TD(0)更新规则：V(s)←V(s)+α[r+γV(s')-V(s)]，其中δ=r+γV(s')-V(s)称为TD误差，α是学习率。TD误差衡量了当前估计与一步观察后新估计的差异，正值表示状态比预期好应增大价值，负值表示比预期差应减小价值。Q-Learning是TD学习的扩展，更新Q(s,a)←Q(s,a)+α[r+γmax_{a'}Q(s',a')-Q(s,a)]。 |
| 缺点 | 自举引入偏差（用估计更新估计），初始估计不准会传播误差；偏差-方差权衡需调节n-step或λ参数；对学习率α敏感。 |

### 2.5 蒙特卡洛 vs 时序差分

| 维度 | 内容 |
|------|------|
| 是什么 | 蒙特卡洛(MC)和时序差分(TD)两种无模型价值估计方法的对比，在更新时机、偏差方差和适用场景上的差异。 |
| 能做什么 | MC用完整episode的真实回报更新无偏差但方差大需等episode结束；TD用一步bootstrap更新有偏差但方差小可在线学习。 |
| 怎么用 | MC：V(s)←V(s)+α[G_t-V(s)]，G_t=Σγ^k r_{t+k}为完整回报；TD：V(s)←V(s)+α[r+γV(s')-V(s)]。 |
| 原理和工作流程 | 蒙特卡洛方法等待一个完整episode结束后，用实际获得的累计回报G_t作为目标更新V(s)。优点是无偏差（用真实回报），缺点是方差大（G_t是多个随机奖励的加和）且必须等episode结束。时序差分方法每步用r+γV(s')作为目标更新，优点是方差小（只有一步随机性）且可在线学习，缺点是有偏差（V(s')是估计值不是真实值）。n-step TD和TD(λ)在两者间插值：n-step TD用n步真实奖励加第n步估计值，TD(λ)用λ加权混合所有n-step。 |
| 缺点 | MC在连续任务（无终止状态）中无法使用；TD的偏差在某些情况下可能导致慢收敛；两者在非平稳环境中表现不同需根据场景选择。 |

## 第三段：策略梯度方法

### 3.1 策略梯度定理

| 维度 | 内容 |
|------|------|
| 是什么 | 直接对策略参数求梯度以最大化期望回报的理论基础，证明策略梯度等于优势函数与score function的期望。 |
| 能做什么 | 为REINFORCE、Actor-Critic、PPO等算法提供理论支撑；允许直接优化随机策略无需价值函数。 |
| 怎么用 | ∇J(θ)=E_{τ~π_θ}[Σ_t ∇log π_θ(a_t\|s_t)·A^π(s_t,a_t)]，其中A为优势函数。 |
| 原理和工作流程 | 策略梯度定理推导：目标函数J(θ)=E_{τ~π_θ}[Σγ^t r_t]为期望累计回报。对J求梯度，利用log-derivative trick将∇π_θ转化为π_θ·∇log π_θ，得到∇J(θ)=E[∇log π_θ(τ)·R(τ)]。进一步用优势函数A^π(s_t,a_t)=Q^π(s_t,a_t)-V^π(s_t)替代回报R，减小方差。直觉：∇log π_θ(a\|s)是增加动作a概率的梯度方向，乘以正优势A>0则增大好动作概率，乘以负优势A<0则减小坏动作概率。 |
| 缺点 | 梯度估计方差极大需大量采样；样本效率低；on-policy限制不能用旧数据；对学习率敏感易发散。 |

### 3.2 REINFORCE 算法

| 维度 | 内容 |
|------|------|
| 是什么 | 最基础的策略梯度算法，用完整episode的累计回报作为优势信号直接更新策略参数。 |
| 能做什么 | 实现最简单的策略梯度；用蒙特卡洛回报G_t作为优势估计；为后续Actor-Critic和PPO奠定基础。 |
| 怎么用 | 采样episode→计算每步回报G_t→更新θ←θ+α·∇log π_θ(a_t\|s_t)·G_t。 |
| 原理和工作流程 | REINFORCE算法流程：用当前策略π_θ采样一个完整episode τ=(s_0,a_0,r_0,s_1,...)；对episode中每一步计算回报G_t=Σ_{k=0}^{T-t}γ^k r_{t+k}；用G_t作为优势估计更新策略参数θ←θ+α·∇log π_θ(a_t\|s_t)·G_t。REINFORCE是最直接的策略梯度实现，但使用完整回报G_t导致方差极大（G_t是多个随机奖励的加和）。减去baseline V(s_t)可以减小方差：θ←θ+α·∇log π_θ(a_t\|s_t)·(G_t-V(s_t))。 |
| 缺点 | 方差极大收敛慢；必须等完整episode结束才能更新；样本效率极低；无baseline时性能很差。 |

### 3.3 Actor-Critic 架构

| 维度 | 内容 |
|------|------|
| 是什么 | 结合策略梯度和价值函数的架构，Actor负责选动作Critic负责评估动作好坏，用Critic的TD误差作为Actor的优势估计。 |
| 能做什么 | Actor网络π_θ(a\|s)输出动作概率；Critic网络V_φ(s)估计状态价值；用TD误差δ=r+γV(s')-V(s)作为优势降低方差。 |
| 怎么用 | Actor更新：θ←θ+α·∇log π_θ(a\|s)·δ；Critic更新：φ←φ+β·δ·∇V_φ(s)，其中δ=r+γV(s')-V(s)。 |
| 原理和工作流程 | Actor-Critic架构由两个网络组成：Actor网络π_θ(a\|s)参数化策略输出动作概率分布，Critic网络V_φ(s)参数化价值函数估计状态价值。Critic用TD学习更新：V_φ(s)←V_φ(s)+β·δ，其中δ=r+γV_φ(s')-V_φ(s)为TD误差。Actor用Critic的TD误差作为优势估计更新：θ←θ+α·∇log π_θ(a\|s)·δ。相比REINFORCE用蒙特卡洛回报G_t，Actor-Critic用一步TD误差δ作为优势估计，方差大幅降低但引入偏差。在LLM的PPO中Actor是策略模型π_θ，Critic是价值模型V_φ。 |
| 缺点 | 两个网络需联合训练协调困难；Critic估计不准会误导Actor；TD误差的偏差可能导致次优策略；训练不稳定需仔细调参。 |

### 3.4 A2C 与 A3C：同步与异步

| 维度 | 内容 |
|------|------|
| 是什么 | Actor-Critic的两种并行实现：A2C（同步 Advantage Actor-Critic）和A3C（异步 Advantage Actor-Critic），差异在多worker的协调方式。 |
| 能做什么 | A2C多worker同步收集数据统一更新梯度一致；A3C多worker异步独立更新无需等待但梯度有延迟；A3C不需GPU支持CPU即可。 |
| 怎么用 | A2C：N个worker同步采样→汇总梯度→统一更新→所有worker同步参数；A3C：N个worker各自采样和更新→异步推送梯度到全局模型。 |
| 原理和工作流程 | A2C（同步）：多个worker并行收集经验，等待所有worker完成一个batch后汇总梯度统一更新策略，所有worker同步到新参数。优点是梯度更新一致可利用GPU批量计算，缺点是等待最慢worker造成闲置。A3C（异步）：多个worker各自独立采样和计算梯度，异步将梯度推送到全局模型并拉取最新参数，无需等待其他worker。优点是无同步开销CPU即可运行适合大规模并行，缺点是worker用的是过期参数计算梯度存在延迟。 |
| 缺点 | A2C的同步等待造成资源闲置；A3C的异步梯度有staleness问题影响稳定性；A3C不支持GPU批量计算效率低；两者在LLM场景中较少使用。 |

## 第四段：SFT 监督微调

### 4.1 SFT 在 RLHF 中的角色

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF三阶段的第一阶段，用高质量指令-回答对微调预训练模型，使其从"续写文本"转变为"遵循指令回答问题"。 |
| 能做什么 | 教会模型理解指令并按要求生成；为RM阶段提供能生成合理回答的SFT模型；为PPO阶段提供初始策略和KL参考。 |
| 怎么用 | 准备instruction-output对数据→在预训练模型上做监督微调→输出SFT模型π_SFT。 |
| 原理和工作流程 | 预训练模型只学会续写文本不知道遵循指令。SFT通过少量（通常1万-10万条）高质量instruction-output对微调，让模型学会"理解指令→完成任务"的模式。SFT模型是RLHF后续阶段的基础：RM阶段用SFT模型生成候选回答供标注者排序；PPO阶段用SFT模型作为初始策略和KL散度参考防止偏离太远。SFT的数据质量直接决定整个RLHF的上限，低质量SFT数据会导致后续阶段无法弥补。 |
| 缺点 | 需要高质量标注数据成本高；SFT数据覆盖面不足时泛化能力受限；仅靠SFT无法教会模型哪个回答更好（缺乏比较信号）。 |

### 4.2 高质量指令数据构建

| 维度 | 内容 |
|------|------|
| 是什么 | SFT阶段高质量指令数据的构建方法，涵盖数据来源、多样性要求、格式规范和质量控制。 |
| 能做什么 | 从人工编写、开源数据集、用户日志等来源收集指令数据；覆盖多样化任务类型和领域；格式统一为instruction-input-output三元组。 |
| 怎么用 | 数据格式：{"instruction":"任务描述","input":"可选输入","output":"期望回答"}；质量标准：正确性、多样性、格式规范、长度适中。 |
| 原理和工作流程 | 数据来源三个途径：人工编写（质量最高但成本高，InstructGPT约1.3万条）、开源数据集（Alpaca、FLAN等）、用户日志（ChatGPT收集用户实际使用数据再筛选）。多样性要求覆盖分类、生成、推理、翻译、代码、创作等多种任务类型和多个领域。格式统一为instruction-input-output三元组，instruction描述任务，input为可选的输入内容，output为期望的回答。质量控制包括人工审核、格式校验、去重去噪。InstructGPT的SFT数据约1.3万条，质量远比数量重要。 |
| 缺点 | 人工编写成本高规模有限；开源数据集质量参差不齐可能有错误；用户日志含噪声需大量筛选；多样性难以量化评估。 |

### 4.3 Self-Instruct：自动生成指令数据

| 维度 | 内容 |
|------|------|
| 是什么 | 利用强模型（如GPT-3）自动生成指令-回答对来扩充SFT数据集的方法，降低人工标注成本。 |
| 能做什么 | 从175个种子指令自动生成52K条指令数据；用强模型同时生成指令和回答；通过去重和质量过滤获得有效数据。 |
| 怎么用 | 种子指令→强模型生成新指令→过滤低质量→强模型生成回答→去重→获得SFT数据。 |
| 原理和工作流程 | Self-Instruct流程：准备175个种子指令作为few-shot示例；用强模型（GPT-3）根据种子指令生成新指令；用规则过滤低质量指令（太短、重复、非指令等）；用强模型为每个指令生成回答；对指令-回答对做ROUGE去重移除相似度高的重复项。Alpaca用Self-Instruct从175个种子生成52K条指令数据，成本仅约500美元，微调LLaMA-7B后性能接近GPT-3.5的很多能力。 |
| 缺点 | 生成的数据质量依赖强模型能力可能引入偏差；自动生成可能产生幻觉或错误回答；去重不充分时存在冗余；缺乏真正的人工创意。 |

### 4.4 SFT 训练细节

| 维度 | 内容 |
|------|------|
| 是什么 | SFT微调的训练细节，包括损失函数计算、学习率调度、epoch选择和灾难性遗忘的应对。 |
| 能做什么 | 只对output部分计算损失不对instruction部分计算；学习率低于预训练使用cosine调度；训练1-3个epoch避免过拟合。 |
| 怎么用 | 损失函数：L=-Σ_{t∈output} log π(y_t\|y_<t, x)；学习率：1e-5到5e-5，cosine调度加warmup；epoch：1-3轮。 |
| 原理和工作流程 | 损失函数设计：输入instruction+input后模型生成output，损失只计算output部分的token损失，instruction部分作为条件不计算损失（通过label masking实现）。学习率：SFT通常用比预训练更小的学习率（1e-5到5e-5），使用cosine调度加warmup防止训练初期不稳定。Epoch选择：通常1-3个epoch足够，过多epoch会导致过拟合和灾难性遗忘。灾难性遗忘应对：混入部分预训练数据、使用较小的学习率、使用PEFT方法如LoRA减少参数更新量。 |
| 缺点 | epoch过多导致过拟合和灾难性遗忘；学习率选择敏感；只对output计算损失可能遗漏instruction中的学习信号；小数据集容易过拟合。 |

## 第五段：Reward Model 与 Bradley-Terry 模型

### 5.1 奖励模型的核心任务

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF第二阶段训练的奖励模型，输入prompt和response输出一个标量奖励分数，反映回答质量的好坏。 |
| 能做什么 | 学习人类偏好排序的打分函数；为PPO阶段提供奖励信号；将偏好数据转化为可微分的奖励标量。 |
| 怎么用 | 输入(x,y)→RM→输出标量r(x,y)；训练目标使r(x,y_w)>r(x,y_l)的似然最大化。 |
| 原理和工作流程 | 奖励模型的核心任务是从人类偏好排序中学习一个打分函数r_φ(x,y)，使好的回答得分高于差的回答。RM架构通常取SFT模型移除最后的LM Head（语言模型头），替换为一个标量输出头（linear层映射到维度1），输出一个实数作为奖励分数。RM的输入是prompt和response的拼接，输出是该回答的质量分数。训练数据是偏好对(x,y_w,y_l)其中y_w是人类偏好的回答y_l是被拒绝的回答。RM需要能泛化到训练集之外的prompt和response。 |
| 缺点 | RM只能学到相对偏好无法学到绝对质量；RM的泛化能力有限对分布外输入可能给出错误奖励；RM容易被策略模型钻空子产生reward hacking。 |

### 5.2 偏好数据收集

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF第二阶段收集人类偏好数据的方法，标注者对同一prompt的多个回答进行排序，构成偏好对用于训练RM。 |
| 能做什么 | 对每个prompt收集K个候选回答；标注者对K个回答排序；将排序转换为C(K,2)个偏好对(y_w,y_l)。 |
| 怎么用 | 标注流程：给定prompt→SFT模型生成K个回答→标注者排序→转换为偏好对(x,y_w,y_l)。 |
| 原理和工作流程 | 偏好数据收集流程：对每个prompt，用SFT模型采样生成K个回答（通常K=4或9）；标注者对K个回答从最好到最差排序；将排序转换为所有两两组合的偏好对，K=4产生C(4,2)=6个偏好对，K=9产生C(9,2)=36个偏好对。标注指南需要明确定义"好"的标准：有用性（准确、完整、相关）、无害性（不含有害、偏见、误导内容）、诚实性（不编造信息）。InstructGPT收集约3.3万条偏好数据。让标注者排序比打分更容易且一致性更高，因为相对比较比绝对评分更稳定。 |
| 缺点 | 标注者偏好不一致引入噪声；标注成本高尤其大规模数据；K个回答质量都差时排序意义有限；标注指南的偏差会影响RM。 |

### 5.3 Bradley-Terry 偏好模型

| 维度 | 内容 |
|------|------|
| 是什么 | 将偏好排序建模为概率的统计模型，假设回答y_w优于y_l的概率等于r(y_w)/(r(y_w)+r(y_l))，经logit变换变为sigmoid(r(y_w)-r(y_l))。 |
| 能做什么 | 将偏好排序转化为可微分的概率；推导RM的交叉熵训练损失；为RM训练提供理论框架。 |
| 怎么用 | P(y_w>y_l)=σ(r(x,y_w)-r(x,y_l))；损失L=-log σ(r(x,y_w)-r(x,y_l))。 |
| 原理和工作流程 | Bradley-Terry模型假设每个回答有一个潜在"实力"分数r(y)，回答y_w优于y_l的概率为P(y_w>y_l)=r(y_w)/(r(y_w)+r(y_l))。通过logit变换等价于P(y_w>y_l)=σ(r(y_w)-r(y_l))，即偏好概率等于实力差的sigmoid。将r(y)替换为RM输出r_φ(x,y)，得到RM训练的损失函数：L=-log σ(r_φ(x,y_w)-r_φ(x,y_l))。最大化此似然等价于让好回答的分数尽可能高于差回答的分数。损失关于r_φ的梯度会增大y_w的分数减小y_l的分数。 |
| 缺点 | Bradley-Terry模型假设偏好是传递的（A>B且B>C则A>C），实际人类偏好可能不传递；模型假设偏好概率只依赖分数差，忽略了偏好的不确定性；对极端偏好（极好vs极差）的建模不够灵活。 |

### 5.4 奖励模型架构

| 维度 | 内容 |
|------|------|
| 是什么 | RM的架构设计：以SFT模型为backbone移除LM Head替换为标量输出头，输入prompt加response输出奖励分数。 |
| 能做什么 | 复用SFT模型学到的语言理解能力；在最终token位置输出标量奖励；支持多种位置选择策略。 |
| 怎么用 | RM = SFT模型(去LM Head) + Scalar Head(Linear→1)；输入[x,y]拼接序列；在EOS token位置取hidden state经Scalar Head输出r(x,y)。 |
| 原理和工作流程 | RM架构基于SFT模型：保留SFT模型的所有Transformer层作为backbone（复用其语言理解能力），移除最后的LM Head（输出词表概率的层），替换为一个标量输出头（将最后一层hidden state映射到维度1的linear层）。输入是prompt和response的拼接序列[x,y]，模型前向传播后在指定位置取hidden state经Scalar Head输出标量奖励r(x,y)。位置选择有三种策略：EOS位置（最常用，取response结束位置的hidden state）、最后一个token位置、response所有token的平均。RM参数量与SFT模型相同（backbone加少量Scalar Head参数）。 |
| 缺点 | RM参数量大与策略模型相同显存开销大；标量输出头表达能力有限；位置选择策略影响效果但缺乏理论指导；RM只能输出一个标量无法表达多维度偏好。 |

### 5.5 奖励攻击与 RM 的局限性

| 维度 | 内容 |
|------|------|
| 是什么 | RM的两大核心局限：reward hacking（策略模型钻RM空子输出高分但低质量的回答）和泛化能力有限（分布外输入奖励不准确）。 |
| 能做什么 | 识别reward hacking的表现（重复、过长、格式化模板）；理解RM泛化受限的原因；用KL惩罚和多样性采样缓解。 |
| 怎么用 | 缓解reward hacking：KL惩罚π_θ与π_ref的散度限制策略偏离；缓解泛化：RM训练数据覆盖多样化prompt。 |
| 原理和工作流程 | Reward hacking原因：RM只学到偏好数据的表面模式而非真正的质量标准，策略模型PPO优化会找到RM的盲区。常见表现：重复回答（RM可能偏好冗长回答）、格式化模板（RM可能偏好特定格式）、规避敏感话题（RM可能偏好安全但无用的回答）。泛化局限原因：RM训练数据有限无法覆盖所有prompt类型，分布外prompt的奖励不准确。缓解措施：KL惩罚项β·KL(π_θ\|π_ref)限制策略与SFT模型的偏离程度防止过度优化RM；RM训练数据尽可能多样化；定期更新RM用新策略生成的数据。 |
| 缺点 | KL惩罚只能缓解不能消除reward hacking；RM泛化能力受训练数据覆盖面限制；reward hacking检测困难；RM更新成本高需重新收集偏好数据。 |

## 第六段：PPO 近端策略优化

### 6.1 PPO 在 RLHF 中的角色

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF第三阶段的核心算法，用PPO近端策略优化以RM奖励为信号优化SFT策略模型，使其生成更高奖励的回答同时不偏离SFT太远。 |
| 能做什么 | 将RM的标量奖励转化为策略梯度优化信号；通过KL惩罚防止策略偏离SFT模型太远；实现对齐后的策略模型π_RL。 |
| 怎么用 | PPO输入：SFT模型(初始策略+KL参考)、RM(奖励信号)、prompt数据集；输出：对齐策略模型π_RL。 |
| 原理和工作流程 | PPO在RLHF中的角色：以SFT模型π_SFT为初始策略π_θ和KL参考模型π_ref（冻结不更新）；对每个prompt由π_θ采样回答y；RM计算奖励r_φ(x,y)；PPO目标最大化奖励同时最小化与π_ref的KL散度防止过度优化RM。PPO选择的原因：相比REINFORCE方差更小（用Critic估计优势），相比TRPO计算更高效（用clip替代约束优化），支持off-policy修正（用重要性采样比率）。PPO训练需要同时维护4个模型：策略模型π_θ、价值模型V_φ、RM、参考模型π_ref。 |
| 缺点 | 需同时维护4个模型显存开销极大；PPO训练不稳定超参数敏感；RM偏差通过奖励信号传播到策略；训练时间长成本高。 |

### 6.2 Actor-Critic 架构

| 维度 | 内容 |
|------|------|
| 是什么 | PPO在RLHF中使用的Actor-Critic架构，Actor是策略模型π_θ生成回答，Critic是价值模型V_φ估计状态价值用于计算优势降低方差。 |
| 能做什么 | Actor生成回答并接受PPO更新；Critic估计V(s)提供baseline降低梯度方差；两者联合训练互相促进。 |
| 怎么用 | Actor=策略模型π_θ(y\|x)；Critic=价值模型V_φ(s)；优势A=r+γV(s')-V(s)用于Actor更新。 |
| 原理和工作流程 | PPO的Actor-Critic架构在RLHF中具体化为：Actor是策略模型π_θ，输入prompt生成回答，参数通过PPO目标函数更新。Critic是价值模型V_φ，输入prompt（或prompt加部分回答）估计当前状态的价值，参数通过TD误差更新。Critic的作用是提供baseline V(s)计算优势函数A=r+γV(s')-V(s)，优势函数衡量当前回答相对于期望水平的好坏，正值鼓励负值抑制，相比直接用奖励r降低梯度方差。Critic通常初始化为SFT模型（或RM）并加标量输出头。 |
| 缺点 | Actor和Critic需联合训练协调困难；Critic估计不准会误导Actor更新方向；两个模型增加显存和计算开销；训练初期Critic不准导致优势估计偏差大。 |

### 6.3 PPO 的核心机制：Clip 与 KL 惩罚

| 维度 | 内容 |
|------|------|
| 是什么 | PPO的两个核心机制：Clip限制策略更新步长防止破坏性大步，KL惩罚防止策略偏离参考模型太远导致reward hacking。 |
| 能做什么 | Clip通过截断重要性采样比率r_t(θ)=π_θ/π_θ_old限制单次更新幅度在[1-ε,1+ε]范围；KL惩罚β·KL(π_θ\|π_ref)防止过度优化RM。 |
| 怎么用 | Clip目标：min(r_t·A, clip(r_t,1-ε,1+ε)·A)，ε通常0.2；KL惩罚：从奖励中减去β·KL(π_θ\|π_ref)。 |
| 原理和工作流程 | Clip机制：PPO用重要性采样比率r_t(θ)=π_θ(a\|s)/π_θ_old(a\|s)衡量新旧策略概率比。目标函数为L_CLIP=min(r_t·A, clip(r_t,1-ε,1+ε)·A)，当r_t超出[1-ε,1+ε]时截断梯度防止策略更新过大。ε通常设0.2，意味着单次更新策略概率比不超过20%变化。KL惩罚机制：从RM奖励中减去KL散度惩罚r'=r_φ(x,y)-β·KL(π_θ(y\|x)\|π_ref(y\|x))，β是KL系数。KL惩罚使策略在追求高奖励的同时不能偏离SFT参考模型太远，防止reward hacking。 |
| 缺点 | Clip的ε选择敏感太大不稳定太小收敛慢；KL系数β需动态调节固定β不适应训练过程；Clip和KL双重约束可能过度限制策略探索。 |

### 6.4 PPO-ptx：混合训练目标

| 维度 | 内容 |
|------|------|
| 是什么 | InstructGPT在PPO目标中加入预训练梯度的改进方案，在RLHF对齐的同时防止模型遗忘预训练能力。 |
| 能做什么 | 在PPO目标中加入预训练损失项γ·L_PT；防止策略模型过度优化奖励而遗忘通用语言能力；在对齐和通用能力间取平衡。 |
| 怎么用 | 总目标：L_PPO-ptx = L_PPO + γ·E[log π_θ(x)]，其中L_PT=E[log π_θ(x)]为预训练数据上的LM损失。 |
| 原理和工作流程 | 标准PPO只优化RM奖励可能导致策略模型遗忘预训练阶段学到的通用语言能力（如语法、常识、世界知识），表现为回答虽然符合RM偏好但语言质量下降。PPO-ptx在PPO目标函数中加入预训练梯度项：总目标L = L_PPO + γ·L_PT，其中L_PT是在预训练数据上计算的标准语言模型损失E[log π_θ(x)]，γ是预训练损失权重。预训练项的梯度拉回策略模型使其不忘预训练能力，PPO项的梯度推动策略模型对齐人类偏好。InstructGPT实验表明PPO-ptx在保持对齐效果的同时显著减少了通用能力的退化。 |
| 缺点 | 预训练损失权重γ需调优太大压制对齐太小无法防遗忘；需要额外的预训练数据计算增加开销；混合目标的梯度可能冲突。 |

### 6.5 PPO 训练的完整目标函数

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF中PPO训练的完整目标函数，包含RM奖励、KL惩罚、价值函数损失、熵正则化四个部分。 |
| 能做什么 | RM奖励项推动策略生成高质量回答；KL惩罚项防止策略偏离参考模型；价值损失训练Critic；熵正则化鼓励探索。 |
| 怎么用 | L = E[r_φ(x,y) - β·KL(π_θ\|π_ref)] - c_1·L_VF + c_2·S[π_θ]。 |
| 原理和工作流程 | PPO在RLHF中的完整目标函数：L = L_Policy - c_1·L_Value + c_2·S[π_θ]。策略损失L_Policy = E[min(r_t·A, clip(r_t,1-ε,1+ε)·A)] - β·KL(π_θ\|π_ref)，其中r_t是新旧策略概率比，A是优势函数，β·KL惩罚防止偏离参考模型。价值损失L_Value = E[(V_φ(s)-R_target)²]训练Critic准确估计状态价值。熵正则化S[π_θ]=E[H(π_θ(·\|s))]鼓励策略保持一定随机性防止过早收敛。c_1和c_2是价值损失和熵正则化的权重系数。优势函数A通常用GAE（Generalized Advantage Estimation）计算平衡偏差和方差。 |
| 缺点 | 目标函数包含多个项和超参数调优困难；项之间可能冲突（如奖励项和KL惩罚方向相反）；GAE的λ参数选择影响优势估计质量。 |

### 6.6 PPO 训练的工程挑战

| 维度 | 内容 |
|------|------|
| 是什么 | PPO在RLHF中的四大工程挑战：显存爆炸（4个模型同时加载）、训练不稳定、奖励尺度敏感、评估困难。 |
| 能做什么 | 量化显存需求（7B模型4个模型需数百GB）；识别训练不稳定的症状（loss震荡、KL爆炸）；设计评估方案监控对齐效果。 |
| 怎么用 | 显存优化：用LoRA减少可训练参数、DeepSpeed ZeRO分片、RM和参考模型用量化；稳定性：自适应KL系数、学习率调度、梯度裁剪。 |
| 原理和工作流程 | 显存爆炸：PPO需同时维护策略模型π_θ（训练）、价值模型V_φ（训练）、RM（推理）、参考模型π_ref（推理），7B模型4个模型需约4×14GB=56GB仅参数，加梯度和优化器状态需数百GB。训练不稳定：PPO对超参数极度敏感，学习率太大导致KL爆炸（策略急剧偏离参考模型），β太小导致reward hacking，ε太大导致训练不稳定。奖励尺度敏感：RM输出的奖励尺度不确定，需reward normalization（标准化为均值0方差1）和reward scaling。评估困难：RLHF目标（人类偏好）难以用自动指标衡量，需人工评估或LLM-as-Judge。 |
| 缺点 | 显存需求极大即使7B模型也需多卡；超参数调优耗时耗资源；训练不稳定可能突然崩溃；评估需人工或强模型成本高。 |

## 第七段：DPO 与新兴对齐技术

### 7.1 DPO 的核心动机：绕过 Reward Model

| 维度 | 内容 |
|------|------|
| 是什么 | Direct Preference Optimization，直接用偏好数据训练策略模型绕过RM和PPO的简化对齐方法，将偏好学习转化为分类问题。 |
| 能做什么 | 消除RM训练和PPO强化学习两个阶段；将RLHF三阶段简化为SFT加DPO两阶段；降低训练复杂度和不稳定性的同时性能接近PPO。 |
| 怎么用 | SFT模型作为初始策略→用偏好数据(x,y_w,y_l)直接优化DPO损失→输出对齐模型。 |
| 原理和工作流程 | DPO的核心洞察：RLHF的PPO目标（最大化RM奖励减KL惩罚）在最优解下可以解析地表达RM为策略的函数r(x,y)=β·log(π_θ(y\|x)/π_ref(y\|x))+β·log Z(x)。将此关系代入Bradley-Terry偏好模型P(y_w>y_l)=σ(r(x,y_w)-r(x,y_l))，得到DPO损失L_DPO=-log σ(β·log(π_θ(y_w\|x)/π_ref(y_w\|x)) - β·log(π_θ(y_l\|x)/π_ref(y_l\|x)))。DPO直接用偏好数据优化策略模型，无需训练RM也无需PPO强化学习，将偏好学习转化为二分类问题。 |
| 缺点 | DPO对SFT模型质量依赖更强（因无RM中间阶段）；缺乏在线探索只能用离线偏好数据；对偏好数据质量敏感；理论上不如PPO灵活（PPO可在线采样探索）。 |

### 7.2 DPO 损失函数推导

| 维度 | 内容 |
|------|------|
| 是什么 | DPO损失函数的数学推导，从RLHF的PPO目标出发通过解析求解最优RM再代入Bradley-Terry模型得到直接优化策略的损失。 |
| 能做什么 | 证明最优RM可用策略和参考模型的log-ratio表示；将偏好概率转化为策略log-ratio的sigmoid；推导DPO损失为负对数似然。 |
| 怎么用 | L_DPO = -log σ(β·log[π_θ(y_w\|x)/π_ref(y_w\|x)] - β·log[π_θ(y_l\|x)/π_ref(y_l\|x)])。 |
| 原理和工作流程 | 推导步骤：第一步，RLHF的PPO目标最大化E[r(x,y)]-β·KL(π_θ\|π_ref)，对其求导令导数为0得到最优策略π*(y\|x)=π_ref(y\|x)·exp(r(x,y)/β)/Z(x)。第二步，反解得到r(x,y)=β·log(π_θ(y\|x)/π_ref(y\|x))+β·log Z(x)，注意Z(x)在偏好概率中消去。第三步，将r代入Bradley-Terry模型P(y_w>y_l)=σ(r(x,y_w)-r(x,y_l))，Z(x)消去后得到P(y_w>y_l)=σ(β·log[π_θ(y_w\|x)/π_ref(y_w\|x)] - β·log[π_θ(y_l\|x)/π_ref(y_l\|x)])。第四步，取负对数得到DPO损失L_DPO=-log σ(β·log[π_θ(y_w\|x)/π_ref(y_w\|x)] - β·log[π_θ(y_l\|x)/π_ref(y_l\|x)])。梯度会增大y_w概率减小y_l概率同时保持与π_ref的关系。 |
| 缺点 | 推导假设最优策略可达实际中有限训练步数可能未达最优；β参数控制偏离程度选择敏感；log-ratio在策略概率接近0时数值不稳定。 |

### 7.3 DPO vs RLHF 全面对比

| 维度 | 内容 |
|------|------|
| 是什么 | DPO与RLHF（PPO）在训练流程、数据需求、计算成本、性能效果、稳定性等维度的系统对比。 |
| 能做什么 | DPO两阶段(SFT+DPO) vs RLHF三阶段(SFT+RM+PPO)；DPO无需RM和PPO训练更简单；DPO离线学习 vs PPO在线探索。 |
| 怎么用 | 选型表：资源有限/快速迭代选DPO，追求极致性能/有在线数据选PPO，两者可结合先用DPO后用PPO精调。 |
| 原理和工作流程 | 训练流程：RLHF需SFT+RM+PPO三阶段，DPO需SFT+DPO两阶段。数据需求：RLHF需SFT数据+偏好数据+prompt数据（PPO阶段），DPO只需SFT数据+偏好数据。计算成本：RLHF需4个模型（策略+Critic+RM+参考）同时训练显存大，DPO只需2个模型（策略+参考）显存小。性能效果：在多数benchmark上DPO与PPO接近，PPO在复杂对齐场景略优。稳定性：DPO是监督学习训练稳定，PPO是强化学习训练不稳定。探索方式：DPO是离线学习只用预收集偏好数据，PPO是在线学习可实时采样新回答。 |
| 缺点 | DPO缺乏在线探索能力只用离线数据；PPO训练复杂不稳定成本高；两者选型需根据资源、时间和效果需求权衡；最优方案可能是结合使用。 |

### 7.4 RLAIF：用 AI 反馈替代人类反馈

| 维度 | 内容 |
|------|------|
| 是什么 | 用AI模型（如GPT-4）替代人类标注者提供偏好反馈的方法，将RLHF的成本从人工标注降低到API调用。 |
| 能做什么 | 用强模型对候选回答排序替代人工标注；大幅降低偏好数据收集成本；规模化生成偏好数据。 |
| 怎么用 | 给定prompt和K个候选回答→用强模型(如GPT-4)按指定标准排序→将排序转换为偏好对→训练RM或DPO。 |
| 原理和工作流程 | RLAIF流程：对每个prompt用SFT模型生成K个候选回答，将prompt和K个回答发送给强模型（如GPT-4），在prompt中指定评估标准（有用性、无害性、诚实性），强模型输出排序结果。将AI排序转换为偏好对(x,y_w,y_l)后用于训练RM或直接用于DPO。RLAIF的优势：成本远低于人工标注（API调用费用约为人工标注的1/100），速度快（API调用秒级vs人工标注分钟级），可规模化。Google研究表明RLAIF训练的模型在人类评估中与RLHF训练的模型表现相当。 |
| 缺点 | 强模型的偏好可能不完全代表真实人类偏好（AI偏差）；强模型对某些领域判断可能不准确；依赖外部API成本和可用性；AI偏好可能存在系统性偏差（如偏好长回答）。 |

### 7.5 Constitutional AI：宪法式 AI 对齐

| 维度 | 内容 |
|------|------|
| 是什么 | Anthropic提出的对齐方法，用一组"宪法"原则指导模型自我批评和修正，减少对人工标注的依赖。 |
| 能做什么 | 用宪法原则让模型自我批评生成的有害回答；模型根据批评重写更安全的回答；用AI反馈（RLAIF）替代人工反馈训练。 |
| 怎么用 | 阶段一监督学习：模型生成回答→按宪法原则自我批评→重写回答→用重写数据做SFT；阶段二RLAIF：用宪法AI做偏好标注。 |
| 原理和工作流程 | Constitutional AI两阶段：阶段一监督学习（SL），模型先对有害prompt生成初始回答，然后根据预定义的宪法原则（如"回答不应包含歧视""回答应诚实承认不确定"）自我批评指出回答中的问题，最后根据批评重写更安全的回答。用（初始prompt, 重写回答）对做SFT训练。阶段二RLAIF，用两个模型实例生成回答对，一个遵循宪法原则一个不遵循，让AI评估哪个更好构成偏好对，用RLHF/DPO训练。宪法原则通常包括有益、无害、诚实等高层原则。 |
| 缺点 | 宪法原则的设计本身需要人工且可能带有设计者偏见；模型自我批评能力有限可能遗漏某些有害内容；宪法原则之间可能冲突；对复杂伦理问题的处理能力有限。 |

### 7.6 SPIN：自我博弈微调

| 维度 | 内容 |
|------|------|
| 是什么 | Self-Play fIne-tuNing，利用模型自身生成负样本与真实人类回答配对做DPO训练的方法，无需额外偏好标注。 |
| 能做什么 | 用模型自身生成的回答作为负样本y_l；用SFT数据中的人类回答作为正样本y_w；通过DPO训练让模型区分自身生成和人类回答。 |
| 怎么用 | 正样本=SFT数据中的人类回答；负样本=当前模型对同一prompt的生成回答；DPO损失训练模型偏好人类回答。 |
| 原理和工作流程 | SPIN核心思想：将SFT数据中的人类回答作为正样本y_w，用当前模型π_θ对同一prompt生成回答作为负样本y_l，构成偏好对(x,y_w_human,y_l_model)用于DPO训练。训练目标是让模型偏好人类回答而非自身生成，迫使模型学习人类回答的高质量特征。多轮迭代：每轮用更新后的模型生成新的负样本（质量逐渐提升），继续DPO训练。随着迭代模型生成质量提升，负样本与正样本差距缩小，训练信号减弱最终收敛。SPIN无需额外的偏好标注数据，只需SFT数据即可实现对齐效果。 |
| 缺点 | 模型自身生成的负样本质量可能过低无法提供有效学习信号；多轮迭代计算成本高；当模型生成质量接近人类回答时训练信号消失可能停滞；无法处理模型自身无法发现的错误类型。 |

### 7.7 KTO：从 Kahneman-Tversky 展望理论出发

| 维度 | 内容 |
|------|------|
| 是什么 | Kahneman-Tversky Optimization，基于人类前景理论的损失不对称性（对损失比收益更敏感）设计的对齐方法，只需二元反馈（好/坏）而非偏好对。 |
| 能做什么 | 只需二元反馈（好/坏标签）无需成对偏好对；利用前景理论的损失厌恶特性设计非对称损失；降低数据收集成本。 |
| 怎么用 | 正样本（好回答）损失：L_good=-log σ(β·log[π_θ(y\|x)/π_ref(y\|x)]-z_0)；负样本（坏回答）损失加入损失厌恶权重λ。 |
| 原理和工作流程 | KTO基于Kahneman-Tversky前景理论：人类对损失的敏感度约为收益的2.25倍（损失厌恶）。DPO需要成对偏好对(x,y_w,y_l)，KTO只需要单个回答加二元标签（好或坏）。KTO损失对正样本和负样本采用非对称设计：正样本（好回答）鼓励增大π_θ(y\|x)/π_ref(y\|x)的log-ratio；负样本（坏回答）减小log-ratio但权重更大（反映损失厌恶）。优势：二元反馈比偏好排序更容易收集（只需标注"好"或"坏"），数据收集成本更低，可用点赞/踩等现成反馈数据。 |
| 缺点 | 二元反馈信息量低于偏好对（丢失了相对排序信息）；损失厌恶系数λ需调优；理论假设（前景理论）在AI对齐场景的适用性待验证；与DPO相比在复杂偏好场景可能效果不足。 |

### 7.8 ORPO：无需参考模型的单阶段对齐

| 维度 | 内容 |
|------|------|
| 是什么 | Odds Ratio Preference Optimization，将SFT和对齐合并为单阶段训练的方法，无需参考模型π_ref也无需单独SFT阶段。 |
| 能做什么 | 在一个阶段同时完成SFT和对齐；用比值比（odds ratio）替代log-ratio无需参考模型；降低训练复杂度。 |
| 怎么用 | L_ORPO = L_SFT + λ·L_OR，其中L_OR=-log σ(log[odds(y_w)/odds(y_l)])，odds(y)=π_θ(y\|x)/(1-π_θ(y\|x))。 |
| 原理和工作流程 | ORPO将SFT损失和对齐损失合并：总损失L = L_SFT + λ·L_OR。L_SFT是标准语言模型损失在正样本y_w上计算，L_OR是比值比偏好损失。比值比odds(y)=π_θ(y\|x)/(1-π_θ(y\|x))衡量模型生成y的概率与非y概率的比。L_OR=-log σ(log[odds(y_w)/odds(y_l)])让正样本的比值比大于负样本。ORPO无需参考模型π_ref（DPO需要），因为用odds ratio替代了log-ratio避免了参考模型的需求。也无需单独SFT阶段，SFT损失和对齐损失同时优化。 |
| 缺点 | 单阶段训练中SFT和对齐目标可能冲突；比值比在概率接近1或0时数值不稳定；λ权重需调优；缺乏参考模型约束可能导致策略偏离预训练分布。 |

### 7.9 对齐技术全景对比

| 维度 | 内容 |
|------|------|
| 是什么 | PPO、DPO、RLAIF、Constitutional AI、SPIN、KTO、ORPO七种对齐技术在数据需求、训练复杂度、计算成本、性能上的系统对比。 |
| 能做什么 | 量化各方法的数据需求（偏好对vs二元反馈vs无需偏好）；对比训练复杂度（三阶段vs两阶段vs单阶段）；指导方法选择。 |
| 怎么用 | 选型表：性能最优选PPO，快速迭代选DPO，低成本选KTO，无偏好数据选SPIN，端到端选ORPO，减少人工选RLAIF/CAI。 |
| 原理和工作流程 | PPO：偏好对数据，三阶段(SFT+RM+PPO)，4个模型显存大，性能最优但最复杂。DPO：偏好对数据，两阶段(SFT+DPO)，2个模型显存小，性能接近PPO且简单。RLAIF：AI生成偏好对，同RLHF/DPO流程，依赖强模型API，降低人工成本。Constitutional AI：宪法原则+AI反馈，两阶段(SL+RLAIF)，自我批评重写，减少有害输出。SPIN：无需偏好数据只用SFT数据，多轮自博弈DPO，无需额外标注但效果有限。KTO：二元反馈(好/坏)，两阶段(SFT+KTO)，损失非对称，数据收集最简单。ORPO：偏好对数据，单阶段(SFT+对齐合并)，无需参考模型，最简洁。 |
| 缺点 | 各方法在不同任务和模型规模上表现可能变化；对比基于公开实验实际效果需验证；新方法不断涌现对比结果时效性有限；最优方法可能因场景而异无通用最优。 |

## 第八段：GRPO 算法

### 8.1 GRPO 的核心动机

| 维度 | 内容 |
|------|------|
| 是什么 | Group Relative Policy Optimization，DeepSeek提出的PPO简化算法，用组内相对优势替代Critic价值网络消除对独立价值模型的需求。 |
| 能做什么 | 消除Critic价值模型降低显存；用同一prompt的多个采样的平均奖励作为baseline；在数学推理任务上效果优于PPO。 |
| 怎么用 | 对每个prompt采样G个回答→计算组内相对优势A_i=(r_i-mean(r))/std(r)→用PPO clip目标更新策略，无需Critic。 |
| 原理和工作流程 | 标准PPO需要独立的Critic网络V_φ(s)估计baseline计算优势函数，Critic与策略模型规模相当增加一倍显存。GRPO的核心改进：对同一prompt x采样G个回答{y_1,...,y_G}，用组内奖励{r_1,...,r_G}的均值和标准差计算相对优势A_i=(r_i-mean(r))/std(r)。正优势表示该回答比组内平均好应鼓励，负优势表示比平均差应抑制。这种方式用组内统计量替代Critic的值函数估计，消除了对独立价值网络的需求。GRPO的baseline（组均值）天然与当前策略同步，避免了Critic估计滞后的问题。 |
| 缺点 | 需要对每个prompt采样多个回答（G通常8-16）增加计算量；组内样本数太少时优势估计方差大；仅适用于可多次采样的场景不适用于不可重复任务。 |

### 8.2 GRPO 目标函数

| 维度 | 内容 |
|------|------|
| 是什么 | GRPO的目标函数，在PPO clip目标基础上用组内相对优势替代Critic优势，并加入KL惩罚项。 |
| 能做什么 | 用组内归一化优势A_i=(r_i-mean)/std替代Critic优势；保留PPO clip机制限制更新步长；加入KL惩罚防止偏离参考模型。 |
| 怎么用 | L_GRPO = E[min(r_t·A_i, clip(r_t,1-ε,1+ε)·A_i)] - β·KL(π_θ\|π_ref)，其中A_i=(r_i-mean(r_{1:G}))/std(r_{1:G})。 |
| 原理和工作流程 | GRPO目标函数L = E_{x,y_i~π_θ}[min(r_t^i·A_i, clip(r_t^i,1-ε,1+ε)·A_i)] - β·D_KL(π_θ\|π_ref)。其中r_t^i=π_θ(y_i\|x)/π_θ_old(y_i\|x)是重要性采样比率，A_i=(r_i-mean(r_{1:G}))/std(r_{1:G})是组内相对优势。与标准PPO的差异：第一，优势A_i用组内统计量计算无需Critic网络；第二，KL惩罚直接加入目标函数（而非从奖励中减去），用KL散度的无偏估计D_KL≈β·(π_θ(y\|x)/π_ref(y\|x) - log[π_θ(y\|x)/π_ref(y\|x)] - 1)。clip机制与PPO相同限制单次更新幅度。 |
| 缺点 | 组内归一化假设组内回答具有可比性，极端情况下（所有回答都好或都差）优势信号弱；KL无偏估计的方差较大；ε和β的选择仍需调优。 |

### 8.3 GRPO 采样与训练流程

| 维度 | 内容 |
|------|------|
| 是什么 | GRPO的完整采样和训练流程，从prompt采样多个回答到计算组内优势再到策略更新的端到端过程。 |
| 能做什么 | 对每个prompt采样G个回答；用规则或RM计算每个回答的奖励；计算组内归一化优势；用PPO clip更新策略。 |
| 怎么用 | 流程：采样prompt→π_θ生成G个回答→计算奖励r_i→组内归一化A_i→PPO clip更新→（可选）迭代。 |
| 原理和工作流程 | GRPO训练流程：第一步从prompt数据集采样batch个prompt。第二步对每个prompt x用当前策略π_θ采样G个回答{y_1,...,y_G}（temperature>0保证多样性）。第三步计算每个回答的奖励r_i，奖励来源可以是RM（通用对齐）或规则（数学推理中验证答案正确性给1分错误给0分）。第四步计算组内相对优势A_i=(r_i-mean(r_{1:G}))/std(r_{1:G})，组内归一化使优势以组内均值为中心。第五步用PPO clip目标函数计算梯度更新策略参数。第六步可选迭代重复以上步骤。DeepSeek-R1在数学推理中用规则奖励（答案正确性验证）替代RM，避免了RM的训练成本和偏差。 |
| 缺点 | 每个prompt需采样G个回答计算量为标准推理的G倍；规则奖励只适用于有明确正确答案的任务（如数学）；多轮迭代需持续采样计算成本高。 |

### 8.4 DeepSeek-R1 应用案例

| 维度 | 内容 |
|------|------|
| 是什么 | DeepSeek用GRPO训练R1系列推理模型的实践案例，用规则奖励替代RM在数学和代码推理上取得突破性效果。 |
| 能做什么 | R1-Zero直接用GRPO在基座模型上训练无需SFT展现推理能力；R1在R1-Zero基础上加SFT和多领域GRPO达到OpenAI o1水平。 |
| 怎么用 | R1-Zero：基座模型→GRPO(规则奖励)→推理模型；R1：基座→SFT(R1-Zero生成数据)→GRPO(多领域)→对齐模型。 |
| 原理和工作流程 | DeepSeek-R1-Zero直接在DeepSeek-V3基座模型上用GRPO训练，不经过SFT阶段。奖励完全基于规则：数学题验证最终答案正确性，代码题运行测试用例。GRPO让模型通过自我探索学会Chain-of-Thought推理，甚至自发出现"aha moment"（模型意识到需要换思路）。R1-Zero的问题：输出可读性差（中英文混杂、格式混乱）。DeepSeek-R1改进：先用R1-Zero生成高质量推理数据做SFT提升可读性，再在数学、代码、写作等多领域上做GRPO，最后加DPO对齐。R1在AIME 2024数学竞赛上79.8% pass@1接近OpenAI o1的79.2%。 |
| 缺点 | R1-Zero的输出可读性差需额外SFT修复；规则奖励只适用于可验证答案的任务无法推广到开放式生成；训练成本高需大量采样和迭代；复现需要大规模计算资源。 |

## 第九段：DPO 微调实战

### 9.1 环境准备与数据格式

| 维度 | 内容 |
|------|------|
| 是什么 | DPO微调的环境配置和偏好数据格式准备，包括trl库安装和chosen-rejected对数据格式。 |
| 能做什么 | 安装trl库提供DPOTrainer；准备DPO偏好数据集格式为prompt-chosen-rejected三元组；配置DPOConfig训练参数。 |
| 怎么用 | 数据格式：{"prompt":"...","chosen":"...","rejected":"..."}；pip install trl。 |
| 原理和工作流程 | 环境准备：安装trl库（提供DPOTrainer）和peft库（支持LoRA加DPO）。DPO偏好数据集格式与SFT不同：每条数据包含prompt（指令）、chosen（偏好的回答）、rejected（被拒绝的回答）三个字段。数据来源可以是人工标注的偏好对、开源偏好数据集（如Anthropic HH-RLHF、UltraFeedback）或用强模型生成的偏好对（RLAIF）。数据预处理：chosen和rejected须为完整回答（不含prompt），prompt不含特殊token（由tokenizer自动添加）。DPOConfig配置训练参数：beta（KL惩罚系数，通常0.1）、learning_rate（通常5e-7，比SFT小一个数量级）、max_length等。 |
| 缺点 | 偏好数据集构建成本高需人工标注或强模型API；数据格式需严格匹配框架要求否则训练报错；DPO学习率比SFT小训练慢。 |

### 9.2 完整 DPO 训练代码

| 维度 | 内容 |
|------|------|
| 是什么 | 使用trl库DPOTrainer对SFT模型做DPO微调的完整Python代码，涵盖模型加载、数据加载、DPOConfig配置、训练全流程。 |
| 能做什么 | 加载SFT模型作为初始策略和参考模型；用DPOTrainer自动处理log-ratio计算和DPO损失；支持LoRA加DPO降低显存。 |
| 怎么用 | DPOTrainer(model=peft_model, ref_model=ref_model, args=dpo_config, train_dataset=dataset, processing_class=tokenizer)。 |
| 原理和工作流程 | 代码流程：第一步加载模型和分词器，AutoModelForCausalLM加载SFT模型，若用LoRA则先加载基座模型再get_peft_model。第二步配置DPOConfig，关键参数beta=0.1（控制与参考模型的偏离程度）、learning_rate=5e-7、batch_size和gradient_accumulation。第三步加载数据集为DPO格式（prompt-chosen-rejected三元组）。第四步创建DPOTrainer，DPOTrainer自动创建参考模型（复制策略模型并冻结），在训练时计算π_θ和π_ref对chosen和rejected的log-prob，按DPO损失更新策略参数。第五步trainer.train()启动训练并保存模型。DPOTrainer内部实现：对每个batch计算log π_θ(y_w\|x)、log π_θ(y_l\|x)、log π_ref(y_w\|x)、log π_ref(y_l\|x)，构造DPO损失=-log σ(β·(log_ratio_w - log_ratio_l))，反向传播更新策略参数（参考模型冻结不更新）。 |
| 缺点 | DPO训练代码需正确配置beta和学习率否则效果差；参考模型占用额外显存（可用LoRA共享基座缓解）；训练日志需监控reward_margin防止退化。 |

### 9.3 关键参数调优

| 维度 | 内容 |
|------|------|
| 是什么 | DPO训练中beta、学习率、batch size、训练轮数等关键超参数的调优指南。 |
| 能做什么 | beta控制策略与参考模型的偏离程度；学习率DPO比SFT小一个数量级；训练轮数通常1-3轮观察reward_margin。 |
| 怎么用 | beta：0.1-0.5（默认0.1保守，0.3-0.5激进）；学习率：5e-7到5e-6；batch size：4-16配合梯度累积；训练1-3轮。 |
| 原理和工作流程 | beta是DPO最重要的参数，控制策略偏离参考模型的程度。beta大（如0.5）策略偏离更激进对齐效果强但可能过拟合偏好数据；beta小（如0.1）偏离保守更安全但对齐效果弱。学习率DPO比SFT小一个数量级（5e-7到5e-6），因为DPO直接修改策略分布变化太大会破坏语言能力。Batch size根据显存调整配合梯度累积。训练轮数通常1-3轮，监控关键指标reward_margin=log[π_θ(y_w)/π_ref(y_w)]-log[π_θ(y_l)/π_ref(y_l)]，reward_margin持续增大说明模型在学习偏好，停止增大或减小则应停止。 |
| 缺点 | beta最优值依赖任务和偏好数据需实验确定；学习率太小收敛慢太大破坏语言能力；reward_margin不能完全反映对齐质量需人工评估。 |

### 9.4 训练后评估

| 维度 | 内容 |
|------|------|
| 是什么 | DPO训练后的评估方法，包括自动指标监控、能力基准评估和人类偏好评估三个层面。 |
| 能做什么 | 监控训练指标reward_margin和准确率；评估MMLU/MT-Bench等能力基准防止能力退化；做人类偏好A/B测试评估对齐效果。 |
| 怎么用 | 训练指标：reward_margin、chosen_reward、rejected_reward；能力基准：MT-Bench、AlpacaEval；偏好评估：A/B测试胜率。 |
| 原理和工作流程 | DPO训练后评估三个层面：第一层训练指标监控，reward_margin=chosen_reward-rejected_reward应持续增大，准确率（chosen得分高于rejected的比例）应接近1.0但不达到1.0（达到说明过拟合）。第二层能力基准评估，用MT-Bench（GPT-4打分）、AlpacaEval（与参考模型比较胜率）评估指令遵循和对话能力，同时用MMLU/GSM8K等评估通用能力是否退化。第三层人类偏好评估，准备DPO模型和SFT模型的回答对，让人类评估者盲选更好的回答计算DPO模型胜率。理想DPO模型应在能力基准不退化的前提下人类偏好胜率显著高于SFT模型。 |
| 缺点 | 训练指标不能反映真实对齐质量；能力基准可能数据污染；人类偏好评估成本高且主观；三个层面评估需大量时间和资源。 |
