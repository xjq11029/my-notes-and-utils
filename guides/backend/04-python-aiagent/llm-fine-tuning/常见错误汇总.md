# 大模型微调 - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 混淆BERT/GPT/T5三种架构的适用场景和注意力机制 | 三种架构预训练目标和注意力掩码不同，但外观相似易混淆 | BERT用双向注意力适合理解任务；GPT用因果掩码适合生成；T5用Encoder-Decoder适合seq2seq | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| 误以为增加头数一定提升Multi-Head Attention效果 | 头数过多导致每头维度过小，表达能力反而下降 | 头数选择需平衡每头维度，通常d_model/h需保持合理范围（如64-128） | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| 将模型参数量等同于性能，忽略Scaling Law中的计算最优 | Scaling Law指出计算预算固定时存在最优模型大小和训练数据量组合 | 根据可用计算资源（FLOPs）按Chinchilla定律确定模型大小和数据量配比 | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| 微调时学习率设置过大导致灾难性遗忘 | 微调学习率接近预训练学习率时，参数更新幅度过大覆盖预训练知识 | 微调学习率比预训练小1-2个数量级；使用LoRA降低可训练参数规模；混合预训练数据 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| LoRA的rank选择过大接近全量微调，失去参数效率 | 误以为rank越大效果越好，忽略了低秩假设的本意 | rank通常选4-16，r=8是常见平衡点；实验中r从1增到4-8效果提升明显，继续增大收益递减 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| QLoRA量化后训练精度损失，但未做NF4和双重量化配置 | 直接使用标准4-bit量化而不使用NormalFloat4和双重量化，精度损失显著 | QLoRA必须使用NF4数据类型加双重量化，配合分页优化器处理梯度检查点 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| PPO训练中RL策略崩溃或reward hacking | RL训练不稳定，RM被策略钻空子（如生成冗长但无用的回答获高分），KL惩罚不足 | 动态调整KL系数β；监控KL散度防止爆炸；使用PPO-ptx混合预训练损失防止能力退化 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| 误认为DPO完全不需要参考模型 | DPO损失函数中隐式依赖参考模型π_ref计算log-ratio，只是消除了显式RM和PPO | DPO仍需参考模型（冻结的SFT模型），但只需2个模型而非4个 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| RLHF偏好数据标注质量差导致RM训练偏差 | 标注者偏好不一致、标注标准模糊、标注者自身偏见引入噪声 | 制定明确标注指南（有用性/无害性/诚实性）；多标注者交叉验证；使用排序而非打分 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| 面试中混淆LoRA/QLoRA/Adapter/Prefix-tuning的差异 | 多种PEFT方法名称相似但插入位置和可训练参数形式不同 | LoRA在权重旁路加低秩矩阵；Adapter在层间插入瓶颈层；Prefix-tuning在输入前加可学习前缀 | [面试题集导览](./04-大模型微调笔面试题集-导览.md) |
| 微调数据量太少导致过拟合 | 仅有数百条数据做全量微调，模型记忆训练集而非学习模式 | 少量数据用LoRA/QLoRA降低过拟合风险；数据增强扩充训练集；增加dropout和正则化 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 忘记在推理时将LoRA权重合并到基座模型 | LoRA训练后BA矩阵未合并到W_0，推理时仍分开计算增加延迟 | 推理前执行`model.merge_and_unload()`将LoRA权重合并，消除额外计算开销 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
