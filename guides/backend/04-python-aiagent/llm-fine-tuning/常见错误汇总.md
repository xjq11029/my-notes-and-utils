# 大模型微调 - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 混淆BERT/GPT/T5三种架构的适用场景和注意力机制 | 三种架构预训练目标和注意力掩码不同，但外观相似易混淆 | BERT用双向注意力适合理解任务；GPT用因果掩码适合生成；T5用Encoder-Decoder适合seq2seq | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| 误以为增加头数一定提升Multi-Head Attention效果 | 头数过多导致每头维度过小，表达能力反而下降 | 头数选择需平衡每头维度，通常d_model/h需保持合理范围（如64-128） | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| 将模型参数量等同于性能，忽略Scaling Law中的计算最优 | Scaling Law指出计算预算固定时存在最优模型大小和训练数据量组合 | 根据可用计算资源（FLOPs）按Chinchilla定律确定模型大小和数据量配比 | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| 微调时学习率设置过大导致灾难性遗忘 | 微调学习率接近预训练学习率时，参数更新幅度过大覆盖预训练知识 | 微调学习率比预训练小1-2个数量级；使用LoRA降低可训练参数规模；混合预训练数据 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| LoRA的rank选择过大接近全量微调，失去参数效率 | 误以为rank越大效果越好，忽略了低秩假设的本意 | rank通常选4-16，r=8是常见平衡点；实验中r从1增到4-8效果提升明显，继续增大收益递减 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| QLoRA量化后训练精度损失，但未做NF4和双重量化配置 | 直接使用标准4-bit量化而不使用NormalFloat4和双重量化，精度损失显著 | QLoRA必须使用NF4数据类型加双重量化，配合分页优化器处理梯度检查点 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| PPO训练中RL策略崩溃或reward hacking | RL训练不稳定，RM被策略钻空子（如生成冗长但无用的回答获高分），KL惩罚不足 | 动态调整KL系数β；监控KL散度防止爆炸；使用PPO-ptx混合预训练损失防止能力退化 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| 误认为DPO完全不需要参考模型 | DPO损失函数中隐式依赖参考模型π_ref计算log-ratio，只是消除了显式RM和PPO | DPO仍需参考模型（冻结的SFT模型），但只需2个模型而非4个 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| RLHF偏好数据标注质量差导致RM训练偏差 | 标注者偏好不一致、标注标准模糊、标注者自身偏见引入噪声 | 制定明确标注指南（有用性/无害性/诚实性）；多标注者交叉验证；使用排序而非打分 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| 面试中混淆LoRA/QLoRA/Adapter/Prefix-tuning的差异 | 多种PEFT方法名称相似但插入位置和可训练参数形式不同 | LoRA在权重旁路加低秩矩阵；Adapter在层间插入瓶颈层；Prefix-tuning在输入前加可学习前缀 | [面试题集导览](./04-大模型微调笔面试题集-导览.md) |
| 微调数据量太少导致过拟合 | 仅有数百条数据做全量微调，模型记忆训练集而非学习模式 | 少量数据用LoRA/QLoRA降低过拟合风险；数据增强扩充训练集；增加dropout和正则化 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 忘记在推理时将LoRA权重合并到基座模型 | LoRA训练后BA矩阵未合并到W_0，推理时仍分开计算增加延迟 | 推理前执行`model.merge_and_unload()`将LoRA权重合并，消除额外计算开销 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 盲目把rank调大，参数量上升但效果没提升 | 显存占用增加、过拟合风险上升，验证集指标反而变差 | 误以为"可训练参数越多越好"，忽略了LoRA的低秩假设 | 7B/13B用r=8，70B+用r=16~32，在验证集上选满足性能要求的最小r | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 把alpha当成学习率来调 | 训练不稳定，或几乎学不动 | 混淆alpha（缩放因子，实际缩放为α/r）与learning rate，两者概念完全不同 | alpha通常取r或2r；学习率通过lr单独设置，LoRA推荐1e-4~5e-4 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 训练集未做loss mask，模型学会了"复述问题" | 推理时输出问题本身而不是答案，或答案前重复整段prompt | labels直接复制input_ids，prompt部分也参与了损失计算 | 把prompt段对应的labels置为-100，或使用SFTTrainer的completion-only掩码只对答案计损失 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 显存不足直接把batch降到1，训练不收敛 | loss剧烈震荡，梯度噪声大，训练不稳定 | 没有用梯度累积补偿有效batch size | batch_size=1配合gradient_accumulation_steps=16等效batch=16；同时开梯度检查点省显存 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 混淆QLoRA与LoRA的适用条件 | 显存充足却多此一举用4-bit量化，或显存不足仍硬上全精度训练 | 两者区别在于基座是否做4-bit量化（QLoRA需NF4+双重量化） | 显存紧张用QLoRA（基座4-bit），显存充足用LoRA（bf16），精度损失约0.5%~1%可接受 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 评估集与训练集重叠导致指标虚高 | 评估分数很漂亮，上线效果却明显下降 | 同一来源的样本同时进入训练集和评估集，造成数据污染 | 按来源/用户维度切分并去重，评估集绝不参与任何训练或调参 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| max_length截断丢失关键信息 | 长样本的答案被截掉，模型学不到完整输出 | 直接按max_length从尾部截断，而答案往往在样本末尾 | 先统计样本长度分布；优先截断prompt保留答案，或按长度分桶处理长样本 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| Tokenizer与基座模型不匹配导致输出乱码或乱答 | 生成内容不可读，或答非所问 | 用了与基座不同系列的tokenizer，或未设置pad_token | tokenizer与模型同源加载；设置`tokenizer.pad_token = tokenizer.eos_token` | [Transformer导览](./01-大模型基础与Transformer架构-导览.md) |
| SFT数据格式错误导致对话模板不生效 | 模型不按角色回答，把user内容和assistant内容混在一起 | 手写prompt拼接而没有用`apply_chat_template`，或DPO数据中chosen/rejected混入了prompt | 统一用`tokenizer.apply_chat_template`生成输入；DPO的chosen/rejected只放回答部分 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| 关闭或调小KL惩罚后出现奖励作弊 | 输出冗长、空洞却拿到高奖励，文本质量明显下降 | 没有KL约束时策略漂移，模型钻RM的评分空子 | KL系数β取0.01~0.1并动态调整；监控KL散度，超过10说明偏离严重，应增大β或降低学习率 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| DPO偏好数据质量差，训练后效果反而下降 | 模型回答变差，偏好学习方向错误 | chosen与rejected差异不明显、标注错误，或两者长度差异过大 | 保证同一prompt下chosen明显更优；避免长度悬殊的偏好对；至少1k~10k对高质量数据 | [RLHF导览](./03-强化学习与RLHF对齐技术-导览.md) |
| 推理时temperature与重复惩罚设置不当 | 输出重复啰嗦，或完全发散跑题 | temperature过高导致随机，过低则死板；repetition_penalty过大破坏语义 | 通用对话从temperature=0.7、top_p=0.9、repetition_penalty=1.1起步，再按任务微调 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
| 只盯单一自动指标导致评估失真 | MMLU分数很高，但实际对话体验很差 | 单一指标无法覆盖多维度能力，且存在few-shot数量与数据污染干扰 | 组合评估：PPL+MMLU+MT-Bench/LLM-as-Judge，最终以业务场景人工评估为准 | [微调导览](./02-微调技术与LoRA原理-导览.md) |
