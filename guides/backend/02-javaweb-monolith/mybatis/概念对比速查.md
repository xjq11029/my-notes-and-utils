# MyBatis - 概念对比速查

---

### MyBatis vs JPA vs MyBatis-Plus

| 对比维度 | MyBatis | JPA | MyBatis-Plus |
|---------|---------|-----|-------------|
| 核心定位 | 半自动 ORM 框架，需要手动编写 SQL | 全自动 ORM 框架，自动生成 SQL | MyBatis 增强工具包，在 MyBatis 基础上提供内置 CRUD |
| SQL 控制 | 完全手动编写 SQL，灵活性最高 | 自动生成 SQL（JPQL/HQL），复杂查询难控制 | 继承 MyBatis 的 SQL 编写能力，增加条件构造器简化动态 SQL |
| CRUD 操作 | 需手动编写 Mapper XML 中的 SQL | 继承 JpaRepository 自动获得 CRUD 方法 | 继承 BaseMapper 自动获得 CRUD 方法，无需写 SQL |
| 学习成本 | 较低，会 SQL 即可上手 | 较高，需理解实体关系映射、缓存、懒加载等概念 | 较低，在 MyBatis 基础上增加少量注解和 API |
| 复杂查询 | 原生 SQL 灵活表达，适合复杂报表和多表关联 | JPQL/Criteria API 表达能力有限，复杂查询需原生 SQL | 原生 SQL + 条件构造器 + 分页插件，查询能力强大 |
| 适用场景 | 复杂查询、报表、多表关联场景 | 标准 CRUD 为主、实体关系清晰的场景 | 需要快速开发 CRUD 的同时保留复杂 SQL 能力 |

### #{} vs ${}

| 对比维度 | #{} | ${} |
|---------|-----|-----|
| 核心定位 | 预编译参数占位符，安全的参数传递方式 | 字符串直接拼接，灵活的 SQL 结构替换 |
| 底层实现 | PreparedStatement 的 ? 占位符，预编译 | 直接将参数值拼接到 SQL 字符串中 |
| SQL 注入 | 安全，参数作字面量值处理 | 存在注入风险，不做任何转义 |
| 类型处理 | 自动类型转换，自动加引号 | 不做类型处理，不加引号 |
| 适用场景 | 所有参数值（WHERE 条件、INSERT 值等） | 表名、列名、ORDER BY 字段、动态 SQL 结构 |
| 使用建议 | 优先使用，是默认安全选择 | 仅在无法用 #{} 的场景（SQL 结构部分）使用，且必须做白名单校验 |

### resultType vs resultMap

| 对比维度 | resultType | resultMap |
|---------|-----------|-----------|
| 核心定位 | 自动映射，指定返回结果的 Java 类型 | 显式映射，手动定义列与属性的对应关系 |
| 映射方式 | 列名与属性名按名称自动匹配（需完全相同） | 通过 <result> 标签显式声明列与属性的映射 |
| 使用复杂度 | 简单，一行配置 | 复杂，需定义多个 <result> 或 <id> 标签 |
| 适用场景 | 简单的单表查询，列名与属性名一致 | 列名与属性名不一致（下划线转驼峰除外）、嵌套查询、关联查询 |
| 性能 | 略高（无需解析映射规则） | 略低（需解析映射规则，但差异可忽略） |
| 选择建议 | 简单场景优先使用，配合 mapUnderscoreToCamelCase 开启驼峰映射 | 复杂映射、关联查询、字段名不一致时使用 |

### 一级缓存 vs 二级缓存

| 对比维度 | 一级缓存 | 二级缓存 |
|---------|---------|---------|
| 核心定位 | SqlSession 级别缓存，默认开启 | Mapper（namespace）级别缓存，需手动开启 |
| 作用域 | 同一个 SqlSession 内有效 | 同一 namespace 跨 SqlSession 共享 |
| 数据结构 | SqlSession 内部的 HashMap | 默认 PerpetualCache（HashMap），可集成 Ehcache/Redis |
| 开启方式 | 默认开启，无需配置 | 全局 cacheEnabled=true + Mapper 内加 <cache/> |
| 失效条件 | 执行 insert/update/delete；调用 clearCache()；SqlSession 关闭 | 该 namespace 执行 insert/update/delete |
| 写入时机 | 查询后立即写入 | 事务提交（commit）后才写入，未提交不命中 |
| 查询顺序 | 二级缓存 -> 一级缓存 -> 数据库 | 先于一级缓存被查询 |
| 注意事项 | 非线程安全，不可跨 SqlSession | 缓存对象需实现 Serializable；分布式环境需集成外部缓存；多表关联可能脏读 |
| 适用场景 | 同会话内重复查询 | 读多写少、数据变化不频繁的场景 |
