# MyBatis - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| namespace 与接口全限定名不一致导致 BindingException | XML 的 namespace 与接口包路径不匹配 | 确保 namespace 等于接口全限定名，方法名等于 SQL 标签 id | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| SqlSession 未关闭导致连接泄漏、内存溢出 | SqlSession 非线程安全且持有连接，未释放 | 使用 try-with-resources 或 finally 中 close() | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| 使用 ${} 导致 SQL 注入 | ${} 直接拼接字符串 | 参数值用 #{}；表名/列名用 ${} 时做白名单校验 | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| 二级缓存脏读（跨表查询读到旧数据） | 二级缓存是 namespace 级别，多表关联时一方更新不会清另一方缓存 | 关联查询的表共用 namespace 或使用 CacheNamespaceRef；或禁用二级缓存 | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| foreach 批量插入超大集合导致 SQL 过长被数据库拒绝 | 单条 SQL 拼接过多 VALUES 超过 max_allowed_packet | 分批执行（每批 500~1000 条）；或使用 BATCH 执行器 | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| 动态 SQL 中 < 报 XML 解析错误 | < 被当作标签起始符 | 使用 `&lt;` 转义，或用 `<![CDATA[ ... ]]>` 包裹 | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| 参数为单个 String/Integer 时取不到值 | 单参数未加 @Param 时 MyBatis 无法按属性名定位 | 加 @Param("name") 注解；或在 XML 中用 #{_parameter} 或 #{value} | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| 实体属性与列名不匹配导致查询结果字段为 null | 数据库下划线命名（user_name）与 Java 驼峰命名不一致 | 开启 mapUnderscoreToCamelCase=true；或配置 resultMap 显式映射 | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| resultMap 和 resultType 混用混乱导致映射异常或字段丢失 | resultType 自动映射列名需完全一致；resultMap 需显式声明 | 简单单表用 resultType；复杂关联/驼峰映射用 resultMap | [MyBatis 原生框架](./03-MyBatis原生框架.md) |
| 生产环境开启 OSIV 导致连接池耗尽 | OSIV 在请求处理期间保持数据库连接，高并发时连接无法释放 | 关闭 OSIV（spring.jpa.open-in-view: false），在 @Transactional 方法内访问懒加载属性 | [Spring Data JPA 深度](./04-Spring-Data-JPA深度.md) |
| JPA 实体 equals/hashCode 未正确重写导致 Set 集合重复元素 | 使用 @GeneratedValue 时 id 在 persist 前为 null，导致 hashCode 不一致 | id 为 null 时使用 Object.equals；hashCode 返回固定值（getClass().hashCode()） | [Spring Data JPA 深度](./04-Spring-Data-JPA深度.md) |
| 双向关联 JSON 序列化无限递归导致 StackOverflowError | User 有 orders，Order 有 user，JSON 序列化时互相引用形成循环 | 使用 @JsonIgnore 忽略一方；使用 @JsonManagedReference/@JsonBackReference；使用 DTO 避免循环引用 | [Spring Data JPA 深度](./04-Spring-Data-JPA深度.md) |
| 分页查询后直接序列化 IPage 导致序列化效率低 | IPage 对象包含大量内部元数据（如 pages、searchCount 等） | 只返回需要的数据：封装 PageResult，只传 total 和 records | [MyBatis-Plus 实战](./05-MyBatis-Plus实战.md) |
| 循环单条插入导致批量插入极慢 | 每次 insert 都是一次数据库交互，网络开销大 | 使用 saveBatch() 分批插入（每 100 条一批）；使用 insertBatchSomeColumn 自定义 SQL 合并 | [MyBatis-Plus 实战](./05-MyBatis-Plus实战.md) |
| 乐观锁更新失败未重试导致高并发下业务异常 | 版本号不匹配时 updateById 返回 0 行，未做重试处理 | 实现重试机制（如最多 3 次），失败后重新读取最新数据再更新 | [MyBatis-Plus 实战](./05-MyBatis-Plus实战-导览.md) |
| 一级缓存跨 SqlSession 失效，同一数据被重复查询 | 两个 SqlSession 之间查同一条件仍各发一条 SQL | 一级缓存作用域是单个 SqlSession，会话关闭或执行 insert/update/delete 后即被清空 | 同一会话内复用 SqlSession；跨请求共享数据用二级缓存或 Redis，不要指望一级缓存 | [MyBatis 原生框架](./03-MyBatis原生框架-导览.md) |
| 一级缓存读到同会话内的过期数据 | 同一 SqlSession 中更新后仍读到旧值 | 绕过 MyBatis 直接执行 SQL（如混用原生 JDBC）时缓存不会失效 | 避免在同一会话混用原生 JDBC 更新；必要时调用 `clearCache()` 手动清空 | [MyBatis 原生框架](./03-MyBatis原生框架-导览.md) |
| 开启二级缓存后抛出 NotSerializableException | 缓存写入失败或反序列化报错 | 二级缓存默认存储对象要求实现 `Serializable`，且仅在事务提交后才写入 | 让实体实现 Serializable；分布式环境改用 Redis 等外部缓存 | [MyBatis 原生框架](./03-MyBatis原生框架-导览.md) |
| 二级缓存与事务提交时机不一致导致读到旧数据 | 事务未提交期间其他会话读到旧值，提交后又读到新值 | 二级缓存仅在事务提交后才写入，缓存与事务边界不完全对齐 | 只对读多写少的单表开启二级缓存；涉及多表关联的查询建议禁用 | [MyBatis 原生框架](./03-MyBatis原生框架-导览.md) |
| resultMap 中 column 与 property 写反导致字段全为 null | SQL 正常返回，但映射出的对象属性为空 | column 对应数据库列名、property 对应 Java 属性名，两者写反即映射不上 | 逐字段核对 column/property；简单单表可直接用 resultType + `mapUnderscoreToCamelCase` | [MyBatis 原生框架](./03-MyBatis原生框架-导览.md) |
| 关联查询出现 N+1 导致接口响应慢 | 一次列表查询背后发出 1+N 条 SQL | 遍历主实体时逐个访问懒加载的关联属性，每个实体触发一次查询 | 用 `JOIN FETCH` 一次取回，或用 `@EntityGraph`/`@BatchSize` 减少往返次数 | [Spring Data JPA 深度](./04-Spring-Data-JPA深度-导览.md) |
| 事务外访问懒加载属性抛 LazyInitializationException | 接口报 could not initialize proxy - no Session | 懒加载代理在 Session 关闭后才被访问 | 在 `@Transactional` 方法内访问；或用 JOIN FETCH / DTO 投影预取，不要靠开启 OSIV 兜底 | [Spring Data JPA 深度](./04-Spring-Data-JPA深度-导览.md) |
| 自定义分页拦截器与分页插件叠加导致 SQL 重复拼 LIMIT | 分页语句出现两个 LIMIT，或 count 查询异常 | 手写的分页拦截器与 MyBatis-Plus 的 PaginationInnerInterceptor 同时生效 | 只保留一套分页实现；自定义分页需注意拦截器顺序与 BoundSql 改写时机 | [MyBatis-Plus 实战](./05-MyBatis-Plus实战-导览.md) |
| 逻辑删除后唯一索引冲突，新数据插不进去 | 唯一键（如 username）报 Duplicate entry，但列表里又查不到这条记录 | 逻辑删除只把 deleted 置 1，物理行仍在，唯一索引照样生效 | 唯一索引带上删除标记（如 `(username, deleted)`）；或用删除时间戳替代 0/1 | [MyBatis-Plus 实战](./05-MyBatis-Plus实战-导览.md) |
| 乐观锁 version 未生效导致并发更新互相覆盖 | 高并发下后提交的事务覆盖了先提交的修改 | 未注册 OptimisticLockerInnerInterceptor，或更新走的是自定义 SQL 而非 updateById | 注册乐观锁插件、实体加 `@Version`；更新统一用 updateById 让插件自动追加 version 条件 | [MyBatis-Plus 实战](./05-MyBatis-Plus实战-导览.md) |
| saveBatch 批量插入依然很慢 | 万条数据仍耗时数分钟，与逐条插入差不多 | JDBC URL 未开 `rewriteBatchedStatements`，批处理被驱动拆成逐条发送 | URL 加 `rewriteBatchedStatements=true`；或用 insertBatchSomeColumn 合并成一条多 VALUES 的 SQL | [MyBatis-Plus 实战](./05-MyBatis-Plus实战-导览.md) |
| @Transactional 自调用导致事务不生效 | 内部 `this.other()` 调用抛异常后数据没有回滚 | Spring AOP 基于代理实现，同类内部调用绕过了代理对象 | 把方法拆到另一个 Bean，或注入自身代理（`AopContext.currentProxy()`）再调用 | [Spring Data JPA 深度](./04-Spring-Data-JPA深度-导览.md) |
| @Transactional 未指定 rollbackFor 导致受检异常不回滚 | 抛出 checked 异常后事务却已提交 | 默认只对 RuntimeException 和 Error 回滚，受检异常不触发回滚 | 显式声明 `@Transactional(rollbackFor = Exception.class)` | [Spring Data JPA 深度](./04-Spring-Data-JPA深度-导览.md) |
