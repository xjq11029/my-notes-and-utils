# Spring Boot - 概念对比速查

---

### Spring Boot vs Spring MVC（传统）

| 对比维度 | Spring Boot | Spring MVC（传统） |
|---------|------------|-------------------|
| 核心定位 | 基于 Spring 的快速开发框架，约定优于配置 | Spring 框架的 Web 模块，需要大量手动配置 |
| 配置方式 | 自动配置，开箱即用 | 需手动配置 web.xml、Spring 配置文件、DispatcherServlet 等 |
| 内嵌服务器 | 内置 Tomcat/Jetty/Undertow，直接 java -jar 运行 | 需外部部署到 Tomcat 等 Servlet 容器，打包为 WAR |
| 依赖管理 | Starter 机制，一键引入所需依赖 | 需手动管理每个依赖的版本和兼容性 |
| 项目启动 | 一个 main 方法即可启动 | 需配置 web.xml、加载 Spring 上下文 |
| 监控运维 | 内置 Actuator，提供健康检查、指标采集 | 需自行集成监控组件 |
| 适用场景 | 微服务、快速开发、独立部署 | 传统企业级应用、已有容器环境 |

### @Component vs @Bean

| 对比维度 | @Component | @Bean |
|---------|-----------|-------|
| 核心定位 | 作用于类级别，通过类路径扫描自动注册为 Bean | 作用于方法级别，在 @Configuration 类中手动声明 Bean |
| 使用方式 | 直接标注在类上，Spring 自动扫描并注册 | 在 @Configuration 类的 @Bean 方法上使用，返回实例由 Spring 管理 |
| 控制粒度 | 全自动，无法控制实例化过程 | 精确控制 Bean 的创建过程、初始化逻辑 |
| 适用场景 | 自己编写的类（Service、Repository、Controller 等） | 第三方库的类、需要复杂初始化逻辑的 Bean、条件创建 |
| 生命周期 | 由 Spring 容器全权管理 | 可在 @Bean 方法中自定义初始化和销毁逻辑 |
| 典型示例 | @Component、@Service、@Repository、@Controller | DataSource、RestTemplate、ObjectMapper 等第三方 Bean |

### application.properties vs application.yml

| 对比维度 | application.properties | application.yml |
|---------|----------------------|-----------------|
| 核心定位 | 键值对格式配置，Spring Boot 传统默认格式 | 层级树状结构配置，现代推荐格式 |
| 语法风格 | key=value 扁平结构 | 缩进层级结构，支持 YAML 语法 |
| 可读性 | 配置多层级前缀时重复累赘 | 层级嵌套直观，结构清晰 |
| 数据表达 | 仅支持简单字符串键值对 | 支持列表、Map、嵌套对象等复杂数据结构 |
| 多 Profile | 每个 Profile 单独文件 | 单文件内可用 --- 分隔多 Profile |
| 选择建议 | 简单项目、习惯传统格式的团队 | 复杂配置、多环境管理、微服务项目推荐 |

### JWT vs Session 认证

| 对比维度 | JWT | Session |
|---------|-----|---------|
| 核心定位 | 无状态令牌认证，客户端存储凭证 | 有状态会话认证，服务端存储凭证 |
| 存储位置 | 客户端（浏览器/App） | 服务端（内存/Redis） |
| 扩展性 | 无状态，天然支持分布式和水平扩展 | 需 Session 共享（Redis）才能支持分布式 |
| 安全性 | 签发后无法主动失效，需配合黑名单或短过期时间 | 服务端控制，可主动踢人、删除 Session |
| 体积 | 携带用户信息，每次请求传输完整 Token | 只传 SessionId，体积小 |
| 失效机制 | 依赖过期时间，无法主动失效（需配合黑名单） | 服务端直接删除 Session，即时生效 |
| 适用场景 | 前后端分离、移动端、微服务、API 网关 | 传统 Web 应用（服务端渲染）、需要主动失效的场景 |

### @Transactional 失效场景对比

| 对比维度 | 同类方法调用 | 非 public 方法 | 异常被 catch |
|---------|------------|---------------|-------------|
| 核心定位 | this.method() 绕过代理对象直接调用 | AOP 代理无法拦截 private/protected 方法 | 异常在方法内部被捕获，未传播到代理层 |
| 失效原理 | Spring AOP 基于代理，this 引用的是原始对象而非代理对象 | JDK 动态代理需要接口，CGLIB 继承子类无法覆写非 public 方法 | @Transactional 通过异常回滚，异常未抛出则代理层感知不到 |
| 解决方案 | 拆分为两个 Service；AopContext.currentProxy()；@Autowired + @Lazy 自注入 | 将方法改为 public；将事务逻辑抽取到单独的 Service | 在 catch 块中手动抛出异常或使用 TransactionAspectSupport.currentTransactionStatus().setRollbackOnly() |
| 典型场景 | Controller 调用自身方法 | 事务方法放在 private 辅助方法中 | 业务代码 try-catch 后吞掉异常 |
