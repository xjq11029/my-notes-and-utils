# JavaWeb Servlet - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| Cookie 中文乱码 | Cookie 值不支持非 ASCII 字符，直接写入中文导致乱码 | 使用 URLEncoder.encode(value, "UTF-8") 编码存储，读取时 URLDecoder.decode 解码 | [JavaWeb核心与HTTP协议](./01-JavaWeb核心与HTTP协议-导览.md) |
| Session 固定攻击 | 攻击者获取 JSESSIONID 诱导用户使用该 ID 登录，登录后攻击者可用同一 ID 冒充用户 | 登录成功后调用 session.invalidate() 销毁旧 Session 再创建新 Session | [JavaWeb核心与HTTP协议](./01-JavaWeb核心与HTTP协议-导览.md) |
| Cookie 跨域问题 | Domain 属性默认限制在当前域名，无法跨顶级域名共享 | 设置 Domain 为父域名可共享给子域名；跨顶级域名需使用其他方案如 SSO | [JavaWeb核心与HTTP协议](./01-JavaWeb核心与HTTP协议-导览.md) |
| HTTPS 混合内容警告 | HTTPS 页面加载 HTTP 资源（图片、脚本等），浏览器警告或阻止 | 确保页面所有资源均使用 HTTPS 协议；使用 CSP 头升级不安全请求 | [JavaWeb核心与HTTP协议](./01-JavaWeb核心与HTTP协议-导览.md) |
| HTTPS 证书问题导致访问失败 | 自签名证书不被信任、证书过期、证书链不完整 | 生产环境使用 CA 签发证书；及时续期；配置中间证书完成证书链 | [JavaWeb核心与HTTP协议](./01-JavaWeb核心与HTTP协议-导览.md) |
| Servlet 线程安全问题（数据错乱） | Servlet 是单例多线程，实例变量被所有线程共享 | 不使用实例变量，或使用 ThreadLocal，或使用 synchronized（注意性能影响） | [Servlet与Tomcat底层](./02-Servlet与Tomcat底层-导览.md) |
| 类加载器泄漏导致 PermGen/Metaspace 溢出 | Tomcat WebappClassLoader 在应用重载时被外部引用（ThreadLocal 对象、JDBC 驱动注册），无法回收 | 关闭 JDBC 驱动、清理 ThreadLocal、避免启动未关闭的后台线程 | [Servlet与Tomcat底层](./02-Servlet与Tomcat底层-导览.md) |
| Forward 与 Redirect 路径混淆导致 404 | Forward 路径以 "/" 开头相对于 Web 应用根目录，Redirect 以 "/" 开头相对于服务器根目录 | 明确路径基准：Forward 路径省略 contextPath，Redirect 路径需加 contextPath | [Servlet与Tomcat底层](./02-Servlet与Tomcat底层-导览.md) |
| Servlet 注解 urlPatterns 配置错误 | urlPatterns 未以 "/" 开头 | 确保 urlPatterns 值以 "/" 开头，如 @WebServlet("/hello") | [Servlet与Tomcat底层](./02-Servlet与Tomcat底层-导览.md) |
| Filter 执行顺序与预期不符 | @WebFilter 注解无法控制多个 Filter 的执行顺序 | 使用 FilterRegistrationBean 注册并设置 setOrder() 控制顺序 | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| Listener 异常导致应用启动失败 | contextInitialized 中未捕获异常直接抛出 | 在 Listener 中用 try-catch 包裹异常处理逻辑，记录日志后选择降级或终止 | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| 文件上传路径穿越攻击 | 攻击者上传包含 `../../etc/passwd` 的文件名，覆盖系统文件 | 过滤 `../` 和 `..\\` 等字符，仅保留纯文件名，使用 UUID 重命名文件 | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| 中文乱码（多环节遗漏） | 仅配置了部分环节的编码，遗漏其他环节导致乱码 | 同时覆盖 Tomcat URIEncoding、request.setCharacterEncoding、response.setContentType、页面 charset、数据库 characterEncoding 五个环节 | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| 文件下载中文文件名乱码 | 各浏览器对 Content-Disposition 中文编码处理不一致 | 使用 `filename*=UTF-8''urlEncodedFileName` 格式设置 Content-Disposition 头 | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| GET 请求 URL 参数中文乱码 | Tomcat URI 编码默认 ISO-8859-1 | 配置 server.tomcat.uri-encoding=UTF-8（Spring Boot 默认已为 UTF-8），或使用 URLEncoder.encode() | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| POST 请求表单提交中文乱码 | 请求体未设置编码 | 在 doPost 第一行调用 request.setCharacterEncoding("UTF-8")，或使用 EncodingFilter | [Request与Response&Filter监听器](./03-Request与Response&Filter监听器-导览.md) |
| Session 丢失导致用户频繁重新登录 | Session 超时时间过短；负载均衡未做 Session 共享 | 调大 server.servlet.session.timeout；使用 Redis Session 共享 | [JavaWeb核心与HTTP协议](./01-JavaWeb核心与HTTP协议-导览.md) |
| 302 重定向后 POST 数据丢失变成 GET | 302 重定向标准要求使用 GET 方法 | 使用 307（保留请求方法）或 Forward 转发 | [Servlet与Tomcat底层](./02-Servlet与Tomcat底层-导览.md) |
| 内嵌 Tomcat 启动报 PortInUseException | 端口已被其他进程占用 | 修改 server.port 配置；或终止占用端口的进程 | [Servlet与Tomcat底层](./02-Servlet与Tomcat底层-导览.md) |
