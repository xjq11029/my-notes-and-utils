# Maven - 概念对比速查

---

### Maven vs Gradle

| 对比维度 | Maven | Gradle |
|---------|-------|--------|
| 核心定位 | 基于 XML 的声明式构建工具，强调约定优于配置和标准化生命周期 | 基于 Groovy/Kotlin DSL 的构建工具，强调灵活性和高性能 |
| 构建模型 | 固定生命周期（clean、default、site），阶段不可跳过 | 基于任务 DAG（有向无环图），可自定义任务依赖关系 |
| 依赖管理 | GAV 坐标 + 传递依赖 + 最短路径优先 + 最先声明优先 | 与 Maven 兼容的坐标体系，支持动态版本和依赖排除 |
| 性能特点 | 默认无增量构建支持，全量构建较慢 | 增量构建、构建缓存、守护进程，大幅提升构建速度 |
| 构建脚本 | pom.xml，结构固定，IDE 支持好 | build.gradle / build.gradle.kts，编写灵活但学习曲线高 |
| 插件生态 | 插件丰富，生态成熟，文档完善 | 兼容 Maven 插件，自身插件生态也在增长 |
| 选择建议 | 项目标准化要求高、团队熟悉 XML、需要与 CI/CD 深度集成时首选 | 需要灵活构建逻辑、大型多模块项目追求构建速度、Android 开发首选 |

### dependencyManagement vs dependencies

| 对比维度 | dependencyManagement | dependencies |
|---------|---------------------|-------------|
| 核心定位 | 声明式版本管理，仅定义版本号，不实际引入依赖 | 实际引入依赖到项目 classpath |
| 声明位置 | 通常在父 POM 中声明 | 父 POM 和子模块均可声明 |
| 是否实际引入 | 否，仅锁定版本，子模块需要显式声明 gav 才能使用 | 是，直接引入依赖到编译、测试、运行 classpath |
| 版本继承 | 子模块引用时无需写 version，自动继承父 POM 中定义的版本 | 子模块需自行指定 version，或继承父 POM dependencyManagement 中的版本 |
| 适用场景 | 多模块项目统一版本控制，避免版本冲突 | 描述模块实际需要的依赖 |
| 选择建议 | 父 POM 中优先使用 dependencyManagement 统一管理版本；子模块中只声明需要的 gav（省略 version） | 仅在父 POM 中声明所有模块都需要的公共依赖时使用 |

### compile vs provided vs runtime scope

| 对比维度 | compile（默认） | provided | runtime |
|---------|----------------|----------|---------|
| 核心定位 | 编译和运行都需要，默认 scope | 编译时需要，运行时由容器提供 | 运行时需要，编译时不需要 |
| 编译 classpath | 包含 | 包含 | 不包含 |
| 测试 classpath | 包含 | 包含 | 包含 |
| 运行时 classpath | 包含 | 不包含 | 包含 |
| 是否打包进最终产物 | 是 | 否 | 是 |
| 传递性 | 传递 | 不传递 | 传递 |
| 典型示例 | spring-core、commons-lang3 | Servlet API、JSP API、Lombok | JDBC 驱动、SLF4J 实现 |
| 选择建议 | 通用依赖，谨慎使用避免打包膨胀 | 容器提供的 API 必须用 provided，避免与容器版本冲突 | 仅运行时需要的接口实现类，编译时通过接口编程 |
