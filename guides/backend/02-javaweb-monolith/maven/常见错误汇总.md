# Maven - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 传递依赖版本冲突导致 NoSuchMethodError / NoClassDefFoundError | 多路径引入同一库不同版本，最短路径裁决规则生效的版本不是预期版本 | `mvn dependency:tree -Dverbose` 查看被丢弃版本，用 exclusions 排除或在 dependencyManagement 锁定版本 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| scope 配错导致 jar 打包体积异常大 | 把 test/provided 依赖写成 compile，测试库被打进产物 | JUnit、Mockito 用 test；Servlet API 用 provided | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| SNAPSHOT 进入生产环境导致线上行为不确定 | SNAPSHOT 会被私服更新为最新构建，版本不固定 | 发布版本用 RELEASE，禁止生产依赖 SNAPSHOT | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 子模块版本各自写死导致多模块版本不一致 | 未用 dependencyManagement 统一管理 | 在父 POM 集中声明版本，子模块省略 version | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 中文注释编译报错或编码乱码 | maven-compiler-plugin 未指定 UTF-8 | properties 中设 project.build.sourceEncoding=UTF-8，插件配 encoding | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 忘记 parent 的 relativePath 导致找不到父 POM | 子模块 parent 的 relativePath 默认为 ../pom.xml，目录结构不符 | 显式写 relativePath 或设空，配合 -N 在父目录安装 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| mirrorOf 配成 * 导致私服内部构件拉取失败 | 镜像拦截了所有仓库请求，私服被重定向 | mirrorOf 限定为 central，或用 `*,!nexus-public` 排除私服 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| servers 的 id 不匹配导致 deploy 报 401 Unauthorized | distributionManagement 的 repository id 与 settings 的 server id 不一致 | 两处 id 保持完全一致，并确认账号有写入权限 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| releases 仓库重复上传报 400 Repository does not allow updating assets | releases 仓库禁止覆盖同版本 | 重新发布前升级版本号，或改用 SNAPSHOT；需要覆盖时在 Nexus 开启该仓库的 Allow Redeploy | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| SNAPSHOT 不更新，拉取到旧快照 | 本地缓存了旧 SNAPSHOT，updatePolicy 默认 daily | 设 updatePolicy=always，或加 `-U` 强制更新（`mvn clean package -U`） | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| 离线构建失败，报 Cannot access 仓库 | 本地仓库缺构件且 offline=true | settings.xml 设 offline=false，或预先在联网环境 install 好构件 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| 密码明文泄露，settings.xml 中明文存储私服密码 | 直接写 password | 用 `${env.NEXUS_PWD}` 从环境变量读取，或用 mvn 的 settings security 加密 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| 在 dependencyManagement 里声明后子模块仍报找不到类 | 子模块以为父 POM 已经引入依赖，编译报 cannot find symbol | 混淆 dependencyManagement 与 dependencies，前者只声明版本、不实际引入依赖 | 子模块需显式声明 GAV（可省略 version），dependencyManagement 才会把版本套上去 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 引入 spring-boot-dependencies 后版本仍不受控 | BOM 中的版本没有生效，仍需逐个写版本号 | `scope=import` 必须与 `type=pom` 成对出现，缺一不可 | dependencyManagement 中导入 BOM 时同时写 `<type>pom</type>` 和 `<scope>import</scope>` | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 公共库把一堆第三方依赖传递给所有下游服务 | 下游 classpath 被污染，出现意料之外的类 | 公共库中非必需的依赖未标记为可选，传递依赖默认全量传播 | 在公共库 POM 中给可选依赖加 `<optional>true</optional>`，下游需要时自行声明 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 在子模块目录执行 install 报找不到兄弟模块 | 编译报兄弟模块的坐标无法解析 | 只在子目录构建了当前模块，兄弟模块尚未安装到本地仓库 | 在父目录执行 `mvn install`（聚合一次构建全部），或用 `-pl order-service -am` 同时构建其依赖模块 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 聚合与继承混淆导致某个模块被漏构建 | 打包后产物缺少某个子模块 | 以为写了 `<parent>` 就等于被聚合，实际未列入父 POM 的 `<modules>` | 聚合靠父 POM 的 `<modules>`，继承靠子模块的 `<parent>`，两者独立配置、按需组合 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 用 -DskipTests 跳测试后 CI 依然很慢 | 测试没有执行，但测试类仍在编译，耗时没降下来 | `-DskipTests` 只跳过测试执行，测试代码依旧参与编译 | 彻底跳过用 `-Dmaven.test.skip=true`；`-DskipTests` 仅用于临时排查 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 生产构建长期带 -DskipTests，缺陷直接漏到线上 | 单测形同虚设，回归问题反复出现 | 把"跳过测试加速构建"当成常规手段，质量门禁缺失 | CI 保留测试执行作为质量门禁，只在明确排障时临时跳过 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| 插件未锁版本导致不同环境构建结果不一致 | 同一份代码在不同机器上打包产物行为不同 | 插件未写 `<version>`，不同 Maven 版本绑定的默认插件版本不同 | 在父 POM 的 pluginManagement 中统一锁定插件版本 | [Maven核心原理与依赖管理](./01-Maven核心原理与依赖管理-导览.md) |
| profile 未激活导致环境配置没生效 | 构建产物仍是默认 dev 配置，上线后连错库 | 只在 POM 声明了 profile 却没用 `-P` 激活，或 activeByDefault 被其他 profile 覆盖 | 构建时显式 `-P prod`；注意 activeByDefault 在其他 profile 被激活时会失效 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| Spring Boot 资源过滤占位符冲突，配置项没被替换 | 打包后 application.yml 里仍是 `@env@` 或 `${env}` 原样 | Spring 的 `${}` 占位符与 Maven 资源过滤语法冲突 | 使用 `@env@` 分隔符（spring-boot-starter-parent 默认），避免与 Spring 占位符冲突 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
| deploy 成功但同事仍拉不到构件 | 自己本地能编译，同事解析依赖失败 | 发布用的 repository 与对方读取的 repository 不是同一个（如只发到 releases 却读 snapshots） | 核对 distributionManagement 与 profile 中 repositories 的地址与策略是否指向同一仓库 | [Maven私服与实战配置](./02-Maven私服与实战配置-导览.md) |
