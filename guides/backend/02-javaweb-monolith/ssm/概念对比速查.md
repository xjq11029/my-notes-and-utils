# SSM - 概念对比速查

---

### Spring IoC vs DI

| 对比维度 | IoC（控制反转） | DI（依赖注入） |
|---------|----------------|---------------|
| 核心定位 | 一种设计思想，将对象创建和依赖管理的控制权从程序代码转移给容器 | IoC 的具体实现方式，容器动态将依赖对象注入到目标对象中 |
| 层次关系 | 是思想/原则层面 | 是实现/手段层面 |
| 关注点 | 谁控制对象的创建和生命周期 | 如何将被依赖的对象传递给目标对象 |
| 实现方式 | 通过 DI 和 DL（依赖查找）两种方式实现 | 通过构造器注入、Setter 注入、字段注入三种方式实现 |
| 容器角色 | 容器作为控制者，管理所有 Bean 的生命周期 | 容器在创建 Bean 时解析依赖关系并完成注入 |
| 选择建议 | IoC 是目标，DI 是实现目标的手段；理解 IoC 思想是掌握 Spring 的基础 | 优先使用构造器注入，避免字段注入，Setter 注入用于可选依赖 |

### BeanFactory vs ApplicationContext

| 对比维度 | BeanFactory | ApplicationContext |
|---------|------------|-------------------|
| 核心定位 | Spring IoC 容器的基础接口，提供最基本的 Bean 管理功能 | BeanFactory 的子接口，提供更丰富的企业级功能 |
| Bean 加载时机 | 延迟加载（Lazy），首次 getBean() 时才创建 | 预加载（Eager），容器启动时创建所有单例 Bean |
| 国际化支持 | 不支持 | 支持 MessageSource 国际化 |
| 事件发布 | 不支持 | 支持 ApplicationEvent 事件发布与监听 |
| 资源加载 | 不支持 | 支持 ResourceLoader 统一资源加载 |
| 环境与配置 | 不支持 | 支持 Environment 和 @PropertySource 配置管理 |
| AOP 支持 | 需手动配置 | 内置 AOP 支持 |
| 启动速度 | 快，不创建 Bean | 较慢，启动时创建所有单例 Bean |
| 内存占用 | 低，按需创建 | 较高，预加载所有单例 Bean |
| 适用场景 | 资源受限环境（如移动设备、小程序） | 企业级应用开发，功能完整 |
| 选择建议 | 几乎不需要直接使用 BeanFactory，ApplicationContext 是企业开发的标准选择 | 使用 AnnotationConfigApplicationContext 或 ClassPathXmlApplicationContext |

### AOP vs 拦截器

| 对比维度 | AOP（面向切面编程） | 拦截器（Interceptor） |
|---------|-------------------|---------------------|
| 核心定位 | 编程范式，将横切关注点（日志、事务、安全）从业务逻辑中分离 | Web 层请求拦截组件，在 Controller 方法执行前后进行拦截 |
| 所属规范 | Spring 框架核心特性 | Spring MVC 框架组件 |
| 拦截粒度 | 方法级别，可拦截任意 Spring Bean 的任意方法 | 请求级别，仅拦截进入 DispatcherServlet 的 HTTP 请求 |
| 连接点类型 | 方法执行、异常抛出、字段访问等 | 仅 HTTP 请求处理 |
| 实现方式 | @Aspect + @Around/@Before/@After 等注解，或 XML 配置 | 实现 HandlerInterceptor 接口，重写 preHandle/postHandle/afterCompletion |
| 可访问资源 | 可访问方法参数、返回值、异常、目标对象 | 可访问 HttpServletRequest、HttpServletResponse、Handler |
| 执行顺序 | 通过 @Order 注解或实现 Ordered 接口控制 | 通过注册顺序和 addPathPatterns/excludePathPatterns 控制 |
| 适用场景 | 事务管理、日志记录、权限校验、性能监控、缓存 | 登录验证、权限检查、请求日志、参数预处理 |
| 选择建议 | 需要拦截非 Web 层方法或需要精细方法级控制时使用 AOP | 仅需拦截 Web 请求、需要访问请求/响应对象时使用拦截器 |

### Spring MVC vs Struts2

| 对比维度 | Spring MVC | Struts2 |
|---------|-----------|---------|
| 核心定位 | 基于方法级别的轻量级 MVC 框架，与 Spring 生态无缝集成 | 基于类级别的 MVC 框架，继承自 WebWork |
| 入口 | DispatcherServlet（Servlet） | StrutsPrepareAndExecuteFilter（Filter） |
| 请求映射粒度 | 方法级别，一个 Controller 类可包含多个处理方法 | 类级别，一个 Action 类通常对应一个请求（或通过方法调用配置） |
| 线程安全 | Controller 默认单例，线程安全由开发者保证 | Action 每次请求创建新实例，天然线程安全 |
| 参数绑定 | 通过 @RequestParam、@PathVariable、@RequestBody 等注解直接绑定 | 通过 Action 属性 + 拦截器栈实现参数注入 |
| 返回值处理 | 支持 @ResponseBody（JSON）、ModelAndView、String 视图名等多种方式 | 返回 String 类型的逻辑视图名，通过 Result 配置指定视图 |
| RESTful 支持 | 原生支持，@GetMapping/@PostMapping 等注解 | 需额外配置，支持不如 Spring MVC 自然 |
| 配置复杂度 | 注解驱动，配置简洁 | 需 struts.xml 配置文件，配置相对复杂 |
| 社区与生态 | Spring 生态核心组件，社区活跃，文档完善 | 社区萎缩，新项目很少采用 |
| 选择建议 | 现代 Java Web 项目首选，与 Spring Boot 深度集成 | 维护遗留项目时使用，新项目不推荐 |
