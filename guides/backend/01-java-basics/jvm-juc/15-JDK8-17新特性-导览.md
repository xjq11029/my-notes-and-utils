## 一、核心概念

### 1.1 Lambda 表达式

| 维度 | 内容 |
|------|------|
| 是什么 | JDK8 引入的匿名函数语法，简化函数式接口实例的编写 |
| 能做什么 | 替代匿名内部类；作为参数传递；配合 Stream 与 Optional；闭包捕获变量 |
| 怎么用 | `list.forEach(s -> System.out.println(s));` |
| 原理和工作流程 | Lambda 本质是函数式接口的实例，语法为 参数列表 -> 表达式或语句块。无参用 ()，单参可省括号，多参用 (a,b)。类型可推断。捕获外部变量须 final 或 effectively final。编译为 invokedynamic 指令运行时由 LambdaMetafactory 生成实现类，比匿名内部类少生成额外类文件 |
| 缺点 | 复杂逻辑可读性差；调试栈信息不直观；捕获变量限制；过度嵌套致回调地狱 |

### 1.2 函数式接口

| 维度 | 内容 |
|------|------|
| 是什么 | 有且仅有一个抽象方法的接口，是 Lambda 的类型基础 |
| 能做什么 | @FunctionalInterface 校验；四大核心接口；自定义业务接口 |
| 怎么用 | `@FunctionalInterface interface Fn { void apply(); }` |
| 原理和工作流程 | 函数式接口仅一个抽象方法可含默认与静态方法。四大核心：Predicate<T> 接受 T 返回 boolean 用于过滤，Function<T,R> 接受 T 返回 R 用于转换，Consumer<T> 接受 T 无返回用于消费，Supplier<T> 无参返回 T 用于生产。BiFunction 与 BiConsumer 等为扩展。@FunctionalInterface 注解让编译器校验单抽象方法 |
| 缺点 | 仅单抽象方法限制；默认方法多时易混；初学者对四大接口不熟；与泛型结合复杂 |

### 1.3 方法引用与构造器引用

| 维度 | 内容 |
|------|------|
| 是什么 | Lambda 的简写形式，用 :: 直接引用已有方法或构造器 |
| 能做什么 | 类名::静态方法；对象::实例方法；类名::实例方法；类名::new 构造器 |
| 怎么用 | `list.forEach(System.out::println);` 或 `User::new` |
| 原理和工作流程 | 四种引用：一类名::静态方法如 Integer::parseInt。二对象::实例方法如 System.out::println。三类名::实例方法如 String::length 第一个参数作接收者。四类名::new 构造器引用如 User::new。方法引用要求方法签名与函数式接口抽象方法匹配，是 Lambda 的语法糖更简洁 |
| 缺点 | 仅匹配单方法时可用；过简降低可读性；重载方法引用歧义；初学者难匹配签名 |

### 1.4 Stream API

| 维度 | 内容 |
|------|------|
| 是什么 | JDK8 引入的对集合进行函数式流式操作的 API |
| 能做什么 | 中间操作 filter、map、sorted；终止操作 collect、forEach、reduce；惰性求值；并行流 |
| 怎么用 | `list.stream().filter(s->s.length()>3).map(String::toUpperCase).collect(toList());` |
| 原理和工作流程 | Stream 分中间操作与终止操作。中间操作如 filter、map、sorted、distinct 是惰性的不立即执行只记录操作。终止操作如 collect、forEach、reduce、count 触发流水线执行。惰性求值允许多操作融合一次遍历。Stream 不存数据不修改源。parallelStream 用 ForkJoinPool 并行处理适合大数据量 |
| 缺点 | 学习曲线陡；调试不直观；并行流有线程安全与顺序问题；小数据量开销大于 for |

### 1.5 Optional

| 维度 | 内容 |
|------|------|
| 是什么 | JDK8 引入的包装可能为 null 值的容器类，避免 NPE |
| 能做什么 | of/ofNullable 创建；map/flatMap 转换；filter 过滤；orElse/orElseGet 默认值；ifPresent 消费 |
| 怎么用 | `Optional.ofNullable(user).map(User::getName).orElse("默认");` |
| 原理和工作流程 | Optional 是容器包装一个可能为 null 的值。of 不接受 null，ofNullable 接受 null。map 与 flatMap 链式转换值非 null 才执行。filter 过滤。orElse 与 orElseGet 提供默认值，orElse 总计算默认值 orElseGet 仅在空时调 Supplier。ifPresent 有值才消费。设计为方法返回类型而非字段，强制调用方处理空 |
| 缺点 | 不应作字段序列化复杂；orElse 总计算默认值浪费；嵌套 flatMap 复杂；不能完全消除 NPE |

### 1.6 接口默认方法与静态方法

| 维度 | 内容 |
|------|------|
| 是什么 | JDK8 允许接口含 default 默认方法与 static 静态方法的增强 |
| 能做什么 | default 提供默认实现可被重写；static 属接口不可重写；向后兼容扩展接口 |
| 怎么用 | `default void m(){}` 或 `static int add(a,b){}` |
| 原理和工作流程 | JDK8 接口增强允许默认方法用 default 提供实现实现类可重写可不，静态方法属接口通过接口名调用实现类不继承。解决接口扩展向后兼容问题如 Collection 加 stream 不破坏已有实现。多接口同名默认方法冲突实现类必须重写。类优先原则：类方法优于接口默认方法，子接口优于父接口 |
| 缺点 | 多继承冲突需手动解决；过度使用破坏接口纯粹性；静态方法不能被实现类继承；菱形继承复杂 |

### 1.7 var 局部变量类型推断（JDK 10）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK10 引入的局部变量类型推断关键字 var |
| 能做什么 | 局部变量省略类型；编译期推断；简化泛型与链式声明 |
| 怎么用 | `var list = new ArrayList<String>();` |
| 原理和工作流程 | var 仅用于局部变量声明，编译期根据右侧表达式推断类型并在字节码写入具体类型，运行时仍是强类型无影响。var 不可用于字段、方法参数、返回值。适合类型明显或泛型冗长的场景如 var stream = list.stream()。var 是语法糖不引入动态类型 |
| 缺点 | 仅局部变量；过度使用降低可读性；推断类型可能不符合预期如 var i = 1 为 int；不可用于 null |

### 1.8 记录类 Record（JDK 14 预览，JDK 16 正式）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK16 正式的不可变数据载体类，自动生成构造器、getter、equals、hashCode、toString |
| 能做什么 | 简洁声明不可变 DTO；自动生成访问器与相等方法；解构模式匹配；紧凑构造器校验 |
| 怎么用 | `record Point(int x, int y) {}` |
| 原理和工作流程 | record 是 final 不可变类，组件为 private final 字段，自动生成全参构造器、访问器 x() 与 y()、equals、hashCode、toString。紧凑构造器可在构造时校验如 if(x<0) throw。record 不能 extends 其他类但可实现接口，不能定义可变字段。适合 DTO、值对象、不可变数据，替代 Lombok @Value 的样板代码 |
| 缺点 | 不可变不能修改；不能继承类；访问器名为字段名无 get 前缀与传统不符；不能自定义实例字段 |

### 1.9 密封类 Sealed Class（JDK 15 预览，JDK 17 正式）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK17 正式的限制哪些类可继承或实现它的修饰符 sealed 与 permits |
| 能做什么 | sealed 声明密封类；permits 指定子类；子类须为 final、sealed 或 non-sealed；穷尽模式匹配 |
| 怎么用 | `sealed interface Shape permits Circle, Square {}` |
| 原理和工作流程 | sealed 修饰类或接口声明密封，permits 列出允许的子类。子类必须明确为 final 不再可继承、sealed 继续密封、non-sealed 开放继承三者之一。密封类让编译器知晓所有子类，支持 switch 模式匹配的穷尽性检查，缺 default 也编译通过。用于建模封闭领域如状态机、代数数据类型 |
| 缺点 | 子类须同模块或同包；permits 列表维护成本；与 final 相比更灵活但更复杂；需 JDK17 |

### 1.10 模式匹配（Pattern Matching）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK16 instanceof 模式匹配与 JDK21 switch 模式匹配，简化类型判断与绑定 |
| 能做什么 | instanceof 模式绑定变量；switch 类型与 record 模式；穷尽性检查；简化 instanceof 强转 |
| 怎么用 | `if (obj instanceof String s) { s.length(); }` |
| 原理和工作流程 | instanceof 模式匹配 JDK16 正式：`obj instanceof String s` 判断同时绑定变量 s 作用域内可直接用免强转。switch 模式匹配 JDK21：case 可匹配类型如 case Integer i、record 组件如 case Point(int x,int y)、null 处理。密封类配合 switch 实现穷尽性检查编译器校验所有分支。简化类型判断与数据解构代码 |
| 缺点 | switch 模式匹配需 JDK21；模式作用域规则复杂；record 解构需理解；旧代码迁移成本 |

### 1.11 文本块 Text Block（JDK 13 预览，JDK 15 正式）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK15 正式的用三引号定义多行字符串字面量的语法 |
| 能做什么 | 多行字符串免转义；保留格式；\ 转义换行；\s 保留尾部空格；模板 SQL JSON |
| 怎么用 | `String json = """ { "name":"张三" } """;` |
| 原理和工作流程 | 文本块用三引号 """ 包裹多行字符串，编译期处理换行与缩进。开闭三引号最小缩进决定去除前导空格，使代码缩进不影响内容。\ 转义换行合并为一行，\s 保留尾部空格。文本块仍是 String 对象编译期常量进常量池。免转义简化 SQL、JSON、HTML 等多行文本编写 |
| 缺点 | 缩进规则需理解；\ 与 \s 转义易混；不支持插值需 String.format；开闭引号位置影响缩进 |

## 二、底层原理

### 2.1 Lambda 实现原理

| 维度 | 内容 |
|------|------|
| 是什么 | Lambda 编译为 invokedynamic 指令运行时生成实现类的原理 |
| 能做什么 | invokedynamic 指令；LambdaMetafactory 生成；不生成额外类文件；捕获变量存字段 |
| 怎么用 | javap 查看 invokedynamic 指令 |
| 原理和工作流程 | Lambda 编译为 invokedynamic 指令而非生成匿名类。首次执行时 invokedynamic 引导 LambdaMetafactory.metafactory 动态生成实现函数式接口的字节码，生成内部类如 $$Lambda$1。无捕获 Lambda 实现为单例复用，有捕获 Lambda 每次创建实例捕获变量存字段。方法体提取为私有静态方法 invokedynamic 调用。比匿名内部类少生成额外类文件更高效 |
| 缺点 | 生成类对开发者透明；调试栈信息不直观；首次执行有引导开销；捕获 Lambda 需新实例 |

### 2.2 Stream 执行原理

| 维度 | 内容 |
|------|------|
| 是什么 | Stream 惰性求值与流水线融合的执行机制 |
| 能做什么 | 中间操作记录不执行；终止操作触发；操作融合一次遍历；并行流 ForkJoinPool |
| 怎么用 | 中间操作链以 pipeline 组织终止操作触发 |
| 原理和工作流程 | Stream 内部用 pipeline 模式，每个中间操作返回新 Stream 并记录操作谓词。中间操作惰性不立即执行。终止操作触发时反向回溯构建执行链，元素逐个流经所有操作融合为一次遍历避免多次集合遍历。短路操作如 findFirst、anyMatch 遇满足条件立即停止。并行流用 ForkJoinPool.commonPool 分割任务并行处理 |
| 缺点 | 调试不直观难看中间状态；并行流有线程安全与顺序问题；小数据量开销大；短路需理解 |

### 2.3 Optional 内部实现

| 维度 | 内容 |
|------|------|
| 是什么 | Optional 内部 value 字段与链式方法返回新 Optional 的实现 |
| 能做什么 | 内部 final value；map 返回新 Optional；filter 条件过滤；flatMap 处理嵌套 |
| 怎么用 | map 与 flatMap 链式调用 |
| 原理和工作流程 | Optional 内部 private final T value，of 与 ofNullable 创建实例 of 校验非 null。map 接收 Function，value 非 null 则应用函数返回 ofNullable(结果) 否则 empty。flatMap 与 map 区别在于 Function 返回 Optional 避免 Optional<Optional> 嵌套。filter 接收 Predicate 不满足返回 empty。所有方法不修改原 Optional 返回新实例符合不可变设计 |
| 缺点 | map 与 flatMap 区别易混；嵌套处理复杂；不应序列化；不能完全消除 NPE |

### 2.4 Record 底层实现

| 维度 | 内容 |
|------|------|
| 是什么 | Record 编译为 final 类并自动生成方法的底层机制 |
| 能做什么 | final 类不可继承；private final 字段；自动生成全参构造器与访问器；自动 equals/hashCode/toString |
| 怎么用 | `record Point(int x,int y){}` 编译为 final 类 |
| 原理和工作流程 | record 编译为继承 java.lang.Record 的 final 类，组件为 private final 字段。自动生成规范构造器赋值所有字段，访问器方法名为字段名无 get 前缀。equals 与 hashCode 基于所有字段，toString 格式为 类名[字段=值]。可加紧凑构造器校验。Record 不可继承其他类但可实现接口，不能定义额外实例字段只能静态字段 |
| 缺点 | 访问器无 get 前缀与传统 Bean 不符影响框架；不可变不能修改；不能继承类；不能加实例字段 |

## 三、实战应用

### 3.1 Stream 实战：订单数据处理

| 维度 | 内容 |
|------|------|
| 是什么 | 用 Stream 对订单列表进行过滤分组统计的实战 |
| 能做什么 | filter 过滤；map 转换；groupingBy 分组；summarizingDouble 统计；sorted 排序 |
| 怎么用 | `orders.stream().filter(o->o.getAmount()>100).collect(groupingBy(Order::getCategory))` |
| 原理和工作流程 | 用 filter 过滤金额大于 100 的订单，map 提取客户名，groupingBy 按分类分组为 Map，summingDouble 统计每类总金额，sorted 按金额降序，limit 取前 10。collect 触发终止操作流水线一次遍历完成。相比传统 for 循环代码更声明式简洁，但需熟悉收集器 Collectors API |
| 缺点 | 收集器 API 多需记忆；调试不直观；大数据量需考虑并行流；性能不如手写 for |

### 3.2 Optional 实战：避免 NPE 链式调用

| 维度 | 内容 |
|------|------|
| 是什么 | 用 Optional 链式调用避免深层属性 NPE 的实战 |
| 能做什么 | ofNullable 包装；map 链式取属性；orElse 提供默认；避免层层判空 |
| 怎么用 | `Optional.ofNullable(user).map(User::getAddr).map(Addr::getCity).orElse("未知")` |
| 原理和工作流程 | 用 ofNullable 包装可能为 null 的 user，map 链式取 addr 与 city，任一层为 null 则 map 返回 empty 不抛 NPE，最终 orElse 提供默认值。相比传统 if(user!=null && user.getAddr()!=null) 层层判空更简洁优雅。适合方法返回值链式处理，但不应滥用作字段 |
| 缺点 | 不应作字段；嵌套深时 flatMap 复杂；orElse 总计算默认值；不能完全替代判空 |

### 3.3 文本块 + 模式匹配实战

### 3.4 密封类实战：支付状态机

### 3.5 函数式接口组合

|------|------|
| 是什么 | 用 andThen、compose、and、or、negate 组合函数式接口的实战 |

## 四、常见面试题（附答案）

### 1. Lambda 表达式的底层实现原理是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Lambda 编译为 invokedynamic 的实现 |
| 能做什么 | 解释 invokedynamic 指令；解释 LambdaMetafactory 生成；解释不生成类文件 |
| 怎么用 | javap 查看 invokedynamic |
| 原理和工作流程 | Lambda 编译为 invokedynamic 指令而非匿名内部类。首次执行时引导方法 LambdaMetafactory.metafactory 动态生成实现函数式接口的内部类如 $$Lambda$1。方法体提取为私有静态方法。无捕获 Lambda 实例为单例复用有捕获每次新建实例捕获变量存字段。比匿名内部类少生成额外类文件更高效 |
| 缺点 | 生成类透明难调试；首次引导开销；捕获 Lambda 需新实例；调试栈不直观 |

### 2. Stream 的中间操作和终止操作有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Stream 中间与终止操作的惰性求值区别 |
| 能做什么 | 区分惰性与立即；说明融合一次遍历；说明短路；列举操作 |
| 怎么用 | 中间操作返回 Stream，终止操作触发执行 |
| 原理和工作流程 | 中间操作如 filter、map、sorted、distinct 返回新 Stream 是惰性的只记录操作不立即执行。终止操作如 collect、forEach、reduce、count、findFirst 触发流水线执行。惰性求值允许多操作融合为一次遍历避免多次集合遍历。短路终止操作 findFirst、anyMatch 遇满足条件立即停止。无终止操作中间操作不执行 |
| 缺点 | 无终止操作不执行易误解；调试不直观；短路需理解；小数据量开销大 |

### 3. orElse 和 orElseGet 有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Optional 两个默认值方法的执行时机区别 |
| 能做什么 | 区分 orElse 总计算；区分 orElseGet 惰性调用；说明性能影响 |
| 怎么用 | 默认值轻量用 orElse，计算重或副作用用 orElseGet |
| 原理和工作流程 | orElse(T other) 无论 Optional 是否有值都会计算 other 参数，因 Java 参数求值是立即的。orElseGet(Supplier supplier) 仅在 Optional 为空时才调用 Supplier 获取默认值是惰性的。当默认值是重计算或有副作用时 orElse 会浪费计算应用 orElseGet。轻量默认值如字符串字面量用 orElse 无妨 |
| 缺点 | orElse 总计算易踩坑；重计算用 orElse 性能差；需理解参数求值时机；选择需谨慎 |

### 4. Record 和 Lombok @Data 有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Record 与 Lombok @Data 的差异 |
| 能做什么 | 对比语言级与工具级；对比不可变与可变；对比访问器命名；对比依赖 |
| 怎么用 | 不可变 DTO 用 Record，可变 Bean 用 Lombok |
| 原理和工作流程 | Record 是 JDK16 语言级特性 final 不可变，字段 private final，访问器名为字段名无 get 前缀，自动生成全参构造器与 equals、hashCode、toString，无 setter。Lombok @Data 是工具注解编译期生成 getter setter 生成 get 前缀访问器与无参构造器，可变非 final，需 Lombok 依赖。Record 不可变适合 DTO 值对象，Lombok 适合传统可变 Bean 兼容框架 |
| 缺点 | Record 访问器无 get 前缀影响框架兼容；不可变不能修改；Lombok 需依赖；各有适用场景 |

### 5. 密封类和 final 类有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查密封类与 final 类的继承限制差异 |
| 能做什么 | 区分完全禁止与指定允许；说明 permits；说明穷尽性检查 |
| 怎么用 | 完全禁止继承用 final，指定子类用 sealed |
| 原理和工作流程 | final 类完全禁止任何类继承。密封类用 sealed 修饰 permits 指定允许的子类，子类须为 final、sealed 或 non-sealed。密封类允许受控继承指定固定子类，配合 switch 模式匹配实现穷尽性检查编译器校验所有分支。final 是密封的极端形式 permits 为空。密封类适合建模封闭领域如状态机，final 适合完全不可变类如 String |
| 缺点 | 密封类需 JDK17；permits 维护成本；子类限制严格；理解成本高于 final |

### 6. Stream 并行流和普通流的区别？什么时候用并行流？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查并行流与串行流的区别与适用场景 |
| 能做什么 | 区分单线程与 ForkJoinPool 并行；说明线程安全要求；说明适用场景 |
| 怎么用 | 大数据量 CPU 密集且线程安全用 parallelStream |
| 原理和工作流程 | 普通流单线程顺序处理。并行流用 ForkJoinPool.commonPool 自动分割任务多线程并行处理。并行流要求操作无状态且线程安全，结果顺序不保证除非用 forEachOrdered。适用场景：数据量大（万级以上）、CPU 密集计算、操作无状态线程安全、不关心顺序。小数据量或 IO 操作并行流开销大于收益不宜用 |
| 缺点 | 共用 commonPool 致资源竞争；线程安全要求高；顺序不保证；小数据量开销大 |

### 7. 接口默认方法解决了什么问题？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查默认方法引入的动机与解决的问题 |
| 能做什么 | 向后兼容扩展接口；库 API 演进；多继承默认实现；解决 Collection 加 stream 问题 |
| 怎么用 | `default Stream stream() { return StreamSupport.stream(...); }` |
| 原理和工作流程 | JDK8 前接口只能有抽象方法，扩展接口会破坏所有已有实现类。默认方法用 default 提供默认实现，实现类不重写也能用，使接口可向后兼容地添加新方法。典型如 Collection 接口加 stream 与 forEach 默认方法不破坏已有集合实现。多接口同名默认方法冲突实现类须重写，遵循类优先原则 |
| 缺点 | 多继承冲突需手动解决；过度使用破坏纯粹性；菱形继承复杂；与抽象类边界模糊 |
