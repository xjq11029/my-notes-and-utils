## 一、核心概念

### 1.1 数组概述

| 维度 | 内容 |
|------|------|
| 是什么 | 多个相同类型数据按顺序排列、用统一名字与下标管理的集合 |
| 能做什么 | 固定类型与长度；连续内存 O(1) 访问；自动默认初始化 |
| 怎么用 | `int[] arr = new int[5];` |
| 原理和工作流程 | 数组是引用类型，变量存堆中数组对象首地址。元素类型固定，长度创建后不可变，在堆中连续存储支持随机访问。创建后元素按类型自动赋予默认值，int 为 0、引用类型为 null。length 属性存于对象头创建时确定不可更改 |
| 缺点 | 长度固定不可动态调整；类型单一不能混存；插入删除需移动元素 O(n) |

### 1.2 一维数组

| 维度 | 内容 |
|------|------|
| 是什么 | 单一下标索引的线性数组，分静态与动态两种初始化方式 |
| 能做什么 | 静态初始化声明即赋值；动态初始化指定长度后逐个赋值；按默认值填充 |
| 怎么用 | `int[] a = {1,2,3};` 或 `int[] b = new int[5];` |
| 原理和工作流程 | 静态初始化 `new int[]{...}` 或简写 `{...}` 在声明时直接给定元素。动态初始化 `new int[5]` 先分配长度全部填默认值再逐个赋值。推荐 `int[] arr` 写法。基本类型数组默认 0，boolean 默认 false，char 默认空字符，引用类型默认 null |
| 缺点 | 简写仅限声明时使用；动态初始化忘记赋值用默认值易出 bug；与 Python list 等动态数组差异大 |

### 1.3 二维数组

| 维度 | 内容 |
|------|------|
| 是什么 | 本质为"数组的数组"的二维结构，每行长度可不同 |
| 能做什么 | 静态初始化嵌套花括号；动态初始化指定外层或内外层长度；构造不规则数组 |
| 怎么用 | `int[][] a = {{1,2},{3,4,5}};` 或 `new int[3][4]` |
| 原理和工作流程 | 二维数组是一维数组，每个元素又是一维数组引用。外层数组在堆连续存内层数组引用地址，各内层数组独立分配不一定连续，故每行长度可不同形成锯齿数组。`new int[3][]` 仅分配外层内层为 null 须逐行初始化，`new int[3][4]` 同时分配内外层 |
| 缺点 | 内层未初始化访问致 NPE；不规则数组遍历需按行长度；嵌套结构内存不连续影响缓存命中 |

## 二、底层原理：数组内存模型（重点）

### 2.1 JVM 内存区域回顾

| 维度 | 内容 |
|------|------|
| 是什么 | JVM 划分的栈、堆、方法区三大内存区域及其职责 |
| 能做什么 | 区分存储内容；区分线程共享与私有；为理解数组内存奠基 |
| 怎么用 | 局部变量与调用帧入栈，对象与数组入堆，类信息入方法区 |
| 原理和工作流程 | 栈存储局部变量与方法调用帧，线程私有生命周期与线程相同。堆存储所有对象实例与数组，线程共享是 GC 主要区域。方法区存储类信息、常量、静态变量，线程共享。理解三者分工是分析数组内存行为的前提 |
| 缺点 | 内存划分抽象初学者难对应实际代码；栈溢出与堆溢出表现不同；方法区演进（永久代→元空间）增加认知成本 |

### 2.2 一维数组内存解析

| 维度 | 内容 |
|------|------|
| 是什么 | 一维数组在栈堆间的引用与对象存储关系，区分基本类型与引用类型数组 |
| 能做什么 | 解释栈存引用堆存对象；解释连续存储 O(1) 访问；解释引用类型数组二级引用 |
| 怎么用 | `int[] arr = new int[]{10,20,30};` arr 在栈指向堆数组 |
| 原理和工作流程 | arr 变量在栈存堆中数组对象首地址，数组元素在堆连续存储。基本类型数组元素直接存值，引用类型数组元素存对象引用而非对象本身，实际 String 等对象存于堆其他位置。通过首地址加索引乘元素大小计算地址实现 O(1) 随机访问。length 存于对象头 |
| 缺点 | 引用类型数组多级间接降低缓存命中；引用本身占用额外内存；理解层级多易混淆 |

### 2.3 二维数组内存解析

| 维度 | 内容 |
|------|------|
| 是什么 | 二维数组外层存内层引用、各内层独立分配的内存模型 |
| 能做什么 | 解释外层存引用地址；解释内层不一定连续；解释不规则数组成因 |
| 怎么用 | `int[][] arr = {{1,2,3},{4,5},{6,7,8}};` |
| 原理和工作流程 | 外层数组在堆连续存内层数组的引用地址而非内层数据。各内层数组在堆独立分配不一定连续。访问 arr[1][2] 先经外层引用找到内层数组引用再找到具体元素。因内层独立分配故每行长度可不同形成锯齿数组 |
| 缺点 | 二级间接访问降低性能；内存不连续影响缓存；不规则数组遍历需按行长度判断 |

### 2.4 数组赋值与复制的内存行为

| 维度 | 内容 |
|------|------|
| 是什么 | 数组变量赋值的引用传递与真正复制的区别及四种复制方式 |
| 能做什么 | 区分引用传递与值复制；用 System.arraycopy 等复制；区分基本类型深拷贝与引用类型浅拷贝 |
| 怎么用 | `int[] copy = Arrays.copyOf(arr, arr.length);` |
| 原理和工作流程 | `int[] b = a` 仅复制引用两变量指向同一数组对象，改 b 影响 a。真正复制有四种：手动循环、System.arraycopy（native 性能最优）、Arrays.copyOf（基于前者封装）、clone。对基本类型数组是深拷贝元素独立，对引用类型数组复制的是引用本身属浅拷贝 |
| 缺点 | 引用传递误认为复制是高频 bug；引用类型数组浅拷贝共享内部对象；深拷贝需手动递归复制 |

### 2.5 数组作为方法参数的内存解析

| 维度 | 内容 |
|------|------|
| 是什么 | 数组作方法参数时引用地址值传递可在方法内修改对象状态的机制 |
| 能做什么 | 传递数组引用；方法内修改堆中数组；理解 Java 只有值传递 |
| 怎么用 | `void modify(int[] arr){ arr[0]=999; }` |
| 原理和工作流程 | 调用方法时将 nums 的值即数组对象地址复制一份传给形参 arr，arr 与 nums 指向堆中同一数组对象，方法内通过 arr[0]=999 修改堆对象内容，方法返回后 nums[0] 也变 999。Java 方法参数只有值传递，引用类型传递的是地址的值，故可改对象状态但不能改原引用指向 |
| 缺点 | 误以为引用传递可在方法内改变原引用指向；方法内修改数组的副作用难追踪；值传递概念易混淆 |

## 三、实战应用：数组常见算法

### 3.1 数组反转

| 维度 | 内容 |
|------|------|
| 是什么 | 将数组元素顺序前后颠倒的算法，分原地与新数组两种 |
| 能做什么 | 双指针原地反转空间 O(1)；新建数组反转空间 O(n) |
| 怎么用 | 双指针 `left=0,right=len-1` 交换后靠近 |
| 原理和工作流程 | 原地反转用双指针，left 从头 right 从尾，交换两元素后 left 加 1 right 减 1 直到相遇，空间 O(1)。新建数组法创建等长数组，将原数组从末尾按序填入，空间 O(n) 但不修改原数组 |
| 缺点 | 原地反转修改原数组；新数组法多占内存；奇数长度中间元素处理需注意边界 |

### 3.2 数组扩容

| 维度 | 内容 |
|------|------|
| 是什么 | 因数组长度不可变，通过新建大数组并复制实现的扩容操作 |
| 能做什么 | 创建新数组复制旧元素；ArrayList 1.5 倍扩容策略；用 Arrays.copyOf 简化 |
| 怎么用 | `int[] newArr = Arrays.copyOf(arr, newCapacity);` |
| 原理和工作流程 | 数组长度固定，扩容本质是新建更大数组再用 System.arraycopy 复制旧元素，多出位置填默认值。ArrayList 内部 grow 方法按 `oldCapacity + (oldCapacity >> 1)` 即 1.5 倍扩容，并用 Arrays.copyOf 替换内部数组引用 |
| 缺点 | 扩容需全量复制 O(n)；1.5 倍策略可能浪费空间；频繁扩容影响性能应预设容量 |

### 3.3 数组缩容

| 维度 | 内容 |
|------|------|
| 是什么 | 删除指定位置或匹配元素后通过新建小数组实现的缩容操作 |
| 能做什么 | 删除指定索引元素；删除首个匹配值；前移后续元素 |
| 怎么用 | 两次 System.arraycopy 分别复制 index 前后元素 |
| 原理和工作流程 | 删除指定索引元素时新建长度减 1 数组，先复制 index 之前元素，再复制 index 加 1 到末尾元素，实现后续元素前移。删除匹配值先线性查找定位索引再调用删除索引方法。未找到返回原数组 |
| 缺点 | 删除需全量复制 O(n)；无法原地删除长度固定；多次删除性能差 |

### 3.4 数组查找

| 维度 | 内容 |
|------|------|
| 是什么 | 在数组中定位目标元素的线性查找与二分查找两种算法 |
| 能做什么 | 线性查找 O(n) 通用；二分查找 O(log n) 需排序；返回索引或 -1 |
| 怎么用 | `mid = left + (right-left)/2` 防溢出 |
| 原理和工作流程 | 线性查找从头遍历比较返回首次出现索引，未找到返回 -1，O(n) 不要求有序。二分查找要求数组已升序，每次取中点比较缩小一半范围，left 与 right 逐步靠近，用 `left+(right-left)/2` 防止整数溢出，O(log n) |
| 缺点 | 线性查找大数据慢；二分查找须先排序；未排序用二分查找返回错误结果 |

### 3.5 数组排序

| 维度 | 内容 |
|------|------|
| 是什么 | 冒泡排序与快速排序两种经典数组排序算法及对比 |
| 能做什么 | 冒泡稳定 O(n²)；快排不稳定平均 O(n log n)； Arrays.sort 双轴快排 |
| 怎么用 | `Arrays.sort(arr);` 生产用工具方法 |
| 原理和工作流程 | 冒泡每轮相邻元素比较交换将最大值冒泡到末尾，加 swapped 标志提前终止，稳定 O(n²) 空间 O(1)。快排选基准分区使左小右大再递归，平均 O(n log n) 最坏 O(n²) 不稳定空间 O(log n)。Arrays.sort 对基本类型用双轴快排对对象用 TimSort |
| 缺点 | 冒泡大数据慢；快排最坏退化为 O(n²)；选基准不当影响性能 |

### 3.6 Arrays 工具类

| 维度 | 内容 |
|------|------|
| 是什么 | java.util.Arrays 提供的数组操作工具类，含排序查找比较填充复制转换 |
| 能做什么 | sort 排序；binarySearch 查找；equals 比较；fill 填充；copyOf 复制；toString 转串；asList 转 List |
| 怎么用 | `Arrays.sort(arr);`、`Arrays.toString(arr);` |
| 原理和工作流程 | sort 对基本类型用双轴快排对对象用 TimSort。binarySearch 要求数组已排序返回索引未找到返回负的插入点加 1。equals 逐元素比较。asList 返回 Arrays 内部固定长度 List 是数组视图不支持 add/remove，转可变 List 须 `new ArrayList<>(Arrays.asList(...))` |
| 缺点 | asList 返回 List 不可变是高频坑；基本类型数组 asList 整体当一个元素；binarySearch 前未排序结果错误 |

## 四、常见异常

### 4.1 数组索引越界异常

| 维度 | 内容 |
|------|------|
| 是什么 | 访问不存在的数组索引时抛出的 ArrayIndexOutOfBoundsException |
| 能做什么 | 识别有效索引范围；遍历用 i < length；访问前做边界检查 |
| 怎么用 | 有效索引为 `[0, arr.length-1]` |
| 原理和工作流程 | JVM 在数组访问指令执行前检查索引是否在 0 到 length-1 范围内，超出即抛 ArrayIndexOutOfBoundsException。常见原因包括遍历误用 `i <= arr.length`、访问负索引、循环边界计算错误 |
| 缺点 | 运行时才报错非编译期；负索引同样越界；多维数组各维均需检查 |

### 4.2 空指针异常

| 维度 | 内容 |
|------|------|
| 是什么 | 数组引用为 null 或二维数组内层未初始化时访问抛出的 NullPointerException |
| 能做什么 | 使用前判空；二维数组确保内层已分配；识别 null 引用场景 |
| 怎么用 | `if (arr != null)` 再访问 |
| 原理和工作流程 | 数组引用变量为 null 时访问其 length 或元素，JVM 无法解引用 null 地址抛 NullPointerException。二维数组 `new int[3][]` 仅分配外层内层为 null，直接访问 arr[0][0] 因 arr[0] 为 null 抛 NPE。预防须使用前判空并逐行初始化内层 |
| 缺点 | NPE 信息少难定位；二维数组内层 null 易忽略；链式调用多处可能 null |

### 4.3 类型不兼容异常

| 维度 | 内容 |
|------|------|
| 是什么 | 向数组存入不兼容类型对象时运行时抛出的 ArrayStoreException |
| 能做什么 | 理解数组协变；识别运行时类型检查；避免 Object[] 误用 |
| 怎么用 | `Object[] o = new String[]{"A"}; o[0]=123;` 抛异常 |
| 原理和工作流程 | 数组是协变的即 String[] 可赋给 Object[]。编译期 Object[] 允许存任何对象，但运行时数组实际类型是 String[]，存入 Integer 时 JVM 检查元素类型不兼容抛 ArrayStoreException。这是数组协变特性带来的类型安全漏洞，泛型集合用擦除避免了此问题 |
| 缺点 | 协变破坏类型安全；运行时才暴露错误；泛型不可协变致数组与泛型集合行为不一致 |

## 五、常见面试题（附答案）

### 1. 数组和 ArrayList 的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查固定长度数组与动态 ArrayList 在长度、类型、性能上的差异 |
| 能做什么 | 对比长度可变性；对比类型支持；对比泛型与性能；给出选型决策 |
| 怎么用 | 数量固定用数组，频繁增删用 ArrayList |
| 原理和工作流程 | 数组长度固定创建后不可变，可存基本与引用类型，不支持泛型，性能略高无装箱开销，仅 length 属性。ArrayList 长度动态自动 1.5 倍扩容，只能存引用类型基本类型需装箱，支持泛型编译期检查，有装箱开销与方法丰富。选型看数量是否固定与是否需频繁增删 |
| 缺点 | 数组不够灵活；ArrayList 装箱有开销；两者各有适用场景不能互相替代 |

### 2. 数组在内存中是如何存储的？为什么数组索引从 0 开始？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查数组连续存储模型与索引从 0 起始的设计原因 |
| 能做什么 | 解释栈引用堆对象；解释 O(1) 地址计算；解释索引从 0 的计算优势 |
| 怎么用 | 地址 = 首地址 + 索引 × 元素大小 |
| 原理和工作流程 | 数组对象在堆连续存储，栈变量持有首地址引用。通过首地址加索引乘元素大小计算元素地址实现 O(1) 随机访问。索引从 0 开始因第 i 个元素地址为 首地址 + i×元素大小，若从 1 开始则需 首地址 + (i-1)×元素大小 多一次减法，从 0 起始省去减法是 C 传统 Java 沿用 |
| 缺点 | 索引从 0 与人类直觉不符易误；连续存储要求大块内存；长度固定插入删除低效 |

### 3. 二维数组的每一行长度可以不同吗？为什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查二维数组本质为"数组的数组"及不规则数组成因 |
| 能做什么 | 解释外层存内层引用；解释内层独立分配；构造锯齿数组 |
| 怎么用 | `int[][] j = new int[3][]; j[0]=new int[3]; j[1]=new int[5];` |
| 原理和工作流程 | Java 二维数组本质是数组的数组，外层数组每个元素是内层数组的引用地址。各内层数组在堆独立分配长度可各不相同，形成不规则数组或锯齿数组。这与 C 语言的连续二维数组不同，因 Java 内层数组各自独立 |
| 缺点 | 不规则数组遍历需按行长度；内存不连续影响性能；与数学矩阵概念不完全对应 |

### 4. Arrays.asList() 有哪些坑？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Arrays.asList 返回固定长度内部类 List 及基本类型数组陷阱 |
| 能做什么 | 识别不可变 List；识别基本类型数组整体当元素；识别 set 互相影响 |
| 怎么用 | `new ArrayList<>(Arrays.asList(1,2,3))` 转可变 List |
| 原理和工作流程 | 三大坑：一返回的是 Arrays 内部 ArrayList 非java.util.ArrayList 长度固定不支持 add/remove 否则抛 UnsupportedOperationException。二基本类型数组 `asList(new int[]{1,2,3})` 因泛型不支持基本类型将整个 int[] 当一个元素。三对返回 List 调 set 会影响原数组反之亦然因底层同一数组 |
| 缺点 | add/remove 抛异常是高频坑；基本类型数组不展开；与原数组共享状态易误改 |
