## 一、核心概念

### 1.1 流程控制全景

| 维度 | 内容 |
|------|------|
| 是什么 | 控制程序执行路径的语句体系，分顺序、分支、循环三大类 |
| 能做什么 | 按条件分支；按次数或条件循环；跳转控制 |
| 怎么用 | 分支用 if-else 与 switch，循环用 for、while、do-while |
| 原理和工作流程 | 顺序结构为默认自上而下执行。分支结构根据 boolean 表达式或离散值选择路径。循环结构由初始化、条件判断、执行体、迭代四要素构成，for 将四要素集中，while 与 do-while 分散，do-while 先执行后判断至少执行一次 |
| 缺点 | 嵌套过深降低可读性；循环控制不当易死循环；分支过多难维护应考虑策略模式 |

### 1.2 分支结构对比

| 维度 | 内容 |
|------|------|
| 是什么 | if-else、if-else if-else、switch-case 三种分支结构的特性比较 |
| 能做什么 | 区分适用场景；说明判断条件类型；说明穿透性 |
| 怎么用 | 区间判断用 if，等值判断用 switch |
| 原理和工作流程 | if-else 基于 boolean 表达式无穿透。if-else if-else 用多个 boolean 表达式做多条件区间判断。switch-case 基于 byte、short、char、int、String、enum 等离散等值判断，存在穿透性须用 break 阻断。switch 适合固定值匹配，if 适合区间与复杂条件 |
| 缺点 | switch 仅支持等值判断不支持区间；if-else if 链过长难读；穿透特性易引发遗漏 break bug |

### 1.3 循环结构对比

| 维度 | 内容 |
|------|------|
| 是什么 | for、while、do-while 三种循环结构的执行特点对比 |
| 能做什么 | 区分执行顺序；区分最少执行次数；指导选型 |
| 怎么用 | 次数已知用 for，条件未知用 while，至少一次用 do-while |
| 原理和工作流程 | for 按 初始化→条件判断→执行体→迭代 顺序，循环变量作用域限定在循环内，最少执行 0 次。while 先判断后执行，最少 0 次。do-while 先执行后判断，最少 1 次。三者可相互改写但适用场景不同 |
| 缺点 | do-while 使用少易误用；for 循环变量作用域局限有时不便；while 易漏迭代导致死循环 |

## 二、底层原理

### 2.1 if-else 分支预测与性能优化

| 维度 | 内容 |
|------|------|
| 是什么 | 现代 CPU 对 if-else 路径的预测机制及对应的性能优化手段 |
| 能做什么 | 利用分支预测提升流水线效率；短路求值减少无效计算；条件顺序优化防 NPE |
| 怎么用 | 高频路径放前，先排序再分支，`user != null && user.getAge() > 18` |
| 原理和工作流程 | CPU 分支预测器猜测 if-else 走向，预测正确流水线顺畅，错误则清空重建致性能损失。对随机数据排序后分支预测正确率接近 100%，性能可提升 3 到 6 倍。短路求值将开销小或更可能为 false 的条件放前，左侧为 false 时右侧短路不执行 |
| 缺点 | 分支预测依赖数据分布对随机数据失效；过度优化牺牲可读性；短路顺序错误引发 NPE |

### 2.2 switch-case 底层实现

| 维度 | 内容 |
|------|------|
| 是什么 | switch 在字节码层用 tableswitch 与 lookupswitch 两种指令实现的机制 |
| 能做什么 | 连续值 O(1) 跳转；稀疏值 O(log n) 二分查找；JDK14+ 箭头语法防穿透 |
| 怎么用 | 连续 case 用 tableswitch，离散 case 用 lookupswitch |
| 原理和工作流程 | case 值连续或接近连续时编译器生成 tableswitch，通过偏移量直接跳转索引 O(1)。case 值离散时生成 lookupswitch，对排序后的 case 值二分查找 O(log n)。String 类型的 switch 先算 hashCode 再 switch int 并用 equals 二次校验防哈希冲突。JDK14+ 箭头语法默认不穿透用逗号分隔多值 |
| 缺点 | lookupswitch 性能低于 tableswitch；String switch 依赖 hashCode 有哈希冲突风险；箭头语法需 JDK14+ |

### 2.3 for 循环的底层优化

| 维度 | 内容 |
|------|------|
| 是什么 | JIT 对热点循环的循环展开、不变式外提等优化及遍历方式选型 |
| 能做什么 | 循环展开减少控制开销；不变式外提避免重复计算；按集合类型选遍历方式 |
| 怎么用 | 缓存 `int size = list.size()` 再循环，ArrayList 用索引遍历 |
| 原理和工作流程 | JIT 的 C2 编译器对热点循环展开，将多次迭代合并减少循环控制开销。循环不变式外提把不依赖循环变量的计算移出循环。ArrayList 索引 get 为 O(1) 适合普通 for，LinkedList 索引 get 为 O(n) 适合迭代器或增强 for。需删除元素用迭代器 remove |
| 缺点 | 展开由 JIT 决定不可控；过度手动优化降低可读性；遍历方式选错致 O(n) 灾难 |

### 2.4 break 与 continue 的标签用法

| 维度 | 内容 |
|------|------|
| 是什么 | break 终止循环、continue 跳过迭代的控制语句及其带标签用法 |
| 能做什么 | 跳出当前层循环；跳过当前迭代；用标签跳出指定外层循环 |
| 怎么用 | `break outer;` 跳出外层，`continue outer;` 跳过外层当前迭代 |
| 原理和工作流程 | 不带标签的 break 与 continue 只作用于最近一层循环。带标签时标签编译为字节码偏移量，break label 与 continue label 本质是跳转到指定位置的 goto 指令。Java 保留 goto 为保留字但未实现，标签机制是其受限替代方案 |
| 缺点 | 标签用法可读性差易被滥用；类似 goto 破坏结构化；嵌套循环跳转逻辑难追踪 |

## 三、实战应用

### 3.1 Scanner 键盘输入

| 维度 | 内容 |
|------|------|
| 是什么 | java.util.Scanner 提供的命令行输入读取工具 |
| 能做什么 | 读取字符串、整数、浮点数、整行；按空白符分隔 |
| 怎么用 | `Scanner sc = new Scanner(System.in); int age = sc.nextInt();` |
| 原理和工作流程 | Scanner 包装输入流，用正则分隔符（默认空白）解析 token。next 以空白分隔读取字符串，nextInt 读取整数，nextLine 读取整行。nextInt 不消费换行符，其后接 nextLine 会读到空串，需额外调用一次 nextLine 消费换行符。用完应 close 释放资源 |
| 缺点 | nextInt 后 nextLine 陷阱频发；next 不能读含空格字符串；忘记关闭致资源泄漏 |

### 3.2 质数判断的算法优化

| 维度 | 内容 |
|------|------|
| 是什么 | 从暴力枚举到埃氏筛法的质数判断优化演进案例 |
| 能做什么 | 缩小搜索范围；排除无效检查；批量预计算 |
| 怎么用 | 单次判断用 6k±1 优化，批量判断用埃氏筛 |
| 原理和工作流程 | V1 暴力枚举 2 到 n-1 为 O(n)。V2 缩小到 sqrt(n) 因合数必有因子小于等于 sqrt(n) 为 O(sqrt n)。V3 跳过偶数减半。V4 利用 6k±1 性质排除 2 和 3 倍数。埃氏筛批量标记合数 O(n log log n) 空间换时间。用 `i*i <= n` 替代 Math.sqrt 避免浮点运算 |
| 缺点 | 高级优化可读性降低；埃氏筛空间占用大；过度优化对小规模数据无意义 |

### 3.3 嵌套循环经典案例

| 维度 | 内容 |
|------|------|
| 是什么 | 用嵌套循环打印九九乘法表与菱形的经典练习 |
| 能做什么 | 外层控制行内层控制列；控制空格与星号数量；打印对称图形 |
| 怎么用 | 乘法表 `for i=1..9 for j=1..i`，菱形分上下两部分 |
| 原理和工作流程 | 九九乘法表外层 i 控制行内层 j 控制列，j 从 1 到 i 形成三角形。菱形上半部分正三角行数递增星号为 2i-1，下半部分倒三角递减。嵌套循环时间复杂度为两层循环乘积，应尽量缩短内层、外提不变计算、减少层数 |
| 缺点 | 嵌套层数多性能差；边界依赖外层变量易越界；可读性差应优先单层方案 |

### 3.4 谷粒记账项目实战

| 维度 | 内容 |
|------|------|
| 是什么 | 综合运用流程控制实现的命令行家庭收支记账应用 |
| 能做什么 | 收支明细查询；登记收入支出；余额校验；退出确认 |
| 怎么用 | while 主菜单循环 + switch 分发 + if 校验 |
| 原理和工作流程 | 用 while 配合 boolean 控制变量维持主菜单循环，switch 分发 1 到 4 菜单选项，if-else 处理余额校验与退出确认，break 跳出 switch 分支，Scanner 读取用户输入。收支明细用字符串拼接（实际应用 StringBuilder 或集合），余额用 double 累加 |
| 缺点 | double 存金额有精度问题应用 BigDecimal；字符串拼接明细性能差；无持久化重启丢失数据 |

## 四、常见面试题（附答案）

### 1. switch 语句可以作用于哪些数据类型？String 类型是如何支持的？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 switch 支持类型及 String 支持原理 |
| 能做什么 | 列举支持类型；解释 String 编译转换；说明哈希冲突校验 |
| 怎么用 | 支持 byte、short、char、int、String、enum 及包装类 |
| 原理和工作流程 | switch 支持 byte、short、char、int、String（JDK7+）、enum（JDK5+）及包装类。String 支持原理是编译器将 switch(str) 转为先算 str.hashCode()，再按 int 值 switch，同时用 equals 二次校验防止哈希冲突导致误匹配 |
| 缺点 | String switch 性能低于 int；哈希冲突需 equals 兜底；不支持 long 与 boolean |

### 2. for 循环和 while 循环有什么区别？什么时候用哪个？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 for 与 while 在适用场景与作用域上的区别 |
| 能做什么 | 区分循环次数已知与未知；说明作用域差异；给出选型原则 |
| 怎么用 | 次数已知用 for，未知用 while，至少一次用 do-while |
| 原理和工作流程 | for 将初始化、条件、迭代集中在一行，循环变量作用域限定在循环体内。while 三部分分散，循环变量需在循环外声明作用域更广。选型原则：遍历数组集合或已知次数用 for，依赖条件判断如读文件到 EOF 用 while，先执行后判断用 do-while |
| 缺点 | while 循环变量作用域外泄易误用；for 灵活性低于 while；选型不当降低可读性 |

### 3. break 和 continue 的区别？带标签的用法是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 break 与 continue 语义及标签用法 |
| 能做什么 | 区分终止与跳过；说明影响范围；演示标签跳出外层 |
| 怎么用 | `break` 终止循环，`continue` 跳过迭代，`break outer` 跳出外层 |
| 原理和工作流程 | break 终止当前循环整个结束，continue 仅跳过本次迭代进入下一次。带标签时 break label 终止标签所在外层循环，continue label 结束外层循环当前迭代。标签编译为字节码偏移量对应受限 goto 跳转 |
| 缺点 | 标签用法类似 goto 破坏结构化；嵌套跳转难追踪；滥用降低可读性 |

### 4. 为什么 switch 中忘记写 break 会导致 case 穿透？这是设计缺陷还是有意为之？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 switch 穿透特性的设计意图与利用方式 |
| 能做什么 | 解释穿透机制；演示多 case 共享逻辑；说明 JDK14 箭头语法改进 |
| 怎么用 | 利用穿透让多 case 共用一段代码，加 break 阻断 |
| 原理和工作流程 | 穿透是有意设计的 fall-through 特性，允许多个 case 值共享同一段执行代码，如月份天数判断将 1、3、5 等月归为 31 天。忘写 break 会继续执行后续 case 直到遇到 break 或 switch 结束。JDK14 引入箭头语法默认不穿透从根本解决意外穿透问题 |
| 缺点 | 意外穿透是高频 bug；穿透与阻断混用易误读；箭头语法需高版本 JDK |
