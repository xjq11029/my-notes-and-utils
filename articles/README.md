# 对外发布稿（articles）

**全仓库唯一的对外发布出口**：把内部笔记 / 长文改写成能直接投到技术社区（掘金 / CSDN / 知乎等）的独立文章。

按**类别**分目录；每个类别下**一篇文章一个独立目录**（正文 + 该文专属的 `images/` + 该文的 `README.md`）：

```
articles/
├── README.md                                   本文件（出口定位、文章索引、统一约定）
├── 大模型原理/
│   └── llm-three-layers-from-raw-model-to-ai-application/
│       ├── README.md                           该文的对应关系 / 再生成命令 / 发布状态
│       ├── llm-three-layers-from-raw-model-to-ai-application.md
│       └── images/                             fig01–fig09.{svg,png}
└── agent-harness/
    └── agent-harness-from-analogy-to-12-components/
        ├── README.md
        ├── agent-harness-from-analogy-to-12-components.md
        └── images/                             fig01–fig13.{svg,png}
```

> ⚠️ **为什么一篇文章一个目录**：各文的配图都叫 `fig01`…，共享一个 `images/` 会撞名。类别目录本身**不单独建 README**——类别只是分组，索引统一维护在本文件，避免多层重复。

## 统一约定（所有发布稿共用）

1. **发布稿不是源文件的同步副本**——追求「单独读完能自洽」，不追求覆盖源文件全部章节。
2. **重新编号**，并把正文里所有「第 N 章」「见 x.y」改成自包含表述。**编号重排后必查悬空引用**，这是这类移植最常见的隐性错误。
3. **图号烧进图片底部居中**，不靠 HTML 居中：Markdown 没有居中语法；`<div align="center">` 在掘金 / CSDN 能渲染，但多数本地 Markdown 预览器会显示成裸标签、知乎会剥离。做进图片则任何平台、任何预览器都居中，图被单独转发时也带着编号。
4. **配图导出 4×（2720px 宽）**，不是仓库默认的 2×——图要上传到平台被放大查看 / 经平台二次缩放，位图需更高像素密度。这是对「2× 导出」约定的**有意例外**，已在根 [`CONVENTIONS.md`](../CONVENTIONS.md) 登记。⚠️ 提分辨率**不改变**图在平台正文列宽下的显示尺寸，收益只在「点开原图 / 高 DPI」。
5. **引用框带类型标签**：`> **核心 · …**` / `> **提示 · …**` / `> **注意 · …**` / `> **本章小结**`。四类语义在纯 Markdown 里只能靠类型词承载（源文件里的色块到这里全部塌成同一种灰引用块）。
6. **字数口径**：「N 万字」= **CJK 字符数 + 英文单词数**。⚠️ 别用「去空白字符数」——后者约为前者的 1.6 倍（例：1.29 万 vs 2.07 万）。两个数一律用下面这段现算，**别手填、也别换正则**（2026-09-21 实测：改了正文却只重算 CJK、英文沿用旧值，两个数就漂了）：

    ```python
    import re, sys
    s = open(sys.argv[1], encoding='utf-8', newline='').read()
    cjk = re.findall(r'[\u3400-\u4dbf\u4e00-\u9fff\u3040-\u30ff]', s)  # CJK 字符
    en  = re.findall(r"\b[A-Za-z]{2,}(?:[-'][A-Za-z]+)*\b", s)        # 英文单词：≥2 个字母
    print(len(cjk), '+', len(en), '=', len(cjk) + len(en))
    ```

    ⚠️ `en` 这条的 `\b` 走 Python 的 Unicode 词边界，**汉字也算词字符**——所以紧贴汉字的英文（例如写成「的token」）不计入。这是既有口径，换成别的正则会得到另一个数，**不要顺手「优化」它**。
7. **加粗定界符别踩 CommonMark 的坑**：`**` 能不能开、能不能闭，由它**前后各一个字符**决定（CommonMark 的 flanking 规则）。两种写法都会失效：
   - **闭合失效**：闭合 `**` 前一字符是标点、后一字符既非空白也非标点时，掘金不会把它当收尾 → 写 `**本章小结**：正文`，**不要**写 `**本章小结：**正文`。
   - **开头失效**：开头 `**` 后一字符是标点、前一字符既非空白也非标点时，掘金不会把它当开头 → 写 `所以"体积大"不等于"算得贵"——**文件体积按总参数记**。`，**不要**写 `所以**"体积大"不等于"算得贵"**——…`（`**` 后紧跟引号 / 括号就废了）。
   ⚠️ 本地预览器比掘金宽松，**本地正常 ≠ 掘金正常**，发布前必须自查。⚠️ 这条**不只针对发布稿**——课程笔记、任何 Markdown 都会踩，改完正文一律过一遍。

每篇的**再生成命令、与源文件的逐节对应关系、发布渠道与状态**，写在**该文自己的 `README.md`** 里。

## 发布渠道

| 平台 | 定位 |
|---|---|
| **掘金** | 建议首发、挂原创；技术社区氛围最好 |
| **CSDN** | SEO 与长尾流量最强 |
| **知乎** | 深度长文表现好，论证扎实吃香 |
| **腾讯云 / 阿里云 / 华为云开发者社区** | 有流量扶持与征文，收录好 |
| **微信公众号** | 私域沉淀，不依赖算法 |
| **InfoQ / 机器之心 / 量子位** | 垂类投稿，审核严但权重高 |

**两个操作提醒**

- **图片**：Markdown 里的图片是相对路径，只在本地有效；粘贴到平台后需**重新上传**（掘金 / CSDN 编辑器都支持批量拖拽，或导入 Markdown 时自动上传）。正文用相对路径是对的——方便本地预览与批量上传。
- **原创声明**：多平台同发一般要求「原创 + 首发 / 授权」，建议**一个平台首发**、其余同步，避免被判定为非原创。

## 维护约定

- **新增一篇文章**：在对应类别下建 `<文章 slug>/` 目录，放入正文 + `images/` + 该文的 `README.md`；然后同步本文件的「文章索引」与目录树、根 `README.md` 统计表、`AGENTS.md` 目录结构。**统计数字用脚本重算，不要手填**。
- **改动源文件**：若涉及事实、数字、结论，**对应发布稿必须同步**——两者对同一事实的表述不允许出现分歧；若涉及图示，重跑该文 `README.md` 里的再生成命令。
- **类别增删**：类别只是分组目录，增删类别只需同步本文件的目录树与索引表。
