## 配图

### 来源与再生成

13 张图**不是重绘的**，而是从 `agent-harness-deep-dive.html` 的内联 SVG 原样抽出——保证与长文的图示一致。重新生成分两步：

```bash
# 第 1 步：按锚点抽出 §0–§3 区间的内联 SVG → 注入深色底 → 注入底部居中的「图 N」
python scripts/extract-svg-from-html.py \
    docs/harness/agent-harness-deep-dive.html \
    articles/agent-harness/agent-harness-from-analogy-to-12-components/images \
    --from-anchor s0 --to-anchor s4 --bg '#111721' --expect 13 --label \
    --replace '方块里的数字与 3.1 的组件表一致=方块里的数字与组件表的编号一致' \
    --names three-layers,von-neumann,concentric-rings,five-problems,controlled-loop,problem-component-map,agent-loop,memory-scales,silent-failure,prompt-layers,state-management,subagent-firewall,component-placement

# 第 2 步：渲染 4× PNG（2720px 宽）
node scripts/svg-to-png.mjs articles/agent-harness/agent-harness-from-analogy-to-12-components/images --scale 4 --force
```

> ⚠️ **`--replace` 不能省**：图 6 的图内印着「与 3.1 的组件表一致」。`3.1` 在长文里是对的（§3.1），但发布稿把 §3 重编号成了第 4–6 章，所以发布稿这张图必须改成「组件表的编号」。**只改抽出的 SVG 而不改 HTML 源，重跑抽取时这个死引用就会复活**——所以这条修正以 `--replace` 的形式写进命令，而不是手工改文件。

### 为什么必须注入深色底

`scripts/svg-to-png.mjs` 硬编码 `background: '#FFFFFF'`，而长文是深色主题——这 13 张图的**文字全部是浅色**（`#dfe6ee` / `#7d8b9c` / `#93a1b1` 等）。不注入底色直接渲染，得到的是「浅字白底」，在掘金 / CSDN 的浅色页面上**完全不可读**。

`--bg '#111721'` 用的是长文的 `--bg-soft`，注入后等于把原文的深色图面板原样搬到浅色平台上：视觉一致、可读性有保障。

### 图号：做进图片里，不靠 HTML

每张图底部有一行**居中的「图 N」**，由 `--label` 在抽图时烧进 SVG（viewBox 高度 +34）。底栏放在**原 viewBox 之外**——各图底部留白从 6px 到 38px 不等，塞进留白会让留白小的图（如图 5，仅 6px）压到内容。

**为什么不用 HTML 居中**：Markdown 没有居中语法，居中只能靠 HTML；而 HTML 在不同环境里待遇不一——掘金 / CSDN 会渲染（掘友实测 `<div align=center>` 有效），但**多数本地 Markdown 预览器会把它转义成纯文本**、知乎会剥离。做进图片则**任何平台、任何预览器都居中**，图被单独转发或截图时也带着编号。

代价是**有意分叉**：长文的图内没有图号（它的图号在 `<figcaption>` 里），发布稿有。所以本目录的 SVG 与 HTML 内联 SVG **不完全相同**——`--label` 与 `--replace` 两处差异都已写进再生成命令，重跑即可复现。

### 为什么导出 4×（而不是仓库默认的 2×）

`svg-to-png.mjs` 的默认倍率是 **2×**（1360px 宽），那是给**课程笔记**定的——那些图在本地编辑器里按容器宽度显示，2× 够用。

**发布稿的处境不同**：图片要被上传到掘金 / CSDN，读者点开原图放大看、或在 Retina 屏上浏览，而长文里同一张图是**内联 SVG 矢量**、放大不糊。位图必须靠更高的像素密度补偿，故这里用 **4×（2720px 宽）**。

| | 课程笔记（默认） | 对外发布稿（本目录） |
|---|---|---|
| 倍率 | 2× · 1360px 宽 | **4× · 2720px 宽** |
| 理由 | 本地阅读、按容器宽度显示 | 平台上会被放大查看 / 缩放，需更高像素密度 |

单张 113–285KB、合计 **2.41MB**。这是本目录对仓库「2× 导出」约定的**有意例外**，已在根 [`CONVENTIONS.md`](../../../CONVENTIONS.md) 登记。

### 一处已修正的图内文字

图 6 的 SVG 里原本烧进了一句「方块里的数字与 3.1 的组件表一致」——`3.1` 在长文里**是对的**（§3.1），但发布稿把 §3 重编号成第 4–6 章后指向失效。已改为「方块里的数字与组件表的编号一致」。**这类烧进图片的文字改不了，只能改 SVG 源**，是移植长文图示时最容易漏的一类死引用。

⚠️ 这条修正**曾经只落在抽出的 SVG 上、没进 HTML 源**，导致重跑抽取会复活死引用（自查时实测：重抽后 13 张里只有图 6 与现有文件不一致）。现已改为由再生成命令里的 `--replace` 承载（见上），**源与产物之间不再有隐式差异**。

## 平台渲染注意

### 加粗定界符 `**` 在掘金上会失效（CommonMark 规则）

掘金的解析器严格遵循 CommonMark 的**翼定界符（flanking delimiter）**规则：**闭合 `**` 前面是标点、后面紧跟非标点非空白字符时，这个 `**` 不算「右翼定界符」，无法收尾**。后果分两种——轻则原样显示 `**文字**`，重则生成畸形的嵌套 `<strong>`。

本文踩到 5 处，已全部改掉：

| 错误写法 | 掘金上的结果 | 已改为 |
|---|---|---|
| `**先说清这张图的层次：**它讲的是` | 畸形嵌套 `<strong>` | `**先说清这张图的层次**：它讲的是` |
| `那是 **① 层（实体）**的问题` | 原样显示 `**` | `那是 **① 层（实体）** 的问题` |
| `> **本章小结：**裸 LLM…`（共 3 处） | 原样显示 `**` | `> **本章小结**：裸 LLM…` |

**通用修法**：把标点挪出加粗（`**标题**：正文`），或在闭合 `**` 后补一个空格。⚠️ **本地预览器（VSCode / Typora）大多比掘金宽松，本地看着正常不代表掘金正常**——发布前必须按这条规则自查（判据：闭合 `**` 前一字符是 Unicode 标点、后一字符既非空白也非标点）。
