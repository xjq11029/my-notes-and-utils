# Nginx - 概念对比速查

---

### 正向代理 vs 反向代理

| 对比维度 | 正向代理 | 反向代理 |
|---------|---------|---------|
| 核心定位 | 代理客户端，帮助客户端访问外部网络资源 | 代理服务端，接收客户端请求并转发到后端服务器 |
| 代理方向 | 客户端 -> 代理 -> 目标服务器 | 客户端 -> 反向代理 -> 后端服务器 |
| 客户端感知 | 客户端需要配置代理地址，知道代理的存在 | 客户端无感知，以为直接访问目标服务器 |
| 服务端感知 | 目标服务器不知道真实客户端，只知道代理 | 后端服务器不知道真实客户端，只知道反向代理 |
| 典型用途 | VPN 科学上网、内网穿透、访问控制 | 负载均衡、SSL 卸载、缓存加速、安全防护 |
| 配置位置 | 在客户端侧配置（浏览器、系统代理设置） | 在服务端侧配置（Nginx 服务器） |
| 安全性 | 隐藏客户端真实 IP | 隐藏后端服务器真实 IP，统一入口防护 |
| 选择建议 | 客户端需要突破网络限制时使用 | 服务端需要统一入口管理和负载分发时使用 |

### 负载均衡算法对比：轮询 vs 权重 vs ip_hash

| 对比维度 | 轮询（round-robin） | 加权轮询（weight） | ip_hash |
|---------|-------------------|-------------------|---------|
| 核心定位 | 依次将请求分发到每个后端服务器 | 根据服务器权重比例分配请求 | 根据客户端 IP 的哈希值固定路由到同一服务器 |
| 分发策略 | 循环顺序分发，每个服务器平均分配 | 权重越高的服务器分配越多请求 | 同一客户端 IP 始终路由到同一后端服务器 |
| 适用场景 | 后端服务器性能一致的无状态服务 | 后端服务器性能不一致（如不同配置的机器） | 需要 Session 保持的场景（如登录状态） |
| Session 保持 | 不保证，请求可能分发到不同服务器 | 不保证，请求可能分发到不同服务器 | 保证同一客户端 IP 请求到同一服务器 |
| 服务器增减影响 | 平均分配，无影响 | 权重调整后重新按比例分配 | 哈希值变化，部分客户端路由可能改变 |
| 配置示例 | 默认值，无需额外配置 | `server backend1 weight=3;` | `ip_hash;` 放在 upstream 块第一行 |
| 选择建议 | 后端同构的首选方案 | 后端异构（不同性能）时的首选 | 需要 Session 粘性且无共享存储时使用 |

### keepalive 长连接 vs 短连接

| 对比维度 | keepalive 长连接 | 短连接 |
|---------|-----------------|-------|
| 核心定位 | TCP 连接建立后保持不关闭，复用已建立的连接 | 每次请求新建 TCP 连接，请求完成后立即关闭 |
| 连接建立过程 | 首次请求建立连接，后续请求复用同一连接 | 每次请求都需要三次握手建立连接 |
| TCP 握手开销 | 仅首次握手，后续请求零开销 | 每次请求都需要完整的三次握手 + 四次挥手 |
| 资源占用 | 持续占用连接和内存资源 | 请求结束后释放连接资源 |
| 并发能力 | 连接数有限，高并发时可能耗尽连接 | 可支持更多并发请求（但效率低） |
| 适用场景 | 客户端与 Nginx 之间（HTTP/1.1 默认 keepalive） | Nginx 与后端服务器之间（默认短连接） |
| 配置方式 | `keepalive_timeout 65;` 客户端保持连接；`keepalive 32;` upstream 保持连接池 | 默认行为，无需额外配置 |
| 选择建议 | 客户端侧始终开启 keepalive 减少握手开销；后端侧根据实际负载选择性开启 upstream keepalive | 后端服务器性能敏感或连接数充足时可用短连接 |
