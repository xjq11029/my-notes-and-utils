### 1. Nginx 中反向代理的主要作用是什么？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | 位于客户端与后端服务器之间的代理转发机制，对客户端隐藏后端真实地址。 |
| 能做什么 | 隐藏后端服务器地址；实现负载均衡分发请求；统一鉴权与SSL卸载；承接静态资源处理。 |
| 怎么用 | `location / { proxy_pass http://backend; }` |
| 原理和工作流程 | 客户端请求先到达Nginx，Nginx依据location匹配反向代理配置，将请求转发给后端服务器组，再将后端响应返回客户端。整个过程对客户端透明，客户端感知不到后端真实IP。配合upstream可实现多后端负载均衡。 |
| 缺点 | 增加一跳网络延迟；Nginx成为单点需高可用保障；后端无法直接获取客户端真实IP需额外传递头。 |

### 2. Nginx 负载均衡中，默认的调度算法是？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx upstream未指定调度指令时默认启用的轮询调度算法。 |
| 能做什么 | 按顺序均等分配请求；无需额外参数；适配性能相近的无状态集群。 |
| 怎么用 | `upstream backend { server 192.168.1.10:8080; server 192.168.1.11:8080; }` |
| 原理和工作流程 | Nginx维护后端服务器列表，每个请求按列表顺序轮流分发到下一台服务器，循环往复。ip_hash、least_conn、fair需显式声明，不声明即为轮询。 |
| 缺点 | 不考虑服务器性能差异；无会话保持，同一用户请求可能落到不同节点。 |

### 3. 关于 Nginx 动静分离，以下说法正确的是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 将静态资源与动态请求分开处理，由Nginx直出静态、应用服务器处理动态的架构设计。 |
| 能做什么 | 减轻后端压力；提升静态资源响应速度；独立配置缓存策略；可同机不同目录或不同服务器实现。 |
| 怎么用 | 静态location用root直出，动态location用proxy_pass转发。 |
| 原理和工作流程 | Nginx通过location匹配规则分流，静态资源匹配本地目录直接返回，动态请求转发后端应用服务器。Nginx事件驱动处理静态文件效率高，应用服务器专注动态逻辑。不要求必须部署在不同服务器，也不限于正则匹配。 |
| 缺点 | 增加配置复杂度；资源版本同步需额外机制保障。 |

### 4. Nginx 配置 HTTPS 需要在 http 块中配置哪个指令？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | HTTPS配置中必须指定的公钥证书与私钥文件路径指令。 |
| 能做什么 | 指定证书链文件；指定私钥文件；启用TLS加密通信。 |
| 怎么用 | `ssl_certificate /path/to/cert.pem;` `ssl_certificate_key /path/to/private.key;` |
| 原理和工作流程 | ssl_certificate指向全链证书（服务器证书+中间证书），ssl_certificate_key指向与证书公钥配对的私钥。TLS握手时服务端用证书向客户端证明身份，用私钥参与密钥交换。新版Nginx废弃ssl on指令，改在listen中加ssl参数。 |
| 缺点 | 私钥泄露导致中间人攻击风险；证书过期需续期；旧客户端兼容性问题。 |

### 5. Nginx 中 `proxy_pass` 指令的作用是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 反向代理核心指令，指定后端服务器地址。 |
| 能做什么 | 转发请求到单机后端；转发到upstream服务器组；控制URI替换行为。 |
| 怎么用 | `proxy_pass http://backend;` |
| 原理和工作流程 | proxy_pass指定后端地址，Nginx将匹配location的请求转发到该地址。proxy_cache对应缓存，proxy_connect_timeout对应连接超时，proxy_set_header对应请求头设置，三者职责不同。 |
| 缺点 | 带路径与不带路径的URI行为差异易混淆，配置错误会导致后端收到错误URI。 |

### 6. 关于 Nginx 限流，`limit_req_zone` 指令中 `rate` 参数的作用是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | limit_req_zone基于令牌桶算法对单位时间请求数进行限制的机制。 |
| 能做什么 | 按IP或变量限制请求速率；设定平均速率与突发容量；保护后端不被突发流量打垮。 |
| 怎么用 | `limit_req_zone $binary_remote_addr zone=perip:10m rate=10r/s;` |
| 原理和工作流程 | rate参数设定平均速率（如10r/s每秒10请求），以固定速率生成令牌，请求消耗令牌。limit_conn限制并发连接数，limit_rate限制带宽速率，三者职责不同。 |
| 缺点 | 单IP粒度在NAT下误伤正常用户；rate设置不当影响正常流量或失去保护意义。 |

### 7. Nginx 中 worker_processes 配置为 CPU 核心数的主要原因是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 配置Worker进程数量以匹配CPU核心数的全局指令。 |
| 能做什么 | 让每个Worker绑定一个CPU核心；充分利用多核并行处理；避免进程跨核切换。 |
| 怎么用 | `worker_processes auto;` |
| 原理和工作流程 | Nginx多进程单线程模型，worker_processes设为CPU核心数使每个Worker绑定一个核心，避免进程在多核心间切换，充分利用多核并行处理提升并发。虽也能减少切换开销，但主要目的是多核利用。 |
| 缺点 | 设置过大增加切换开销；容器环境auto可能识别不准。 |

### 8. 以下哪个不是 Nginx 负载均衡的健康检查相关指令？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | upstream块中配置后端服务器被动健康检查的核心参数。 |
| 能做什么 | 设定允许失败次数；设定隔离时间；自动标记不可用节点；超时后重新探测。 |
| 怎么用 | `server 192.168.1.10:8080 max_fails=3 fail_timeout=30s;` |
| 原理和工作流程 | max_fails设定允许失败次数，达到阈值后在fail_timeout时间内将节点标记为不可用。proxy_next_upstream定义哪些错误触发转发到下一节点。proxy_connect_timeout仅是连接超时，非健康检查控制指令。 |
| 缺点 | 被动检查无法提前发现故障；首个请求仍会落到故障节点导致用户感知错误。 |

### 9. Nginx 配置 Gzip 压缩，主要目的是？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | 对HTTP响应内容进行gzip压缩以减少传输体积的优化机制。 |
| 能做什么 | 压缩文本类资源至原体积1/3到1/5；加快传输速度；节省带宽。 |
| 怎么用 | `gzip on; gzip_types text/plain text/css application/javascript;` |
| 原理和工作流程 | gzip对HTML、CSS、JS、JSON等文本资源压缩，减少网络传输量，浏览器自动解压。不加密、不缓存、不提升服务器压缩能力。 |
| 缺点 | 压缩消耗CPU资源；对已压缩格式（JPG、PNG）效果微弱且浪费CPU。 |

### 10. 关于 Nginx 正向代理和反向代理，说法错误的是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 代理服务器代理客户端（正向）与代理服务端（反向）两种代理模式的对照。 |
| 能做什么 | 正向代理为客户端服务，需配置resolver解析域名；反向代理为服务端服务，隐藏后端地址，不需resolver。 |
| 怎么用 | 正向代理需resolver配置DNS；反向代理用proxy_pass指向后端。 |
| 原理和工作流程 | 正向代理代理客户端发起请求，客户端明确知道目标但因代理才能访问，需解析任意域名故需resolver。反向代理代理服务端接收请求，客户端感知不到真实后端，后端地址已知不需resolver。 |
| 缺点 | 两者概念易混淆；正向代理在受限网络环境使用需合规考量。 |

### 11. Nginx 中 `keepalive_timeout` 的作用是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 设定客户端与Nginx之间长连接保持存活的超时时间指令。 |
| 能做什么 | 复用TCP连接；减少三次握手开销；控制连接空闲回收。 |
| 怎么用 | `keepalive_timeout 65s;` |
| 原理和工作流程 | keepalive_timeout设定长连接空闲保持时间，超时后Nginx关闭连接。合理设置可复用连接降低握手开销。设置后端连接超时用proxy_connect_timeout，请求读取超时用proxy_read_timeout。 |
| 缺点 | timeout过长导致连接资源闲置；高并发下空闲连接占用连接数配额。 |

### 12. 以下哪种场景不适合使用 Nginx 限流？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx限流机制的适用场景与非适用场景边界。 |
| 能做什么 | 防止爬虫疯狂爬取；防止DDoS攻击打垮服务器；限制下载站并发与带宽。 |
| 怎么用 | `limit_req` `limit_conn` `limit_rate` |
| 原理和工作流程 | 限流本质是限制速率保护服务器，防止被突发流量打垮。提升访问速度需依靠缓存、压缩、CDN等手段，限流反而会限制速度，不适用于提升静态资源访问速度。 |
| 缺点 | 限流无法提升访问速度；配置不当会误伤正常流量。 |

### 13. Nginx 负载均衡中 ip_hash 的主要作用是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 基于客户端IP哈希结果分配后端服务器以实现会话保持的调度算法。 |
| 能做什么 | 同一IP固定访问同一节点；解决后端Session共享问题；实现Session粘滞。 |
| 怎么用 | `upstream backend { ip_hash; server ...; }` |
| 原理和工作流程 | ip_hash对客户端IP哈希后取模分配节点，同一客户端IP始终落到同一节点，实现会话保持。不提升负载均衡性、安全性，也不减少缓存命中。 |
| 缺点 | NAT环境下负载严重不均；节点增减导致会话失效。 |

### 14. 关于 Nginx 缓存，以下说法错误的是？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx缓存后端响应内容的机制，存储于硬盘文件系统。 |
| 能做什么 | 缓存后端响应；降低后端QPS；按响应码设置缓存时间；配置缓存路径与层级。 |
| 怎么用 | `proxy_cache_path /data/cache levels=1:2 keys_zone=cache:10m;` `proxy_cache cache;` `proxy_cache_valid 200 10m;` |
| 原理和工作流程 | proxy_cache将后端响应缓存到硬盘（文件系统），可配置缓存路径、大小与层级。proxy_cache_valid按响应码设定缓存时间。缓存降低后端QPS，不是只能存内存。 |
| 缺点 | 硬盘IO可能成为瓶颈；缓存失效策略需谨慎设计避免脏数据。 |

### 15. Nginx 处理请求时，worker 进程采用什么模型？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx采用一个master进程管理多个单线程worker进程的架构模型。 |
| 能做什么 | 内存占用少；切换开销小；并发能力强；进程隔离互不影响。 |
| 怎么用 | master-worker模型，worker进程单线程基于事件驱动处理请求。 |
| 原理和工作流程 | 一个master进程管理多个worker进程，每个worker单线程基于事件驱动模型（如epoll）处理请求。单线程避免锁竞争与线程切换开销，多进程实现并行处理。非多进程多线程、单进程单线程或单进程多线程。 |
| 缺点 | 单Worker单线程，CPU密集任务会阻塞该Worker所有连接。 |

### 1. 请简述 Nginx 反向代理的工作流程。 ★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx作为反向代理接收客户端请求并转发后端、再回传响应的完整处理流程。 |
| 能做什么 | 解析请求；匹配location；构建后端请求；转发并接收响应；回传客户端。 |
| 怎么用 | `location / { proxy_pass http://backend; proxy_set_header Host $host; }` |
| 原理和工作流程 | 客户端请求到达Nginx，Nginx解析请求头与URL，依据location规则匹配反向代理配置；构建发往后端的请求，添加或修改请求头（如proxy_set_header）；建立与后端连接发送请求；接收后端响应；将响应转发回客户端，处理连接释放或保持。整个过程对客户端透明。 |
| 缺点 | 增加一跳延迟；Nginx单点风险；连接管理不当放大后端压力。 |

### 2. Nginx 负载均衡有哪几种常用调度算法？分别适用什么场景？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx upstream支持的多种请求调度算法及其适用场景的对比。 |
| 能做什么 | 轮询均等分配；加权按性能分配；ip_hash会话保持；least_conn动态均衡；fair按响应时间调度。 |
| 怎么用 | `upstream backend { least_conn; server ...; }` |
| 原理和工作流程 | 轮询按顺序均等分配，适配性能相近无状态集群；加权轮询按权重比例分配，适配性能差异集群；ip_hash按客户端IP哈希分配实现会话保持；least_conn按当前连接数最少分配，适配请求处理时间差异大场景；fair按响应时间分配，需第三方模块。 |
| 缺点 | 各算法均有局限，轮询不考虑性能差异，ip_hash负载不均，fair依赖第三方模块。 |

### 3. 什么是动静分离？为什么要做动静分离？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 将动态资源与静态资源分开处理，由Nginx直出静态、应用服务器处理动态的架构思想。 |
| 能做什么 | 减轻后端压力；提升静态响应速度；独立缓存优化；便于架构扩展。 |
| 怎么用 | 静态location用root直出，动态location用proxy_pass转发。 |
| 原理和工作流程 | Nginx对静态文件处理能力远强于应用服务器，将静态资源交由Nginx直接处理，动态请求转发后端应用服务器。应用服务器专注动态逻辑提升整体吞吐。静态资源可独立做缓存、压缩、CDN加速，动态资源独立扩容。 |
| 缺点 | 增加配置复杂度；资源版本同步需额外机制保障。 |

### 4. 请简述 Nginx 配置 HTTPS 的步骤和核心配置项。 ★★

### 5. Nginx 限流的主要实现方式有几种？分别解决什么问题？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx提供的请求速率、并发连接数、带宽速率三种限流方式。 |
| 能做什么 | limit_req限制请求速率；limit_conn限制并发连接数；limit_rate限制带宽速率。 |
| 怎么用 | `limit_req_zone ... rate=10r/s;` `limit_conn` `limit_rate 1024k;` |

### 6. 请列举几个 Nginx 性能优化的常用手段。 ★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx性能优化的常用手段集合，覆盖进程、事件、压缩、缓存、连接等维度。 |
| 能做什么 | 进程与连接调优；事件模型优化；gzip压缩；静态缓存；长连接复用；代理缓存；sendfile零拷贝。 |
| 怎么用 | `worker_processes auto;` `sendfile on;` `gzip on;` `keepalive_timeout 65s;` `proxy_cache` |
| 原理和工作流程 | 进程层调worker_processes与worker_connections匹配多核与并发；事件层用epoll与multi_accept；gzip压缩减小传输体积；静态资源expires缓存减少重复请求；keepalive复用连接减少握手；proxy_cache缓存后端响应降低QPS；sendfile零拷贝优化静态传输。关闭静态资源日志减少磁盘IO。 |
| 缺点 | 各优化项相互关联，单点调优可能转移瓶颈；过度优化增加复杂度与排障难度。 |

### 7. Nginx 502 Bad Gateway 错误常见原因是什么？怎么排查？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx作为反向代理从后端收到无效响应时返回502错误的成因与排查方法。 |
| 能做什么 | 检查后端服务状态；验证网络连通性；排查后端负载；校验配置正确性；分析日志。 |
| 怎么用 | `curl http://backend:8080` 检查后端；查看Nginx error.log与后端日志。 |
| 原理和工作流程 | 502表示Nginx无法从后端获取有效响应。常见原因：后端服务挂掉端口未监听、连接超时超过proxy_connect_timeout或proxy_read_timeout、后端负载过高资源耗尽、网络不通防火墙拦截、upstream配置错误、FastCGI配置错误。排查思路：检查后端运行与端口监听、curl后端接口验证连通、查看后端日志、查看Nginx错误日志、调大超时观察、检查后端负载。 |
| 缺点 | 502成因多样，定位耗时；部分间歇性502难以复现；需多方日志协同排查。 |

### 8. 请解释 Nginx 的 master-worker 模型，以及优点。 ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | Nginx一个master进程加多个单线程worker进程架构的核心优势。 |
| 能做什么 | 高稳定性；支持热部署；充分利用多核；内存可控；低开销。 |
| 怎么用 | master管理worker，worker单线程事件驱动处理请求。 |
| 原理和工作流程 | master进程负责读取配置、管理worker生命周期（启动、停止、重启、平滑升级），不处理具体请求。worker进程单线程基于事件驱动处理请求，数量通常为CPU核心数。worker异常退出时master快速拉起新worker。多worker分布多核并行处理，单线程无锁竞争与线程切换开销。 |
| 缺点 | 单worker单线程，CPU密集任务阻塞该worker所有连接；进程间共享数据需共享内存，编程模型复杂。 |

### 1. 场景设计：三台后端应用服务器负载均衡（会话保持、异常剔除、权重分配、1分钟恢复检查） ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | 集成加权轮询、ip_hash会话保持、被动健康检查、故障转移的综合负载均衡配置。 |
| 能做什么 | 按性能分配权重；会话保持；故障节点自动剔除与恢复；异常请求转发下一节点。 |
| 怎么用 | `upstream backend { ip_hash; server ... weight=10 max_fails=2 fail_timeout=60s; }` `proxy_next_upstream error timeout http_502 ...;` |
| 原理和工作流程 | weight按性能A(5)小于B(8)小于C(10)分配，性能越好权重越高承担更多请求。ip_hash实现同一IP访问同一节点会话保持。max_fails=2连续失败2次标记不可用，fail_timeout=60s符合1分钟后检查恢复要求。proxy_next_upstream配置error、timeout、502/503等错误时自动转发下一节点，提升可用性。 |
| 缺点 | ip_hash与weight组合时权重效果减弱；被动健康检查首个请求仍会落到故障节点；fail_timeout过短导致频繁试探。 |

### 2. 场景设计：大量静态资源网站的限流与性能优化（API限流、静态缓存、Gzip、下载限速） ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | 集成API限流、静态资源缓存、gzip压缩、下载限速的综合优化配置。 |
| 能做什么 | API按IP限流每秒100请求突发50；静态资源缓存7天；gzip压缩文本；下载限速1MB/s。 |
| 怎么用 | `limit_req_zone $binary_remote_addr zone=api:10m rate=100r/s;` `expires 7d;` `gzip on;` `limit_rate 1024k;` |
| 原理和工作流程 | limit_req_zone基于客户端IP限流，rate=100r/s每秒100请求，burst=50允许突发50排队，nodelay立即处理。静态资源expires 7d设置浏览器缓存，access_log off减少IO。gzip压缩文本类资源减小传输体积。limit_rate 1024k限制单连接下载速率1MB/s防占满带宽。 |
| 缺点 | 限流与限速组合可能影响用户体验；gzip消耗CPU；静态缓存7天需配合文件名哈希避免过期。 |
