# ClickHouse - 概念对比速查

---

### ClickHouse vs MySQL

| 对比维度 | ClickHouse | MySQL |
|---------|-----------|-------|
| 核心定位 | 面向列的 OLAP 分析型数据库 | 面向行的 OLTP 关系型数据库 |
| 存储方式 | 列式存储，同一列数据连续存放 | 行式存储，同一行数据连续存放 |
| 查询特点 | 大批量行少量列的聚合扫描 | 少量行全列的精确查询和更新 |
| 写入方式 | 批量写入，不适合频繁单行更新 | 支持高频单行写入和更新 |
| 事务支持 | 不支持事务 | 完整支持 ACID 事务 |
| 并发能力 | 中低并发（数十连接） | 高并发（数千连接） |
| 索引结构 | 稀疏索引（每 8192 行一个 Mark） | B+Tree 稠密索引（每行一个索引项） |
| 数据压缩 | 列式同类型高压缩比 5-10 倍 | 行式压缩比低 |
| 向量化执行 | 支持 SIMD 指令批量处理 | 不支持 |
| UPDATE/DELETE | 异步 Mutation，重写整个 Part，性能差 | 原地更新，性能好 |
| 适用场景 | 实时报表、日志分析、用户行为分析、广告统计 | 业务数据存储、事务操作、高并发 OLTP |
| 选择建议 | 分析聚合场景选 ClickHouse；业务主库选 MySQL；两者配合使用 | |

### MergeTree vs InnoDB

| 对比维度 | MergeTree（ClickHouse） | InnoDB（MySQL） |
|---------|------------------------|-----------------|
| 核心定位 | ClickHouse 最核心的列式存储表引擎 | MySQL 默认的行式存储引擎 |
| 存储方式 | 列式存储，按列分块存放 | 行式存储，按页（16KB）存放 |
| 索引结构 | 稀疏索引（每 8192 行一个 Mark），按排序键生成 | B+Tree 稠密索引，按主键生成 |
| 索引大小 | 约为数据量的千分之一 | 约为数据量的 10%-30% |
| 数据写入 | 每次批量写入产生不可变 Part，后台合并线程合并 | 写入 Buffer Pool，后台线程刷脏页 |
| 数据更新 | 不支持原地更新，UPDATE 是异步 Mutation 重写 Part | 支持原地更新，通过 Undo Log 保证一致性 |
| 分区机制 | 按 PARTITION BY 表达式拆分到物理目录，支持分区裁剪 | 支持分区表，但裁剪效果较弱 |
| 压缩能力 | 列式同类型压缩比 5-10 倍（LZ4/ZSTD） | 支持页级压缩，但压缩比不如列式 |
| TTL 支持 | 原生支持 TTL，自动过期删除数据 | 不支持原生 TTL，需定时任务清理 |
| 衍生引擎 | ReplacingMergeTree（去重）、SummingMergeTree（汇总）、AggregatingMergeTree（聚合）等 | 无衍生引擎，通过 SQL 实现类似功能 |
| 适用场景 | 海量数据聚合分析、时序数据存储 | 事务处理、高并发 OLTP |
| 选择建议 | 分析场景选 MergeTree；事务场景选 InnoDB | |
