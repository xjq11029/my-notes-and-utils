# MySQL Advanced - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 使用 EXPLAIN 分析但忽略 type 和 Extra 列 | 只关注 key 是否使用了索引，未关心扫描类型 | type 至少要到 range 级别，Extra 避免 Using filesort 和 Using temporary | [06-导览](./06-MySQL深度优化-导览.md) |
| 创建索引后不验证是否生效 | 未执行 EXPLAIN 确认优化器是否选择了索引 | 每次创建索引后 EXPLAIN 对比前后执行计划 | [06-导览](./06-MySQL深度优化-导览.md) |
| 索引列上使用函数或表达式导致索引失效 | `WHERE DATE(create_time) = '2025-01-01'` 破坏了索引有序性 | 使用范围查询：`WHERE create_time >= '2025-01-01' AND create_time < '2025-01-02'` | [06-导览](./06-MySQL深度优化-导览.md) |
| LIMIT 10000, 20 深分页性能差 | 需要扫描前 10020 行再丢弃前 10000 行，大量无效 I/O | 使用基于主键的延迟关联：`SELECT * FROM t1 JOIN (SELECT id FROM t1 LIMIT 10000, 20) AS t2 ON t1.id = t2.id` | [06-导览](./06-MySQL深度优化-导览.md) |
| 使用 SELECT * 查询所有列 | 查询不需要的列增加 I/O 开销，无法使用覆盖索引 | 只查询需要的列，利用覆盖索引避免回表 | [06-导览](./06-MySQL深度优化-导览.md) |
| 隐式类型转换导致索引失效 | 字段是 VARCHAR 类型却用数字比较，MySQL 自动转换导致索引失效 | 查询条件类型与字段类型严格匹配 | [06-导览](./06-MySQL深度优化-导览.md) |
| 负向查询（NOT IN、!=、NOT EXISTS）导致索引失效 | 优化器认为负向查询结果集占比大，选择全表扫描 | 尽可能改写为正向查询或使用覆盖索引 | [06-导览](./06-MySQL深度优化-导览.md) |
| 长事务导致锁等待、Undo 膨胀、主从延迟 | 事务长时间未提交，行锁一直被持有，Undo 日志无法回收 | 事务尽量短小；避免在事务中执行远程调用；监控长事务 | [06-导览](./06-MySQL深度优化-导览.md) |
| 死锁发生后无自动重试机制 | 死锁被 MySQL 检测到后回滚其中一个事务，业务未处理 | 捕获死锁异常（DeadlockException）后重试事务 | [06-导览](./06-MySQL深度优化-导览.md) |
| 隔离级别设置不当导致数据异常 | 脏读（READ UNCOMMITTED）、不可重复读（READ COMMITTED）、幻读（REPEATABLE READ） | 默认 REPEATABLE READ 已足够；特殊场景考虑 SERIALIZABLE | [06-导览](./06-MySQL深度优化-导览.md) |
| 分库分表选错分片键导致跨库查询 | 分片键选择不当，大部分查询跨越多个分片 | 分片键选择最频繁的查询条件字段，避免跨库 JOIN | [07-导览](./07-数据库笔面试题集-导览.md) |
| 主从延迟导致读操作读到旧数据 | 主库写入后立即从从库读取，主从同步未完成 | 关键业务强制读主库；或使用半同步复制降低延迟 | [07-导览](./07-数据库笔面试题集-导览.md) |
| 误用 COUNT(column) 代替 COUNT(*) | COUNT(column) 不统计 NULL 值，可能得到错误结果 | 统计行数用 COUNT(*)；统计某列非 NULL 行数才用 COUNT(column) | [07-导览](./07-数据库笔面试题集-导览.md) |
| 大表 DDL 直接执行导致锁表 | ALTER TABLE 需要拷贝表数据，执行期间会锁表 | 使用 pt-online-schema-change 在线改表，或 MySQL 8.0 的 ALGORITHM=INSTANT | [07-导览](./07-数据库笔面试题集-导览.md) |
