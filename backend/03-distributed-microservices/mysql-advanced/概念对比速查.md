# MySQL Advanced - 概念对比速查

---

### B 树 vs B+ 树

| 对比维度 | B 树 | B+ 树 |
|---------|------|------|
| 核心定位 | 多路平衡搜索树，数据分布在所有节点 | B 树的变体，数据仅存储在叶子节点 |
| 数据存储 | 所有节点（内部节点和叶子节点）都存储数据 | 仅叶子节点存储数据，内部节点只存储索引键 |
| 叶子节点结构 | 叶子节点之间无链接 | 叶子节点通过双向链表连接，形成有序序列 |
| 范围查询 | 需要中序遍历，涉及多次磁盘 I/O | 叶子节点链表可直接顺序扫描，单次 I/O 扫描大量数据 |
| 查询稳定性 | 非叶子节点命中数据时查询更快，否则需到叶子节点 | 任何查询都需到叶子节点，查询路径长度固定，稳定可预测 |
| 磁盘 I/O | 内部节点存储数据导致每个节点可容纳的键更少，树更高 | 内部节点不存数据，每个节点可容纳更多键，树更矮，I/O 更少 |
| 选择建议 | 已逐步被 B+ 树替代 | MySQL InnoDB 默认索引结构，适合数据库场景 |

### 聚簇索引 vs 非聚簇索引

| 对比维度 | 聚簇索引 | 非聚簇索引（二级索引） |
|---------|---------|----------------------|
| 核心定位 | 数据行物理存储顺序与索引顺序一致，索引即数据 | 索引与数据分开存储，索引存储的是指向数据的引用 |
| 数据存储 | 叶子节点存储完整数据行 | 叶子节点存储主键值（聚簇索引键） |
| 每个表数量 | 仅一个（InnoDB 默认主键即聚簇索引） | 可多个 |
| 查询路径 | 通过索引直接定位到数据行 | 先查二级索引获取主键，再回表查聚簇索引获取完整数据 |
| 回表 | 无需回表 | 需要回表（除非查询列被索引覆盖） |
| 插入性能 | 插入需保证物理顺序，页分裂代价较高 | 插入仅更新索引结构，开销较小 |
| 选择建议 | 主键应尽量使用自增 ID，避免随机 UUID 导致频繁页分裂 | 频繁查询的列创建二级索引，结合覆盖索引避免回表 |

### InnoDB vs MyISAM

| 对比维度 | InnoDB | MyISAM |
|---------|--------|--------|
| 核心定位 | 事务型存储引擎，MySQL 5.5+ 默认引擎 | 非事务型存储引擎，曾是 MySQL 默认引擎 |
| 事务支持 | 支持 ACID 事务（COMMIT、ROLLBACK、SAVEPOINT） | 不支持事务 |
| 锁粒度 | 行级锁（通过 MVCC 实现高并发） | 表级锁（写操作会阻塞所有读写） |
| 外键 | 支持外键约束 | 不支持外键 |
| 崩溃恢复 | 通过 redo log 和 undo log 实现崩溃恢复 | 崩溃后需手动修复，可能丢失数据 |
| 全文索引 | MySQL 5.6+ 支持 | 原生支持 |
| 数据存储 | 表数据和索引存在同一个表空间文件 | 表数据（.MYD）和索引（.MYI）分开存储 |
| 计数查询 | COUNT(*) 需遍历全表 | COUNT(*) 直接读取表元数据，常数时间 |
| 选择建议 | 生产环境首选，需要事务、高并发、数据安全时使用 | 仅适合只读场景或日志表等对事务无要求的场景 |

### 事务隔离级别四种

| 对比维度 | READ UNCOMMITTED | READ COMMITTED | REPEATABLE READ | SERIALIZABLE |
|---------|-----------------|----------------|-----------------|-------------|
| 核心定位 | 最低隔离级别，一个事务可读到其他事务未提交的修改 | 一个事务只能读到其他事务已提交的修改 | 同一事务中多次读取同一数据结果一致 | 最高隔离级别，事务串行执行 |
| 脏读 | 可能 | 不可能 | 不可能 | 不可能 |
| 不可重复读 | 可能 | 可能 | 不可能 | 不可能 |
| 幻读 | 可能 | 可能 | 不可能（InnoDB 通过 MVCC 解决） | 不可能 |
| 实现方式 | 不加锁，直接读最新版本 | 每次读取生成新的 Read View | 事务开始时生成 Read View，整个事务使用同一快照 | 所有 SELECT 隐式加共享锁，读写互斥 |
| 并发性能 | 最高 | 高 | 较高 | 最低 |
| 选择建议 | 几乎不使用 | 适合对一致性要求不高的场景 | MySQL InnoDB 默认级别，适合大多数场景 | 仅在对数据一致性要求极高的场景使用 |
