## 一、核心概念

### 1.1 泛型概述

| 维度 | 内容 |
|------|------|
| 是什么 | JDK5 引入的参数化类型机制，允许类与方法在定义时使用类型占位符 |
| 能做什么 | 编译期类型检查；消除强制转换；提升代码复用；避免 ClassCastException |
| 怎么用 | `List<String> list = new ArrayList<>();` |
| 原理和工作流程 | 泛型是编译期概念，用类型参数 T、E、K、V 占位，使用时传入具体类型。编译器在编译期做类型检查避免运行时 ClassCastException，并在擦除后自动插入强转。泛型本质是向后兼容的设计，编译后类型信息被擦除 |
| 缺点 | 不支持基本类型需装箱；运行时类型信息丢失；语法限制多；初学者对通配符困惑 |

### 1.2 泛型在集合中的使用

| 维度 | 内容 |
|------|------|
| 是什么 | 泛型在集合类中的典型应用，约束集合元素类型 |
| 能做什么 | 约束 List、Set、Map 元素类型；编译期检查；遍历免强转 |
| 怎么用 | `Map<String,Integer> map = new HashMap<>();` |
| 原理和工作流程 | 集合接口与实现均带泛型参数，如 List<E>、Map<K,V>。声明时指定具体类型编译器即可在 add 时校验类型，get 时免强转。菱形语法 <> 让编译器推断类型。未指定泛型用原始类型会产生警告失去类型安全 |
| 缺点 | 原始类型遗留代码无类型安全；不同泛型实参的集合运行时同类型；基本类型需包装类 |

### 1.3 自定义泛型类与泛型方法

| 维度 | 内容 |
|------|------|
| 是什么 | 开发者自定义带类型参数的类、接口与方法 |
| 能做什么 | 定义泛型类 `<T>`；定义有界泛型 `<T extends Number>`；定义泛型方法 `<T> T foo(T t)` |
| 怎么用 | `class Box<T>{ T data; }`、`public <T> T get(T t)` |
| 原理和工作流程 | 泛型类在类名后加 `<T>` 可有多个参数与上界 `<T extends Comparable<T>`。泛型方法在返回值前加 `<T>` 与类泛型独立，类型由调用时实参推断。类型参数命名约定 T 类型、E 元素、K 键、V 值。有界泛型限制类型范围并允许调用边界方法 |
| 缺点 | 不能 new T、不能 new T[]、不能静态字段用类泛型参数；有界泛型只能单上界；类型推断有时需显式指定 |

### 1.4 泛型在继承上的体现

| 维度 | 内容 |
|------|------|
| 是什么 | 泛型类父子关系与类型参数的具体化关系 |
| 能做什么 | 子类指定父类泛型具体类型；泛型不协变；区分同泛型不同实参 |
| 怎么用 | `class StrList extends ArrayList<String>` 合法，`List<Object> = List<String>` 非法 |
| 原理和工作流程 | 泛型不协变：`List<String>` 不是 `List<Object>` 子类，因若允许则可加入任意对象破坏类型安全。子类继承泛型父类时可指定具体类型 `class IntList extends ArrayList<Integer>`，或保留泛型 `class MyList<T> extends ArrayList<T>`。父类泛型须被指定或保留不能忽略 |
| 缺点 | 不协变限制复用需通配符弥补；子类指定具体类型后泛型信息固化；继承关系需仔细区分 |

### 1.5 通配符

| 维度 | 内容 |
|------|------|
| 是什么 | 用 `?` 表示未知类型的泛型参数，分无界、上界、下界三种 |
| 能做什么 | 无界 `?` 只读 null；上界 `? extends T` 只读；下界 `? super T` 只写 |
| 怎么用 | `void print(List<?> list)`、`List<? extends Number>`、`List<? super Integer>` |
| 原理和工作流程 | 无界通配符 `List<?>` 可接收任意泛型 List 但只能读 null 不能写非 null。上界通配符 `? extends T` 接收 T 或子类型，读取为 T 但不能写入因类型不确定。下界通配符 `? super T` 接收 T 或父类型，可写入 T 及子类型但读取为 Object。通配符解决泛型不协变的复用问题 |
| 缺点 | 通配符读写限制易混；上下界选择需 PECS 指导；嵌套通配符复杂难读 |

### 1.6 PECS 原则（重点）

| 维度 | 内容 |
|------|------|
| 是什么 | Producer Extends Consumer Super 的通配符选择原则 |
| 能做什么 | 读频繁用 `? extends T`；写频繁用 `? super T`；指导 API 设计 |
| 怎么用 | 生产者读用 extends，消费者写用 super |
| 原理和工作流程 | PECS 即 Producer Extends Consumer Super。若集合作为生产者只读取不写入用 `? extends T`，因读取类型至少是 T 安全。若集合作为消费者只写入不读取用 `? super T`，因可安全写入 T 及子类型。如 `void copy(List<? extends T> src, List<? super T> dst)`。同时读写则用精确类型 T 不用通配符 |
| 缺点 | 原则需结合场景理解；extends 只读 super 只写易记反；同时读写不适用 |

## 二、底层原理

### 2.1 类型擦除

| 维度 | 内容 |
|------|------|
| 是什么 | 编译后泛型类型信息被擦除替换为原始类型的机制 |
| 能做什么 | 编译期类型检查；擦除为 Object 或边界；自动插入强转；保证向后兼容 |
| 怎么用 | 无界 `<T>` 擦除为 Object，有界 `<T extends Number>` 擦除为 Number |
| 原理和工作流程 | 泛型是编译期概念，编译后类型信息擦除。三步：一擦除类型参数无界替换为 Object 有界替换为边界类型；二在取值处自动插入强制类型转换；三生成桥接方法保证多态。运行时 `List<String>` 与 `List<Integer>` 的 Class 相同。擦除带来限制：不能用基本类型泛型、不能 new T、不能 new T[]、不能 instanceof 泛型、不能泛型异常类、不能静态字段用类泛型参数 |
| 缺点 | 运行时无泛型信息；不能 new T 与 T[]；不能 instanceof 泛型；基本类型需装箱；重载擦除后可能冲突 |

### 2.2 桥接方法

| 维度 | 内容 |
|------|------|
| 是什么 | 编译器为泛型子类自动生成的合成方法，保证擦除后多态仍正确 |
| 能做什么 | 弥补擦除后方法签名不一致；保证多态调用；处理协变返回类型 |
| 怎么用 | 编译器自动生成，isBridge 可验证 |
| 原理和工作流程 | 父类泛型 `Node<T>` 的 setData 擦除后参数为 Object，子类 MyNode 重写 setData(Integer) 参数为 Integer 签名不同非真正重写多态失效。编译器为子类生成桥接方法 `setData(Object data)` 内部强转调用 `setData((Integer)data)`，参数与父类擦除后一致实现多态。协变返回类型也会生成桥接方法。可用 method.isBridge 验证 |
| 缺点 | 桥接方法对开发者透明易困惑；反射会看到合成方法；泛型重写需理解擦除才能懂 |

## 三、实战应用

### 3.1 泛型 DAO 层设计

| 维度 | 内容 |
|------|------|
| 是什么 | 用泛型抽象公共 CRUD 操作的基类 DAO 设计模式 |
| 能做什么 | 定义 `BaseDao<T>` 公共增删改查；子类指定实体类型；消除重复代码 |
| 怎么用 | `class UserDao extends BaseDao<User>` |
| 原理和工作流程 | BaseDao<T> 定义 save、delete、findById、findAll 等公共方法，T 为实体类型。子类继承并指定 T 如 UserDao extends BaseDao<User> 复用全部 CRUD。需运行时获取 T 的 Class 用反射 ParameterizedType 的 getActualTypeArguments。MyBatis-Plus 的 BaseMapper 即此模式 |
| 缺点 | 运行时获取泛型类型需反射；泛型擦除致部分场景受限；过度抽象降低灵活性 |

### 3.2 泛型工具类实战

| 维度 | 内容 |
|------|------|
| 是什么 | 封装类型安全通用工具方法的泛型工具类 |
| 能做什么 | 类型安全转换；空安全获取；泛型数组转换；Optional 链式 |
| 怎么用 | `public static <T> T cast(Object o, Class<T> clazz)` |
| 原理和工作流程 | 泛型方法在返回值前声明 `<T>`，类型由实参 Class 推断，编译期检查调用方类型。常用模式：cast 用 clazz.cast 转换，getList 用 `T[]` 或反射创建数组，firstOrNull 用空判断。泛型边界 `<T extends Comparable<T>>` 约束并可调用比较方法 |
| 缺点 | 泛型数组创建需反射或 Array.newInstance；类型推断偶尔失败需显式；擦除致运行时无 T |

### 3.3 泛型 + 工厂模式

| 维度 | 内容 |
|------|------|
| 是什么 | 用泛型与反射结合实现类型安全的工厂模式 |
| 能做什么 | 按类型创建实例；统一对象创建；消除强转 |
| 怎么用 | `static <T> T create(Class<T> clazz)` |
| 原理和工作流程 | 工厂方法声明 `<T> T create(Class<T> clazz)`，内部用 clazz.getDeclaredConstructor().newInstance() 反射创建实例，返回类型由 Class 推断免强转。注册表用 `Map<Class<?>, Supplier<?>>` 存储创建逻辑，按类型查找并创建。Spring 的 BeanFactory 即泛型工厂的体现 |
| 缺点 | 反射创建有性能开销；需处理异常；私有构造器需 setAccessible；类型安全依赖正确注册 |

### 3.4 泛型方法返回值类型推导

| 维度 | 内容 |
|------|------|
| 是什么 | 泛型方法返回值类型由调用上下文推断的机制 |
| 能做什么 | 按目标变量类型推断；按方法实参推断；链式调用推断 |
| 怎么用 | `List<String> list = Collections.emptyList();` |
| 原理和工作流程 | 编译器根据赋值目标变量类型、方法实参类型推断泛型方法的类型参数。Collections.emptyList 推断为 List<String>。复杂场景如 `<T> T foo()` 仅靠目标类型推断。JDK8 改进目标类型推断支持链式调用与 lambda。Collections.<String>emptyList 可显式指定 |
| 缺点 | 推断失败时需显式指定类型；无目标类型时推断为 Object；链式推断可能不符合预期 |

## 四、常见面试题

### 1. Java 泛型是什么？有什么好处？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查泛型定义与核心价值 |
| 能做什么 | 解释参数化类型；列举类型安全与复用好处；说明编译期检查 |
| 怎么用 | `List<String>` 约束元素类型 |
| 原理和工作流程 | 泛型是 JDK5 引入的参数化类型机制，用类型参数 T、E、K、V 占位使用时传入具体类型。好处：编译期类型检查提前发现错误，消除强制转换提升可读性，提升代码复用，避免运行时 ClassCastException。本质是编译期概念编译后擦除 |
| 缺点 | 不支持基本类型需装箱；运行时无类型信息；语法限制多 |

### 2. 泛型中的 ? extends T 和 ? super T 有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查上下界通配符的读写限制差异 |
| 能做什么 | 区分上界只读；区分下界只写；结合 PECS 选型 |
| 怎么用 | 读用 extends 写用 super |
| 原理和工作流程 | `? extends T` 上界通配符接收 T 及子类型，读取为 T 安全但不能写入因具体类型不确定。`? super T` 下界通配符接收 T 及父类型，可写入 T 及子类型安全但读取为 Object。PECS 原则生产者读用 extends 消费者写用 super |
| 缺点 | 读写限制易记反；同时读写不适用；嵌套复杂 |

### 3. 什么是 PECS 原则？请举例说明。

| 维度 | 内容 |
|------|------|
| 是什么 | 考查通配符选择的 PECS 指导原则 |
| 能做什么 | 解释 Producer Extends；解释 Consumer Super；给出 copy 示例 |
| 怎么用 | `copy(List<? extends T> src, List<? super T> dst)` |
| 原理和工作流程 | PECS 即 Producer Extends Consumer Super。集合作为生产者只读不写用 `? extends T` 因读取至少是 T 安全。集合作为消费者只写不读用 `? super T` 因可写入 T 及子类型安全。典型如 Collections.copy 源 src 用 extends 目标 dst 用 super。同时读写则用精确类型 T |
| 缺点 | 原则抽象需结合场景；初学者易混；不适用同时读写 |

### 4. 泛型是如何实现的？什么是类型擦除？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查泛型擦除实现机制与三步流程 |
| 能做什么 | 解释编译期擦除；解释擦除为 Object 或边界；解释自动强转与桥接方法 |
| 怎么用 | 无界擦除 Object 有界擦除边界类型 |
| 原理和工作流程 | Java 泛型用类型擦除实现，泛型是编译期概念编译后类型信息擦除。三步：一擦除类型参数无界替换 Object 有界替换边界类型；二取值处自动插入强转；三生成桥接方法保证多态。运行时 List<String> 与 List<Integer> 同 Class。擦除保证向后兼容但带来诸多限制 |
| 缺点 | 运行时无泛型信息；不能 new T 与 T[]；不能 instanceof 泛型；基本类型需装箱 |

### 5. 什么是桥接方法？为什么需要它？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查桥接方法的生成原因与作用 |
| 能做什么 | 解释擦除致签名不一致；解释桥接保证多态；说明协变返回场景 |
| 怎么用 | 编译器自动生成 isBridge 验证 |
| 原理和工作流程 | 父类泛型方法擦除后参数为 Object，子类重写方法参数为具体类型签名不同非真正重写多态失效。编译器为子类生成桥接方法参数为 Object 内部强转调用具体类型方法，使签名与父类一致实现多态。协变返回类型也会生成桥接方法。可用 method.isBridge 验证 |
| 缺点 | 桥接方法透明易困惑；反射会看到合成方法；需理解擦除才能懂 |

### 6. 为什么 List<String> 不能赋值给 List<Object>？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查泛型不协变的原因 |
| 能做什么 | 解释不协变定义；解释类型安全考虑；说明通配符弥补 |
| 怎么用 | 用 `List<? extends Object>` 接收 |
| 原理和工作流程 | 泛型不协变，`List<String>` 不是 `List<Object>` 子类。若允许赋值则可通过 List<Object> 引用加入 Integer 等任意对象，原 List<String> 类型安全被破坏。String 是 Object 子类但 List<String> 与 List<Object> 无父子关系。需用通配符 `List<? extends Object>` 接收任意泛型 List |
| 缺点 | 不协变限制复用；需通配符弥补增加复杂度；与数组协变行为不一致 |

### 7. 泛型有哪些使用限制？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查类型擦除带来的泛型使用限制 |
| 能做什么 | 列举六大限制；解释擦除原因；说明替代方案 |
| 怎么用 | 基本类型用包装类，创建实例用反射 |
| 原理和工作流程 | 六大限制：一不能用基本类型作泛型参数用包装类替代；二不能 new T 运行时无类型用 Class 反射；三不能 new T[] 用 Array.newInstance 或 List；四不能 instanceof 泛型用原始类型；五不能声明泛型异常类；六类泛型参数不能用于静态字段与方法。均源于类型擦除运行时无类型信息 |
| 缺点 | 限制多需记忆；替代方案增加代码复杂度；与 C# 真泛型对比有差距 |
