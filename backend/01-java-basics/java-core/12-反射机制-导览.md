## 一、核心概念

### 1.1 反射是什么

| 维度 | 内容 |
|------|------|
| 是什么 | 程序运行期间动态获取类信息并操作类成员的机制 |
| 能做什么 | 运行时探知类结构；动态创建对象调用方法访问字段；动态代理；框架基础 |
| 怎么用 | `Class<?> c = Class.forName("com.a.User"); Object o = c.newInstance();` |
| 原理和工作流程 | 反射以 Class 对象为入口，每个加载的类在方法区有唯一 Class 对象，反射 API 通过该对象在运行时获取字段方法构造器等元数据并操作。反射突破了编译期类型检查，使程序能在运行时动态操作未知类型，是 Spring、MyBatis 等框架的基石 |
| 缺点 | 性能低于直接调用；破坏封装与类型安全；编译期检查丢失；代码可读性差 |

### 1.2 反射核心类体系

| 维度 | 内容 |
|------|------|
| 是什么 | java.lang.reflect 包下反射相关的核心类体系 |
| 能做什么 | Class 表示类；Field 表示字段；Method 表示方法；Constructor 表示构造器；Array 操作数组 |
| 怎么用 | `Field f = c.getDeclaredField("name"); Method m = c.getMethod("run");` |
| 原理和工作流程 | Class 是反射入口表示运行时类。Field 封装字段元数据与 set/get 操作。Method 封装方法元数据与 invoke 调用。Constructor 封装构造器与 newInstance 创建对象。Modifier 解析修饰符。Array 提供数组反射操作。AccessibleObject 是三者父类提供 setAccessible 绕过访问检查 |
| 缺点 | 类多 API 繁琐；getDeclared 与 get 区别易混；私有访问需 setAccessible；性能开销 |

### 1.3 反射的优缺点

| 维度 | 内容 |
|------|------|
| 是什么 | 反射机制的优势与劣势的客观评估 |
| 能做什么 | 提升灵活性；支撑框架；动态扩展；但牺牲性能与安全 |
| 怎么用 | 框架内部用反射，业务代码尽量避免 |
| 原理和工作流程 | 优点：动态性运行时操作未知类型，灵活性高，支撑 Spring IOC 与 AOP、注解处理、动态代理等框架能力。缺点：性能低于直接调用因需方法查找与安全检查，破坏封装访问私有成员，编译期类型检查丢失运行时才暴露错误，代码可读性差。故框架内部用反射业务代码应避免 |
| 缺点 | 性能损耗；破坏封装；类型安全弱化；可读性差；调试困难 |

### 1.4 与 Python/JS 动态特性对比

| 维度 | 内容 |
|------|------|
| 是什么 | Java 反射与 Python、JS 动态特性的对比 |
| 能做什么 | 对比动态程度；对比类型检查时机；对比运行时修改能力 |
| 怎么用 | Java 反射是有限动态，Python/JS 天生动态 |
| 原理和工作流程 | Python 与 JS 是动态类型语言运行时天然可增删改对象属性与方法无需反射 API，类型检查在运行时。Java 是静态强类型语言编译期类型检查严格，反射是补充机制运行时通过 API 动态操作但仍受字节码约束不能随意增删类结构。Java 反射本质是访问已有的元数据而非像 Python 可运行时新建类 |
| 缺点 | Java 反射不如动态语言灵活；需显式 API 调用；不能运行时改类结构；性能差距 |

## 二、底层原理

### 2.1 Class 类的 4 种获取方式

| 维度 | 内容 |
|------|------|
| 是什么 | 获取某个类的 Class 对象的四种方式 |
| 能做什么 | 类名.class 静态；对象.getClass 动态；Class.forName 按名加载；ClassLoader.loadClass |
| 怎么用 | `Class<?> c = User.class;` 或 `Class.forName("com.a.User")` |
| 原理和工作流程 | 四种方式：一类名.class 编译期已知性能最高仅获取不初始化。二对象.getClass() 运行时获取已初始化。三Class.forName(全限定名) 按字符串加载会触发类初始化最常用。四ClassLoader.loadClass 加载但不初始化。同一类在 JVM 中只有一个 Class 对象故四种方式获取的 == 为 true |
| 缺点 | Class.forName 需处理 ClassNotFoundException；forName 触发初始化有副作用；字符串类名易拼写错误 |

### 2.2 类加载过程

| 维度 | 内容 |
|------|------|
| 是什么 | 类从加载到 JVM 到可用的五个阶段：加载、验证、准备、解析、初始化 |
| 能做什么 | 加载字节码；验证合法性；准备分配默认值；解析符号引用；初始化赋实际值 |
| 怎么用 | `new` 或反射触发类加载初始化 |
| 原理和工作流程 | 加载通过类加载器读取 .class 字节码生成 Class 对象存方法区。验证检查字节码格式与语义合法性。准备为静态变量分配内存赋零值如 int 为 0。解析将常量池符号引用转为直接引用。初始化执行静态变量赋值与静态代码块。使用与卸载为后续阶段。反射与 new 等主动引用触发初始化，子类加载会先初始化父类 |
| 缺点 | 过程复杂；初始化有副作用；类加载失败致 NoClassDefFoundError；卸载条件严格 |

### 2.3 类加载器层次结构

| 维度 | 内容 |
|------|------|
| 是什么 | JVM 类加载器的层级结构与双亲委派机制 |
| 能做什么 | Bootstrap 加载核心类；Extension 加载扩展类；Application 加载应用类；自定义扩展 |
| 怎么用 | `ClassLoader cl = Thread.currentThread().getContextClassLoader();` |
| 原理和工作流程 | 层级为 Bootstrap ClassLoader（C++ 加载 rt.jar 或 java.base 核心类）→ Extension/Platform ClassLoader（加载 ext 或 jdk.ext 目录）→ Application ClassLoader（加载 classpath）→ 自定义 ClassLoader。双亲委派：收到加载请求先委派父加载器，父加载失败才自行加载，保证核心类由顶层加载避免被篡改与重复加载 |
| 缺点 | 严格层级限制灵活性；SPI 需线程上下文类加载器打破；Tomcat 等容器需自定义层级；理解成本高 |

### 2.4 通过反射创建运行时对象

| 维度 | 内容 |
|------|------|
| 是什么 | 用反射在运行时创建类实例的方法 |
| 能做什么 | clazz.newInstance 调无参构造（已废弃）；getDeclaredConstructor().newInstance 调指定构造 |
| 怎么用 | `Object o = clazz.getDeclaredConstructor().newInstance();` |
| 原理和工作流程 | 旧方式 clazz.newInstance() 调用无参构造器已废弃因绕过编译期检查。推荐 clazz.getDeclaredConstructor(参数类型).newInstance(参数) 调用任意构造器，可调私有构造器需 setAccessible(true)。 newInstance 会传播构造器异常。工厂模式与 Spring IOC 通过此方式按类名创建对象 |
| 缺点 | 需处理多种异常；私有构造需 setAccessible；newInstance 已废弃；性能低于 new |

### 2.5 获取类的完整结构

| 维度 | 内容 |
|------|------|
| 是什么 | 通过反射获取类的字段、方法、构造器、父类、接口、注解等完整结构 |
| 能做什么 | getFields 获取 public 含继承；getDeclaredFields 获取本类全部含私有；获取方法构造器同理 |
| 怎么用 | `Field[] fs = c.getDeclaredFields(); Method[] ms = c.getDeclaredMethods();` |
| 原理和工作流程 | getFields 与 getMethods 返回 public 成员含继承自父类的。getDeclaredFields 与 getDeclaredMethods 返回本类声明的所有成员含 private 不含继承。getConstructors 返回 public 构造器，getDeclaredConstructors 返回全部。getSuperclass 获取父类，getInterfaces 获取接口，getAnnotations 获取注解。getModifiers 配合 Modifier 解析修饰符 |
| 缺点 | get 与 getDeclared 区别易混；性能开销；私有访问需 setAccessible；反射看不到泛型实参 |

### 2.6 调用指定属性、方法、构造器

| 维度 | 内容 |
|------|------|
| 是什么 | 通过反射动态调用指定字段、方法、构造器 |
| 能做什么 | field.set/get 读写字段；method.invoke 调用方法；constructor.newInstance 创建对象 |
| 怎么用 | `m.invoke(obj, args);` 或 `f.set(obj, value);` |
| 原理和工作流程 | 字段：getDeclaredField 获取后 setAccessible(true) 访问私有，set(obj,value) 写 get(obj) 读，静态字段 obj 传 null。方法：getDeclaredMethod(名,参数类型) 获取，invoke(obj,实参) 调用，静态方法 obj 传 null，有返回值。构造器：getDeclaredConstructor(参数类型) 获取 newInstance(实参) 创建对象。需处理各种反射异常 |
| 缺点 | 性能开销；需 setAccessible 访问私有；异常处理繁琐；参数类型匹配易错 |

### 2.7 动态代理原理

| 维度 | 内容 |
|------|------|
| 是什么 | 运行时动态生成代理类拦截方法调用的机制，分 JDK Proxy 与 CGLIB |
| 能做什么 | JDK Proxy 基于接口加 InvocationHandler；CGLIB 基于继承加 MethodInterceptor；AOP 基础 |
| 怎么用 | `Proxy.newProxyInstance(loader, interfaces, handler)` |
| 原理和工作流程 | JDK 动态代理通过 Proxy.newProxyInstance 传入类加载器、接口数组、InvocationHandler，运行时生成继承 Proxy 实现接口的 $Proxy0 类，所有方法调用转发到 InvocationHandler.invoke 执行增强后 method.invoke(target)。只能代理接口。CGLIB 通过 Enhancer 生成目标类子类，MethodInterceptor.intercept 拦截非 final 方法调用 invokeSuper。Spring 有接口用 JDK 无接口用 CGLIB，SpringBoot2.x 默认 CGLIB |
| 缺点 | JDK Proxy 只能代理接口；CGLIB 不能代理 final 类与方法；代理有性能开销；生成类占内存 |

## 三、实战应用

### 3.1 通用对象属性拷贝工具

| 维度 | 内容 |
|------|------|
| 是什么 | 用反射实现同类型或不同类型对象属性拷贝的工具 |
| 能做什么 | 遍历源目标字段；按名匹配；类型兼容拷贝；忽略指定字段 |
| 怎么用 | `BeanUtils.copyProperties(src, dst);` |
| 原理和工作流程 | 获取源类与目标类的 declaredFields，按字段名匹配，类型兼容则用 sourceField.get(src) 读取后 targetField.set(dst,value) 写入，访问私有需 setAccessible(true)。可加注解决定是否拷贝 null 与忽略字段。Spring 的 BeanUtils 与 Apache 的 BeanUtils 即此实现，生产优先用现成工具 |
| 缺点 | 反射性能低于手动拷贝；类型不匹配需处理；深拷贝需递归；null 拷贝覆盖问题 |

### 3.2 配置文件驱动的工厂模式

| 维度 | 内容 |
|------|------|
| 是什么 | 通过配置文件类名用反射创建对象的工厂模式 |
| 能做什么 | 读配置类名；Class.forName 加载；newInstance 创建；统一对象创建 |
| 怎么用 | 配置 `impl=com.a.UserServiceImpl` 后反射创建 |
| 原理和工作流程 | 工厂读取 properties 或 yaml 配置的接口实现类全限定名，用 Class.forName 加载类，getDeclaredConstructor().newInstance 创建实例并按接口类型返回。更换实现只需改配置无需改代码实现解耦。Spring 的 BeanFactory 即配置驱动的反射工厂，按 bean 定义创建实例 |
| 缺点 | 配置类名拼写错误运行时才暴露；反射创建有开销；需处理异常；类型安全弱 |

### 3.3 注解处理器（模拟 @Autowired 注入）

| 维度 | 内容 |
|------|------|
| 是什么 | 用反射扫描字段注解并完成依赖注入的处理器 |
| 能做什么 | 遍历字段；判断注解；setAccessible；注入依赖实例 |
| 怎么用 | 字段标 `@Autowired` 处理器自动注入 |
| 原理和工作流程 | 容器初始化时遍历 bean 的 declaredFields，判断字段是否标注 @Autowired，若是则 setAccessible(true) 后用 field.set(bean, 依赖实例) 注入。按字段类型从容器查找依赖实例。可加 @Qualifier 按名查找。这是 Spring 依赖注入的简化版，Spring 还处理构造器与方法注入及循环依赖 |
| 缺点 | 反射注入有性能开销；循环依赖需特殊处理；私有注入破坏封装；类型查找歧义 |

### 3.4 反射在 Spring IOC 中的应用

| 维度 | 内容 |
|------|------|
| 是什么 | 反射在 Spring 控制反转容器中的核心应用 |
| 能做什么 | 按 bean 定义创建实例；依赖注入；初始化回调；管理生命周期 |
| 怎么用 | Spring 通过反射读 bean 定义创建管理对象 |
| 原理和工作流程 | Spring 启动时读配置或注解得到 bean 定义含类名。用 Class.forName 加载类，getDeclaredConstructor 反射创建实例。遍历字段或构造器参数按 @Autowired 注解反射注入依赖。调用 @PostConstruct 标注的初始化方法。单例缓存复用。反射贯穿 bean 创建注入初始化全生命周期，是 IOC 容器的核心机制 |
| 缺点 | 启动时反射扫描有开销；反射创建性能低于 new；依赖复杂时调试难；循环依赖需三级缓存 |

### 3.5 反射在 Spring AOP 中的应用

| 维度 | 内容 |
|------|------|
| 是什么 | 反射结合动态代理在 Spring 切面编程中的应用 |
| 能做什么 | JDK Proxy 或 CGLIB 生成代理；拦截器链增强；@Aspect 切面织入 |
| 怎么用 | @Aspect 定义切面 Spring 自动生成代理 |
| 原理和工作流程 | Spring AOP 基于动态代理实现。目标类有接口用 JDK Proxy 生成实现接口的代理类，无接口用 CGLIB 生成子类。代理对象方法调用转发到 InvocationHandler 或 MethodInterceptor，执行前置、环绕、后置、异常等通知链，最终 method.invoke(target) 调用目标方法。@Aspect 定义的切点与通知通过反射解析注解织入。事务与日志即 AOP 典型应用 |
| 缺点 | 代理有性能开销；只能代理 public 方法；CGLIB 不能代理 final；自调用不走代理；调试复杂 |

## 四、常见面试题（附答案）

### 1. 什么是反射？反射的原理是什么？优缺点？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查反射定义、原理与优缺点 |
| 能做什么 | 解释运行时动态操作；解释 Class 对象入口；列举优缺点 |
| 怎么用 | `Class.forName` + `getMethod` + `invoke` |
| 原理和工作流程 | 反射是程序运行期间动态获取类信息并操作类成员的机制。原理是每个加载的类在方法区有唯一 Class 对象，反射 API 通过该对象运行时获取字段方法构造器等元数据并操作。优点是动态性强支撑框架。缺点是性能低于直接调用因需方法查找与安全检查，破坏封装访问私有，编译期类型检查丢失运行时才暴露错误 |
| 缺点 | 性能损耗；破坏封装；类型安全弱化；可读性差 |

### 2. Class.forName() 和 ClassLoader.loadClass() 的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查两种类加载方式在初始化上的区别 |
| 能做什么 | 区分是否触发初始化；说明静态块执行；说明适用场景 |
| 怎么用 | 需初始化用 forName，仅加载用 loadClass |
| 原理和工作流程 | Class.forName(全限定名) 不仅加载类还触发初始化阶段执行静态变量赋值与静态代码块，因默认 initialize 为 true。ClassLoader.loadClass(全限定名) 仅执行加载阶段不触发初始化。Class.forName 可传 false 与类加载器参数控制不初始化。JDBC 注册驱动用 Class.forName 触发 Driver 静态块注册 |
| 缺点 | forName 触发初始化有副作用；loadClass 不初始化可能致使用时才初始化；需理解类加载阶段 |

### 3. JDK 动态代理和 CGLIB 动态代理的区别？Spring 如何选择？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查两种动态代理的实现与 Spring 选型策略 |
| 能做什么 | 对比基于接口与继承；对比限制；说明 Spring 默认策略 |
| 怎么用 | 有接口用 JDK，无接口用 CGLIB，SpringBoot 默认 CGLIB |
| 原理和工作流程 | JDK 动态代理基于接口运行时生成实现接口的代理类所有方法转发 InvocationHandler.invoke，只能代理接口方法。CGLIB 基于继承生成目标类子类 MethodInterceptor 拦截非 final 方法，不能代理 final 类与方法。Spring 默认有接口用 JDK 代理无接口用 CGLIB，SpringBoot2.x 起默认 CGLIB 设 proxy-target-class=true。CGLIB 创建慢调用快 JDK 创建快调用略慢 |
| 缺点 | JDK 只代理接口；CGLIB 不能代理 final；各有性能权衡；选型影响行为 |

### 4. 反射在 Spring 框架中有哪些应用？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查反射在 Spring 中的典型应用场景 |
| 能做什么 | IOC 创建注入；AOP 动态代理；注解扫描；MVC 参数绑定 |
| 怎么用 | Spring 大量用反射实现框架能力 |
| 原理和工作流程 | Spring 中反射应用广泛：IOC 容器按 bean 定义用反射创建实例并注入依赖；AOP 用动态代理生成代理对象拦截方法；注解扫描用反射读 @Controller @Service 等注册 bean；MVC 用反射调用 handler 方法并绑定参数；事务用反射读 @Transactional 生成代理。反射是 Spring 框架能力的基石 |
| 缺点 | 启动反射扫描开销；性能低于直接调用；调试复杂；安全限制 |

### 5. 如何通过反射破坏单例？如何防御？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查反射破坏单例与防御手段 |
| 能做什么 | 反射调私有构造创建多实例；枚举防御反射；读时创建防御 |
| 怎么用 | 枚举单例是最佳防御 |
| 原理和工作流程 | 反射破坏：单例私有构造器可被 getDeclaredConstructor 后 setAccessible(true) 再 newInstance 创建新实例破坏唯一性。防御方式：一构造器中判断实例已存在则抛异常阻止二次创建；二用枚举实现单例因枚举实例在类加载创建且 JVM 禁止反射创建枚举对象反射会抛异常；三读时创建单例结合标志位防御。枚举单例是最佳防御方式 |
| 缺点 | 普通防御可被绕过；枚举不能懒加载；反射破坏需主动防御；序列化也需防御 |
