## 一、核心概念

### 1.1 IO 流概述

| 维度 | 内容 |
|------|------|
| 是什么 | Java 处理数据传输的流式 API，以流为单位读写文件、网络、内存等数据源 |
| 能做什么 | 读写文件；网络通信；内存数据流转；支持字节与字符两种单位 |
| 怎么用 | `InputStream is = new FileInputStream("a.txt");` |
| 原理和工作流程 | IO 流按流向分输入流与输出流，按数据类型分字节流与字符流，按角色分节点流与处理流。字节流读写二进制 8 位字节，字符流读写 16 位字符需指定编码。节点流直接连接数据源，处理流包装节点流增强功能。流的读写是阻塞式的 BIO 模型 |
| 缺点 | BIO 阻塞效率低；流类繁多难记；忘记关闭致资源泄漏；字符编码处理易错 |

### 1.2 File 类

| 维度 | 内容 |
|------|------|
| 是什么 | java.io.File 表示文件或目录路径的抽象表示类 |
| 能做什么 | 创建删除文件目录；获取路径名与属性；判断存在与类型；遍历目录 |
| 怎么用 | `File f = new File("a.txt"); f.createNewFile();` |
| 原理和工作流程 | File 是路径抽象不保证文件真实存在，仅操作元数据不读写内容。createNewFile 创建空文件，mkdirs 创建多级目录，delete 删除。list 与 listFiles 遍历目录。JDK7 引入 Path 与 Files 提供更现代的 API，功能更强异常更明确，推荐替代 File |
| 缺点 | 不能读写内容仅操作元数据；跨平台分隔符问题；部分操作非原子；已逐步被 NIO Path/Files 替代 |

### 1.3 IO 流分类体系

| 维度 | 内容 |
|------|------|
| 是什么 | IO 流按流向、数据类型、角色划分的四大基类体系 |
| 能做什么 | 区分字节流与字符流；区分节点流与处理流；识别 InputStream、OutputStream、Reader、Writer 四基类 |
| 怎么用 | 字节流处理二进制，字符流处理文本 |
| 原理和工作流程 | 按数据类型分字节流 InputStream 与 OutputStream 和字符流 Reader 与 Writer 四大抽象基类。按角色分节点流直接连数据源如 FileInputStream、FileReader，处理流包装节点流增强如 BufferedInputStream、InputStreamReader。命名规律：节点流前缀为数据源如 File，处理流前缀为功能如 Buffered |
| 缺点 | 体系庞大类多；命名规律需记忆；初学者难选对流；处理流层层包装易混 |

### 1.4 节点流：字节流

| 维度 | 内容 |
|------|------|
| 是什么 | 直接读写字节数据的节点流，基类为 InputStream 与 OutputStream |
| 能做什么 | 读写二进制文件；按字节或字节数组读取；拷贝文件 |
| 怎么用 | `FileInputStream fis = new FileInputStream("a.jpg"); fis.read(buf);` |
| 原理和工作流程 | FileInputStream 与 FileOutputStream 读写文件字节，read 返回 0 到 255 字节或 -1 表示结束，read(byte[]) 批量读取提升性能。ByteArrayInputStream 与 ByteArrayOutputStream 读写内存字节数组。字节流适合图片视频等二进制文件，不适合直接处理文本因编码问题 |
| 缺点 | 单字节读慢需用缓冲；不能正确处理字符编码；忘记关闭致泄漏；中文易乱码 |

### 1.5 节点流：字符流

| 维度 | 内容 |
|------|------|
| 是什么 | 直接读写字符数据的节点流，基类为 Reader 与 Writer |
| 能做什么 | 读写文本文件；按字符或字符数组读取；处理中文编码 |
| 怎么用 | `FileReader fr = new FileReader("a.txt", StandardCharsets.UTF_8);` |
| 原理和工作流程 | FileReader 与 FileWriter 读写文件字符内部依赖 InputStreamReader 桥接字节到字符需指定编码。read 返回字符或 -1。字符流自动处理编码适合文本文件避免中文乱码。CharArrayReader 与 StringWriter 读写内存字符。JDK11 FileReader 支持显式指定 Charset |
| 缺点 | 不适合二进制文件；默认编码依赖平台易乱码；性能低于缓冲流；需显式指定编码 |

### 1.6 处理流之一：缓冲流

| 维度 | 内容 |
|------|------|
| 是什么 | 包装节点流提供缓冲区减少实际 IO 次数的处理流 |
| 能做什么 | BufferedInputStream 与 BufferedOutputStream 缓冲字节；BufferedReader 与 BufferedWriter 缓冲字符；readLine 读整行 |
| 怎么用 | `BufferedReader br = new BufferedReader(new FileReader("a.txt"));` |
| 原理和工作流程 | 缓冲流内部维护默认 8KB 缓冲区，读取时一次性读入缓冲区后续从内存读取减少磁盘 IO。BufferedReader.readLine 按行读取文本返回不含换行符的字符串。写入时先写缓冲区满或 flush 时才真正写出。使用后只需关闭最外层缓冲流它会级联关闭内部节点流 |
| 缺点 | 需 flush 否则数据残留缓冲区；缓冲区大小固定；忘记关闭致数据丢失 |

### 1.7 处理流之二：转换流

| 维度 | 内容 |
|------|------|
| 是什么 | 字节流与字符流之间的桥梁，指定编解码的处理流 |
| 能做什么 | InputStreamReader 字节转字符；OutputStreamWriter 字符转字节；指定编码 |
| 怎么用 | `InputStreamReader isr = new InputStreamReader(fis, "UTF-8");` |
| 原理和工作流程 | InputStreamReader 包装 InputStream 按指定 Charset 解码字节为字符，是字节流到字符流的桥梁。OutputStreamWriter 包装 OutputStream 按指定 Charset 编码字符为字节。FileReader 与 FileWriter 内部即用转换流但 JDK11 前不暴露编码参数。转换流解决中文乱码与跨平台编码问题 |
| 缺点 | 需显式指定编码否则用平台默认；编解码有性能开销；常用编码需记忆 |

### 1.8 处理流之三：对象流与序列化

| 维度 | 内容 |
|------|------|
| 是什么 | 将对象转为字节序列持久化或传输的对象流，基类 ObjectInputStream 与 ObjectOutputStream |
| 能做什么 | 序列化对象到文件；反序列化恢复对象；transient 排除字段；serialVersionUID 版本控制 |
| 怎么用 | `oos.writeObject(obj);` 与 `Object o = ois.readObject();` |
| 原理和工作流程 | 对象须实现 Serializable 接口才能序列化。ObjectOutputStream.writeObject 将对象图转为字节序列，ObjectInputStream.readObject 恢复。transient 修饰的字段不参与序列化，static 字段也不参与。serialVersionUID 标识版本反序列化时校验一致性不一致抛 InvalidClassException。序列化是深拷贝实现方式 |
| 缺点 | Serializable 无方法标记接口需手动维护 UID；序列化不安全可被篡改；性能不如 JSON；版本不一致致反序列化失败 |

### 1.9 NIO 基础

| 维度 | 内容 |
|------|------|
| 是什么 | JDK1.4 引入的新 IO，基于 Channel、Buffer、Selector 的非阻塞 IO 模型 |
| 能做什么 | Channel 双向通道；Buffer 缓冲区；Selector 多路复用；面向缓冲区 |
| 怎么用 | `FileChannel fc = FileChannel.open(path); ByteBuffer buf = ByteBuffer.allocate(1024);` |
| 原理和工作流程 | NIO 三核心：Channel 是双向数据通道如 FileChannel、SocketChannel，Buffer 是数据缓冲区如 ByteBuffer，Selector 多路复用器监听多个 Channel 事件实现非阻塞。NIO 面向缓冲区数据先读入 Buffer 再处理，BIO 面向流逐字节读。Buffer 有 position、limit、capacity 三指针。NIO 适合高并发连接如 Netty |
| 缺点 | API 复杂学习曲线陡；Buffer 指针状态易错；单线程处理不如简单 BIO 直观；编程模型难掌握 |

## 二、底层原理

### 2.1 装饰器模式在 IO 流中的应用

| 维度 | 内容 |
|------|------|
| 是什么 | IO 流通过层层包装增强功能的设计模式，处理流即装饰器 |
| 能做什么 | 节点流为基础；处理流装饰增强；运行时组合功能；避免类爆炸 |
| 怎么用 | `new BufferedInputStream(new FileInputStream("a"))` 层层包装 |
| 原理和工作流程 | 装饰器模式中组件与装饰器实现同一接口，装饰器持有组件引用并在调用前后增强。IO 流中 InputStream 是抽象组件，FileInputStream 是具体组件，FilterInputStream 是抽象装饰器，BufferedInputStream 是具体装饰器。`new BufferedInputStream(new FileInputStream("a"))` 即用缓冲装饰文件流。运行时按需组合避免为每种功能组合建类。关闭只需关最外层装饰器级联关闭 |
| 缺点 | 层层包装类多难记；构造嵌套深可读性差；装饰顺序有时影响行为；调试难定位实际类 |

### 2.2 serialVersionUID 的底层原理与作用

| 维度 | 内容 |
|------|------|
| 是什么 | 序列化类的版本标识，反序列化时校验类版本一致性的字段 |
| 能做什么 | 标识序列化版本；反序列化校验；兼容性控制；显式声明避免自动生成 |
| 怎么用 | `private static final long serialVersionUID = 1L;` |
| 原理和工作流程 | 序列化时将 serialVersionUID 写入字节流，反序列化时比对字节流的 UID 与当前类 UID，不一致抛 InvalidClassException。若未显式声明编译器根据类结构自动生成，类结构任何改动都致 UID 变化反序列化失败。显式声明固定 UID 可在增删非关键字段时保持兼容。serialver 工具可查看生成的 UID |
| 缺点 | 不显式声明致升级后反序列化失败；UID 维护需谨慎；兼容性边界难把握；删除字段可能致数据丢失 |

### 2.3 字节流与字符流的底层转换原理

| 维度 | 内容 |
|------|------|
| 是什么 | 字符流底层依赖字节流并通过 Charset 编解码的转换原理 |
| 能做什么 | 解释字符流本质；解释 InputStreamReader 桥接；解释编码解码过程 |
| 怎么用 | 字符流 = 字节流 + Charset |
| 原理和工作流程 | 字符流并非独立存在，底层仍读写字节，通过 Charset 将字节解码为字符或字符编码为字节。InputStreamReader 持有 InputStream 与 StreamDecoder，读取字节后用 Charset 解码为字符。OutputStreamWriter 用 StreamEncoder 编码字符为字节。FileReader 内部包装 InputStreamReader。故字符流本质是字节流加编解码器 |
| 缺点 | 编解码有性能开销；编码选错致乱码；默认编码依赖平台；中文编码复杂 |

### 2.4 NIO Buffer 的 flip / clear / compact 机制

| 维度 | 内容 |
|------|------|
| 是什么 | Buffer 在读与写模式间切换的三个核心方法 |
| 能做什么 | flip 翻转为读；clear 清空为写；compact 压缩保留未读切换为写 |
| 怎么用 | `buf.flip(); channel.read(buf); buf.compact();` |
| 原理和工作流程 | Buffer 有 position、limit、capacity 三指针。写模式 position 指向写入位置 limit 在 capacity。flip 将 limit 设为当前 position、position 归零切换为读模式，用于读完写入数据。clear 将 position 归零 limit 设 capacity 清空缓冲区切换为写模式但数据未真正清除。compact 将未读数据复制到开头 position 指向其后 limit 设 capacity 保留未读数据切换为写 |
| 缺点 | 三方法易混用错致数据错乱；指针状态需手动管理；忘记 flip 读不到数据；compact 涉及复制有开销 |

## 三、实战应用

### 3.1 文件复制工具类（支持多种方式）

| 维度 | 内容 |
|------|------|
| 是什么 | 封装多种文件复制方式的工具类，含字节流、缓冲流、NIO、Files.copy |
| 能做什么 | 字节流逐字节复制；缓冲流批量复制；NIO transferTo；Files.copy 一行 |
| 怎么用 | `Files.copy(src, dst, REPLACE_EXISTING)` |
| 原理和工作流程 | 四种方式：一字节流逐字节 read/write 性能最差；二缓冲流用 byte[] 批量读写性能好；三 NIO FileChannel.transferTo 利用零拷贝操作系统直接传输最快；四 Files.copy 一行代码底层 NIO。生产优先 Files.copy 或 NIO transferTo，需兼容旧代码用缓冲流 |
| 缺点 | 逐字节复制慢；忘记关闭流致泄漏；大文件复制占内存；目标存在未处理覆盖 |

### 3.2 文本文件读取与写入工具类

| 维度 | 内容 |
|------|------|
| 是什么 | 封装文本文件按行读写并指定编码的工具类 |
| 能做什么 | 按行读取；按行写入；指定 UTF-8 编码；try-with-resources 自动关闭 |
| 怎么用 | `Files.readAllLines(path, UTF_8)` |
| 原理和工作流程 | 读取用 BufferedReader 包装 InputStreamReader 指定 UTF-8 编码 readLine 按行读，或 JDK8 Files.lines 返回 Stream 按行流式处理。写入用 BufferedWriter 包装 OutputStreamWriter 指定编码 write 加 newLine。JDK7+ Files.readAllLines 与 Files.write 一行完成小文件读写。大文件用流式避免一次性加载 |
| 缺点 | 不指定编码致乱码；大文件一次性读入 OOM；忘记 flush 数据丢失；换行符跨平台差异 |

### 3.3 对象序列化工具类

| 维度 | 内容 |
|------|------|
| 是什么 | 封装对象序列化与反序列化的工具类 |
| 能做什么 | 序列化对象到文件；反序列化恢复；深拷贝；处理 transient |
| 怎么用 | `serialize(obj, "data.ser");` 与 `Object o = deserialize("data.ser");` |

| 缺点 | Java 序列化不安全性能差；版本不一致致失败；transient 字段丢失；不如 JSON 跨语言 |

## 四、常见面试题（附答案）

### 1. Java IO 流分为哪几种？它们之间有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 IO 流按数据类型与角色的分类 |
| 能做什么 | 区分字节流与字符流；区分节点流与处理流；说明四基类 |
| 怎么用 | 二进制用字节流，文本用字符流 |
| 原理和工作流程 | 按数据类型分字节流 InputStream 与 OutputStream 和字符流 Reader 与 Writer。字节流读写 8 位字节适合二进制，字符流读写 16 位字符处理编码适合文本。按角色分节点流直接连数据源如 FileInputStream，处理流包装节点流增强如 BufferedInputStream。字符流底层依赖字节流加编解码 |
| 缺点 | 分类维度多易混；类繁多难记；选错流致乱码或损坏 |

### 2. 什么是装饰器模式？Java IO 流中如何体现？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查装饰器模式在 IO 流中的应用 |
| 能做什么 | 解释装饰器结构；说明处理流即装饰器；说明运行时组合 |
| 怎么用 | `new BufferedInputStream(new FileInputStream("a"))` |
| 原理和工作流程 | 装饰器模式中组件与装饰器实现同一接口，装饰器持有组件引用调用前后增强。IO 流 InputStream 是抽象组件，FileInputStream 具体组件，FilterInputStream 抽象装饰器，BufferedInputStream 具体装饰器。处理流包装节点流层层增强如缓冲、转换、对象序列化，运行时按需组合避免类爆炸。关闭只需关最外层 |
| 缺点 | 包装层次深难读；类多难记；装饰顺序影响行为；调试难定位 |

### 3. 什么是序列化？serialVersionUID 的作用是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查序列化概念与版本标识作用 |
| 能做什么 | 解释对象转字节；解释 UID 版本校验；解释显式声明必要性 |
| 怎么用 | `private static final long serialVersionUID = 1L;` |
| 原理和工作流程 | 序列化是将对象转为字节序列持久化或传输，对象须实现 Serializable。serialVersionUID 是版本标识，序列化时写入字节流，反序列化时比对字节流与当前类 UID 不一致抛 InvalidClassException。未显式声明则编译器按类结构自动生成，类结构改动致 UID 变化反序列化失败，故应显式声明固定 UID 保持兼容 |
| 缺点 | 不显式声明致升级失败；UID 维护需谨慎；Java 序列化不安全；不如 JSON 跨语言 |

### 4. transient 关键字的作用是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 transient 排除字段序列化的作用 |
| 能做什么 | 排除敏感字段；排除临时字段；反序列化后为默认值；与 static 区别 |
| 怎么用 | `private transient String password;` |
| 原理和工作流程 | transient 修饰的字段不参与序列化，序列化时跳过该字段，反序列化后该字段为类型默认值如 null 或 0。常用于排除敏感信息如密码或临时计算字段。static 字段也不参与序列化因属于类而非对象。transient 与 static 都不序列化但原因不同 |
| 缺点 | 反序列化后字段为默认值需手动恢复；不能修饰 static；与 Externalizable 配合可自定义 |

### 5. BIO（传统 IO）和 NIO 的区别是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查阻塞 BIO 与非阻塞 NIO 的差异 |
| 能做什么 | 对比阻塞模型；对比面向流与缓冲；对比 Selector 多路复用；说明适用场景 |
| 怎么用 | 简单 IO 用 BIO，高并发用 NIO |
| 原理和工作流程 | BIO 面向流逐字节读写阻塞式，一个连接需一个线程，连接空闲也占用线程，适合连接数少且固定的场景。NIO 面向缓冲区数据读入 Buffer 处理，Channel 双向，Selector 多路复用一个线程管理多个连接，非阻塞适合高并发连接如 Netty。NIO 通过 Selector 轮询就绪 Channel 实现单线程多连接 |
| 缺点 | BIO 阻塞线程浪费；NIO 编程复杂；BIO 不适合高并发；NIO 学习曲线陡 |

### 6. FileReader 和 BufferedReader 有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查节点流 FileReader 与处理流 BufferedReader 的区别 |
| 能做什么 | 区分节点与处理；说明缓冲提升性能；说明 readLine 功能 |
| 怎么用 | `new BufferedReader(new FileReader("a"))` 组合使用 |
| 原理和工作流程 | FileReader 是节点流直接连接文件按字符读取无缓冲每次读触发磁盘 IO 性能差。BufferedReader 是处理流包装 Reader 提供缓冲区减少 IO 次数性能好，并提供 readLine 按行读取功能。实际使用应 BufferedReader 包装 FileReader。BufferedReader 默认 8KB 缓冲区 |
| 缺点 | FileReader 无缓冲性能差；需组合使用；忘记包装致性能问题 |

### 7. Files.copy() 和传统 IO 流复制有什么区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 NIO Files.copy 与传统字节流复制的区别 |
| 能做什么 | 对比简洁性；对比底层实现；对比性能；说明覆盖选项 |
| 怎么用 | `Files.copy(src, dst, REPLACE_EXISTING)` |
| 原理和工作流程 | Files.copy 是 JDK7 NIO 一行代码完成复制底层用 NIO Channel，简洁且性能好支持 REPLACE_EXISTING 等选项处理目标存在。传统 IO 流需手动开流循环读写并关闭代码繁琐易错且性能低于 NIO。Files.copy 还支持 InputStream 与 OutputStream 复制。生产优先 Files.copy |
| 缺点 | Files.copy 大文件仍需注意内存；传统流需手动关闭；选项需了解 |
