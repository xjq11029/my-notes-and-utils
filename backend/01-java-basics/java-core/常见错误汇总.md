# java-core - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

## 总览

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 文件名与类名不一致 | Java 规定 public 类的类名必须与文件名完全一致（包括大小写） | 确保文件名与 public 类名一致，或使用非 public 类 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| Java 区分大小写 | `System` 写成 `system`、`String` 写成 `string`、`main` 写成 `Main`，编译报错 `找不到符号` | 养成严格区分大小写的习惯，Java 是大小写敏感的语言 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| 中文字符编码问题 | 源代码包含中文注释或字符串，javac 默认使用系统编码，编译报错 `编码 GBK 的不可映射字符` | 编译时加 `-encoding UTF-8` 参数；或 IDE 中统一设置 UTF-8 编码 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| Path 配置后仍无效 | 未重启命令行窗口；或 Path 中存在多个 JDK 版本冲突，`java` 命令找不到 | 关闭并重新打开命令行；检查 Path 中 JDK 路径的顺序 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| 运行时加 .class 后缀 | `java HelloWorld.class` 是错误写法，`java` 命令的参数是类名而非文件名，报错 `错误: 找不到或无法加载主类` | 使用 `java HelloWorld`，不加 `.class` 后缀 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| 多行注释嵌套 | 编译报错或注释提前结束 | Java 的多行注释 `/* */` 不支持嵌套，避免嵌套多行注释；或者用单行注释 `//` 替代内层注释 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| 混淆 JDK 安装路径 | 多个 JDK 共存，不确定使用的哪个版本，安装了多个 JDK，Path 中路径顺序混乱 | 使用 `where java`（Windows）或 `which java`（macOS/Linux）查看实际使用的 java 路径 | [01-Java语言概述-导览](./01-Java语言概述-导览.md) |
| `switch` 忘记 `break` | 执行了不该执行的 case 分支，case 穿透（fall-through）特性 | 每个 case 末尾加 `break`；使用 JDK 14+ 箭头语法（`->`） | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| `if (a = 5)` 误写为赋值 | 条件永远为 true，逻辑错误，`=` 是赋值，`==` 才是比较 | 将常量放前面：`if (5 == a)` 编译期即可发现错误；使用 IDE 静态检查 | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| `for` 循环中 `list.size()` 作为条件 | 每次循环都调用 `size()` 方法，`size()` 可能在循环中被修改或产生额外开销 | 提前缓存：`int size = list.size()` | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| `nextInt()` 后接 `nextLine()` | `nextLine()` 读到空字符串，换行符未被 `nextInt()` 消费 | 在 `nextLine()` 前额外调用一次 `nextLine()` 消费换行符 | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| `do-while` 少用导致逻辑错误 | 不该执行时执行了一次，`do-while` 至少执行一次 | 确认确实需要"先执行一次再判断"的场景才使用 | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| 嵌套循环中 `break` 只跳出内层 | 内层 break 后外层继续执行，`break` 默认只跳出最近一层循环 | 使用标签 `break outer` 跳出指定层 | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| 循环中字符串拼接 | 性能低下，创建大量临时对象，`String` 不可变，每次 `+=` 创建新对象 | 使用 `StringBuilder` 或 `StringBuffer` | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| `Scanner` 未关闭 | 资源泄漏，`System.in` 是有限的系统资源 | 使用 `try-with-resources` 或在 finally 中关闭 | [03-流程控制语句-导览](./03-流程控制语句-导览.md) |
| 数组越界遍历 | `ArrayIndexOutOfBoundsException`，循环条件写成 `i <= arr.length`（应为 `i < arr.length`） | 统一使用 `for (int i = 0; i < arr.length; i++)` 或增强 for 循环 | [04-数组-导览](./04-数组-导览.md) |
| 二维数组内层未初始化 | `NullPointerException`，`int[][] arr = new int[3][];` 后直接访问 `arr[0][0]`，内层数组为 null | 逐行初始化：`arr[0] = new int[4];`；或使用 `new int[3][4]` | [04-数组-导览](./04-数组-导览.md) |
| 数组赋值误认为复制 | 修改新变量影响原数组，`int[] b = a;` 只是复制引用，a 和 b 指向同一对象 | 使用 `Arrays.copyOf()` 或 `System.arraycopy()` 创建独立副本 | [04-数组-导览](./04-数组-导览.md) |
| `Arrays.asList()` 后调 add/remove | `UnsupportedOperationException`，`asList` 返回固定长度的内部类 List | 包装为 `new ArrayList<>(Arrays.asList(...))` | [04-数组-导览](./04-数组-导览.md) |
| 二分查找前未排序 | 返回错误结果或不可预期的负数，`binarySearch` 要求数组已升序排列 | 先调用 `Arrays.sort()` 排序，再调用 `binarySearch()` | [04-数组-导览](./04-数组-导览.md) |
| 打印数组直接 `toString()` | 输出类似 `[I@15db9742` 的哈希码，数组未重写 `toString()`，默认调用 `Object.toString()` | 使用 `Arrays.toString(arr)` 或 `Arrays.deepToString()` | [04-数组-导览](./04-数组-导览.md) |
| 构造器中写 `return` 返回值 | 编译错误，构造器没有返回值类型，也不能 `return` 值 | 构造器只能 `return;`（无值） | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 子类构造器未调用 `super()` | 编译错误（父类无默认构造器时），子类构造器默认调用父类无参构造器，若父类没有则报错 | 显式调用 `super(参数)` | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 方法重写时访问权限更严格 | 编译错误，子类重写方法不能缩小父类方法的访问权限 | 保持或扩大访问权限 | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 多态下调用子类特有方法 | 编译错误，父类引用看不到子类特有的方法 | 向下转型（先 `instanceof` 判断） | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| `Integer` 用 `==` 比较 | 时而 true 时而 false，缓存范围内 `==` 为 true，超出为 false | 统一使用 `equals()` | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 匿名内部类引用局部变量 | 编译错误，局部变量必须是 `final` 或 effectively final | 将变量声明为 `final` 或不在内部类中修改 | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 接口中定义非 `static final` 变量 | 编译错误，接口中的变量默认是 `public static final` | 使用抽象类或在实现类中定义 | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 忘记 `break` 导致枚举 switch 穿透 | 逻辑错误，枚举 switch 同样有穿透特性 | 每个 case 末尾加 `break` | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 递归没有终止条件 | `StackOverflowError`，方法无限递归调用 | 确保递归有明确的终止条件 | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 可变参数放在非最后位置 | 编译错误，可变参数必须是参数列表的最后一个 | 将可变参数移到最后 | [05-面向对象基础-导览](./05-面向对象基础-导览.md) |
| 吞掉异常（空 catch 块） | 异常被静默忽略，程序继续运行，后续出现难以排查的 bug，`catch (Exception e) { }` 空处理 | 至少要记录日志：`catch (Exception e) { log.error("...", e); }` | [06-异常处理-导览](./06-异常处理-导览.md) |
| catch 中使用父类在前 | 编译错误：`unreachable catch block`，子类 catch 块永远无法到达 | 子类异常 catch 放在父类之前 | [06-异常处理-导览](./06-异常处理-导览.md) |
| finally 中写 return | 异常被吞掉，返回值被覆盖，finally 的 return 优先级最高 | finally 中只做资源释放，不写 return | [06-异常处理-导览](./06-异常处理-导览.md) |
| 循环中包裹过大的 try-catch | 一次异常导致整个循环终止，try 块包裹了整个循环体 | 将 try-catch 放在循环内部，只包裹可能失败的单次操作 | [06-异常处理-导览](./06-异常处理-导览.md) |
| 异常信息不具体 | 排查困难，无法定位根因，只记录了 `e.getMessage()` 或简单的 "操作失败" | 记录完整的异常栈：`log.error("用户 {} 查询失败", userId, e)` | [06-异常处理-导览](./06-异常处理-导览.md) |
| 滥用受检异常 | 代码充满 try-catch，方法签名冗长，对不应强制处理的场景使用了受检异常 | 非强制处理的场景使用 RuntimeException | [06-异常处理-导览](./06-异常处理-导览.md) |
| 异常转换丢失原始异常 | 排查时无法找到根因，`throw new BusinessException("失败")` 丢失了 cause | 始终传递原始异常：`throw new BusinessException("失败", e)` | [06-异常处理-导览](./06-异常处理-导览.md) |
| try-with-resources 资源未实现 AutoCloseable | 编译错误，只有实现了 `AutoCloseable` 接口的类才能使用 | 确认资源类实现了 `AutoCloseable`（绝大多数 JDK 资源类都已实现） | [06-异常处理-导览](./06-异常处理-导览.md) |
| 在 finally 中抛出异常 | 原始异常被覆盖，finally 块中关闭资源时抛出了异常 | 使用 try-with-resources 替代手动 finally；必须手动时在 finally 内部再加 try-catch | [06-异常处理-导览](./06-异常处理-导览.md) |
| 循环中使用 `+=` 拼接字符串 | 程序卡顿，GC 频繁，OOM 风险，每次 `+=` 都创建新的 String 对象和 StringBuilder 对象 | 使用 `StringBuilder` 替代 | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `String` 用 `==` 比较 | 明明内容相同却返回 false，`==` 比较引用地址，而非内容 | 始终使用 `equals()` 比较字符串内容 | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `SimpleDateFormat` 多线程共享 | 解析结果错误或抛出异常，`SimpleDateFormat` 不是线程安全的 | 使用 `ThreadLocal` 或 `DateTimeFormatter` | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `BigDecimal` 用 double 构造 | 精度不符合预期，double 本身是近似值，传入构造器时精度已丢失 | 使用 `new BigDecimal(String)` 或 `BigDecimal.valueOf()` | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `BigDecimal` 用 `equals` 比较 | 金额相等却判断为不等，`equals` 比较 scale，`1.0` 和 `1.00` 不相等 | 使用 `compareTo()` 比较数值 | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `BigDecimal` 除法未指定精度 | `ArithmeticException`，除不尽时（如 1/3）无法精确表示 | 必须指定精度和 `RoundingMode` | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `Calendar` 月份按 0-11 计算 | 获取到错误的月份，`Calendar.MONTH` 返回 0-11（0 表示 1 月） | 使用 JDK 8+ `LocalDate`，或记得 +1 处理 | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `new Random()` 多线程共享 | 性能下降，随机数质量降低，内部使用 CAS 竞争同一个种子 | 多线程使用 `ThreadLocalRandom` | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| `String.split()` 的参数是正则 | 按 `.` 分割时得不到预期结果，`.` 在正则中表示任意字符，`"a.b.c".split(".")` 返回空数组 | 转义：`split("\\.")` | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| 基本类型用 `toString()` | 编译错误，基本类型没有方法 | 使用 `String.valueOf()` 或 `Integer.toString()` | [07-常用类与基础API-导览](./07-常用类与基础API-导览.md) |
| HashMap 多线程 put（JDK 7） | CPU 100%，get() 或 put() 时 while 循环无法退出，JDK 7 扩容使用头插法，多线程扩容时链表反转形成循环引用（A -> B -> A） | 使用 ConcurrentHashMap 替代；JDK 8 虽改用尾插法避免死循环，但 HashMap 仍非线程安全，并发 put 仍会导致数据丢失，必须使用 ConcurrentHashMap | [08-面向对象与集合框架-导览](./08-面向对象与集合框架-导览.md) |
| ArrayList 遍历时删除元素 | 抛出 ConcurrentModificationException，for-each 循环内部使用迭代器，直接调用 list.remove() 导致 modCount 不一致 | 使用 Iterator.remove()；使用 JDK 8 removeIf()；从后往前遍历（for 循环） | [08-面向对象与集合框架-导览](./08-面向对象与集合框架-导览.md) |
| subList 修改原列表 | 对原列表结构性修改后 subList 失效，抛出 ConcurrentModificationException，subList 是原列表的视图，非独立副本 | 创建独立副本：`new ArrayList<>(list.subList(1, 4))` | [08-面向对象与集合框架-导览](./08-面向对象与集合框架-导览.md) |
| 认为 `List<String>` 是 `List<Object>` 的子类 | 编译错误：类型不兼容，泛型没有继承关系，`List<String>` 和 `List<Object>` 是并列类型 | 根据需求使用通配符：`List<? extends Object>` 或 `List<?>` | [09-泛型-导览](./09-泛型-导览.md) |
| 在 `List<? extends T>` 中尝试添加元素 | 编译错误，extends 通配符限制写入，编译器不知道集合实际类型 | 读取场景用 extends，写入场景用 super，遵循 PECS 原则 | [09-泛型-导览](./09-泛型-导览.md) |
| 在 `List<? super T>` 中读取元素并赋值给 T 类型 | 编译错误：类型不兼容，super 通配符限制读取，只能读为 Object | 写入场景用 super，如需读取则用 `<T>` 而非通配符 | [09-泛型-导览](./09-泛型-导览.md) |
| 使用基本类型作为泛型参数 | 编译错误，泛型参数必须是引用类型，基本类型不行 | 使用对应的包装类：`List<Integer>` 而非 `List<int>` | [09-泛型-导览](./09-泛型-导览.md) |
| 试图用 `instanceof` 检查泛型类型 | 编译错误，泛型信息在运行时被擦除，无法检查 | 使用原始类型 `instanceof List`，或通过其他方式判断 | [09-泛型-导览](./09-泛型-导览.md) |
| 静态方法中使用类的泛型参数 | 编译错误，静态方法在类加载时存在，此时泛型参数尚未确定 | 静态方法需要定义自己的泛型参数：`static <T> void method(T t)` | [09-泛型-导览](./09-泛型-导览.md) |
| 创建泛型数组 | 编译错误，类型擦除后无法在运行时保证数组类型安全 | 使用 `ArrayList<T>` 代替数组；或通过反射 `Array.newInstance()` | [09-泛型-导览](./09-泛型-导览.md) |
| `List` 和 `List<?>` 混淆 | 前者有原始类型警告，后者无警告，原始类型 `List` 绕过了泛型检查，不安全 | 始终使用 `List<?>` 而非原始类型 `List` | [09-泛型-导览](./09-泛型-导览.md) |
| 在循环中错误地使用 `Collections.sort()` 的比较器泛型 | 编译错误，比较器泛型不匹配 | 遵循 `Comparator<? super T>` 的设计，比较器可以接收父类型 | [09-泛型-导览](./09-泛型-导览.md) |
| 泛型方法的类型参数与类的类型参数重名 | 编译错误或行为不符合预期，方法级泛型参数会隐藏（shadow）类级泛型参数 | 避免重名，方法级泛型使用不同的字母 | [09-泛型-导览](./09-泛型-导览.md) |
| 未关闭 IO 流 | 文件被占用无法删除、内存泄漏、文件句柄耗尽，流对象持有底层操作系统资源 | 始终使用 try-with-resources 自动关闭流（JDK 7+） | [10-IO流-导览](./10-IO流-导览.md) |
| 用字节流读取文本文件 | 中文字符乱码，字节流按字节读取，一个中文字符占 2-3 字节，被拆分后乱码 | 文本文件使用字符流（FileReader/FileWriter）或转换流指定编码 | [10-IO流-导览](./10-IO流-导览.md) |
| FileReader 未指定编码 | 读取非默认编码文件时乱码，FileReader 使用系统默认编码，无法指定 | 使用 InputStreamReader + FileInputStream 指定编码 | [10-IO流-导览](./10-IO流-导览.md) |
| 序列化类未声明 serialVersionUID | 反序列化时抛出 InvalidClassException，类修改后自动生成的 serialVersionUID 变化 | 始终显式声明 serialVersionUID | [10-IO流-导览](./10-IO流-导览.md) |
| 序列化大对象 | 文件体积巨大，反序列化慢，对象内部引用了大量不需要序列化的数据 | 使用 transient 排除不需要的字段，或使用自定义序列化 | [10-IO流-导览](./10-IO流-导览.md) |
| NIO Buffer 未调用 flip() | 读取到的数据为空或错误，写入数据后 position 在末尾，直接读取当然读不到数据 | 读取前必须调用 flip()，写入前调用 clear() 或 compact() | [10-IO流-导览](./10-IO流-导览.md) |
