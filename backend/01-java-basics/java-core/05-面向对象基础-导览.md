## 一、类与对象基础

### 1.1 类与对象

| 维度 | 内容 |
|------|------|
| 是什么 | 类是抽象模板定义属性与行为，对象是类的实例，是面向对象编程的基本单元 |
| 能做什么 | 封装数据与行为；通过 new 创建对象；用构造器初始化；支持匿名对象 |
| 怎么用 | `Person p = new Person("张三", 25);` |
| 原理和工作流程 | new 在堆分配内存创建对象实例，对象变量在栈存堆中引用地址。成员变量随对象存于堆有默认值，局部变量在栈无默认值。构造器用于初始化，定义有参构造器后默认无参构造器消失。this 指代当前对象区分成员与局部变量。多个变量可指向同一对象 |
| 缺点 | 对象创建有内存开销；引用共享致并发修改风险；封装不当致状态混乱 |

### 1.2 成员变量 vs 局部变量

| 维度 | 内容 |
|------|------|
| 是什么 | 按声明位置区分的两类变量，前者在类内方法外后者在方法内 |
| 能做什么 | 区分默认值有无；区分内存位置；区分生命周期与作用域 |
| 怎么用 | 成员变量有默认值，局部变量必须先赋值后使用 |
| 原理和工作流程 | 成员变量随对象存于堆有默认值（int 为 0、引用为 null），可用 public、private、static、final 修饰，生命周期随对象。局部变量存于栈无默认值必须初始化，只能用 final 修饰，随方法调用创建方法结束销毁。同名时局部变量优先，用 this 区分成员变量 |
| 缺点 | 局部变量无默认值易未初始化错误；成员变量默认值掩盖未赋值 bug；同名变量易混淆 |

### 1.3 方法声明与重载

| 维度 | 内容 |
|------|------|
| 是什么 | 方法定义对象行为，重载是同类中同名不同参数列表的多方法机制 |
| 能做什么 | 声明方法；方法重载实现编译时多态；可变参数与形参组合 |
| 怎么用 | `int add(int a,int b)` 与 `int add(int a,int b,int c)` 重载 |
| 原理和工作流程 | 方法由修饰符、返回值、方法名、参数列表、方法体组成。重载要求方法名相同参数列表不同（个数、类型、顺序），与返回值无关，发生在同类中属编译时多态。编译器根据实参类型与数量在编译期绑定具体方法 |
| 缺点 | 重载过多降低可读性；参数顺序不同易误用；仅返回值不同不能重载 |

### 1.4 可变参数（Varargs）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK5 引入的允许方法接收任意数量同类型参数的语法 |
| 能做什么 | 接收 0 到多个参数；内部作为数组处理；简化重载 |
| 怎么用 | `void sum(int... nums)` |
| 原理和工作流程 | 可变参数语法 `类型... 参数名`，编译器将其转为数组，方法内按数组操作。一个方法最多一个可变参数且必须放参数列表最后。调用时可传数组或散列值，编译器自动包装为数组 |
| 缺点 | 必须放最后；只能有一个；传 null 可能引发 NPE；与数组重载冲突时优先数组 |

### 1.5 值传递机制

| 维度 | 内容 |
|------|------|
| 是什么 | Java 方法参数只有值传递，基本类型传值副本引用类型传地址副本 |
| 能做什么 | 解释基本类型不改原值；解释引用类型可改对象内容；解释无法改变原引用指向 |
| 怎么用 | swap 方法无法交换两个变量，须改对象属性 |
| 原理和工作流程 | 基本类型传递值的副本，方法内修改不影响实参。引用类型传递地址的副本，形参与实参指向同一堆对象，通过形参修改对象内容对外可见，但形参重新指向新对象不影响实参。String 因不可变表现为值传递效果。swap 无法交换因只改形参副本 |
| 缺点 | 值传递概念易误为引用传递；引用修改副作用难追踪；无法实现真正的交换 |

### 1.6 递归（Recursion）

| 维度 | 内容 |
|------|------|
| 是什么 | 方法自己调用自己的编程技巧，适用于可分解为同型子问题的场景 |
| 能做什么 | 计算阶乘斐波那契；解决汉诺塔；树形结构遍历 |
| 怎么用 | `f(n) = n * f(n-1)` 配终止条件 `f(1)=1` |
| 原理和工作流程 | 每次递归调用压入新栈帧，子问题规模须缩小直至命中终止条件返回，再逐层出栈合并结果。阶乘递推 f(n)=n×f(n-1) 终止 f(1)=1。无终止条件或递归过深致 StackOverflowError。递归可转循环或用尾递归优化 |
| 缺点 | 栈空间有限易溢出；性能低于迭代；重复计算需记忆化优化 |

## 二、封装继承多态

### 2.1 封装（Encapsulation）

| 维度 | 内容 |
|------|------|
| 是什么 | 隐藏对象内部实现细节对外暴露公共接口的面向对象特性 |
| 能做什么 | 私有化属性；提供 getter/setter；控制访问权限；数据校验 |
| 怎么用 | `private` 属性配 `public` 的 get/set 方法 |
| 原理和工作流程 | 用 private 修饰成员变量禁止外部直接访问，通过 public 的 getter 与 setter 暴露受控访问入口，setter 内可加参数校验。四种访问权限 private、default、protected、public 控制可见范围。封装保护数据完整性降低耦合 |
| 缺点 | getter/setter 样板代码多；过度封装增加调用层级；Lombok 可缓解但增加依赖 |

### 2.2 继承（Inheritance）

| 维度 | 内容 |
|------|------|
| 是什么 | 子类复用父类属性与方法的机制，Java 仅支持单继承 |
| 能做什么 | 复用父类代码；扩展新成员；重写父类方法；形成类型层次 |
| 怎么用 | `class Dog extends Animal {}` |
| 原理和工作流程 | 用 extends 实现单继承，子类获得父类非 private 成员。构造器调用链：子类构造器首行默认 super() 调用父类无参构造器，父类无无参构造器须显式 super(参数)。子类可新增成员或重写方法。所有类默认继承 Object。继承遵循 is-a 关系 |
| 缺点 | 单继承限制复用；父类变更影响所有子类；过度继承致层次臃肿应优先组合 |

### 2.3 super 关键字

| 维度 | 内容 |
|------|------|
| 是什么 | 子类中引用父类成员的关键字，可调用父类属性方法与构造器 |
| 能做什么 | 调用父类构造器；访问父类被遮蔽的成员；解决父子类同名冲突 |
| 怎么用 | `super(name)` 调父构造，`super.method()` 调父方法 |
| 原理和工作流程 | super 在子类构造器首行调用父类构造器初始化父类部分，必须放第一行。super.成员 访问父类被重写或同名的成员变量与方法。super 不指代对象而是编译期指引编译器访问父类作用域。每个构造器默认首行隐式 super() |
| 缺点 | super 必须放构造器首行；多层继承 super 链长难追踪；不能跨层调用祖父类 |

### 2.4 方法重写（Override）

| 维度 | 内容 |
|------|------|
| 是什么 | 子类重新定义父类同名同参数方法的运行时多态机制 |
| 能做什么 | 改写父类行为；实现运行时多态；遵循两同两小一大规则 |
| 怎么用 | 子类用 `@Override` 标注重写方法 |
| 原理和工作流程 | 重写要求方法名与参数列表相同，返回值相同或子类型，访问权限不能更严格，抛出异常不能更宽泛，即两同两小一大。private、static、final 方法不能被重写。运行时 JVM 根据对象实际类型动态分派调用子类方法。@Override 注解帮助编译器校验 |
| 缺点 | 重写规则多易违例；静态方法隐藏非重写易混淆；过度重写破坏父类契约 |

### 2.5 多态（Polymorphism）

| 维度 | 内容 |
|------|------|
| 是什么 | 父类引用指向子类对象运行时调用子类实现的对象多态机制 |
| 能做什么 | 向上转型；运行时动态绑定；向下转型调用子类特有方法 |
| 怎么用 | `Animal a = new Dog(); a.eat();` 调 Dog 的 eat |
| 原理和工作流程 | 多态三前提：继承、重写、父类引用指向子类对象。向上转型即父类引用指向子类对象安全隐式。运行时动态绑定调用对象实际类型的重写方法。向下转型需显式强转并用 instanceof 判断避免 ClassCastException。多态提高扩展性 |
| 缺点 | 父类引用不能调子类特有方法需向下转型；向下转型有类型异常风险；instanceof 滥用降低设计质量 |

### 2.6 Object 类

| 维度 | 内容 |
|------|------|
| 是什么 | 所有 Java 类的根父类，提供 equals、hashCode、toString 等基础方法 |
| 能做什么 | 比较对象相等；获取哈希码；转字符串；获取运行时类；克隆 |
| 怎么用 | 重写 `equals`、`hashCode`、`toString` |
| 原理和工作流程 | Object 是所有类隐式父类。equals 默认用 == 比较地址，String、Integer 等重写为比较内容。hashCode 返回对象哈希码，重写 equals 须重写 hashCode 保证相等对象哈希码相同以适配 HashMap。toString 默认返回类名@哈希码，重写返回有意义描述。getClass 返回运行时 Class 对象 |
| 缺点 | equals 与 hashCode 重写易出错致集合异常；clone 默认浅拷贝；finalize 已废弃 |

## 三、高级特性

### 3.1 static 关键字

| 维度 | 内容 |
|------|------|
| 是什么 | 修饰类级别成员的关键字，所有对象共享同一份静态成员 |
| 能做什么 | 定义静态变量常量方法代码块内部类；静态导入；无需对象访问 |
| 怎么用 | `public static final double PI = 3.14;` |
| 原理和工作流程 | static 修饰的成员属于类而非对象，存于方法区（JDK8 后元空间），类加载时初始化一次。静态方法只能访问静态成员不能用 this 与 super。静态代码块类加载时执行一次用于初始化静态变量。静态导入 import static 可直接调用静态成员 |
| 缺点 | 静态成员生命周期长致内存常驻；静态方法不能用 this 限制多态；全局状态致并发问题 |

### 3.2 final 关键字

| 维度 | 内容 |
|------|------|
| 是什么 | 表示最终不可改变的关键字，可修饰类、方法、变量 |
| 能做什么 | final 类不可继承；final 方法不可重写；final 变量不可重新赋值 |
| 怎么用 | `final class String`、`final int MAX=3`、`final void m()` |
| 原理和工作流程 | final 修饰类禁止被继承如 String、Integer 保证不可变与安全。final 修饰方法禁止子类重写保证逻辑不被篡改。final 修饰变量变为常量只能赋值一次，实例常量须在构造器结束前初始化。final 修饰引用变量引用不可变但对象内容可变。static final 为类级全局常量存于方法区 |
| 缺点 | final 类无法扩展降低灵活性；final 方法限制多态；final 引用对象内容仍可改易误判 |

### 3.3 代码块

| 维度 | 内容 |
|------|------|
| 是什么 | 用花括号包围的代码段，分静态代码块、实例代码块、构造器、局部代码块四种 |
| 能做什么 | 静态代码块类加载初始化；实例代码块对象初始化；构造器初始化；局部代码块限作用域 |
| 怎么用 | `static { }` 静态，`{ }` 实例 |
| 原理和工作流程 | 静态代码块类加载时执行仅一次按定义顺序。实例代码块每次 new 对象时执行在构造器之前。构造器在实例代码块之后执行。父子类执行顺序：静态父→静态子→实例父→构造父→实例子→构造子。口诀静态先行父到子，实例跟随父实例父构造子实例子构造 |
| 缺点 | 执行顺序复杂易混淆；静态代码块异常致类加载失败；实例代码块使用少降低可读性 |

### 3.4 抽象类（Abstract Class）

| 维度 | 内容 |
|------|------|
| 是什么 | 不能实例化、用于定义子类通用模板的类，可含抽象方法与具体方法 |
| 能做什么 | 定义抽象方法强制子类实现；提供通用实现；声明构造器供子类调用 |
| 怎么用 | `abstract class Shape { abstract double getArea(); }` |
| 原理和工作流程 | 用 abstract 修饰类与方法，抽象方法无方法体由子类实现。抽象类可有普通属性、构造器、具体方法。子类须实现所有抽象方法否则也须声明抽象。抽象类用于 is-a 关系的模板方法模式，体现部分实现与部分抽象 |
| 缺点 | 单继承限制复用；抽象方法过多增加子类负担；与接口选择需权衡 |

## 四、接口与内部类

### 4.1 接口（Interface）

| 维度 | 内容 |
|------|------|
| 是什么 | 定义规范契约的抽象方法集合，支持多实现 |
| 能做什么 | 定义常量与抽象方法；多实现解决单继承限制；接口多继承 |
| 怎么用 | `interface Flyable { void fly(); }` 后 `class Bird implements Flyable` |
| 原理和工作流程 | 接口成员变量默认 public static final 即常量，方法默认 public abstract。一个类可实现多个接口用 implements，接口可继承多个接口用 extends。实现类须实现所有抽象方法。接口体现 can-do 能力契约，用于解耦与多态 |
| 缺点 | JDK7 前无方法实现；无构造器无状态；字段必须常量限制灵活性 |

### 4.2 JDK 8/9 接口新特性

| 维度 | 内容 |
|------|------|
| 是什么 | JDK8 引入默认方法静态方法、JDK9 引入私有方法的接口增强 |
| 能做什么 | 默认方法提供实现且可被重写；静态方法属接口；私有方法复用内部代码 |
| 怎么用 | `default void m(){}`、`static int add(a,b)`、`private void log(){}` |
| 原理和工作流程 | JDK8 默认方法用 default 关键字提供默认实现，实现类可重写可不。静态方法属接口通过接口名调用实现类不继承。多接口同名默认方法冲突时实现类必须重写，遵循类优先原则：类方法优于接口默认方法，子接口优于父接口。JDK9 私有方法抽取默认方法间公共代码 |
| 缺点 | 默认方法冲突需手动解决；静态方法不能被实现类继承；过度使用破坏接口纯粹性 |

### 4.3 内部类（Inner Class）

| 维度 | 内容 |
|------|------|
| 是什么 | 定义在另一个类内部的类，分成员、静态、局部、匿名四种 |
| 能做什么 | 成员内部类访问外部类私有成员；静态内部类不依赖外部实例；匿名内部类简化回调 |
| 怎么用 | `Outer.Inner i = new Outer().new Inner();` |
| 原理和工作流程 | 成员内部类持有外部类引用可访问其私有成员，依赖外部实例创建。静态内部类用 static 修饰不持有外部引用可独立创建。局部内部类定义在方法内仅方法内可见。匿名内部类无类名即时实现接口或继承类，常用于回调与事件处理。匿名内部类引用局部变量须 final 或 effectively final |
| 缺点 | 内部类增加类文件与复杂度；匿名内部类可读性差；持有外部引用易致内存泄漏 |

## 五、枚举、注解与包装类

### 5.1 枚举（Enum）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK5 引入的有限命名常量集合类型，本质是继承 Enum 的 final 类 |
| 能做什么 | 定义命名常量；携带属性与方法；实现接口；switch 匹配 |
| 怎么用 | `enum Color { RED("红"), GREEN("绿"); }` |
| 原理和工作流程 | 枚举本质是继承 java.lang.Enum 的 final 类，每个常量是单例实例在类加载时创建。枚举可定义属性、构造器、方法，构造器只能 private。枚举天然线程安全且防反射攻击，是实现单例的最佳方式。switch 支持枚举且 JDK14+ 箭头语法防穿透。values 返回所有常量 |
| 缺点 | 枚举常量在类加载创建无法懒加载；占用内存多于普通常量；扩展性受限 |

### 5.2 注解（Annotation）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK5 引入的元数据机制，用于为代码添加标记信息供编译器或运行时处理 |
| 能做什么 | 标记代码；配置框架行为；编译检查；运行时反射读取 |
| 怎么用 | `@Override`、`@Deprecated`、`@SuppressWarnings` |
| 原理和工作流程 | 注解用 @interface 定义，可用 @Target 指定作用目标、@Retention 指定保留策略（SOURCE、CLASS、RUNTIME）。元注解控制注解行为。编译器处理 SOURCE 级注解如 @Override 校验重写。RUNTIME 级注解通过反射在运行时读取，是 Spring 等框架的核心机制。注解本身不改变代码逻辑需处理器配合 |
| 缺点 | 注解不改变逻辑需处理器配合；运行时反射有性能开销；注解泛滥降低代码直观性 |

### 5.3 包装类（Wrapper Class）

| 维度 | 内容 |
|------|------|
| 是什么 | 为每种基本类型提供的对应引用类型，实现基本类型与对象互转 |
| 能做什么 | 自动装箱拆箱；字符串与基本类型互转；进制转换；提供常量 |
| 怎么用 | `Integer obj = 100;` 自动装箱，`int n = obj;` 自动拆箱 |
| 原理和工作流程 | 八种包装类 Byte、Short、Integer、Long、Float、Double、Character、Boolean。JDK5 自动装箱编译为 valueOf，拆箱编译为 xxxValue。Integer 缓存 **-128 到 127**，自动装箱在此范围返回缓存对象故 == 为 true，超出则新建为 false。包装类提供 parseInt、toString、toBinaryString 等方法及 MAX_VALUE、MIN_VALUE 常量 |
| 缺点 | 自动装箱有性能开销；Integer 缓存致 == 时而成立时而不成立；包装类为 null 拆箱抛 NPE |

## 常见面试题精选

### 1. 重载和重写的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查编译时重载与运行时重写的概念辨析 |
| 能做什么 | 区分发生位置；区分参数要求；区分多态类型 |
| 怎么用 | 重载同类同名不同参，重写子类同名同参 |
| 原理和工作流程 | 重载发生在同一个类中方法名相同参数列表必须不同与返回值无关属编译时多态由编译器静态绑定。重写发生在子类与父类间方法名与参数列表相同返回值相同或子类型访问权限不能更严格异常不能更宽泛属运行时多态由 JVM 动态分派 |
| 缺点 | 两者英文相似易混；重载仅返回值不同不算；重写规则多易违例 |

### 2. 抽象类和接口的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查抽象类与接口在设计理念与语法上的差异 |
| 能做什么 | 对比继承方式；对比成员构成；对比设计理念 |
| 怎么用 | is-a 用抽象类，can-do 用接口 |
| 原理和工作流程 | 抽象类用 abstract class 单继承有构造器可有普通变量与具体方法体现 is-a。接口用 interface 多实现无构造器仅常量与抽象方法（JDK8+ 默认静态方法 JDK9+ 私有方法）体现 can-do。抽象类用于模板复用，接口用于规范契约与解耦 |
| 缺点 | 两者边界有时模糊；选型不当致设计僵化；JDK8 后接口增强模糊了差异 |

### 3. == 和 equals() 的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 == 比较地址与 equals 比较内容的差异及重写关系 |
| 能做什么 | 区分基本与引用比较；说明 equals 默认实现；强调重写 hashCode |
| 怎么用 | 引用类型内容比较用 equals 不用 == |
| 原理和工作流程 | == 对基本类型比值对引用类型比内存地址。equals 是 Object 方法默认用 == 比地址，String、Integer 等重写为比较内容。重写 equals 必须重写 hashCode 保证相等对象哈希码相同，否则 HashMap、HashSet 容器会出错。Integer 缓存范围内 == 巧合成立不可依赖 |
| 缺点 | == 误用于内容比较是高频 bug；equals 不重写 hashCode 致集合异常；Integer 缓存干扰判断 |

### 4. 静态代码块、构造代码块、构造方法的执行顺序？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查父子类下静态代码块、实例代码块、构造器的执行顺序 |
| 能做什么 | 说明静态先行父到子；说明实例跟随父实例父构造子实例子构造；区分执行次数 |
| 怎么用 | 口诀静态先行父到子实例跟随 |
| 原理和工作流程 | 静态代码块类加载时执行仅一次按父到子顺序。实例代码块与构造器每次 new 对象时执行。父子类完整顺序：父静态→子静态→父实例→父构造→子实例→子构造。静态块仅一次，实例块与构造器每次创建对象都执行 |
| 缺点 | 顺序复杂易记错；静态块异常致类加载失败；多对象创建顺序需结合实例块 |

### 5. Integer 的缓存机制是怎样的？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Integer 自动装箱缓存 -128 到 127 的机制及 == 影响 |
| 能做什么 | 解释缓存范围；解释 == 时而 true 时而 false；推荐用 equals |
| 怎么用 | 比较 Integer 值用 equals 不用 == |
| 原理和工作流程 | Integer 默认缓存 **-128 到 127** 的对象，自动装箱时值在缓存范围直接返回缓存对象不新建，故 Integer a=100 与 b=100 的 == 为 true。超出范围则 new 新对象 == 为 false。缓存上限可通过 -XX:AutoBoxCacheMax 调整。Byte、Short、Long 缓存 -128 到 127，Character 缓存 0 到 127，Float、Double 无缓存 |
| 缺点 | 缓存致 == 行为不一致易出 bug；范围可调增加不确定性；易误用 == 比较包装类 |
