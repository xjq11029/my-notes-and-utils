## 一、核心概念

### 1.1 集合体系总览

| 维度 | 内容 |
|------|------|
| 是什么 | Java 提供的用于存储和操作一组对象的容器体系，分 Collection 与 Map 两大根接口 |
| 能做什么 | List 有序可重复；Set 无序不重复；Queue 队列；Map 键值对；支持泛型与迭代 |
| 怎么用 | `List<String> list = new ArrayList<>();` |
| 原理和工作流程 | 集合分两大根：Collection 下分 List（ArrayList、LinkedList）、Set（HashSet、LinkedHashSet、TreeSet）、Queue（ArrayDeque、PriorityQueue）；Map 下分 HashMap、LinkedHashMap、TreeMap、ConcurrentHashMap。集合只能存对象基本类型需装箱。泛型提供编译期类型检查。相比数组集合长度可变功能丰富 |
| 缺点 | 只能存对象需装箱；非线程安全（除并发包）；选型不当性能差 |

### 1.2 List 系列核心类

| 维度 | 内容 |
|------|------|
| 是什么 | 有序、可重复、可按索引访问的集合，核心实现为 ArrayList 与 LinkedList |
| 能做什么 | 按索引增删改查；随机访问；用 subList 截取；用 ListIterator 双向遍历 |
| 怎么用 | `list.add("a"); list.get(0); list.set(0,"b");` |
| 原理和工作流程 | ArrayList 底层 Object[] 动态数组随机访问 O(1) 尾插均摊 O(1) 中间增删 O(n)，1.5 倍扩容。LinkedList 底层双向链表增删 O(1) 随机访问 O(n) 内存占用大。Vector 是线程安全的 ArrayList 已淘汰。ListIterator 支持双向与增删 |
| 缺点 | ArrayList 中间增删慢；LinkedList 随机访问慢内存大；Vector 同步开销大 |

### 1.3 Set 系列核心类

| 维度 | 内容 |
|------|------|
| 是什么 | 不允许重复元素的集合，核心实现为 HashSet、LinkedHashSet、TreeSet |
| 能做什么 | 去重；用 HashSet O(1) 查找；用 TreeSet 排序；用 LinkedHashSet 保留插入顺序 |
| 怎么用 | `Set<String> set = new HashSet<>(); set.add("a");` |
| 原理和工作流程 | HashSet 基于 HashMap 的 key 实现 O(1) 增删查无序。LinkedHashSet 继承 HashSet 用双向链表维护插入顺序。TreeSet 基于 TreeMap 红黑树实现元素自然排序或 Comparator 排序增删查 O(log n)。去重依赖 equals 与 hashCode |
| 缺点 | HashSet 无序；TreeSet 增删查 O(log n) 慢于 HashSet；自定义对象须正确重写 equals 与 hashCode |

### 1.4 Map 系列核心类

| 维度 | 内容 |
|------|------|
| 是什么 | 存储键值对映射的集合，核心实现为 HashMap、LinkedHashMap、TreeMap、ConcurrentHashMap |
| 能做什么 | 键值映射；按 key 增删改查；遍历 entrySet；判断包含 key 或 value |
| 怎么用 | `map.put("k",1); map.get("k");` |
| 原理和工作流程 | HashMap 数组加链表加红黑树无序允许 null。LinkedHashMap 用双向链表维护插入或访问顺序。TreeMap 红黑树按 key 排序。ConcurrentHashMap 线程安全。Hashtable 线程安全但已淘汰不允许 null。key 须正确重写 equals 与 hashCode |
| 缺点 | HashMap 非线程安全；TreeMap 性能 O(log n)；key 唯一性依赖 equals 与 hashCode；ConcurrentHashMap 不允许 null |

### 1.5 Queue 与 Deque 系列

| 维度 | 内容 |
|------|------|
| 是什么 | 队列与双端队列接口，核心实现为 ArrayDeque、LinkedList、PriorityQueue |
| 能做什么 | FIFO 队列；LIFO 栈；双端增删；优先级出队 |
| 怎么用 | `Deque<Integer> stack = new ArrayDeque<>(); stack.push(1);` |
| 原理和工作流程 | ArrayDeque 基于循环数组性能优于 LinkedList 推荐用作栈与队列。LinkedList 实现 Deque 但有节点开销。PriorityQueue 基于堆实现按优先级出队，元素须实现 Comparable 或传 Comparator。Queue 方法 offer/poll/peek 失败返回特殊值，add/remove/element 失败抛异常。栈用 push/pop/peek |
| 缺点 | Stack 继承 Vector 已淘汰；PriorityQueue 非线程安全；ArrayDeque 不能存 null |

### 1.6 Iterator 迭代器

| 维度 | 内容 |
|------|------|
| 是什么 | 统一遍历集合元素的接口，提供 hasNext、next、remove 方法 |
| 能做什么 | 遍历集合；安全删除元素；ListIterator 双向与增删改；增强 for 底层依赖 |
| 怎么用 | `Iterator<String> it = list.iterator(); while(it.hasNext()){ it.next(); }` |
| 原理和工作流程 | Iterator 是集合遍历的统一接口。增强 for 编译为 Iterator 实现。迭代中删除元素须用 iterator.remove 否则触发 ConcurrentModificationException。ListIterator 扩展支持 hasPrevious、previous、add、set 双向遍历与修改。iterator.remove 是唯一安全的迭代删除方式 |
| 缺点 | 只能单向（ListIterator 除外）；迭代中直接集合删除抛异常；遍历中修改受限 |

### 1.7 Collections 工具类

| 维度 | 内容 |
|------|------|
| 是什么 | java.util.Collections 提供集合操作的静态工具类 |
| 能做什么 | sort 排序；shuffle 打乱；reverse 反转；binarySearch 查找；synchronizedXxx 同步包装；unmodifiableXxx 不可变包装 |
| 怎么用 | `Collections.sort(list);`、`Collections.synchronizedList(list)` |
| 原理和工作流程 | sort 基于归并的 TimSort 稳定排序。synchronizedXxx 用装饰器模式包装集合每个方法加 synchronized 实现线程安全。unmodifiableXxx 包装后增删改抛 UnsupportedOperationException。singletonXxx 返回单元素不可变集合。frequency、disjoint 等辅助方法。emptyXxx 返回空不可变集合 |
| 缺点 | synchronizedXxx 粒度粗性能低应优先并发包；不可变包装运行时才报错；工具方法多难全记 |

## 二、底层原理（源码深度解析）

### 2.1 HashMap 源码深度解析

| 维度 | 内容 |
|------|------|
| 是什么 | 基于数组加链表加红黑树实现的哈希表，JDK8 尾插法替代 JDK7 头插法 |
| 能做什么 | O(1) 增删查；扩容翻倍；链表树化优化；扰动函数降低碰撞 |
| 怎么用 | `Map<String,Integer> m = new HashMap<>(16,0.75f)` |
| 原理和工作流程 | 默认容量 **16** 负载因子 **0.75** 树化阈值 **8** 退化阈值 **6** 最小树化容量 **64**。hash 扰动 `h ^ (h>>>16)` 融合高低位降低碰撞，下标 `(n-1)&hash` 等价取模更快。put 流程：算 hash 定下标，空桶直接插入，否则匹配首节点或遍历链表尾插或红黑树插入，链表长度达 8 且数组达 64 树化。扩容翻倍用 `e.hash & oldCap` 高低位拆分避免 JDK7 头插死循环。容量 2 的幂使位运算替代取模 |
| 缺点 | 非线程安全多线程致数据丢失；扩容全量 rehash 有开销；树化退化有转换开销 |

### 2.2 ConcurrentHashMap 源码深度解析

| 维度 | 内容 |
|------|------|
| 是什么 | 线程安全的 HashMap，JDK7 用 Segment 分段锁 JDK8 用 CAS 加 synchronized |
| 能做什么 | 高并发读写；get 无锁；put 桶级锁；渐进式扩容；分段计数 |
| 怎么用 | `ConcurrentHashMap<String,Integer> m = new ConcurrentHashMap<>();` |
| 原理和工作流程 | JDK7 用 **16** 个 Segment 分段锁每段独立 HashMap 并发度 16。JDK8 废弃 Segment 改为 CAS 加 synchronized 锁桶头节点并发度等于桶数。putVal 四种桶状态：空桶 CAS 插入无锁，MOVED 协助扩容，链表头 synchronized 加锁尾插，TreeBin synchronized 加锁插入。sizeCtl 多重语义控制初始化与扩容。渐进式扩容用 ForwardingNode 标记已迁移桶其他线程读写时协助迁移。get 无锁因 val 与 next 用 volatile。size 用 baseCount 加 CounterCell 分段计数 |
| 缺点 | 不允许 null key 与 value；size 是弱一致性；JDK7 分段锁并发度受限；实现复杂 |

### 2.3 ArrayList vs LinkedList

| 维度 | 内容 |
|------|------|
| 是什么 | 基于动态数组的 ArrayList 与基于双向链表的 LinkedList 的对比与选型 |
| 能做什么 | 对比随机访问与增删性能；对比内存占用；对比缓存友好度；给出选型决策 |
| 怎么用 | 随机访问用 ArrayList，头尾增删用 LinkedList，栈队列用 ArrayDeque |
| 原理和工作流程 | ArrayList 底层 Object[] 随机访问 O(1) 头部增删 O(n) 尾插均摊 O(1)，1.5 倍扩容，连续内存缓存友好内存紧凑。LinkedList 底层双向链表增删 O(1) 随机访问 O(n)，每节点额外 prev 与 next 指针内存大，节点分散缓存不友好。决策：频繁随机访问与尾追加用 ArrayList，头部增删用 LinkedList，栈队列优先 ArrayDeque |
| 缺点 | ArrayList 中间增删慢；LinkedList 随机访问慢内存大；LinkedList 缓存不友好实际性能常低于预期 |

### 2.4 fail-fast 与 fail-safe 机制

| 维度 | 内容 |
|------|------|
| 是什么 | 集合迭代时检测结构性修改的两种机制，fail-fast 抛异常 fail-safe 不抛 |
| 能做什么 | fail-fast 及时发现并发修改；fail-safe 弱一致性；区分底层实现 |
| 怎么用 | 迭代删除用 iterator.remove，并发用 CopyOnWriteArrayList |
| 原理和工作流程 | fail-fast 集合如 ArrayList 维护 modCount，迭代器遍历前比对 expectedModCount 与 modCount 不一致抛 ConcurrentModificationException，但仅检测非保证安全。fail-safe 集合如 CopyOnWriteArrayList 迭代时复制快照遍历不抛异常但弱一致性可能读旧值。ConcurrentHashMap 迭代弱一致性不抛异常 |
| 缺点 | fail-fast 不能保证并发安全仅提示；fail-safe 弱一致性读旧值；CopyOnWrite 写时复制内存开销大 |

## 三、实战应用

### 3.1 HashMap 使用注意事项

| 维度 | 内容 |
|------|------|
| 是什么 | HashMap 实际使用中的容量预估、key 不可变与线程安全注意事项 |
| 能做什么 | 预估容量避免扩容；key 用不可变对象；多线程用 ConcurrentHashMap；自定义对象重写 equals 与 hashCode |
| 怎么用 | `new HashMap<>((int)(expected/0.75f)+1)` |
| 原理和工作流程 | 预知元素数应在构造时指定初始容量 预期大小除以 0.75 加 1 避免扩容。key 须用不可变对象否则 key 改变后查找不到。自定义 key 须同时重写 equals 与 hashCode 保证逻辑一致。多线程环境用 ConcurrentHashMap 而非 synchronizedMap 或 Hashtable |
| 缺点 | 容量预估不当多次扩容；可变 key 致查找失败；equals 与 hashCode 不一致致集合异常 |

### 3.2 遍历集合的正确姿势

| 维度 | 内容 |
|------|------|
| 是什么 | 各种集合场景下推荐与不推荐的遍历方式对比 |
| 能做什么 | entrySet 遍历 Map；iterator.remove 删除；forEach 与 Stream；避免增强 for 中增删 |
| 怎么用 | `map.forEach((k,v)->{})` 或 `for (var e : map.entrySet())` |
| 原理和工作流程 | Map 遍历优先 entrySet 一次拿到键值优于先 keySet 再 get 两次查找。需删除用 iterator.remove 或 JDK8 removeIf。ArrayList 索引 for 优于迭代器，LinkedList 迭代器或增强 for 优于索引 get。Stream 与 forEach 代码简洁但性能略低于传统 for。增强 for 中直接 add/remove 抛 ConcurrentModificationException |
| 缺点 | keySet 遍历 Map 两次查找慢；增强 for 删除抛异常；索引遍历 LinkedList 灾难性慢 |

### 3.3 不可变集合（JDK 9+）

| 维度 | 内容 |
|------|------|
| 是什么 | JDK9 引入的 List.of、Set.of、Map.of 等工厂方法创建的不可变集合 |
| 能做什么 | 简洁创建不可变集合；防止修改；节省内存；多线程安全共享 |
| 怎么用 | `List.of(1,2,3)`、`Map.of("k",1)` |
| 原理和工作流程 | JDK9 的 of 静态工厂方法创建不可变集合，增删改抛 UnsupportedOperationException。Set.of 与 Map.of 不允许 null 与重复 key 重复直接抛异常而非覆盖。相比 Collections.unmodifiableXxx 包装现有集合更简洁。底层针对不同元素数量有优化实现减少内存占用 |
| 缺点 | 不可变不可修改；Set.of 重复抛异常非覆盖；JDK9 才支持；与 Arrays.asList 行为不同易混 |

### 3.4 集合与数组互转

| 维度 | 内容 |
|------|------|
| 是什么 | 集合与数组之间相互转换的方法与常见坑 |
| 能做什么 | 数组转 List；List 转数组；区分可变与不可变；区分基本与引用类型 |
| 怎么用 | `list.toArray(new String[0])`、`Arrays.asList(arr)` |
| 原理和工作流程 | 数组转 List 用 Arrays.asList 返回固定长度视图不可增删，转可变用 `new ArrayList<>(Arrays.asList(arr))`。List 转数组用 toArray 无参返回 Object[] 不推荐，带参 `toArray(new String[0])` 返回指定类型数组。基本类型数组 asList 整体当一个元素因泛型不支持基本类型，须手动装箱或用流 |
| 缺点 | asList 返回 List 不可变是高频坑；基本类型数组不展开；toArray 无参类型丢失 |

## 四、常见面试题（附答案）

### 1. HashMap 的底层原理（必考）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 HashMap 数据结构与 put 扩容流程 |
| 能做什么 | 描述数组加链表加红黑树；描述扰动函数与下标计算；描述扩容机制 |
| 怎么用 | 默认容量 16 负载因子 0.75 树化阈值 8 |
| 原理和工作流程 | JDK8 底层 Node 数组加链表加红黑树。put 先算 hash 扰动 `h ^ (h>>>16)` 再 `(n-1)&hash` 定下标，空桶直接插入，否则匹配首节点或遍历链表尾插或红黑树插入。链表长度达 8 且数组达 64 树化为红黑树优化冲突。size 超阈值 capacity 乘 loadFactor 触发扩容翻倍，用 `e.hash & oldCap` 高低位拆分。容量 2 的幂使 `(n-1)&hash` 等价取模更快 |
| 缺点 | 非线程安全；扩容 rehash 开销；树化退化转换开销 |

### 2. HashMap 为什么用红黑树？为什么树化阈值是 8？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查红黑树优化目的与阈值 8 的概率依据 |
| 能做什么 | 解释红黑树优化哈希冲突；解释泊松分布概率；解释退化阈值 6 |
| 怎么用 | 链表长度 8 且数组 64 树化，节点 6 退化 |
| 原理和工作流程 | 哈希冲突严重时链表查找退化为 O(n)，红黑树优化为 O(log n)。树化条件为链表长度达 8 且数组长度达 64，若数组不足 64 优先扩容而非树化。阈值选 8 因负载因子 0.75 时根据泊松分布链表长度达 8 的概率约 **0.00000006** 几乎不发生，避免频繁树化退化开销。退化阈值 6 留缓冲避免 8 附近反复转换 |
| 缺点 | 树化退化有转换开销；红黑树节点内存大于链表；阈值依据理论概率实际可能不同 |

### 3. HashMap 和 Hashtable 的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 HashMap 与 Hashtable 在线程安全、null 支持、继承上的差异 |
| 能做什么 | 对比线程安全；对比 null 支持；对比继承关系；给出选型 |
| 怎么用 | 单线程用 HashMap，多线程用 ConcurrentHashMap |
| 原理和工作流程 | HashMap 非线程安全允许 null key 与 value 继承 AbstractMap。Hashtable 线程安全方法加 synchronized 不允许 null 继承 Dictionary。Hashtable 已淘汰，多线程应用 ConcurrentHashMap 替代其并发度更高性能更好。HashMap JDK8 引入红黑树 Hashtable 无 |
| 缺点 | Hashtable 同步粒度粗性能低；已淘汰不应使用；null 限制影响灵活 |

### 4. ConcurrentHashMap 的原理？JDK 7 和 JDK 8 的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 ConcurrentHashMap 两版实现的并发控制机制 |
| 能做什么 | 解释 JDK7 分段锁；解释 JDK8 CAS 加 synchronized；解释 get 无锁与渐进式扩容 |
| 怎么用 | JDK7 Segment 16 并发度，JDK8 桶级锁 |
| 原理和工作流程 | JDK7 用 16 个 Segment 分段锁每段独立 HashMap 并发度 16 get 无锁靠 volatile。JDK8 废弃 Segment 改 CAS 加 synchronized 锁桶头节点并发度等于桶数。putVal 空桶 CAS 插入，MOVED 协助扩容，链表与树 synchronized 桶头。渐进式扩容用 ForwardingNode 标记迁移桶其他线程协助。get 无锁因 val 与 next volatile。size 用 baseCount 加 CounterCell 分段计数 |
| 缺点 | 不允许 null；size 弱一致性；实现复杂难掌握 |

### 5. ArrayList 和 LinkedList 的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查两者数据结构与性能差异及选型 |
| 能做什么 | 对比底层数据结构；对比随机访问与增删性能；对比内存与缓存；给出选型 |
| 怎么用 | 随机访问与尾追加用 ArrayList，头尾增删用 LinkedList |
| 原理和工作流程 | ArrayList 底层 Object[] 随机访问 O(1) 头部增删 O(n) 尾插均摊 O(1)，1.5 倍扩容，连续内存缓存友好内存紧凑。LinkedList 底层双向链表增删 O(1) 随机访问 O(n)，每节点额外 prev 与 next 指针内存大节点分散缓存不友好。决策频繁随机访问与尾追加用 ArrayList，头部增删用 LinkedList，栈队列优先 ArrayDeque |
| 缺点 | ArrayList 中间增删慢；LinkedList 随机访问慢内存大；LinkedList 缓存不友好实际常慢于预期 |

### 6. fail-fast 和 fail-safe 是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查两种迭代修改检测机制的原理与区别 |
| 能做什么 | 解释 fail-fast modCount 检测；解释 fail-safe 快照复制；说明弱一致性 |
| 怎么用 | 迭代删除用 iterator.remove，并发用 CopyOnWrite |
| 原理和工作流程 | fail-fast 集合如 ArrayList 维护 modCount 迭代器遍历前比对 expectedModCount 不一致抛 ConcurrentModificationException 仅检测非保证安全。fail-safe 集合如 CopyOnWriteArrayList 迭代时复制快照遍历不抛异常但弱一致性读旧值。ConcurrentHashMap 迭代弱一致性不抛异常 |
| 缺点 | fail-fast 仅提示非保证安全；fail-safe 弱一致性读旧值；CopyOnWrite 写复制内存大 |
