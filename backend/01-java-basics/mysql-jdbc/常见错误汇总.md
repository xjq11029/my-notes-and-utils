# mysql-jdbc - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南章节提取。

---

## 来自 01-MySQL基础与SQL核心

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| UPDATE/DELETE 不带 WHERE 导致全表数据被修改/删除 | 忘记加条件或先执行了语句 | 执行前用 SELECT 验证条件；开启安全模式 `SET sql_safe_updates=1` | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| VARCHAR 长度设置过大导致创建表失败或行数据超限 | MySQL 单行最大 65535 字节，多个 VARCHAR 累加超限 | 评估实际需求；超长文本用 TEXT 类型 | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| 金额使用 FLOAT/DOUBLE 导致计算结果出现精度误差 | 浮点数采用二进制存储，无法精确表示十进制小数 | 金额使用 `DECIMAL(10,2)`，应用层使用 BigDecimal | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| DATETIME 与 TIMESTAMP 混用导致跨时区显示异常或 2038 年溢出 | TIMESTAMP 自动转时区且范围仅到 2038 | 业务时间用 DATETIME；自动记录时间可用 TIMESTAMP | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| 分页深翻页慢，`LIMIT 1000000,10` 查询耗时数秒 | 扫描并丢弃前 100 万行后才取 10 行 | 子查询先定位主键再 JOIN；或用游标分页（记录上一页最大 id） | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| GROUP BY 后直接 SELECT 非聚合列导致结果不确定或报错 | SQL 模式 `ONLY_FULL_GROUP_BY` 禁止非聚合列随意出现 | SELECT 只包含分组列或聚合列；或调整业务逻辑 | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| 隐式类型转换导致索引失效，字符串列与数字比较时全表扫描 | MySQL 对列做类型转换使索引失效 | 比较值与列类型一致：`WHERE phone = '13800000001'` | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |
| 索引列上使用函数导致索引失效 | 函数破坏索引有序性 | 把函数移到值一侧：`WHERE created_at >= '2025-01-01'` | [01-MySQL基础与SQL核心-导览](./01-MySQL基础与SQL核心-导览.md) |

## 来自 02-JDBC核心原理

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 资源未关闭导致连接泄漏，连接池耗尽 | ResultSet/Statement/Connection 未在 finally 关闭 | 使用 try-with-resources 自动关闭；按 rs -> ps -> conn 逆序关闭 | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| Statement 拼接 SQL 导致 SQL 注入漏洞 | 用户输入直接拼入 SQL 字符串 | 全部使用 PreparedStatement + `?` 占位 + setXxx 设值 | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| 事务未提交/回滚导致数据不一致或脏数据残留 | 异常时未 rollback，或 autoCommit 仍为 true | try-catch-finally 模式，异常时 rollback，finally 中恢复 autoCommit 并关闭 | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| 连接池 maxLifetime 过大导致连接被数据库单方面断开 | maxLifetime 大于数据库 `wait_timeout`，连接失效仍在用 | maxLifetime 设置为 `wait_timeout` 的 60%~80%，如 30min | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| 获取连接超时导致请求堆积、接口超时 | 最大连接数过小或慢 SQL 长期占用连接 | 调大 maximumPoolSize；排查慢 SQL；设置合理 connectionTimeout | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| 批量插入逐条执行导致插入万条数据耗时数分钟 | 每次 executeUpdate 都一次网络往返 | 使用 `addBatch` + `executeBatch`；开启 `rewriteBatchedStatements=true` | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| ResultSet 使用后关闭报错 `Operation not allowed after ResultSet closed` | 同一 Statement 执行新查询后旧 ResultSet 自动关闭 | 先读取完旧 ResultSet 数据再执行新查询；使用不同 Statement | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
| 日期类型精度丢失，时间字段时分秒为 00:00:00 | 用 `rs.getDate()` 只取日期部分 | 使用 `rs.getTimestamp()` 获取完整时间 | [02-JDBC核心原理-导览](./02-JDBC核心原理-导览.md) |
