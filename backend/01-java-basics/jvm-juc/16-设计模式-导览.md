## 一、核心概念

### 1.1 什么是设计模式

| 维度 | 内容 |
|------|------|
| 是什么 | 在特定场景下可复用的面向对象设计经验总结，分创建型、结构型、行为型三大类 |
| 能做什么 | 提供通用解决方案；统一沟通词汇；提升代码可维护性与扩展性；沉淀前人经验 |
| 怎么用 | 识别场景套用模式；遵循开闭原则；不过度设计 |
| 原理和工作流程 | 设计模式是前人对面向对象设计的经验抽象，GOF 总结 23 种经典模式，按职责分创建型关注对象创建如单例工厂、结构型关注类与对象组合如代理装饰、行为型关注对象交互如策略模板。模式是经验模板需结合场景灵活运用而非生搬硬套，核心是遵循单一职责、开闭等设计原则 |
| 缺点 | 过度设计增加复杂度；模式有适用边界误用反成负担；学习曲线陡；初学者易滥用 |

### 1.2 为什么面试必考设计模式

| 维度 | 内容 |
|------|------|
| 是什么 | 设计模式作为衡量工程师设计能力与工程素养的考查维度 |
| 能做什么 | 考查设计能力；考查源码理解；考查工程经验；统一技术语言 |
| 怎么用 | 结合项目场景说明模式选型与权衡 |
| 原理和工作流程 | 设计模式体现对面向对象原则的理解与抽象能力，是区分初级与高级工程师的标尺。框架源码如 Spring 大量使用设计模式，理解模式才能读懂源码。面试常考单例、工厂、策略、代理、模板方法等高频模式，结合场景说明选型与权衡展示工程经验 |
| 缺点 | 仅背概念不理解易被追问穿；脱离场景谈模式空洞；面试与实际能力可能脱节 |

## 二、五种核心设计模式

### 2.1 单例模式（Singleton）

| 维度 | 内容 |
|------|------|
| 是什么 | 确保一个类只有一个实例并提供全局访问点的创建型模式 |
| 能做什么 | 五种实现饿汉、懒汉、DCL、静态内部类、枚举；防反射防序列化破坏；Spring Bean 默认单例 |
| 怎么用 | 推荐 `private static volatile` DCL 或静态内部类或枚举 |
| 原理和工作流程 | 五种实现：饿汉式类加载即创建线程安全非懒加载；懒汉式 synchronized 懒加载但性能差；DCL 双重检查 volatile 防指令重排懒加载高性能；静态内部类利用类加载机制懒加载天然线程安全；枚举天然单例防反射防序列化最佳。DCL 需 volatile 因 new 分配内存、初始化、赋引用三步可能重排致其他线程获未初始化对象。Spring 单例通过 ConcurrentHashMap 缓存 Bean |
| 缺点 | 饿汉式非懒加载；懒汉式性能差；DCL 需 volatile；全局状态不利测试与扩展 |

### 2.2 工厂模式（Factory）

| 维度 | 内容 |
|------|------|
| 是什么 | 将对象创建逻辑封装到工厂类的创建型模式，分简单工厂、工厂方法、抽象工厂 |
| 能做什么 | 简单工厂按参数创建；工厂方法延迟到子类；抽象工厂创建产品族；解耦创建与使用 |
| 怎么用 | `AnimalFactory.create("dog")` 或 `new DogFactory().create()` |
| 原理和工作流程 | 简单工厂一个工厂类按参数 switch 创建不同产品违反开闭原则新增产品需改工厂。工厂方法每产品一工厂子类符合开闭原则新增产品加工厂即可。抽象工厂创建一系列相关产品族支持产品等级与产品族。Spring 的 BeanFactory 是 IoC 顶层接口定义 getBean 工厂方法，FactoryBean 允许自定义创建逻辑 |
| 缺点 | 简单工厂违反开闭原则；工厂方法类爆炸；抽象工厂扩展产品等级困难；增加类层次 |

### 2.3 策略模式（Strategy）

| 维度 | 内容 |
|------|------|
| 是什么 | 定义一系列算法封装起来使它们可相互替换的行为型模式 |
| 能做什么 | 封装算法族；运行时切换策略；消除 if-else；结合工厂或注解自动选择 |
| 怎么用 | `new PaymentContext(new AliPayStrategy()).pay(amount)` |
| 原理和工作流程 | 定义策略接口，每算法一实现类，上下文持有策略引用委托执行。运行时按需注入不同策略切换算法，避免大量 if-else 分支。结合工厂或注解扫描可按参数自动选择策略。Spring 中 Resource 接口不同实现、InstantiationStrategy 实例化策略、AuthenticationProvider 认证策略均此模式 |
| 缺点 | 策略类增多；客户端需了解策略差异；上下文与策略耦合；简单场景过度设计 |

### 2.4 代理模式（Proxy）

| 维度 | 内容 |
|------|------|
| 是什么 | 为其他对象提供代理以控制访问的结构型模式，分静态代理与动态代理 |
| 能做什么 | 静态代理手动编写；JDK 动态代理基于接口；CGLIB 基于继承；AOP 基础 |
| 怎么用 | `Proxy.newProxyInstance(loader, interfaces, handler)` |
| 原理和工作流程 | 静态代理编译期手写代理类实现相同接口。JDK 动态代理运行时 Proxy.newProxyInstance 生成实现接口的代理类方法转发 InvocationHandler.invoke 只能代理接口。CGLIB 运行时 Enhancer 生成子类 MethodInterceptor 拦截非 final 方法不要求接口。Spring AOP 默认有接口用 JDK 无接口用 CGLIB，SpringBoot2.x 默认 CGLIB。@Transactional、@Async 经代理实现 |
| 缺点 | 静态代理类爆炸；JDK 只代理接口；CGLIB 不能代理 final；代理有性能开销；自调用不走代理 |

### 2.5 模板方法模式（Template Method）

| 维度 | 内容 |
|------|------|
| 是什么 | 定义算法骨架将某些步骤延迟到子类实现的行为型模式 |
| 能做什么 | 父类定骨架 final 方法；子类实现具体步骤；复用骨架代码；统一流程 |
| 怎么用 | `abstract class DataProcessor { final void process(){read();transform();write();} }` |
| 原理和工作流程 | 父类用 final 模板方法定义算法骨架调用抽象方法，子类重写抽象方法实现具体步骤不变骨架。骨架稳定步骤可变，复用公共流程只扩展变化点。Spring 的 JdbcTemplate 封装获取连接、Statement、结果集、释放资源模板，RestTemplate、TransactionTemplate、AbstractApplicationContext.refresh 均此模式 |
| 缺点 | 继承而非组合耦合较强；子类受限；骨架修改影响所有子类；与策略模式需权衡 |

## 三、设计模式在 Spring 中的全景应用

| 维度 | 内容 |
|------|------|
| 是什么 | Spring 框架对各类设计模式的综合应用全景 |
| 能做什么 | 单例管理 Bean；工厂创建 Bean；代理实现 AOP；模板方法封装流程；策略选择实现 |
| 怎么用 | 理解模式才能读懂 Spring 源码 |
| 原理和工作流程 | Spring 综合应用多种模式：单例模式 Bean 默认 singleton 作用域用 ConcurrentHashMap 缓存。工厂模式 BeanFactory 与 FactoryBean 管理创建。代理模式 AOP 用 JDK 或 CGLIB 代理实现 @Transactional 等增强。模板方法 JdbcTemplate 等封装固定流程。策略模式 Resource 与 InstantiationStrategy 按场景选择。观察者模式 ApplicationEvent 事件机制。责任链模式 HandlerInterceptor 拦截器链 |
| 缺点 | 模式交织增加源码理解难度；框架封装过度致调试难；需扎实模式基础才能深入 |

## 四、常见面试题

### 1. 单例模式的双重检查锁定为什么需要 volatile？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 DCL 单例需 volatile 的指令重排原因 |
| 能做什么 | 解释 new 三步；解释重排致半初始化；解释 volatile 禁止重排 |
| 怎么用 | `private static volatile Singleton instance;` |
| 原理和工作流程 | new Singleton() 非原子分三步：分配内存、初始化对象、将引用指向内存。无 volatile 时 JVM 可能重排为分配内存、赋引用、初始化，其他线程在第一次检查 instance 非 null 时获未初始化对象致 NPE 或错误。volatile 通过内存屏障禁止指令重排保证对象完整构造后才对其他线程可见 |
| 缺点 | volatile 有微量性能开销；DCL 实现复杂；静态内部类与枚举更简洁 |

### 2. 工厂方法和抽象工厂的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查工厂方法与抽象工厂的结构与适用差异 |
| 能做什么 | 区分产品等级与产品族；区分扩展方式；给出选型 |
| 怎么用 | 单产品用工厂方法，产品族用抽象工厂 |
| 原理和工作流程 | 工厂方法针对单一产品等级，每产品一工厂子类符合开闭原则新增产品加工厂即可。抽象工厂针对多个产品等级与产品族，一个工厂创建一系列相关产品。区别：工厂方法创建单一产品扩展产品等级容易，抽象工厂创建产品族扩展产品族容易但扩展新产品等级需改所有工厂违反开闭原则 |
| 缺点 | 抽象工厂扩展产品等级困难；工厂方法类多；各有适用边界 |

### 3. Spring AOP 使用 JDK 动态代理还是 CGLIB？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Spring AOP 代理选择策略 |
| 能做什么 | 说明默认策略；说明 SpringBoot 默认；说明选择依据 |
| 怎么用 | 有接口用 JDK，无接口用 CGLIB，SpringBoot 默认 CGLIB |
| 原理和工作流程 | Spring AOP 代理选择：目标类实现接口默认用 JDK 动态代理生成接口代理类，无接口用 CGLIB 生成子类代理。可通过 proxy-target-class=true 强制 CGLIB。SpringBoot 2.x 起默认 CGLIB 设 proxy-target-class=true。JDK 代理只能代理接口方法，CGLIB 不能代理 final 类与方法。@Transactional、@Async、@Cacheable 经代理实现 |
| 缺点 | JDK 只代理接口；CGLIB 不能代理 final；自调用不走代理；选型影响行为 |

### 4. 策略模式如何消除 if-else？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查策略模式消除分支的机制 |
| 能做什么 | 封装每分支为策略；运行时注入切换；结合工厂或 Map 自动选择 |
| 怎么用 | `Map<String,Strategy>` 按参数取策略执行 |
| 原理和工作流程 | 将每 if-else 分支封装为独立策略实现类，上下文持有策略引用委托执行。运行时按参数从 Map 或工厂选择对应策略注入，避免硬编码分支判断。结合 Spring 注解扫描将策略注册到 Map 按参数自动选择。新增策略只需加实现类注册无需改主流程符合开闭原则 |
| 缺点 | 策略类增多；需维护注册表；客户端需了解策略；简单分支过度设计 |

### 5. 模板方法模式和策略模式的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查两种行为型模式的结构与适用差异 |
| 能做什么 | 区分继承与组合；区分骨架与算法替换；给出选型 |
| 怎么用 | 流程固定步骤可变用模板方法，算法可替换用策略 |
| 原理和工作流程 | 模板方法用继承父类定义算法骨架 final 方法子类实现具体步骤，强调流程复用骨架稳定步骤可变，依赖继承耦合较强。策略模式用组合上下文持有策略引用运行时切换算法，强调算法可替换无骨架约束，依赖组合更灵活。选型：流程骨架固定步骤可变用模板方法，仅算法替换无固定流程用策略 |
| 缺点 | 模板方法继承耦合强；策略类多；各有适用场景；初学者易混 |
