# 日志整合与监控

> 学习路线对应：第2周 -- Spring Boot 框架
> 前置知识：Spring Boot 基础、Maven 依赖管理
> 预计学习时间：1-2 天

## 一、核心概念

### 1.1 日志框架演进

| 框架 | 全称 | 特点 | 现状 |
|------|------|------|------|
| **JUL** | java.util.logging | JDK 内置，功能简单 | 仅用于小型项目 |
| **Log4j** | Log for Java | Apache 开源，划时代产品 | 已停止维护 |
| **Logback** | Logback | Log4j 作者开发，性能更优 | Spring Boot 默认 |
| **Log4j2** | Log4j 2 | 重构版本，异步性能极致 | 高并发场景首选 |

```
演进路线：JUL -> Log4j -> Logback -> Log4j2
                        └──────────┘
                    (Logback 和 Log4j2 同为现代主流)
```

### 1.2 SLF4J 门面模式

SLF4J（Simple Logging Facade for Java）是日志门面，只定义接口不提供实现。底层可切换 Logback、Log4j2 等具体实现，解耦应用代码与日志框架。

```
应用代码 -> SLF4J（门面接口） -> 具体实现（Logback / Log4j2 / JUL）
```

**桥接器（Bridge）：** 当项目依赖了其他日志框架（如 commons-logging）时，桥接器将其日志调用转发到 SLF4J。

| 桥接器 | 作用 |
|--------|------|
| `jcl-over-slf4j` | 将 commons-logging 调用桥接到 SLF4J |
| `log4j-over-slf4j` | 将 Log4j 调用桥接到 SLF4J |
| `jul-to-slf4j` | 将 JUL 调用桥接到 SLF4J |

**注意：** 桥接器和适配器方向相反，不要同时引入 `xxx-over-slf4j` 和 `slf4j-xxx`，会造成死循环。

> **生活化类比：SLF4J 门面模式就像万能遥控器** —— 想象你家有电视、空调、音响三台设备（Logback、Log4j2、JUL 三种日志实现），每台设备自带一个专用遥控器（各自 API），你要分别学习三套操作方式。SLF4J 就像买了一个"万能遥控器"（日志门面接口），你的应用代码只需要学会操作万能遥控器（面向 SLF4J 接口编程），至于万能遥控器背后控制的是哪台设备（底层日志实现），由"配对码"（绑定包 slf4j-logback / slf4j-log4j12）决定。换设备时只需重新配对（更换绑定包），遥控器的操作方式不变（业务代码无需修改）。桥接器则像一个"信号转发器"——当老设备（commons-logging）发出红外信号时，转发器将其转为万能遥控器的信号格式，统一交给 SLF4J 处理。

> 📖 **参考链接**：
> - [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/docs/) -- Spring Boot 官方文档（日志系统整合、SLF4J 门面模式、Logback 配置）
> - [Spring Framework Reference](https://docs.spring.io/spring-framework/reference/) -- Spring 框架参考文档（日志抽象层与桥接机制）

### 1.3 Spring Boot 默认日志

Spring Boot 默认使用 **Logback + SLF4J**，开箱即用，无需额外配置即可输出日志。

```xml
<!-- spring-boot-starter 自带日志依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter</artifactId>
</dependency>
<!-- 内部已包含：logback-classic + slf4j-api + jul-to-slf4j + log4j-over-slf4j -->
```

**默认行为：**
- 日志级别：INFO
- 输出目标：控制台
- 日志格式：`时间 级别 PID 线程 类名 消息`

## 二、底层原理

### 2.1 Logback 架构

Logback 由三大核心组件构成：

| 组件 | 作用 | 类比 |
|------|------|------|
| **Logger** | 日志记录器，决定日志是否输出 | 门禁安检级别 |
| **Appender** | 日志输出目的地（控制台/文件） | 快递投递目的地 |
| **Layout/Encoder** | 日志格式化 | 快递包装方式 |

> Logger 的核心职责是根据日志级别决定是否放行，而非将日志分发到不同目的地（那是 Appender 的职责）。类比门禁安检：TRACE 级别最宽松（所有人可进），ERROR 级别最严格（只有紧急情况才放行）。

**Logger 层级关系：** Logger 按包名形成树形层级，子 Logger 继承父 Logger 的级别。根 Logger 名称为 ROOT。

```
ROOT (DEBUG)
  └── com.example (INFO)
        └── com.example.service (未设置，继承 INFO)
              └── com.example.service.UserService (未设置，继承 INFO)
```

### 2.2 日志级别

级别从低到高：`TRACE < DEBUG < INFO < WARN < ERROR < OFF`

```
设为 INFO 级别时：
  TRACE  -> 不输出
  DEBUG  -> 不输出
  INFO   -> 输出
  WARN   -> 输出
  ERROR  -> 输出
```

| 级别 | 用途 | 示例场景 |
|------|------|---------|
| TRACE | 最详细的跟踪信息 | 方法入参出参、SQL 参数 |
| DEBUG | 调试信息 | 关键变量值、流程分支 |
| INFO | 重要业务信息 | 用户登录、订单创建 |
| WARN | 警告信息 | 缓存命中率低、重试次数较多 |
| ERROR | 错误信息 | 异常捕获、接口调用失败 |

### 2.3 logback-spring.xml 配置详解

`logback-spring.xml`（Spring Boot 专属，支持 Profile）比 `logback.xml` 优先级更高。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 引入 Spring Boot 默认配置 -->
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

    <!-- 属性定义 -->
    <property name="LOG_PATH" value="logs"/>
    <property name="LOG_PATTERN"
              value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{50} - %msg%n"/>

    <!-- 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 滚动文件输出 -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH}/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${LOG_PATH}/app.%d{yyyy-MM-dd}.%i.log</fileNamePattern>
            <maxFileSize>100MB</maxFileSize>
            <maxHistory>30</maxHistory>
            <totalSizeCap>3GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>${LOG_PATTERN}</pattern>
        </encoder>
    </appender>

    <!-- 异步文件输出 -->
    <appender name="ASYNC_FILE" class="ch.qos.logback.classic.AsyncAppender">
        <queueSize>1024</queueSize>
        <discardingThreshold>0</discardingThreshold>
        <neverBlock>true</neverBlock>
        <appender-ref ref="FILE"/>
    </appender>

    <!-- 多环境配置 -->
    <springProfile name="dev">
        <root level="DEBUG">
            <appender-ref ref="CONSOLE"/>
        </root>
    </springProfile>

    <springProfile name="prod">
        <logger name="com.example" level="INFO"/>
        <root level="WARN">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="ASYNC_FILE"/>
        </root>
    </springProfile>
</configuration>
```

**pattern 常用占位符：**

| 占位符 | 含义 |
|--------|------|
| `%d` | 时间（`%d{yyyy-MM-dd HH:mm:ss}`） |
| `%thread` | 线程名 |
| `%-5level` | 日志级别（左对齐 5 字符） |
| `%logger{50}` | Logger 名（最大 50 字符） |
| `%msg` | 日志消息 |
| `%n` | 换行 |
| `%pid` | 进程 ID |

### 2.4 异步日志

**Logback AsyncAppender：** 基于阻塞队列（ArrayBlockingQueue）实现，日志写入队列后立即返回，后台线程从队列取出写入文件。

```
应用线程 -> 写入 BlockingQueue（队列满则丢弃或阻塞）-> 后台线程 -> 写入文件
```

**Log4j2 AsyncLogger：** 基于 Disruptor 无锁环形队列，性能远超 Logback 异步方案。

| 方案 | 队列类型 | 吞吐量 | 延迟 |
|------|---------|--------|------|
| Logback AsyncAppender | ArrayBlockingQueue（有锁） | 中 | 中 |
| Log4j2 AsyncAppender | ArrayBlockingQueue（有锁） | 中 | 中 |
| Log4j2 AsyncLogger | Disruptor（无锁） | 极高 | 极低 |

> **生活化类比：异步日志就像寄快递 vs 亲自送货** —— 同步日志就像亲自送货：你（业务线程）要把一件货物（日志消息）送到目的地（日志文件），必须亲自跑一趟，等对方签收后才返回继续工作——如果目的地很远（磁盘 I/O 慢），你的工作时间被大量浪费在送货路上。异步日志就像寄快递：你只需把包裹（日志消息）丢到快递柜（BlockingQueue 队列）就立刻返回继续工作，快递员（后台线程）会在有空时取走包裹统一投递。Logback 的 AsyncAppender 就像一个有锁的快递柜（ArrayBlockingQueue），多人同时投递时需要排队拿钥匙（锁竞争）；Log4j2 的 AsyncLogger 基于 Disruptor，就像一排无锁智能快递柜（无锁环形队列），每个人可以直接找到空格子投递无需等待，吞吐量大幅提升。队列满时相当于快递柜爆仓——要么拒绝投递（丢弃日志），要么等快递员清空柜子（阻塞等待）。

> 📖 **参考链接**：
> - [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/docs/) -- Spring Boot 官方文档（异步日志配置、Logback AsyncAppender、Log4j2 切换）
> - [Spring Framework Reference](https://docs.spring.io/spring-framework/reference/) -- Spring 框架参考文档（Micrometer 指标采集与 Actuator 监控集成）

### 2.5 日志框架切换（Logback 切换为 Log4j2）

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
    <exclusions>
        <!-- 排除 Logback -->
        <exclusion>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-logging</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<!-- 引入 Log4j2 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-log4j2</artifactId>
</dependency>
```

切换后使用 `log4j2-spring.xml` 替代 `logback-spring.xml`。

### 2.6 Actuator 监控

Spring Boot Actuator 提供生产级监控端点，开箱即用。

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

**常用端点：**

| 端点 | 路径 | 作用 |
|------|------|------|
| health | `/actuator/health` | 健康检查（数据库、磁盘、Redis 等） |
| info | `/actuator/info` | 应用基本信息 |
| metrics | `/actuator/metrics` | 指标数据（内存、线程、GC 等） |
| env | `/actuator/env` | 环境变量和配置属性 |
| beans | `/actuator/beans` | 所有 Bean 列表 |
| loggers | `/actuator/loggers` | 日志级别动态调整 |
| threaddump | `/actuator/threaddump` | 线程转储 |
| heapdump | `/actuator/heapdump` | 堆转储（下载 .hprof 文件） |

```yaml
# 暴露所有端点（生产环境按需开放）
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  endpoint:
    health:
      show-details: always  # 显示健康检查详情
```

**健康检查（HealthIndicator）：** Spring Boot 内置多种健康检查器，自动检测数据库、Redis、磁盘等组件状态。

**自定义端点：**

```java
@Endpoint(id = "custom")
@Component
public class CustomEndpoint {

    @ReadOperation
    public Map<String, Object> customInfo() {
        Map<String, Object> info = new HashMap<>();
        info.put("status", "running");
        info.put("uptime", ManagementFactory.getRuntimeMXBean().getUptime());
        return info;
    }
}
// 访问 /actuator/custom 即可获取信息
```

### 3.2 Prometheus 指标暴露配置

```xml
<!-- 引入 Micrometer Prometheus 依赖 -->

    <groupId>io.micrometer</groupId>
```


```java
// 自定义业务指标
@Service
public class OrderService {

    private final Counter orderCounter;
    private final Timer orderTimer;

    public OrderService(MeterRegistry meterRegistry) {
        this.orderCounter = Counter.builder("order.created.total")
                .description("订单创建总数")
                .tag("type", "normal")
                .register(meterRegistry);
        this.orderTimer = Timer.builder("order.create.duration")
                .description("订单创建耗时")
                .register(meterRegistry);
    }

    public void createOrder() {
        orderTimer.record(() -> {
            // 业务逻辑
            orderCounter.increment();
        });
    }
}
```

### 3.3 日志最佳实践

```java
@Service
@Slf4j
public class UserService {

    // 1. 使用参数化日志（占位符），避免字符串拼接开销
    public void login(String username) {
        // 正确：SLF4J 会判断级别后再拼接
        log.info("用户 {} 登录成功", username);
        // 错误：字符串拼接先执行，级别不匹配时浪费性能
        // log.info("用户 " + username + " 登录成功");
    }

    // 2. 使用占位符的同时记录异常（异常对象作为最后一个参数）
    public void readFile(String path) {
        try {
            // 读取文件
        } catch (IOException e) {
            log.error("读取文件失败，路径：{}", path, e);
        }
    }

    // 3. DEBUG 级别日志使用 isDebugEnabled 守卫（仅当日志拼接复杂时）
    public void process(List<String> items) {
        if (log.isDebugEnabled()) {
            log.debug("处理 {} 个项目，详情：{}", items.size(), items);
        }
    }
}
```

## 四、常见面试题（附答案）

### 1. SLF4J 和 Logback 的关系是什么？

SLF4J 是日志门面（接口），Logback 是日志实现。应用代码面向 SLF4J 接口编程，底层可以灵活切换为 Logback、Log4j2 等实现，而无需修改业务代码。这种设计是门面模式（Facade Pattern）的典型应用。

### 2. 日志级别有哪些？如何选择？

从低到高为 TRACE、DEBUG、INFO、WARN、ERROR、OFF。生产环境通常使用 INFO，开发环境使用 DEBUG。TRACE 用于极详细的跟踪信息，ERROR 用于记录异常但不应输出过多（避免日志淹没关键信息）。

### 3. 如何动态调整日志级别？

通过 Actuator 的 loggers 端点动态调整，无需重启应用：

```
POST /actuator/loggers/com.example.service
Content-Type: application/json

{"configuredLevel": "DEBUG"}
```

也可通过 `logging.level.com.example=DEBUG` 在配置文件中设置。

### 4. Logback 和 Log4j2 的异步日志有什么区别？

Logback 的 AsyncAppender 基于 ArrayBlockingQueue（有锁队列），在高并发下存在锁竞争。Log4j2 的 AsyncLogger 基于 Disruptor 无锁环形队列，吞吐量可达 Logback 的数倍，延迟更低。高并发场景推荐 Log4j2。

### 5. Spring Boot Actuator 的作用是什么？

Actuator 提供生产级监控能力，包括健康检查、指标采集、环境信息、线程转储等。通过 HTTP 端点暴露运行时状态，便于运维监控和问题排查。结合 Prometheus + Grafana 可实现完整的监控告警体系。

## 五、避坑指南

| 常见错误 | 现象 | 原因 | 解决方案 |
|---------|------|------|---------|
| 日志字符串拼接 | 性能下降 | 级别不匹配时仍执行字符串拼接 | 使用参数化日志 `log.info("msg {}", arg)` |
| 桥接器与适配器共存 | 应用启动死循环 | `log4j-over-slf4j` 和 `slf4j-log4j` 同时存在 | 只保留桥接器，排除适配器 |
| 异步日志队列满 | 日志丢失 | AsyncAppender 默认队列满后丢弃 | 调大 `queueSize`；设 `neverBlock=true` 明确丢弃策略 |
| 日志文件无限增长 | 磁盘写满 | 未配置滚动策略 | 使用 RollingFileAppender，设 `maxHistory` 和 `totalSizeCap` |
| 敏感信息泄露 | 密码/Token 出现在日志 | 直接打印完整请求/响应 | 日志脱敏处理；使用 `@ToString(exclude=...)` 排除敏感字段 |
| Actuator 端点暴露过多 | 安全风险 | `include=*` 暴露所有端点 | 生产环境只暴露 `health,info,prometheus`；配合 Spring Security 鉴权 |
