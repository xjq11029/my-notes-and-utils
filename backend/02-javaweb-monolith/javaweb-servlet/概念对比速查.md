# JavaWeb Servlet - 概念对比速查

---

### Servlet vs JSP

| 对比维度 | Servlet | JSP |
|---------|---------|-----|
| 核心定位 | Java 类，用于处理请求和生成响应，适合编写业务逻辑和控制流程 | 基于 HTML 的模板页面，适合编写视图展示层，内嵌 Java 代码 |
| 编写方式 | 纯 Java 代码，通过 PrintWriter 输出 HTML | HTML 中嵌入 Java 代码（脚本表达式、脚本片段、声明），最终编译为 Servlet |
| 可读性 | HTML 与 Java 混写，大量 out.println() 可读性差 | 以 HTML 为主体，少量 Java 代码，视图层可读性好 |
| 性能 | 直接编译为 class，无转换开销 | 首次访问需编译为 Servlet（JSP -> Servlet -> class），后续访问与 Servlet 相同 |
| 适用场景 | 控制器（Controller）、业务逻辑处理、REST 接口 | 视图层（View）、动态页面生成、报表展示 |
| 选择建议 | MVC 模式中 Controller 层使用 Servlet；纯 API 接口使用 Servlet | MVC 模式中 View 层使用 JSP；需要频繁修改页面布局时使用 JSP |

### forward vs redirect

| 对比维度 | forward（转发） | redirect（重定向） |
|---------|---------------|-------------------|
| 核心定位 | 服务器内部跳转，将请求转发给另一个资源处理 | 客户端跳转，服务器通知浏览器重新请求新地址 |
| 请求次数 | 1 次请求 | 2 次请求（第一次返回 302，第二次请求新地址） |
| 地址栏变化 | 不变，浏览器地址保持原 URL | 变化，浏览器地址变为新 URL |
| 数据传递 | 共享同一个 request 对象，可传递 request 属性 | 无法直接传递 request 属性，需通过 URL 参数或 Session |
| 路径解析 | 以 "/" 开头相对于 Web 应用根目录 | 以 "/" 开头相对于服务器根目录（需加 contextPath） |
| 速度 | 更快，仅服务器内部跳转 | 较慢，多一次网络往返 |
| 跨域 | 不能跨域，仅限同一 Web 应用内 | 可以跨域，可重定向到任意 URL |
| 适用场景 | 内部页面跳转、请求分发、MVC 中 Controller 到 View | 登录后跳转、防止表单重复提交（PRG 模式）、跨应用跳转 |
| 选择建议 | 同一应用内需要传递数据时使用 forward | 需要改变浏览器地址、跨域跳转、防止表单重复提交时使用 redirect |

### Cookie vs Session

| 对比维度 | Cookie | Session |
|---------|--------|---------|
| 核心定位 | 客户端存储技术，数据保存在浏览器 | 服务器端存储技术，数据保存在服务器 |
| 存储位置 | 浏览器本地 | 服务器内存/Redis/数据库 |
| 安全性 | 较低，明文存储在客户端，可被篡改和窃取 | 较高，数据在服务器端，客户端仅持有 Session ID |
| 容量限制 | 单个 Cookie 最大 4KB，每个域名最多 20-50 个 | 无明确限制，取决于服务器内存和存储方案 |
| 有效时间 | 可设置过期时间（maxAge），关闭浏览器后仍可保留 | 默认会话结束即失效，可配置超时时间 |
| 性能影响 | 每次请求携带 Cookie，增加网络传输量 | 需要服务器存储和查找 Session，增加服务器开销 |
| 跨域支持 | 不可跨域，受 Domain 和 Path 限制 | 通过 Session 共享（如 Redis）可实现跨域 |
| 禁用影响 | 用户可禁用 Cookie | 依赖 Cookie 传递 JSESSIONID，Cookie 禁用后需 URL 重写 |
| 选择建议 | 存储非敏感、小容量、需持久化的数据（如用户偏好、浏览记录） | 存储敏感数据、登录状态、大容量临时数据 |

### GET vs POST

| 对比维度 | GET | POST |
|---------|-----|------|
| 核心定位 | 从服务器获取资源，查询操作 | 向服务器提交数据，创建/修改操作 |
| 参数位置 | URL 查询字符串中 | 请求体（Body）中 |
| 参数长度 | 受 URL 长度限制（浏览器通常 2KB-8KB，服务器 8KB） | 无明确限制，取决于服务器配置 |
| 安全性 | 参数暴露在 URL 中，浏览器历史、日志中可见 | 参数在请求体中，URL 不可见，相对安全 |
| 缓存 | 可被浏览器缓存、CDN 缓存、代理缓存 | 默认不被缓存 |
| 书签 | 可收藏为书签 | 不可收藏 |
| 幂等性 | 幂等，多次请求结果相同 | 非幂等，多次请求可能产生不同结果 |
| 编码 | 仅支持 ASCII，中文需 URL 编码 | 支持多种编码，通过 Content-Type 指定 |
| 适用场景 | 查询、搜索、分页、数据获取 | 表单提交、登录、文件上传、数据修改 |
| 选择建议 | 数据获取类操作一律使用 GET | 数据提交、敏感信息、大容量数据使用 POST |

### Filter vs Interceptor

| 对比维度 | Filter（过滤器） | Interceptor（拦截器） |
|---------|-----------------|---------------------|
| 核心定位 | Servlet 规范定义的组件，对请求和响应进行预处理和后处理 | Spring 框架提供的组件，在 Handler 执行前后进行拦截 |
| 所属规范 | Servlet 规范（javax.servlet / jakarta.servlet） | Spring 框架（org.springframework.web.servlet） |
| 依赖容器 | 依赖 Servlet 容器（Tomcat） | 依赖 Spring 容器（IoC） |
| 拦截范围 | 所有进入 Servlet 容器的请求，包括静态资源 | 仅拦截进入 Spring MVC DispatcherServlet 的请求 |
| 可访问资源 | 只能访问 request 和 response | 可访问 Handler（Controller 方法）、参数、返回值、Spring Bean |
| 执行顺序控制 | @WebFilter 注解无法控制顺序，需 FilterRegistrationBean | 可通过 @Order 注解或实现 Ordered 接口控制顺序 |
| 生命周期方法 | init()、doFilter()、destroy() | preHandle()、postHandle()、afterCompletion() |
| 适用场景 | 编码设置、跨域处理、安全过滤、请求日志、XSS 过滤 | 权限校验、日志记录、性能监控、参数预处理、返回值处理 |
| 选择建议 | 需要拦截所有请求（包括静态资源）或依赖 Servlet 容器时使用 Filter | 需要访问 Spring 上下文、Controller 方法信息或只拦截业务请求时使用 Interceptor |
