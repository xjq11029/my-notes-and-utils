## 一、核心概念

### 1.1 Linux 发行版简介

| 维度 | 内容 |
|------|------|
| 是什么 | 基于Linux内核由不同厂商或社区打包而成的完整操作系统套件 |
| 能做什么 | 提供包管理、桌面环境、默认软件栈；适配服务器、桌面、容器、嵌入式等多种场景 |
| 怎么用 | `apt install nginx`（Debian系）；`yum install nginx`（RHEL系）；`apk add nginx`（Alpine） |
| 原理和工作流程 | 各发行版共享同一Linux内核，差异在用户态工具链与包管理器。包管理器维护本地软件数据库与依赖关系图，从配置的远程仓库拉取RPM或DEB包，校验签名后解包安装并执行脚本。滚动发行版如Arch持续推送新版，稳定发行版如CentOS冻结版本只回溯安全补丁 |
| 缺点 | 发行版碎片化导致命令与路径不统一，跨发行版脚本需做适配；部分发行版生命周期短，生产环境选型需评估长期支持周期 |

### 1.2 FHS 文件系统层次结构标准

| 维度 | 内容 |
|------|------|
| 是什么 | 规定Linux各目录用途与层级布局的规范，使软件与用户能在不同发行版间找到固定位置 |
| 能做什么 | 区分可执行命令、配置文件、可变数据、设备文件；统一`/etc`存配置、`/var`存日志、`/usr`存应用 |
| 怎么用 | `ls /etc/nginx/nginx.conf`；`cat /var/log/messages`；`cat /proc/cpuinfo` |
| 原理和工作流程 | FHS按职责划分目录：`/bin`、`/sbin`存放系统级命令，`/usr`存放用户级应用，`/var`存放运行时可变数据，`/proc`与`/sys`是内核暴露的虚拟文件系统。根目录下每个顶级目录承担固定角色，软件安装时按规范将文件分散到对应目录避免混乱 |
| 缺点 | 规范为推荐性而非强制，部分发行版存在`/bin`与`/usr/bin`合并等差异；新手需记忆目录含义，学习曲线略陡 |

### 1.3 文件与目录操作核心命令

| 维度 | 内容 |
|------|------|
| 是什么 | Linux下对文件与目录执行增删改查的基础命令集合 |
| 能做什么 | 列出目录内容；切换工作目录；创建删除移动复制；按名称类型大小查找文件；打包压缩解压 |
| 怎么用 | `ls -alh`；`mkdir -p project/{src,bin}`；`find /var/log -name "*.log"`；`tar -czf archive.tar.gz project/` |
| 原理和工作流程 | 这些命令通过系统调用操作文件系统。`ls`调用`getdents`读取目录项，`find`遍历目录树并按表达式过滤，`tar`将多个文件按tar格式归档再交给gzip压缩。`-r`参数递归的本质是命令内部对子目录重复调用相同操作 |
| 缺点 | `rm -rf`误删不可恢复；`find`全盘扫描大目录耗时；`tar`参数顺序敏感，`-f`必须最后跟文件名 |

### 1.4 管道与重定向

| 维度 | 内容 |
|------|------|
| 是什么 | 将命令的标准输入输出错误流连接或改写到文件与设备的机制 |
| 能做什么 | 用`|`串联多个命令形成处理流水线；用`>`、`>>`、`<`、`2>`在文件与命令间流转数据；用`/dev/null`丢弃输出 |
| 怎么用 | `cat access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head -10`；`./script.sh > out.log 2>&1` |
| 原理和工作流程 | 每个进程默认打开0(stdin)、1(stdout)、2(stderr)三个文件描述符。重定向由Shell在`fork`后`exec`前用`dup2`系统调用把描述符指向目标文件。管道由Shell创建一个内核环形缓冲区，把前一个进程的stdout接到后一个进程的stdin，两个进程并发执行 |
| 缺点 | 匿名管道只能单向传输且仅限有亲缘关系的进程；管道缓冲区满时写进程阻塞，可能造成流水线某环节卡死；错误流默认不进管道易被忽略 |

### 1.5 文本处理三剑客

| 维度 | 内容 |
|------|------|
| 是什么 | grep、sed、awk三个文本处理工具的统称，分别负责搜索、编辑、字段计算 |
| 能做什么 | grep按模式过滤匹配行；sed做行级替换删除插入；awk按字段切分并支持统计与编程逻辑 |
| 怎么用 | `grep -irn "TODO" src/`；`sed -i 's/foo/bar/g' file.txt`；`awk -F: '{print $1":"$3}' /etc/passwd` |
| 原理和工作流程 | grep逐行读取输入并用正则引擎匹配，命中则输出该行。sed是流编辑器，按行读入模式空间执行编辑命令后输出。awk也逐行处理，自动按分隔符切分为字段，对每行执行`BEGIN`、主体、`END`三个阶段的脚本 |
| 缺点 | sed正则语法在不同平台有GNU与BSD差异，`-i`参数行为不一致；awk处理超大文件性能不如专用工具；三者组合虽灵活但可读性差，复杂逻辑应改用脚本语言 |

### 1.6 Shell 脚本基础

| 维度 | 内容 |
|------|------|
| 是什么 | 用Shell解释器编写的脚本语言，整合变量、条件、循环、函数完成自动化任务 |
| 能做什么 | 定义变量与环境变量；用`if`、`case`分支判断；用`for`、`while`循环遍历；封装函数复用逻辑；通过`$?`判断命令成败 |
| 怎么用 | `#!/bin/bash`；`NAME="Alice"`；`if [ -f file ]; then ...; fi`；`for i in 1 2 3; do echo $i; done` |
| 原理和工作流程 | Shell解释器逐行读取脚本，经过分词、变量与命令替换、通配符展开、重定向处理后，调用`execve`执行外部命令或直接执行内置命令。退出码通过`$?`传递，0为成功。函数在当前Shell环境执行不产生子进程，通过位置参数传参 |
| 缺点 | 语法对空格极度敏感，`[$x]`报错；缺少数据结构，复杂逻辑难维护；错误处理弱，`set -e`前默认忽略失败；跨平台`sh`与`bash`语法不完全兼容 |

## 二、底层原理

### 2.1 Linux 文件系统原理

| 维度 | 内容 |
|------|------|
| 是什么 | Linux以"一切皆文件"抽象管理所有资源，并通过inode与block组织存储的机制 |
| 能做什么 | 将设备、管道、套接字统一为文件接口；用硬链接共享inode；用软链接跨文件系统引用路径 |
| 怎么用 | `ln source hardlink`；`ln -s source softlink`；`stat file`查看inode信息 |
| 原理和工作流程 | 每个文件对应一个inode，存储权限、大小、时间戳与数据块指针，文件名存在目录项中。硬链接是目录项指向同一inode，链接数增减；软链接是独立文件，inode中存储目标路径字符串。读取硬链接直接定位数据块，读取软链接先解析路径再二次查找目标inode |
| 缺点 | 硬链接不能跨文件系统、不能链接目录，否则破坏文件系统树结构；软链接原文件删除后变悬空链接；inode耗尽后即使磁盘有空间也无法创建文件 |

---

### 2.2 管道实现原理

| 维度 | 内容 |
|------|------|
| 是什么 | 基于内核环形缓冲区实现进程间单向数据传输的通信机制 |
| 能做什么 | 连接父子进程的输入输出；命名管道可在任意进程间通信；提供读写阻塞同步 |
| 怎么用 | `mkfifo mypipe`；`command1 | command2` |
| 原理和工作流程 | 管道在内核中分配一块固定大小（通常4KB即一页内存）的环形缓冲区。写端写入数据，缓冲区满则写进程阻塞；读端读取数据，缓冲区空则读进程阻塞。匿名管道通过`pipe`系统调用创建，只能在`fork`产生的亲缘进程间使用。命名管道以FIFO文件形式存在于文件系统，任意进程可`open`后通信 |
| 缺点 | 半双工单向传输，双向通信需两个管道；缓冲区容量有限，大数据传输需多次读写；匿名管道限于亲缘进程，跨进程需命名管道或socket |

---

### 2.3 Shell 执行脚本流程

| 维度 | 内容 |
|------|------|
| 是什么 | Shell解释器从读取命令行到执行程序的完整处理阶段 |
| 能做什么 | 完成命令分词、变量与通配符展开、重定向设置、命令派发 |
| 怎么用 | `echo "Hello $(whoami)"`；`VAR=value command` |
| 原理和工作流程 | 依次执行四步：先读取命令行，再按空白与元字符分词，接着展开通配符、变量、命令替换与算术替换，然后处理`>`、`<`重定向文件描述符，最后对外部命令调用`execve`派生新进程执行，内置命令则由Shell直接处理。展开顺序固定，理解顺序可避免引用错误 |
| 缺点 | 展开顺序复杂，变量含空格或特殊字符易触发非预期分词；通配符在无匹配时保留字面量可能误传给命令 |

---

### 2.4 环境变量与进程环境

| 维度 | 内容 |
|------|------|
| 是什么 | 每个进程持有的`key=value`形式环境表，用于传递运行时配置 |
| 能做什么 | 子进程继承父进程环境变量；`export`导出变量供子进程使用；通过`PATH`定位命令路径 |
| 怎么用 | `export JAVA_HOME=/usr/local/jdk`；`echo $PATH`；`env`查看全部环境变量 |
| 原理和工作流程 | 进程创建时内核为其维护一张环境表，存放于进程地址空间。`fork`时子进程复制父进程环境表副本，`execve`可指定新环境表替换。`export`将Shell变量标记为环境变量，使其在后续`fork`时被子进程继承。常见变量`PATH`决定命令搜索路径，`HOME`、`USER`、`SHELL`记录用户上下文 |
| 缺点 | 环境变量明文存储敏感信息存在泄露风险；子进程修改不影响父进程，配置无法回传；变量过多会占用进程内存与命令行长度限制 |

| 是什么 | 综合运用ls、mkdir、rm、cp、find、tar等命令完成日常文件管理任务的实践集合 |

### 3.2 管道与重定向实战

| 维度 | 内容 |
|------|------|
| 是什么 | 用重定向与管道组合完成日志统计、错误分离、输出控制的实战示例 |
| 能做什么 | 覆盖与追加写入文件；合并标准输出与错误；丢弃错误；统计日志TopN IP |
| 怎么用 | `echo "text" >> file`；`./script.sh > out.log 2>&1`；`./script.sh 2> /dev/null`；`cat access.log | awk '{print $1}' | sort | uniq -c | sort -nr | head -10` |
| 原理和工作流程 | `>`由Shell用`open`以`O_TRUNC`打开文件再`dup2`到stdout，`>>`则用`O_APPEND`。`2>&1`把stderr描述符复制为stdout当前指向的文件。管道场景下每个命令作为独立进程并发，通过内核缓冲区传递数据，`sort`需等上游全部输出完才能排序 |
| 缺点 | `sort`需缓存全部输入，大文件耗内存；管道中途命令失败默认不中断后续，需`set -o pipefail`捕获；`2>&1`顺序写反会导致错误仍输出到屏幕 |

| 能做什么 | 递归搜索代码TODO；直接修改文件内容；删除空行；按字段统计求和 |

| 原理和工作流程 | grep递归遍历目录对每个文件逐行正则匹配。sed将行读入模式空间执行替换命令，`-i`先写到临时文件再原子替换原文件。awk按行读取，自动按分隔符切字段，`$1`为第一字段，`END`块在所有行处理完后执行一次输出汇总 |

### 3.4 Shell 脚本基础实战

| 维度 | 内容 |
|------|------|
| 是什么 | 涵盖变量、条件、循环、函数及完整Spring Boot启停脚本的Shell编程实战 |
| 能做什么 | 定义只读与位置变量；用if/case分支；用for/while循环；封装函数传参与返回；编写服务启停状态管理脚本 |
| 怎么用 | `readonly PI=3.14`；`if [ -f file ]; then ...; fi`；`for ((i=0;i<10;i++)); do ...; done`；`nohup java -jar app.jar >> app.log 2>&1 &` |

## 四、常见面试题

### 1. 软链接和硬链接的区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 两种不同的文件链接方式，硬链接共享inode，软链接存储目标路径 |
| 能做什么 | 硬链接防误删保护数据；软链接实现跨文件系统引用与版本切换 |
| 怎么用 | `ln source hardlink`；`ln -s source softlink` |
| 原理和工作流程 | 硬链接在目录表新增一个条目指向已存在的inode，inode的链接计数加一，所有硬链接地位平等，删除一个只是减计数，归零才释放数据块。软链接创建独立inode，其数据块存放目标路径字符串，访问时内核解析路径二次查找，原文件删除后路径失效成悬空链接 |
| 缺点 | 硬链接不能跨文件系统、不能链接目录；软链接有额外inode与路径解析开销，原文件移动或删除即失效 |

---

### 2. tar 命令 czf、xzf 参数的含义？

| 维度 | 内容 |
|------|------|
| 是什么 | tar命令中控制创建、解压、压缩算法、文件名指定的参数组合 |
| 能做什么 | `c`创建归档；`x`解压归档；`z`调用gzip压缩解压；`f`指定归档文件名 |
| 怎么用 | `tar -czf archive.tar.gz project/`；`tar -xzf archive.tar.gz` |
| 原理和工作流程 | tar先将多个文件按tar格式流式归档为单一数据流，`z`参数使tar在归档流上调用gzip程序做压缩，`f`告诉tar后续参数是输出文件名而非磁带设备。解压时反向执行，先gzip解压再tar展开。`f`必须放在最后，其后紧跟文件名 |
| 缺点 | `f`参数位置敏感，写错会导致文件名被当作其他参数；gzip为单线程压缩大文件慢；不支持随机访问，解压单个文件仍需扫描整个归档 |

---

### 3. | 管道和 ; 分号、&& 区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 三种连接多条命令的运算符，分别实现数据传递、无条件顺序、条件依赖执行 |
| 能做什么 | `|`传递stdout给下一条命令；`;`无视成败顺序执行；`&&`仅在前一条成功时执行下一条 |
| 怎么用 | `ls | grep txt`；`make ; make install`；`test -f file && cat file` |
| 原理和工作流程 | `|`由Shell创建管道并fork两个进程，通过内核缓冲区传递数据。`;`顺序fork执行每条命令，不检查退出码。`&&`在前一条命令退出码为0时才fork下一条，非0则短路跳过。`||`相反，前一条失败才执行下一条 |
| 缺点 | `|`只传stdout不传stderr，错误易丢失；`;`忽略失败可能导致后续命令在错误状态下运行；`&&`链过长可读性差 |

---

### 4. grep、sed、awk 各自适用场景？

| 维度 | 内容 |
|------|------|
| 是什么 | 文本三剑客的职责划分：搜索、编辑、字段计算 |
| 能做什么 | grep过滤匹配行；sed做行级替换删除插入；awk按字段处理并支持统计与编程 |
| 怎么用 | `grep "error" log`；`sed 's/a/b/g' file`；`awk '{sum+=$1} END{print sum}' file` |
| 原理和工作流程 | grep逐行正则匹配，命中即输出，不修改原文。sed把行读入模式空间执行编辑命令，是流编辑器。awk逐行读取自动按分隔符切字段，提供BEGIN、逐行、END三阶段脚本执行能力，支持变量、条件、循环 |
| 缺点 | grep只能过滤不能改写；sed跨平台`-i`行为不一致；awk处理大文件性能有限，复杂统计应改用专用工具 |

### 5. Shell 中单引号和双引号区别？

| 维度 | 内容 |
|------|------|
| 是什么 | 两种引用方式，单引号禁止所有展开，双引号允许变量与部分特殊字符展开 |
| 能做什么 | 单引号原样输出字面内容；双引号展开变量、命令替换、算术替换但保护空格 |
| 怎么用 | `echo 'Hello $name'`输出字面；`echo "Hello $name"`展开变量 |
| 原理和工作流程 | Shell分词阶段处理引用。单引号内的所有字符（含`$`、反引号、`\`）都失去特殊含义，Shell不做任何展开。双引号内`$`、反引号、`\`仍保留特殊含义，变量与命令替换正常展开，但空格被保护不被分词。不加引号时空格作为分词符、通配符会被展开 |
| 缺点 | 单引号内无法嵌入单引号本身；双引号内反引号与`$`仍需注意转义；新手混淆两者导致变量不展开或意外分词 |

### 6. 如何在 Shell 脚本中获取脚本所在目录？

| 维度 | 内容 |
|------|------|
| 是什么 | 获取脚本文件自身所在绝对路径的技巧，而非运行时的工作目录 |
| 能做什么 | 让脚本以自身位置为基准定位配置与资源文件，不依赖调用者的cwd |
| 怎么用 | `SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)` |
| 原理和工作流程 | `BASH_SOURCE[0]`是Bash内置数组，存放当前脚本被调用时的路径（可能是相对路径）。`dirname`提取目录部分，`cd`进入该目录后`pwd`输出绝对路径。用`$(...)`命令替换捕获pwd结果赋给变量。相比`$0`，`BASH_SOURCE[0]`在source执行时也能正确指向脚本文件 |
| 缺点 | 依赖Bash特有变量，POSIX sh不可用；符号链接场景需额外`readlink -f`解析真实路径；脚本被管道执行时无法获取路径 |

### 7. $?、$$、$#、$@、$* 分别表示什么？

| 维度 | 内容 |
|------|------|
| 是什么 | Shell中五类特殊内置变量，分别表示退出码、进程号、参数个数、参数列表 |
| 能做什么 | `$?`判断命令成败；`$$`获取当前PID；`$#`统计参数数；`$@`与`$*`遍历所有参数 |
| 怎么用 | `if [ $? -eq 0 ]; then ...`；`echo $$`；`for arg in "$@"; do ...; done` |
| 原理和工作流程 | `$?`读取内核在子进程退出时设置的退出码，0为成功。`$$`取自当前Shell进程的PID。`$#`是位置参数数组长度。`$@`与`$*`都代表所有位置参数，区别在于加双引号时：`"$@"`保留每个参数独立边界展开为多个词，`"$*"`用IFS首字符连接成单一字符串 |
| 缺点 | `$?`易被中间命令覆盖需及时捕获；`$*`合并参数行为易引发错误，推荐用`"$@"`；这些变量名易与自定义变量混淆 |
