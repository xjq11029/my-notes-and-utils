# Linux - 概念对比速查

---

### 硬链接 vs 软链接

| 对比维度 | 硬链接 | 软链接（符号链接） |
|---------|-------|-------|
| 核心定位 | 同一 inode 的多个目录入口，指向相同数据块 | 指向目标文件路径的快捷方式 |
| 适用场景 | 防止误删重要文件，创建文件的多重备份入口 | 创建快捷方式、版本切换、跨文件系统引用 |
| 跨文件系统 | 不支持，必须在同一文件系统内 | 支持，可跨分区和网络文件系统 |
| 删除原文件 | 不影响，只要还有一个硬链接数据就存在 | 链接失效，成为悬空链接（dangling symlink） |
| 目录链接 | 不支持（防止循环引用） | 支持 |
| inode 编号 | 与原文件相同 | 与原文件不同，拥有独立的 inode |
| 命令示例 | `ln source.txt hardlink.txt` | `ln -s source.txt softlink.txt` |
| 选择建议 | 需要防止误删时使用硬链接 | 需要灵活引用、跨文件系统、版本管理时使用软链接 |

### find vs grep vs locate

| 对比维度 | find | grep | locate |
|---------|------|-------|--------|
| 核心定位 | 按文件名、类型、大小、时间等属性搜索文件 | 在文件内容中搜索匹配的文本模式 | 基于文件名数据库快速定位文件 |
| 适用场景 | 按文件属性（名称、大小、修改时间）精确查找文件 | 在日志、代码、配置文件中搜索特定文本内容 | 只知道文件名或部分文件名时快速查找 |
| 搜索范围 | 实时遍历文件系统 | 指定文件或标准输入的内容 | 查询预建的索引数据库（updatedb） |
| 性能特点 | 慢，实时遍历磁盘 | 中等，取决于文件大小 | 极快，基于索引查询 |
| 索引机制 | 无索引，实时扫描 | 无索引，顺序读取 | 依赖 updatedb 定期更新的数据库 |
| 新文件可见性 | 立即可见 | 立即可见 | 需等待 updatedb 更新后才可见 |
| 命令示例 | `find / -name "*.log" -mtime -7` | `grep -r "ERROR" /var/log/` | `locate nginx.conf` |
| 选择建议 | 需要按文件属性（时间、大小、权限）精确查找时用 find | 需要搜索文件内容时用 grep | 需要快速按文件名定位时用 locate，但注意索引可能不是最新的 |

### top vs htop vs vmstat

| 对比维度 | top | htop | vmstat |
|---------|-----|------|--------|
| 核心定位 | 实时进程监控，查看 CPU 和内存使用 | top 的增强版，彩色交互式进程查看器 | 系统整体性能统计，关注虚拟内存和 I/O |
| 适用场景 | 日常进程监控、快速定位高 CPU/内存进程 | 交互式进程管理，需要直观的图形界面 | 宏观性能分析，排查内存压力和 I/O 瓶颈 |
| 交互方式 | 键盘单键命令（k 杀进程、r renice） | 鼠标+键盘，支持上下滚动、点击排序 | 非交互式，按指定间隔输出统计信息 |
| 显示内容 | 进程列表、CPU、内存、负载、运行时间 | 彩色进程树、CPU/内存柱状图、自定义列 | 进程、内存、swap、I/O、系统、CPU 综合统计 |
| CPU 展示 | 汇总百分比 | 每核独立柱状图 | 用户态/系统态/空闲/等待 I/O 百分比 |
| 内存展示 | 总量/已用/可用/缓存 | 彩色柱状图 | 虚拟内存、空闲内存、缓存、swap 进/出 |
| 历史数据 | 不支持 | 不支持 | 不支持（需配合 sar 收集历史数据） |
| 选择建议 | 快速查看系统负载和进程排名时用 top | 需要深入排查进程关系和直观交互时用 htop | 需要分析系统级性能趋势、swap 和 I/O 瓶颈时用 vmstat |

### nohup vs screen vs systemd

| 对比维度 | nohup | screen | systemd |
|---------|-------|--------|---------|
| 核心定位 | 让进程忽略 SIGHUP 信号，在后台持续运行 | 终端多路复用器，创建可断开重连的会话 | 系统和服务管理器，Linux 标准初始化系统 |
| 适用场景 | 临时运行一个后台任务，快速启动 | 需要保留终端会话环境，断开 SSH 后可重连 | 生产环境服务管理，需要开机自启、日志管理、资源控制 |
| 进程管理 | 仅启动进程，无状态监控 | 会话内管理多个窗口，无自动重启 | 完整的进程生命周期管理：启动、停止、重启、状态监控 |
| 持久化 | 关闭终端后进程继续运行 | 可 detach 后重连，但 screen 进程本身无守护 | 系统级守护，开机自启、崩溃自动重启 |
| 日志管理 | 需手动重定向到文件 | 无内置日志，需手动处理 | systemd journal 自动收集 stdout/stderr |
| 资源限制 | 无 | 无 | 支持 CPU/Memory 限制（cgroup） |
| 开机自启 | 不支持 | 不支持 | 支持（systemctl enable） |
| 命令示例 | `nohup java -jar app.jar &` | `screen -S mysession` 然后 `Ctrl+A D` 断开 | `systemctl start myapp.service` |
| 选择建议 | 临时快速启动后台任务时用 nohup | 需要保留交互式终端环境时用 screen | 生产环境正式部署服务时用 systemd |
