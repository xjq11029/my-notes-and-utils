## 第一段：微调基础

### 1.1 什么是大模型微调

| 维度 | 内容 |
|------|------|
| 是什么 | 在预训练好的大语言模型基础上，使用特定领域或任务数据继续训练，让模型学习新知识、风格或格式同时保留通用能力的过程。 |
| 能做什么 | 领域适配（医疗、法律、金融等垂直领域）；风格对齐（对话、JSON、代码等格式）；能力提升（注入新知识提升特定任务性能）；对齐人类偏好（RLHF/DPO）。 |
| 怎么用 | 准备领域数据→选择微调策略（全量/PEFT）→训练→评估→部署。 |
| 原理和工作流程 | 预训练阶段在大规模无标注语料上学习通用语言表示，微调阶段在少量领域标注数据上更新部分或全部参数，使模型适配特定任务。核心价值在于迁移学习：预训练获得的通用能力作为基础，微调在此之上叠加领域特定能力。微调需平衡新能力注入与通用能力保持，避免灾难性遗忘。 |
| 缺点 | 全量微调显存占用极大；微调数据质量差会引入偏差；过度微调导致灾难性遗忘，通用能力下降。 |

### 1.2 全量微调 vs 参数高效微调（PEFT）

| 维度 | 内容 |
|------|------|
| 是什么 | 全量微调更新模型所有参数，PEFT只微调一小部分额外参数冻结大部分原始参数，两者在显存、速度、性能上的对比。 |
| 能做什么 | 全量微调性能上限高所有参数可优化；PEFT显存极低训练速度快，只需存储少量增量参数，可叠加多个适配器到同一基座。 |
| 怎么用 | 全量微调：7B模型需上百GB显存，每个任务保存完整权重(13GB)；PEFT：只训练额外参数，存储量降低一个数量级。 |
| 原理和工作流程 | 全量微调对预训练模型所有参数计算梯度并更新，性能上限最高但显存和存储开销极大。PEFT冻结原始模型参数，仅训练少量额外插入的参数（如LoRA的低秩矩阵），可训练参数通常仅占0.1%~1%。PEFT已成为业界主流方案，在绝大多数场景下性能接近全量微调但成本降低一个数量级以上。 |
| 缺点 | 全量微调显存极大、成本高、每个任务需保存完整权重；PEFT性能略低于全量微调（差距很小），在极复杂任务上可能不足。 |

### 1.3 指令微调（Instruction Tuning）

| 维度 | 内容 |
|------|------|
| 是什么 | 使用指令-回答格式的数据对模型微调，让模型学会理解人类指令并遵循要求生成的训练方法。 |
| 能做什么 | 让模型从"预测下一个token"转变为"理解指令→完成任务"；大幅提升零样本/少样本场景下的泛化能力。 |
| 怎么用 | 数据格式：{"instruction":"请将以下中文翻译成英文","input":"人工智能正在改变世界","output":"Artificial intelligence is changing the world"}。 |
| 原理和工作流程 | 预训练模型只学会预测下一个token，不知道如何遵循指令。指令微调通过大量多样化的指令-回答对，让模型学会"理解指令→完成任务"的模式。指令数据覆盖分类、生成、推理、翻译、代码等多种任务类型。训练目标为标准语言模型损失，在给定instruction和input的条件下最大化output的概率。 |
| 缺点 | 需要高质量多样化的指令数据，标注成本高；指令数据覆盖面不足时泛化能力受限；无法教会模型哪个回答更好（缺乏比较信号）。 |

### 1.4 Prompt Tuning

| 维度 | 内容 |
|------|------|
| 是什么 | 一种极轻量的PEFT方法，只优化连续的soft prompt嵌入，冻结模型其余所有参数。 |
| 能做什么 | 参数极少（几十到几百个token的嵌入）；理论优雅；在大于10B的模型上才能发挥效果。 |
| 怎么用 | 在输入前拼接可训练的soft prompt：[P1][P2]...[Pk][CLS]请回答以下问题...，其中P1...Pk是可训练参数。 |
| 原理和工作流程 | 在输入序列前添加若干可训练的soft prompt token，这些token的嵌入向量是可训练参数，模型其余参数全部冻结。训练时只更新这些prompt token的嵌入，通过反向传播学习最优的prompt表示。soft prompt在连续空间中优化，比离散的文本prompt更灵活。 |
| 缺点 | 小模型上性能不如LoRA；需要大模型（>10B）才能发挥效果；目前工业界较少使用；soft prompt的可解释性差。 |

## 第二段：LoRA 原理

### 2.1 LoRA 核心思想：低秩分解

| 维度 | 内容 |
|------|------|
| 是什么 | 微软提出的低秩自适应方法，核心洞察是大模型权重的更新具有较低的秩，可用低秩矩阵近似权重更新。 |
| 能做什么 | 用极少的可训练参数实现有效微调；推理时可将LoRA权重合并到原始权重实现零延迟；同一基座模型可插多个不同任务的LoRA。 |
| 怎么用 | 冻结原始权重W₀，仅训练低秩矩阵B(d×r)和A(r×k)，前向传播h = W₀x + (α/r)BAx。 |
| 原理和工作流程 | 原始权重更新W = W₀ + ΔW，LoRA不对ΔW直接参数化，而是用低秩分解ΔW = BA，其中r远小于min(d,k)。A初始化为高斯分布，B初始化为零矩阵，因此训练开始时ΔW=0，不改变原始模型行为。α是缩放因子，通过α/r缩放增量权重的贡献。 |
| 缺点 | 低秩假设在某些复杂任务上可能不成立；rank选择需要实验调优；对非线性强的任务适配能力有限。 |

### 2.2 数学推导

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA的数学基础推导，从权重更新W = W₀ + ΔW出发，用低秩分解ΔW = BA替代直接参数化。 |
| 能做什么 | 量化可训练参数量从d×k降至(d+r)×k；保证训练开始时不改变原始模型行为；通过缩放因子平衡新旧权重贡献。 |
| 怎么用 | 前向传播：h = W₀x + ΔWx = W₀x + (α/r)BAx；A~高斯初始化，B=零矩阵初始化。 |
| 原理和工作流程 | 原始权重W₀∈R^(d×k)的更新ΔW直接参数化需要d×k个参数。LoRA将ΔW分解为B∈R^(d×r)和A∈R^(r×k)的乘积，参数量降为(d×r+r×k)=(d+k)×r，当r远小于d和k时参数量大幅减少。初始化策略使训练开始时ΔW=BA=0（B为零矩阵），模型行为与原始模型完全一致。缩放因子α/r控制增量权重的大小，α越大LoRA模块影响越大。 |
| 缺点 | 数学推导假设ΔW的低秩性，实际中秩的选择依赖经验；低秩约束可能限制模型表达能力。 |

### 2.3 rank 参数选择

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA中rank(r)决定低秩矩阵的维度，直接影响可训练参数量和微调性能的关键超参数。 |
| 能做什么 | r=1-4适合风格适配和数据量少的场景；r=8-16适合大部分场景（推荐）；r=32-64适合数据量大复杂任务；r=64+接近全量微调。 |
| 怎么用 | 7B/13B模型通常r=8足够；70B+模型考虑r=16或r=32；在验证集上选择最小满足性能要求的r。 |
| 原理和工作流程 | rank决定低秩矩阵B(d×r)和A(r×k)的维度，r越大参数量越多、表达能力越强但参数效率越低。论文实验表明r从1增加到4、8时效果提升明显，继续增大到16、32、64时收益递减甚至饱和。过小的r表达能力不足，过大的r接近全量微调失去参数效率优势。经验法则：增大r一定增加参数量但不一定提升性能。 |
| 缺点 | 最优r依赖任务和数据量，需实验确定；r过大失去参数效率优势；r过小可能表达能力不足。 |

### 2.4 alpha 缩放因子

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA中用于缩放ΔW输出的超参数，通过scaling = α/r平衡原始权重和增量权重的贡献。 |
| 能做什么 | 防止增量权重过大或过小；控制LoRA模块对模型行为的影响程度；α越大LoRA模块影响越大。 |
| 怎么用 | 通常设置alpha=r（scaling=1）；或alpha=2×r增大LoRA影响；不建议alpha远小于r。 |
| 原理和工作流程 | 前向传播中增量权重输出为(α/r)×BAx，α/r即为缩放因子。α的作用是平衡原始权重W₀x和增量权重ΔWx的贡献。当α=r时scaling=1，增量权重按原始大小叠加；当α=2r时scaling=2，增量权重影响加倍。初始化时B为零矩阵故ΔW=0，训练过程中α/r控制增量权重的增长速度。 |
| 缺点 | α与r的配比缺乏严格理论指导，依赖经验；α设置不当可能导致训练不稳定或LoRA几乎不起作用。 |

### 2.5 target_modules（目标模块）

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA插入低秩矩阵的目标模块配置，通常选择注意力层的投影矩阵，决定微调覆盖范围和参数量。 |
| 能做什么 | 只q_proj+v_proj参数最小（论文推荐）；加k_proj+o_proj参数约2倍略有提升；所有线性层含MLP参数约4-8倍提升有限。 |
| 怎么用 | target_modules = ["q_proj", "v_proj"]；显存允许时可加k_proj, o_proj, mlp等。 |
| 原理和工作流程 | LoRA不是对所有层都插入低秩矩阵，而是只针对指定模块。注意力层的q_proj（Query投影）和v_proj（Value投影）是最常见的目标，因为注意力机制是模型理解上下文的核心。不同目标模块选择在参数量、性能和显存间权衡。论文结论：除非数据集极大，否则只关注q_proj和v_proj就足够。 |
| 缺点 | 目标模块选择依赖经验；覆盖更多模块增加参数量但提升有限；不同模型结构的模块命名不同需适配。 |

### 2.6 LoRA 为什么有效

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA有效性的四个原因分析：参数效率极高、不影响推理速度、可热插拔、梯度更稳定。 |
| 能做什么 | 7B模型仅需几十万到几百万可训练参数；推理时合并权重零延迟开销；同一基座模型插多个LoRA；冻结原始参数减少梯度方差。 |
| 怎么用 | 训练时冻结W₀只训练A和B；推理时W_merged = W₀ + (α/r)BA，合并后与原始模型完全相同。 |
| 原理和工作流程 | 参数效率：低秩分解将可训练参数从d×k降至(d+k)×r，7B模型通常只需0.5-5M参数。推理零开销：训练完成后可将BA合并到W₀中，模型结构不变推理速度与原始模型完全相同。可热插拔：不同任务训练不同的LoRA权重，共享同一基座模型，切换任务只需替换LoRA矩阵。梯度稳定：原始参数冻结减少了梯度方差，训练更稳定。 |
| 缺点 | 低秩约束在极复杂任务上可能限制表达能力；多个LoRA同时使用时可能存在干扰；合并后无法再分离单独LoRA。 |

### 2.7 LoRA 权重合并

| 维度 | 内容 |
|------|------|
| 是什么 | 训练完成后将LoRA低秩矩阵乘积合并回原始权重的过程，使推理时不需要任何额外修改和开销。 |
| 能做什么 | 消除推理时的额外计算开销；合并后模型结构不变；推理速度与原始模型完全相同。 |
| 怎么用 | W_merged = W₀ + (α/r)×BA；合并后保存为标准模型格式，无需LoRA适配器。 |
| 原理和工作流程 | 训练时前向传播为h = W₀x + (α/r)BAx，需要额外的BA矩阵乘法。合并时直接计算W_merged = W₀ + (α/r)BA，将增量权重加到原始权重上，得到一个标准权重矩阵。合并后前向传播简化为h = W_merged×x，与原始模型完全相同，无任何额外计算。合并是不可逆操作，合并后无法再分离出LoRA权重。 |
| 缺点 | 合并是不可逆的，合并后无法再单独使用或替换LoRA；多个LoRA合并到同一基座会相互覆盖；合并前需确认LoRA训练已完成。 |

## 第三段：QLoRA 进阶

### 3.1 QLoRA 是什么

| 维度 | 内容 |
|------|------|
| 是什么 | 华盛顿大学提出的高效微调技术，将4-bit量化和LoRA结合，可在单块消费级GPU上微调大模型。 |
| 能做什么 | 在RTX 3060 12GB上微调7B模型；4-bit量化基础上微调性能与FP16全量微调几乎相同；三大核心创新降低显存。 |
| 怎么用 | 原始模型量化为4-bit NF4→冻结量化权重→插入并训练LoRA低秩矩阵（FP32/BF16）→Paged Optimizers管理显存。 |
| 原理和工作流程 | 三大核心创新：4-bit NormalFloat(NF4)量化针对正态分布权重优化的量化方案；双重量化对量化常数进一步量化减少显存；Paged Optimizers分页优化器处理峰值显存。QLoRA将基座模型量化到4-bit大幅减少显存，同时LoRA矩阵保持FP32/BF16精度训练，反向传播时通过Paged Optimizers管理显存峰值。 |
| 缺点 | 量化引入轻微精度损失；4-bit推理需要专门的量化内核支持；训练速度比LoRA慢（量化/反量化开销）。 |

### 3.2 4-bit NormalFloat (NF4) 量化

| 维度 | 内容 |
|------|------|
| 是什么 | 针对正态分布权重优化的4-bit量化方案，分位数与正态分布对齐，在权重密集区域粒度更细。 |
| 能做什么 | 比均匀量化精度损失更低（约0.5-1% vs 1-2%）；在权重值密集处（靠近零点）量化粒度更细；在稀疏处粒度更粗。 |
| 怎么用 | NF4量化：分位数与标准正态分布的分位数对齐，无需训练后校准。 |
| 原理和工作流程 | 预训练模型权重近似服从标准正态分布W~N(0,1)。传统均匀量化将值域等分，对正态分布不是最优。NF4将4-bit的16个量化等级的分位数与正态分布的分位数对齐：在权重值密集的区域（靠近零点）分配更多量化级别实现更细粒度，在稀疏区域（远离零点）分配较少级别。理论上对正态分布权重比均匀量化更优。 |
| 缺点 | 假设权重服从正态分布，偏离假设时效果下降；4-bit精度仍有信息损失；量化/反量化增加计算开销。 |

### 3.3 双重量化（Double Quantization）

| 维度 | 内容 |
|------|------|
| 是什么 | 对量化常数本身再进行量化的技术，第一次将权重量化为4-bit，第二次对缩放因子再量化进一步节省显存。 |
| 能做什么 | 对7B模型约节省0.5GB显存；几乎没有精度损失；默认开启建议始终开启。 |
| 怎么用 | 第一次量化：16/32-bit权重→4-bit（每通道一个scale）；第二次量化：对这些scale再量化。 |
| 原理和工作流程 | 第一次量化将原始16/32-bit权重量化为4-bit，每个输出通道需要一个缩放因子(scale)。这些scale本身以FP32存储占用额外显存。双重量化对这些scale再进行量化（如从FP32量化到8-bit），进一步减少显存占用。由于scale的数量远少于权重数量，第二次量化的精度损失可忽略不计。对7B模型约节省0.5GB显存。 |
| 缺点 | 节省的显存量相对有限（0.5GB）；二次量化引入微量精度损失（可忽略）；实现复杂度略增。 |

### 3.4 显存对比

| 维度 | 内容 |
|------|------|
| 是什么 | 以LLaMA-2 7B为例，全量微调、LoRA、QLoRA三种方案的训练显存占用和硬件要求对比。 |
| 能做什么 | 全量微调需~140GB（A100 80GB×2）；LoRA需~30GB（RTX 3090/4090）；QLoRA需~5-8GB（RTX 3060 12GB/4060 8GB）。 |
| 怎么用 | 对照显存表选择方案：资源充足选全量微调，消费级显卡选LoRA，入门级显卡选QLoRA。 |
| 原理和工作流程 | 全量微调需存储模型参数(FP16)、梯度(FP16)、优化器状态(FP32的Adam一阶矩、二阶矩、主权重)，总计约16Ψ字节。LoRA冻结原始参数只训练少量LoRA参数，优化器状态大幅减少，但基座模型仍以FP16存储。QLoRA将基座模型量化到4-bit（参数存储减少4倍），加上双重量化和Paged Optimizers，7B模型显存降至5-8GB。关键结论：QLoRA在4-bit量化基础上微调性能与FP16全量微调几乎相同。 |
| 缺点 | 全量微调硬件门槛极高；LoRA仍需30GB无法在消费级显卡运行；QLoRA虽显存低但训练速度较慢。 |

### 3.5 QLoRA 工作流程

| 维度 | 内容 |
|------|------|
| 是什么 | QLoRA微调的完整工作流程，从模型量化到LoRA训练再到显存管理的端到端过程。 |
| 能做什么 | 将原始模型量化为4-bit NF4；冻结量化权重只训练LoRA矩阵；通过Paged Optimizers处理显存峰值。 |
| 怎么用 | 步骤：1.量化模型为4-bit NF4→2.冻结量化权重→3.插入并训练LoRA低秩矩阵(FP32/BF16)→4.Paged Optimizers管理显存。 |
| 原理和工作流程 | 第一步将原始FP16权重量化为4-bit NF4格式存储，大幅减少基座模型显存。第二步冻结所有量化权重不更新。第三步在指定模块插入LoRA低秩矩阵A和B，这些矩阵以FP32或BF16精度存储和训练，保证梯度计算的数值稳定性。反向传播时需要将4-bit权重反量化为FP16计算梯度，再更新LoRA参数。第四步Paged Optimizers利用CPU内存处理GPU显存峰值，防止OOM。 |
| 缺点 | 4-bit权重的反复量化/反量化增加计算开销；Paged Optimizers的GPU-CPU传输增加延迟；流程比标准LoRA复杂。 |

## 第四段：其他 PEFT 方法对比

### 4.1 Adapter 方法

| 维度 | 内容 |
|------|------|
| 是什么 | 最早的PEFT方法之一，在每层之间插入小型瓶颈结构（降维→非线性→升维+残差）适配下游任务。 |
| 能做什么 | 每层只需几百到几千参数；通过瓶颈结构学习任务特定特征；冻结原始模型参数。 |
| 怎么用 | 输出 = x + adapter(x)，其中adapter(x) = 升维(非线性(降维(x)))。 |
| 原理和工作流程 | 在Transformer每层的子层后插入Adapter模块：先将高维输入降维到低维瓶颈（如512→64），经非线性激活函数，再升维回原始维度（64→512），最后通过残差连接加到输入上。训练时冻结原始模型参数只更新Adapter参数。Adapter参数量通常每层几百到几千。 |
| 缺点 | 引入额外推理延迟（需额外前向计算）；推理时不能像LoRA一样合并权重；逐渐被LoRA取代。 |

### 4.2 Prefix Tuning

| 维度 | 内容 |
|------|------|
| 是什么 | 类似Prompt Tuning但优化Key/Value缓存中前缀的PEFT方法，只优化前缀的K/V冻结其余参数。 |
| 能做什么 | 对Transformer结构侵入更小；参数量比Prompt Tuning略多；只优化前缀的K/V。 |
| 怎么用 | 在每层的K/V缓存前添加可训练的前缀向量，冻结模型其余参数。 |
| 原理和工作流程 | Prompt Tuning只优化输入层的soft prompt嵌入，Prefix Tuning直接优化注意力机制中Key和Value缓存的前缀。前缀向量作为可训练参数插入到每层的K/V矩阵前，使模型在计算注意力时能利用这些学习到的前缀信息。相比Prompt Tuning，Prefix Tuning对注意力机制的侵入更直接。 |
| 缺点 | 实际应用不如LoRA广泛；前缀长度选择依赖经验；对深层模型效果可能不稳定。 |

### 4.3 P-Tuning v2

| 维度 | 内容 |
|------|------|
| 是什么 | 在Prefix Tuning基础上的改进版本，对每一层都加入可训练的前缀嵌入而非仅在输入层。 |
| 能做什么 | 原始P-Tuning只在输入层加prompt，v2在每一层都加prefix；对更深的模型效果更好。 |
| 怎么用 | 在Transformer每一层的注意力计算前都添加可训练的前缀向量。 |
| 原理和工作流程 | 原始P-Tuning只在输入层（第0层）添加可训练prompt，深层模型中信息逐层衰减效果受限。P-Tuning v2在每一层都添加可训练前缀嵌入，使每层注意力都能利用学习到的前缀信息。深层前缀可以捕获更复杂的任务模式，对更深的模型（如32层以上）效果更好。 |
| 缺点 | 仍然不如LoRA普及；每层添加前缀增加参数量；实现复杂度较高；社区支持不如LoRA成熟。 |

### 4.4 IA³

| 维度 | 内容 |
|------|------|
| 是什么 | 通过缩放激活值适配模型的PEFT方法，只学习一组缩放向量对Key和Value进行元素级缩放。 |
| 能做什么 | 参数量极少（每个注意力层仅d个参数）；可合并到原始权重不增加推理延迟；简单优雅。 |
| 怎么用 | k = s_k⊙k_0，v = s_v⊙v_0，其中s_k和s_v是可训练向量初始化为1。 |
| 原理和工作流程 | IA³通过学习缩放向量s_k和s_v对注意力的Key和Value进行元素级缩放。初始化为1时不改变原始行为，训练过程中学习最优缩放比例。参数量每个注意力层仅d维（隐藏维度），是所有PEFT方法中最少的之一。缩放向量可合并到原始权重矩阵中，推理时零额外开销。 |
| 缺点 | 性能在复杂任务上不如LoRA；表达能力受限于元素级缩放；对某些任务适配能力不足。 |

### 4.5 各种 PEFT 方法对比总结

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA、QLoRA、IA³、Adapter、Prefix Tuning、P-Tuning v2、Prompt Tuning七种PEFT方法在参数量、推理延迟、性能、流行度上的系统对比。 |
| 能做什么 | 量化各方法的参数量（7B模型从0.01M到10M）；对比推理延迟（可合并零延迟 vs 有额外延迟）；指导方法选择。 |
| 怎么用 | 对照对比表：LoRA/QLoRA综合最优（5星），IA³良好（3星），Prompt Tuning仅大模型有效（1星）。 |
| 原理和工作流程 | LoRA参数量0.5-5M可合并零延迟性能很好，QLoRA同LoRA但显存更低。IA³参数量0.1-1M零延迟性能良好。Adapter参数量1-10M有额外延迟性能良好。Prefix Tuning参数量0.1-1M性能一般。P-Tuning v2参数量1-5M性能良好。Prompt Tuning参数量0.01-0.1M仅大模型有效。结论：LoRA/QLoRA综合最优，是工业界首选。 |
| 缺点 | 对比基于公开实验，不同任务和模型上排名可能变化；流行度受社区生态影响不完全反映技术优劣；新方法不断涌现对比结果时效性有限。 |

## 第五段：DeepSpeed 分布式训练

### 5.1 为什么需要 ZeRO

| 维度 | 内容 |
|------|------|
| 是什么 | 微软DeepSpeed的核心技术ZeRO（Zero Redundancy Optimizer），通过分片消除数据并行中的显存冗余。 |
| 能做什么 | 将标准DP中每卡16Ψ字节的显存降至16Ψ/N_d；让7B模型在8卡上单卡仅14GB（RTX 4090可容纳）。 |
| 怎么用 | 标准DP显存组成：参数2Ψ+梯度2Ψ+优化器状态12Ψ=16Ψ字节；ZeRO通过分片消除冗余。 |
| 原理和工作流程 | 标准数据并行中每张GPU保存完整模型副本（参数、梯度、优化器状态），存在大量冗余。以Adam优化器FP16混合精度为例，Ψ参数模型显存为16Ψ字节：参数(FP16)2Ψ+梯度(FP16)2Ψ+优化器状态(FP32的一阶矩m、二阶矩v、主权重)12Ψ。7B模型需112GB，A100 80GB单卡无法容纳，多卡DP只是复制不减少单卡显存。ZeRO核心思想是将这些状态在GPU间分片，每卡只保存一部分。 |
| 缺点 | 分片引入额外通信开销；需要多GPU环境；配置复杂度高于标准DP。 |

### 5.2 ZeRO 三阶段原理

| 维度 | 内容 |
|------|------|
| 是什么 | ZeRO的三个递进分片阶段：Stage1分片优化器状态，Stage2加分片梯度，Stage3全分片含参数。 |
| 能做什么 | Stage1显存4Ψ+12Ψ/N_d；Stage2显存2Ψ+14Ψ/N_d；Stage3显存16Ψ/N_d。7B模型8卡从112GB降至14GB。 |
| 怎么用 | Stage1：OS分片，通信量同DP几乎不影响速度（推荐默认）；Stage2：OS+G分片，轻微影响速度；Stage3：全分片，通信量增50%速度降20-40%。 |
| 原理和工作流程 | Stage1将优化器状态分片到N张卡，每卡只存1/N的OS，显存4Ψ+12Ψ/N_d，7B/8卡=38.5GB。Stage2在Stage1基础上将梯度也分片，显存2Ψ+14Ψ/N_d，7B/8卡=26.25GB。Stage3将参数、梯度、优化器状态全部分片，显存16Ψ/N_d，7B/8卡=14GB。通信开销权衡：Stage1和Stage2通信量与标准DP相同几乎不影响速度，Stage3需前向/反向时all-gather参数通信量增加约50%训练速度降低20-40%。 |
| 缺点 | Stage3通信开销大训练速度降低20-40%；分片策略选择需在显存和速度间权衡；70B模型8卡Stage3仍需140GB需多卡。 |

### 5.3 ZeRO-Offload：CPU 卸载

| 维度 | 内容 |
|------|------|
| 是什么 | 在ZeRO-2基础上将优化器状态和参数更新计算卸载到CPU内存的技术，利用CPU大内存扩展可用存储。 |
| 能做什么 | 在单卡上运行10B模型（V100 32GB）；GPU存参数和梯度做前向/反向计算；CPU存优化器状态执行Adam更新。 |
| 怎么用 | 配置offload_optimizer: {device: "cpu", pin_memory: true}，将优化器状态卸载到CPU。 |
| 原理和工作流程 | GPU显存存储模型参数(FP16)和梯度(FP16)负责前向/反向计算，通过PCIe将梯度传输到CPU内存。CPU内存存储优化器状态(FP32的一阶矩、二阶矩、主权重)并在CPU上执行Adam参数更新，更新后的参数通过PCIe传回GPU。以10B模型单卡为例：标准DP需160GB无法运行，ZeRO-Offload GPU显存仅40GB(参数+梯度)，CPU内存120GB(优化器)，单卡A100 40GB勉强可运行。 |
| 缺点 | GPU-CPU之间的PCIe传输增加显著延迟；CPU计算速度远慢于GPU成为瓶颈；不适合对训练速度要求高的场景。 |

### 5.4 ZeRO-Infinity：NVMe 卸载

| 维度 | 内容 |
|------|------|
| 是什么 | 进一步将卸载扩展到NVMe SSD的技术，突破CPU内存限制，可在32张A100 40GB上训练1万亿参数模型。 |
| 能做什么 | 三层存储层级：GPU显存(40-80GB)→CPU内存(256-2000GB)→NVMe SSD(4-16TB)；智能预取和异步更新掩盖存储延迟。 |
| 怎么用 | 配置offload_param和offload_optimizer的device为"cpu"或"nvme"，利用三层存储层级调度数据。 |
| 原理和工作流程 | 三层存储层级按速度和容量分配：GPU显存存当前计算所需的参数分片和batch激活值（最快最贵）；CPU内存存部分参数、梯度和优化器状态（中速中价）；NVMe SSD存完整的优化器状态、参数分片和梯度分片（慢速便宜）。三大创新：无限卸载引擎在GPU/CPU/NVMe间智能调度最大化重叠计算和传输；带宽中心化映射将高频数据放快速存储；内存中心化划分按带宽比例分配工作负载。 |
| 缺点 | NVMe读写速度远低于GPU显存成为瓶颈；三层调度逻辑复杂；预取和异步更新的调优困难。 |

### 5.5 DeepSpeed 与 PyTorch FSDP 对比

| 维度 | 内容 |
|------|------|
| 是什么 | DeepSpeed ZeRO与PyTorch原生FSDP（Fully Sharded Data Parallel）在分片策略、卸载支持、生态集成等维度的对比。 |
| 能做什么 | DeepSpeed支持ZeRO-1/2/3三级可选、CPU/NVMe卸载、Pipeline并行；FSDP仅ZeRO-3级别但代码简洁、原生支持。 |
| 怎么用 | 需ZeRO-1/2或CPU/NVMe卸载或Pipeline并行选DeepSpeed；纯PyTorch生态模型规模适中选FSDP。 |
| 原理和工作流程 | DeepSpeed ZeRO提供1/2/3三阶段可选分片策略，支持CPU卸载(ZeRO-Offload)和NVMe卸载(ZeRO-Infinity)，内置混合精度，用JSON配置文件，集成HuggingFace Accelerate，支持Pipeline并行和张量并行（Megatron集成）。PyTorch FSDP功能类似ZeRO-3，CPU卸载支持有限，不支持NVMe卸载，混合精度依赖PyTorch AMP，用Python代码配置，原生集成，调试难度较低。 |
| 缺点 | DeepSpeed配置复杂调试难度高；FSDP仅支持ZeRO-3级别灵活性低；两者在超大模型上的表现差异需实测验证。 |

### 5.6 DeepSpeed 配置示例

| 维度 | 内容 |
|------|------|
| 是什么 | DeepSpeed使用JSON配置文件定义训练参数的典型示例，涵盖ZeRO-2和ZeRO-3两种配置。 |
| 能做什么 | 通过JSON配置ZeRO阶段、卸载设备、通信参数、优化器、调度器、激活检查点等；在HuggingFace Trainer中指定deepspeed配置文件即可使用。 |
| 怎么用 | deepspeed="deepspeed_config.json"传入TrainingArguments；关键参数：stage(1/2/3)、offload_optimizer.device(cpu/none)、overlap_comm(true)。 |
| 原理和工作流程 | ZeRO-2配置：stage=2，offload_optimizer卸载到CPU，开启overlap_comm/reduce_scatter/contiguous_gradients优化通信，配置activation_checkpointing节省激活值显存。ZeRO-3配置：stage=3，offload_optimizer和offload_param都卸载到CPU，配置stage3_prefetch_bucket_size和stage3_gather_16bit_weights_on_model_save等参数。关键参数：stage控制分片阶段，offload_optimizer/param控制卸载目标，overlap_comm重叠通信和计算，reduce_bucket_size控制梯度聚合桶大小，activation_checkpointing用计算换显存。 |
| 缺点 | JSON配置项繁多学习曲线陡；参数间存在耦合关系调优困难；不同版本参数名可能变化兼容性差。 |

## 第六段：大模型评估方法

### 6.1 生成式评估指标

| 维度 | 内容 |
|------|------|
| 是什么 | 困惑度(PPL)、BLEU、ROUGE-L、BERTScore四种生成式评估指标的原理和适用场景。 |
| 能做什么 | PPL衡量语言建模能力；BLEU评估机器翻译n-gram匹配；ROUGE-L评估文本摘要召回率；BERTScore捕获语义相似度。 |
| 怎么用 | PPL=exp(-1/N×Σlog P(w_i|w_<i))；BLEU=BP×exp(Σw_n×log p_n)；ROUGE-L基于LCS；BERTScore用BERT嵌入计算余弦相似度。 |
| 原理和工作流程 | PPL衡量模型对文本的困惑程度，PPL越低语言建模能力越强，GPT-3约11.4，LLaMA-2 70B约3.5，但PPL只衡量预测下一个词能力不反映指令遵循。BLEU衡量生成文本与参考文本的n-gram重叠，侧重精确率，BP为长度惩罚。ROUGE-L基于最长公共子序列(LCS)计算F值，侧重召回率。BERTScore用预训练BERT编码后计算token级最佳匹配的余弦相似度，能捕获语义等价性（"快乐"和"高兴"BERTScore接近1.0而BLEU会扣分）。 |
| 缺点 | PPL不反映高级能力；BLEU/ROUGE无法捕获语义等价性只看n-gram匹配；BERTScore依赖BERT模型质量且计算开销大。 |

### 6.2 能力评估基准

| 维度 | 内容 |
|------|------|
| 是什么 | MMLU、HumanEval、GSM8K、BBH、CEval、MT-Bench、HellaSwag、TruthfulQA等业界核心评估基准的评估能力和方法。 |
| 能做什么 | MMLU评估多任务语言理解(57学科)；HumanEval评估代码生成(pass@k)；GSM8K评估数学推理；BBH评估复杂推理上限。 |
| 怎么用 | 使用lm-eval-harness：lm_eval --model hf --model_args pretrained=... --tasks mmlu,hellaswag,gsm8k,humaneval --num_fewshot 5。 |
| 原理和工作流程 | MMLU覆盖57学科多选题，让模型生成A/B/C/D或计算各选项log-prob选最高。HumanEval由164个编程问题组成，模型补全函数实现后运行测试用例，pass@k=1-C(n-c,k)/C(n,k)。GSM8K包含8500道小学数学应用题，要求模型逐步推理提取最终数字答案与标准答案比较。BBH是Big-Bench中23个最困难任务子集，小模型接近随机水平，仅GPT-4级别模型能取得60%以上准确率。 |
| 缺点 | 评估集可能泄露到训练数据中（数据污染）；few-shot数量影响结果；单一基准不能全面反映模型能力。 |

### 6.3 LLM-as-Judge：使用大模型评估大模型

| 维度 | 内容 |
|------|------|
| 是什么 | 利用强大的LLM（如GPT-4）作为评判者评估其他模型输出的方法，特别适合开放式生成任务的评估。 |
| 能做什么 | 评估准确性、有用性、无害性、简洁性等多维度；对开放式问答和对话打分；MT-Bench多轮对话评估。 |
| 怎么用 | 构建评估prompt（任务描述+评分标准+待评估内容+输出格式）→调用Judge模型→解析评分。 |
| 原理和工作流程 | 工作流程：准备评估数据（prompt+候选回答+可选参考回答），构建评估prompt包含任务描述、评分标准（准确性、有用性、无害性、简洁性）、待评估内容和输出格式要求，调用Judge模型（GPT-4）获取评分和理由，解析数值评分。MT-Bench使用GPT-4对模型多轮对话能力评分。常见偏差及缓解：位置偏差（随机打乱顺序取平均）、长度偏差（加长度惩罚）、自我偏好（用多Judge取平均）、一致性偏差（多次采样取平均）。 |
| 缺点 | Judge模型存在位置偏差、长度偏差、自我偏好等系统性偏差；评估成本高（需调用强模型API）；评分一致性不完美。 |

### 6.4 评估框架

| 维度 | 内容 |
|------|------|
| 是什么 | lm-eval-harness（EleutherAI）和OpenCompass（上海AI实验室）两个最广泛使用的LLM评估框架。 |
| 能做什么 | lm-eval-harness支持200+任务国际通用基准；OpenCompass支持100+任务中文支持优秀；两者均支持HuggingFace、vLLM、API模型。 |
| 怎么用 | lm-eval-harness：pip install lm-eval；lm_eval --model hf --model_args pretrained=... --tasks mmlu,gsm8k。 |
| 原理和工作流程 | lm-eval-harness由EleutherAI开发，支持200+评估任务，评估方式包括生成式和log-prob，支持HuggingFace/vLLM/API模型，中文支持一般，适合国际通用基准。OpenCompass由上海AI实验室开发，支持100+任务，中文支持优秀，内置可视化仪表盘，适合中文加国际基准。两者均通过命令行或Python API配置评估任务和模型，自动计算指标。 |
| 缺点 | 框架间评估结果可能因实现细节差异不可直接比较；任务覆盖面有限无法评估所有能力；自定义评估任务接入有一定门槛。 |

### 6.5 评估指标选择策略

| 维度 | 内容 |
|------|------|
| 是什么 | 根据任务类型选择合适评估指标的决策策略，涵盖语言建模、生成式任务、选择题、代码生成、数学推理、开放式问答等场景。 |
| 能做什么 | 语言建模用PPL；翻译用BLEU、摘要用ROUGE-L、语义等价用BERTScore；选择题用准确率；代码用pass@k；开放式问答用LLM-as-Judge。 |
| 怎么用 | 决策树：任务类型→对应指标；综合评估用MMLU+HumanEval+GSM8K组合基准。 |
| 原理和工作流程 | 评估指标选择决策树按任务类型分支：语言建模/困惑度用PPL（仅基座评估）；生成式任务翻译用BLEU、摘要用ROUGE-L、语义等价用BERTScore；选择题/分类用准确率；代码生成用pass@k执行测试用例；数学推理用准确率提取最终数字比较；开放式问答/对话有人工标注用人工评分无标注用LLM-as-Judge；综合能力用MMLU+HumanEval+GSM8K组合。最佳实践：基座能力PPL+MMLU，指令遵循MT-Bench，代码HumanEval+MBPP，数学GSM8K+MATH，中文C-Eval+CMMLU，安全TruthfulQA+ToxiGen。 |
| 缺点 | 不应只看单一指标（MMLU高不等于对话好）；评估集可能数据污染；few-shot数量影响结果；最终应以业务场景人工评估为准。 |

## 第七段：微调实战与部署推理

### 7.1 HuggingFace 生态

| 维度 | 内容 |
|------|------|
| 是什么 | 微调大模型离不开的HuggingFace生态系统，包含transformers、peft、datasets、trl、bitsandbytes、accelerate六个核心库。 |
| 能做什么 | transformers加载预训练模型和分词器；peft提供LoRA等PEFT方法；datasets加载处理数据集；trl支持SFT/DPO/PPO；bitsandbytes支持4/8-bit量化；accelerate多GPU分布式训练。 |
| 怎么用 | pip install transformers peft datasets trl bitsandbytes accelerate。 |
| 原理和工作流程 | HuggingFace生态为微调全流程提供工具链：transformers提供AutoModelForCausalLM和AutoTokenizer统一接口加载数百种预训练模型；peft库封装LoRA、IA³、Adapter等PEFT方法，通过LoraConfig和get_peft_model几行代码即可启用；datasets库支持JSON/JSONL/CSV等多种格式数据加载和处理；trl库提供SFTTrainer和DPOTrainer简化微调和对齐训练；bitsandbytes提供BitsAndBytesConfig实现4-bit/8-bit量化；accelerate处理多GPU分布式训练配置。 |
| 缺点 | 库版本更新频繁可能存在兼容性问题；文档分散学习成本高；部分高级功能配置复杂。 |

### 7.2 数据集准备

| 维度 | 内容 |
|------|------|
| 是什么 | 指令微调数据集的准备方法，包括JSON/JSONL格式、对话模板格式化和高质量数据要点。 |
| 能做什么 | 统一多轮对话为messages格式；通过tokenizer.apply_chat_template应用模型对话模板；数据清洗去重移除错误样本。 |
| 怎么用 | 数据格式：{"messages":[{"role":"system","content":"..."},{"role":"user","content":"..."},{"role":"assistant","content":"..."}]}。 |
| 原理和工作流程 | 指令微调数据集通常为JSON/JSONL格式，每条数据包含messages列表，每个message有role（system/user/assistant）和content字段。使用datasets.load_dataset加载后，通过tokenizer.apply_chat_template将多轮对话格式化为模型输入文本。高质量数据要点：数据质量大于数量（1k高质量远胜100k低质量）；覆盖多样化指令和场景；清洗去重移除错误和重复样本；控制样本长度避免过长样本占显存。 |
| 缺点 | 数据质量难以量化评估；多样化覆盖面不足时泛化受限；数据清洗需大量人工审核。 |

### 7.3 完整训练脚本（QLoRA + SFT）

| 维度 | 内容 |
|------|------|
| 是什么 | 使用QLoRA加SFT微调LLaMA-3-8B的完整Python训练脚本，涵盖配置、模型加载、数据加载、训练全流程。 |
| 能做什么 | 4-bit量化加载基座模型；LoRA配置(r=8, alpha=16, target=q_proj+v_proj)；SFTTrainer训练；可训练参数仅0.59%。 |
| 怎么用 | LoraConfig(r=8, lora_alpha=16, target_modules=["q_proj","v_proj"])；BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4")；SFTTrainer训练。 |
| 原理和工作流程 | 第一步配置参数：LoRA配置(r=8, alpha=16, target=q_proj+v_proj, dropout=0.05)，4-bit量化配置(NF4+双重量化+bfloat16计算精度)，训练参数(batch=4, gradient_accumulation=4, lr=2e-4, epochs=3, paged_adamw_8bit)。第二步加载模型：AutoTokenizer设置pad_token，AutoModelForCausalLM以4-bit量化加载，prepare_model_for_kbit_training准备k-bit训练，get_peft_model应用LoRA。第三步加载数据集并格式化。第四步SFTTrainer训练并保存LoRA权重。print_trainable_parameters输出可训练参数41,943,040(0.59%)。 |
| 缺点 | 脚本配置项繁多初学者上手困难；4-bit量化训练比FP16慢；超参数需根据任务调优。 |

### 7.4 参数调优指南

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA/QLoRA微调中学习率、batch size、rank r、训练轮数等关键超参数的调优指南。 |
| 能做什么 | 学习率LoRA推荐1e-4到5e-4，QLoRA可适当高一点2e-4到5e-4；batch size根据显存调整配合梯度累积；rank按数据量选择。 |
| 怎么用 | 学习率：LoRA 1e-4~5e-4，QLoRA 2e-4~5e-4；rank：数据量小r=1-4，中等r=8-16，大r=32-64；训练2-5轮观察验证损失提前停止。 |
| 原理和工作流程 | 学习率太小收敛慢太大容易发散，LoRA因只训练少量参数可用比全量微调更高的学习率。Batch size与梯度累积：显存不够时减小batch size增大梯度累积，如batch_size=1+gradient_accumulation=16等效batch_size=16。Rank r按数据量选择：数据量小用小r防止过拟合，数据量大用大r提升表达能力。训练轮数一般2-5轮足够，观察验证损失提前停止避免过拟合。 |
| 缺点 | 超参数最优值依赖具体任务和数据需实验确定；调优耗时耗资源；超参数间存在交互效应。 |

### 7.5 合并 LoRA 权重

| 维度 | 内容 |
|------|------|
| 是什么 | 训练完成后将LoRA适配器权重合并回基座模型得到完整模型的操作，便于后续部署。 |
| 能做什么 | 将LoRA增量权重合并到基座模型；消除推理时LoRA适配器开销；保存为标准模型格式。 |
| 怎么用 | base_model = AutoModelForCausalLM.from_pretrained(...)；model = PeftModel.from_pretrained(base_model, lora_path)；model = model.merge_and_unload()；model.save_pretrained(output_path)。 |
| 原理和工作流程 | 加载原始FP16基座模型，用PeftModel.from_pretrained加载训练好的LoRA适配器，调用merge_and_unload将LoRA权重BA合并到基座权重W₀中（W = W₀ + (α/r)BA），合并后模型结构恢复为标准Transformer无额外LoRA层。保存合并后的完整模型和分词器到指定目录，可直接用于vLLM等推理框架部署。 |
| 缺点 | 合并不可逆，合并后无法再分离LoRA；基座模型需以FP16加载合并（不能用量化模型）；合并后的完整模型存储空间大（7B约13GB）。 |

### 7.6 部署推理：vLLM

| 维度 | 内容 |
|------|------|
| 是什么 | 目前最快的开源LLM推理引擎，支持PagedAttention和高吞吐量，兼容OpenAI API格式。 |
| 能做什么 | 启动OpenAI兼容的API服务；支持PagedAttention消除KV Cache显存碎片；高吞吐量推理；gpu_memory_utilization控制显存使用。 |
| 怎么用 | python -m vllm.entrypoints.openai.api_server --model ./merged-model --port 8000 --gpu-memory-utilization 0.9。 |
| 原理和工作流程 | vLLM通过PagedAttention技术借鉴操作系统虚拟内存分页机制，将KV Cache划分为固定大小block按需分配回收，消除传统预分配方案的显存碎片。启动服务后提供OpenAI兼容的API接口，客户端用openai库的chat.completions.create调用。支持Continuous Batching动态管理推理batch最大化GPU利用率。gpu_memory_utilization参数控制vLLM可使用的GPU显存比例。 |
| 缺点 | 首次加载模型需较长时间；对部分自定义模型结构支持可能不完善；显存利用率设置过高可能导致OOM。 |

### 7.7 量化部署：GGUF / AWQ / GPTQ

| 维度 | 内容 |
|------|------|
| 是什么 | 三种主流模型量化部署格式：GGUF（llama.cpp格式跨平台CPU推理）、AWQ（激活感知量化NVIDIA GPU推荐）、GPTQ（成熟4-bit量化方案）。 |
| 能做什么 | GGUF跨平台支持CPU推理适合端侧部署；AWQ速度比GPTQ更快NVIDIA GPU推荐；GPTQ成熟方案支持ExLlamaV2加速。 |
| 怎么用 | GGUF：python convert.py ./model --outtype f16 → ./quantize model-f16.gguf model-q4_0.gguf q4_0；AWQ：AutoAWQForCausalLM.quantize()。 |
| 原理和工作流程 | GGUF是llama.cpp使用的格式，先用convert.py将模型转为f16 GGUF，再用quantize工具量化为4-bit（如q4_0），优点是跨平台支持CPU推理适合端侧。AWQ（Activation-aware Weight Quantization）在量化时考虑激活值分布，保护对输出影响大的权重通道，速度比GPTQ更快NVIDIA GPU推荐。GPTQ基于近似二阶信息（Hessian矩阵）逐列量化权重并更新剩余权重补偿误差，是成熟的4-bit量化方案支持ExLlamaV2加速。 |
| 缺点 | GGUF的CPU推理速度慢于GPU；AWQ需要校准数据集；GPTQ量化过程计算量大；三种格式互不兼容。 |

### 7.8 Ollama 本地部署

| 维度 | 内容 |
|------|------|
| 是什么 | 最简单的本地部署方案，通过Modelfile一键创建和运行微调后的模型，适合演示和开发。 |
| 能做什么 | 通过Modelfile定义模型来源和参数；一键创建和运行模型；支持temperature等参数配置；适合本地快速验证。 |
| 怎么用 | 创建Modelfile：FROM ./merged-model，PARAMETER temperature 0.7；ollama create my-model -f Modelfile；ollama run my-model。 |
| 原理和工作流程 | Ollama通过Modelfile定义模型配置：FROM指定模型来源（本地路径或官方仓库），PARAMETER设置推理参数（temperature等），SYSTEM设置系统提示词。使用ollama create命令根据Modelfile创建模型，ollama run命令启动交互式对话。Ollama内部使用llama.cpp引擎，自动处理模型量化和推理，用户无需关心底层细节。 |
| 缺点 | 性能不如vLLM等专用推理引擎；不适合高并发生产环境；对模型格式支持有限（主要支持GGUF）；自定义配置灵活性不足。 |
