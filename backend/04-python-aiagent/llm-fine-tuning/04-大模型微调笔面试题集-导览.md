### 1. Transformer 架构中，Multi-Head Attention 的"多头"机制的核心目的是什么？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | 多头注意力机制将输入投影到多个低维子空间独立计算注意力后拼接输出的设计。 |
| 能做什么 | 让模型从语义、语法、位置等不同角度联合关注序列中不同位置的信息；每个头学习不同的关注模式。 |
| 怎么用 | MultiHead = Concat(head_1,...,head_h)×W_O，每个head独立计算Scaled Dot-Product Attention。 |
| 原理和工作流程 | 将输入线性投影到h个低维子空间（每头维度d/h），每个头独立计算注意力捕获不同关系模式，输出拼接后经线性变换恢复原维度。核心目的是多角度关注而非增加参数量（参数增加是副作用）。 |
| 缺点 | 头数过多时每头维度过小表达能力下降；不同头可能学习到冗余模式；增加计算量而非减少。 |

### 2. 在 Transformer 中，Positional Encoding 的必要性是什么？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | 为Self-Attention机制提供序列中token位置信息的编码方案。 |
| 能做什么 | 弥补Self-Attention置换等变导致的位置感知缺失；使模型感知词序；支持外推到更长序列。 |
| 怎么用 | 正弦编码PE(pos,2i)=sin(pos/10000^(2i/d))；可学习位置嵌入作为可训练参数；RoPE对Q/K乘旋转矩阵。 |
| 原理和工作流程 | Self-Attention本身是置换等变的，打乱输入顺序输出也相应打乱，无法感知token顺序。Positional Encoding将位置信息注入输入表示使Transformer能捕捉序列顺序结构。正弦编码因能外推到训练时未见的长度而被原始论文采用。 |
| 缺点 | 正弦编码外推能力有限；可学习编码无法外推；RoPE在极长序列仍需配合长度外推技术。 |

### 3. 关于 Layer Normalization 在 Transformer 中的位置，Post-LN 和 Pre-LN 的区别是什么？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | LayerNorm在Transformer子层中放置位置的两种方案：Post-LN放在残差加法之后，Pre-LN放在子层之前。 |
| 能做什么 | Post-LN为原始论文方案；Pre-LN训练更稳定梯度流动更顺畅；GPT系列等现代大模型普遍采用Pre-LN。 |
| 怎么用 | Post-LN：LayerNorm(x + Sublayer(x))；Pre-LN：x + Sublayer(LayerNorm(x))。 |
| 原理和工作流程 | Post-LN将LN放在残差连接之后，需要warmup但效果可能更好。Pre-LN将LN放在子层之前，梯度通过残差连接直接传播更稳定，尤其在深层网络中。Pre-LN训练更稳定是现代大模型普遍采用的原因。 |
| 缺点 | Post-LN训练不稳定需warmup；Pre-LN在极深网络中性能可能略低于Post-LN；两者选择需权衡稳定性和性能。 |

### 4. LoRA（Low-Rank Adaptation）的核心思想是什么？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 假设权重更新矩阵具有低内在秩，用低秩矩阵分解近似权重更新的参数高效微调方法。 |
| 能做什么 | 冻结原始权重仅训练低秩矩阵B(d×r)和A(r×k)；推理时合并BA到W零额外延迟；可训练参数仅占0.1%~1%。 |
| 怎么用 | ΔW = BA，前向传播h = W₀x + BAx；A高斯初始化，B零矩阵初始化使训练开始时ΔW=0。 |
| 原理和工作流程 | LoRA假设微调时的权重更新ΔW具有低秩性质，将其分解为两个小矩阵乘积BA。r远小于min(d,k)使参数量从d×k降至(d+k)×r。推理时可将BA合并到W₀中不增加延迟。 |
| 缺点 | 低秩假设在复杂任务上可能不成立；rank选择需实验调优；不是直接修改所有参数。 |

### 5. LoRA 中秩 r 的选择对微调效果有什么影响？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA中超参数rank(r)决定低秩矩阵维度，影响可训练参数量和微调性能的关系。 |
| 能做什么 | r在合理范围内增大通常提升效果但边际收益递减；r过小表达能力不足；r过大接近全量微调失去参数效率。 |
| 怎么用 | 实际应用中r=8或r=16是常见平衡选择；对不同权重矩阵（q/k/v/o）应用LoRA效果不同。 |
| 原理和工作流程 | 论文实验表明r从1增到4、8时效果提升明显，继续增到16、32、64时收益递减甚至饱和。过小r（如1）表达能力不足，过大r接近全参数微调失去参数效率优势。 |
| 缺点 | r越大不一定效果越好（收益递减）；最优r依赖任务和数据需实验确定；r增大一定增加参数量。 |

### 6. 在 RLHF（Reinforcement Learning from Human Feedback）流程中，Reward Model 的训练数据格式是什么？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF中奖励模型训练使用的(prompt, chosen_response, rejected_response)偏好对数据格式。 |
| 能做什么 | 标注者对同一prompt的多个response比较选择更偏好的；形成chosen-rejected三元组；用Bradley-Terry模型训练。 |
| 怎么用 | 数据格式：(prompt, chosen, rejected)三元组；损失L=-E[log(σ(r(x,y_w)-r(x,y_l)))]。 |
| 原理和工作流程 | 标注人员比较同一prompt的多个response，选择更偏好的形成偏好对。训练时用Bradley-Terry模型让RM给chosen更高分数给rejected更低分数。偏好比较比连续打分更可靠，因为人类难以给出精确分数但相对比较更一致。 |
| 缺点 | 人类难以给出精确连续分数（故不用score格式）；偏好对仅提供相对信息无绝对质量标准；标注者偏好不一致引入噪声。 |

### 7. RLHF 流程中，PPO（Proximal Policy Optimization）阶段的主要挑战是什么？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | PPO阶段需同时维护4个模型（Policy、Reference、Reward、Value）导致的显存开销大和训练不稳定问题。 |
| 能做什么 | 识别PPO的工程挑战；理解4个模型的角色；认识reward hacking和策略崩溃等不稳定现象。 |
| 怎么用 | 4个模型：Actor(策略)、Reference(KL约束)、Reward(奖励信号)、Critic(价值估计)；需精细超参数调优。 |
| 原理和工作流程 | PPO阶段需同时加载Actor Model（待优化策略）、Reference Model（计算KL散度约束）、Reward Model（提供奖励信号）、Critic/Value Model（估计状态价值计算优势）。四个模型内存开销巨大，RL训练本身的不稳定性（reward hacking、策略崩溃）需精细超参数调优。这也是DPO被提出的重要动机。 |
| 缺点 | 4个模型显存开销巨大；RL训练不稳定需大量调参；reward hacking和策略崩溃风险；这也是DPO等方法提出的动机。 |

### 8. DPO（Direct Preference Optimization）相比 RLHF 的核心优势是什么？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | DPO通过数学推导将偏好优化目标重新参数化，直接从偏好数据优化策略模型，省去RM和PPO两个阶段。 |
| 能做什么 | 不需要Reward Model和RL训练；将偏好对转化为二元交叉熵分类损失；训练更稳定计算开销更小。 |
| 怎么用 | DPO将问题转化为简单分类损失，理论基础是最优策略和Reward函数间存在一一映射关系。 |
| 原理和工作流程 | DPO通过数学推导证明最优策略和Reward函数之间存在一一映射关系，因此可以直接从偏好数据中提取最优策略。省去了显式训练Reward Model和PPO强化学习两个阶段，将RLHF三阶段简化为SFT加DPO两阶段。训练更稳定（标准监督学习范式），计算开销更小（无需多模型多步采样）。 |
| 缺点 | 完全离线无法利用在线探索收益；偏好数据分布与策略分布差异大时效果可能下降；需要预训练模型作为起点。 |

### 9. DPO 损失函数中，隐含的 KL 散度约束是通过什么方式体现的？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | DPO通过Reference Model的概率比值隐式控制策略偏离程度，而非显式加KL散度项。 |
| 能做什么 | 通过log-ratio隐式约束KL散度；β参数控制偏离惩罚强度；β越大对偏离惩罚越强。 |
| 怎么用 | L_DPO = -E[log σ(β×(log(π_θ(y_w\|x)/π_ref(y_w\|x)) - log(π_θ(y_l\|x)/π_ref(y_l\|x))))]。 |
| 原理和工作流程 | DPO损失函数中比较chosen和rejected在策略模型和参考模型下的对数概率比值差，隐式约束了KL散度。β控制偏离程度：β越大策略偏离参考模型的惩罚越强。通过log-ratio而非显式KL项实现约束，是DPO数学推导的自然结果。 |
| 缺点 | 隐式约束不如显式KL项直观；β选择敏感太大压制对齐太小无法约束；log-ratio在概率接近0时数值不稳定。 |

### 10. 以下关于模型量化的描述，哪个是正确的？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | INT8量化将FP32权重映射到INT8整数，模型大小减少约4倍且基本不损失精度的量化技术。 |
| 能做什么 | 减少模型大小和显存带宽需求；加速推理；支持GPTQ、AWQ、GGUF等多种量化方案。 |
| 怎么用 | INT8量化：FP32(32位)→INT8(8位)，模型大小减少约4倍；带校准的量化可基本不损失精度。 |
| 原理和工作流程 | INT8量化将32位浮点权重映射到8位整数，理论模型大小减少4倍。现代量化技术（尤其是带校准的量化）通常能在基本不损失精度的情况下实现显著压缩和加速。常用方案包括GPTQ（基于近似二阶信息的一次性量化）、AWQ（激活感知量化）、GGUF/GGML（CPU友好格式）。 |
| 缺点 | 量化后模型仅用于推理不能直接用于训练；低位量化（如4-bit）可能有精度损失；不同量化方案精度和速度差异大。 |

### 11. FlashAttention 的核心优化原理是什么？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 通过分块计算和重计算策略减少HBM读写，将Attention从IO-bound变为Compute-bound的优化技术。 |
| 能做什么 | 大幅减少HBM读写次数；将O(N²)内存访问优化为近似O(N)分块访问；实现2-4倍加速。 |
| 怎么用 | Tiling将输入分块计算；Recomputation在反向传播时重新计算softmax而非存储中间结果。 |
| 原理和工作流程 | 标准Attention计算中QK^T矩阵和softmax后的attention weights需完整写入HBM成为IO瓶颈。FlashAttention通过Tiling（将输入分块）和Recomputation（反向传播时重新计算softmax而非存储中间结果），大幅减少HBM读写次数，将标准Attention的O(N²)内存访问优化为近似O(N)的分块访问模式。 |
| 缺点 | 实现复杂需要自定义CUDA内核；重计算增加少量计算量换取IO节省；对小序列加速效果不明显。 |

### 12. vLLM 中 PagedAttention 的核心思想是什么？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 借鉴操作系统虚拟内存分页机制，将KV cache划分为固定大小block按需分配和回收的推理优化技术。 |
| 能做什么 | 近乎零显存浪费；支持物理上非连续的KV cache存储；实现高效显存共享（并行采样共享prompt KV cache）。 |
| 怎么用 | 将每个序列的KV cache划分为固定大小block（类似内存页），block不需要连续存储，按需分配回收。 |
| 原理和工作流程 | 传统方案预分配最大长度的KV cache导致大量显存碎片。PagedAttention借鉴OS虚拟内存分页思想，将KV cache划分为固定大小block，block不需要连续存储。好处：近乎零显存浪费（消除碎片）、支持非连续存储、实现高效显存共享（并行采样的序列可共享相同prompt的KV cache）。 |
| 缺点 | block管理有少量额外开销；非连续存储的访存模式可能影响缓存命中率；实现复杂度高于连续分配。 |

### 13. 关于 Speculative Decoding（投机解码），以下描述正确的是？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 使用小模型快速生成候选token再由大模型并行验证的无损推理加速技术。 |
| 能做什么 | 小模型自回归生成K个候选token；大模型一次性并行验证；接受或拒绝每个候选token；输出分布与target model完全相同。 |
| 怎么用 | draft model生成K个候选token→target model并行验证→接受概率匹配的token→拒绝的用target model分布重采样。 |
| 原理和工作流程 | 轻量级draft model自回归生成K个候选token，target model一次性并行验证。根据target model概率分布接受或拒绝每个候选token，被拒绝的token用target model分布重新采样。验证阶段是并行的，且理论上保证输出分布与target model完全相同，是无损加速方案。 |
| 缺点 | 需要额外的小模型（draft model）；候选token接受率低时加速效果有限；不适合计算量远小于IO量的场景。 |

### 14. 在模型部署中，Continuous Batching（连续批处理）相比 Static Batching 的优势是什么？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 允许在序列完成时动态替换新请求的迭代级batch管理技术，消除静态批处理的GPU空闲时间。 |
| 能做什么 | 序列生成EOS后立即从batch移除；同时插入新请求；大幅提升GPU利用率和系统吞吐量。 |
| 怎么用 | 迭代级别动态管理batch：序列完成后移除→插入新请求→继续生成，而非等待整个batch完成。 |
| 原理和工作流程 | Static Batching要求batch中所有序列同时开始同时结束，短序列完成后GPU空闲等待长序列（木桶效应）。Continuous Batching在迭代级别动态管理batch：序列生成EOS后立即移除，同时插入新请求。大幅提升GPU利用率和吞吐量，是vLLM、TGI等现代推理框架的标准特性。 |
| 缺点 | 实现复杂度高于静态批处理；动态batch管理有少量调度开销；需配合PagedAttention等显存管理技术才能发挥最大效果。 |

### 15. GPTQ 量化算法中，使用二阶信息（Hessian 矩阵）的目的是什么？ ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | GPTQ使用Hessian矩阵的逆逐列量化权重并更新剩余权重，以补偿量化误差最小化输出扰动。 |
| 能做什么 | 逐列量化权重矩阵；每次量化一列后用Hessian逆更新剩余权重补偿误差；在4-bit下保持更好精度。 |
| 怎么用 | 逐列量化→计算Hessian矩阵→用Hessian逆更新未量化权重→最小化整体输出扰动。 |
| 原理和工作流程 | GPTQ是基于近似二阶信息的一次性权重量化方法。核心思想：逐列量化权重矩阵，每次量化一列后使用Hessian矩阵的逆来更新剩余未量化的权重，将量化误差传播到后续权重中最小化整体输出扰动。相比直接量化，GPTQ能在更低位宽（如4-bit）下保持更好精度。 |
| 缺点 | Hessian矩阵计算和求逆开销大；对校准数据集敏感；实现复杂度高于简单量化方案。 |

### 1. 简述 Transformer 的 Encoder-Decoder 架构与 Decoder-Only 架构的区别，并说明各自适用场景。 ★

| 维度 | 内容 |
|------|------|
| 是什么 | Transformer两种主流架构的区别：Encoder-Decoder用双向注意力编码输入再单向生成，Decoder-Only仅用因果注意力统一处理输入输出。 |
| 能做什么 | Encoder-Decoder适合需要深度理解输入后再生成的任务；Decoder-Only适合开放式生成和大规模预训练；明确各自适用场景。 |
| 怎么用 | Encoder-Decoder：Encoder双向注意力+Decoder单向+Cross-Attention；Decoder-Only：仅因果注意力+Next Token Prediction。 |
| 原理和工作流程 | Encoder-Decoder架构（如T5、BART）：Encoder使用双向自注意力看到整个输入序列，Decoder用因果掩码逐token生成，通过Cross-Attention关注Encoder输出。适合翻译、摘要等seq2seq任务。Decoder-Only架构（如GPT、LLaMA）：仅含因果注意力，将输入输出拼接在同一序列处理，训练目标为Next Token Prediction。适合对话、代码生成等开放式生成。关键区别：Encoder-Decoder在Encoder阶段有双向上下文适合深度理解，Decoder-Only更统一简洁适合大规模预训练和通用生成。 |
| 缺点 | Encoder-Decoder参数效率低于Decoder-Only；Decoder-Only单向注意力无法利用右侧上下文；架构选择需根据任务特点权衡。 |

### 2. 什么是自注意力机制中的缩放因子 √d_k？为什么需要它？ ★

| 维度 | 内容 |
|------|------|
| 是什么 | Scaled Dot-Product Attention中除以√d_k的缩放操作，防止点积值过大导致softmax梯度消失。 |
| 能做什么 | 将点积方差控制在1左右；使softmax输出更平滑；保证梯度稳定不进入饱和区。 |
| 怎么用 | Attention(Q,K,V) = softmax(QK^T / √d_k) × V，其中d_k为每个头的维度。 |
| 原理和工作流程 | 当d_k较大时Q和K的点积值很大，大值经softmax后落入梯度极小的饱和区域（概率分布接近one-hot）导致梯度消失。假设Q和K各分量独立且均值为0方差为1，则QK^T每个元素方差为d_k。除以√d_k后方差变为1，有效避免softmax饱和。 |
| 缺点 | 缩放因子是经验性设计非严格最优；在某些特殊分布下可能不需要缩放；对d_k很小的场景影响不大。 |

### 3. 请详细说明 LoRA 的数学原理，并解释为什么它能在极少参数的情况下实现有效微调。 ★★

| 维度 | 内容 |
|------|------|
| 是什么 | LoRA将权重更新ΔW约束为低秩分解ΔW=BA，用极少参数实现有效微调的数学原理和有效性解释。 |
| 能做什么 | 量化参数量从d×k降至(d+k)×r；通过低秩假设和隐式正则化实现高效微调；推理时合并权重零开销。 |
| 怎么用 | W₀∈R^(d×k)，ΔW=BA，B∈R^(d×r)，A∈R^(r×k)，r远小于min(d,k)；h=W₀x+BAx；A高斯初始化B零矩阵初始化。 |
| 原理和工作流程 | 数学原理：对预训练权重W₀，LoRA将微调更新ΔW约束为低秩分解ΔW=BA，参数量从d×k降至(d+k)×r。初始化A为高斯B为零使训练开始ΔW=0。用α/r缩放增量权重。有效性原因：低秩假设（预训练模型已学到通用特征，下游适配只需低秩子空间调整）；隐式正则化（低秩约束防止小数据集过拟合）；多任务友好（不同任务训练不同LoRA共享基座）；推理零开销（BA合并到W₀计算量不变）。 |
| 缺点 | 低秩假设在某些复杂任务上可能不成立；rank选择依赖实验；低秩约束可能限制表达能力。 |

### 4. 请描述 RLHF 的完整三阶段流程，并说明每个阶段的目的和关键技术细节。 ★★

| 维度 | 内容 |
|------|------|
| 是什么 | RLHF三阶段SFT（监督微调）、RM（奖励模型）、PPO（强化学习优化）的完整流程、目的和技术细节。 |
| 能做什么 | SFT让模型学会遵循指令；RM训练模拟人类偏好的奖励函数；PPO用RM信号优化策略同时KL约束防偏离。 |
| 怎么用 | SFT：交叉熵损失训练；RM：Bradley-Terry负对数似然L=-E[log(σ(r(x,y_w)-r(x,y_l)))]；PPO：max E[r(x,y)-β·KL(π_θ\|π_ref)]。 |
| 原理和工作流程 | 阶段一SFT：用高质量(prompt,response)指令对微调预训练模型，标准交叉熵损失，输出SFT模型作为后续初始策略。阶段二RM：用人工偏好对(prompt,chosen,rejected)训练奖励模型，Bradley-Terry负对数似然损失，标注质量至关重要需明确标准（有用性、安全性、真实性）。阶段三PPO：用RM奖励信号优化策略，需Actor/Reference/Reward/Critic四个模型，目标函数含RM奖励和KL散度约束防止reward hacking，挑战是训练不稳定和显存开销大。 |
| 缺点 | 三阶段流程长误差累积；RM质量直接决定PPO效果；PPO训练不稳定需大量调参；4个模型显存开销大。 |

### 5. 请对比 DPO 和 RLHF 的异同，包括数学原理、工程实现和适用场景。 ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | DPO和RLHF(PPO)在核心思想、训练阶段、模型数量、数学基础、稳定性、计算开销、数据需求、适用场景上的系统对比。 |
| 能做什么 | RLHF三阶段SFT→RM→PPO需4个模型；DPO两阶段SFT→DPO需2个模型；DPO更稳定计算更小但完全离线。 |
| 怎么用 | RLHF：偏好对+在线采样，大规模高质量标注在线迭代；DPO：离线偏好对，有限资源快速迭代。 |
| 原理和工作流程 | RLHF核心思想先训练RM再用RL优化策略，三阶段需4个模型，数学基础为Bradley-Terry+PPO策略梯度，训练不稳定需大量调参，计算开销大，需偏好对加在线采样，适合大规模高质量标注在线迭代。DPO核心思想直接从偏好数据优化策略跳过RM，两阶段需2个模型，数学基础为闭式解推导将RL目标转化为分类损失，训练稳定标准监督学习，计算开销小单次前向传播，需离线偏好对，适合有限资源快速迭代。DPO局限性：完全离线无法利用在线探索，偏好数据分布与策略分布差异大时效果下降，迭代DPO可部分缓解。 |
| 缺点 | DPO完全离线无法在线探索；RLHF训练复杂不稳定成本高；两者各有局限最优方案可能是结合使用。 |

### 6. 什么是 KV Cache？它在推理加速中的作用是什么？有哪些限制？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 自回归推理时缓存已生成token的Key和Value向量避免重复计算的推理加速技术。 |
| 能做什么 | 将每次推理计算复杂度从O(n²)降至O(n)；对长序列生成加速显著；缓存历史token的K/V向量。 |
| 怎么用 | 生成第t个token时只需计算当前token的Q/K/V，然后与缓存的K/V进行Attention。 |
| 原理和工作流程 | 自回归推理时每个新token需与所有历史token进行Attention计算。KV Cache缓存已生成token的K和V向量，生成第t个token时只需计算当前token的Q/K/V，然后与缓存的K/V做Attention，避免重复计算历史token的K/V。将每次推理从O(n²)降至O(n)。限制：显存占用随序列长度和batch size线性增长成为长序列推理瓶颈；传统预分配方案造成显存碎片；不同请求KV Cache相互独立无法共享；超长上下文（128K）时KV Cache可能超GPU显存容量。 |
| 缺点 | 显存占用随序列长度线性增长成为瓶颈；预分配方案造成显存碎片；无法跨请求共享；超长上下文时可能超显存容量。 |

### 7. 请解释模型量化中的对称量化与非对称量化的区别，并说明各自的优缺点。 ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 对称量化零点固定为0量化范围对称分布，非对称量化零点根据数据分布计算量化范围完整覆盖数据区间。 |
| 能做什么 | 对称量化实现简单计算效率高；非对称量化量化范围利用率更高对非对称分布精度更好；权重用对称激活用非对称。 |
| 怎么用 | 对称：q=round(r/scale)，scale=max(\|r\|)/(2^(b-1)-1)；非对称：q=round((r-zero_point)/scale)。 |
| 原理和工作流程 | 对称量化映射公式q=round(r/scale)，零点固定为0，量化范围对称分布（如INT8的[-127,127]）。优点实现简单计算效率高无需处理零点偏移，缺点数据分布不对称时量化范围利用率低精度损失大。非对称量化映射公式q=round((r-zero_point)/scale)，零点根据数据实际分布计算，量化范围可完整覆盖数据区间。优点量化范围利用率更高对非对称分布精度更好，缺点计算时需处理零点偏移略微增加开销。选择建议：权重通常用对称量化（分布近似对称），激活值通常用非对称量化（ReLU等输出非负分布不对称），现代方案如AWQ根据每通道分布自适应选择。 |
| 缺点 | 对称量化对非对称分布精度损失大；非对称量化需处理零点偏移增加计算开销；选择策略依赖经验。 |

### 9. 什么是 Catastrophic Forgetting（灾难性遗忘）？在微调过程中如何缓解？ ★★

| 维度 | 内容 |
|------|------|
| 是什么 | 模型微调时过度适应新任务数据分布导致原始预训练能力显著下降的现象，及五种缓解策略。 |
| 能做什么 | 识别灾难性遗忘的表现；使用PEFT、混合训练、正则化约束、渐进式微调、多任务学习缓解。 |

| 原理和工作流程 | 灾难性遗忘指模型微调下游任务时过度适应新数据分布导致预训练能力下降。缓解策略：参数高效微调PEFT（LoRA/Adapter只微调少量参数保持大部分预训练权重不变天然抗遗忘）；混合训练（微调数据中混入预训练数据保持通用能力）；正则化约束（EWC对重要参数施更大变化惩罚，KL散度约束限制策略偏离）；渐进式微调（先微调顶层再逐步解冻更多层温和适应）；多任务学习（同时训练多相关任务增强泛化）。 |
| 缺点 | PEFT在复杂任务上可能表达能力不足；混合训练需额外预训练数据；EWC需计算参数重要性增加开销；渐进式微调流程复杂耗时长。 |

| 原理和工作流程 | LoRA配置：target_modules覆盖q/k/v/o/gate/up/down全部线性层最大化效果，r=8对13B足够避免过拟合，alpha=16缩放强度适中，dropout=0.05正则化，lr=1e-4（LoRA可用更高学习率），bf16混合精度，DeepSpeed ZeRO-2分布式。多语言平衡：温度采样平衡数据量（Python:Java:Go=1:1:1.2给Go更高权重），分阶段训练（先混合3 epoch再对弱语言补训1 epoch），每语言独立验证集用Pass@k监控。DPO策略：用测试用例执行结果作自动化偏好信号（通过>未通过），结合人工评审把控风格效率，β=0.1适中KL约束，参考模型为SFT后的LoRA模型，每语言独立或均衡混合DPO训练。 |
| 缺点 | 三种语言能力可能不均衡需持续监控；DPO偏好信号依赖测试用例质量；Go语言数据量少(5000条)可能不足；多语言LoRA可能存在语言间干扰。 |

### 场景三：大模型推理服务的性能优化方案 ★★★

| 维度 | 内容 |
|------|------|
| 是什么 | LLaMA-3-70B推理服务从P50延迟3.5秒/QPS=5优化到P50<1秒/QPS>20的完整方案，涵盖模型优化、分布式部署、框架调优和调度策略。 |
| 能做什么 | AWQ 4-bit量化(140GB→35GB)；Tensor Parallelism(TP=4)多实例部署；vLLM(PagedAttention+Continuous Batching)；Prefill/Decode分离调度。 |
| 怎么用 | 模型：AWQ 4-bit+KV Cache FP8量化+FlashAttention-2；部署：TP=4×2实例+负载均衡；框架：vLLM(max_num_seqs=64,gpu_mem=0.92)；调度：优先级队列+动态batch+Prefill/Decode分离。 |
| 原理和工作流程 | 模型层面：AWQ 4-bit量化将70B从140GB降至35GB，KV Cache FP8量化减50%显存支持更大batch，FlashAttention-2减少显存读写。分布式部署：TP=4将模型切分到4张GPU（每卡9GB），剩余4卡部署第二实例，负载均衡横向扩展。框架优化：vLLM开启PagedAttention消除KV Cache碎片，Continuous Batching动态管理batch，配置max_num_seqs=64/max_model_len=8192/gpu_memory_utilization=0.92。调度策略：优先级队列短请求优先减少Head-of-Line Blocking，请求合并设50ms最大等待时间，Prefill(Compute-bound)与Decode(Memory-bound)分离部署到不同GPU组独立优化。预期效果：P50从3.5s降至<1s，P99从8s降至<3s，QPS从5提升到20-30。渐进式上线：灰度发布10%→50%→100%，A/B测试对比质量，保持FP16回滚预案。 |
| 缺点 | 4-bit量化可能导致轻微质量下降需A/B验证；TP=4的通信开销在高负载时可能成为瓶颈；Prefill/Decode分离增加系统复杂度；8卡资源投入大。 |
