# Python核心 - 概念对比速查

---

### Python vs Java

| 对比维度 | Python | Java |
|---------|--------|------|
| 核心定位 | 解释型、动态类型、通用脚本语言，强调简洁和可读性 | 编译型、静态类型、面向对象企业级语言，强调健壮性和可维护性 |
| 适用场景 | 数据分析、AI/ML、自动化脚本、快速原型、Web后端 | 企业级后端、Android开发、大数据处理（Hadoop/Spark）、金融系统 |
| 性能特点 | 解释执行较慢，GIL限制多线程，CPU密集型任务需多进程 | JIT编译优化，JVM性能优秀，真正多线程，启动慢但运行快 |
| 类型系统 | 鸭子类型，运行时检查，灵活但缺乏编译期保障 | 静态强类型，编译期检查，泛型支持完善，类型安全高 |
| 选择建议 | 适合快速开发、数据科学、AI领域；代码量少、迭代快 | 适合大型团队协作、高并发系统、长期维护的企业级项目 |

### 列表 vs 元组 vs 集合 vs 字典

| 对比维度 | 列表（list） | 元组（tuple） | 集合（set） | 字典（dict） |
|---------|-------------|--------------|------------|-------------|
| 核心定位 | 有序可变序列，通用容器 | 有序不可变序列，用于固定数据 | 无序不重复元素集合 | 键值对映射，键唯一 |
| 适用场景 | 需要频繁增删改的顺序数据 | 多返回值、字典键、不希望被修改的数据 | 去重、成员检测、集合运算 | 查找、映射、计数、缓存 |
| 性能特点 | 尾部追加O(1)，中间插入O(n)，查询O(n) | 访问O(1)，不可变无需额外内存 | 成员检测O(1)，无序，元素必须可哈希 | 键查找O(1)，键必须可哈希 |
| 内存开销 | 有一定预留空间 | 比列表更紧凑，无额外预留 | 有哈希表开销 | 有哈希表开销 |
| 选择建议 | 需要动态增删改的顺序数据 | 固定不变的数据、需要哈希的场景 | 去重、集合运算、快速成员检测 | 键值映射、计数、缓存 |

### 深拷贝 vs 浅拷贝

| 对比维度 | 浅拷贝（shallow copy） | 深拷贝（deep copy） |
|---------|----------------------|---------------------|
| 核心定位 | 复制外层容器，内层元素仍共享引用 | 递归复制所有层级，完全独立的对象 |
| 适用场景 | 内层元素为不可变对象、只需修改外层结构 | 多层嵌套可变对象、需要完全独立的副本 |
| 性能特点 | 快，只复制一层引用 | 慢，递归复制所有层级，可能遇到循环引用 |
| 内存开销 | 小，内层元素共享 | 大，每层都创建新对象 |
| 选择建议 | `copy.copy()`：内层元素不可变或无需修改时 | `copy.deepcopy()`：嵌套可变对象且需要独立修改时 |
