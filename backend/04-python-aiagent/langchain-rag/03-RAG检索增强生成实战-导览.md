## 第一段：RAG 概念与架构

### 1.1 什么是 RAG（检索增强生成）

| 维度 | 内容 |
|------|------|
| 是什么 | 将信息检索与大语言模型结合，生成前先检索相关文档注入Prompt的技术架构。 |
| 能做什么 | 解决知识截止；抑制幻觉；注入领域知识；提供可追溯来源。 |
| 怎么用 | 用户提问 → 检索相关文档片段 → 拼入Prompt → LLM生成回答。 |
| 原理和工作流程 | 用户提问经检索模块从外部知识库召回相关文档片段，作为上下文拼入Prompt，LLM结合上下文生成回答，使答案基于真实文档可溯源，缓解训练截止与幻觉痛点。 |
| 缺点 | 检索质量决定上限，召回不准致答案错误；上下文拼接增加token消耗；构建维护知识库成本高。 |

---

### 1.2 RAG 与微调（Fine-tuning）的对比

| 维度 | 内容 |
|------|------|
| 是什么 | 对比RAG检索注入知识与微调更新模型参数两种知识增强方案的差异。 |
| 能做什么 | 权衡知识更新即时性；比较可解释性与计算成本；选择适用场景。 |
| 怎么用 | 知识频繁更新需溯源选RAG；风格格式定制选微调；混合方案先用微调再RAG。 |
| 原理和工作流程 | RAG检索外部文档注入Prompt，知识更新只需增删文档即时生效，可追溯到来源；微调在特定数据上继续训练模型权重，知识内化难以追溯，更新需重新训练耗算力。 |
| 缺点 | RAG受检索质量与上下文窗口制约；微调成本高且可能学到噪声；两者均无法完全消除幻觉。 |

---

### 1.3 RAG 的经典架构

| 维度 | 内容 |
|------|------|
| 是什么 | RAG系统多路召回加重排序加Prompt组装加LLM生成的标准架构。 |
| 能做什么 | 关键词/向量/混合多路召回；Reranker重排序；Prompt组装；LLM生成。 |
| 怎么用 | 多路检索 → 重排序 → Prompt组装 → LLM生成 → 最终回答。 |
| 原理和工作流程 | 用户提问同时经关键词、向量、混合多路检索召回候选，EnsembleRetriever融合后由Reranker重排序精选Top-K，拼入Prompt作为上下文，LLM据此生成最终回答。 |
| 缺点 | 架构链路长延迟高；各环节参数调优复杂；任一环节失效拖累整体效果。 |

## 第二段：文档加载与切分 & 向量化与存储

### 2.1 文档加载（Document Loader）

| 维度 | 内容 |
|------|------|
| 是什么 | LangChain将不同格式文档转换为统一Document对象的加载组件。 |
| 能做什么 | 加载PDF/Word/Markdown/网页/CSV；批量加载目录；保留元数据。 |
| 怎么用 | `PyPDFLoader("f.pdf").load()`；`DirectoryLoader(path, glob="**/*.md")`。 |
| 原理和工作流程 | 各Loader针对格式调用解析库提取文本，返回List[Document]，每个Document含page_content与metadata（来源、页码等），DirectoryLoader按glob匹配批量调用指定Loader。 |
| 缺点 | 不同格式解析质量参差，扫描版PDF需OCR；大文件加载占内存；元数据字段不统一需清洗。 |

---

### 2.2 文本切分（Text Splitter）

| 维度 | 内容 |
|------|------|
| 是什么 | 将长文档切分为合适文本块以适配嵌入模型与上下文限制的组件。 |
| 能做什么 | 按字符/递归字符/Token/Markdown标题切分；语义切分；控制块大小与重叠。 |
| 怎么用 | `RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200)`。 |
| 原理和工作流程 | chunk_size限定单块最大长度，chunk_overlap保留相邻块重叠维持语义连贯；RecursiveCharacterTextSplitter按分隔符优先级递归切分，SemanticChunker依相邻句嵌入相似度骤降处切分。 |
| 缺点 | 固定长度切分易破坏语义；chunk_size与overlap需反复调参；语义切分依赖嵌入模型成本高。 |

---

### 2.3 向量化（Embedding）

| 维度 | 内容 |
|------|------|
| 是什么 | 将文本转换为高维数值向量、语义相近者距离更近的过程。 |
| 能做什么 | 单条与批量向量化；选择云端或本地模型；按场景选型。 |
| 怎么用 | `OpenAIEmbeddings(model="text-embedding-3-small")`；`embed_query("文本")`。 |
| 原理和工作流程 | Embedding模型将文本编码为定长向量，语义相近文本在向量空间距离小，embed_query向量化查询，embed_documents批量向量化文档，向量维度与模型决定语义区分能力。 |
| 缺点 | 向量化质量依赖模型，领域术语效果可能不佳；API调用有成本与延迟；本地大模型占显存。 |

---

### 2.4 向量数据库

| 维度 | 内容 |
|------|------|
| 是什么 | 存储与高效检索向量化文档的专用数据库，如Chroma、FAISS、Milvus。 |
| 能做什么 | 持久化存储向量；相似度检索；带分数与元数据过滤检索；选型适配规模。 |
| 怎么用 | `Chroma.from_documents(docs, embedding=emb, persist_directory="./db")`。 |
| 原理和工作流程 | 向量库为向量建立索引（Flat/IVF/HNSW）加速近似最近邻检索，similarity_search计算查询向量与文档向量距离返回Top-K，同时存储原始文本与元数据供过滤与回显。 |
| 缺点 | 近似检索有精度损失；大规模数据索引构建慢；分布式部署运维复杂（Milvus）。 |

## 第三段：检索策略

### 3.1 相似度检索（Similarity Search）

| 维度 | 内容 |
|------|------|
| 是什么 | 最基本的检索方式，计算查询向量与文档向量距离返回最相似文档。 |
| 能做什么 | 基础Top-K检索；带分数检索；元数据过滤检索。 |
| 怎么用 | `vectorstore.similarity_search(query, k=4, filter={"source":"..."})`。 |
| 原理和工作流程 | 查询经嵌入转为向量，向量库按距离度量（L2/内积/余弦）计算与所有文档向量相似度，返回Top-K最相似文档，filter参数先按元数据筛选再排序。 |
| 缺点 | 仅按相似度排序易返回高度重复结果；不关注多样性；语义相近但无关文档被误召回。 |

---

### 3.2 MMR（最大边际相关性检索）

| 维度 | 内容 |
|------|------|
| 是什么 | 在相关性与多样性间取得平衡、避免返回高度相似重复结果的检索策略。 |
| 能做什么 | 兼顾相关性与多样性；调节lambda_mult权重；先取候选池再精选。 |
| 怎么用 | `vectorstore.max_marginal_relevance_search(query, k=4, fetch_k=20, lambda_mult=0.7)`。 |
| 原理和工作流程 | 先从向量库取fetch_k个候选，再迭代选择使MMR=λ*Sim(q,d)-(1-λ)*max Sim(d,d_j)最大的文档，λ越大越偏相关性，越小越偏多样性，从而选出既相关又多样的结果。 |
| 缺点 | 候选池fetch_k过小限制多样性；lambda_mult需调参；计算量高于普通相似度检索。 |

---

### 3.3 自查询检索（Self-Query Retrieval）

| 维度 | 内容 |
|------|------|
| 是什么 | 让LLM从自然语言问题自动提取结构化过滤条件与语义查询的检索方式。 |
| 能做什么 | 自动拆解语义查询与过滤条件；按元数据字段过滤；支持比较运算。 |
| 怎么用 | `SelfQueryRetriever.from_llm(llm, vectorstore, document_contents, metadata_field_info)`。 |
| 原理和工作流程 | LLM依据元数据字段描述将自然语言拆为语义查询部分与结构化过滤条件，向量库先按过滤条件筛文档再做语义相似度检索，verbose可查看LLM生成的查询结构。 |
| 缺点 | 依赖LLM解析能力可能提取错误；元数据字段需预先定义描述；复杂条件解析不稳定。 |

---

### 3.4 多路召回与重排序（Multi-Route Retrieval & Reranking）

| 维度 | 内容 |
|------|------|
| 是什么 | 结合多种检索策略召回再用Cross-Encoder重排序精选的检索方案。 |
| 能做什么 | 向量/BM25/MMR多路召回；加权融合；Cross-Encoder精排；商业Rerank API。 |
| 怎么用 | `EnsembleRetriever(retrievers=[...], weights=[...])` + `CrossEncoderReranker(top_n=5)`。 |
| 原理和工作流程 | 多路检索器各召回Top-K，EnsembleRetriever按权重RRF融合去重形成候选集，Cross-Encoder将query与每篇文档同时输入模型计算精确相关性分数重排，取Top-N最终结果。 |
| 缺点 | 链路长延迟与成本高；Cross-Encoder计算量大；多路权重与top_n需调参。 |

## 第五段：RAG 评估体系

### 5.1 RAGAS 框架概述

| 维度 | 内容 |
|------|------|
| 是什么 | RAGAS是目前最主流的RAG系统评估框架，定义核心评估维度。 |
| 能做什么 | 检索质量评估；生成质量评估；多维度量化RAG效果。 |
| 怎么用 | `from ragas import evaluate`；传入dataset与metrics执行评估。 |
| 原理和工作流程 | RAGAS将评估分为检索质量（Context Recall/Precision/Relevancy）与生成质量（Faithfulness/Answer Relevance）两大维度，用LLM作为评判自动计算各指标分数量化RAG系统表现。 |
| 缺点 | LLM评判有主观性与成本；指标定义版本间变动；需人工标注ground_truth增加工作量。 |

---

### 5.2 核心评估指标详解

| 维度 | 内容 |
|------|------|
| 是什么 | RAGAS定义的忠实度、答案相关性、上下文召回率精确度相关性等核心指标。 |
| 能做什么 | 衡量回答是否基于文档；回答是否切题；检索是否覆盖与精准。 |
| 怎么用 | evaluate传入faithfulness、answer_relevancy、context_recall、context_precision等metrics。 |
| 原理和工作流程 | Faithfulness为可追溯陈述占比，Answer Relevance为回答与问题匹配度评分，Context Recall为检索覆盖所需信息比例，Context Precision为相关文档占比，Context Relevancy为相关句子占比。 |
| 缺点 | 各指标依赖LLM拆解与判断有误差；计算耗时与token成本高；指标间可能相互制约。 |

---

### 5.3 RAGAS 评估实战

| 维度 | 内容 |
|------|------|
| 是什么 | 用RAGAS对RAG系统执行评估的完整代码实践。 |
| 能做什么 | 准备评估数据集；执行多指标评估；查看整体与逐条结果；自定义延迟指标。 |
| 怎么用 | `evaluate(dataset=dataset, metrics=[...], llm=llm, embeddings=emb)`。 |
| 原理和工作流程 | 构建含question/answer/contexts/ground_truth的Dataset，evaluate用指定LLM与嵌入模型计算各指标，返回整体分数与逐条DataFrame，可自定义函数统计检索生成延迟与P95。 |
| 缺点 | 评估数据集质量决定评估可信度；LLM评估调用成本高；逐条结果排查耗时。 |

---

### 5.4 Faithfulness（忠实度）深度解析

| 维度 | 内容 |
|------|------|
| 是什么 | 衡量回答是否严格基于检索文档、是否存在幻觉的核心评估指标。 |
| 能做什么 | 拆解回答为原子陈述；逐条验证是否可由文档支撑；计算可验证陈述占比。 |
| 怎么用 | Faithfulness = 可验证陈述数 / 总陈述数。 |
| 原理和工作流程 | 先用LLM将回答拆解为原子陈述，再对每条陈述判断能否在检索文档中找到支撑，可验证陈述数除以总陈述数得忠实度分数，分数越高幻觉越少。 |
| 缺点 | 陈述拆解与验证依赖LLM判断有误差；隐含常识陈述难判定；计算需多次LLM调用成本高。 |

---

### 5.5 Answer Relevance（答案相关性）深度解析

| 维度 | 内容 |
|------|------|
| 是什么 | 衡量回答是否直接回应用户问题、避免答非所问的评估指标。 |
| 能做什么 | 基于回答反向生成问题；计算反向问题与原问题相似度；取均值量化相关性。 |
| 怎么用 | Answer Relevance = mean(反向问题与原问题余弦相似度)。 |
| 原理和工作流程 | 让LLM基于回答反向生成多个可能问题，计算这些反向问题与原始问题的余弦相似度取均值，相似度越高说明回答越切题，低则答非所问。 |
| 缺点 | 反向问题生成质量依赖LLM；语义相似但不切题的情况难识别；计算需嵌入与多次LLM调用。 |

---

### 5.6 RAG 评估最佳实践

| 维度 | 内容 |
|------|------|
| 是什么 | RAG系统评估的最佳实践与指标阈值参考。 |
| 能做什么 | 构建高质量评估集；多维度评估；持续监控迭代；设定指标阈值基线。 |
| 怎么用 | Faithfulness>=0.85；Answer Relevance>=0.80；Context Recall>=0.80；Context Precision>=0.75。 |
| 原理和工作流程 | 评估集覆盖多难度与边界样本并人工标注标准答案，从检索、生成、性能三维度量化评估，建立基线后每次架构变更重新评估，结合用户反馈迭代补充数据集。 |
| 缺点 | 高质量评估集构建成本高；阈值需按业务调整非通用；持续监控需工程化投入。 |
