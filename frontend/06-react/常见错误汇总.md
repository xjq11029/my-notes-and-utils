# React - 常见错误汇总

> 汇总本模块所有知识点的常见错误，从各源文件避坑指南提取。

---

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---------|---------|---------|---------|
| 在条件语句中使用 Hooks，状态错乱或报错"渲染的 Hook 比预期少" | Hooks 依赖调用顺序，条件调用导致链表索引错位 | 始终在函数组件顶层调用 Hooks，条件逻辑放在 Hooks 调用之后 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useEffect 闭包捕获过期值，数据不更新 | 依赖数组不完整，effect 不会重新执行，一直使用初始值 | 使用 ESLint 规则 `react-hooks/exhaustive-deps` 检查，诚实填写依赖数组 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useEffect 中直接使用 async 函数，控制台警告或清理函数失效 | useEffect 回调不能是 async（返回 Promise 而非清理函数） | 在 useEffect 内部定义 async 函数并调用，保持回调返回清理函数或 undefined | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useCallback 依赖空数组但内部使用了 state，回调始终使用初始 state | 闭包捕获了初始值，依赖为空不会重新创建函数 | 将状态加入依赖数组，或使用函数式更新 `setCount(c => c + 1)` | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 滥用 useMemo 缓存简单计算，代码复杂且性能反而下降 | useMemo 本身有开销（比较依赖、存储缓存），简单计算不值得缓存 | 仅对昂贵的计算（如大数组过滤、复杂数学运算）使用 useMemo | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 在 render 中创建新对象/函数，导致 React.memo 子组件仍然重渲染 | 每次渲染都创建新引用，浅比较判定为"变化" | 使用 useMemo 包裹对象和数组，useCallback 包裹函数 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| useLayoutEffect 中执行耗时操作，页面渲染阻塞、长时间白屏 | useLayoutEffect 同步执行，阻塞浏览器渲染 | 耗时操作移到 useEffect 中异步执行，useLayoutEffect 仅用于同步读取 DOM 尺寸 | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| Context 值变化导致所有消费者重渲染，性能差 | Context 值变化通知所有消费者，任一字段变化都触发全局渲染 | 拆分 Context 为多个独立 Context，或使用 useMemo 包裹 value | [React核心与Hooks导览](./01-React核心与Hooks-导览.md) |
| 使用 index 作为 key，列表重排时大量 DOM 更新，输入框内容错乱 | index 不稳定，顺序变化导致 key 对应关系错乱 | 使用数据唯一 ID 作为 key，无 ID 时用 nanoid 生成 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 使用随机数作为 key，每次渲染全部节点重建，性能极差 | key 每次变化，React 无法复用节点 | 使用稳定的唯一标识，绝对禁止 `Math.random()` | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 滥用 useMemo/useCallback，代码可读性下降，内存开销增加 | 每个 memo 都需要存储缓存和比较依赖 | 仅在确实需要优化时使用，优先通过组件拆分和状态提升解决问题 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| Context 未拆分，全局状态中任一字段变化，所有消费者重渲染 | 所有消费者订阅同一个 Context | 按业务领域拆分多个 Context | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| useEffect 依赖数组不完整，闭包引用过期值导致逻辑错误 | 内部使用的变量未声明为依赖 | 开启 ESLint 规则，诚实填写依赖 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 将整个组件树用 React.memo 包裹，比较开销超过渲染开销 | 浅比较本身也有开销 | 仅对渲染开销大的子组件使用 React.memo | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| 未使用生产模式构建，性能表现差 | 开发模式有额外的警告和严格模式检查 | 生产环境使用 `NODE_ENV=production` 构建 | [Diff算法与性能优化导览](./02-Diff算法与性能优化-导览.md) |
| BrowserRouter 刷新后非首页路径 404 | 服务器未配置 fallback，找不到对应 HTML 文件 | Nginx 配置 `try_files $uri /index.html`，或使用 HashRouter | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Redux state 直接修改，state 被修改但 UI 不更新 | 直接修改破坏了不可变性，React 无法检测变化 | 始终返回新对象，或使用 RTK 的 immer 集成直接修改 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| useSelector 返回整个 state，任何字段变化都触发重渲染 | useSelector 默认使用严格相等比较 | 精确选择需要的字段，或使用 shallowEqual 比较器 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 路由守卫未处理异步状态，未登录时短暂显示受保护页面 | 异步检查登录状态，初始状态为 null | 添加 loading 状态判断，在认证状态确定前显示加载中 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| Zustand selector 返回新引用，组件频繁重渲染 | selector 每次返回新对象，浅比较判定为变化 | 选择基本类型值，或使用 shallow 比较器 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| 嵌套路由忘记 Outlet，子路由不显示 | 缺少 Outlet 作为子路由渲染出口 | 在父组件中放置 `<Outlet />` | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
| createAsyncThunk 未处理错误，异常未被捕获、应用崩溃 | thunk 内部抛出异常未处理 | 使用 extraReducers 处理 rejected 状态，显示错误信息 | [路由与状态管理导览](./03-路由与状态管理-导览.md) |
