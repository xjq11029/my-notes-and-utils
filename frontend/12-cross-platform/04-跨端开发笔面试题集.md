### 1. ★ uniapp 中条件编译的 `#ifdef` 和 `#ifndef` 是什么阶段的机制？

A. 运行时判断，通过 `process.env` 动态切换
B. 编译时处理，由编译器在打包阶段按目标平台裁剪代码
C. 构建时通过 Babel 插件转换
D. 运行时通过 `uni.getSystemInfoSync()` 判断平台后动态加载

**答案：B**

**解析**：uniapp 的条件编译是**编译时**机制，在打包阶段由编译器处理。`#ifdef PLATFORM` 表示仅在目标平台保留代码块，`#ifndef PLATFORM` 表示仅在非目标平台保留代码块。编译器会根据目标平台，在编译产物中完全移除不属于该平台的代码块，因此不会增加运行时代码体积。条件编译可以在 `<template>`、`<script>`、`<style>` 以及 `.json` 配置文件中使用。

### 2. ★ uniapp 中 `pages.json` 的核心作用不包括以下哪项？

A. 注册页面路由和窗口样式配置
B. 配置底部 TabBar 导航栏
C. 配置分包加载和预加载规则
D. 管理组件间的状态共享

**答案：D**

**解析**：`pages.json` 是 uniapp 最核心的配置文件，负责页面路由注册（pages 数组）、全局窗口样式（globalStyle）、底部 TabBar 配置（tabBar）、分包配置（subPackages）和预加载规则（preloadRule）。组件间的状态共享由 Pinia 或 Vuex 管理，不属于 `pages.json` 的职责范围。

### 3. ★★ 关于 H5 端和小程序端的渲染引擎，以下说法正确的是？

A. 两者都使用浏览器内核的 DOM + CSSOM 渲染管线
B. 小程序采用双线程架构（渲染层 WebView + 逻辑层 JSCore），H5 使用浏览器单线程渲染
C. H5 和小程序都支持完整的 CSS 属性
D. 小程序中可以直接使用 `document.querySelector` 操作 DOM

**答案：B**

**解析**：H5 端运行在浏览器内核（WebKit/Blink）中，使用标准的 DOM + CSSOM 渲染管线，可以完整操作 DOM。小程序采用**双线程架构**，渲染层（WebView）和逻辑层（JSCore）是独立的两个线程，逻辑层通过 `setData` 与渲染层通信，逻辑层中没有 DOM 环境，无法使用 `document` 对象。小程序的 CSS 支持是 Web 标准的一个子集，部分属性（如 `backdrop-filter`、`position: sticky`）不支持。

### 4. ★★ uniapp 中 rpx 单位的换算规则是什么？

A. 1rpx 始终等于 1px
B. 屏幕宽度固定为 750rpx，在 iPhone 6（375px 宽）上 1rpx = 0.5px
C. 屏幕高度固定为 750rpx，根据屏幕高度等比换算
D. rpx 仅在小程序端生效，H5 端自动转换为 vw 单位

**答案：B**

**解析**：rpx（responsive pixel）是 uniapp 的响应式像素单位，规定屏幕宽度为 **750rpx**。换算公式为：`实际 px = 屏幕宽度(px) / 750 * rpx 值`。在 iPhone 6 上（屏幕宽度 375px），1rpx = 375/750 = 0.5px。设计稿通常以 750px 宽度为基准，设计师标注的 px 值直接使用 rpx 即可。rpx 在所有端（H5、小程序、App）均生效。

### 5. ★★ 小程序中 `setData` 为什么是性能瓶颈？以下说法**错误**的是？

A. 每次 setData 调用都涉及数据序列化和跨线程通信
B. setData 传递的数据量过大时，会导致渲染延迟
C. setData 是异步的，多次调用会自动合并，不会影响性能
D. 同一帧内多次 setData 会导致多次渲染，造成页面抖动

**答案：C**

**解析**：setData 每次调用都会经历：数据序列化（JSON.stringify）→ 跨线程通信（Native Bridge）→ 数据反序列化（JSON.parse）→ 视图层 Diff → 渲染更新。即使是异步的，多次频繁调用也会造成性能问题，因为每次调用都涉及跨线程通信开销。优化策略包括：合并多次 setData 为一次调用、只传递变化的数据、控制调用频率、减少传输数据量。

### 6. ★★ Service Worker 的生命周期正确顺序是？

A. activate → install → fetch → waiting
B. install → waiting → activate → fetch
C. fetch → install → waiting → activate
D. waiting → install → activate → fetch

**答案：B**

**解析**：Service Worker 的完整生命周期为：**install**（下载并预缓存关键资源）→ **waiting**（等待旧 SW 控制的页面全部关闭）→ **activate**（激活并清理旧缓存）→ **fetch**（拦截网络请求，应用缓存策略）。`skipWaiting()` 可以在 install 阶段跳过 waiting 直接激活；`clients.claim()` 可以在 activate 阶段立即接管所有已打开的页面。

### 7. ★★ 以下哪种 PWA 缓存策略最适合"API 数据接口，需要保证数据新鲜度，同时提供离线回退"的场景？

A. Cache First（缓存优先）
B. Network First（网络优先）
C. Stale-While-Revalidate（后台更新）
D. Cache Only（仅缓存）

**答案：B**

**解析**：**Network First** 策略先请求网络获取最新数据，网络成功时更新缓存；网络失败时回退到缓存数据，如果缓存也没有则返回离线回退页面。这最适合 API 数据场景——优先保证数据新鲜度，同时提供离线可用性。Cache First 适合静态资源；Stale-While-Revalidate 适合不要求实时性的数据（立即返回缓存，后台更新）；Cache Only 仅用于预缓存的静态资源。

### 8. ★ 关于 Shadow DOM 的样式隔离，以下说法正确的是？

A. Shadow DOM 内部的 CSS 样式会影响到外部页面的元素
B. 外部 CSS 样式可以穿透 Shadow DOM 边界影响内部元素
C. Shadow DOM 内部样式和外部样式完全隔离，互不影响（除继承属性外）
D. Shadow DOM 不支持任何 CSS 样式

**答案：C**

**解析**：Shadow DOM 提供完整的样式隔离机制：内部的 CSS 不会泄漏到外部，外部 CSS 也不会影响 Shadow DOM 内部（**可继承属性**如 `color`、`font-size` 除外）。通过 `:host` 选择器可以从内部定义宿主元素的样式，`::slotted()` 选择器可以选择通过 `<slot>` 传入的 Light DOM 元素。`mode: 'open'` 时外部可通过 `element.shadowRoot` 访问内部结构。

### 9. ★★ Web Components 的三大核心技术不包括以下哪项？

A. Custom Elements（自定义元素）
B. Shadow DOM（影子 DOM）
C. HTML Templates（HTML 模板）
D. Virtual DOM（虚拟 DOM）

**答案：D**

**解析**：Web Components 由三大浏览器原生技术组成：**Custom Elements**（自定义 HTML 标签，定义元素行为和生命周期回调）、**Shadow DOM**（封装组件内部 DOM 和样式，与外部隔离）、**HTML Templates**（通过 `<template>` 标签声明式定义可复用的 DOM 片段）。Virtual DOM 是 React/Vue 等框架的概念，不是 Web Components 的核心技术。

### 10. ★★★ 关于 uniapp 分包加载，以下说法**错误**的是？

A. 分包可以将非首屏页面放入独立分包，减少主包大小
B. 微信小程序主包大小限制为 2MB，整个小程序不超过 20MB
C. 分包中的页面可以直接通过 `uni.navigateTo` 跳转，无需任何额外配置
D. `preloadRule` 可以在进入首页时预下载高频分包，提升后续页面打开速度

**答案：C**

## 二、简答题（8 题）

### 1. ★★ uniapp 条件编译的原理是什么？`#ifdef` 和 `#ifndef` 的区别和使用场景？

**答案要点**：

**原理**：
- 条件编译是**编译时**机制，在打包阶段由 uniapp 编译器处理，不会增加运行时代码体积
- 编译器解析 `.vue` 文件时，识别 `#ifdef` / `#ifndef` 注释指令，根据目标平台决定保留或移除代码块
- 每个 `#ifdef` / `#ifndef` 必须对应一个 `#endif` 结束标记

**`#ifdef` 和 `#ifndef` 的区别**：
- `#ifdef PLATFORM`：如果当前编译目标是 PLATFORM 平台，则**保留**该代码块
- `#ifndef PLATFORM`：如果当前编译目标**不是** PLATFORM 平台，则**保留**该代码块

**使用场景**：
- `<template>` 中：不同平台渲染不同的 UI 组件（如小程序使用 `<button open-type="getUserInfo">`，H5 使用普通 `<button>`）
- `<script>` 中：不同平台调用不同的 API（如 H5 使用 `localStorage`，小程序使用 `uni.setStorageSync`）
- `<style>` 中：不同平台应用不同的 CSS（如 H5 端支持 `backdrop-filter`，小程序端降级为半透明背景）
- 配置文件（`pages.json`、`manifest.json`）中：不同平台的专属配置

**常见平台标识**：`H5`、`MP-WEIXIN`、`MP`（所有小程序）、`APP-PLUS`、`APP`（所有 App 端）、`VUE2`、`VUE3`

> - [uni-app 官方文档](https://uniapp.dcloud.net.cn/)
> - [uni-app 条件编译](https://uniapp.dcloud.net.cn/tutorial/platform.html)

### 2. ★★ H5 端和小程序端的渲染引擎有什么本质区别？这对开发有什么影响？

**答案要点**：

**H5 端渲染**：
- 运行在浏览器内核（WebKit/Blink）中，使用标准的 DOM + CSSOM 渲染管线
- 单线程模型（主线程 + 合成线程），可以直接操作 DOM
- 完整的 CSS 属性支持，灵活的 Web API
- 事件冒泡遵循 DOM 树结构

**小程序端渲染**：
- 采用**双线程架构**：渲染层（WebView）+ 逻辑层（JSCore），两个线程独立运行
- 逻辑层通过 `setData` 向渲染层传递数据，渲染层据此更新视图
- 逻辑层中**没有 DOM 环境**，无法使用 `document`、`window` 等对象
- 使用**同层渲染**技术，原生组件（video、map、canvas）层级最高

**对开发的影响**：
1. 不能用 `document.querySelector` 等 DOM API，需用 `uni.createSelectorQuery()` 替代
2. 不能用 `v-html`，需用 `<rich-text>` 组件替代
3. 原生组件无法被普通 view 覆盖，需用 `cover-view` / `cover-image`
4. 部分 CSS 属性不支持（`backdrop-filter`、`position: sticky`、`@media` 等）
5. `<scroll-view>` 内 `position: fixed` 失效
6. setData 性能敏感，需要优化数据量和调用频率

> - [uni-app 官方文档](https://uniapp.dcloud.net.cn/)
> - [uni-app 性能优化](https://uniapp.dcloud.net.cn/tutorial/performance.html)

### 3. ★★★ 小程序中 setData 的性能瓶颈是什么？请列出至少 5 条优化策略。

**答案要点**：

**性能瓶颈**：每次 `setData` 调用都会经历以下流程：
1. 数据序列化（JSON.stringify）
2. 跨线程通信（通过 Native Bridge 从逻辑层 JSCore 传递到渲染层 WebView）
3. 数据反序列化（JSON.parse）
4. 视图层 Diff 计算
5. 渲染更新

每次调用都涉及多次跨线程通信，当数据量大或频繁调用时，会造成严重的性能问题。

**优化策略**：

1. **合并 setData 调用**：将同一逻辑中多次 setData 合并为一次调用，减少跨线程通信次数
2. **只传递变化的数据**：不要将整个 data 对象传给 setData，使用数据路径精确更新（如 `'list[0].name'`）
3. **控制 setData 频率**：对高频操作（如滚动、拖拽）使用节流/防抖，避免一帧内多次 setData
4. **减少 setData 数据量**：不将非渲染数据放在 data 中（如原始数据缓存、请求 ID、事件处理器），将它们挂在 `this` 上作为非响应式属性
5. **单次数据量限制**：建议单次 setData 数据量不超过 256KB，避免传输耗时过长
6. **使用 WXS 响应事件**：在渲染层直接处理交互（如频繁的触摸事件），避免频繁跨线程通信
7. **分页加载**：列表数据分页加载，每次只 setData 当前页数据，不要一次性加载全部

### 4. ★★ 请描述 uniapp 小程序的完整首屏优化策略。

**答案要点**：

**1. 分包加载**：
- 将非首屏页面放入独立分包（subPackages），减少主包大小
- 微信小程序主包建议不超过 2MB，单个分包不超过 2MB
- 配置 `preloadRule` 在进入首页时预下载高频分包

**2. 组件懒加载**：
- 非首屏组件使用异步加载（`defineAsyncComponent` 或动态 `import()`）
- 首屏渲染完成后，通过 `requestIdleCallback` 或 `setTimeout` 延迟加载非核心组件

**3. 图片优化**：
- 图片懒加载：使用 `IntersectionObserver` 或 `loading="lazy"`（H5）
- 使用 WebP 格式（小程序基础库 2.9.0+ 支持）
- 首屏图片使用本地资源或 Base64 内联，减少网络请求

**4. 请求优化**：
- 在 `App.onLaunch` 中提前请求首屏数据（预取）
- 合并首屏接口请求，减少请求数量
- 使用数据缓存，二次进入直接展示缓存数据

**5. setData 优化**：
- 减少首屏渲染的 setData 次数和数据量
- 骨架屏方案：先展示骨架屏，数据加载完成后更新

**6. 代码层面**：
- 移除未使用的依赖和代码
- 使用条件编译，不同平台不包含无用代码
- 开启代码压缩和 Tree Shaking

### 5. ★★ 请描述 Service Worker 的完整生命周期，以及 `skipWaiting()` 和 `clients.claim()` 的作用。

**答案要点**：

**生命周期四个阶段**：

1. **install 事件**：Service Worker 脚本首次注册或更新时触发。在此阶段应预缓存关键资源（App Shell），使用 `event.waitUntil()` 确保缓存完成后再进入下一阶段。安装失败则该 SW 被废弃。

2. **waiting 状态**：install 成功后，新 SW 进入 waiting 状态，等待旧 SW 控制的所有页面关闭。如果调用 `skipWaiting()`，则跳过此状态直接激活。

3. **activate 事件**：新 SW 激活时触发。在此阶段应清理旧版本的缓存，使用 `event.waitUntil()` 确保清理完成。

4. **fetch 事件**：SW 激活后，拦截其控制范围内的所有网络请求。在此阶段根据缓存策略决定返回缓存数据还是发起网络请求。

**`skipWaiting()` 的作用**：
- 在 install 事件中调用，跳过 waiting 状态，立即激活新 SW
- 不需要等待旧 SW 控制的页面全部关闭
- 风险：可能导致页面状态不一致（旧页面逻辑 + 新缓存策略）

**`clients.claim()` 的作用**：
- 在 activate 事件中调用，新 SW 立即接管所有已打开的页面
- 不需要用户刷新页面即可使新 SW 生效
- 通常与 `skipWaiting()` 配合使用，实现"无刷新更新"

**完整的更新流程**：
```
页面加载 → 注册 SW → 检测到新 SW → install → skipWaiting() → activate → clients.claim() → 控制所有页面
```

> - [MDN - Service Worker API](https://developer.mozilla.org/zh-CN/docs/Web/API/Service_Worker_API)

### 6. ★★ PWA 的四种缓存策略分别是什么？各适用于什么场景？请对比说明。

**答案要点**：

| 策略 | 工作流程 | 适用场景 | 优点 | 缺点 |
|------|---------|---------|------|------|
| **Cache First** | 先查缓存，命中则返回缓存；未命中才请求网络并缓存 | 静态资源（CSS/JS/图片/字体） | 响应极快，离线可用 | 可能返回过期内容，需更新 SW 版本才能刷新 |
| **Network First** | 先请求网络，成功则返回并更新缓存；失败则回退缓存 | API 数据、需要新鲜度的内容 | 保证数据新鲜度，离线有回退 | 网络慢时响应慢，离线时只能返回旧缓存 |
| **Stale-While-Revalidate** | 立即返回缓存，同时后台发起网络请求更新缓存 | 不要求实时性的数据（如文章列表、用户头像） | 响应快 + 数据最终一致 | 用户可能短暂看到旧数据 |
| **Network Only / Cache Only** | 只使用网络/只使用缓存 | 实时交易、在线支付 / 预缓存的 App Shell | 策略简单明确 | 极端场景，缺乏灵活性 |

**选择依据**：
- 数据新鲜度要求 vs 离线可用性 vs 网络速度
- 静态资源用 Cache First，API 数据用 Network First，非关键数据用 Stale-While-Revalidate
- 可结合 Workbox 的路由规则，对不同 URL 模式应用不同策略

### 7. ★★ Shadow DOM 的隔离机制包括哪些？`:host` 和 `::slotted()` 选择器的作用是什么？

**答案要点**：

**Shadow DOM 的隔离机制**：

1. **样式隔离**：Shadow DOM 内部的 CSS 不会泄漏到外部页面，外部 CSS 也不会影响 Shadow DOM 内部（可继承属性如 `color`、`font-size` 除外）
2. **DOM 隔离**：Shadow DOM 内部的 DOM 节点不在主文档树中，`document.querySelector` 无法选中内部节点
3. **事件重定向**：Shadow DOM 内部触发的事件，`event.target` 会被重定向为宿主元素，外部监听器无法获取内部真实目标（可通过 `event.composedPath()` 获取完整路径）
4. **插槽投影**：`<slot>` 元素将 Light DOM 节点投影到 Shadow DOM 中，投影的节点仍属于 Light DOM，样式由外部控制

**`:host` 选择器的作用**：
- 从 Shadow DOM 内部选择宿主元素（即自定义元素标签本身）
- `:host`：选择宿主元素
- `:host(.highlight)`：宿主元素有 `.highlight` 类时应用样式
- `:host-context(.dark-theme)`：宿主的祖先元素有 `.dark-theme` 类时应用样式

**`::slotted()` 选择器的作用**：
- 选择通过 `<slot>` 传入的 Light DOM 元素
- 只能选择顶层的插槽节点，不能选择嵌套的子节点
- 示例：`::slotted(span)` 选择所有通过 slot 传入的 `<span>` 元素

> 📖 **参考链接**：
> - [MDN - ShadowRoot](https://developer.mozilla.org/zh-CN/docs/Web/API/ShadowRoot)
> - [MDN - Web Components](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_components)

### 8. ★★ Web Components 的三大核心技术分别是什么？它们各自解决什么问题？

**答案要点**：

**1. Custom Elements（自定义元素）**：
- 允许开发者定义**自定义 HTML 标签**，扩展 HTML 语义
- 提供生命周期回调：`connectedCallback`（插入 DOM）、`disconnectedCallback`（移除）、`attributeChangedCallback`（属性变化）、`adoptedCallback`（移动到新文档）
- 解决：HTML 标签语义化不足的问题，让开发者可以创建可复用的、有意义的自定义标签

**2. Shadow DOM（影子 DOM）**：
- 为组件提供**封装的 DOM 树和样式作用域**，与主文档隔离
- 通过 `attachShadow({ mode: 'open' | 'closed' })` 创建
- 解决：组件样式冲突和 DOM 结构泄漏问题，确保组件内部实现不受外部干扰

**3. HTML Templates（HTML 模板）**：
- 通过 `<template>` 标签定义**声明式、可复用的 DOM 片段**
- 模板内容在页面加载时解析但不会渲染，需要时通过 JS 克隆使用
- 解决：DOM 片段的复用问题，避免在 JS 中拼接 HTML 字符串

**三者协作关系**：
```
<template> → 定义组件结构（HTML Templates）
customElements.define() → 注册组件（Custom Elements）
this.attachShadow() → 隔离组件内部（Shadow DOM）
```

### 1. ★★ 设计一个跨端统一登录模块（H5 / 微信小程序 / App 三端）

**设计思路**：

**核心挑战**：三端的登录方式完全不同，需要设计一套统一的登录流程和 Token 管理机制。

**架构设计**：

1. **统一登录流程**：
   - 所有端共用同一个登录状态管理（Pinia store）
   - 统一的 Token 存储和校验逻辑
   - 统一的登录成功/失败回调处理

2. **三端差异化处理**（通过条件编译）：

```
微信小程序 → wx.login() 获取 code → 后端换取 openid + token
App 端     → uni.login({ provider: 'weixin' }) → 后端换取 token
H5 端      → 微信 OAuth 2.0 网页授权 → 回调获取 code → 后端换取 token
手机号登录  → 通用方案，所有端共享同一套逻辑
```

3. **Token 管理**：
   - H5 端使用 `localStorage` 存储
   - 小程序/App 端使用 `uni.setStorageSync` 存储
   - 请求拦截器统一添加 `Authorization` 头
   - Token 过期自动刷新或跳转登录页

```javascript
// stores/auth.js —— 统一登录状态管理
import { defineStore } from 'pinia'

export const useAuthStore = defineStore('auth', () => {
  const token = ref('')
  const userInfo = ref(null)
  const isLogin = computed(() => !!token.value)

  // 获取存储的 token
  function initAuth() {
    // #ifdef H5
    token.value = localStorage.getItem('token') || ''
    // #endif
    // #ifndef H5
    token.value = uni.getStorageSync('token') || ''
    // #endif
  }

  // 统一登录方法
  async function login(params) {
    const res = await uni.request({
      url: '/api/auth/login',
      method: 'POST',
      data: params
    })
    token.value = res.data.token
    userInfo.value = res.data.userInfo
    saveToken(res.data.token)
  }

  // 保存 token
  function saveToken(val) {
    // #ifdef H5
    localStorage.setItem('token', val)
    // #endif
    // #ifndef H5
    uni.setStorageSync('token', val)
    // #endif
  }

  // 退出登录
  function logout() {
    token.value = ''
    userInfo.value = null
    // #ifdef H5
    localStorage.removeItem('token')
    // #endif
    // #ifndef H5
    uni.removeStorageSync('token')
    // #endif
    uni.reLaunch({ url: '/pages/login/login' })
  }

  return { token, userInfo, isLogin, initAuth, login, logout }
})
```

**关键要点**：
- 微信小程序登录需要 `wx.login()` 获取临时 code，不可直接获取用户信息（需用户主动触发 `button open-type="getUserInfo"`）
- App 端需在 `manifest.json` 中配置微信 `appid` 和 `UniversalLink`
- H5 端微信网页授权需要已认证的公众号，回调域名需在微信公众平台配置
- 手机号验证码登录作为通用降级方案，覆盖所有端

### 2. ★★ 设计一个跨端通用长列表虚拟滚动方案

**设计思路**：

**核心原理**：只渲染可视区域内的 DOM 节点，通过占位元素撑开滚动高度，大幅减少节点数量。

**关键参数**：
- `itemHeight`：每个列表项的固定高度
- `containerHeight`：可视容器高度
- `visibleCount`：可视区域能显示的项数 = `Math.ceil(containerHeight / itemHeight) + bufferCount * 2`
- `bufferCount`：上下缓冲区项数（避免快速滚动时白屏）
- `startIndex`：当前可视区域起始索引
- `offsetY`：可视区域偏移量 = `startIndex * itemHeight`

**实现要点**：

1. **滚动容器**：使用 `<scroll-view>` 组件（小程序）或普通 `<div>` + `overflow: scroll`（H5）
2. **占位元素**：高度 = `allItems.length * itemHeight`，撑开滚动条
3. **可视区域**：通过 `transform: translateY(offsetY)` 定位到正确位置
4. **滚动计算**：监听 `scroll` 事件，根据 `scrollTop` 计算 `startIndex`，更新 `visibleItems`
5. **性能优化**：仅在 `startIndex` 变化时才更新可视区域数据

```javascript
// mixins/virtualScroll.js —— 虚拟滚动核心逻辑
export default {
  data() {
    return {
      allItems: [],        // 全部数据
      visibleItems: [],    // 可视区域数据
      itemHeight: 80,      // 单项高度（rpx 转 px 后）
      containerHeight: 0,  // 容器高度
      startIndex: 0,
      offsetY: 0,
      visibleCount: 0,
      bufferCount: 3       // 缓冲区
    }
  },

  computed: {
    totalHeight() {
      return this.allItems.length * this.itemHeight
    }
  },

  mounted() {
    const { windowHeight } = uni.getSystemInfoSync()
    this.containerHeight = windowHeight
    this.visibleCount = Math.ceil(this.containerHeight / this.itemHeight) + this.bufferCount * 2
    this.updateVisibleItems()
  },

  methods: {
    onScroll(e) {
      const scrollTop = e.detail.scrollTop
      const newStartIndex = Math.max(0,
        Math.floor(scrollTop / this.itemHeight) - this.bufferCount
      )
      if (newStartIndex !== this.startIndex) {
        this.startIndex = newStartIndex
        this.offsetY = newStartIndex * this.itemHeight
        this.updateVisibleItems()
      }
    },

    updateVisibleItems() {
      const start = Math.max(0, this.startIndex)
      const end = Math.min(this.allItems.length, start + this.visibleCount)
      this.visibleItems = this.allItems.slice(start, end)
    }
  }
}
```

**跨端注意事项**：
- 小程序中使用 `<scroll-view>` 组件，需设置 `scroll-y` 和明确的高度
- H5 端可使用 `overflow: auto` 或 `<scroll-view>`
- `itemHeight` 需要从 rpx 转换为 px 后再计算
- 小程序中 `scroll` 事件的回调频率可能受限，建议配合节流使用

```javascript
// sw.js —— 新闻应用 Service Worker
const CACHE_VERSION = 'news-app-v2';
const STATIC_CACHE = 'static-' + CACHE_VERSION;
const DYNAMIC_CACHE = 'dynamic-' + CACHE_VERSION;

// 1. 预缓存 App Shell
self.addEventListener('install', (event) => {
  event.waitUntil(
    caches.open(STATIC_CACHE).then((cache) =>
      cache.addAll([
        '/',
        '/index.html',
        '/css/main.css',
        '/js/app.js',
        '/offline.html'
      ])
    )
  );
  self.skipWaiting();
});

// 2. 清理旧缓存
self.addEventListener('activate', (event) => {
  event.waitUntil(
    caches.keys().then((keys) =>
      Promise.all(
        keys.filter((k) => !k.includes(CACHE_VERSION)).map((k) => caches.delete(k))
      )
    )
  );
  self.clients.claim();
});

// 3. 智能路由分发
self.addEventListener('fetch', (event) => {
  const { request } = event;
  const url = new URL(request.url);

  // 静态资源：Cache First
  if (request.destination === 'style' || request.destination === 'script') {
    event.respondWith(cacheFirst(request, STATIC_CACHE));
    return;
  }

  // 图片：Stale-While-Revalidate
  if (request.destination === 'image') {
    event.respondWith(staleWhileRevalidate(request, DYNAMIC_CACHE));
    return;
  }

  // 新闻详情 API：Stale-While-Revalidate
  if (url.pathname.startsWith('/api/news/detail')) {
    event.respondWith(staleWhileRevalidate(request, DYNAMIC_CACHE));
    return;
  }

  // 新闻列表 API：Network First
  if (url.pathname.startsWith('/api/news/list')) {
    event.respondWith(networkFirst(request, DYNAMIC_CACHE));
    return;
  }

  // 导航请求：Network First
  if (request.mode === 'navigate') {
    event.respondWith(networkFirst(request, DYNAMIC_CACHE));
    return;
  }

  // 默认：Network First
  event.respondWith(networkFirst(request, DYNAMIC_CACHE));
});

// 缓存策略实现
async function cacheFirst(request, cacheName) {
  const cached = await caches.match(request);
  return cached || fetch(request);
}

async function networkFirst(request, cacheName) {
  try {
    const response = await fetch(request);
    const cache = await caches.open(cacheName);
    cache.put(request, response.clone());
    return response;
  } catch {
    const cached = await caches.match(request);
    return cached || caches.match('/offline.html');
  }
}

async function staleWhileRevalidate(request, cacheName) {
  const cache = await caches.open(cacheName);
  const cached = await cache.match(request);
  const fetchPromise = fetch(request).then((response) => {
    cache.put(request, response.clone());
    return response;
  });
  return cached || fetchPromise;
}
```

**离线功能增强**：
- **离线收藏**：使用 IndexedDB 存储用户收藏的新闻，离线时可阅读
- **阅读进度**：使用 IndexedDB 记录阅读进度，跨设备同步
- **后台同步**：使用 Background Sync API，网络恢复后自动提交用户离线时的操作（如评论、点赞）
- **推送通知**：使用 Push API + Notification API，推送突发新闻通知

**关键挑战**：
- IndexedDB 的存储配额因浏览器和平台而异（通常为可用磁盘空间的 50%-60%）

```javascript
// utils/ai-sdk-loader.js —— AI SDK 动态加载管理器

const SDK_CACHE = new Map();
const LOADING_PROMISES = new Map();

class AISDKLoader {
  /**
   * 通用 SDK 加载器：带缓存、去重、超时、降级
   */
  async loadSDK(name, loader, options = {}) {
    const { timeout = 15000, fallback = null } = options;

    // 1. 缓存命中
    if (SDK_CACHE.has(name)) return SDK_CACHE.get(name);

    // 2. 去重：避免并发重复加载
    if (LOADING_PROMISES.has(name)) return LOADING_PROMISES.get(name);

    // 3. 开始加载
    const loadPromise = Promise.race([
      loader(),
      new Promise((_, reject) =>
        setTimeout(() => reject(new Error(`SDK "${name}" 加载超时`)), timeout)
      )
    ])
      .then((instance) => {
        SDK_CACHE.set(name, instance);
        LOADING_PROMISES.delete(name);
        return instance;
      })
      .catch((err) => {
        console.error(`[AI SDK] "${name}" 加载失败:`, err);
        LOADING_PROMISES.delete(name);
        return fallback || this.getFallbackSDK(name);
      });

    LOADING_PROMISES.set(name, loadPromise);
    return loadPromise;
  }

  /**
   * 加载语音识别 SDK
   */
  async loadVoiceSDK() {
    return this.loadSDK('voice', async () => {
      // #ifdef MP-WEIXIN
      // 小程序：从独立分包加载
      await require.async('../subpkg-ai-voice/index.js');
      return new VoiceRecognitionManager();
      // #endif
      // #ifdef H5
      // H5：动态 import
      const { default: VoiceSDK } = await import(
        /* webpackChunkName: "ai-voice" */ '@/sdk/voice/index.js'
      );
      return new VoiceSDK();
      // #endif
    });
  }

  /**
   * 降级方案
   */
  getFallbackSDK(name) {
    const fallbacks = {
      voice: {
        isAvailable: false,
        start: () => uni.showToast({ title: '语音功能暂不可用', icon: 'none' }),
        stop: () => {},
      },
      ocr: {
        isAvailable: false,
        recognize: async () => {
          uni.showToast({ title: 'OCR 功能暂不可用', icon: 'none' });
          return null;
        },
      },
    };
    return fallbacks[name] || { isAvailable: false };
  }

  /**
   * 预加载：在空闲时提前加载可能需要用到的 SDK
   */
  preload(name, loader) {
    // #ifdef H5
    if (window.requestIdleCallback) {
      requestIdleCallback(() => this.loadSDK(name, loader));
    }
    // #endif
    // #ifdef MP-WEIXIN
    // 小程序中延迟 3 秒后预加载
    setTimeout(() => this.loadSDK(name, loader), 3000);
    // #endif
  }
}

export const aiSDKLoader = new AISDKLoader();
```

### 补充 1：跨端请求封装（基于 uni.request）

```javascript
// utils/request.js —— 跨端统一请求封装

const BASE_URL = 'https://api.example.com';

// 请求拦截器
function requestInterceptor(config) {
  const token = uni.getStorageSync('token');
  if (token) {
    config.header = {
      ...config.header,
      'Authorization': `Bearer ${token}`
    };
  }
  return config;
}

// 响应拦截器
function responseInterceptor(response) {
  const { statusCode, data } = response;

  if (statusCode === 200) {
    if (data.code === 0) return data.data;
    if (data.code === 401) {
      uni.removeStorageSync('token');
      uni.reLaunch({ url: '/pages/login/login' });
      return Promise.reject(new Error('登录已过期'));
    }
    uni.showToast({ title: data.message || '请求失败', icon: 'none' });
    return Promise.reject(new Error(data.message));
  }

  uni.showToast({ title: '网络异常，请稍后重试', icon: 'none' });
  return Promise.reject(new Error(`HTTP ${statusCode}`));
}

// 核心请求方法
function request(options) {
  return new Promise((resolve, reject) => {
    const config = requestInterceptor({
      url: BASE_URL + options.url,
      method: options.method || 'GET',
      data: options.data || {},
      header: { 'Content-Type': 'application/json', ...options.header },
      timeout: options.timeout || 15000
    });

    uni.request({
      ...config,
      success: (res) => {
        try { resolve(responseInterceptor(res)); }
        catch (err) { reject(err); }
      },
      fail: (err) => {
        uni.showToast({ title: '网络连接失败', icon: 'none' });
        reject(err);
      }
    });
  });
}

export const get = (url, data, opts = {}) => request({ ...opts, url, method: 'GET', data });
export const post = (url, data, opts = {}) => request({ ...opts, url, method: 'POST', data });
export default { get, post };
```
