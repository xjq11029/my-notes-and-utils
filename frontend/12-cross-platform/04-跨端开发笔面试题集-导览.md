### 1. uniapp 中条件编译的 `#ifdef` 和 `#ifndef` 是什么阶段的机制

| 维度 | 内容 |
|------|------|
| 是什么 | 条件编译是**编译时**机制，由编译器在打包阶段按目标平台裁剪代码，`#ifdef` 保留目标平台代码，`#ifndef` 保留非目标平台代码，不会增加运行时代码体积。 |
| 能做什么 | 在同一个文件中编写各平台差异化代码，编译器根据目标平台自动裁剪，实现"一套代码，多端运行"。 |
| 怎么用 | `<!-- #ifdef H5 -->H5 专属代码<!-- #endif -->`，`<!-- #ifndef MP-WEIXIN -->非小程序代码<!-- #endif -->`。 |
| 原理和工作流程 | 编译器解析 `.vue` 文件时，识别 `#ifdef`/`#ifndef` 注释指令，根据目标平台决定保留或移除代码块，最终产物中只包含对应平台的代码。 |
| 缺点 | 条件编译增加代码复杂度，过度使用导致代码可读性下降；每个 `#ifdef` 必须对应 `#endif`，容易遗漏。 |

### 4. uniapp 中 rpx 单位的换算规则是什么

| 维度 | 内容 |
|------|------|
| 是什么 | 屏幕宽度固定为 750rpx，在 iPhone 6（375px 宽）上 1rpx = 0.5px，换算公式为 `实际 px = 屏幕宽度(px) / 750 * rpx 值`。 |
| 能做什么 | 实现跨端响应式布局，设计稿 750px 宽度的标注值直接使用 rpx 即可。 |
| 怎么用 | `width: 750rpx; height: 200rpx; padding: 30rpx;`。 |
| 原理和工作流程 | 编译器在构建时将 rpx 转换为各平台对应的单位（H5 转 rem/vw，小程序保留 rpx，App 转原生单位）。 |
| 缺点 | 需要固定像素时仍需使用 px（如 1px 边框）。 |

| 缺点 | 优化后代码复杂度可能增加，需要权衡可读性和性能。 |

### 7. 哪种 PWA 缓存策略最适合 API 数据接口，需要保证数据新鲜度同时提供离线回退

| 维度 | 内容 |
|------|------|
| 是什么 | Network First 策略先请求网络，成功时更新缓存并返回最新数据；失败时回退到缓存数据，若缓存也没有则返回离线回退页面。 |
| 能做什么 | 优先保证数据新鲜度，同时提供离线可用性，适合 API 数据场景。 |
| 怎么用 | `async function networkFirst(request) { try { const res = await fetch(request); cache.put(request, res.clone()); return res; } catch { return await caches.match(request) || caches.match('/offline.html'); } }`。 |
| 原理和工作流程 | 详见原文。 |
| 缺点 | 网络慢时响应慢，离线时只能返回旧缓存数据。 |

### 8. 关于 Shadow DOM 的样式隔离，说法正确的是

| 维度 | 内容 |
|------|------|
| 是什么 | Shadow DOM 内部样式和外部样式完全隔离，互不影响（可继承属性如 `color`、`font-size` 除外）。 |
| 能做什么 | 确保组件内部样式不会污染外部页面，外部样式也不会破坏组件内部结构。 |
| 怎么用 | `this.attachShadow({ mode: 'open' }); shadowRoot.innerHTML = '<style>p { color: blue; }</style><p>内部文字</p>';`。 |
| 原理和工作流程 | Shadow DOM 创建独立的 DOM 树和样式作用域，`:host` 选择宿主元素，`::slotted()` 选择插槽内容。 |
| 缺点 | `mode: 'closed'` 时调试困难；事件 target 被重定向，需通过 `composedPath()` 获取真实路径。 |

| 缺点 | 浏览器兼容性需注意（Safari 部分支持有限）；与 React 18 及以下的属性传递和事件通信需要额外处理。 |
