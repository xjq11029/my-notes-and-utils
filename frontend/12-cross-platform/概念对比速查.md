# uni-app 跨端开发 - 概念对比速查

---

### H5 渲染 vs 小程序渲染

| 对比维度 | H5 渲染 | 小程序渲染 |
|---------|---------|-----------|
| 核心定位 | 基于浏览器 WebView 的单线程渲染，在浏览器环境中运行 | 基于双线程架构（渲染层 WebView + 逻辑层 JSCore），在平台容器中运行 |
| 线程模型 | 单线程，JS 执行和 DOM 渲染在同一线程 | 双线程，逻辑层和渲染层分离，通过 Native Bridge 通信 |
| DOM 操作 | 可直接操作 DOM 和 BOM（document、window 等） | 无法直接操作 DOM，数据更新必须通过 setData 传递 |
| CSS 支持 | 完整支持 CSS3 所有特性 | 仅支持 WXSS（CSS 子集），部分高级特性不支持（如部分渐变、滤镜） |
| 数据更新 | Vue 响应式系统直接更新真实 DOM | Vue 响应式 → setData 序列化 → 跨线程传递 → 渲染层更新 |
| 性能瓶颈 | 大量 DOM 操作和复杂动画导致主线程阻塞 | setData 频率和数据量过大导致跨线程通信阻塞 |
| 调试工具 | Chrome DevTools 完整支持 | 各平台小程序开发者工具（功能受限） |
| 选择建议 | 适用于需要丰富 Web 交互和完整 CSS 支持的场景 | 适用于需要小程序生态能力（分享、支付、订阅消息等）的场景 |

### 条件编译 vs 运行时判断

| 对比维度 | 条件编译（#ifdef / #ifndef） | 运行时判断（uni.getSystemInfoSync / process.env） |
|---------|------------------------------|--------------------------------------------------|
| 核心定位 | 编译时根据不同平台选择性保留或删除代码块 | 运行时根据当前平台动态决定代码执行路径 |
| 执行时机 | 编译阶段，在代码打包前处理 | 运行时，代码执行到判断语句时处理 |
| 代码产物 | 最终产物中只包含目标平台的代码，不包含其他平台代码 | 最终产物中包含所有平台的代码，通过条件分支执行 |
| 包体积影响 | 不增加目标平台包体积（无关代码已删除） | 会增加包体积（所有平台代码都打包进去） |
| 适用场景 | 平台特有代码块较大（如引用平台特有 API、组件）、确定不会跨平台使用的代码 | 需要根据设备信息动态调整行为（如屏幕尺寸适配）、平台差异代码量很小 |
| 使用方式 | `<!-- #ifdef H5 -->` / `// #ifdef MP-WEIXIN` / `/* #ifdef APP-PLUS */` | `if (process.env.UNI_PLATFORM === 'h5') { }` 或 `const { platform } = uni.getSystemInfoSync()` |
| 灵活性 | 低，编译时确定，无法动态切换 | 高，运行时可根据任意条件动态切换 |
| 选择建议 | 优先使用条件编译处理平台特定代码，减少包体积 | 仅在需要运行时动态判断的场景使用（如机型适配、系统版本判断） |

### uni.request vs axios

| 对比维度 | uni.request | axios |
|---------|-------------|-------|
| 核心定位 | uni-app 内置的跨平台网络请求 API，封装了各平台底层请求能力 | 第三方 HTTP 客户端库，基于浏览器 XMLHttpRequest 或 Node.js http 模块 |
| 跨端支持 | 全平台支持（H5、小程序、App），统一 api 调用 | 仅 H5 端可用，小程序端无法使用（缺少 XMLHttpRequest） |
| 请求拦截器 | 支持（通过 `uni.addInterceptor('request', { invoke, success, fail, complete })`） | 支持（通过 `axios.interceptors.request.use` 和 `response.use`） |
| 请求取消 | 支持（通过 `requestTask.abort()`） | 支持（通过 AbortController 或 CancelToken） |
| 上传/下载 | 原生支持 `uni.uploadFile` 和 `uni.downloadFile`，支持进度监听 | 支持上传下载，但进度监听依赖浏览器实现 |
| 小程序适配 | 完全兼容小程序网络请求规范 | 不能直接使用，需要额外适配层（如 `axios-miniprogram-adapter`） |
| Cookie 管理 | 小程序端不自动管理 Cookie，需手动处理 | 浏览器端自动管理 Cookie |
| 选择建议 | 跨端项目必须使用 uni.request 或其封装；仅在纯 H5 项目中可考虑 axios |

### 分包 vs 主包

| 对比维度 | 主包 | 分包 |
|---------|------|------|
| 核心定位 | 应用启动时立即加载的代码包，包含启动页面和公共依赖 | 按需加载的代码包，包含非首屏的业务模块页面 |
| 加载时机 | 应用启动时立即下载并执行 | 用户首次访问分包页面时触发下载 |
| 体积限制 | 小程序主包不超过 2MB（微信），总包（主包+所有分包）不超过 20MB | 单个分包不超过 2MB（微信） |
| 页面配置 | 直接在 `pages.json` 的 `pages` 数组中配置 | 在 `pages.json` 的 `subPackages` 数组中配置 root 和 pages |
| 依赖引用 | 可引用所有公共代码 | 可引用主包中的公共代码，但不能引用其他分包代码 |
| 启动速度 | 直接影响启动速度，主包越大启动越慢 | 不影响启动速度，按需下载 |
| 独立运行 | 始终可运行 | 独立分包可不依赖主包独立运行（适用于临时页面） |
| 选择建议 | 启动页、公共组件、公共工具函数、TabBar 页面放入主包 | 低频访问页、大型业务模块、非核心功能页面放入分包 |

### Vue 组件 vs 原生组件（小程序端）

| 对比维度 | Vue 组件（uni-app 编译后的组件） | 原生组件（小程序原生组件） |
|---------|----------------------------------|---------------------------|
| 核心定位 | 使用 Vue 语法编写的组件，编译后转换为小程序自定义组件 | 小程序平台原生提供的组件（如 `<map>`、`<video>`、`<camera>`、`<canvas>`） |
| 渲染层级 | 在 WebView 渲染层中渲染，与其他普通组件同级 | 在独立原生层级渲染，层级高于 WebView 中的所有组件 |
| CSS 控制 | 可完全通过 CSS 控制样式 | CSS 样式支持有限，部分属性无法通过 CSS 覆盖（如 map 的控件样式） |
| z-index 行为 | 遵循正常层叠规则 | 始终在最顶层，普通组件的 z-index 无法覆盖原生组件 |
| 事件支持 | 支持所有 Vue 事件绑定 | 仅支持组件自身定义的事件（如 map 的 `regionchange`、`markertap`） |
| 覆盖问题 | 可以被其他组件正常覆盖 | 无法被普通组件覆盖（如弹窗无法遮盖 map 组件），需使用 `cover-view` / `cover-image` |
| 性能 | 受 WebView 渲染性能限制 | 原生渲染，性能更优（如 video 播放、map 拖拽） |
| 选择建议 | 通用 UI 组件优先使用 Vue 组件 | 地图、视频、相机、Canvas 等必须使用原生组件；弹窗需要覆盖原生组件时使用 cover-view |

### rpx vs px vs rem

| 对比维度 | rpx | px | rem |
|---------|-----|-----|-----|
| 核心定位 | uni-app 内置的响应式像素单位，以屏幕宽度 750rpx 为基准 | 设备物理像素单位，固定大小 | CSS 相对单位，相对于根元素 font-size |
| 适配方式 | 自动根据屏幕宽度等比缩放，无需手动计算 | 固定尺寸，不同屏幕下显示大小不一致 | 需手动设置根元素 font-size（如 `calc(100vw / 7.5)`） |
| 编译处理 | 编译器自动转换：H5 → rem、小程序 → rpx（原生支持）、App → px | 不转换，直接使用 | 不转换，依赖运行时根元素 font-size |
| 跨端一致性 | 各端表现一致，1rpx 在各端都代表屏幕宽度的 1/750 | 各端表现不一致，375px 在 iPhone 6 上占满宽度，在 iPad 上只占一部分 | 取决于根元素 font-size 的设置方式 |
| 使用场景 | 所有需要自适应屏幕的元素尺寸（宽度、高度、间距、字体） | 固定尺寸场景（如 1px 边框、固定图标尺寸） | 纯 H5 项目的传统适配方案 |
| 选择建议 | 跨端项目优先使用 rpx，1px 边框使用 px 避免非整数像素模糊 | 仅用于必须精确到 1px 的场景 | 仅在纯 H5 项目中使用，跨端项目不推荐 |
