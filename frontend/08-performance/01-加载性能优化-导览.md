## 一、核心概念

| 维度 | 内容 |
|------|------|
| 是什么 | 前端加载性能优化是通过一系列技术手段缩短页面从发起请求到可交互的时间，直接影响用户留存率、转化率和 SEO 排名 |
| 能做什么 | 减少资源体积和请求次数、缩短传输距离、优化关键渲染路径、合理利用缓存策略，让用户尽快看到并交互页面内容 |
| 怎么用 | 三大维度：网络传输（压缩/CDN/预加载）、资源解析（关键渲染路径优化）、缓存策略（强缓存+协商缓存） |
| 原理和工作流程 | 核心目标：让用户尽快看到页面内容并尽快交互。Google 研究表明页面加载超过 3 秒，53% 移动用户会离开。优化从网络传输（减少体积、减少请求、缩短距离）、资源解析（优化关键路径、延迟非关键资源）、缓存策略（浏览器缓存减少重复请求）三个维度入手 |
| 缺点 | 加载优化需要权衡首屏速度和功能完整性；过度优化可能导致代码复杂度增加 |

## 二、底层原理

### Core Web Vitals 三大指标详解

| 维度 | 内容 |
|------|------|
| 是什么 | Google 提出的衡量 Web 用户体验的统一标准，包含 LCP（加载性能）、INP（交互响应性）、CLS（视觉稳定性），是 Google 搜索排名影响因素 |
| 能做什么 | 以统一标准量化用户体验，指导性能优化方向，直接影响 SEO 排名 |
| 怎么用 | 使用 web-vitals 库采集：`import { onLCP, onINP, onCLS } from 'web-vitals'`；通过 `navigator.sendBeacon` 上报 |
| 原理和工作流程 | LCP（最大内容绘制）：视口内可见最大元素渲染完成时间，< 2.5s 良好，元素类型包括 img/video 封面/背景图/文本块，优化策略为预加载 LCP 资源、压缩图片、使用 CDN、避免懒加载 LCP 元素。INP（交互到下次绘制）：衡量页面生命周期内所有交互的响应延迟，取第 98 百分位值，< 200ms 良好，已于 2024 年 3 月替代 FID，优化策略为减少长任务、使用 Web Worker、代码分割。CLS（累积布局偏移）：CLS = 影响比例 x 距离比例，< 0.1 良好，优化策略为给图片/视频设置宽高、预留动态内容空间、使用 transform 动画、font-display: swap |
| 缺点 | LCP 受网络环境和设备性能影响大；INP 需要真实用户数据（RUM）才能准确测量；CLS 对动态内容注入场景难以完全消除 |

### 资源压缩与优化

| 维度 | 内容 |
|------|------|
| 是什么 | 通过图片格式选择、响应式图片、字体优化、CSS/JS 压缩和 HTTP 压缩（Gzip/Brotli）等多维手段减少资源传输体积 |
| 能做什么 | 图片优化：WebP 比 JPEG 小 25-35%，AVIF 更小且支持 HDR，SVG 适合图标；字体优化：font-display: swap 避免 FOIT，子集化减少字体体积；CSS/JS 压缩：Terser/esbuild/cssnano 移除空白和冗余代码 |
| 怎么用 | 图片：`<img srcset="photo-400w.jpg 400w, photo-800w.jpg 800w" sizes="(max-width: 600px) 400px, 800px">` 和 `<picture><source srcset="photo.avif" type="image/avif">`；字体：`font-display: swap`；HTTP 压缩：Nginx 配置 `gzip on` 和 `brotli on` |
| 原理和工作流程 | 图片格式选择：JPEG 有损适合照片，PNG 无损适合图标，WebP 通用推荐，AVIF 现代浏览器首选。响应式图片通过 srcset+sizes 根据屏幕宽度和 DPR 选择合适图片，picture 元素支持格式渐进增强。字体优化中 font-display: swap 立即使用后备字体加载后替换，block 短暂隐藏后替换，optional 网络差时可能不加载。HTTP 压缩中 Gzip 兼容性最好压缩率约 70%，Brotli 比 Gzip 高 15-25% 现代浏览器均支持 |
| 缺点 | 多格式图片增加构建复杂度和存储成本；font-display: swap 可能导致布局偏移（FOUT）；Brotli 压缩级别高时 CPU 开销大 |

### Tree Shaking 原理

| 维度 | 内容 |
|------|------|
| 是什么 | 基于 ES Module 静态导入/导出特性，在编译时分析模块依赖关系，标记并移除未被引用代码（dead code）的优化技术 |
| 能做什么 | 减少打包体积，对大型第三方库效果显著，如 lodash 只引入使用的函数 |
| 怎么用 | 使用 ES Module 的 import/export 语法；package.json 设置 `"sideEffects": false` 或指定副作用文件列表；production 模式构建 |
| 原理和工作流程 | 静态分析：ES Module 的 import/export 在编译时即可确定引用关系；标记未使用导出：构建工具分析依赖图标记所有未被引用的导出；删除死代码：Terser 在打包阶段移除标记代码。sideEffects 字段告知打包工具哪些模块有副作用（如全局 CSS、polyfills），不能移除 |
| 缺点 | 仅支持 ES Module，不能用于 CommonJS；sideEffects: false 误用会移除全局 CSS 等有副作用模块 |

### 代码分割

| 维度 | 内容 |
|------|------|
| 是什么 | 将代码拆分为多个较小包（chunk），按需加载或并行加载，避免将所有代码打包到一个大文件中 |
| 能做什么 | 减少首屏加载体积，实现路由级和组件级按需加载，提升页面初始加载速度 |
| 怎么用 | 入口分割：`entry: { main: './src/main.js', admin: './src/admin.js' }`；动态导入：`const AboutPage = () => import('./pages/About.vue')`；SplitChunksPlugin：提取 node_modules 为 vendor chunk |
| 原理和工作流程 | 三种策略：入口分割（多 entry 手动拆分）、动态导入（import() 返回 Promise，Webpack 自动将动态导入的模块拆分为独立 chunk）、SplitChunksPlugin（自动提取公共依赖，cacheGroups 配置 vendor/共同模块的优先级和 minChunks）。Vite/Rollup 通过 build.rollupOptions.output.manualChunks 配置 |
| 缺点 | 过度分割可能导致 HTTP 请求数量增加；动态导入的 chunk 加载失败需处理错误 |

### 懒加载

| 维度 | 内容 |
|------|------|
| 是什么 | 延迟加载非首屏关键资源（图片、路由、组件），在用户需要时（滚动到可视区域、点击触发）才加载 |
| 能做什么 | 减少首屏资源加载量，加快页面初始渲染速度，节省带宽 |
| 怎么用 | 图片：`<img loading="lazy">` 或 Intersection Observer；路由：`const routes = [{ path: '/dashboard', component: () => import('./views/Dashboard.vue') }]`；组件：`React.lazy(() => import('./HeavyComponent'))` 或 `defineAsyncComponent` |
| 原理和工作流程 | 原生懒加载：loading="lazy" 浏览器自动判断图片是否接近视口。Intersection Observer：监听元素进入视口后替换 src 属性，rootMargin 提前 50px 触发加载。路由懒加载：动态 import() 将每个路由页面拆分为独立 chunk，访问时才加载。组件懒加载：适用于弹窗、图表、复杂表单等非首屏组件 |
| 缺点 | 懒加载过多可能影响用户体验（滚动时出现加载占位）；Intersection Observer 需要 polyfill 支持老浏览器 |

### HTTP 缓存策略

| 维度 | 内容 |
|------|------|
| 是什么 | 通过强缓存（Cache-Control/Expires）和协商缓存（ETag/Last-Modified）控制浏览器资源缓存行为，核心原则是尽最大可能缓存不变内容，尽早验证可能变化内容 |
| 能做什么 | 减少重复请求，降低服务器压力，提升页面二次加载速度 |
| 怎么用 | HTML：`Cache-Control: no-cache`（协商缓存）；JS/CSS 带哈希：`Cache-Control: max-age=31536000, immutable`（强缓存）；图片/字体：`Cache-Control: max-age=31536000`（强缓存） |
| 原理和工作流程 | 强缓存：浏览器在有效期内不发送请求，直接使用本地缓存（200 from disk/memory cache），由 Cache-Control: max-age 和 Expires 控制，前者优先级更高。协商缓存：浏览器发送请求携带 If-None-Match（ETag）或 If-Modified-Since（Last-Modified），服务器验证后返回 304 或 200。最佳策略：HTML 入口文件用协商缓存确保及时更新，JS/CSS 通过文件名哈希实现"永久缓存"，内容更新时哈希变化自动触发新请求 |
| 缺点 | 强缓存期间用户无法获取更新；缓存策略配置不当会导致更新延迟或缓存失效 |

### CDN 加速原理

| 维度 | 内容 |
|------|------|
| 是什么 | CDN（内容分发网络）由分布在全球的边缘服务器组成，将内容缓存到离用户最近的节点，减少网络延迟 |
| 能做什么 | 加速静态资源分发、降低源站压力、提供 DDoS 防护能力 |
| 怎么用 | 将静态资源（JS/CSS/图片/字体）域名指向 CDN，配置缓存规则和预热策略 |
| 原理和工作流程 | DNS 解析到 CDN 全局负载均衡 → 根据用户 IP 定位最近边缘节点 → 边缘节点有缓存则直接返回（命中）→ 无缓存则回源拉取并缓存（回源）。优化策略：预热（提前推送资源到边缘节点）、刷新（清除缓存强制回源）、统一 URL 参数规范提升缓存命中率 |
| 缺点 | CDN 缓存刷新有延迟；回源流量可能产生额外费用；HTTPS 证书需额外配置 |

### 预加载技术

| 维度 | 内容 |
|------|------|
| 是什么 | 通过 link 标签的 rel 属性声明式预加载资源，包括 preload（当前页面必需）、prefetch（未来页面可能需）、dns-prefetch（DNS 预解析）、preconnect（预连接）、prerender（预渲染） |
| 能做什么 | 减少关键资源加载延迟，提升首屏渲染速度和页面切换体验 |
| 怎么用 | `<link rel="preload" href="/fonts/main.woff2" as="font" crossorigin>`；`<link rel="prefetch" href="/page2.js" as="script">`；`<link rel="preconnect" href="https://cdn.example.com">` |
| 原理和工作流程 | preload：强制浏览器立即以高优先级加载，用于当前页面关键资源（首屏 CSS、字体、LCP 图片），3 秒内未使用会触发警告。prefetch：浏览器空闲时以低优先级加载，用于未来页面可能需要的资源。preconnect：提前建立 DNS + TCP + TLS 完整连接，用于确定会使用的第三方资源。dns-prefetch：仅完成 DNS 解析，用于可能使用的第三方域名 |
| 缺点 | preload 资源未及时使用浪费带宽；过多 preload/prefetch 可能与关键资源竞争带宽；prerender 消耗大量资源 |

## 三、实战应用

### 构建一个完整的加载优化方案

| 维度 | 内容 |
|------|------|
| 是什么 | 基于 Vite 的生产环境构建优化配置，包含 Brotli 压缩、打包分析、manualChunks 代码分割 |
| 能做什么 | 减少构建产物体积、可视化分析打包组成、优化 chunk 拆分策略 |
| 怎么用 | `vite.config.js`：`viteCompression({ algorithm: 'brotli' })` + `visualizer({ open: true })` + `rollupOptions.output.manualChunks: { 'react-vendor': ['react', 'react-dom'] }` |
| 原理和工作流程 | vite-plugin-compression 预生成 .br 文件，Nginx 配合 brotli_static 直接返回压缩文件；rollup-plugin-visualizer 生成打包分析 HTML 报告；manualChunks 将大型依赖（react/vue/antd）拆分为独立 chunk，提升缓存命中率 |
| 缺点 | Brotli 预生成增加构建时间；manualChunks 配置不当可能导致 chunk 重复或过小 |

### Nginx 缓存配置示例

| 维度 | 内容 |
|------|------|
| 是什么 | 生产环境 Nginx 配置，实现 HTML 协商缓存、静态资源强缓存和 Gzip 压缩 |
| 能做什么 | 确保 HTML 及时更新、静态资源长期缓存、减少传输体积 |
| 怎么用 | `location / { add_header Cache-Control "no-cache, must-revalidate"; }`；`location ~* \.(js|css|png|jpg)$ { expires 1y; add_header Cache-Control "public, immutable"; }` |
| 原理和工作流程 | HTML 使用 no-cache 强制每次请求验证（协商缓存）；带哈希的 JS/CSS/图片使用 expires 1y + immutable 实现强缓存，内容更新时哈希变化自动触发新请求；Gzip 压缩 text/plain、text/css、application/json、application/javascript 等文本类型 |
| 缺点 | 不正确的缓存策略可能导致用户看到旧版本；Gzip 压缩对图片等已压缩资源无效 |

### 性能监控指标采集

| 维度 | 内容 |
|------|------|
| 是什么 | 使用 web-vitals 库采集 Core Web Vitals 指标（LCP、INP、CLS），通过 sendBeacon 上报 |
| 能做什么 | 实时监控线上用户体验，建立性能基线和告警机制 |
| 怎么用 | `import { onLCP, onINP, onCLS } from 'web-vitals'`；`onLCP(sendToAnalytics)`；`navigator.sendBeacon('/api/analytics', JSON.stringify(metric))` |
| 原理和工作流程 | web-vitals 库通过 PerformanceObserver API 监听 LCP（largest-contentful-paint）、INP（event timing）、CLS（layout-shift）等浏览器事件。sendBeacon 非阻塞上报，确保页面关闭时也能发送数据。上报数据包含 name、value、rating、delta、id 等字段 |
| 缺点 | 需要前后端配合建立完整的监控和告警体系；部分指标（如 INP）需要真实用户数据才能准确测量 |

## 四、常见面试题

### Core Web Vitals 包含哪些指标各自的衡量标准是什么

| 维度 | 内容 |
|------|------|
| 是什么 | 考察 Google Core Web Vitals 三大核心指标：LCP（加载性能 < 2.5s）、INP（交互响应 < 200ms）、CLS（视觉稳定性 < 0.1） |
| 能做什么 | 验证候选人是否了解业界标准的用户体验衡量体系 |
| 怎么用 | 回答要点：LCP 衡量视口最大内容绘制时间，INP 替代 FID 衡量所有交互响应延迟，CLS 衡量布局偏移累积分数 |
| 原理和工作流程 | LCP 追踪视口内最大元素（img/video/文本块）渲染完成时间，< 2.5s 良好。INP 取页面生命周期内所有交互延迟的第 98 百分位值，< 200ms 良好，已于 2024 年 3 月替代 FID。CLS = 影响比例 x 距离比例，< 0.1 良好。三者共同构成 Google 搜索排名影响因素 |
| 缺点 | FID 和 INP 的过渡期可能造成混淆；CLS 可能受第三方广告和动态内容影响难以控制 |

### 强缓存和协商缓存的区别是什么

| 维度 | 内容 |
|------|------|
| 是什么 | 强缓存浏览器直接使用缓存不发送请求，协商缓存浏览器发送请求服务器验证后返回 304 |
| 能做什么 | 合理组合两种缓存策略：HTML 协商缓存确保及时更新，静态资源强缓存 + 文件名哈希实现永久缓存 |
| 怎么用 | 强缓存：`Cache-Control: max-age=31536000`；协商缓存：`Cache-Control: no-cache` + ETag/If-None-Match |
| 原理和工作流程 | 强缓存优先：浏览器先检查 Cache-Control/Expires，有效期内直接使用缓存（200 from disk/memory cache），不发送请求。协商缓存：强缓存过期后，浏览器发送请求携带 If-None-Match（ETag）或 If-Modified-Since（Last-Modified），服务器对比后返回 304（未修改）或 200（新内容）。ETag 优先级高于 Last-Modified |
| 缺点 | 强缓存期间用户无法获取更新；ETag 计算需要服务器资源 |

### Tree Shaking 为什么只支持 ES Module

| 维度 | 内容 |
|------|------|
| 是什么 | ES Module 的 import/export 是静态的（编译时确定引用关系），CommonJS 的 require 是动态的（运行时确定），只有静态的才能被构建工具分析 |
| 能做什么 | 回答时需解释静态分析和动态分析的区别，以及为何 CommonJS 无法被 Tree Shaking |
| 怎么用 | 使用 ES Module 语法；确保 Babel 等转译工具不将 ES Module 转为 CommonJS |
| 原理和工作流程 | 静态导入：import 语句在代码顶层，路径必须是字符串字面量，构建工具在编译时即可确定所有依赖关系，标记未使用导出。动态导入：require 可以在条件语句中、路径可以是变量，运行前无法确定导入什么，因此无法静态分析。Tree Shaking 依赖编译时的确定性，这是 CommonJS 无法提供的 |
| 缺点 | 部分老旧库仍使用 CommonJS，无法享受 Tree Shaking 优化 |

### preload prefetch preconnect 的区别

| 维度 | 内容 |
|------|------|
| 是什么 | preload 强制立即加载当前页面关键资源，prefetch 空闲时加载未来页面资源，preconnect 提前建立与第三方域名的完整连接 |
| 能做什么 | 回答时需区分优先级、使用场景和目标页面 |
| 怎么用 | preload：`<link rel="preload" href="/hero.webp" as="image">`；prefetch：`<link rel="prefetch" href="/page2.js">`；preconnect：`<link rel="preconnect" href="https://api.example.com">` |
| 原理和工作流程 | preload 优先级最高，浏览器立即加载，用于当前页面必需资源，3 秒内未使用触发警告。prefetch 优先级最低，浏览器空闲时加载，用于未来页面可能需要的资源。preconnect 提前完成 DNS + TCP + TLS 握手，用于确定会使用的第三方域名。dns-prefetch 仅做 DNS 解析 |
| 缺点 | preload 滥用会与关键资源竞争带宽；prefetch 在移动网络下可能浪费用户流量 |

### 如何设计前端资源的缓存策略

| 维度 | 内容 |
|------|------|
| 是什么 | 核心思路：HTML 入口文件使用协商缓存确保及时更新，JS/CSS 等静态资源通过文件名哈希实现强缓存"永久缓存" |
| 能做什么 | 回答时需覆盖 HTML、JS/CSS、图片、字体、API 数据等各类资源的缓存策略选择及原理 |
| 怎么用 | HTML：`Cache-Control: no-cache`（协商缓存）；JS/CSS 带哈希：`Cache-Control: max-age=31536000, immutable`（强缓存）；图片/字体：`Cache-Control: max-age=31536000`（强缓存） |
| 原理和工作流程 | HTML 使用协商缓存确保每次请求验证是否有新版本；JS/CSS 文件名包含内容哈希（如 app.a1b2c3.js），内容变化时哈希变化 URL 也变化，旧 URL 的缓存不会影响新版本；immutable 指令告诉浏览器资源在缓存期间不会变化，跳过 304 验证请求 |
| 缺点 | 需要构建工具支持文件名哈希；HTML 协商缓存仍有请求开销 |

## 五、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 加载性能优化中常见的实践错误：LCP 元素懒加载、图片未设宽高、sideEffects 误用、preload 滥用、缓存策略错误、动态 import 无错误处理、字体 FOIT、遗漏 Brotli 压缩 |
| 能做什么 | 帮助开发者提前识别并避免性能优化中的典型反模式，防止优化适得其反 |
| 怎么用 | 对照排查：LCP 元素不用 loading="lazy" 改为 preload 或 fetchpriority="high"；图片设 width/height 或 aspect-ratio 避免 CLS；sideEffects 数组排除 CSS 文件；只 preload 确定会立即使用的关键资源 |
| 原理和工作流程 | 常见错误根源：LCP 元素懒加载延迟首屏核心内容、图片无尺寸导致布局偏移（CLS 偏高）、sideEffects: false 误删全局 CSS、preload 资源 3 秒内未使用浪费带宽、HTML 强缓存导致用户看不到新版本、动态 import 无 catch 导致网络差时白屏、font-display 默认值导致文字不可见（FOIT）、仅依赖 Gzip 未启用 Brotli |
| 缺点 | 这些问题需要在实践中逐步积累经验才能识别；性能优化需要监控数据支撑决策 |
