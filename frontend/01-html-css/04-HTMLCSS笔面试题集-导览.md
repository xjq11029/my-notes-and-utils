### 1. 标准盒模型中 width 属性指的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查标准盒模型中 width 的定义：仅包含 content 区域。 |
| 能做什么 | 检验对两种盒模型 width 包含范围差异的理解。 |
| 怎么用 | 标准盒模型（content-box）：width 仅 content；替代盒模型（border-box）：width = content + padding + border。 |
| 原理和工作流程 | CSS 标准规定 content-box 的 width 只表示内容区宽度，总宽度需要加上 padding + border + margin。border-box 是 CSS3 新增替代方案，将 padding 和 border 算入 width。 |
| 缺点 | 容易和 border-box 混淆，需要牢记"标准盒模型 width 不包含 padding 和 border"。 |

### 2. BFC 的全称是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 BFC 全称：Block Formatting Context（块级格式化上下文）。 |
| 能做什么 | 检验对 CSS 核心概念名称的记忆。 |
| 怎么用 | Block Formatting Context，中文译为块级格式化上下文，是独立的渲染区域。 |
| 原理和工作流程 | BFC 是 CSS 渲染中的一个概念，表示一个独立的渲染上下文，内部布局不影响外部。 |
| 缺点 | 记不住全称是常见问题，需要准确记忆。 |

### 3. Flex 布局中 justify-content 的作用是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Flex 容器属性：justify-content 控制主轴对齐方式。 |
| 能做什么 | 检验对 Flex 容器属性分工的理解（主轴 vs 交叉轴）。 |
| 怎么用 | justify-content 控制主轴方向对齐；align-items 控制交叉轴方向对齐。 |
| 原理和工作流程 | Flex 布局有两个轴：主轴（由 flex-direction 决定）和交叉轴（垂直于主轴）。justify-content 在主轴方向分配剩余空间，align-items 在交叉轴方向对齐项目。 |
| 缺点 | 容易和 align-items 混淆，需要明确区分。 |

### 4. 以下哪个 CSS 属性可以触发 BFC？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 BFC 的触发方式：overflow: hidden 是常见触发方式。 |
| 能做什么 | 检验对 BFC 触发条件的掌握。 |
| 怎么用 | 触发方式：overflow 不为 visible、float 不为 none、position 为 absolute/fixed、display 为 inline-block/flex/grid。 |
| 原理和工作流程 | 满足上述任一条件，浏览器会为该元素创建独立的块级格式化上下文。 |
| 缺点 | display: block 不能触发 BFC，很多人误以为块级元素默认触发，实际上不是。 |

### 5. 以下哪个不是 CSS 伪类？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查伪类和伪元素的语法区别：::before 是伪元素，不是伪类。 |
| 能做什么 | 检验对伪类和伪元素概念区分。 |
| 怎么用 | 伪类以 : 开头，表示元素状态（:hover、:first-child、:active）；伪元素以 :: 开头，表示创建虚拟元素（::before、::after、::first-line）。 |
| 原理和工作流程 | CSS 语法规范中，伪类表示元素的状态信息；伪元素表示创建不存在的虚拟元素。CSS3 规范用双冒号区分伪元素，但为了兼容，单冒号也能工作。 |
| 缺点 | 混淆语法格式是常见错误，需要记住伪元素是双冒号。 |

### 6. CSS 选择器的优先级计算正确的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 CSS 优先级计算规则：!important > 内联 > ID > 类 > 标签。 |
| 能做什么 | 检验对 CSS 优先级规则的掌握，解决样式覆盖问题。 |
| 怎么用 | 优先级从高到低：!important → 内联样式（style 属性）→ ID 选择器 → 类/伪类/属性选择器 → 标签选择器。 |
| 原理和工作流程 | 浏览器根据优先级决定当多个选择器匹配同一元素时应用哪个样式，权值高的胜出。同权重后写覆盖先写。 |
| 缺点 | 容易颠倒顺序，比如把 ID 放在内联前面，需要牢记顺序。 |

### 7. position: sticky 的参照物是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 sticky 定位的参照物：最近的滚动祖先元素。 |
| 能做什么 | 检验对五种定位参照物差异的理解。 |
| 怎么用 | static 无参照物；relative 相对自身；absolute 相对最近已定位祖先；fixed 相对浏览器视口；sticky 相对最近滚动祖先。 |
| 原理和工作流程 | sticky 混合 relative 和 fixed 特性：元素位置未达到阈值时是 relative，达到阈值后变为 fixed，参照物是最近的滚动祖先容器。 |
| 缺点 | 容易误认为参照物是浏览器视口，实际上和 fixed 不同。 |

### 8. 以下哪个属性会触发回流（Reflow）？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查哪些属性修改会触发回流：width 修改几何属性会触发回流。 |
| 能做什么 | 检验对回流触发条件的理解，区分回流和重绘。 |
| 怎么用 | 修改 width/height/top/left/padding/margin 会改变几何属性，触发回流；修改 color/opacity/box-shadow 只触发重绘。 |
| 原理和工作流程 | 回流需要重新计算布局，性能开销大；重绘只需要重新绘制像素，开销较小。width 改变元素宽度，属于几何属性变化，触发回流。 |
| 缺点 | 容易混淆触发回流和重绘的属性，需要记住几何属性触发回流。 |

### 9. Grid 布局中 fr 单位表示？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Grid 中 fr 单位的含义：弹性系数，等分剩余空间。 |
| 能做什么 | 检验对 Grid 核心单位的理解。 |
| 怎么用 | fr 表示剩余空间的等分比例，`grid-template-columns: 1fr 2fr 1fr` 将剩余空间分为 4 份，三列分别占 1/4、2/4、1/4。 |
| 原理和工作流程 | fr 会减去固定尺寸后的剩余空间按比例分配，因此能自动适应容器宽度。 |
| 缺点 | 容易误认为 fr 是比例单位但不理解"剩余空间"的含义。 |

### 10. flex: 1 是哪三个属性的简写？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 flex 简写的展开值：flex-grow: 1; flex-shrink: 1; flex-basis: 0%;。 |
| 能做什么 | 检验对 flex 简写属性的深入理解，很多人只知道 flex: 1 但不知道具体展开。 |
| 怎么用 | 标准规定 `flex: 1` 等价于 `flex: 1 1 0%`，即允许放大、允许缩小、初始大小为 0。 |
| 原理和工作流程 | flex-basis: 0% 让所有项目从零开始分配剩余空间，因此实现等分。如果是 `flex: auto` 则 flex-basis 为 auto，按内容大小分配。 |
| 缺点 | 容易记错 flex-basis 的值为 auto，实际是 0%。 |

### 11. 下面哪个 CSS 属性性能最好（不触发回流重绘）？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 CSS 动画性能：transform: translateX() 只触发合成，性能最好。 |
| 能做什么 | 检验对 CSS 渲染性能的理解，知道哪些属性修改性能最优。 |
| 怎么用 | 只有 transform 和 opacity 的修改只触发 Composite 合成阶段，不触发 Layout（回流）和 Paint（重绘），性能最优。 |
| 原理和工作流程 | 浏览器渲染流水线：Layout → Paint → Composite。transform 只需要最后一步，不需要重新布局和绘制，因此性能最好。 |
| 缺点 | 认为 width/top 会触发回流，但是容易忽略 transform 的性能优势。 |

### 12. CSS 变量的正确使用方式是？

| 维度 | 内容 |

| 能做什么 | 检验对 CSS 原生变量语法的记忆，区分 SASS/Less 变量语法。 |

### 13. 以下哪种方式可以实现元素水平垂直居中？

| 维度 | 内容 |
|------|------|
| 是什么 | 三种常见水平垂直居中方案都正确，因此"以上都可以"是正确答案。 |
| 能做什么 | 检验对多种居中方案的掌握。 |
| 怎么用 | Flex：`display: flex; justify-content: center; align-items: center;`；Grid：`display: grid; place-items: center;`；absolute + transform：`position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%);` 三种都正确。 |
| 原理和工作流程 | 三种方案各有适用场景：Flex 和 Grid 代码简洁；absolute + transform 不依赖父元素布局（父元素只需要 position: relative）。 |
| 缺点 | 只选其中一种是常见错误，实际上三种都能正确实现。 |

| 原理和工作流程 | 媒体查询针对媒体特性（宽度、方向、颜色模式等）应用样式，speed 不属于标准媒体特性。 |

### 15. contain 属性的作用是什么？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 contain 属性作用：告诉浏览器元素子树独立于页面其他部分，用于性能优化。 |
| 能做什么 | 检验对 CSS 性能优化属性的了解。 |
| 怎么用 | `contain: layout style paint;` 告诉浏览器该元素的修改不会影响页面其他部分，浏览器可以只重绘该元素，提升性能。 |

| 缺点 | 很多开发者不知道 contain 属性，对 CSS 性能优化了解不全面。 |

### 1. 盒模型的两种类型及区别

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 content-box 和 border-box 两种盒模型在 width 包含范围上的区别。 |
| 能做什么 | 检验对盒模型基础概念的掌握。 |

### 2. BFC 的触发方式和应用场景

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 BFC 概念、至少 3 种触发方式和常见应用场景。 |
| 能做什么 | 检验对 BFC 概念和实际应用的理解。 |
| 怎么用 | BFC 是独立渲染区域，内部布局不影响外部。触发方式：overflow: hidden、float、position: absolute/fixed、display: flex/grid。应用场景：清除浮动、防止 margin 折叠、自适应两栏布局。 |
| 原理和工作流程 | BFC 内部元素布局不会影响外部，因此可以用来隔离布局。计算高度时包含浮动子元素，解决高度塌陷；不同 BFC 之间 margin 不会折叠。 |
| 缺点 | 说不清应用场景是常见问题，需要记住三个主要场景。 |

### 3. Flex 布局和 Grid 布局的区别和适用场景

| 维度 | 内容 |
|------|------|
| 是什么 | 对比 Flex（一维）和 Grid（二维）的区别，说明各自适用场景。 |
| 能做什么 | 检验能否根据场景选择合适的布局方案。 |
| 怎么用 | Flex：一维布局，沿单轴排列，内容驱动，适合导航栏、列表；Grid：二维布局，同时控制行列，布局驱动，适合整体页面结构。 |
| 原理和工作流程 | Flex 擅长一维方向的弹性分布；Grid 擅长二维平面的网格对齐。两者不互斥，经常配合使用（Grid 做整体布局，Flex 做内部排列）。 |
| 缺点 | 说成"Grid 比 Flex 好"是错误，两者适用场景不同，没有绝对优劣。 |

### 4. 回流和重绘的区别，如何减少回流

| 维度 | 内容 |
|------|------|
| 是什么 | 考查回流和重绘定义区别，以及减少回流的优化策略。 |
| 能做什么 | 检验对浏览器渲染性能优化的理解。 |
| 怎么用 | 回流：重新计算几何属性（位置尺寸），性能开销大；重绘：重新绘制外观，几何属性不变，开销较小。回流一定触发重绘，重绘不一定触发回流。优化：transform 替代 top/left、批量修改 DOM、读写分离、will-change。 |
| 原理和工作流程 | 回流改变布局，需要整个渲染流水线重新走一遍；重绘只需要走绘制和合成。减少回流就是减少需要重新计算布局的次数。 |
| 缺点 | 容易漏掉"回流一定触发重绘"这个关键点。 |

### 5. position 的五个值及参照物

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 static/relative/absolute/fixed/sticky 五个定位值的参照物和文档流行为。 |
| 能做什么 | 检验对 CSS 定位体系的全面掌握。 |
| 怎么用 | static：默认，无定位；relative：相对于自身原有位置，不脱离文档流；absolute：相对于最近已定位祖先，脱离文档流；fixed：相对于浏览器视口，脱离文档流；sticky：相对于最近滚动祖先，不脱离文档流。 |
| 原理和工作流程 | 不同定位值改变元素在文档流中的行为和参照物，需要根据场景选择：relative 做定位上下文，absolute 做弹窗，fixed 做固定导航，sticky 做吸顶。 |
| 缺点 | sticky 的参照物容易记错（是最近滚动祖先不是视口）。 |

### 6. CSS 选择器优先级计算规则

| 缺点 | 权值计算容易记错顺序，需要准确记忆。 |

### 7. CSS 动画性能优化（transform vs top/left）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查为什么 transform 做动画比 top/left 性能更好。 |
| 能做什么 | 检验对浏览器渲染流水线的理解深度。 |
| 怎么用 | 修改 top/left 触发完整的 Layout → Paint → Composite 流程；修改 transform 只触发 Composite 阶段，不经过 Layout 和 Paint，且通常在 GPU 合成层执行利用硬件加速。 |
| 原理和工作流程 | top/left 改变元素几何位置，浏览器需要重新回流（计算布局），每个帧都需要回流，开销巨大导致卡顿；transform 不改变几何位置，只需要最后合成，因此性能好很多。 |
| 缺点 | 说不清 GPU 硬件加速的作用，只说"不触发回流"不完整。 |

### 8. 响应式布局的实现方案

| 维度 | 内容 |
|------|------|
| 是什么 | 考查常见响应式布局实现方案，能否列举几种并说明特点。 |
| 能做什么 | 检验实际响应式开发经验。 |
| 怎么用 | 媒体查询（@media）根据断点应用不同样式；流式布局使用百分比；Flex 弹性布局；Grid 配合 auto-fit/minmax；rem/vw 相对单位；混合方案结合多种技术。 |
| 原理和工作流程 | 响应式的核心是让页面根据不同屏幕宽度自动调整布局和尺寸，提供最佳阅读体验。多种方案结合使用是现代最佳实践。 |
| 缺点 | 只说一种方案不完整，需要列举多种并说明适用场景。 |

### 9. 清除浮动的方法

| 维度 | 内容 |
|------|------|
| 是什么 | 考查解决浮动导致父容器高度塌陷的多种清除浮动方法，推荐 clearfix 伪元素法。 |
| 能做什么 | 检验对浮动布局问题和解决方案的掌握。 |
| 怎么用 | clearfix 伪元素法（推荐）：`.clearfix::after { content: ''; display: block; clear: both; }`；触发父元素 BFC：`overflow: hidden`；空标签法（不推荐）；父元素固定高度（不推荐）。 |
| 原理和工作流程 | 浮动元素脱离文档流，父容器无法感知高度导致塌陷。clearfix 在末尾插入清除浮动的块级元素，撑开父容器高度；BFC 计算高度时包含浮动子元素。 |
| 缺点 | 推荐方案记错，说空标签法是推荐方案，实际上语义差不推荐。 |

### 10. em/rem/vh/vw 的区别和适用场景

| 维度 | 内容 |
|------|------|
| 是什么 | 考查四种相对单位的参照物区别和适用场景。 |
| 能做什么 | 检验对相对单位的全面理解，移动端适配核心考点。 |
| 怎么用 | em 相对于父元素 font-size，适合组件内部，嵌套会累积；rem 相对于根元素 font-size，适合全局，不会累积；vh 相对于视口高度，适合全屏；vw 相对于视口宽度，适合宽度适配。移动端适配常用 rem + vw 混合。 |
| 原理和工作流程 | 不同单位参照物不同，带来不同的缩放行为。rem 不会累积，因此推荐做全局尺寸；vw 直接和视口绑定，纯 CSS 适配不需要 JS。 |
| 缺点 | 参照物混淆是常见错误，需要明确每个单位相对于谁。 |

### 1. 题目：设计一个三栏布局（左右固定宽度，中间自适应）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查经典布局题：左右固定，中间自适应，至少两种方案。 |
| 能做什么 | 检验对 Flex、Grid、BFC 多种布局方案的掌握。 |
| 怎么用 | Flex 方案：`.container { display: flex; } .left { width: 200px; flex-shrink: 0; } .center { flex: 1; } .right { width: 150px; flex-shrink: 0; }`；Grid 方案：`grid-template-columns: 200px 1fr 150px;`；浮动+BFC 方案：左右浮动，中间 overflow: hidden 触发 BFC。 |
| 原理和工作流程 | Flex 和 Grid 方案代码简洁现代，推荐使用；浮动+BFC 方案兼容性好，适合需要兼容旧浏览器的场景。三种方案都能实现需求，核心是中间区域自适应填充剩余空间。 |
| 缺点 | Flex 方案中忘记设置 `flex-shrink: 0` 导致左右栏被压缩，是常见错误。 |

### 2. 题目：设计一个响应式导航栏（移动端汉堡菜单）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查响应式设计实践：桌面显示完整导航，移动端隐藏显示汉堡按钮，点击展开。 |
| 能做什么 | 检验媒体查询配合 Flex 实现响应式导航的能力。 |
| 怎么用 | 使用 Flex 实现导航栏；媒体查询在 <= 768px 隐藏完整菜单，显示汉堡按钮；点击汉堡按钮切换 open 类展开菜单；核心是媒体查询断点配合 CSS display 控制显示隐藏。 |
| 原理和工作流程 | 桌面端 Flex 水平排列导航链接；移动端媒体查询切换布局为垂直排列，默认隐藏，点击后显示。需要少量 JavaScript 切换类名。 |
| 缺点 | 忘记 JavaScript 切换类名，只有 CSS 无法实现点击交互。 |

### 3. 题目：实现一个无限滚动加载的图片列表（CSS + JS）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Grid 响应式布局配合 IntersectionObserver 实现无限滚动。 |
| 能做什么 | 检验 CSS Grid 响应式能力和 IntersectionObserver API 使用经验。 |
| 怎么用 | Grid 布局：`grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));` 自动填充；使用 IntersectionObserver 监听最后一项，提前 200px 触发加载，比监听 scroll 事件性能好。 |
| 原理和工作流程 | Grid 的 auto-fill + minmax 自动计算每行列数，屏幕越大列越多，纯 CSS 实现响应式；IntersectionObserver 异步监听可见性，避免 scroll 事件频繁触发导致性能问题。 |
| 缺点 | 使用 scroll 事件监听而不是 IntersectionObserver，性能较差。 |

### 4. 题目：实现一个 sticky 表头+首列的表格

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 sticky 定位的实际应用：表头吸顶，首列吸左，交叉单元格层级正确。 |
| 能做什么 | 检验对 sticky 定位的理解和实际运用能力。 |
| 怎么用 | 表格容器 overflow: auto 可滚动；表头 th 设置 position: sticky; top: 0 吸顶；首列 td/th 设置 position: sticky; left: 0 吸左；交叉单元格（表头第一列）同时设置 top 和 left，z-index 更高。 |
| 原理和工作流程 | sticky 定位在滚动到阈值时自动变为固定，不需要 JavaScript。z-index 控制层级，交叉单元格需要最高层级保证显示在最上层。 |
| 缺点 | 父容器设置 overflow: hidden 导致 sticky 失效，是常见错误。 |

### 5. 题目：设计一个暗黑模式切换方案（CSS 变量实现）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 CSS 变量实现主题切换的方案：所有颜色用 CSS 变量定义，切换主题只需要修改变量。 |
| 能做什么 | 检验对 CSS 变量实际应用的理解。 |
| 怎么用 | :root 中定义 CSS 变量（--bg-color、--text-color、--card-bg）；light 和 dark 主题修改变量值；HTML 上设置 data-theme 属性选择主题；localStorage 保存用户偏好，页面加载时读取。 |
| 原理和工作流程 | 所有样式使用 CSS 变量，切换主题只需要修改根元素上的变量值，不需要修改每个元素样式，维护方便。JavaScript 读取本地存储，应用用户偏好。 |
| 缺点 | 不使用 CSS 变量，通过替换 class 切换也能实现，但代码冗余维护麻烦，CSS 变量方案更优雅。 |
