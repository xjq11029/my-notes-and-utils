# 常见错误汇总

---

## 微前端常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 子应用样式影响主应用或其他子应用，全局样式错乱 | 未启用 CSS 隔离，或全局样式选择器未带前缀 | qiankun 启用 `experimentalStyleIsolation`；子应用使用 CSS Modules 或 BEM 命名；wujie 天然隔离 | [01-微前端架构-导览 - 2.1](./01-微前端架构-导览.md) |
| React hooks 报错 "Invalid hook call"，多个 React 实例冲突 | 主应用和子应用各自加载了独立的 React 副本，MF shared 未设置 singleton | 所有 shared 依赖必须设置 `singleton: true`，尤其是 react、react-dom、vue 等框架库 | [01-微前端架构-导览 - 2.2](./01-微前端架构-导览.md) |
| 子应用切换后内存泄漏，页面卡顿，定时器仍在运行 | 子应用 unmount 未清理全局事件监听、定时器、WebSocket 连接 | 在 unmount 生命周期中彻底清理：`clearInterval`、`removeEventListener`、`ws.close()` | [01-微前端架构-导览 - 3.1](./01-微前端架构-导览.md) |
| 子应用内部路由跳转后刷新页面出现 404 | 子应用路由与主应用路由冲突，或子应用未配置 historyApiFallback | 主应用配置通配路由捕获子应用路径；子应用 devServer 配置 `historyApiFallback: true` | [01-微前端架构-导览 - 3.3](./01-微前端架构-导览.md) |
| 子应用运行时出现奇怪的 undefined 错误 | 主应用和子应用使用了不同版本的共享依赖 | 统一 `package.json` 中的依赖版本；使用 Module Federation 的 `shared` + `singleton` 机制 | [01-微前端架构-导览 - 2.2](./01-微前端架构-导览.md) |
| 子应用 JS/CSS 加载失败 | 子应用 publicPath 配置不正确，或跨域头未设置 | 动态设置 `__webpack_public_path__`；配置 CORS 头 `Access-Control-Allow-Origin: *` | [01-微前端架构-导览 - 3.1](./01-微前端架构-导览.md) |

## 设计系统与组件库常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 业务代码中无意覆盖了组件库样式，导致组件显示异常 | 组件库样式优先级不够高，或使用了相同的选择器 | 使用 CSS @layer 将组件库样式放在低优先级层；使用 CSS Modules 或 CSS-in-JS 生成唯一类名 | [02-设计系统与组件库架构-导览 - 2.2](./02-设计系统与组件库架构-导览.md) |
| 页面加载时先显示默认主题，然后闪烁切换到用户保存的主题 | JavaScript 在客户端执行主题切换，晚于 CSS 渲染 | 在 `<head>` 中内联执行主题初始化脚本，阻止页面渲染直到主题设置完成 | [02-设计系统与组件库架构-导览 - 3.3](./02-设计系统与组件库架构-导览.md) |
| 项目打包后体积显著增加，首屏加载慢 | 全量引入组件库（如 `import { Button } from 'antd'` 可能引入整个 antd） | 使用支持 Tree Shaking 的组件库；按需引入；使用 ESM 格式；考虑使用 Headless UI + 自定义样式 | [02-设计系统与组件库架构-导览 - 1.3](./02-设计系统与组件库架构-导览.md) |

## 前端分层架构与技术管理常见错误

| 错误现象 | 产生原因 | 正确做法 | 关联导览 |
|---|---|---|---|
| 一个简单的 CRUD 页面需要经过 5 层调用，开发效率极低 | 教条式地套用分层架构，不考虑项目实际规模 | 小项目可以简化分层（如只分 View + Hook）；分层架构适用于中大型项目 | [03-前端分层架构与技术管理-导览 - 1.1](./03-前端分层架构与技术管理-导览.md) |
| 组件中直接调用 API、处理业务校验、格式化数据 | 开发者为了快速完成功能，将所有逻辑写在组件中 | 严格遵守分层规范；Code Review 时重点检查视图层是否包含业务逻辑 | [03-前端分层架构与技术管理-导览 - 3.1](./03-前端分层架构与技术管理-导览.md) |
| 引入不成熟的新技术，导致项目不稳定、团队成员学习成本高 | 技术选型时过于关注技术本身，忽略了团队能力和项目风险 | 使用五维度评估矩阵；优先选择团队熟悉的成熟技术；新技术先在小型项目中试点 | [03-前端分层架构与技术管理-导览 - 3.4](./03-前端分层架构与技术管理-导览.md) |
