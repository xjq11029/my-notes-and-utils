## 一、变量声明与作用域

### 1.1 var、let、const 对比

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 的三种变量声明关键字，var 是 ES5 函数作用域，let 和 const 是 ES6 块级作用域。 |
| 能做什么 | var 声明函数作用域变量，有变量提升；let 声明块级作用域变量，无变量提升，存在暂时性死区；const 声明块级作用域常量，声明时必须初始化，不可重新赋值（但引用类型内部属性可修改）。 |
| 怎么用 | `var a = 1;`（不推荐）、`let b = 2;`（可变变量）、`const c = 3;`（优先使用，常量配置） |
| 原理和工作流程 | var 变量在编译阶段被提升到作用域顶部，初始化为 undefined；let 和 const 同样被提升但进入暂时性死区，在声明前访问会抛出 ReferenceError。const 保证的是引用地址不变，不保证引用对象内部属性不变。 |
| 缺点 | var 无块级作用域导致变量泄露；let 的暂时性死区可能在多重 if 分支中产生意外错误；const 常被误解为"值不可变"。 |

### 1.2 作用域与作用域链

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 引擎在代码执行时按规则查找变量的机制，包括全局作用域、函数作用域和块级作用域（ES6）。 |
| 能做什么 | 控制变量的可访问范围，防止全局污染；函数能访问外部作用域变量，形成闭包的基础。 |
| 怎么用 | 全局变量在任何位置可访问；函数内部变量仅函数内可访问；{} 内 let/const 变量仅块内可访问；`function outer() { let a = 1; function inner() { console.log(a); } }` |
| 原理和工作流程 | 变量查找从当前作用域开始，沿作用域链向外层逐级查找，直到全局作用域，找不到则报 ReferenceError。作用域在函数定义时确定（静态词法作用域），与调用位置无关。 |
| 缺点 | 深层嵌套函数访问外层变量有一定性能开销；全局作用域污染是大型项目的常见问题。 |

### 1.3 变量提升（Hoisting）

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 编译阶段将变量声明和函数声明提升到当前作用域顶部的行为。 |
| 能做什么 | 理解为什么在声明前使用 var 变量得到 undefined；函数声明可以在定义前调用；let/const 为什么有暂时性死区。 |
| 怎么用 | `console.log(a); var a = 1;` → undefined（声明提升，赋值保留原位）；`foo(); function foo(){}` → 正常执行（函数声明整体提升） |
| 原理和工作流程 | 编译阶段：JavaScript 引擎先扫描代码，将 var 声明和函数声明提取到作用域顶部。var 声明初始化为 undefined，函数声明整体提升。let/const 声明也提升但不初始化，形成暂时性死区。赋值操作保留在原位置。 |
| 缺点 | 变量提升是隐式行为，容易导致代码执行结果与预期不符，因此推荐使用 let/const 替代 var。 |

## 二、数据类型

### 2.1 基本类型与引用类型

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 7 种原始类型（string、number、boolean、null、undefined、symbol、bigint）和 1 种引用类型（object），区别在于存储方式和复制行为。 |
| 能做什么 | 理解基本类型按值存储和复制，引用类型按地址存储和复制；理解为什么修改对象参数会影响外部变量。 |
| 怎么用 | 基本类型复制：`let b = a;` 复制值；引用类型复制：`let b = a;` 复制引用地址，修改 b 会影响 a；深拷贝可用 `JSON.parse(JSON.stringify(obj))` 或 `structuredClone`。 |
| 原理和工作流程 | 基本类型值存储在栈内存中，变量直接保存值；引用类型值存储在堆内存中，变量保存堆地址引用。比较时基本类型比较值，引用类型比较地址（两个相同的对象字面量不相等）。 |
| 缺点 | 引用类型浅拷贝容易导致意外修改；JSON 深拷贝不支持函数、undefined、Date 等特殊类型。 |

### 2.2 类型判断与转换

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 判断变量类型的四种方式：typeof、instanceof、Object.prototype.toString.call()、Array.isArray()，以及隐式类型转换规则。 |
| 能做什么 | typeof 判断基本类型；instanceof 判断原型链关系；Object.prototype.toString.call() 通用判断返回 `[object Type]`；Array.isArray() 判断数组。 |
| 怎么用 | `typeof 'abc'` → 'string'；`[] instanceof Array` → true；`Object.prototype.toString.call(null)` → `[object Null]`；`Array.isArray([])` → true |
| 原理和工作流程 | typeof 通过查询值的内部类型标签返回类型字符串，null 的内部标签为 0x00 导致返回 'object'（历史遗留 bug）。instanceof 通过原型链查找构造函数的 prototype。隐式转换在操作符 +、== 等场景下触发，遵循 ToPrimitive 抽象操作。 |
| 缺点 | typeof 无法区分 null 和 object；typeof 无法区分数组和对象；instanceof 在多窗口环境下可能失效（不同窗口的 Array 构造函数不同）。 |

### 2.3 深拷贝与浅拷贝

| 维度 | 内容 |
|------|------|
| 是什么 | 浅拷贝只复制对象第一层属性（引用类型属性共享引用），深拷贝递归复制所有层级的属性值。 |
| 能做什么 | 浅拷贝用于需要共享部分数据的场景；深拷贝用于完全独立的数据副本，避免修改副本影响原对象。 |
| 怎么用 | 浅拷贝：`Object.assign({}, obj)`、展开运算符 `{...obj}`、`Array.prototype.slice()`；深拷贝：`JSON.parse(JSON.stringify(obj))`、`structuredClone(obj)`、手写递归实现 |
| 原理和工作流程 | 浅拷贝创建一个新对象，将原对象的属性值复制到新对象，但引用类型属性复制的是引用地址；深拷贝递归遍历所有属性，对引用类型属性创建新的副本，确保完全独立。手写深拷贝需处理循环引用（WeakMap 记录已拷贝对象）、特殊类型（Date、RegExp、Map、Set）。 |
| 缺点 | JSON 深拷贝无法处理函数、undefined、Symbol、Date、RegExp、循环引用；structuredClone 无法处理函数和 Symbol；手写深拷贝实现复杂。 |

## 三、原型与继承

### 3.1 原型链

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 实现继承的机制：每个对象有 `__proto__` 指向其构造函数的 `prototype`，通过链式查找实现属性共享。 |
| 能做什么 | 实现对象间的属性继承和方法共享；理解 JavaScript 的一切皆对象，原型链是对象属性查找的路径。 |
| 怎么用 | `obj.__proto__` 获取原型；`Object.getPrototypeOf(obj)` 标准方式获取原型；`Constructor.prototype` 获取构造函数原型；所有对象最终指向 `Object.prototype`，其 `__proto__` 为 null。 |
| 原理和工作流程 | 访问对象属性时，先在自身查找，未找到则沿 `__proto__` 链向上查找，直到找到或到达 null。原型链的终点是 `Object.prototype.__proto__ === null`。instanceof 通过原型链判断对象是否由某个构造函数创建。 |
| 缺点 | 原型链过长会影响属性查找性能；不建议直接修改内置对象的原型（如 Array.prototype），属于全局污染。 |

### 3.2 继承方式对比

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 实现继承的 6 种方式：原型链继承、构造函数继承、组合继承、原型式继承、寄生式继承、ES6 class extends。 |
| 能做什么 | 实现代码复用，子类继承父类的属性和方法，ES6 class 是推荐的继承方式。 |
| 怎么用 | 原型链继承：`Child.prototype = new Parent();`；构造函数继承：`Parent.call(this);`；组合继承：原型链 + 构造函数；ES6：`class Child extends Parent { constructor() { super(); } }` |
| 原理和工作流程 | 原型链继承让子类原型指向父类实例，共享父类方法但引用类型属性被所有实例共享；构造函数继承在子类中调用父类构造函数，解决属性共享问题但不继承方法；组合继承结合两者；ES6 class 本质是语法糖，底层仍是原型链，但更清晰。 |
| 缺点 | 组合继承调用两次父类构造函数；ES6 class 可能让开发者忽略底层原型链机制。 |

## 四、执行上下文与闭包

### 4.1 执行上下文与调用栈

| 维度 | 内容 |
|------|------|
| 是什么 | 执行上下文是 JavaScript 代码执行时创建的环境对象，包含变量对象、作用域链和 this 绑定；调用栈是管理执行上下文后进先出的栈结构。 |
| 能做什么 | 理解变量访问规则和 this 指向；理解函数调用堆栈和递归深度限制；理解为什么能通过调用栈追踪错误。 |
| 怎么用 | 全局执行上下文在代码执行前创建；函数调用时创建函数执行上下文，push 到调用栈顶部，执行完毕后 pop 出栈。 |
| 原理和工作流程 | 创建阶段：建立变量对象、建立作用域链、确定 this 指向；执行阶段：变量赋值、函数引用等实际操作。调用栈保证函数执行顺序，栈溢出错误（Maximum call stack size exceeded）发生在递归过深时。 |
| 缺点 | 无限递归导致栈溢出；调用栈过深时调试困难。 |

### 4.2 闭包（Closure）

| 维度 | 内容 |
|------|------|
| 是什么 | 函数能访问其定义时所在作用域中变量的能力，即使函数在其作用域外执行。 |
| 能做什么 | 实现数据私有化（模块模式）；创建工厂函数；实现柯里化和偏函数；缓存计算结果（记忆化）；防抖节流等常见模式。 |
| 怎么用 | `function outer() { let count = 0; return function() { return ++count; }; }`，内部函数持有 outer 作用域的 count 变量引用。 |
| 原理和工作流程 | 闭包在函数定义时创建。函数的内部属性 `[[Scopes]]` 保存了定义时的作用域链，即使外部函数执行完毕，其变量对象因内部函数引用而不会被垃圾回收，形成闭包。 |
| 缺点 | 未及时释放的闭包变量占用内存，可能导致内存泄漏；在循环中错误使用闭包是常见问题（需要使用 let 或 IIFE 解决）。 |

### 4.3 this 指向

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 函数内部的 this 值在调用时确定，不同调用方式有不同绑定规则。 |
| 能做什么 | 普通函数调用时 this 指向全局对象（严格模式为 undefined）；方法调用时指向调用者对象；new 关键字指向新创建实例；call/apply/bind 显式绑定；箭头函数继承外层 this。 |
| 怎么用 | `fn()` → this 为 window/undefined；`obj.fn()` → this 为 obj；`new Fn()` → this 为新实例；`fn.call(ctx)` → this 为 ctx；`() => {}` → this 继承外层 |
| 原理和工作流程 | 调用栈决定 this 绑定：new 绑定优先于显式绑定优先于隐式绑定优先于默认绑定。箭头函数没有自己的 this，使用定义时的外层 this，不能通过 call/apply/bind 修改。 |
| 缺点 | 默认绑定在严格模式下不一致；回调函数中 this 丢失是常见问题；箭头函数无法作为构造函数。 |

## 五、事件循环（Event Loop）

### 5.1 宏任务与微任务

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 运行时处理异步操作的调度机制：宏任务（Task）和微任务（Microtask）两个队列，微任务优先级高于宏任务。 |
| 能做什么 | 理解异步代码执行顺序，解释为什么 `Promise.resolve().then()` 比 `setTimeout` 先执行；理解 `nextTick`（Node.js）和 `queueMicrotask` 的行为。 |
| 怎么用 | 宏任务：setTimeout、setInterval、I/O；微任务：Promise.then/catch/finally、async/await、MutationObserver、queueMicrotask。执行顺序：同步代码 → 微任务队列清空 → 取出一个宏任务执行 → 清空微任务队列 → 循环。 |
| 原理和工作流程 | 浏览器/Node.js 环境中，事件循环持续运行：从宏任务队列取一个任务执行，执行过程中产生的微任务加入微任务队列；宏任务执行完成后清空微任务队列，然后渲染 UI（浏览器），再取下一个宏任务。 |
| 缺点 | 微任务队列过长会阻塞宏任务和 UI 渲染，导致页面卡顿；理解事件循环需要大量实践。 |

## 六、错误处理

### 6.1 try/catch/finally

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 的异常捕获机制，try 块中代码出错时跳转到 catch 块执行，finally 块无论是否出错都会执行。 |
| 能做什么 | 捕获同步代码中的运行时错误，防止程序崩溃；提供错误恢复机制；finally 常用于资源清理（关闭连接、释放锁）。 |
| 怎么用 | `try { riskyCode(); } catch(err) { console.error(err.message); } finally { cleanup(); }`；catch 参数可省略（ES2019）；可嵌套 try/catch 实现分层错误处理。 |
| 原理和工作流程 | 当 try 块中抛出异常时，JavaScript 引擎沿调用栈向上查找最近的 catch 块。如果找到则执行 catch 块，然后执行 finally 块。如果未找到则程序终止。throw 语句可抛出任意类型的值，建议抛 Error 实例。 |
| 缺点 | 只能捕获同步错误，无法捕获异步错误（Promise 需用 .catch() 或 try/catch + await）；滥用 try/catch 会降低性能；过度捕获会掩盖真实 bug。 |

### 6.2 Error 类型与自定义错误

| 维度 | 内容 |
|------|------|
| 是什么 | JavaScript 内置的 7 种错误类型：Error、SyntaxError、TypeError、RangeError、ReferenceError、URIError、EvalError，以及通过继承 Error 创建自定义错误类。 |
| 能做什么 | 区分不同类型的错误，针对性处理；自定义错误类携带业务信息（如错误码、HTTP 状态码）；全局错误捕获（window.onerror、unhandledrejection）。 |
| 怎么用 | 内置错误由引擎自动抛出；自定义错误：`class BusinessError extends Error { constructor(msg, code) { super(msg); this.code = code; } }`；全局捕获：`window.onerror` 捕获未处理同步错误，`window.addEventListener('unhandledrejection')` 捕获未处理 Promise 拒绝。 |
| 原理和工作流程 | Error 实例包含 name、message、stack 三个核心属性。throw 抛出错误后沿调用栈冒泡，直到被 catch 捕获或到达全局作用域。Promise 拒绝通过微任务队列传播，不会被 window.onerror 捕获。 |
| 缺点 | 自定义错误类需要手动设置 name 属性；stack 属性是非标准但广泛支持；全局错误捕获只能做上报，无法真正恢复程序状态。 |

## 七、ArrayBuffer 与 TypedArray

### 7.1 二进制数据处理基础

| 维度 | 内容 |
|------|------|
| 是什么 | ArrayBuffer 是 JavaScript 中表示固定长度原始二进制数据的缓冲区，TypedArray 是操作 ArrayBuffer 的视图（如 Uint8Array、Int32Array、Float64Array）。 |
| 能做什么 | 处理文件二进制数据（如上传文件分片）；WebSocket 二进制消息解析；WebGL 顶点数据传输；与 WebAssembly 共享内存；大文件 MD5 计算等场景。 |
| 怎么用 | `const buf = new ArrayBuffer(16);` 创建 16 字节缓冲区；`const view = new Uint8Array(buf);` 创建视图；`view[0] = 255;` 写入数据；`new DataView(buf)` 提供更灵活的数据视图（支持不同字节序读取）。 |
| 原理和工作流程 | ArrayBuffer 分配连续内存空间，TypedArray 是对这段内存的类型化视图，不额外分配内存。DataView 提供 getInt8/setInt16 等方法，支持指定字节序（大端/小端）。TypedArray 遵循 Array 接口但行为有差异（如 map 返回同类型 TypedArray）。 |
| 缺点 | ArrayBuffer 大小固定，创建后不可调整；TypedArray 方法返回的仍是 TypedArray（非普通数组）；字节序（Endianness）在不同平台可能不同，需 DataView 显式指定。 |

## 八、常见面试题

### 1. var、let、const 的区别

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 JavaScript 三种变量声明关键字在作用域、变量提升、重复声明、暂时性死区四个维度的差异。 |
| 能做什么 | 检验对 ES6 变量声明特性的理解，以及为何推荐使用 const/let 替代 var。 |
| 怎么用 | var：函数作用域、有变量提升、可重复声明；let：块级作用域、有暂时性死区、不可重复声明；const：块级作用域、有暂时性死区、不可重复声明、不可重新赋值。 |
| 原理和工作流程 | 编译阶段 var 声明被提升并初始化为 undefined；let/const 声明被提升但不初始化，形成暂时性死区。const 是引用不可变，不是值不可变。 |
| 缺点 | 回答时容易漏掉"暂时性死区"和"const 引用不可变但内部属性可修改"两个关键点。 |

### 2. 原型链与继承

| 维度 | 内容 |
|------|------|
| 是什么 | 考查原型链查找机制和多种继承方式的实现原理。 |
| 能做什么 | 检验对 JavaScript 面向对象编程的底层理解。 |
| 怎么用 | 每个对象有 `__proto__`，构造函数有 `prototype`；继承方式：原型链继承、构造函数继承、组合继承、ES6 class extends。 |
| 原理和工作流程 | 属性查找沿 `__proto__` 链逐级向上，instanceof 通过原型链判断。ES6 class 的 extends 和 super 是原型链继承的语法糖，底层仍是 `Child.prototype.__proto__ = Parent.prototype`。 |
| 缺点 | 回答时容易混淆 `__proto__` 和 `prototype` 的区别。 |

### 3. 闭包的概念与应用

| 维度 | 内容 |
|------|------|
| 是什么 | 考查闭包的定义、形成条件、常见应用场景和内存泄漏风险。 |
| 能做什么 | 检验对闭包机制的理解和实际应用能力。 |
| 怎么用 | 形成条件：内部函数引用外部函数变量；应用：数据私有化（模块模式）、工厂函数、柯里化、防抖节流、记忆化缓存。 |
| 原理和工作流程 | 函数定义时创建 `[[Scopes]]` 保存外部作用域链，外部函数执行完毕后其变量对象因被内部函数引用而不被 GC 回收，内部函数调用时通过 `[[Scopes]]` 访问外部变量。 |
| 缺点 | 容易忽略闭包的内存泄漏风险，以及循环中 var 导致闭包引用同一变量的问题。 |

### 4. 事件循环（Event Loop）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查事件循环机制：宏任务和微任务的定义、执行顺序、以及 setTimeou t 和 Promise 的优先级。 |
| 能做什么 | 检验对 JavaScript 异步执行机制的深入理解，这是前端面试的核心考点。 |
| 怎么用 | 执行顺序：同步代码 → 清空微任务队列 → 取一个宏任务 → 清空微任务队列 → 循环。宏任务：setTimeout、setInterval；微任务：Promise.then、MutationObserver。 |
| 原理和工作流程 | 事件循环持续运行，微任务队列在宏任务间隙清空。浏览器环境下宏任务执行后、微任务清空后会进行 UI 渲染。Node.js 环境有额外阶段（timers、I/O、check 等）。 |
| 缺点 | 容易混淆哪些是宏任务哪些是微任务；Node.js 的 process.nextTick 优先级高于 Promise。 |

## 九、避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | 汇总 JavaScript 语法基础和执行机制中 6 个高频错误：var 变量泄露、this 指向丢失、闭包内存泄漏、循环中闭包引用、类型判断、事件循环执行顺序。 |
| 能做什么 | 帮助开发者提前规避常见陷阱，写出更健壮的代码。 |
| 怎么用 | 使用 const/let 替代 var；箭头函数避免 this 绑定问题；及时释放闭包引用；循环中使用 let 或 IIFE 解决闭包问题；使用 Object.prototype.toString.call() 准确判断类型。 |
| 原理和工作流程 | 每个错误对应一个底层机制的误解：var 无块级作用域导致变量泄露；this 由调用方式决定；闭包未释放导致内存泄漏；var 循环中闭包引用同一变量；typeof null 返回 object 是历史 bug。 |
| 缺点 | 部分避坑方案需要理解底层机制才能正确应用，初学者容易机械套用。 |
