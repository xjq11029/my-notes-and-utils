### 1. 下面哪一个不是 JavaScript 基本数据类型？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查原始类型和引用类型区分，Object 是引用类型不是基本类型。 |
| 能做什么 | 检验对数据类型分类的记忆。 |
| 怎么用 | 基本类型：string、number、boolean、null、undefined、symbol、bigint；引用类型：Object、Array、Function 等。 |
| 原理和工作流程 | 基本类型存储在栈内存，值直接存储；引用类型存储在堆内存，栈中存储地址引用。 |
| 缺点 | 容易把 null 误认为引用类型，实际上 null 是基本类型。 |

### 2. 以下哪句话描述 this 是错误的？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查箭头函数 this 特性：箭头函数不绑定自己的 this，继承外层作用域的 this。 |
| 能做什么 | 检验对箭头函数 this 规则的理解。 |
| 怎么用 | "箭头函数的 this 由调用方式决定" 是错误的，箭头函数 this 在定义时继承外层，调用方式不改变。 |
| 原理和工作流程 | 普通函数 this 在调用时确定；箭头函数 this 在定义时确定，由外层作用域的 this 决定，call/apply/bind 无法修改。 |
| 缺点 | 混淆普通函数和箭头函数 this 绑定规则是常见错误。 |

### 3. 关于闭包描述正确的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查闭包定义：函数能够访问其定义时所在作用域变量，即使在作用域外执行。 |
| 能做什么 | 检验闭包核心概念记忆。 |
| 怎么用 | 闭包形成条件：内部函数引用外部函数变量；利用 `[[Scopes]]` 保存作用域链，外部函数执行后变量不被回收。 |
| 原理和工作流程 | JavaScript 是词法作用域，函数定义时就保存了作用域链，内部函数引用外部变量导致外部变量无法被垃圾回收。 |
| 缺点 | 认为闭包会导致内存泄漏（不一定，只有不释放才会泄漏）是常见错误。 |

### 4. 关于原型链描述错误的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 `__proto__` 和 `prototype` 的关系：`__proto__` 是对象上的属性，指向构造函数的 `prototype`。 |
| 能做什么 | 检验对原型链核心关系的理解。 |
| 怎么用 | 构造函数有 `prototype`，实例有 `__proto__`，`instance.__proto__ === Constructor.prototype`。 |
| 原理和工作流程 | 实例通过 `__proto__` 链接到原型，查找属性沿链向上，直到 `Object.prototype.__proto__` 为 null。 |
| 缺点 | 混淆 `prototype` 和 `__proto__` 的所属对象是常见错误。 |

### 5. 执行 `typeof null` 的结果是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 typeof null 返回 'object' 是历史遗留 bug，null 本身是基本类型。 |
| 能做什么 | 检验对类型判断陷阱的记忆。 |
| 怎么用 | 由于 JavaScript 最初实现中错误将 null 的类型标签设为 0，导致 typeof 返回 'object'，这个 bug 一直保留至今。 |
| 原理和工作流程 | typeof 根据值的内部类型标签返回结果，null 类型标签为 0，因此返回 'object'。但 null 本身是独立的基本类型。 |
| 缺点 | 容易回答 'null'，实际上返回的是 'object'。 |

### 6. let 和 const 描述错误的是？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 const 的特性：const 声明的变量不可重新赋值，但引用类型内部属性可修改。 |
| 能做什么 | 检验对 const 特性的准确理解。 |
| 怎么用 | "const 声明的对象不能修改" 是错误说法，const 保证的是引用不可变，不保证值不可变。 |
| 原理和工作流程 | const 存储的是值（基本类型）或地址（引用类型），重新赋值会改变地址，const 不允许；修改对象属性不改变地址，因此允许。 |
| 缺点 | 误解为 const 完全不可变是常见错误。 |

| 维度 | 内容 |
| 是什么 | 考查解决回调地狱的方案：Promise、async/await、Generator + co 都能解决，事件冒泡不能解决。 |

| 怎么用 | 回调地狱是多层嵌套导致代码难以维护；Promise 链式调用解决嵌套；async/await 同步写法解决嵌套；Generator + co 自动执行也能解决；事件冒泡是 DOM 事件模型，和异步无关。 |
| 原理和工作流程 | 解决回调地狱的核心是将嵌套结构改为线性结构，方便阅读和维护。三种方案都实现了结构扁平化。 |
| 缺点 | 不知道 Generator 能解决回调地狱是常见错误。 |

### 8. Promise 的哪句话描述是错误的？

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Promise 状态特性：pending 可以变为 fulfilled 或 rejected，状态一旦改变不可逆。 |
| 能做什么 | 检验对 Promise 状态机特性的理解。 |
| 怎么用 | "状态可以在 fulfilled 和 rejected 之间切换" 错误，状态一旦改变就固定，不能再变。 |
| 原理和工作流程 | Promise 状态只能从 pending 到 fulfilled 或 pending 到 rejected，不能反向切换，也不能二次切换。 |
| 缺点 | 忽略不可逆特性是常见错误。 |

### 9. 关于 async/await 描述错误的是？

### 10. 以下哪个事件顺序是正确的？

| 怎么用 | 执行顺序：同步代码 → 清空微任务队列（Promise.then 是微任务） → 取一个宏任务执行（setTimeout 是宏任务） → 清空微任务 → 浏览器渲染 → 下一轮循环。 |

| 能做什么 | 检验对 this 绑定规则的全面理解。 |
| 怎么用 | 优先级：new 绑定 > 显式绑定（bind/call/apply）> 隐式绑定（obj.fn()）> 默认绑定；箭头函数不参与绑定，继承外层 this。 |
| 原理和工作流程 | this 在调用时确定，根据绑定规则确定值；箭头函数 this 在定义时继承外层，不可修改。 |
| 缺点 | 排序优先级错误是常见问题。 |

### 6. Promise 状态和流程，常用 API

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Promise 三种状态、流程、常用静态和实例方法。 |
| 能做什么 | 检验对 Promise 基本概念和 API 的掌握。 |
| 怎么用 | 三种状态：pending、fulfilled、rejected，状态不可逆；流程：构造函数执行器 → resolve/reject 改变状态 → then 处理结果；常用 API：then/catch/finally、Promise.resolve/reject/all/race/allSettled/any。 |
| 原理和工作流程 | then 返回新 Promise 支持链式调用；Promise.all 全部成功才成功，一个失败直接失败；Promise.allSettled 等待所有完成，无论成功失败。 |
| 缺点 | 说不出 all 和 allSettled 的区别是常见问题。 |

### 7. async/await 实现原理，和 Promise 的关系

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 async/await 本质是 Promise + Generator 语法糖，底层依赖 Promise。 |
| 能做什么 | 检验对 async/await 底层机制的理解。 |
| 怎么用 | async 函数返回 Promise；await 等待 Promise 完成；async/await 是语法糖，将 Promise 链式调用改为同步写法，底层还是 Promise。 |
| 原理和工作流程 | 相当于自动执行 Generator，每次 yield 等待 Promise 完成后继续下一个 yield。 |
| 缺点 | 不知道和 Generator 的关系是常见错误。 |

### 8. 说一下事件循环（Event Loop）

| 维度 | 内容 |
|------|------|
| 是什么 | 考查事件循环执行流程、宏任务和微任务、执行顺序。 |
| 能做什么 | 这是 JavaScript 异步机制的核心考点，检验理解深度。 |
| 怎么用 | 执行顺序：同步代码 → 清空微任务队列 → 取一个宏任务 → 清空微任务 → 循环；宏任务：setTimeout、setInterval、I/O；微任务：Promise.then、async/await；微任务优先级高于宏任务。 |
| 原理和工作流程 | JavaScript 单线程，通过事件循环处理异步任务，主线程空闲时不断从任务队列取任务执行。微任务必须在当前宏任务结束后立即执行完，再进入下一轮。 |
| 缺点 | 执行顺序说反（先宏后微）是常见错误。 |

### 9. 防抖和节流的区别，各自应用场景

| 维度 | 内容 |
|------|------|
| 是什么 | 考查两种频率控制技术在核心思想和应用场景上的区别。 |
| 能做什么 | 检验实际开发中能否正确选择方案。 |
| 怎么用 | 防抖：频繁触发只在最后一次后延迟执行一次，适合搜索框输入联想、窗口 resize；节流：固定间隔执行一次，适合滚动事件、鼠标移动、按钮防重复点击。 |
| 原理和工作流程 | 防抖重置计时器，适合需要等输入停止后执行的场景；节流保证间隔执行，适合需要保证一定频率执行的场景。 |
| 缺点 | 混淆应用场景是常见错误。 |

### 10. 事件委托原理和优点

| 维度 | 内容 |
|------|------|
| 是什么 | 考查事件委托原理和核心优点。 |
| 能做什么 | 检验对 DOM 事件模型的理解和优化经验。 |
| 怎么用 | 原理：利用事件冒泡，将事件监听器绑定在父元素，通过目标元素匹配判断是否执行；优点：减少监听器数量、节省内存、动态添加子元素自动支持事件。 |
| 原理和工作流程 | 事件从目标向上冒泡到父元素，父元素一次监听处理所有子元素事件，不需要给每个子元素绑定。 |
| 缺点 | 说不出动态元素支持这个优点是常见错误。 |

### 11. 实现深拷贝需要考虑哪些问题

### 12. 说一下 JavaScript 继承有哪些方式

| 维度 | 内容 |
|------|------|
| 是什么 | 考查常见继承方式以及优缺点，ES6 class 继承本质。 |
| 能做什么 | 检验对 JavaScript 继承实现演进的理解。 |
| 怎么用 | 原型链继承：子类原型 = 父类实例，缺点：引用属性所有实例共享；构造函数继承：调用父类构造函数，缺点：不能继承父类原型方法；组合继承：原型链 + 构造函数（推荐 ES5）；ES6 class extends 是语法糖，底层还是组合寄生继承。 |
| 原理和工作流程 | ES5 组合继承解决了原型链继承和构造函数继承的缺点，是 ES5 最佳实践；ES6 class 语法更清晰。 |
| 缺点 | 说不出组合继承是 ES5 最佳实践是常见错误。 |

### 13. 说一下 CommonJS 和 ES 模块化的区别

|------|------|

| 能做什么 | 检验对 JavaScript 模块化系统的理解。 |
| 怎么用 | CommonJS：运行时加载，输出值副本，require/module.exports；ESM：编译时加载，输出引用绑定，import/export。CommonJS 适合 Node.js，ESM 适合浏览器。 |
| 原理和工作流程 | ESM 静态结构支持 Tree Shaking，打包工具可以删除未使用导出，减少打包体积；CommonJS 动态加载无法 Tree Shaking。 |
| 缺点 | 分不清值副本和引用绑定区别是常见错误。 |

### 14. 为什么会有内存泄漏，哪些情况会导致

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 JavaScript 内存泄漏原因和常见场景。 |
| 能做什么 | 检验对垃圾回收和内存管理的理解。 |
| 怎么用 | 原因：不再需要的对象仍然被引用，垃圾回收无法回收。常见场景：未清理的定时器和事件监听器、闭包持有大对象引用、全局变量、缓存未清理、DOM 移除后仍被引用。 |
| 原理和工作流程 | JavaScript 自动垃圾回收，通过可达性判断对象是否存活，如果对象仍被可达引用就无法回收，形成内存泄漏。 |
| 缺点 | 说不出三种以上场景是常见错误。 |

### 15. 说一下对虚拟 DOM 的理解

| 维度 | 内容 |
|------|------|
| 是什么 | 考查虚拟 DOM 概念、优点、diff 算法核心。 |
| 能做什么 | 检验对现代前端框架核心机制的理解。 |
| 怎么用 | 虚拟 DOM 是真实 DOM 的 JavaScript 对象描述，通过 diff 算法比较新旧虚拟 DOM 差异，最小化更新真实 DOM。优点：减少 DOM 操作、跨平台（SSR、React Native）、简化开发。 |
| 原理和工作流程 | 数据变化生成新虚拟树，diff 算法同层级比较，找到差异后更新对应真实 DOM，避免全量更新 DOM，提升性能。 |
| 缺点 | 说不出 diff 算法同层级比较是核心是常见错误。 |

### 2. 题目：数字千分位格式化

| 维度 | 内容 |

| 是什么 | 考查将数字转为千分位格式（1234567 → 1,234,567），可以用正则或遍历实现。 |
| 能做什么 | 检验正则表达式运用能力或字符串处理能力。 |

### 3. 题目：斐波那契数列第 N 项

| 维度 | 内容 |
|------|------|
| 是什么 | 考查斐波那契数列的优化实现，从递归到动态规划，分析时间复杂度。 |
| 能做什么 | 检验算法优化能力，理解暴力递归缺陷和动态规划优化。 |
| 怎么用 | 暴力递归 O(2^n) 太慢；动态规划自底向上 O(n) 时间 O(1) 空间；记忆化递归用 Map 缓存结果 O(n)。 |
| 原理和工作流程 | 递推公式 `f(n) = f(n-1) + f(n-2)`，暴力递归存在大量重复计算；动态规划保存前两项结果，迭代计算，空间复杂度优化到 O(1)。 |
| 缺点 | 直接写递归不优化，时间复杂度过高对于大 N 会栈溢出。 |

### 4. 题目：对象扁平化（将嵌套对象转为一层对象，键用点连接）

| 维度 | 内容 |

| 能做什么 | 检验递归遍历和对象处理能力。 |
| 怎么用 | 递归遍历每个属性，如果值是对象且非 null 就递归拼接键，否则赋值到结果对象。 |
| 原理和工作流程 | 从根对象开始，递归进入每个对象属性，累积键路径，遇到非对象就将结果写入结果对象。 |
| 缺点 | 忘记处理数组和 null（null typeof 是 object）会导致错误。 |

### 5. 题目：实现 Promise 并发控制，限制最多 N 个并发

| 维度 | 内容 |
|------|------|
| 是什么 | 考查 Promise 并发控制实现，限制同时进行的 Promise 最大数量。 |
| 能做什么 | 检验对 Promise 的深入理解和异步控制能力。 |
| 怎么用 | 维护当前并发计数，取出任务执行，完成后递减计数，继续取下一个任务直到全部完成。 |
| 原理和工作流程 | 先启动 N 个任务，每个任务完成后触发下一个任务，通过 Promise 链控制并发数量，最后返回所有结果。 |
| 缺点 | 不知道用计数控制，直接 Promise.all 无法限制并发。 |
