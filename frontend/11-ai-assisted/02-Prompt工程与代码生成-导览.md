## 核心概念

| 维度 | 内容 |
|------|------|
| 是什么 | Prompt 工程是通过精确指令精确控制 AI 输出的方法体系。同样的 AI 模型，不同的 Prompt 会产生截然不同的代码质量。前端代码生成的特殊性在于：组件有固定的结构（template/script/style），需要遵循框架规范（Vue/React），需要处理复杂的用户交互和状态管理，输出格式要求严格固定。 |
| 能做什么 | 提升 AI 代码准确率 50%+（通过 Few-shot 示例）；避免 AI 幻觉（通过约束 API 范围）；生成固定格式代码（通过结构化输出要求）；处理复杂表单等大规模场景（通过分层分步策略）；让 AI 生成符合项目编码规范的代码（通过注入项目上下文）。 |
| 怎么用 | 遵循核心原则：Prompt 是精确指令不是聊天（不要模糊描述，要像写需求文档一样精确）；上下文决定输出质量（必须显式提供项目结构、技术栈、编码规范）；Few-shot 是质量加速器（提供 1-3 个示例可大幅提升准确率）；结构化输出是可控性的关键（要求固定格式减少幻觉空间）。 |
| 原理和工作流程 | Prompt 中的信息定义了 AI 的"知识视野"，精确的上下文缩小了搜索空间，Few-shot 示例提供了格式模板，约束条件过滤了不安全输出。AI 模型基于 Prompt 中的信息从训练知识中匹配最符合约束的结果。Prompt 越精确，匹配结果越符合预期。 |
| 缺点 | 高质量 Prompt 需要时间编写和迭代；不同 AI 模型对同一 Prompt 的响应可能不同（需要针对模型微调）；长 Prompt 可能超出上下文窗口导致 AI 遗忘关键约束；分步生成会增加交互轮次，开发周期比一次性生成更长。 |

## Prompt 工程五要素

| 维度 | 内容 |
|------|------|
| 是什么 | 通过五要素（角色设定、任务描述、上下文信息、输出格式、约束条件）精确控制 AI 代码输出的方法体系。 |
| 能做什么 | 提升 AI 代码准确率 50%+（Few-shot 示例）；避免 AI 幻觉（约束 API 范围）；生成固定格式代码（结构化输出）；处理复杂表单等大规模场景。 |
| 怎么用 | 角色设定 → 明确任务描述 → 注入项目上下文（技术栈、文件路径、现有代码风格）→ 指定输出格式（JSON Schema / Markdown 表格）→ 添加约束条件。 |
| 原理和工作流程 | Prompt 中的信息决定 AI 的"知识视野"——精确的上下文缩小搜索空间，Few-shot 示例提供格式模板，约束条件过滤不安全输出。 |
| 缺点 | 高质量 Prompt 需要时间编写和迭代；不同 AI 模型对同一 Prompt 的响应可能不同；长 Prompt 可能超出上下文窗口。 |

## 复杂表单 Prompt 策略

| 维度 | 内容 |
|------|------|
| 是什么 | 将几百个字段的复杂表单拆解为多层 Prompt（架构设计 → 依赖规则 → 组件生成），逐步生成的方案。 |
| 能做什么 | 第一层：设计 Pinia 多 store 拆分 + shallowRef 性能优化；第二层：实现声明式字段联动规则引擎；第三层：生成具体组件代码。 |
| 怎么用 | 先 Prompt 架构方案（不写代码）→ 确认方案 → Prompt 依赖规则引擎 → 确认 → Prompt 各子组件代码。 |
| 原理和工作流程 | 分步策略避免单次 Prompt 信息过载：架构层关注宏观设计，规则层关注字段间逻辑，代码层关注具体实现。 |
| 缺点 | 分步执行耗时较长；需要人工判断每步结果的正确性；步骤间上下文可能丢失需要重新注入。 |

## 前端专用 Prompt 模板库

| 维度 | 内容 |
|------|------|
| 是什么 | 针对前端开发四大高频场景（组件生成、单元测试、代码重构、代码审查）预制的 Prompt 模板集合。每个模板遵循五要素原则（角色设定 + 任务描述 + 上下文注入 + 输出格式 + 约束条件），前端开发者可直接套用或微调后使用。 |
| 能做什么 | 组件生成模板：生成 Vue 3 单文件组件，包含 Props/Events 定义、错误处理、可访问性；单元测试模板：生成 Vitest + Vue Test Utils 测试，覆盖所有 props/emits/交互/异步；代码重构模板：按单一职责、类型安全、错误处理等五原则重构；代码审查模板：从类型安全、竞态条件、内存泄漏、安全、性能、可访问性、代码风格七个维度审查。 |
| 怎么用 | 组件生成：复制模板 → 填写功能需求表格（Props/Events 定义）→ 指定技术栈（Vue 3+TypeScript+Element Plus）→ 粘贴代码获取完整 .vue 文件；单元测试：粘贴组件代码 → 指定测试场景（正常值、边界值、用户交互、异步操作）→ 获取完整测试文件；重构：粘贴原始代码 → 指定重构原则 → 获取带注释标注的重构结果；审查：粘贴代码 → 指定审查维度 → 获取按严重程度分级的报告。 |
| 原理和工作流程 | 每个模板预置了前端开发场景的完整上下文和约束条件，AI 只需在模板框架内填充具体内容。模板通过角色设定控制专业水平、通过输出格式控制结果结构、通过约束条件过滤不安全输出。Few-shot 示例在模板中预先嵌入，提供格式参考。 |
| 缺点 | 模板需要根据项目实际情况调整（技术栈、编码规范不同）；过于依赖模板可能导致 Prompt 僵化，不适合高度定制化需求；模板中的示例可能被 AI 直接复制（需使用不同领域的示例体现"格式"而非"内容"）；模板无法覆盖所有边缘场景，复杂场景仍需人工编写 Prompt。 |

## 常见问题与避坑指南

| 维度 | 内容 |
|------|------|
| 是什么 | Prompt 工程中常见的六类问题：AI 使用过时 API（如 Vue 2 语法）、AI 编造不存在的库（训练数据包含虚构内容）、AI 生成的代码缺少错误处理（默认"快乐路径"）、Few-shot 示例被 AI 直接复制（示例与任务太相似）、长对话中 AI 遗忘早期约束（上下文窗口限制）、复杂 Prompt 太长导致 AI 抓不住重点（信息密度过高）。 |
| 能做什么 | 逐项规避：过时 API → 在 Prompt 中明确版本号（如"Vue 3.4+，使用 `<script setup>`"）；编造库 → 限定允许使用的库列表，要求引用来源；缺少错误处理 → 要求"必须包含 loading/error/empty 三种状态"；示例被复制 → 使用不同领域的示例；遗忘约束 → 每轮对话重申关键约束；信息过载 → 拆解为多个子 Prompt 分步生成。 |
| 怎么用 | 遵循避免 AI 幻觉的三大技巧：技巧一 - 约束 API 使用范围（列出允许使用的库，不在列表中的明确说明需额外引入）；技巧二 - 要求引用官方文档（每个 API 标注来源，推测的标注"需验证"）；技巧三 - 分步生成 + 验证（先列出 API 清单 → 确认 → 生成代码 → 标注关键 API 作用）。 |
| 原理和工作流程 | AI 幻觉的根因是训练数据包含时间跨度大、质量不一的信息，AI 无法区分"当前版本有效"和"已废弃"的内容。解决方案是通过 Prompt 手动缩小知识范围（限定版本、限定库、限定 API），将 AI 的搜索空间从"所有训练数据"压缩到"当前项目上下文"。 |
| 缺点 | 约束 API 范围可能限制 AI 推荐更优方案；分步生成增加交互成本（多轮确认）；引用官方文档的要求在部分 AI 工具中可能被忽略；不同 AI 模型对约束的遵循程度不同，需要针对性调整 Prompt 策略。 |
