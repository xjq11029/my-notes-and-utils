## 一、选择题（10 题，每题附解析）

### 1. ★ 以下关于 Cursor 四种核心功能的描述，哪一项是正确的？

A. Tab 补全只能补全单行代码，不支持多行补全
B. Cmd+K（Inline Edit）可以对选中的代码块执行自然语言指令进行修改
C. Composer 只能生成单个文件，不能联动生成多个文件
D. Agent 模式完全自动运行，无需人工监控

**答案：B**

**解析**：Cmd+K（Inline Edit）是 Cursor 的核心功能之一，选中代码块后输入自然语言指令，AI 会直接修改选中区域。A 错误，Cursor 的 Tab 补全支持多行同时补全，能感知上下文中的变量和函数。C 错误，Composer 支持多文件同时生成/编辑，可以一次性创建整个功能模块。D 错误，Agent 模式需要人工监控终端输出和结果，不可完全放任。

### 2. ★ 以下关于 GitHub Copilot 独有优势的描述，哪一项是**错误**的？

A. 与 GitHub 生态深度集成，支持 PR 代码审查
B. 支持多种 IDE（VS Code、JetBrains、Neovim）
C. 提供企业级代码隐私保护，代码不用于训练模型
D. 原生支持终端命令行直接运行，不需要 IDE

**答案：D**

**解析**：GitHub Copilot 是 IDE 插件形式，需要安装在 VS Code、JetBrains 等 IDE 中使用，没有独立的 CLI 模式。Claude Code 才是原生 CLI 工具。A、B、C 均为 Copilot 的独有优势：GitHub 生态集成（PR 审查、Issue 分类）、多 IDE 支持、企业级隐私保护。

---

### 3. ★★ Claude Code 与 Cursor 在项目级重构中的核心差异是什么？

A. Claude Code 有 Tab 实时补全，Cursor 没有
B. Cursor 原生支持终端命令执行，Claude Code 不支持
C. Claude Code 自动读取项目全貌建立全局上下文，Cursor 需要手动 @ 引用
D. Claude Code 只能修改单个文件，Cursor 可以修改多文件

**答案：C**

**解析**：Claude Code 启动时会自动扫描 `package.json`、`tsconfig.json`、目录结构等，无需手动 `@` 引用即可建立全局上下文，这是其在项目级重构中的核心优势。A 错误，Cursor 有 Tab 补全，Claude Code 没有实时补全。B 错误，两者都支持终端命令执行。D 错误，Claude Code 原生支持多文件操作，在大型重构中更稳定。

### 4. ★★ Prompt 工程的五要素中，**不包括**以下哪一项？

A. 角色设定
B. 任务描述
C. 代码优化建议
D. 约束条件

**答案：C**

**解析**：Prompt 工程的五要素是：角色设定（为 AI 设定专业身份）、任务描述（清晰说明要完成的任务）、上下文信息（提供项目技术栈、文件路径等）、输出格式（约束输出结构和格式）、约束条件（限制技术选型、编码规范、边界条件）。"代码优化建议"不属于五要素，它是 AI 输出后的后续步骤。

### 5. ★★ 关于 AI 幻觉（Hallucination）在代码生成中的表现，以下哪一项描述是**错误**的？

A. AI 可能调用不存在的库方法或 API
B. AI 可能使用当前版本中已废弃的语法
C. AI 生成的代码一定存在运行时错误
D. AI 可能编造不存在的导入路径

**答案：C**

**解析**：AI 幻觉是"可能"而非"一定"——AI 生成的代码不一定都存在运行时错误，但存在幻觉风险，需要验证。A（虚构 API，如 Vue 3 中调用 `Vue.set()`）、B（过时语法，如 Vue 3 中使用 `filters`）、D（虚构导入路径，如 `import {} from 'vue/composition-api'`）都是 AI 幻觉的典型表现。

### 6. ★★ Few-shot 示例在 Prompt 工程中的作用是什么？

A. 让 AI 直接复制示例内容
B. 通过示例校准 AI 的输出格式、风格和质量基准
C. 减少 Prompt 的字符数，降低成本
D. 替代五要素中的"约束条件"

**答案：B**

**解析**：Few-shot 通过提供 1-3 个"输入-输出"示例，让 AI 模仿示例的格式、风格和质量标准，可以将输出准确率提升 50% 以上。A 错误，示例应与任务同领域但不同内容，避免 AI 直接复制。C 错误，Few-shot 会增加 Prompt 长度。D 错误，Few-shot 是约束条件的补充而非替代。

### 7. ★★ AI 代码审查的三级模型中，第二级"AI 辅助审查"的职责是什么？

A. 执行 TypeScript 类型检查和 ESLint 规则检查
B. 检测竞态条件、AI 幻觉 API、安全漏洞、内存泄漏等启发式问题
C. 判断架构合理性和业务逻辑正确性
D. 执行单元测试和构建验证

**答案：B**

**解析**：三级审查模型中，第一级是自动化检查（TypeScript + ESLint + 测试 + 构建），第二级是 AI 辅助审查（检测竞态条件、AI 幻觉 API、安全漏洞、内存泄漏等启发式问题），第三级是人工审查（判断架构合理性、业务逻辑正确性、代码可维护性）。A 和 D 属于第一级，C 属于第三级。

### 8. ★★★ 关于前端竞态条件（Race Condition）的检测和防范，以下哪一项描述是**错误**的？

A. 搜索框输入场景应使用 AbortController 取消旧请求
B. useEffect 中的异步操作应在 cleanup 函数中取消
C. 请求版本号机制可以保证只处理最新请求的结果
D. 使用 `Promise.all` 并发请求可以避免竞态条件

**答案：D**

**解析**：`Promise.all` 只是并发执行多个请求，并不解决竞态问题——如果请求的返回顺序不确定，仍然可能出现旧请求覆盖新请求结果的情况。A、B、C 都是正确的竞态防范方案：AbortController 取消旧请求、cleanup 函数清理、请求版本号机制保证只处理最新结果。

### 9. ★★★ 通过自定义 ESLint 规则在 AST 层面拦截 AI 幻觉代码，主要检测的是哪种 AST 节点？

A. VariableDeclaration（变量声明节点）
B. CallExpression（函数调用节点）和 ImportDeclaration（导入声明节点）
C. ReturnStatement（返回语句节点）
D. IfStatement（条件语句节点）

**答案：B**

**解析**：AI 幻觉代码在 AST 层面主要通过 `CallExpression`（检测不存在的 API 调用，如 `Vue.set()`）和 `ImportDeclaration`（检测虚构的导入路径，如 `import {} from 'vue/composition-api'`）来检测。VariableDeclaration、ReturnStatement、IfStatement 通常不包含幻觉特征。

### 10. ★★ 以下关于 AI 编程中上下文管理策略的描述，哪一项是**错误**的？

A. 项目级规则文件（`.cursorrules` / `CLAUDE.md`）可以在每次对话中自动注入
B. 使用 `@file` 精确引用文件比模糊描述"参考项目中已有的组件"更有效
C. 对话超过 20 轮时，AI 的生成质量通常会下降，应开启新对话
D. 上下文越长越好，应该一次性提供所有相关文件给 AI

**答案：D**

**解析**：上下文不是越长越好。AI 的上下文窗口有限，信息密度过高会导致 AI 抓不住重点，反而降低输出质量。正确做法是采用"渐进式上下文"策略——先给概要，再逐步补充细节。A（规则文件持久化）、B（精确引用）、C（定期重置）都是正确的上下文管理策略。

### 1. ★★ 对比 Cursor、Claude Code 和 GitHub Copilot 三款 AI 编程工具，分别说明各自的适用场景和核心优势。

**答案要点**：

**Cursor**：
- 核心优势：AI-first IDE，基于 VS Code 深度定制，Tab 补全流畅，图形界面友好
- 适用场景：日常编码（高频、小改动）、快速原型开发（Composer 多文件生成）
- 特色功能：Tab 多行补全、Cmd+K 精准修改、Composer 多文件生成、Agent 自主规划

**Claude Code**：
- 核心优势：CLI 原生工具，自动读取项目全貌建立全局上下文，大型重构中多文件操作更稳定，会话持久化
- 适用场景：大型重构（10+ 文件联动修改）、架构级调整、需要频繁运行测试验证的复杂任务
- 特色功能：自动项目理解、终端原生集成、CLAUDE.md 规则配置

**GitHub Copilot**：
- 核心优势：与 GitHub 生态深度集成，PR 代码审查、Issue 自动分类，企业级代码隐私保护
- 适用场景：团队协作（GitHub 生态）、多 IDE 环境（VS Code、JetBrains、Neovim）
- 特色功能：Workspace 代理、PR 审查、多 IDE 支持

**推荐组合**：Cursor（日常编码）+ Claude Code（复杂任务），两者互补。

### 2. ★★ 详细阐述 Prompt 工程的五要素，并以前端代码生成为例说明每个要素的应用。

**答案要点**：

| 要素 | 定义 | 前端代码生成中的应用示例 |
|------|------|------------------------|
| **角色设定** | 为 AI 设定专业身份和思维模式 | "你是一名资深 Vue 3 前端工程师，擅长组件抽象和 TypeScript 类型设计" |
| **任务描述** | 清晰说明要完成的具体任务 | "创建一个可复用的搜索表单组件，包含关键字搜索（防抖 300ms）、分类下拉筛选、日期范围选择" |
| **上下文信息** | 提供项目技术栈、文件路径、现有代码风格 | "项目使用 Vue 3 Composition API + TypeScript + Element Plus，组件放置在 src/components/common/" |
| **输出格式** | 约束输出结构和格式 | "输出完整的 .vue 单文件组件，包含 `<template>`、`<script setup lang="ts">`、`<style scoped>` 三个部分" |
| **约束条件** | 限制技术选型、编码规范、边界条件 | "使用 defineProps 和 defineEmits、防抖使用 lodash-es 的 debounce、必须处理 loading/error/empty 三种状态" |

**五要素缺一不可的原因**：
- 缺少角色设定：AI 可能输出初级水平的代码，缺少架构思维
- 缺少任务描述：AI 会自由发挥，输出与需求不匹配
- 缺少上下文：AI 可能使用错误的技术栈（如 Vue 2 语法）
- 缺少输出格式：AI 可能输出散乱的代码片段，无法直接使用
- 缺少约束条件：AI 可能生成无错误处理、无类型定义、不符合项目规范的代码

### 3. ★★ AI 幻觉（Hallucination）在代码生成中有哪些典型表现？请列举至少四种并说明防范策略。

**答案要点**：

**四种典型表现**：

| 幻觉类型 | 具体表现 | 实际案例 |
|---------|---------|---------|
| 虚构 API | 调用不存在的库方法、属性、配置项 | `Vue.set()`（Vue 3 中已移除）、`ElementPlus.Message.success()`（不存在的方法名） |
| 过时语法 | 使用已在当前版本中废弃的 API 或语法 | 在 Vue 3 中使用 `this.$emit`、`filters`、`Vue.extend()` |
| 虚构导入路径 | 导出来自不存在的路径的模块 | `import { useForm } from 'element-plus/es/form'`（实际路径不同） |
| 逻辑错误 | 代码"看起来正确"但运行时行为错误 | 忘记 cleanup 导致竞态条件、未处理 Promise rejection |

**多层防范策略**：

1. **Prompt 层约束**：限定 API 使用范围，要求标注 API 来源，分步生成 + 验证
2. **ESLint 规则拦截**：配置 `no-restricted-imports`、`no-floating-promises` 等规则
3. **自定义 AST 规则**：编写 ESLint 插件拦截黑名单 API（如 `Vue.set`、`Vue.filter`）
4. **TypeScript 类型检查**：编译时拦截不存在的类型和 API 调用

### 4. ★★ 阐述 AI 代码审查的三级模型，并说明各级的职责边界和适用场景。

**答案要点**：

**三级模型全景**：

| 级别 | 执行者 | 职责 | 工具 | 触发时机 | 耗时 |
|------|--------|------|------|---------|------|
| 第一级：自动化检查 | 机器 | 拦截确定性错误（类型错误、语法错误、规范违反） | TypeScript + ESLint + 测试 + 构建 | 每次 commit/push | 秒级 |
| 第二级：AI 辅助审查 | AI | 检测启发式问题（竞态条件、AI 幻觉、安全漏洞、内存泄漏） | Claude Code / Copilot Code Review | 每次 PR | 分钟级 |
| 第三级：人工审查 | 开发者 | 判断架构合理性、业务逻辑正确性、代码可维护性 | 人脑 + 业务知识 | 每次 PR | 10-30 分钟 |

**各级职责详解**：
- **第一级**：所有问题必须在进入 PR 审查前修复，任何一项失败 → CI 标红 → 阻止合入
- **第二级**：AI 审查结果作为参考，生成审查报告作为 PR 评论，需要人工确认
- **第三级**：聚焦于 AI 无法判断的维度——架构是否适合业务发展、逻辑是否符合 PRD 要求、代码是否便于长期维护

**核心原则**："让机器做机器擅长的事（确定性检查），让人做人擅长的事（架构判断和业务理解）"。

### 5. ★★★ 前端如何系统化检测和防范竞态条件（Race Condition）？请列举至少三种解决方案并给出代码示例。

**答案要点**：

**竞态条件分类**：请求竞态（搜索/筛选）、状态更新竞态（useEffect 闭包）、定时器竞态（组件卸载后执行）、事件处理竞态（快速连续点击）。

**方案一：AbortController 取消旧请求**

```typescript
let abortController: AbortController | null = null;

const doSearch = async (kw: string) => {
  abortController?.abort(); // 取消上一次请求
  abortController = new AbortController();

  try {
    const res = await fetch(`/api/search?q=${kw}`, {
      signal: abortController.signal
    });
    const data = await res.json();
    if (!abortController.signal.aborted) {
      results.value = data;
    }
  } catch (err: any) {
    if (err.name !== 'AbortError') console.error(err);
  }
};
```

**方案二：请求版本号机制**

```typescript
let requestId = 0;

async function fetchData(params: any) {
  const id = ++requestId;
  const result = await api.fetch(params);
  if (id === requestId) updateState(result); // 只处理最新请求
}
```

**方案三：ignore 标记 / cleanup 函数**

```typescript
// React useEffect
useEffect(() => {
  let ignore = false;
  fetchUser(userId).then(user => {
    if (!ignore) setUser(user);
  });
  return () => { ignore = true; };
}, [userId]);

// Vue watchEffect
watchEffect((onCleanup) => {
  let cancelled = false;
  onCleanup(() => { cancelled = true; });
  fetchUser(userId.value).then(data => {
    if (!cancelled) user.value = data;
  });
});
```

**方案四：防重复提交（loading 锁）**

```typescript
const submitting = ref(false);
const handleSubmit = async () => {
  if (submitting.value) return;
  submitting.value = true;
  try { await api.submit(formData.value); }
  finally { submitting.value = false; }
};
```

### 6. ★★ 描述 AI 编程的完整工作流（从需求到 PR），并说明每个阶段 AI 协作的要点。

**答案要点**：

**阶段一：需求分析与方案设计（占 20% 时间）**
- 用 Chat 讨论技术方案和架构设计，而非直接写代码
- 拆解需求为可独立执行的子任务
- 让 AI 充当"技术顾问"——发现需求逻辑漏洞、评估技术风险

**阶段二：编码实现（占 50% 时间）**
- 搭建项目结构：用 Composer/Agent 生成目录和基础文件
- 实现核心逻辑：Tab 补全加速编码，Cmd+K 精准修改代码块
- 编写单元测试：选中函数让 AI 生成覆盖边界情况的测试用例
- 采用"渐进式生成"策略——先框架后细节，小步验证

**阶段三：代码审查（占 20% 时间）**
- 自我审查（AI 辅助）：逐文件审查代码质量，检查竞态条件、安全漏洞、AI 幻觉 API
- 修复问题：用 Cmd+K 精准修改，不要重新生成整个文件
- 提交 PR：用 Agent 自动生成 PR 描述

**阶段四：合并部署（占 10% 时间）**
- CI 流水线自动检查（TypeScript + ESLint + 测试 + 构建）
- 人工 Code Review 聚焦架构和业务逻辑
- AI 辅助解决合并冲突

### 7. ★★★ 阐述如何通过自定义 ESLint 规则在 AST 层面拦截 AI 幻觉代码，并说明其核心原理和检测的 AST 节点类型。

**答案要点**：

**核心原理**：AI 幻觉代码在 AST（抽象语法树）层面有可检测的模式特征——不存在的 API 调用、过时的语法模式、虚构的导入路径——这些都可以通过遍历 AST 节点并匹配黑名单/正则来检测。

**关键 AST 节点类型与检测方法**：

| AST 节点类型 | 检测目标 | 检测逻辑 |
|------------|---------|---------|
| `CallExpression` | 不存在的 API 调用 | 检查 callee 的完整路径（如 `Vue.set`）是否在黑名单中 |
| `ImportDeclaration` | 虚构的导入路径 | 检查 `source.value` 是否匹配黑名单模式（如 `vue/composition-api`） |
| `MemberExpression` | 过时的属性访问 | 检查 `this.$set`、`this.$delete` 等模式 |
| `ExpressionStatement` > `CallExpression` | 未处理的 Promise | 检查 `fetch`、`axios` 等调用是否缺少 `await`/`.then`/`.catch` |

**实现要点**：
1. 维护黑名单 API 列表（精确匹配）和黑名单正则模式（模糊匹配）
2. 在 `create(context)` 中返回 AST 访问器对象，遍历目标节点
3. 匹配到黑名单时调用 `context.report()` 报告错误
4. 配置白名单 `allowedAPIs` 避免误报
5. 集成到 CI 流水线中自动执行

> - [ESLint 配置文档](https://eslint.org/docs/latest/use/configure/)

```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  auto-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: pnpm install --frozen-lockfile
      - run: pnpm typecheck
      - run: pnpm lint
      - run: pnpm test -- --coverage

    runs-on: ubuntu-latest

      - uses: actions/checkout@v4

          fetch-depth: 0
      - name: 获取变更文件
        id: changed-files
        run: |

      - name: AI 审查
        run: |
          claude review \
            --files "${{ steps.changed-files.outputs.files }}" \

              ...context.repo,
              issue_number: context.issue.number,

            });
```

### 4. ★★★ 设计一个 AI 生成代码的竞态条件防范方案

**场景描述**：团队发现 AI 生成的代码中，竞态条件（Race Condition）是最常见的深层次缺陷——AI 默认生成"快乐路径"代码，几乎总是遗漏异步操作的取消和顺序保证。请设计一个系统化的防范方案，覆盖代码审查、自动化检测和团队规范三个层面。

**设计思路**：

**1. 代码审查检查清单（人工 + AI 辅助）**：

| 检查项 | 关键词 | 需要确认 |
|--------|--------|---------|
| 异步请求取消 | `fetch`、`axios`、`useEffect`、`watchEffect` | 是否有 AbortController / cleanup / ignore 标记 |
| 搜索/筛选防抖 | `onChange`、`onInput`、`watch` | 是否有 debounce 且结合了请求取消 |
| 表单防重复提交 | `onSubmit`、`handleSubmit` | 是否有 loading 状态防止重复点击 |
| cleanup 函数 | `useEffect`、`watchEffect` | 是否返回了 cleanup 函数 |
| 定时器清理 | `setTimeout`、`setInterval` | 是否有对应的 `clearTimeout`/`clearInterval` |
| 请求顺序保证 | `Promise.all`、并发请求 | 是否考虑了请求到达顺序 |

**2. 自动化检测（自定义 ESLint 规则）**：

```javascript
// 自定义规则：检测 useEffect 中缺少 cleanup 的异步操作
module.exports = {
  rules: {
    'require-cleanup-in-effect': {
      create(context) {
        return {
          CallExpression(node) {
            // 检测 useEffect 调用
            if (node.callee.name === 'useEffect') {
              const callback = node.arguments[0];
              if (callback && callback.type === 'ArrowFunctionExpression') {
                const body = callback.body;
                const bodyText = context.getSourceCode().getText(body);
                // 检测是否有异步操作但没有 return cleanup
                const hasAsync = /\b(fetch|axios|setTimeout|setInterval|addEventListener)\b/.test(bodyText);
                const hasCleanup = /\breturn\s/.test(bodyText) || /\bcleanup\b/.test(bodyText);
                if (hasAsync && !hasCleanup) {
                  context.report({
                    node,
                    message: 'useEffect 中存在异步操作但缺少 cleanup 函数，可能导致竞态条件',
                  });
                }
              }
            }
          },
        };
      },
    },
  },
};
```

**3. 团队规范**：
- 任何 AI 生成的异步代码必须经过竞态条件审查
- 在 Prompt 模板中默认加入"使用 AbortController 取消请求"、"在 cleanup 中清理副作用"等约束
- 建立团队竞态条件案例库，沉淀常见模式和修复方案
- 新人入职培训包含竞态条件识别和防范专题

**4. 防范方案的完整链路**：

```
Prompt 约束（源头预防）
  → AI 代码审查（自动检测）
  → 自定义 ESLint 规则（AST 拦截）
  → 人工审查清单（逐项确认）
  → 单元测试（运行时验证）
```

## 补充编程题：完整代码实现

### 补充1：自定义 ESLint 规则 - AI 幻觉 API 拦截

```javascript
// eslint-plugin-no-ai-hallucination.js
// 用途：在 AST 层面自动拦截 AI 可能生成的幻觉代码

module.exports = {
  rules: {
    'no-fake-api': {
      meta: {
        type: 'problem',
        docs: {
          description: '拦截 AI 幻觉产生的虚假 API 调用',
          recommended: 'error',
        },
        schema: [{
          type: 'object',
          properties: {
            blockedAPIs: { type: 'array', items: { type: 'string' } },
            blockedImportPatterns: { type: 'array', items: { type: 'string' } },
            allowedAPIs: { type: 'array', items: { type: 'string' } },
          },
        }],
        messages: {
          fakeApi: "疑似 AI 幻觉 API：'{{api}}' 在当前版本中不存在或已废弃，请查阅官方文档",
          fakeImport: "疑似 AI 幻觉导入：模块路径 '{{path}}' 可能不存在",
        },
      },

      create(context) {
        const options = context.options[0] || {};
        const blockedAPIs = options.blockedAPIs || [];
        const blockedImportPatterns = options.blockedImportPatterns || [];
        const allowedAPIs = new Set(options.allowedAPIs || []);

        function isAllowed(apiPath) {
          return allowedAPIs.has(apiPath);
        }

        return {
          // 规则 1：检查 CallExpression（函数调用）
          CallExpression(node) {
            if (node.callee.type === 'MemberExpression') {
              let fullPath = '';

              if (node.callee.object.type === 'Identifier') {
                fullPath = `${node.callee.object.name}.${node.callee.property.name}`;
              } else if (
                node.callee.object.type === 'MemberExpression' &&
                node.callee.object.property.type === 'Identifier'
              ) {
                fullPath = `${node.callee.object.object.name}.${node.callee.object.property.name}.${node.callee.property.name}`;
              }

              if (fullPath && !isAllowed(fullPath)) {
                if (blockedAPIs.includes(fullPath)) {
                  context.report({
                    node,
                    messageId: 'fakeApi',
                    data: { api: fullPath },
                  });
                }

                for (const pattern of blockedImportPatterns) {
                  if (fullPath.match(new RegExp(pattern))) {
                    context.report({
                      node,
                      messageId: 'fakeApi',
                      data: { api: fullPath },
                    });
                    break;
                  }
                }
              }
            }
          },

          // 规则 2：检查 ImportDeclaration（导入语句）
          ImportDeclaration(node) {
            const importPath = node.source.value;

            for (const pattern of blockedImportPatterns) {
              if (importPath.match(new RegExp(pattern))) {
                context.report({
                  node,
                  messageId: 'fakeImport',
                  data: { path: importPath },
                });
                break;
              }
            }
          },

          // 规则 3：检查 this.$xxx 模式
          MemberExpression(node) {
            if (
              !node.computed &&
              node.property.type === 'Identifier'
            ) {
              if (
                node.object.type === 'ThisExpression' &&
                (node.property.name === '$set' || node.property.name === '$delete')
              ) {
                const fullPath = `this.${node.property.name}`;
                if (blockedAPIs.includes(fullPath)) {
                  context.report({
                    node,
                    messageId: 'fakeApi',
                    data: { api: fullPath },
                  });
                }
              }
            }
          },
        };
      },
    },

      meta: {
        type: 'problem',
        docs: {
          description: '检测 AI 遗漏的未处理 Promise',
        },
      },
      create(context) {
        return {
          ExpressionStatement(node) {
            if (
              node.expression.type === 'CallExpression' &&
              node.expression.callee.type === 'Identifier'
            ) {

              if (asyncFuncs.includes(node.expression.callee.name)) {

                  node,
                  message: `AI 幻觉风险：'${node.expression.callee.name}()' 返回 Promise 但未被处理，请添加 await 或 .catch()`,
                });
              }
            }
          },
        };
      },
    },
  },
};
```

### 补充2：竞态条件安全请求封装

```typescript
/**
 * 竞态条件安全的请求封装
 * 自动取消上一次未完成的请求，确保只处理最新请求的结果
 */

// ========== 1. 基于 AbortController 的安全请求 Hook ==========
import { ref, onUnmounted } from 'vue';

export function useSafeRequest<T>(
  requestFn: (signal: AbortSignal) => Promise<T>
) {
  const data = ref<T | null>(null);
  const loading = ref(false);
  const error = ref<string | null>(null);

  let abortController: AbortController | null = null;

  async function execute() {
    // 取消上一次请求
    abortController?.abort();
    // 保存局部引用，避免模块级变量被新请求覆盖后判断失效
    const currentController = new AbortController();
    abortController = currentController;

    loading.value = true;
    error.value = null;

    try {
      const result = await requestFn(currentController.signal);
      // 仅在请求未被取消时更新状态
      if (!currentController.signal.aborted) {
        data.value = result;
      }
    } catch (err: any) {
      if (err.name !== 'AbortError') {
        error.value = err.message || '请求失败';
      }
    } finally {
      // 仅在当前请求未被取消时才重置 loading，避免旧请求的 finally 覆盖新请求的状态
      if (!currentController.signal.aborted) {
        loading.value = false;
      }
    }
  }

  // 组件卸载时取消所有请求
  onUnmounted(() => {
    abortController?.abort();
  });

  return { data, loading, error, execute };
}

// ========== 2. 请求版本号机制 ==========
export function createVersionedRequest() {
  let requestId = 0;

  return async function <T>(fn: () => Promise<T>): Promise<T> {
    const id = ++requestId;
    const result = await fn();
    if (id !== requestId) {
      throw new Error('Request cancelled: newer request exists');
    }
    return result;
  };
}

// ========== 3. 防重复提交封装 ==========
export function useSubmitLock() {
  const submitting = ref(false);

  async function withLock<T>(fn: () => Promise<T>): Promise<T | undefined> {
    if (submitting.value) return;
    submitting.value = true;
    try {
      return await fn();
    } finally {
      submitting.value = false;
    }
  }

  return { submitting, withLock };
}
```
