## 一、核心概念

AI 编程工具已从"辅助补全"进化为"自主编码"，深刻改变了前端开发的工作流。理解各工具的核心能力、适用场景和最佳实践，是 2025-2026 年前端工程师的必备技能。

**核心概念要点：**

1. **多层级 AI 编程能力**：从行内补全（Tab 补全）→ 单文件编辑（Cmd+K）→ 多文件重构（Composer / Agent）→ 全项目级任务，不同工具有不同的能力层级
2. **上下文是 AI 编程的灵魂**：AI 工具的输出质量高度依赖上下文质量——项目文件、规则配置、提示词精度共同决定结果
3. **AI 编程 ≠ 完全自动化**：AI 是"加速器"而非"替代品"，代码审查、架构决策、安全把关仍需人工介入
4. **工具选型是效率杠杆**：不同工具适合不同场景，合理搭配可最大化效率

## 二、AI 编程工具详解

### 2.1 Cursor

Cursor 是目前最流行的 AI-first IDE，基于 VS Code 深度定制，内置多模型 AI 能力。

**核心功能矩阵：**

| 功能 | 快捷键 | 说明 |
|------|--------|------|
| Tab 补全 | Tab | 智能预测下一行代码，支持多行同时补全，能感知上下文中的变量和函数 |
| Inline Edit | Cmd+K | 选中代码后输入自然语言指令，AI 直接修改选中区域 |
| Chat | Cmd+L | 侧边栏对话，可以引用文件、代码片段作为上下文 |
| Composer | Cmd+I | 多文件同时生成/编辑，可以一次性创建整个功能模块 |
| Agent 模式 | Composer 内切换 | 自主规划任务步骤、读取项目文件、执行终端命令、检查结果 |
| @ 引用 | @file / @folder / @web | 精确指定上下文范围，引用项目文件、文档或搜索网络 |

**工作流最佳实践：**

```
1. 需求分析 → 用 Chat 讨论技术方案和架构设计
2. 代码生成 → 用 Composer Agent 生成完整功能模块
3. 细节修改 → 用 Cmd+K 选中代码块精准修改
4. 日常编写 → 用 Tab 补全加速编码
5. 代码审查 → 用 Chat 审查代码质量和安全性
```

**Cursor Rules（项目规则配置）**：在项目根目录创建 `.cursorrules` 文件，定义项目级 AI 行为规范：

```markdown
# .cursorrules 示例
You are a senior frontend engineer. Follow these rules:
1. Use TypeScript with strict mode
2. Prefer functional components with hooks
3. Use Tailwind CSS for styling
4. Write unit tests for all new components
5. Follow the project's existing patterns and conventions
```

**Agent 模式使用技巧**：
- 任务描述要具体：包含输入、输出、约束条件、验收标准
- 分步执行：复杂任务拆解为多个小步骤，逐步验证
- 监控终端输出：Agent 执行命令时观察终端输出，及时修正方向

### 2.2 Claude Code

Claude Code 是 Anthropic 推出的 CLI 原生 AI 编程助手，在终端中直接运行，擅长项目级上下文理解和复杂重构。

**核心功能：**

| 功能 | 说明 |
|------|------|
| 项目级上下文 | 自动读取项目文件结构、package.json、tsconfig 等，理解项目全貌 |
| 多文件重构 | 一次对话中修改多个文件，保持代码一致性 |
| 终端命令执行 | 直接在终端中运行 npm、git、测试等命令，查看结果并自动修复 |
| 会话持久化 | 中断后可以恢复会话，保持上下文连续性 |
| 自定义指令 | 通过 CLAUDE.md 文件定义项目级行为规范 |

**CLAUDE.md 配置示例**：

```markdown
# CLAUDE.md

## 项目规范
- 使用 pnpm 作为包管理器
- 所有组件使用 TypeScript
- 遵循 Vue 3 Composition API 风格
- 路径别名：@/ 映射到 src/

## 编码规范
- 组件名使用 PascalCase
- 文件名使用 kebab-case
- 每个函数不超过 50 行
- 优先使用 async/await 而非 then/catch

## 测试要求
- 新组件必须包含单元测试
- 使用 Vitest + Vue Test Utils
- 覆盖率不低于 80%
```

**Claude Code vs Cursor 对比：**

| 维度 | Cursor | Claude Code |
|------|--------|-------------|
| 运行环境 | IDE（VS Code 内核） | 终端（CLI） |
| 交互方式 | 图形界面 + 快捷键 | 命令行 + 对话 |
| 代码补全 | 实时的 Tab 补全 | 无实时补全，依赖对话 |
| 多文件操作 | Composer Agent | 原生支持，更强 |
| 项目理解 | 通过 @ 引用 | 自动读取项目全貌 |
| 适用场景 | 日常编码、快速迭代 | 架构重构、复杂任务 |
| 学习曲线 | 低（IDE 用户友好） | 中（CLI 使用者优先） |

### 2.3 GitHub Copilot

GitHub Copilot 是 GitHub 推出的 AI 编程助手，深度集成在 VS Code、JetBrains 等主流 IDE 中。

**核心功能：**

| 功能 | 说明 |
|------|------|
| 行内补全 | 灰色幽灵文本建议，Tab 接受 |
| Copilot Chat | 侧边栏对话，支持代码解释、生成、重构 |
| 代理模式 | 自动识别和修复终端错误、自动生成 PR 描述 |
| Workspace 代理 | 跨文件理解和修改 |
| 代码审查 | PR 中自动审查代码质量、安全漏洞 |

**Copilot 独有优势**：
- 与 GitHub 生态深度集成（PR 审查、Issue 自动分类）
- 企业级代码隐私保护（代码不用于训练模型）
- 支持多种 IDE（VS Code、JetBrains、Neovim）

### 2.4 Windsurf

Windsurf（原 Codeium）是由 Codeium 公司推出的 AI-first IDE，基于 VS Code 内核，以 **Cascade** 代理模式为核心亮点。

**核心功能：**

| 功能 | 说明 |
|------|------|
| Cascade 代理 | 类似 Cursor Agent，但强调"流式上下文感知"，自动理解项目结构并逐步推理 |
| Supercomplete | 智能代码补全，相比传统 Tab 补全能感知更长的上下文 |
| 多文件编辑 | 一次对话中同时修改多个文件，保持跨文件一致性 |
| 命令面板 AI | 通过 Cmd+Shift+P 直接调用 AI 执行命令 |

**Windsurf 与 Cursor 对比：**

| 维度 | Cursor | Windsurf |
|------|--------|----------|
| 代理模式 | Composer Agent | Cascade（流式推理） |
| 代码补全 | Tab 补全 | Supercomplete（更长上下文感知） |
| 定价 | 免费额度 + Pro 订阅 | 免费额度 + Pro 订阅 |
| 上下文窗口 | 较大 | 较大（强调自动上下文收集） |
| 适用场景 | 日常编码 + 复杂重构 | 日常编码，尤其是需要逐步推理的复杂任务 |

### 2.5 Amazon Q Developer

Amazon Q Developer（原 CodeWhisperer）是 AWS 推出的 AI 编程助手，深度集成 AWS 生态，在云服务相关开发场景中具有独特优势。

**核心功能：**

| 功能 | 说明 |
|------|------|
| 代码补全 | 支持 15+ 编程语言，上下文感知的代码建议 |
| 安全扫描 | 内置代码安全漏洞扫描，自动检测 OWASP Top 10 等安全风险 |
| AWS 生态集成 | 对 AWS SDK、CDK、CloudFormation 等有深度优化 |
| 代码转换 | 支持 Java 到 Kotlin、.NET Framework 到 .NET Core 等代码迁移 |
| 企业级控制 | 支持组织级策略管理、代码引用追踪 |

**Amazon Q Developer 独有优势：**
- 与 AWS 服务深度集成，在云原生开发场景中建议更精准
- 内置安全扫描功能，无需额外配置
- 企业级代码隐私保护（代码不用于训练模型）
- 对 AWS 基础设施即代码（IaC）有专项优化

### 2.6 Gemini Code Assist

Gemini Code Assist 是 Google 推出的 AI 编程助手，基于 Gemini 模型，深度集成 Google Cloud 生态和主流 IDE。

**核心功能：**

| 功能 | 说明 |
|------|------|
| 代码补全 | 基于 Gemini 2.5 Pro 模型，支持多语言智能补全 |
| 对话式编程 | 支持自然语言描述需求，生成完整代码片段 |
| Google Cloud 集成 | 对 GCP 服务（Cloud Run、BigQuery、Firebase 等）有深度优化 |
| IDE 支持 | 支持 VS Code、JetBrains（IntelliJ、PyCharm 等） |
| 大上下文窗口 | 支持 100 万 token 上下文窗口，可理解整个项目代码库 |

**Gemini Code Assist 独有优势：**
- 100 万 token 超大上下文窗口，可一次性理解整个代码库
- 与 Google Cloud 生态深度集成
- 对 Android 开发、Flutter、Angular 等 Google 技术栈有专项优化
- 免费计划慷慨，适合个人开发者

### 2.7 工具选型建议

| 使用场景 | 推荐工具 | 原因 |
|---------|---------|------|
| 日常编码（高频、小改动） | Cursor | Tab 补全流畅，IDE 体验好 |
| 大型重构（跨文件、多步骤） | Claude Code | 项目级理解强，多文件操作稳定 |
| 团队协作（GitHub 生态） | Copilot | PR 审查、Issue 分类深度集成 |
| 快速原型（从零搭建） | Cursor Composer | 多文件生成速度快 |
| 代码审查（质量把关） | Claude Code + Copilot | 双工具交叉验证 |
| AWS 云服务开发 | Amazon Q Developer | AWS 生态深度集成，内置安全扫描 |
| Google Cloud 开发 | Gemini Code Assist | GCP 生态集成，超大上下文窗口 |
| Android / Flutter 开发 | Gemini Code Assist | Google 技术栈专项优化 |
| 逐步推理复杂任务 | Windsurf | Cascade 流式推理，自动上下文收集 |
| 个人项目 | Cursor（免费额度） | 成本低，功能全面 |

**推荐组合**：Cursor（日常编码）+ Claude Code（复杂任务），两者互补。云服务开发场景下建议引入对应平台的 AI 工具（Amazon Q Developer / Gemini Code Assist）。

## 三、AI 编程工作流最佳实践

### 3.1 从需求到 PR 的完整链路

```
需求分析                          AI 辅助
  ├── 理解需求文档              → Chat：分析需求，提出技术问题
  ├── 拆解为子任务              → Chat：将需求拆解为可执行步骤
  └── 输出技术方案              → Chat：生成技术方案文档

编码实现
  ├── 搭建项目结构              → Composer/Agent：生成目录和基础文件
  ├── 实现核心逻辑              → Tab 补全 + Cmd+K：加速编码
  ├── 编写单元测试              → Cmd+K：选中函数生成测试
  └── 样式实现                  → Cmd+K：描述样式效果

代码审查
  ├── 自我审查（AI 辅助）       → Chat：检查代码质量和安全性
  ├── 修复问题                  → Cmd+K：修改具体问题
  └── 提交 PR                   → Agent：自动生成 PR 描述

合并部署
  ├── CI 流水线检查             → 自动化（已有）
  ├── 人工 Code Review          → 团队审查
  └── 合并到主分支              → 自动化
```

### 3.2 上下文管理策略

AI 编程工具的输出质量与上下文成正比，管理上下文是 AI 编程的核心技能：

1. **项目级规则文件**：`.cursorrules` / `CLAUDE.md` 定义项目规范
2. **精确引用**：使用 `@file`、`@folder` 指定范围，而非让 AI 猜测
3. **渐进式上下文**：先给概要，再逐步补充细节
4. **上下文清理**：对话过长时开启新对话，避免上下文污染

### 3.3 代码质量保障机制

AI 生成的代码需要经过以下质量关卡：

| 关卡 | 工具/方法 | 检查内容 |
|------|----------|---------|
| 类型检查 | TypeScript | 类型安全、接口一致性 |
| 静态分析 | ESLint | 代码规范、潜在错误 |
| 单元测试 | Vitest / Jest | 功能正确性 |
| 安全扫描 | AI Review + 人工 | 安全漏洞、敏感信息 |
| 性能审查 | 人工 + Lighthouse | 性能回归 |
| 可维护性 | 人工审查 | 代码可读性、架构合理性 |

## 四、常见问题与避坑指南

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| AI 生成的代码看起来对但实际运行错误 | AI 基于训练数据生成，不保证运行时正确 | 必须运行测试验证，不要直接合并 AI 生成的代码 |
| AI 胡编不存在的 API | 训练数据包含过时或错误信息 | 在 Prompt 中约束 API 使用范围，要求使用已知的库 |
| 上下文过长导致 AI 遗忘 | 对话历史超出上下文窗口 | 定期开启新对话，用规则文件替代对话中的重复说明 |
| AI 生成的代码风格不一致 | 缺乏项目规范约束 | 配置 `.cursorrules` / `CLAUDE.md` 统一风格 |
| 过度依赖 AI 导致技能退化 | 不再自己思考代码逻辑 | 保持"理解后再使用"原则，AI 是加速器不是替代品 |

## 常见面试题

### 1. Cursor 的 Tab/Cmd+K/Composer/Agent 四种核心功能分别适用什么场景？

Cursor 的四种核心功能构成了从"行级补全"到"全项目自主编码"的完整能力层级，每种功能有明确的适用场景：

| 功能 | 快捷键 | 适用场景 | 典型使用方式 |
|------|--------|---------|-------------|
| **Tab 补全** | Tab | 行级/多行代码补全，日常编码中的高频小改动 | 编写函数体、补全变量赋值、生成循环/条件语句 |
| **Inline Edit (Cmd+K)** | Cmd+K | 选中代码块进行精准修改，单文件内的小范围重构 | 修改函数签名、重命名变量、调整代码风格、添加错误处理 |
| **Composer** | Cmd+I | 单文件或多文件联动生成，创建完整的功能模块 | 新建组件、生成 CRUD 页面、搭建项目骨架 |
| **Agent 模式** | Composer 内切换 | 自主规划、多步骤复杂任务，需要读取项目文件、执行终端命令 | 全项目重构、跨文件修改、创建完整功能并运行测试 |

**场景选择决策树：**

```
修改范围？
├── 单行/几行代码        → Tab 补全
├── 单个代码块/函数      → Cmd+K (Inline Edit)
├── 单个文件/新组件      → Composer
└── 多文件 + 需要执行命令 → Agent 模式
```

**面试要点：** 面试官关注的是你是否理解"能力分层"的概念——AI 编程不是"一把梭"，而是根据任务粒度选择合适的功能层级。同时要强调 Agent 模式需要人工监控，不可完全放任。

### 2. Claude Code 与 Cursor 在项目级重构中各自的优势是什么？如何选择？

这是一个经典的"IDE vs CLI"工具选型问题，核心差异在于交互模式和上下文理解方式：

**Claude Code 在项目级重构中的优势：**

1. **自动项目理解**：Claude Code 启动时会自动扫描 `package.json`、`tsconfig.json`、目录结构等，无需手动 `@` 引用即可建立全局上下文
2. **多文件一致性**：一次对话中修改 10+ 个文件时，Claude Code 比 Cursor 更稳定，不容易遗漏关联文件
3. **终端原生集成**：重构后可以直接运行 `pnpm typecheck`、`pnpm test`，根据结果自动修复，形成"改-测-修"闭环
4. **会话持久化**：重构任务中断后可恢复，保持上下文连续性，适合持续数小时的大型重构

**Cursor 在项目级重构中的优势：**

1. **可视化操作**：IDE 界面可以直观查看文件变更、diff 对比、git 状态
2. **Tab 补全辅助**：重构过程中仍需大量手写代码时，Tab 补全大幅提升效率
3. **Composer 快速生成**：对于"替换某个模式的所有出现"这类任务，Composer 的多文件生成速度更快
4. **学习曲线低**：团队中不熟悉 CLI 的成员更容易上手

**选择策略：**

```
重构任务特征              → 推荐工具
─────────────────────────────────────────
涉及 10+ 文件联动修改      → Claude Code
需要频繁运行测试验证       → Claude Code
需要 2 小时以上的持续重构   → Claude Code（会话持久化）
需要边改边看 UI 效果       → Cursor
团队协作、多人审查         → Cursor（GitHub Copilot 集成）
小型重构（3-5 个文件）     → Cursor Composer
```

**最佳实践：** 两者不是互斥的，推荐"双工具组合"——用 Claude Code 做架构级重构（改目录结构、改类型系统、改状态管理），用 Cursor 做日常编码和细节调整。一个典型的流程是：Claude Code 完成重构后，在 Cursor 中打开项目进行 diff 审查和微调。

### 3. AI 编程工作流的标准步骤是什么？每个步骤的 AI 协作要点是什么？

完整的 AI 编程工作流分为四个阶段，每个阶段有明确的 AI 协作方式：

**阶段一：需求分析与方案设计（占 20% 时间）**

| 步骤 | AI 协作要点 |
|------|-----------|
| 理解需求文档 | 用 Chat 提问澄清模糊需求，AI 可以帮助发现需求中的逻辑漏洞 |
| 拆解子任务 | 将需求拆解为可独立执行的小步骤，每个步骤有明确的输入/输出 |
| 输出技术方案 | 用 Chat 生成技术方案文档，包含组件树、数据流、状态管理方案 |

**关键技巧：** 这一阶段不要让 AI 直接写代码，而是用它做"技术顾问"——讨论方案、发现问题、评估风险。Prompt 要聚焦在"方案设计"而非"代码实现"。

**阶段二：编码实现（占 50% 时间）**

| 步骤 | AI 协作要点 |
|------|-----------|
| 搭建项目结构 | 用 Composer/Agent 生成目录和基础文件，一次性创建完整骨架 |
| 实现核心逻辑 | 用 Tab 补全加速编码，用 Cmd+K 精准修改代码块 |
| 编写单元测试 | 用 Cmd+K 选中函数，让 AI 生成覆盖边界情况的测试用例 |
| 样式实现 | 用 Cmd+K 描述视觉效果，让 AI 生成 CSS/Tailwind 样式 |

**关键技巧：** 采用"渐进式生成"策略——先让 AI 生成框架代码，人工审查确认后，再逐步填充细节。不要一次性让 AI 生成 500 行代码然后审查，那样效率极低。

**阶段三：代码审查（占 20% 时间）**

| 步骤 | AI 协作要点 |
|------|-----------|
| 自我审查（AI 辅助） | 用 Chat 逐文件审查代码质量，检查竞态条件、安全漏洞、AI 幻觉 API |
| 修复问题 | 用 Cmd+K 精准修改具体问题，不要重新生成整个文件 |
| 提交 PR | 用 Agent 自动生成 PR 描述，包含变更摘要和测试说明 |

**关键技巧：** AI 审查和人工审查是互补的——AI 擅长发现模式匹配类问题（如缺少 cleanup），人工擅长判断架构合理性和业务逻辑正确性。

**阶段四：合并部署（占 10% 时间）**

| 步骤 | AI 协作要点 |
|------|-----------|
| CI 流水线检查 | 自动化（TypeScript + ESLint + 测试），AI 可辅助修复 CI 失败 |
| 人工 Code Review | 团队审查，AI 生成的审查报告可作为参考 |
| 合并到主分支 | 自动化，AI 可辅助解决合并冲突 |

### 4. 如何管理 AI 编程中的上下文，避免上下文溢出导致的生成质量下降？

AI 编程工具（尤其是大语言模型）有一个关键限制：**上下文窗口有限**。当对话过长时，早期的指令和约束会被"挤出"上下文窗口，导致 AI 遗忘项目规范、生成质量下降。以下是系统化的上下文管理策略：

**策略一：项目级规则文件（持久化上下文）**

将项目规范写入 `.cursorrules` 或 `CLAUDE.md`，这些规则会在每次对话中自动注入，不会被对话历史挤出：

```markdown
# .cursorrules
你是一名资深前端工程师。在每次回复中：
1. 使用 TypeScript 严格模式
2. 遵循 Vue 3 Composition API + `<script setup>` 语法
3. 使用 pnpm 作为包管理器
4. 路径别名：@/ 映射到 src/
5. 组件名 PascalCase，文件名 kebab-case
```

**策略二：精确引用而非模糊描述**

| 错误做法 | 正确做法 |
|---------|---------|
| "参考项目中的组件风格" | `@file:src/components/common/BaseTable.vue` 精确引用 |
| "使用项目中已有的工具函数" | `@file:src/utils/request.ts` 引用具体文件 |
| "按照之前的模式" | 重新粘贴关键代码片段，不要依赖 AI 的"记忆" |

**策略三：渐进式上下文（分层注入）**

不要一次性提供所有上下文，采用"先概要后细节"的策略：

```
第一轮对话：
  "项目使用 Vue 3 + TypeScript + Element Plus，请设计一个用户管理页面的组件结构"

第二轮对话（在 AI 理解结构后）：
  "现在实现 UserTable 组件，参考 @file:src/components/common/BaseTable.vue 的写法"

第三轮对话（在 AI 生成基础代码后）：
  "为 UserTable 添加分页、排序、筛选功能，分页参数通过 Pinia store 管理"
```

**策略四：上下文清理（定期重置）**

| 场景 | 处理方式 |
|------|---------|
| 对话超过 20 轮 | 开启新对话，将关键约束重新写入第一条消息 |
| 任务方向改变 | 立刻开启新对话，避免旧上下文干扰 |
| AI 开始遗忘早期约束 | 开启新对话，不要试图"提醒"AI |
| 切换项目/模块 | 必须开启新对话 |

**策略五：上下文预算管理**

把上下文窗口当作"预算"来管理：

```
总预算：~200K tokens（以 Claude 为例）
├── 系统提示词（规则文件）：~2K tokens（固定消耗）
├── 项目文件引用：~10K tokens（按需消耗，用完即弃）
├── 当前任务描述：~2K tokens（必须保留）
├── 对话历史：随对话增长（动态消耗）
└── 剩余给 AI 生成：由上述决定
```

**面试要点：** 面试官想听到的是"上下文管理"是个系统性问题，而非"多写点注释"就能解决的。强调规则文件的持久化、精确引用和定期重置三个核心策略。

### 5. AI 编程工具生成的代码，如何确保代码质量和安全性？

AI 生成的代码绝对不能直接合并到生产环境，必须经过多层质量关卡。以下是完整的质量保障体系：

**第一层：自动化检查（每次提交自动执行）**

```yaml
# CI 流水线中的质量关卡
- TypeScript 类型检查：pnpm typecheck     # 拦截类型错误
- ESLint 规则检查：  pnpm lint            # 拦截代码规范问题
- 单元测试：         pnpm test            # 拦截功能错误
- 构建验证：         pnpm build           # 拦截构建失败
```

**第二层：AI 代码审查（每次 PR 自动执行）**

使用 AI 审查工具（Claude Code / Copilot Code Review）从以下维度检查：

| 检查维度 | 具体检查内容 | 工具/方法 |
|---------|-------------|---------|
| 竞态条件 | 异步请求是否有 AbortController / cleanup | AI 审查 Prompt |
| AI 幻觉 API | 是否存在不存在的 API、过时的语法 | 自定义 ESLint 规则 |
| 安全漏洞 | XSS 风险、敏感信息泄露、eval 调用 | AI 审查 + ESLint |
| 内存泄漏 | 事件监听/定时器是否清理 | AI 审查 |
| 错误处理 | 是否覆盖 loading/error/empty 状态 | AI 审查 |

**第三层：人工审查（每次 PR 必须执行）**

AI 无法替代的审查维度：

| 审查维度 | 为什么 AI 无法替代 |
|---------|-------------------|
| 架构合理性 | AI 不理解业务上下文，无法判断架构是否适合业务发展 |
| 业务逻辑正确性 | AI 不知道 PRD 的具体要求 |
| 代码可维护性 | AI 不理解团队的长期维护策略 |
| 安全敏感逻辑 | 权限控制、支付逻辑等必须人工审查 |

**第四层：安全扫描（定期执行）**

```bash
# 依赖安全扫描
pnpm audit

# 密钥泄露扫描（git-secrets / truffleHog）
git secrets --scan

# 容器镜像扫描（如使用 Docker）
trivy image my-app:latest
```

**实践中的经验法则：**

```
"AI 生成的代码 = 初稿，不是终稿"
- 100% 的 AI 生成代码需要经过自动化检查
- 100% 的 AI 生成代码需要人工审查
- 涉及安全、支付、权限的代码，AI 仅用于生成模板，核心逻辑必须手写
- 每次 AI 生成后，必须运行 pnpm typecheck && pnpm lint && pnpm test
```
